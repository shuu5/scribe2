設計判断記録 (ADR) scribe2 — 群の予約の持ち主

予約は逼迫した群だけが持つ — 逼迫していない先の群は候補を測らず予約も導かず、 逼迫した後の群が鍵の先頭を取る。 移り先の無い断りは群用 dir の印と doctor の群の行で host の全席から読める (ADR-0069 の予約の読みを部分 supersede)

ADR-0069 は群を宣言順に見て先の群 (Tier1) が先に移り先を予約し、 後の群 (Tier2) はそれを避けると決めた。 先の群は逼迫していなくても予約を持つので、 口座 6 つのうち 3 つが上限・2 つが使用中の周に、 残る 1 つを暇な Tier1 が予約し、 上限に達した Tier2 が 3 時間「移り先なし」で止まった。 本 ADR は予約をその周に逼迫している群だけに限り、 断りを host の全席から読める印にする。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「群」は同じ口座の候補を共に使う project の集まり、 「予約」は群が次に移る口座、 「逼迫」は口座が上限に近いことです。 前の決定 (ADR-0069) は群を宣言順に見て、 先の群 (Tier1) が先に移り先を予約し、 後の群 (Tier2) はそれを避けると決めました。 ところが先の群は逼迫していなくても予約を持つので、 口座 6 つのうち 3 つが上限・2 つが使用中の周に、 残る 1 つを暇な Tier1 が予約し、 上限に達した Tier2 が 3 時間「移り先なし」で止まりました。 断りは判定した 1 席の画面にしか出ませんでした。 この記録は、 予約をその周に逼迫している群だけに限り (両方が逼迫した周だけ宣言順)、 移り先の無い断りを群用 dir の印と doctor の群の行で host のどの席からも読めるようにすると決めます。 持ち主は 2026-09-26 にこの形を裁定しました。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (予約は宣言順で先の群が先に取る)・事象 (暇な Tier1 の予約が上限に達した Tier2 の唯一の移り先を奪い 3 時間止まった)・機序 (予約は移る周にしか要らないのに移らない群も持っている)・これまでの決まり・この判断の範囲の 5 つから説明します。 前の決定 (ADR-0069) の周に持ち主は「後の群が移り先なしになるのは想定内」と是認しましたが、 それは両方が逼迫した周の話で、 暇な群が塞ぐ形は想定していませんでした。

CTX1

経緯 — 群の予約群が次に移る口座は宣言順で、 先の群が先に取る (ADR-0069・設計 §29)

ADR-0069 は移り先の候補を残量の鍵候補を並べる物差し (7 日窓と役割の model の 7 日窓の残量の小さい方が大きい順 → 7 日窓の reset → 宣言順) で並べ、 群を宣言順に見て「どの群の今の口座群がいま使う口座でもなく先の群の予約でもない先頭」を各群の予約とすると決めた。 予約は記録せず周ごとに lock の内側で導く。 後の群が移り先なしになるのは想定内として持ち主が是認した (2026-09-26T01:3xZ)。 現物の予約の 1 関数は、 先の群の逼迫口座が上限に近いことを読まずに先の群の候補を測って予約を導く。

CTX2

事象 — 暇な Tier1 の予約が上限に達した Tier2 の唯一の移り先を奪い、 3 時間止まった

2026-09-26 12:05Z から 14:07Z まで、 Tier2 の判定 (管理 tick席を周期で見る仕組み) は今の口座の Fable 7 日窓 100% を実測しながら 3 周とも「移り先なし」で断った。 候補 6 口座のうち 3 つは閾値 (95%) 以上、 1 つは Tier1 の今の口座、 残る 1 つ (82%) は逼迫していない Tier1 (43%) の予約で、 Tier2 には回らなかった。 断りは判定した 1 席の画面と event log にしか出ず、 持ち主が気づいたのは 14:3xZ で、 記録を手で書き換えて 6 席を移した。

CTX3

機序 — 予約は「群が移る周に要る」のに、 移らない群も持っている

予約の意味は、 同じ周に 2 群が同じ口座へ移らないことと、 両方が逼迫した周に先の群が良い方を取ることの 2 つで、 どちらも先の群が移る周にしか要らない。 現物は先の群の逼迫を読まないので、 移らない群が候補を 1 つ塞ぎ続ける。 口座の数が群の数より十分多い host では見えず、 上限に達した口座が増えた周に初めて現れる。 断りの出方も、 判定を撃つ席の置き場 (state dir) の event と pane に閉じ、 別の置き場の席 (別 project) からは見えない。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C17 (決定はしご) から、 先の群の逼迫は今の口座 1 つの実測で分かり、 候補を全部測る呼びは要らない。 C10 (宣言値・実測値・導出値を分ける) から、 予約は導出値のまま記録せず、 断りは判定の実測の印として別の file に置き、 導出値の語 (next=) に畳まない。 C1 (消さない) から、 印は次の判定で history へ退避する。 N3 (host 固有の値で分岐しない) から、 別の置き場の席を列挙して断りを送る形は採らず、 host で 1 つの群用 dir群の file の置き場 の印を doctor が読む。

CTX5

射程 — 動かすのは予約の持ち主・断りの印・doctor の群の行の 3 か所

動かすのは (1) 予約の 1 関数が先の群の予約を導く条件 (先の群の今の口座が鮮度の内側の実測で逼迫している周だけ・鮮度の外は今の口座だけ 1 回測る)、 (2) 移り先の無い断りの周に群用 dir へ印 1 file を書き、 次の判定 (留まる・移る) で history へ退避すること、 (3) doctor の群の行に印の時刻を出すこと。 動かさないのは、 残量の鍵・門・判じる群の予約の導き・両方が逼迫した周の宣言順・断りの 1 行の宛先・断りの event の 1 回性・記録の形・便用の選定。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 逼迫した群を逼迫していない群が飢えさせないこと (移らない群は候補を塞がない)。 先の群の優先は保つこと (両方が逼迫した周は宣言順で先の群が良い方を取る)。 止まった群が host のどの席からも見えること (断りが 1 席の画面に閉じない)。 呼びと状態を増やさないこと (逼迫の読みは今の口座 1 つの実測で足り、 印は 1 file で次の判定が退避する)。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 4 つ並べます。 予約を逼迫した群だけに限り断りの印を群用 dir に置く案 (選んだ案)、 逼迫した後の群が先の群の予約を奪う案、 断りの 1 行を host の全席へ送る案、 口座を増やす運用で受ける案です。 選ばなかった 3 つは、 規則が 2 つになる・別の置き場は列挙できない・運用は規則でない、 という理由で退けました。

OPT1予約は逼迫した群だけ + 断りの印移り先なしの控えを群用 dir に置き doctor が出す採用

予約の 1 関数は先の群ごとに今の口座の実測 (鮮度の外なら今の口座だけ 1 回測る) を読み、 逼迫の周だけ候補を測って予約を導く。 逼迫でない先の群は予約なし。 移り先の無い断りの周は群用 dir に印 1 file を書き、 次の判定で history へ退避し、 doctor の群の行に時刻を出す。 決め手は持ち主の裁定 (14:41Z)。

予約をその周に逼迫している群だけに限る案です。 予約の 1 関数は先の群ごとに今の口座の実測を読み (古ければ今の口座だけ 1 回測る)、 上限に近い周だけ候補を測って予約を導きます。 暇な先の群は予約を持たず候補も測りません。 両方が逼迫した周は今のまま宣言順で先の群が良い方を取ります。 あわせて、 移り先の無い断りの周は群用 dir に印を 1 つ書き、 次の判定で history へ退避し、 doctor の群の行に時刻を出します。 暇な群が候補を塞がず、 先の群の優先は保たれ、 断りは host のどの席からも読め、 増える呼びと状態は最小である点で勝ります。 代わりに、 先の群が暇な周は予約が無く逼迫に転じた周の移り先が次の周に決まり、 doctor の行が 1 欄増えます。 持ち主の裁定で選びました。

+ 利点

  • 移らない群が候補を塞がず、 逼迫した後の群が鍵の先頭を取る (DR1)
  • 両方が逼迫した周は今のまま宣言順で先の群が先 (DR2)
  • 断りの印は host で 1 つの群用 dir に在り、 どの席の doctor からも読める (DR3)
  • 増える呼びは先の群の今の口座 1 回、 増える状態は印 1 file で次の判定が退避する (DR4)

− 欠点

  • 先の群が逼迫していない周は予約が無いので、 その周に先の群が逼迫に転じても移り先は次の周に決まる
  • doctor の群の行が 1 欄増え、 既存の歯の期待が動く
OPT2逼迫した後の群が先の群の予約を奪う不採用

先の群の予約は今のまま導き、 後の群が逼迫した周だけそれを飛ばさずに取る。 決め手は分析 (規則が 2 つになる)。

先の群の予約は今のまま導き、 逼迫した後の群だけがそれを奪える案です。 予約の導き方を変えない点で勝ります。 けれども、 「予約は避ける」と「奪ってよい」の 2 規則になり、 両方が逼迫した周の優先との境目が読み手に見えません。 先の群の候補を全部測る呼びも残ります。 退けました。

+ 利点

  • 予約の導き方は変えない

− 欠点

  • 「予約は避ける」と「奪ってよい」の 2 規則になり、 両方が逼迫した周の優先 (DR2) との境目が読み手に見えない
  • 先の群の候補を全部測る呼びは残る (DR4)
OPT3断りの 1 行を host の全席へ送る不採用

判定を撃った tick が別の置き場の席にも断りの 1 行を注入する。 決め手は分析 (別の置き場は列挙できない)。

判定を撃った tick が別の置き場の席にも断りの 1 行を注入する案です。 人が見ている席へ能動的に届く点で勝ります。 けれども、 tick は自分の置き場の登録 row しか読まず、 別の project の置き場を列挙する形は host 固有の path になります。 席の数だけ注入が増え、 作業中の席の入力欄を汚します。 退けました。

+ 利点

− 欠点

  • tick は自分の置き場の登録 row しか読まず、 別の置き場 (別 project の state dir) の列挙は host 固有の path になる (N3)
  • 席の数だけ注入が増え、 作業中の席の入力欄を汚す (DR4)
OPT4現状維持 — 口座を増やす運用で受ける不採用

器は変えず、 口座の数を群の数より十分多く保つ。 決め手は分析 (運用は規則でない)。

器は変えず、 口座の数を群の数より十分多く保つ運用の案です。 器に足すものが無い点で勝ります。 けれども、 上限に達した口座が増える周は必ず来て、 そのたびに暇な群が移り先を塞ぎます。 断りが 1 席の画面に閉じる問題も残ります。 退けました。

+ 利点

  • 器に足すものが無い

− 欠点

  • 上限に達した口座が増える周は必ず来て、 そのたびに暇な群が移り先を塞ぐ (DR1)
  • 断りが 1 席の画面に閉じる問題は残る (DR3)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 予約の 1 関数は先の群ごとに今の口座の実測 (鮮度の外なら今の口座だけ 1 回測る) を読み、 逼迫の周だけ候補を測って予約を導きます。 逼迫でない先の群は予約を持ちません。 移り先の無い断りの周は群用 dir に印 1 file を書き、 留まる判定と移る判定が history へ退避し、 doctor の群の行に時刻を出します。 支えるのは FR38 (群の逼迫の通知と移動) の根拠と FR27 (管理 tick) への主張です。

採用 — OPT1

群の予約の 1 関数 SHALL 先の群ごとに、 その群の今の口座の鮮度の内側の実測 (鮮度の外なら今の口座だけ 1 回測る) が閾値以上の周だけ候補を測って予約を導き、 逼迫していない先の群と実測を持たない先の群 SHALL 予約を持たず候補を測らない。 判じる群の予約の導き・両方が逼迫した周の宣言順 (先の群が鍵の先頭)・役割の行が無い周の止まり方は変えない。 移り先の無い断りの周 SHALL 群用 dir に印 1 file (群の名・断りの時刻・理由) を書き、 同じ実測に 2 度断らない周は書き直さず、 留まる判定と記録を書く判定 SHALL 在る印を history へ退避する。 doctor の群の行 SHALL 印の時刻 (無ければ無し・形でなければ読めない) を予約の語の後ろに出す。 残量の鍵・門・断りの 1 行の宛先・断りの event の 1 回性・記録の形・種・便用の選定は変えない。 本 ADR は ADR-0069 の「先の群は逼迫に依らず予約を持つ」読みを置き換え、 要件書は変えない (FR38 / AC41 の範囲)。

群の予約の 1 関数は、 先の群ごとに、 その群の今の口座の新しい実測 (古ければ今の口座だけ 1 回測る) が閾値以上の周だけ候補を測って予約を導きます。 上限に近くない先の群と実測を持たない先の群は予約を持たず、 候補を測りません。 判じる群の予約の導き方・両方が逼迫した周の宣言順 (先の群が先)・役割の行が無い周の止まり方は変えません。 移り先の無い断りの周は群用 dir に印を 1 つ (群の名・断りの時刻・理由) 書き、 同じ実測に 2 度断らない周は書き直さず、 留まる判定と記録を書く判定は在る印を history へ退避します。 doctor の群の行は印の時刻 (無ければ無し・形でなければ読めない) を予約の語の後ろに出します。 残量の鍵・門・断りの 1 行の宛先・断りの event の 1 回性・記録の形・種・便用の選定は変えません。 この記録は ADR-0069 の「先の群は逼迫に依らず予約を持つ」読みを置き換え、 要件書は変えません。 持ち主の裁定は、 予約をその周に逼迫している群だけに限り、 両方が逼迫した周だけ宣言順を効かせ、 断りを見える形にする、 の受諾でした。 予約の意味は「同じ周に 2 群が同じ口座へ移らない」と「両方が逼迫した周に先の群が良い方を取る」の 2 つで、 どちらも先の群が移る周にしか要りません。 移らない群が候補を塞ぐのは、 この意味から外れています。 先の群の逼迫は今の口座 1 つの実測で分かるので、 候補を全部測る呼びは要りません。 断りを群用 dir の印にするのは、 群用 dir が host で 1 つで、 どの置き場の席の doctor からも同じ file を読めるからです。 断りの 1 行を host の全席へ送る形は、 別の置き場の列挙が host 固有の path になるので採りません。 後の群が予約を奪う形は規則が 2 つになり、 口座を増やす運用は規則になりません。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

  • ●先の群が逼迫していない周は予約が無く、 その周に逼迫に転じた先の群の移り先は次の周に決まる (同じ周の候補は後の群が取っている)
