設計判断記録 (ADR) scribe2 — 検出線の費用

検出線は契約が名指した歯と package の単体の歯だけを mutant に当て、 歯の名は宣言 file の 4 つ目の穴 {teeth} で器が渡す (ADR-0021 §2.1 と ADR-0050 の穴の閉じた 3 つを部分 supersede・R-C12-1 の記録の母集団を「契約の歯 + 単体の歯」に狭める)

変異検査は mutant 1 つごとに package の歯を全部回す。 e2e の歯しか持たない契約では、 撃墜が決まった後も e2e の binary を最後まで回すので mutant 1 つが 44 秒、 枠を待ち切れず 1 thread に縮退した周は 6 分になり、 gate 1 本が 12 分から 8 時間に及んだ。 本 ADR は mutant に当てる歯を「契約が名指した歯と package の単体の歯」に閉じ、 歯の名を器が宣言 file の穴で道具へ渡す。

この判断が約束すること (1 文サマリ)

変異検査は、code をわざと少し壊した版（mutant）を 1 つずつ作り、test がそれを見つけられるかを確かめる仕組みです。いまは mutant を 1 つ作るたびに package の test を全部回していました。e2e の test しか持たない契約では、最初の 3 秒で答えが出ているのに e2e の test 全体を 44 秒かけて回し、混んで同時実行数が 1 に落ちた回は 6 分かかり、検査 1 本が 8 時間に及ぶこともありました。そこで、mutant ごとに回す test を「その契約が名指した test」と「package の単体の test」だけに閉じます。契約が名指した test の名前は器が契約から導き、宣言 file の 4 つ目の差し込み口で道具へ渡します。検査は gate の中に残るので、審査役はこれまでどおり生き残った mutant を材料にできます。代わりに、契約が名指していない e2e の test だけが見つけられる壊し方は「生き残り」として数えられるようになるので、その事実を記録の欄に残します。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、実測と現物から説明します。mutant 1 つの費用の 9 割超は答えが出た後の test の走行で、混んで 1 に絞られた回は 20 倍かかりました。変異の生き残りを止める規則の行はいま記録だけの状態で、検査は審査役の材料と記録のために走っています。契約から test の名前を導く口は器に既に在り、道具には test を選ぶ式の口が在ります。

CTX1

実測 — mutant 1 つの費用の 9 割超は、 判定に寄与しない歯の走行

2026-09-21 の便 (台帳 s2-07l.516 の再 gate・67 mutants・4 job × 8 thread) の outcomes は、 撃墜 52・生存 7・compile 不能 7 で、 mutant 1 つの test phase の中央値は 43.7 秒だった。 その契約の歯は e2e の binary にしか無く、 e2e の binary は package の e2e の歯を全部 (数百本) 走らせる。 別の便 (台帳 s2-07l.511・58 mutants) では単体の歯が 3 秒で落ちているのに e2e を最後まで回して 320〜410 秒を払っていた。 mutant の cargo test を fail-fast にする直し (台帳 s2-07l.518・同日着地) は単体の歯で落ちる契約にしか効かず、 s2-07l.516 の再 gate は 755 秒から 714 秒にしか縮まなかった。

CTX2

実測 — 枠を待ち切れず縮退した周は同じ mutant が 20 倍かかる

受付の枠を gate.slot_wait_s (900 秒) の間に取れなかった周は 1 job かつ 1 thread に縮退する (ADR-0050 の形)。 1 thread では e2e の binary が直列になり mutant 1 つが約 6 分で、 同日の 2 便 (台帳 s2-07l.511 / s2-07l.517) は 58 と 83 の mutants に 5〜8 時間の見込みとなり、 席が止めた。 gate 1 本の長さ (20〜30 分) が待ちの上限より長いので、 列の 2 本目は必ず縮退する。 上限の値は別の裁定 (本 ADR の外) だが、 mutant 1 つの費用が下がればどちらの周も短くなる。

CTX3

現物 — 検出線の記録の極性と、 穴の閉じた集合

変異の生存を止める rules 行 R-C12-1 は enabled = false で、 値は「週次記録 (deny 化の裁定材料は実測 2 周分)」である。 検出線は gate を落とす線ではなく、 審査役 (lens) が歯の空虚さを判じる材料と記録のために走っている。 宣言 file の検出線が置ける穴は {base} と {jobs} と {threads} の閉じた 3 つ (ADR-0021 §2.1・ADR-0050) で、 intake の判定と gate の置換が同じ 1 列を見る。 契約の verify 行から歯の名 (filter の語) を導く口は器の受付に既に在り、 preflight は「teeth=<filter>:<本数>@<file>」として出す。

CTX4

現物 — 道具の filter の口

cargo-mutants は mutant ごとの test の道具を cargo test か nextest から選べ、 1 つ目の -- の後ろの引数を道具へ逐語で渡す。 cargo test の位置引数の filter は package の全 binary に同じ filter が掛かるので「単体の歯は全部・e2e の歯は名指した分だけ」を 1 行で表せない。 nextest は filter の式どの test を走らせるかを 1 行で選ぶ書き方 (歯の種類と名の正規表現の和) を持ち、 同じ 1 行で「lib の歯 ∪ bin の歯 ∪ 名が語で始まる歯」を選べる。 thread は nextest の引数で渡す。

CTX5

user の裁定と憲法の向き

user の裁定 (要旨・逐語は台帳 s2-07l.519 の notes) は「5〜7 時間は許容できない」と、 2 案 (A = 契約の歯だけを mutant に当てる・B = 検出線を gate の外へ出す) のうち A である。 憲法は、 検出線が変異の生存を記録し deny への昇格は user の裁定でだけ行うこと (C12.4)、 宣言値と測定値と実効値を型で分け測定なしに実効へ上げないこと (C10)、 環境変数で子 process へ値を渡さないこと (C2.2)、 足す前に消すものを名指すこと (C17) を求める。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。mutant 1 つの費用を答えを変えうる走行だけにすること、検査を gate の中に残して審査役が生き残りを見られること、test の名前の出所を器の 1 か所にして道具は受け取るだけにすること、そして検査の範囲が狭まった事実を黙らずに記録に残すことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。差し込み口を足して単体の test と契約の test だけを回す案、検査を gate の外へ出す案、契約の test だけにして単体の test も外す案、道具が契約を自分で読む案、道具を変えず位置引数で絞る案、そして何も変えず同時本数を増やす案です。

OPT1宣言 file の検出線に穴 {teeth} を足し、 mutant の test を「単体の歯 ∪ bin の歯 ∪ 契約が名指した歯」の filter で回す採用

器が契約の verify 行から導いた歯の名の列を穴 {teeth} で検出線の行へ渡す。 道具は mutant ごとの test を nextest の filter で「lib の歯 ∪ bin の歯 ∪ 名がその語で始まる歯」に閉じる。 baseline は従来どおり道具の外で全数 (fail-fast にしない)。 記録の 1 行に語の数を足す。

宣言 file の検査の行に 4 つ目の差し込み口を足し、器が契約から導いた test の名前をそこへ入れる案です。道具は mutant ごとに、package の単体の test と bin の test は全部、e2e の test は名指された分だけを回します。変異を当てない最初の 1 回は従来どおり全部回して、時間切れの目安もそこから取ります。記録には名指した名前の数を足して、検査の範囲が狭まったことを残します。

+ 利点

  • e2e の歯しか持たない契約で mutant 1 つが 44 秒から数秒になる (e2e は名指した数本だけ)
  • 検出線が gate の中に残り、 審査役は生存 mutant を材料にできる
  • 歯の名の導出は受付の既存の 1 本を使い回し、 道具は値を持たない (thread と同じ形)
  • 縮退した周 (1 thread) でも e2e の直列の費用がほぼ消える

− 欠点

  • 検出の母集団が狭まる — 契約が名指さない e2e の歯だけが捕まえる mutant は生存に数えられ、 生存の数は増えうる
  • 穴が 1 つ増えるので intake の閉じた集合と gate の置換と宣言 file の行が動き、 着地は道具 (PATH の binary) の入れ替えを伴う
  • mutant の test の道具が cargo test から nextest に変わり、 baseline (cargo test) と test の道具が違う
OPT2検出線を gate の外へ出し、 着地した木に後追いで 1 回当てる不採用

gate は共通 verify と契約の歯だけで通し、 変異検査は着地の後に走らせて記録だけ残す。

変異検査を gate から外し、変更を本線に載せた後にまとめて 1 回だけ行う案です。gate はいちばん短くなりますが、審査役が審査の時点で生き残りを見られなくなり、中身のない test を機械で拾う力が弱くなります。載せた後に生き残りが出たときの戻し方も要ります。user の裁定はこの案を採りませんでした。

+ 利点

  • gate の壁時計が最も短くなる (検出線の秒が 0)
  • 穴も道具の filter も要らない

− 欠点

  • 審査役が審査の時点で生存 mutant を見られず、 歯の空虚さを機械で拾う面が弱くなる
  • 着地の後に生存が出た周の戻し方が要る (main を常に緑に保つ形と噛み合わない・ADR-0050 OPT2 と同じ却下理由)
  • user の裁定が A を採った
OPT3mutant の test を契約が名指した歯だけにする (単体の歯も回さない)不採用

filter を契約の verify 行の歯だけにし、 package の lib と bin の歯は回さない。

mutant ごとに回す test を、契約が名指した test だけにして、単体の test も回さない案です。いちばん速いのですが、既にある単体の test が見つけられる壊し方まで全部「生き残り」に数えられてしまい、記録が実態より悪く見えます。単体の test は 3 秒で回るので、外して得る時間もほとんどありません。

+ 利点

  • 最も速い (歯の数が最小)
  • 契約の歯の空虚さだけを測る形が最も純粋

− 欠点

  • 既存の単体の歯が捕まえる mutant (共有 code の変更) が全部生存に数えられ、 記録の生存が実態より大きく出る
  • 単体の歯は 3 秒で回るので、 外して得る秒がほぼ無い
OPT4道具が契約の verify 行を自分で読んで歯の名を導く不採用

xtask が run dir や契約 file を環境変数か既定の path で見つけ、 verify 行から filter を組む。

道具（xtask）が自分で契約の file を探して、test の名前を組み立てる案です。差し込み口は増えませんが、名前を導く仕組みが器と道具の 2 か所になり、道具が契約の置き場を知るには環境変数か暗黙の path が要ります。契約の無い場面で道具だけを撃つときの既定も別に決めなければなりません。

+ 利点

  • 宣言 file の穴が増えない

− 欠点

  • 導出の正本が器と道具の 2 か所になる (thread の導出を器の 1 か所に寄せた ADR-0050 の向きに反する)
  • 道具が run dir の置き場を知るには環境変数か暗黙の path が要る (C2.2 の裏口)
  • CI で道具を単独で撃つ周 (契約の無い周) の既定が別に要る
OPT5cargo test の位置引数の filter で歯を絞る不採用

道具を変えず、 cargo test に歯の名の列を位置引数で渡す。

道具を変えずに、cargo test に test の名前を並べて渡す案です。ただしその絞り方は package の全部の test の入れ物に同じように掛かるので、単体の test まで名前で絞られてしまい、結局「単体は全部・e2e は名指した分だけ」を表せません。

+ 利点

  • 道具の入れ替えが無い

− 欠点

  • 位置引数の filter は package の全 binary に同じ filter が掛かるので、 単体の歯まで名指した語で絞られる (OPT3 と同じ母集団になる)
  • 「lib は全部・e2e は名指した分だけ」を 1 行で表せない
OPT6何も変えず並列度の上限を上げる不採用

gate.mutants_jobs を上げ、 mutant ごとの費用はそのままに同時本数で稼ぐ。

何も変えず、同時に走らせる本数の上限を上げて時間を稼ぐ案です。同時本数は core の数で頭打ちになるうえ、1 つの mutant にかかる 44 秒そのものは短くなりません。混んで 1 に絞られた回には何も効かず、e2e の test が増えるほど費用も増え続けます。

+ 利点

  • 設計も道具も動かない

− 欠点

  • 並列度は core 数で頭打ちで (ADR-0050 の受付)、 e2e の binary の 44 秒は 1 本ずつには効かない
  • 縮退した周 (1 job・1 thread) には何も効かない
  • 費用が e2e の歯の本数に比例したまま増え続ける
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、それが要件書のどの要件を支えるかを示します。宣言 file の差し込み口は 4 つになり、器が契約から導いた test の名前をそこへ入れます。道具は mutant ごとに単体の test と bin の test と名指された test だけを回し、変異を当てない最初の 1 回（baseline）は従来どおり全部回します。記録には名指した名前の数を足します。

採用 — OPT1

宣言 file の検出線が置ける穴 SHALL {base} と {jobs} と {threads} と {teeth} の閉じた 4 つとし (ADR-0021 §2.1 と ADR-0050 の閉じた 3 つを置き換える)、 契約の verify 行には従来どおり穴を置かない。 {teeth} の値 SHALL 器が契約の verify 行から導いた歯の名の列 (filter の語) とし、 導出 SHALL 受付が preflight で既に使う同じ 1 本を通す (正本は器の 1 か所)。 語が 1 つも無い周 SHALL 空を表す閉じた 1 語で埋める。 道具 (xtask の mutants-diff) SHALL 受けた語をそのまま使い、 mutant ごとの test を nextest で走らせ、 走らせる歯を「package の lib の歯 ∪ bin の歯 ∪ 名が受けた語のどれかで始まる歯」に閉じる (e2e の歯は契約が名指した分だけ)。 空の周 SHALL lib の歯 ∪ bin の歯だけとする。 thread SHALL nextest の引数で渡す (値は従来どおり穴 {threads} から)。 baseline SHALL 従来どおり道具の外で 1 回、 package の歯を全数、 fail-fast にせず走らせ、 timeout の導出も変えない。 記録の 1 行 SHALL 語の数を運ぶ欄を末尾に足し、 検出の母集団が狭まった事実を残す (C10)。 R-C12-1 が記録する変異の生存 SHALL 「契約が名指した歯と package の単体の歯が捕まえない mutant」と読む (C12.4 の記録の母集団の読み替え・deny への昇格の手続きは不変)。 器 SHALL NOT 検出線を gate の外へ出さない。 器 SHALL NOT 歯の名を環境変数で道具へ渡さない (C2.2)。 器 SHALL NOT 本 ADR で新しい rules 行を足さない。

宣言 file の検査の行に置ける差し込み口を、便の base・並列の本数・同時実行数・契約の test の名前の 4 つにします。契約の行にはこれまでどおり差し込み口を置きません。test の名前は器が契約の検証の行から導き、その導き方は受付が事前確認で既に使っている 1 本を使い回します。名前が 1 つも無いときは「無い」を表す決まった 1 語を入れます。道具は受け取った名前をそのまま使い、mutant ごとの test を nextest で走らせて、単体の test と bin の test は全部、それ以外は名前がその語で始まる test だけを回します。名前が無いときは単体と bin だけです。同時実行数は nextest の引数で渡します。変異を当てない最初の 1 回は従来どおり道具の外で全部回し、途中で止めず、時間切れの目安もそこから導きます。記録の 1 行には名前の数を足して、検査の範囲が狭まった事実を残します。規則の行が記録する「変異の生き残り」は、契約が名指した test と単体の test が見つけられなかった mutant、と読み替えます。検査を gate の外へは出さず、名前を環境変数で渡さず、新しい規則の行も足しません。 mutant 1 つの費用の 9 割超は、答えが出た後や答えに届かない test の走行でした。答えを変えうるのは、その契約が名指した test と、壊した場所の周りにある単体の test です。ですから回す test をその 2 つに閉じれば、検査の意味を保ったまま費用だけが消えます。検査を gate の外へ出さないのは、審査役が生き残りを材料にする面を残すためで、user の裁定もそちらを採りました。名前を器が導いて差し込み口で渡すのは、同時実行数を渡すときと同じ形で、導き方の正本を 1 か所に保ち、道具に裏口を作らないためです。範囲が狭まったことを記録に残すのは、生き残りの数が裁定の材料だからで、黙って狭めると材料の意味が変わってしまいます。
