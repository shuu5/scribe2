設計判断記録 (ADR) scribe2 — 群の移動の退避の猶予

群の移動の退避は合図が先で /exit は猶予の後 — 群が別の口座へ移った周に古い席へ送るのは退避の合図の 1 行で、 /exit は猶予 (rules 行 1 本・起点は群の記録の時刻) を越えた周に送り、 合図は席ごとの記録 1 つで移動につき 1 回、 群の段の続きの周も同じ猶予を読む (ADR-0066 の移動の門と ADR-0068 の梯子は前提のまま・要件は FR38 / AC41 の範囲)

ADR-0066 は群の移動の判定を管理 tick に置き、 移った周は各席の tick が自席に退避 (/exit) を撃つと決めた。 席が前面で作業中なら /exit は turn の終わりまで待つが、 席が裏で走らせる subagent は席の turn が先に終わるため待たれず、 次の周の /exit で claude ごと落ちる。 2026-09-26 に別 project の設計席がこれを 3 回観測して報告し、 持ち主は「合図 → 猶予 → /exit」の二段の退避を裁定した (06:29Z)。 限度を越えた口座で席が猶予の分だけ動き続ける害を、 走行中の作業を毎回落とす害より小さいと判断した。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「群」はある project の席が使う口座の集まり、 「見回り (管理 tick)」は席の外から周期で席を見る仕組み、 「subagent」は席が起こす下請けの agent です。 群が別の口座へ移ると、 古い口座の席は終わらせて新しい口座で起こし直します。 これまで見回りは移った 15 秒後に古い席へ /exit を送っていました。 席が前面で作業中なら /exit は作業の区切りまで待ちますが、 席が裏で走らせている subagent は待たれず、 途中で落ちていました。 この記録は、 移った周にまず「退避の合図」の 1 行を送り、 /exit は猶予 (規則の表の行 1 本・既定 30 分・起点は群の記録の時刻) を越えてから送ると決めます。 合図は席ごとの記録 1 つで移動につき 1 回だけ送り、 便の終端の周 (群の段) も同じ猶予を読みます。 持ち主は 2026-09-26 に、 限度を越えた口座で席が猶予の分だけ動き続ける害を受け入れると裁定しました。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (移った周の退避の今の形)・事象 (裏の subagent が落ちた)・器の今の部品・これまでの決まり・この判断の範囲の 5 つから説明します。 前の決定 (ADR-0066) は群の移動の判定を見回りに置き、 移った周は各席の見回りが自席へ退避 (/exit) を撃つと決めました。 設計はさらに、 移動の周は席の状態の打刻を読まずに /exit を周期ごとに送ると決めました (打刻を失った席が移らない穴を塞ぐため)。 2026-09-26 に別 project の席が、 移動のたびに裏で走らせていた subagent が途中で消えたと報告し、 本席が機序を再現しました。 部品は見回りの移動の門・群の段の退避・群の記録・規則の表の行です。

CTX1

経緯 — 移った周の退避は各席の tick が撃ち、 打刻を読まずに /exit を送る (ADR-0066・設計 §10)

ADR-0066 は群の移動の判定 (逼迫の読み・移り先・記録・承認 event) を管理 tick席を周期で見る仕組み に置き、 判定の後は各席の tick の移動の門移る周の tick の段が自席にだけ退避 (/exit・確認 dialog なら Enter) か起こし直しを撃つと決めた。 設計 seat-heartbeat.md §10 (形 8〜10) はさらに、 移動の周は席の状態の打刻 (Busy / Idle) を読まずに /exit を周期ごとに送ると決めた。 上限の error で終わった turn が Busy の打刻を残し、 打刻に依る門では席が移らない穴 (台帳 s2-07l.635) を塞ぐためである。 turn の途中に送った /exit は claude の入力の列に積まれ turn の終わりで実行されるので、 前面の作業は落ちない、 が根拠だった。

CTX2

事象 — 席が裏で走らせる subagent席が起こす下請けの agent が移動のたびに落ちた

2026-09-26 に別 project の設計席が、 群 (口座の群) の移動 3 回のたびに席が /exit → 起こし直しされ、 そのとき席が走らせていた subagent (制作の便・20〜40 分) が 3 回とも途中で消えたと報告した。 出力は file に残るが途中の状態で止まり、 席は毎回起こし直しの後に点検からやり直した。 席の状態の打刻が busy と記されていた周でも退避が撃たれていた。 本席は現物で再現した — 打刻を読まないのは設計どおり (形 8・形 10) で、 機序は形 9 の外側に在る。 Agent tool の subagent は background で走り、 席の turn は subagent の完了を待たずに終わる。 turn が終わると入力欄が空に戻り、 次の周 (15 秒) の /exit が即実行され、 claude の process ごと subagent が落ちる。 「turn の終わりで実行」は前面の turn だけを守っていた。

CTX3

現物 — tick の移動の門・群の段の退避・群の記録・rules 行

main 735c7f4 で、 管理 tick の移動の周 (seat/tick.rs の moving) は群の記録群の今の口座の控えの口座と自席の登録 row の口座が違う周に、 lock の内側で退避 (evacuate = 入力欄の門 → /exit の 1 行・dialog の既定の行なら Enter・記録は tick.jsonl に who=seat-tick-move) を撃つ。 判定で移った周も同じ関数を撃つ。 手の語移動の周の判定行の語 (Move) は launch / exit / enter の閉じた 3 値。 群の段 (pipe/dispatch/group.rs) は移動の周に古い口座の席へ退避の合図移るための席への 1 行の 1 行 (字面は群の段の中の format!) を送って起動の待ち (settle) を置き、 続きの周群の段の 2 周目以降に shell へ戻らない席へ /exit を 1 回送る。 群の記録 (hook/group.rs の Record) は口座・時刻 (UTC 秒の字面)・理由・前の口座の 4 行で、 読み手 current_of は口座と出所だけを返して時刻を落とす。 時刻の字面を UNIX 秒にする読み手 (fleet/wait.rs の epoch_of) と tick の今 (seat/state.rs の now_secs) は在る。 rules 行は周期・黙りの初段・梯子の列・送達の窓・群の閾値を tick が読み、 欠く周は rc 1 で語 no-rule。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C2 (経路は 1 本) から、 猶予の判定・合図の字面・合図の記録の書き手はそれぞれ 1 関数で、 tick と群の段が同じものを読む。 C10 (宣言値・実測値・導出値を分ける) から、 猶予は rules 行の宣言値、 起点は群の記録の時刻 (実測値)、 残りの秒はその導出値で、 時刻の字面が形でない記録は読めない記録として断る (数の読み替えをしない)。 C17 (足すときに何を外すかを名指す) から、 足すのは rules 行 1 本・合図の記録 1 file・Move の変種 2 つ・関数 3 本で、 外すのは群の段の中の合図の字面 (hook/group.rs へ移す) である。 決定はしごの各段を通した — 要るか (走行中の作業が毎回落ちる)・既に在るか (群の段の合図は在るが tick の周には無く、 /exit を待たせる口も無い)・既存の記録で足りるか (群の記録の時刻を起点にすれば猶予の起点は足りる・合図の 1 回性だけ席ごとの記録 1 つが要る)・1 行で書けるか (合図の記録合図を送った印は 1 行)・最小か (rules 行 1 本と file 1 つ)。 N2 (散文にしか無い規則は規則として扱わない) から、 席の側の作法 (新しい subagent を起こさず今のを待つ) は合図の字面が伝える案内であって規則ではない。 ADR-0066 の判定の置き場と移動の門、 ADR-0067 の起こし直し (会話 id を運ぶ)、 ADR-0068 の梯子、 ADR-0069 の移り先の鍵は本 ADR の前提で変えない。

CTX5

射程 — 動かすのは退避の順と猶予・合図の 1 回性・群の段の続きの周の 3 か所

動かすのは (1) tick の移動の周の退避の順 (合図が先・/exit は猶予の後・猶予は rules 行 seat.move_grace_s・起点は群の記録の時刻・値 0 は今の形)、 (2) 合図の 1 回性 (席の状態の dir の合図の記録 1 file に群の記録の時刻を書き、 同じ時刻の記録が在れば送らない・群の段の合図も同じ記録を書く)、 (3) 群の段の続きの周 (/exit は猶予を越えた周だけ) の 3 つ。 動かさないのは、 判定の列の順と移動の周の位置 (打刻を読まない)・lock・起こし直し・梯子・heartbeat の停止・status と doctor の項目・event の種類・rules 行の他の値。 要件は FR38 (群の移動) と AC41 (古い席に退避の合図が届く) の範囲に収まり、 SRS の改訂を伴わない。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 走行中の作業を落とさないこと (裏の subagent が移動のたびに途中で消える害を無くす)。 限度を越えた口座で動き続ける時間に上限を置くこと (猶予は規則の表の行 1 本で、 越えた周は今どおり /exit を送る)。 打刻に依らないこと (席の自己申告や状態の打刻で待つと、 打刻を失った席が移らない穴が戻る)。 経路は 1 本であること (猶予の判定・合図の字面・合図の記録の書き手はそれぞれ 1 関数で、 見回りと群の段が同じものを読む)。

DR1走行中の作業を落とさない — 席が裏で走らせる subagent が移動のたびに途中で消える害を無くす (持ち主の裁定) CTX2・CTX5
DR2限度を越えた口座で動き続ける時間に上限を置く — 猶予は rules 行 1 本の宣言値で、 越えた周は今どおり /exit を送る CTX1・CTX4
DR3打刻に依らない — 席の自己申告や状態の打刻で待つと、 打刻を失った席が移らない穴 (台帳 .635) が戻る CTX1・CTX4
DR4経路は 1 本 — 猶予の判定・合図の字面・合図の記録の書き手はそれぞれ 1 関数で、 tick と群の段が同じものを読む (C2・C17) CTX3・CTX4
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 合図が先・/exit は猶予の後・合図は席ごとの記録 1 つで移動につき 1 回とする案 (選んだ案)、 席が「作業中」の札を自分で書き見回りが待つ案、 器を変えず subagent の出力を file に落とす案、 見回りが subagent の有無を process の木で読む案、 猶予を群の段の起動の待ちの窓で持つ案です。 選ばなかった 4 つは、 自己申告の穴・損失が毎回・見えない・意味が別、 という理由で退けました。

OPT1二段の退避 — 合図が先・/exit は猶予の後・合図は席ごとの記録 1 つで移動につき 1 回採用

rules 行 seat.move_grace_s (整数の秒・既定 1800・裁定 id つき) を足す。 tick の移動の周は、 群の記録の時刻 + 猶予 − 今 が正なら「残りが在る」と読み、 合図の記録 (席の状態の dir の move-signal・1 行 ts=<群の記録の時刻>) が同じ時刻を持たない周は退避の合図の 1 行 (字面は hook/group.rs の 1 関数・群の段と共通・残りの秒を載せる) を入力欄が空なら送って記録を書き、 同じ時刻を持つ周は待つ (0 key)。 残りが無い周 (猶予 0・越えた・記録なし = 種) は今の形 (/exit・dialog なら Enter)。 群の段の移動の周は同じ字面の合図を送って席ごとに記録を書き、 続きの周の /exit は残りが無い周だけ。 手の語に signal / wait を足す。 決め手は現物 (持ち主の裁定)。

移った周にまず退避の合図の 1 行を送り、 /exit は猶予 (規則の表の行 1 本・既定 30 分) を越えてから送る案です。 猶予の起点は器が書く群の記録の時刻で、 合図は席ごとの記録 1 つで移動につき 1 回だけ送ります。 猶予が残っていない周 (猶予 0・越えた・記録なし) は今どおり /exit です。 群の段の続きの周も同じ猶予を読みます。 裏の subagent は猶予の間に終われ、 限度を越えた口座で動き続ける時間は猶予が上限で、 打刻も自己申告も読まず、 判定・字面・記録の書き手は 1 関数ずつです。 代わりに、 席の dir に file が 1 つと規則の表に行が 1 本増え、 猶予の間は限度を越えた口座で席が動き、 席の作法は案内で器が強制できません。 持ち主の裁定で選びました。

+ 利点

  • 席が裏で走らせる subagent は猶予の間に終われ、 席は合図で新しい subagent を起こすのを止められる (DR1)
  • 限度を越えた口座で動き続ける時間は猶予の値が上限で、 越えれば今どおり /exit が届く (DR2)
  • 打刻も席の自己申告も読まず、 起点は器が書く群の記録の時刻で、 打刻を失った席も猶予の後に必ず移る (DR3)
  • 猶予の判定・合図の字面・記録の書き手が 1 関数ずつで、 tick と群の段が同じ字面と同じ記録を使う (DR4)

− 欠点

  • 席の状態の dir に file が 1 つ増え (合図の記録)、 rules 行が 1 本増える
  • 猶予の間 (既定 30 分) は限度を越えた口座で席が動き続ける
  • 合図の送達が入力欄の門で断られた周は次の周に送り直すが、 席が合図を読むのは次の turn の頭で、 席の作法 (新しい subagent を起こさない) は案内であって器は強制できない
OPT2席が「作業中」の札を自分で書き、 tick が札の在る間は /exit を待つ不採用

席の状態の dir に席自身が作業中の記録を置き、 tick は在る間は退避しない。 決め手は分析 (自己申告の穴)。

席が「いま作業中」の札を自分で書き、 見回りは札が在る間は /exit を待つ案です。 席が自分の区切りを最も正確に知っている点で勝ります。 けれども、 書き忘れ・消し忘れ・落ちた席が残した札で移動が止まり、 打刻を失った席が移らない穴 (台帳 .635) と同じ形になります。 上限も無く、 限度を越えた口座で動き続ける時間を器が抑えられません。 退けました。

+ 利点

  • 席が自分の区切りを最も正確に知っている

− 欠点

  • 書き忘れ・消し忘れ・落ちた席の残した札で移動が止まり、 打刻を失った席が移らない穴 (台帳 .635) と同型になる (DR3)
  • 上限が無く、 限度を越えた口座で動き続ける時間を器が抑えられない (DR2)
OPT3現状維持 — subagent の出力を file に落とし、 起こし直した席が file から拾う不採用

器は変えず、 席の運用で損失を小さくする。 決め手は分析 (損失は毎回)。

器は変えず、 subagent の出力を file に落として起こし直した席が file から拾う運用にする案です。 器に足すものが無く、 限度を越えた口座は 15 秒で止まる点で勝ります。 けれども、 走行中の便は毎回途中で落ち、 席は起こし直しの後に点検からやり直します。 損失は移動のたびに繰り返し、 file に落とす作法も席の側の案内で器が保証できません。 退けました。

+ 利点

  • 器に足すものが無く、 限度を越えた口座は 1 周 (15 秒) で止まる (DR2)

− 欠点

  • 走行中の便は毎回途中で落ち、 席は起こし直しの後に点検からやり直す。 損失は移動のたびに繰り返す (DR1)
  • 出力を file に落とす作法は席の側の案内で、 器が保証できない (DR3)
OPT4tick が subagent の有無を process の木で読み、 在る間は待つ不採用

窓が shell かの判定 (子 process まで見る・設計 §6) と同じ読みで、 claude の下に subagent が在れば待つ。 決め手は分析 (見えない)。

見回りが subagent の有無を process の木で読み、 在る間は待つ案です。 席の作法に依らず器が実測で待てる点で勝ります。 けれども、 Agent tool の subagent は claude の process の内側で走り、 process の木には現れません (Bash の子 process しか見えません)。 見えたとしても上限が無く、 長い Bash が在る限り移動が止まります。 退けました。

+ 利点

  • 席の作法に依らず器が実測で待てる

− 欠点

  • Agent tool の subagent は claude の process の内側で走り、 process の木には現れない (Bash の子 process しか見えない) (DR1)
  • 見えたとしても上限が無く、 長い Bash が在る限り移動が止まる (DR2)
OPT5猶予を群の段の settle の窓で持つ (合図 → settle → /exit)不採用

群の段は既に合図 → 起動の待ち (settle) の順で撃つので、 その窓を伸ばして tick の /exit もそれに合わせる。 決め手は分析 (意味が別)。

群の段は既に「合図 → 起動の待ち (settle)」の順で撃つので、 その待ちの窓を伸ばして見回りの /exit もそれに合わせる案です。 規則の表に行を足さない点で勝ります。 けれども、 起動の待ちは「窓が shell に戻るのを待つ秒」で、 退避の猶予とは別の量です。 1 つの値に 2 つの意味を持たせると片方を変えると片方が壊れます。 見回りの周は群の段の待ちを読まず、 群の段は便の終端にしか回らないので、 猶予には見回りが周ごとに読める起点 (群の記録の時刻) が要ります。 退けました。

+ 利点

− 欠点

  • settle は「窓が shell に戻るのを待つ秒」で、 起動の待ちと退避の猶予/exit までの待ち時間は別の量。 1 つの値に 2 つの意味を持たせると片方を変えると片方が壊れる (DR4)
