§1. Context

口座の残りを読む口 (ADR-0017) は、 各窓の「使用率」と「いつ元に戻るか (reset 時刻)」の 2 つが揃って初めて「測れた」としていました。 ところが口座の endpoint は、 その窓にまだ消費が無い口座に対して「使用率 0・reset は無し (null)」を返します。 器はこれを「形が違う＝測れなかった」と記録し、 口座の選定は「測れない口座は選ばない」規則でその口座を外します。 結果、 使い始めていない口座ほど便に選ばれず、 使い始めなければ 5 時間窓に消費が乗らないので永久に選ばれません。 並列の便が 1 口座に閉じ、 席の立て直しの候補も痩せました。 この記録は、 消費の無い窓を「測れた 0%・reset 未定」として正直に記録し、 選定がそれを数えるように形を決めます。

記録時点 (2026-09-13) の現物 (main 1658d79): 口座の endpoint の応答は five_hour / seven_day = {utilization: 数, resets_at: 文字列} (設計 docs/design/fleet-usage.md §3) と設計されているが、 5 時間窓に消費の無い口座では five_hour = {utilization: 0.0, resets_at: null} が返る (管理席の実測・3 口座で同形・使い始めた口座は同じ周から文字列になる)。 fleet/usage.rs の reading() は resets_at を文字列必須で読み (node.get("resets_at")?.as_str()?)、 欠けは UnmeasuredReason::ShapeMismatch の AllowanceUnmeasured 行になる。 fleet/select.rs の fresh_windows() は「数える窓に Unmeasured が在れば測れない口座」として候補から外し (設計 account-autonomy.md §3・C10)、 seat/tick.rs の pressure() も同じ数え方で逼迫度を None にする。 EventKind::AllowanceMeasured の resets_at は String 必須 (fleet/mod.rs)。 実害: 便用の候補が使用中の 1 口座に閉じ (fleet select --purpose run = 1 口座・除くと none=all-limited)、 user 直命の 4 便並列が成立しない。 席の立て直し (FR38・AC13) の候補も同じ理由で痩せる。

憲法の向き: C10 は宣言値・出所付き実測値・導出値・有効値を型で分ける。 「消費が無く reset が予定されていない」は endpoint が返した実測であって「測れなかった」ではなく、 reset 時刻を計測 ts + 窓長で埋める形は実測行に導出値を混ぜる。 C9.2 は各口座を allowance 窓の終わりまで使い切ると定め、 消費 0 の口座を選べない形はその逆に倒れる。 C11.3 は core で untyped な error を持たず、 C3 は fleet の状態を 1 つの file に置く。 先行決定: ADR-0017 §2.1 は実測行が使用率と reset 時刻を持つと定め、 ADR-0004 §2.5 D-5 は「同じ schema 番号なら既存の行はすべて読める」と定める (field を足す・必須を任意へ緩めるはこの内側・run / bead を任意へ緩めた前例が ADR-0017 §2.1 に在る)。 ADR-0020 §2.2 / §2.3 は選定の純関数と「候補なしの周は最も早い reset まで待つ」を定める。

§2. Decision

§2.1 実測行の reset 時刻は任意。 消費の無い窓は「測れた 0%・reset 未定」の Measured 行

endpoint が「使用率 0・reset 無し」と返した窓は、 「測れなかった」ではなく「測れた。 使っていないので戻る時刻もまだ無い」として記録します。 行には使用率 0 を書き、 reset 時刻の欄は置きません。 逆に、 使用率が 0 でないのに reset 時刻が無い応答は、 endpoint の約束と食い違うので従来どおり「形が違う＝測れなかった」のままです。 0 を書けるのはこの 1 形だけです。

器 SHALL AllowanceMeasured 行の resets_at を任意 fieldとする。 応答の窓が utilization (数) を持ち resets_at が null (または不在) である周、 器 SHALL その窓を AllowanceMeasured (used_pct = 読んだ整数 %・resets_at 無し) として記録する。 この形 SHALL used_pct が 0 の周に限る: utilization が 0 でなく resets_at が無い応答は endpoint の契約 (消費が在れば reset が予定される) と食い違うので、 従来どおり AllowanceUnmeasured (理由 ShapeMismatch) とする (「0 に読み替えない」の逆向き＝0 以外を reset 無しで記録しない)。 出所 3 つ (ts / account / endpoint)・window・model の規則は ADR-0017 §2.1 のまま。 AllowanceUnmeasured 行が used_pct を持てば malformed のまま (構造で 0 の捏造を拒む)。 型の側: Measured::resets_at SHALL Option<String> とし、 「reset 無し」を空文字・番兵の文字列・遠未来の時刻で表してはならない (MUST NOT・C10「型で分ける」・C11.3)。 stdout の 1 行表示 (fleet usage の外形) SHALL reset 無しを明示の字面 (例: resets=none・字面は外形 snapshot が正本) で出し、 時刻の欄を空にしない。

§2.2 選定と逼迫度は reset 無しの行を古くない実測として数え、 最も早い reset の導出には数えない

口座を選ぶ計算と「どれだけ逼迫しているか」の計算は、 reset 時刻の無い行を「古くなっていない実測」として数えます。 使っていない窓は 0% のまま有効で、 時刻が過ぎて古くなることが無いからです。 候補が無いときに「いちばん早く戻る時刻まで待つ」計算には、 この行は入れません。 戻る時刻が無い窓は上限に当たっていないので、 待つ理由になりません。

選定の純関数 (fleet/select.rs・ADR-0020 §2.2) と tick の逼迫度 (seat/tick.rs・設計 account-autonomy.md §3 / §5) は、 resets_at を持たない AllowanceMeasured 行を SHALL 古くない実測として数える (「reset 時刻を過ぎた古い行は数えない」の規則は reset 時刻を持つ行にだけ掛かる)。 その行の used_pct SHALL 逼迫度の最大の計算に入る (0 なので最大を動かさないが、 「数える窓が 1 つも無い＝測れない」には倒れない)。 候補なしの周の最も早い reset 時刻 (ADR-0020 §2.3・Completion::AccountFree) の導出には、 reset 無しの行 SHALL NOT 入らない (上限に当たっている窓は必ず reset を持つ・0% の窓は待つ対象ではない)。 「当たっている」(使用率 100) の判定は不変。 便用 / session 用の 2 規則・除外・R-C9-1 の読みは ADR-0020 のまま。

§2.3 event log の schema 版は 1 のまま。 field の欠けを許すのは AllowanceMeasured の resets_at だけ

記録 file の版番号は変えません。 既に書かれた行はすべて今までどおり読めます (reset 時刻を持つ行は、 これからも持ちます)。 新しい形の行 (reset 時刻の無い行) を古い器が読むと「読めない」と止まりますが、 記録は host の中だけで使い、 器は host ごとに 1 つに揃えるので、 実害は無いと判断します。 緩めるのはこの 1 つの欄だけで、 他の欄の必須性は変えません。

event log の schema 版 SHALL 1 のまま (ADR-0004 §2.5 D-5「既存の行はすべて読める」を満たす: 本 ADR は必須を任意へ緩めるだけで、 既存の行の読みを変えない)。 必須から任意へ緩める field SHALL AllowanceMeasured の resets_at の 1 つに限る (kind ごとの必須 field の網羅 match で検査する形は不変・KNOWN_KEYS は増えない)。 前方互換の非対称を記録する: 本 ADR より前の器 (reader) が resets_at の無い AllowanceMeasured 行を読むと Err (fail-closed・ADR-0017 §2.1 のとおり) になる。 event log は host-local (C3・state dir 配下) で、 host の器は 1 つの binary に揃えて更新する運用 (doctor の版の突合・C3.2) ゆえ、 この非対称は受け入れる。 跨版 面 2 (fleet export・ADR-0004 §2.2) SHALL 変えない (allowance 行は export の外形に無い)。

§2.4 射程外

この記録が決めるのは「reset 無しの窓をどう記録し、 どう数えるか」だけです。 tick が口座の一覧を埋め込みの manifest から読んでしまう穴、 立て直しの起動経路の穴 (設定 dir・初回の trust・session を終える手)、 モデル別窓の結び方の細部、 R-C9-1 の値は、 別の契約・memo・裁定の領分です。

次は本 ADR の決定ではない (MUST NOT be read as such): tick の口座 label 列を --rules の写しから読む修正 (台帳 s2-07l.224・設計の変更を伴わない bug)、 立て直しの起動経路の 3 つの穴 (台帳 s2-07l.226・memo)、 モデル別 7 日窓の結び方 (display name・設計 doc)、 R-C9-1 の値の改訂 (A2)、 5 時間窓を選定の数える窓から外すこと (§5 (B) で却下)、 endpoint の応答の他の形 (limits[] の要素の resets_at が null になる形は実測に無く、 現れた周は ShapeMismatch のまま＝本 ADR は five_hour / seven_day の窓の object にだけ掛かる)。

§3. SRS との関係 (正本は SRS)

この記録が仕える要件は要件書 (SRS v0.8) に在ります。 要件の文面はここには置かず、 当該行を指すだけにします。 この記録は要件書を 1 字も変えません。 「reset 時刻を読む」という要件の字面は、 reset が予定されていない窓では「無いと読む」ことで満たします。

本 ADR の §2.1〜§2.3 が仕える要件は SRS v0.8 が正本である: FR33 口座残量の計測 (実測値の記録・「読めない回は理由付きの測れなかった」＝本 ADR は「読めた 0%」と「読めない」の境を reset の有無で越えない形に固定する)・FR36 口座の選定 (実測した口座残量だけから決定的に選ぶ・消費の無い口座が候補に入る)・FR38 席の退避と立て直し / AC13 (立て直しの候補が痩せない)・FR35 (5 時間窓の上限の検知は不変＝窓を外さない)。 SRS の改訂は不要: FR33 の「reset 時刻を … 読み」は endpoint が返す値を読むことであり、 値が無い窓を「無い」と読むのは要件の内側である。 実装手段 (field の任意性・Option の型・数え方) は §2 が正本で SRS は持たない。

§4. Consequences

良い面は、 使っていない口座が便と席の候補に入り、 並列の便が口座の数だけ出せること、 「測れなかった」と「使っていない」が記録の上で分かれること、 記録の版番号を変えないことです。 悪い面は、 古い器が新しい形の行を読めないこと (host ごとに器を揃える運用で受ける)、 reset 時刻を Option にする分だけ読み手 (選定・逼迫度・表示・export の歯) が分岐を 1 つずつ持つことです。

Positive: 消費の無い口座が候補に入り、 便用の選定が使用中の 1 口座に閉じない (C9.2・user 直命の 4 便並列の前提)。 席の立て直し (FR38 / AC13) の候補が痩せない。 「測れた 0%」と「測れなかった」が型で分かれる (C10)。 schema 版 1 のまま (D-5)。 rules 行を足さない (C5 非該当)。

Negative (受け入れるコスト): 前方互換の非対称 (§2.3・古い reader は新しい行を Err)。 Measured::resets_at が Option になる分の分岐 (select / tick の pressure / usage の表示 / e2e の fixture) と外形 snapshot の更新。 endpoint の「消費が無い窓は null」という振る舞いへの読み取り依存 (振る舞いが変われば ShapeMismatch に倒れる・fail-closed・止まらない)。

§5. Alternatives Considered

4 つの案を退けました。 reset 時刻を「今 + 窓の長さ」で埋める案は、 測った値に計算した値を混ぜます。 5 時間窓を選定から外す案は、 5 時間の上限を見張る要件を壊します。 「reset 無し」を測れなかった理由の 1 つにする案は、 その口座を選べない問題を解きません。 空文字や遠い未来の時刻で「無し」を表す案は、 型でなく約束事で意味を運ぶことになります。

(A) resets_at を計測 ts + 窓長 (5h / 7d) で埋めて Measured にする。 却下: 実測行に導出値を混ぜる (C10 は実測値と導出値を型で分ける)。 埋めた時刻が過ぎた周に「古い行」として数えられなくなり、 使っていない口座がまた候補から落ちる。

(B) 5 時間窓を選定・逼迫度の数える窓から外す。 却下: FR35 (5 時間窓の上限の検知) と FR38 (5 時間窓の使用率での退避) が立たない。 問題は窓ではなく「消費の無い窓の形」に在る。

(C) UnmeasuredReason に NoReset を足して Unmeasured のまま理由だけ分ける。 却下: 選定の「Unmeasured が在れば測れない口座」の規則で候補から外れたままになり、 鶏卵が残る。 理由の弁別は要るが、 それは Unmeasured ではなく Measured の側で持つべき事実 (測れている)。

(D) 「無し」を空文字・none・遠未来の時刻の文字列で表す。 却下: 値の意味を字面の約束事で運ぶ (C10「型で分ける」・C11.3 の untyped に近い)。 比較 (resets_at >= now) が偶然の順序で通る。 Option で持ち、 読み手が分岐を型で強制される形にする。

§6. Trace

出所は、 管理席が便の口座を選ぼうとして候補が 1 つしか無いことに気付き、 endpoint の生の応答まで確かめた実測と、 planner が席の立て直しを実演して同じ理由で候補が痩せることを見た実測、 そして器の現物 (読み手・選定・逼迫度・event の型) です。

  • 管理席の実測 (2026-09-13・便の口座選定): fleet select --purpose run --exclude <planner の口座> --exclude <管理席の口座> の候補が使用中の 1 口座だけ・それを除くと none=all-limited。 原因: 3 口座の five_hour が unmeasured:shape_mismatch。 endpoint の生応答は five_hour = {utilization: 0.0, resets_at: null} (3 口座とも同形・使い始めた口座は同じ周から文字列)。 台帳 s2-07l.225 の description が原本。
  • planner の実測 (2026-09-13・AC13 の実演・私用 state dir): 立て直しの候補が同じ理由で痩せる (候補 0 の直接の原因は別の穴 s2-07l.224)。 台帳 s2-07l の notes が原本。
  • 器の現物 (main 1658d79): fleet/usage.rs reading() (resets_at 文字列必須)・fleet/mod.rs Measured::resets_at: String・fleet/select.rs fresh_windows() (Unmeasured が在れば None・resets_at >= now で古さを判定)・seat/tick.rs pressure() (同じ数え方)。
  • 先行決定: ADR-0017 §2.1 (実測行の形・run / bead を任意へ緩めた前例) / §2.2 (失敗は FailOpen の Unmeasured)。 ADR-0004 §2.5 (schema 版の規則)。 ADR-0020 §2.2 / §2.3 (選定・最も早い reset まで待つ)。
  • 設計: docs/design/fleet-usage.md §3 (応答の形に null の周を足す) / §4 (event の表で resets_at を任意に)・docs/design/account-autonomy.md §3 (候補から外す規則に reset 無しの行の読みを足す)。 契約は台帳 s2-07l.225 (本 ADR の land 後に契約化)。
