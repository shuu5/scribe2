設計判断記録 (ADR) scribe2 — 着地の列と再 gate

着地の列は候補の木 1 つに対して gate を 1 回撃つ (merge train・列の先頭 N 本を順に rebase した木を 1 回検査し緑なら順に着地・赤は列を解いて 1 本ずつに戻す・検出線は patch-id が不変なら持ち越す・N は rules 行)

main が動くたびに着地待ちの便が全部の検査を撃ち直す (1 日に 29 回・便の延べ時間の 43% が gate)。 着地の列の先頭 N 本を 1 つの候補の木に積んで検査を 1 回にし、 赤の周だけ 1 本ずつに戻す。 便ごとの記録と着地の順序は変えない。

この判断が約束すること (1 文サマリ)

着地を待つ便の並び（着地の列）の先頭から数本を、main に順に積んだ 1 つの作業木にまとめ、検査をその木に 1 回だけ撃ちます。緑なら順に着地し、赤なら列を解いて今までどおり 1 本ずつに戻します。便の記録と着地の順序は変わりません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、実測と現物から説明します。main が動くたびに着地待ちの便が検査を全部撃ち直しており、1 日で 29 回、便の延べ時間の 43% が検査でした。列が長いほど撃ち直しは 2 乗に伸びます。

CTX1

実測 — 再 gate が 1 日 29 回・gate が便の延べ時間の 43%

fleet の event log (2026-09-16 00:00Z 以降・84 便・37 bead) の機械集計で、 便の延べ 83 時間のうち gate が 36 時間 (43%)、 追随の再 gate (rebase の後に gate を撃ち直す周) が 29 回 (1 周 中央値 16 分・最大 151 分)、 gate 1 周目は中央値 25 分・最大 299 分だった。 着地した 17 bead の壁時計は中央値 238 分・最大 637 分で、 その多くが列で待つ間の再 gate である。 同時に走る便が 10 以上の時間帯は main が数十分おきに動くので、 列の先頭でない便は着地の番が来るまでに 2〜3 回 gate を撃ち直す。

CTX2

現物 — 追随の再 gate は共通 verify・検出線・契約 verify を全部撃ち直す

land の追随 (pipe/land.rs の follow_main) は main の tip が便の base より進んだ周に worktree を rebase し、 gate を撃ち直す (SRS FR34)。 撃ち直す列は共通 verify 6 本 (flip-check・nextest --workspace・clippy・xtask check・deny) と検出線 (mutants-diff) と契約 verify で、 1 周目と同じ。 main の差分が検出線の面 (crates/・Cargo.toml・Cargo.lock・rules/・.vessel.toml) に触れない周だけ検出線を省く (設計 pipeline.md §30・ADR-0021 §2.4) 形と、 面の外だけの周は再 gate ごと省く (同 §33・台帳 s2-07l.416) 形は在るが、 面の内で main が動いた周 (別の便の着地) は全部撃ち直す。 便の自分の diff は衝突無しの rebase で変わらない (29 回全部が衝突無し) のに、 その diff の変異を殺せるかの検出線も撃ち直している。

CTX3

現物 — 着地の列着地の順番待ちの便の並びは gate 済みの便を先に通す (ADR-0021 §2.5・gate-cost.md §6)

Gated ∧ verdict PASS の便が在る間は他の便の land が待ち (先に gate を通った便を先に着地させる)、 順番の鍵は event log の replay で導く (ADR-0021 §2.5・設計 gate-cost.md §6・台帳 s2-07l.147)。 列の先頭が着地すると main が動き、 次の便は追随して再 gate する = 列の長さ N に対して再 gate が N 回、 gate の時間が N の 2 乗に近く伸びる。 着地の外の merge (docs PR の squash) も同じ再 gate を誘発する (台帳 s2-07l.212・pipeline.md §19 の待ち口)。

CTX4

憲法と要件の向き

C12.6 は main を常に緑に保つ (known-red の台帳を持たない)。 FR34 は追随の周に gate をやり直すことを、 FR10 は base が古い周に land が main を動かさないことを、 FR12 と FR50 は便ごとに Landed の記録と着地 commit の CI の照合を求める。 C2 は選定・除外・順序を 1 列挙の上の 1 関数で持つ。 C10 は実測値と持ち越した値を型で分ける。 C5 は規則の値 (列の長さの上限1 回の検査に積む便の数の上限) に裁定 id を要る。 ADR-0019 の衝突の起こし直し (rebase が衝突した便は runner を起こし直す) は動かさない。

選択肢を測るものさし (安全・速さ)

判断を評価する 5 本のものさしです。main の先端が常に緑であること、検査の総時間が便の数に比例すること、着地の順序と便ごとの記録を変えないこと、赤の周に手で選別しないこと、持ち越した値を実測と区別することです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。先頭数本を 1 つの木にまとめて 1 回検査する案、今の 1 本ずつの形、追随の検査を撃たない案、先に着地して赤なら戻す案、先頭 k 本ごとの木を並列に検査する案です。

OPT1着地の列の先頭 N 本を 1 つの候補の木列の先頭 N 本を main に順に積んだ作業木に積み、 gate を 1 回撃って緑なら順に着地する (merge train)採用

列 (ADR-0021 §2.5 の順) の先頭から N 本 (rules 行 land.train_max が上限) を、 main の先端に順に rebase して 1 つの候補の木を作る (rebase が衝突した便は列から外れて ADR-0019 の起こし直しへ・後続は詰める)。 候補の木に対して共通 verify を 1 回、 各便の契約 verify をその便の分、 検出線は便の diff の patch-iddiff の中身だけから決まる指紋 が前周の記録と同じなら前周の record を provenance 付きで写し、 違えば撃つ。 緑なら N 本を列の順に着地 (便ごとに squash commit・Landed の記録・push は 1 回・CI の照合は先端の commit で)。 赤なら列を解き、 先頭 1 本だけの既存の経路 (追随 → 再 gate) に戻る (帰属はしない)。 N = 1 の周は現行と同じ。

着地待ちの先頭数本を main に順に積んだ 1 つの作業木を作り、検査をその木に 1 回撃ちます。緑なら順に着地し、赤なら列を解いて 1 本ずつに戻します。変異検査は便の diff の指紋（patch-id）が前回と同じなら前回の結果を印付きで使い回します。

+ 利点

  • 列の長さ N に対して gate が N 回から 1 回になる (CTX1 の 29 回が数回に落ちる)・検出線は patch-id 不変の便で撃たない
  • 着地の順序・待ちの規則・便ごとの記録は不変 (列は同じ 1 関数の上に「N 本まとめて検査する」を足すだけ)
  • 赤の周の処置が既存の経路 (1 本ずつ) そのもので、 新しい判定を足さない

− 欠点

  • 候補の木で検査されるのは N 本を全部積んだ木だけで、 途中の commit (先頭 k 本だけの木) は個別に検査されない (main の途中の commit が赤でありうる・先端は緑)
  • 1 本の赤が N 本の待ちを 1 周分止める (列を解いた後は先頭から 1 本ずつ)
  • rules 行 1 本 (列の長さの上限) が増え、 値は裁定 id を要る
OPT2現行のまま (1 本ずつ追随 → 再 gate) + docs だけの周の省略 (§33)不採用

列の先頭が着地するたびに次の便が追随して全部撃ち直す。 main の差分が面の外だけの周は省く。

今の形です。列の先頭が着地するたびに次の便が追随して検査を全部撃ち直します。docs だけの変更で main が動いた周は撃ち直しを省きますが、便の着地で動いた周は全部撃ち直します。

+ 利点

  • 器の変更が §33 だけで済む
  • 途中の commit も含めて main の全 commit が検査済み

− 欠点

  • 面の内で main が動く周 (便の着地) は全部撃ち直すので、 列が長いほど 2 乗に伸びる (CTX1)
  • 検出線を patch-id 不変でも撃つ
OPT3追随の再 gate を撃たず、 便ごとの gate と main の CI だけに頼る不採用

base が古い便も rebase だけして着地し、 赤は main の CI で拾う。

追随の検査を撃たず、便ごとの検査と main の CI だけに頼る案です。検査は 1 回で済みますが、着地の前に着地後の木を検査しないので、main が赤になってから気づくことになります。

+ 利点

  • gate が便ごとに 1 回で済む

− 欠点

  • 着地の前に着地後の木を検査しない = FR34 と C12.6 に反する (main が赤になってから気づく)
  • 赤の main を直す便が列に割り込む = known-red の運用になる
OPT4楽観的に着地して main が赤なら revert する不採用

検査を後回しにして着地し、 CI が赤なら器が revert commit を積む。

先に着地して、CI が赤なら器が戻す案です。列は止まりませんが、main が赤である時間を認めることになり、戻しの commit が記録を汚します。

+ 利点

  • 列が止まらない

− 欠点

  • main が赤である時間を認める (C12.6 に反する)・revert の連鎖が便の記録を汚す
OPT5先頭 k 本ごとの木 (k = 1..N) を並列に検査する (merge queue の一般形)不採用

候補の木を N 個 (先頭 1 本・2 本・…・N 本) 作り、 並列に gate して緑の最長の先頭列を着地する。

先頭 1 本・2 本・…・N 本の木を並列に検査する案です。途中の commit まで検査でき赤の便も特定できますが、検査の費用が N 倍に戻り、封じ込めの枠と口座の窓を N 個食います。枠の余裕を実測した後に改訂で足す候補です。

+ 利点

  • 途中の commit も検査済みになり、 赤の便を機械で特定できる

− 欠点

  • gate の費用が N 倍に戻る (封じ込めの枠と口座の窓を N 個食う・ADR-0021 の並列の上限に当たる)
  • 検査の枠が空いた周だけ有効で、 空かない host では OPT1 と同じ形に縮退する = まず OPT1 を置き、 枠の余裕の実測の後に改訂 ADR で足す
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、それが要件書のどの要件を支えるかを示します。列の先頭 N 本を 1 つの木に積んで 1 回検査し、緑なら順に着地、赤なら列を解きます。追随の検査・古い base の扱い・便ごとの着地の記録・push と CI の照合の要件に対応します。

採用 — OPT1

器 SHALL 着地の列 (ADR-0021 §2.5 の順) の先頭から rules 行 land.train_max 本までを main の先端に順に rebase した候補の木 1 つを作り、 その木に対して共通 verify を 1 回と各便の契約 verify を撃ち、 検出線 SHALL 便の diff の patch-id が前周の記録と同じ周は前周の record を持ち越しの印付きで写して撃たず、 記録が無いか違う周は撃つ。 緑の周は器 SHALL N 本を列の順に着地し (便ごとに commit と Landed の記録・push は 1 回・CI の照合は先端の commit)、 赤の周は器 SHALL 列を解いて先頭 1 本の既存の経路に戻る。 rebase が衝突した便 SHALL 列から外れて ADR-0019 の起こし直しへ進む。

着地の列の先頭から、規則の値までの本数を main に順に積んだ 1 つの作業木を作り、共通の検査を 1 回、各便の契約の検査をその便の分だけ撃ちます。変異検査は便の diff の指紋が前回と同じなら前回の結果を印付きで写します。緑なら便ごとに commit と記録を残して順に着地し、push は 1 回で CI は先端の commit で照合します。赤なら列を解き、先頭 1 本だけの今までの経路に戻します。rebase がぶつかった便は列から外れ、起こし直しに進みます。 撃ち直しが 2 乗に伸びるのは、検査の単位が便だからです。着地後の木を 1 回検査すれば、先端が緑であることは同じ強さで保証でき、便ごとに持つべきものは記録だけになります。赤の周は帰属せずに列を解けば、新しい判定を足さずに今の経路に戻れます。途中の commit が検査されない代償は、先端の緑と便ごとの記録で受けます。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR34claim追随の周の「gate をやり直す」を、 便ごとでなく候補の木 1 つに対して 1 回行う = やり直しの単位が便から木に変わり、 進んだ base の事実は便ごとに記帳する。
FR10claimbase が古い便は候補の木に積まれるまで main を動かさない。 列を解いた周も同じ (land は何もしない)。
FR12claim着地は便ごとに Landed を記帳し verdicts.jsonl に 1 行ずつ append する = 列でまとめて検査しても記録の単位は便のまま。
FR50claimpush は列で 1 回、 CI の照合は先端の着地 commit の id で行い、 台帳の close は便ごと。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、代わりに引き受けることです。検査が列の長さに比例しなくなる一方、途中の commit は個別に検査されず、1 本の赤が同じ列の便を 1 周止め、列の長さの上限という規則の値が 1 つ増えます。

✓ 良い結果

  • ●列の長さ N に対して gate が 1 回になり、 検出線は patch-id 不変の便で撃たない = 1 日 29 回の再 gate が数回に落ち、 着地の壁時計が列の長さに比例しなくなる
  • ●着地の順序・待ちの規則・便ごとの記録 (Landed・着地 commit・CI の照合・台帳の close) は不変
  • ●赤の周の処置は既存の 1 本ずつの経路そのもので、 帰属の判定や散文の運用を足さない

⚖ トレードオフ・代償

  • ●検査されるのは N 本を積んだ木だけで、 main の途中の commit (先頭 k 本の木) は個別に検査されない = 先端は緑だが途中の commit が赤でありうる (bisect の粒度が落ちる)
  • ●1 本の赤が同じ列の N 本を 1 周分止める (列を解いた後は先頭から 1 本ずつ)
  • ●rules 行 land.train_max (列の長さの上限) が増え、 値は裁定 id を要る (C5)・patch-id の記録 (gate の record の 1 語) が増える
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この ADR が版の系譜のどこに在るかと、判断が最後に行き着く原則です。着地の順序の原則（ADR-0021 §2.5）と衝突の起こし直し（ADR-0019）は変えず、列に「まとめて 1 回検査する」を足します。

改訂状態current

置き換える ADRなし (新規)

置き換えられたなし (現行)

本 ADR は現行。 ADR-0021 §2.5 (着地は gate 済みの便を先に通す) の順序の原則は不変で、 本 ADR はその列に「N 本まとめて 1 回検査する」を足す。 ADR-0019 (衝突の起こし直し) と ADR-0021 §2.4 (検出線は面に触れた周だけ) は不変。 設計 pipeline.md §33 (面の外だけの周は再 gate を省く) は本 ADR の N = 1 の周の特例として残る。

照会終端 — PRIN-GATE-THE-TREE-NOT-THE-RUN

着地の前の検査は着地後の木に対して行い、 検査の回数を便の数に比例させない。 便ごとに持つのは記録であって検査ではない。

本 ADR の判断はこの原則に行き着く (これ以上は遡らない照会終端)。
