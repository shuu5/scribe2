§1. Context

便を何本か同時に流すと、 2 本が同じ file を触っていたときに、 後から着地する便が main に追いつこうとして衝突します。 いまの器は衝突した便を「失敗」で止め、 その worktree を畳む口もありません。 user は「並列で速度を上げたいが、 review で範囲が広がって後から重なることは絶対にありうる。 誰がどう解くかを決めておかないと、 全部 admin に集まって詰まる」と問い、 planner の提案 (入口で重なりを排他し、 起きたら実装役に解かせ、 人は質問への回答でだけ関わる) を採り、 「本当に両方が働くかの歯は必須」と裁定しました。 この記録はその形を決めます。

記録時点 (2026-09-12) の現物: 便 1 本 = worktree 1 つ + runner 1 つ (FR4)。 runner は契約の write-set の外を編集できない (write-set guard・ADR-0009 §2.1)。 land は base が main の祖先なら worktree の branch を main へ rebase し、 段を Implemented へ戻して gate を撃ち直す (設計 pipeline.md §5.4)。 rebase が衝突した周は git rebase --abort で木を戻し Failed detail=rebase-conflict で**終端**する。 pipe retire が畳めるのは Landed と Failed detail=rebase-empty だけで、 衝突で終端した便の worktree は畳めない (台帳 s2-07l.132)。 intake は契約の形を検査する (ADR-0009 §2.2・Unfit の閉じた enum) が、 live な他の便の write-set と照合しない。 並列に 2 本を流した実績は無い (これまでの便はすべて 1 本ずつ)。 便の途中で範囲が広がる経路は runner の質問 → planner の回答だけ (lens は読むだけ・guard が外を deny する)。

憲法の向き: C2 は選択・除外・routing を 1 enum の 1 関数で持ち、 新しい理由は variant 1 つで表す。 C16 は逸脱を edit time で止め、 事後検証で代えない。 C6 は起動口を 1 つ (Budget を要する spawn) に限る。 N1 は器が管理する物の不可逆な削除を拒み、 N1.2 は退役を可逆な move に限る。 ADR-0016 §2.5 は「契約の write-set の交差を intake で検査する形」を本 ADR の決定ではないと明記して残した。 user の裁定 (2026-09-12・会話面・逐語は台帳 s2-07l.143 の notes): planner の推奨 (入口で排他 + 起きたら runner が解く・人は質問経由のみ) でよい・歯は必須。

§2. Decision

§2.1 intake は live な便の write-set と交差する契約を受け付けない (排他は 1 enum の 1 関数・C2)

便を受け付ける入口で、 いま走っている便が触る file と重なる契約は断ります。 断る理由は器の中の「断る理由の一覧」に 1 つ足すだけで、 判定は 1 本の関数です。 重なりの判定は path の集合の共通部分で、 dir はその配下の file を含みます。 断られた契約は、 重なる便が終わってから出し直します。

pipe intake SHALL 契約の write-set を、 live な便 (段が Landed / Stopped / Failed のいずれでもない run・event log の replay から導く) の write-set (各 run の契約の写し) と照合し、 交差する周は受け付けない (Unfit に variant 1 つ・rc は既存の拒否と同じ・run を作らず event を書かない)。 交差の定義 SHALL path の集合の共通部分が空でないこととし、 末尾 / の dir はその配下の path を含む (正規化: 先頭の ./ と重複する / を落とす・symlink は解かない)。 判定 SHALL 既存の intake の除外関数の内側に variant 1 つとして足す (C2・宣言順の末尾・ADR-0014 §2.1 の既存 guard intake-unfit の内側ゆえ極性一覧の行は増えない・InLoop / FailClosed)。 器 SHALL NOT 交差を許す flag を持たない。 live な便の write-set を読めない周 (契約の写しが無い・parse 不能) SHALL 受け付けない側へ倒す (fail-closed・「読めない」を「交差なし」に化けさせない)。

§2.2 land の rebase 衝突は終端にせず、 runner を起こし直して write-set の内側で解かせ、 gate をやり直す

入口で排他しても、 質問への回答で範囲が広がる周や、 dir 単位の write-set が実際には別 file を触る周に衝突は起きえます。 衝突したら便を失敗にせず、 木を衝突前に戻してから実装役をもう 1 回起こし、 「main が進んだので取り込んで衝突を解いてから続けよ」と契約に添えて渡します。 実装役は自分の write-set の中でだけ解き、 解けなければ質問で止まります。 解けたら審査 (gate) をやり直し、 通れば着地します。

land の追随 (設計 §5.4) で rebase が衝突した周、 器 SHALL git rebase --abort で木を戻し、 RunStage stage=Implemented detail=rebase-conflict:<base>..<main> を記帳して (終端の Failed にしない)、 同じ run の worktree と契約で runner を起こし直す (C6 の 1 つの spawn 口・Budget は Precheck から)。 起こし直しの stdin SHALL 契約の写しに「追随」節 (main の sha と「git rebase <main> を実行し衝突を write-set の内側で解いて commit せよ・解けなければ質問 record で止まれ」の定型) を付ける (ADR-0016 §2.2 の「回答」節と同じ置き場・定型の字面は prompt template が持つ)。 runner の終了後、 器 SHALL 通常の spawn 完了と同じく Implemented → gate → land を通す (rebase は再び走り、 解けていれば衝突しない)。 runner が write-set の外を触ることは従来どおり guard が deny する (ADR-0009 §2.1)。 runner が質問 record で止まった周は Questioned へ倒れ、 planner の回答で再開する (FR31 / FR32)。 resume SHALL この段 (Implemented detail=rebase-conflict で runner が起きていない周) からも同じ起こし直しを撃てる。

§2.3 人が関わるのは質問への回答だけ。 admin は中継と操作、 planner は契約の設計と回答。 手で merge する経路は持たない

衝突を人が手で直す道は作りません。 係の席 (admin) は便を流し・質問を届け・着地の操作をするだけ、 計画役 (planner) は契約の write-set を設計し、 質問に答えるだけです。 こうすると、 便を何本並べても人の手番は「質問に答える」の 1 種類に収まり、 admin に仕事が集まって詰まる形になりません。

器 SHALL NOT 衝突した worktree を席や人が編集して land する経路を持たない (gate 分離・C16: 逸脱は edit time で止める)。 管理席の仕事は ADR-0016 §2.1 の 3 つ (流す・中継する・land する) のまま増やさない。 planner SHALL 契約の write-set を「触る file でなく構造の連鎖」で設計し、 交差を入口で避ける (排他は planner の設計の穴を器が止める最後の線であって、 設計の代わりではない)。 回答で write-set を広げる周 (台帳 s2-07l.133) は、 広げた write-set で §2.1 の照合をやり直す (広げた結果 live な便と交差すれば、 回答は受け付けず planner に戻す)。

§2.4 起こし直しの回数は rules 行で上限を持ち、 超えた便は Failed で終端して畳める

解けない衝突で実装役を無限に起こし直さないよう、 回数の上限を規則の値として持ちます。 上限を超えた便は「失敗」で終わり、 その worktree は可逆に畳めます (消しません)。 上限の値は user の裁定で決めます。

器 SHALL 1 つの run の衝突による起こし直しの回数を rules 行 (pipe.follow_retries・値は裁定 id 付き・C5・本 ADR は値を決めない) で上限とし、 超えた周は Failed detail=rebase-conflict で終端する (fail-closed)。 pipe retire SHALL Failed detail=rebase-conflict の便の worktree を可逆 move で畳める (N1.2・台帳 s2-07l.132 の memo を本 ADR が吸収する)。 回数は event log の rebase-conflict の行数から導く (replay の導出値・別の状態を持たない)。

§2.5 射程外

この記録が決めるのは「入口の排他」「衝突時の起こし直し」「人の関わり方」「回数の上限」だけです。 host をまたぐ便、 write-set を自動で分割する仕組み、 便の優先度や待ち行列、 同時に何本まで流すかの上限は別に決めます。

次は本 ADR の決定ではない (MUST NOT be read as such): 複数 host にまたがる便の排他 (event log は host ごと・v3)、 write-set の自動分割や契約の自動生成、 排他で断られた契約の待ち行列と再投入 (管理席か tick の運用・別途)、 同時に流す便の本数の上限 (admission control・口座の自律制御 s2-07l.142 と併せて別途)、 lens の指摘で範囲を広げる経路 (lens は読むだけで write-set を変えない・広げるのは planner の契約改訂)、 「追随」節の定型の字面 (prompt template の現物が正本)。

§3. SRS との関係 (正本は SRS)

この記録は要件書の文面を変えません。 便の形 (worktree 1 つ・runner 1 つ)、 着地の前提 (審査合格・出発点の一致)、 別 process からの再開、 配送構造と質問の停止は、 要件書の当該行が正本です。

本 ADR が仕える要件は SRS v0.5 が正本である: FR4 (契約 1 本に worktree 1 つと runner 1 つ)・FR10 / FR11 (land の前提と CAS・§2.2 の追随はこの内側)・FR14 (別 process からの resume・§2.2 の起こし直しは resume と同じ口)・FR30 (配送構造・§2.3)・FR31 (質問の停止・§2.2 / §2.3)。 本 ADR は SRS に新しい要件を求めない (排他と起こし直しは FR10 / FR11 / FR14 の実装形)。 intake の拒否の理由 (variant の名)・「追随」節の字面・rules 行の値は §2 と現物が持ち SRS は持たない。

§4. Consequences

良い面は、 便を並べても人の手番が「質問に答える」だけに収まること、 衝突が失敗ではなく実装役の 1 turn として処理されること、 衝突で終端した便を畳めるようになることです。 悪い面は、 実装役の起こし直しの分だけ口座の枠を使うこと、 入口の排他で契約が断られて出し直しの手間が増えること、 write-set を dir で広く取った契約ほど排他に掛かりやすいことです。

Positive: 並列の便で人の手番が回答 1 種類に閉じる (ADR-0016 §2.3 の形を保つ)。 衝突が typed な event (rebase-conflict) として残り、 回数が replay から読める。 排他は既存 guard の内側の variant 1 つで極性一覧の形を変えない。 retire の前提が広がり、 Failed の worktree が溜まらない (N1.2)。

Negative (受け入れるコスト): 起こし直しは runner の turn を増やし口座の枠を使う (上限は §2.4・枠の自律制御は s2-07l.142)。 排他は保守的 (dir 単位・symlink を解かない) なので、 実際には重ならない契約も断られうる (出し直しは管理席の運用)。 rules 行 1 つ・prompt template の節 1 つ・Unfit の variant 1 つ・event の detail 1 種が増える。 並列 2 本の実地試験 (台帳 s2-07l.143) で追随と枠の減りを実測してから契約を流す。

§5. Alternatives Considered

5 つの案を退けました。 衝突した便を計画役が切り直す案は、 計画役が詰まります。 係の席が手で merge する案は、 審査の分離を壊します。 入口の排他だけで解く案は、 回答で広がる周に衝突が残ります。 全部を 1 本ずつ流す案は、 並列性がゼロです。 衝突を機械的な 3-way merge で解く案は、 意味の衝突を解けません。

(A) 衝突した便は planner が契約を切り直す。 却下: planner が律速になり、 並列を上げるほど悪化する (ADR-0016 §1 の実測と同型)。 起こし直しで解けない周だけ質問として planner へ戻す (§2.2)。

(B) 管理席が worktree を手で merge して land する。 却下: gate 分離を破り (審査の後に人が編集)、 C16 (逸脱を edit time で止める) に反する。 席の仕事は 3 つのまま (§2.3)。

(C) 入口の排他だけを持ち、 衝突時の解消経路を持たない。 却下: 回答で write-set が広がる周 (s2-07l.133) と dir 単位の write-set が別 file を触る周に衝突が残り、 Failed の worktree が溜まる。

(D) 全便を直列に流す。 却下: 並列性がゼロで user の目的 (速度) に反する。 直列は排他の特殊形 (常に交差扱い) として §2.1 に含まれる。

(E) 衝突を器が 3-way merge の道具で自動解決する。 却下: 意味の衝突 (同じ関数を別々に直した) は道具で解けず、 解けたように見える誤 merge が gate を通る危険がある。 解くのは契約を読んだ runner で、 判定は gate (C16 の向き)。

§6. Trace

出所は、 user の問いと裁定、 器の現物 (land の追随と衝突の終端・intake の検査・retire の前提)、 そして先行決定 (write-set guard・質問 record・guard の定義) です。

  • user の問いと裁定 (2026-09-12・会話面・planner 席): 並列で後から重なる衝突を誰がどう解くか／全部 admin だと詰まる → planner の推奨 (入口で排他 + 起きたら runner が解く・人は質問経由のみ) を採用・歯は必須。 逐語は台帳 s2-07l.143 の notes (tracked file には写さない・CON2)。
  • 器の現物 (2026-09-12): crates/<NAME>/src/pipe/land.rs の follow_main / rebase_onto (祖先なら rebase → Implemented detail=rebase:… → gate 撃ち直し・衝突は abort → Failed detail=rebase-conflict・0 commit は rebase-empty)・pipe/declaration.rs の Unfit (intake の拒否理由・極性一覧 intake-unfit)・pipe/contract.rs の write_set (必須・1 本以上)・headless/runner.txt (write-set の外を書き換えない・回答節)・設計 pipeline.md §5.4 (retire の前提 = Landed ∨ rebase-empty)。
  • 台帳の memo: s2-07l.132 (gate / lens FAIL の worktree を retire で畳む)・s2-07l.133 (回答で write-set が広がる周の写しの再読)。 本 ADR は前者を §2.4 で吸収し、 後者を §2.3 の再照合に結ぶ。
  • 先行決定: ADR-0009 §2.1 (write-set guard) / §2.2 (intake の拒否)・ADR-0014 §2.1 (guard の定義と極性)・ADR-0016 §2.1〜§2.3 (配送構造・質問 record・回答の権限) / §2.5 (交差の検査は射程外)。
  • 設計: docs/design/pipeline-conflict.md (交差の判定・live の定義・「追随」節・起こし直しの段と event・回数の導出・retire の拡張・歯・契約・並列試験の観測)。
