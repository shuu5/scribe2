設計判断記録 (ADR) scribe2 — 席の指示文の出所の印

席の指示文の出所の印は器の文書だと名乗り (→ 器の SSOT:)、 印の後ろの参照は 1 本残らず pointer の形に分類できなければならない — 1 本でも分類できない参照を持つ行は雛形の違反 (ADR-0018 §2.2 の印の字・ADR-0022 §2.4 の規範文の定義の読み・ADR-0046 の用語 pointer 行の字を部分 supersede)

器は登録された全ての席 (器の repo の席も、 別の repo の席も) へ同じ 11 行の指示文を渡す。 各行の末尾の出所の参照は器の repo の文書を指すが、 字からはそれが分からず、 別の repo の席が自分の repo の同じ名の文書と読み違えうる。 本 ADR は印そのものに持ち主を名乗らせ、 あわせて印の後ろに分類できない参照が在る行を黙って通していた穴を塞ぐ。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「席の指示文」は器が session の始まりに席へ渡す 11 行の案内です。 指示文の各行の末尾には「→ SSOT:」という印があり、 その後ろに出所の参照 (憲法の条・決定記録の番号・設計の文書) が並びます。 参照は器の repo の文書を指しますが、 字からはそれが分かりません。 器を使う別の repo の席も同じ指示文を受け取り、 その repo も自分の憲法や決定記録を持つので、 字の近い条を自分の repo の条と読み違えうることが 2026-09-29 の報告で分かりました。 この記録は、 印そのものを「→ 器の SSOT:」に替えて持ち主を名乗らせ、 あわせて印の後ろに器が形を見分けられない参照が 1 本でも在る行を、 黙って通さず雛形の違反にすると決めます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (印の字と pointer 行の定義を 3 本の決定記録が持つ)・事象 (別の repo の席が器の文書を自分の repo の文書と読みうる)・機序 (行の分類が形の外の参照を捨てる)・憲法と既存の決定の向き・この判断の範囲の 5 つから説明します。 印はもともと、 今は廃止された作業記憶の命令行の印でした。

CTX1

経緯 — 印の字と pointer 行の定義は 3 本の決定が持つ

ADR-0018 §2.2 は、 作業記憶の命令行が本文末に出所 pointer器の文書を指す参照 (→ SSOT: の後ろの参照) を持ち、 器が形を閉じた enum (PointerKind参照の形の一覧) で分類すると決めた。 ADR-0022 §2.4 は席の指示文席への最初の案内の雛形の行を穴か出所 pointer を持つ行に限り (ADR-0018 §2.2 と同じ検査)、 規範文を「pointer を持たない行」と定めた。 ADR-0046 の用語集は pointer 行を「行末の → SSOT: の後ろに出所を持つ行」と字で定める。 作業記憶は ADR-0045 §2 (2) で廃止され、 印は席の指示文の雛形にだけ残る。

CTX2

事象 — 別の repo の席が器の文書を自分の repo の文書と読みうる

器は SessionStart で、 登録された全ての席 (器の repo の席も消費側器を使う別の repoの席も) へ同じ 11 行の指示文を渡す。 行末の → SSOT: の後ろの参照 (憲法の条・ADR の番号・設計 doc の path) は器の repo の文書を指すが、 字からはそれが分からない。 消費側の席の報告 (2026-09-29) と写しの表の突き合わせで、 消費側の repo の憲法にも器の条と字の近い id の条 (中身は別) が在り、 席が指示文の条を自分の repo の条と読みうることが分かった (実測 1 件・記録は memo s2-07l.739)。 同じ害は ADR の番号と設計 doc の path にも及ぶ。 印 → SSOT: は器の前の版の作業記憶の印で、 消費側の repo の文書にもその repo 自身の文書を指す印として残りうる。

CTX3

機序 — 行の分類は分類できない参照形の外の参照を捨てる

行の分類は、 印の後ろの参照のうち分類できたものの最も強い kind を取り、 分類できない参照を捨てる。 雛形の歯も分類できない参照を黙って飛ばす。 同じ行に分類できる参照が 1 本在れば、 「憲法 N-7」「器の憲法 N3」のような分類できない字が印の後ろに在っても行は通り、 印の後ろに隠れた散文が規範文の検査の外に出る。 今の雛形 11 行には分類できない参照が無い。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C1.2 (生成文に手書きの規範文を持たない) は、 pointer 行の読みを「印の後ろの参照が全部 pointer の形の行」と狭めるほど強く執行される。 N2 (散文にしか無い規則を規則と扱わない) と N3 (host 固有の値で分岐しない) は動かさない。 印の字は host に依らず、 器の repo の置き場 (絶対 path) も指示文に書かない。 CON2 (公開面) から、 消費側の repo の名と条の中身は本 ADR に写さない。

CTX5

射程 — 動かすのは印の字と、 行の分類の 1 規則だけ

動かすのは (1) 雛形 11 行の行末の印の字、 (2) 印の字の定数 (器の中の 1 つと xtask の写し)、 (3) 行の分類が分類できない参照を 1 本でも持つ行を違反にすること。 動かさないのは PointerKind の閉じた列と形と宣言順・前置き語の表・Anchor の解決・穴の列 (5 つ)・生成文の行数 11・hook の出す順と記録の what・rules 行・xtask の seat-brief の判定の形 (印の後ろに pointer の字が 1 つ在る行を通す)・消費側の repo の文書。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 どの行を 1 行だけ抜き出しても持ち主が読めること。 参照の形を見分ける仕組みを 1 通りのまま増やさないこと。 印の後ろに散文を隠させないこと (形の外の参照を黙って通さない)。 公開面と host に依らない形を守ること (置き場・名・別の repo の値を書かない)。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 9 つ並べます。 印を「→ 器の SSOT:」に替えて印の後ろの参照を全部見分ける案 (選んだ案) と、 選ばなかった 8 つです。 選ばなかった案は、 持ち主の書き方を変える 5 つ (各参照に前置き・器の名・冒頭の 1 行・印の直後の語・anchor 付きの path)、 穴の塞ぎ方を変える 2 つ (歯だけを直す・前置き語の参照だけを違反にする)、 何もしない案です。

OPT1印を「→ 器の SSOT:」に替え、 印の後ろの参照は全部分類する採用

雛形 11 行の行末の印を → 器の SSOT: に替え (印より前の字・参照の列・行の数と順は不変)、 器の中の印の定数と xtask の写しを同じ字にする。 行の分類は印の後ろの参照を 1 本残らず分類し、 1 本でも分類できなければ分類できない行として違反に数える。 雛形の歯も黙って飛ばさない。 決め手は分析 (印が持ち主を名乗り、 分類の形は変わらない)。

各行の末尾の印を「→ 器の SSOT:」に替える案です。 印より前の字と参照の並びは 1 字も変えません。 印そのものが持ち主を名乗るので、 どの行を 1 行だけ抜き出しても、 印の後ろに参照が何本並んでも、 器の文書だと読めます。 器の中の直しは印の字の定数とその写しだけで、 参照の形を見分ける仕組みは変わりません。 あわせて、 印の後ろの参照を 1 本残らず見分け、 見分けられない参照が 1 本でも在る行を違反にします。 代わりに、 全ての席の指示文が 1 行 7 byte 伸び、 「器」の語が通じるかは指示文の 1 行目に頼ります。 分析で選びました。

+ 利点

  • 行を 1 行だけ抜き出しても器の文書と読め、 印の後ろに参照が何本並んでも全部に掛かる (DR1)
  • 解き手の変更は印の定数とその写しだけで、 PointerKind と前置き語の表は 1 字も変わらない (DR2)
  • 前の版の印だけの行は既存の規則で pointer を持たない行になり、 新しい仕組みが要らない (DR2)
  • 印の後ろに分類できない字を置いた行が違反として名指され、 散文の逃げ道が塞がる (DR3)

− 欠点

  • 全席の指示文の字が変わり、 1 行につき 7 byte 伸びる
  • 器の語が席に通じるかは、 指示文の 1 行目と名乗りの行に頼る
  • xtask の seat-brief は印の後ろに pointer の字が 1 つ在る行を通したままで、 全参照を測るのは器の中の歯だけ
OPT2各参照の頭に「器の」を付ける不採用

印は今のまま、 印の後ろの各参照の頭に「器の」を付ける案です (器の憲法 N3 など)。 参照ごとに持ち主が分かる点で勝ります。 けれども、 21 本の参照に同じ語が並び、 参照の形を見分ける仕組みに 2 段の前置きを足すことになって、 形ごとに書き方が 2 通りになります。 印の字は別の repo が自分の文書に使う印と同じままです。 退けました。

+ 利点

  • 参照ごとに持ち主が字で分かる

− 欠点

  • 前置き語の表に 2 段の前置きを足すことになり、 kind ごとに形が 2 通りになって、 形が互いに重ならないかを測り直す (DR2)

印は今の字のまま、 印の直後に 1 度だけ持ち主の語を置く。 決め手は分析 (掛かる範囲が字から読めない)。

印は今のまま、 印の直後に 1 度だけ「器の」を置く案です。 印の字を替えない点で勝ります。 けれども、 その語が区切りの後ろの参照にも掛かるのかが字から読めません。 別の repo が使う印とも字が同じままです。 持ち主の語は参照の形ではないので、 前の決定記録の形から外れ、 新しい決定記録も避けられません。 退けました。

04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 雛形の各行の印を「→ 器の SSOT:」に替え、 印の字は器の中の定数と検査道具の写しで同じにします。 行の分類は印の後ろの参照を 1 本残らず見分け、 1 本でも見分けられない行を違反に数えます。 参照の形の一覧・行の数・hook の出し方は変えません。 支えるのは FR42 (指示文に手書きの規範文を含めない) と NFR4 (不正な入力を黙って落とさない) への主張です。
