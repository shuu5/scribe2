設計判断記録 (ADR) scribe2 — 3 クラスを字面から導く

3 クラス (消す / 出す / 使う) は契約表の行の verify 行から rules 行の語列で導き、 名乗らない行を契約表の検査が断る — 申告の口と承認の口は変えず、 自 repo への PR は導出の入力に無い

取り消せない操作 (消す / 出す / 使う = 3 クラス) の前で器が人の承認を待つ関門は、 契約が自分で 3 クラスを名乗ったときにしか立たなかった。 名乗り忘れた契約は、 verify 行で repo の外へ push していても承認なしで通る。 本 ADR は、 3 クラスの名を閉じた型 1 つにし、 クラスごとの command の語列を manifest の rules 行 1 つに置き、 契約表の検査 (docs PR の CI と受付が撃つ同じ 1 本) が行の verify 行をその語列に当てて導いたクラスを行が名乗っていなければ断る、 と決める。 導出の入力は契約表の行の verify 行だけで、 write-set と land の口 (自 repo への push と PR) は入力にしないので、 自 repo への PR を「出す」と誤判定しない。 申告の口 (行の classes) と承認の口 (spawn の手前の Blocked と承認 event) は変えない。 語列の値は user の裁定で決まり、 本 ADR は値を決めない。

この判断が約束すること (1 文サマリ)

この記録で「3 クラス」は、 取り消せないので先に人に聞く 3 種の操作 (消す / 出す / 使う) のことです。 器 (scribe2 の本体) は、 契約 (1 つの仕事の約束) が自分で「この仕事は 3 クラスに当たる」と名乗ったときだけ、 仕事を始める前に止まって人の許可を待っていました。 名乗り忘れた契約は、 検証の命令の中で repo の外へ送る操作を書いていても、 許可なしで進みます。 この記録は、 3 種の操作の名前を 1 つの閉じた型にし、 種ごとの命令の語の並びを規則の行 (rules 行) 1 つに置き、 契約の表を検査する仕組みが検証の命令をその語に当てて、 当たった種を契約が名乗っていなければ断る、 と決めます。 止めるのは契約を仕事にする前の検査 (受付) で、 同じ 1 つの関数が設計の文書を直す段 (docs PR の CI) でも先に知らせます。 導き出す材料は検証の命令だけで、 種は命令の語の並び (名前) で決め、 送り先は調べません。 触ってよい file の列や、 自分の repo へ PR を出す口は材料にしないので、 自分の repo への PR を「出す」と取り違えません。 契約が名乗る欄と、 人の許可を受け取る仕組みは変えません。 語の並びの中身は user が決め、 この記録は中身を決めません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 user の決定と監査と器の現物と前の決定から説明します。 user は、 器の決まりを文章の作法でなく仕組みで守らせる、 と決めました。 同じ日の監査は、 3 クラスの関門が契約の名乗りだけで立つことを 4 つの見方から指摘し、 器の現物でもそのとおりでした。 契約の 3 クラスの欄は書かなくてよい欄で、 空のときは関門が立たず、 いま表に在る 238 行のうち欄を書いた行は 0 行です。 検証の命令は器自身が撃つ命令で、 撃ってよい命令の上限は cargo・git・bats、 撃ってはいけない語の並び (禁じる語列) は「絶対にやらない」側の表だけです。 ∴ 検証の命令に git push を書いた契約は、 名乗らなければそのまま撃たれます。 憲法は、 3 クラスの前に許可を取ること、 merge・自分の repo への送り出し・依存を変えない code の変更は取り消せると扱うこと (自分の repo への branch の push と PR 作成をこの送り出しと読むのは前の決定 ADR-0008 の解釈です)、 規則の値を規則の file に置き変更には user の決定の印を付けること、 逸脱を編集の時点で止め、 後からの検査で止めの代わりにしないことを求めます。 前の決定 (ADR-0008) は、 PR を出す道具を使ったことから 3 クラスを導く形を、 取り消せるかどうかでなく道具の名前で止めていたとして廃止しました。 PR を出す道具の文面や送り先の URL から送り先を調べる案も退け、 名乗り間違いを捕まえる仕組みは次の版に回していました。 契約の字面のうち、 触ってよい file の列は自分の repo の中の変更だけを指し (着地で file を消す形も git から戻せます)、 便の中で実装役が撃つ命令や、 命令が起こす code の中の操作は字面に現れません。 「使う」は憲法の語釈では追加課金です。 前の決定 (ADR-0049) は口座を消費する session の起動を一般に「使う」と読み、 決めたのは席の群の常設の許可だけです (群の移動の決定 ADR-0055 も同じ読みです)。 設計の文書は「使う」を追加課金だけと書くので、 仕事の便を起こすことが当たるかは割れたままで、 この記録では決めません。

CTX1

裁定と監査 — 承認の関門は名乗った契約にしか立たない

2026-09-12 の user 裁定は、 器の規律を散文や字面の作法でなく構造と機械で守らせる、 という向きを定めた (要旨・逐語は台帳)。 同日の全体監査は、 3 クラス先に聞く 3 種の操作 (消す / 出す / 使う) の関門が契約の自己申告だけで発火することを 4 つの見方から指摘した (台帳 s2-07l.167)。 main の現物で再現すると次のとおりである。 契約 file の classes は任意の key で既定は空である (pipe/contract.rs)。 承認の判定は classes が空でなく承認 event人の許可の記録 が無いときだけ Blocked人の許可待ちの段 を返す (pipe/approve.rs の判定)。 判定は唯一の起動口 (pipe/spawn.rs) の頭に在り、 spawn・resume・run の全経路を覆う。 land の PR の口の注記は「3 クラスの判定は契約の自己申告だけに効く」と書く (pipe/land/finish.rs)。 設計 doc は操作の中身から判定する enforcer を後続に置く (pipeline.md §5.5 と §11)。 tracked な設計 doc の契約表設計 doc の契約の表 238 行 (contracts check の rows・main e5da320) のうち classes を書いた行は 0 行である。 ∴ 名乗り忘れた契約には関門が一度も立たず、 承認 event を記す堅い後段が空回りしうる。

CTX2

現物 — verify 行検証の命令 1 行は器が自分で撃つ command で、 git の中の push は通る

契約の verify 行は、 gate着地の前の検査 が便の worktree で sh -c で撃つ command である (契約表の行から生成した写しの値)。 受付便にする前の検査と契約表の検査は各行に形の門を掛け、 次の 6 つのどれかに当たる行を断る。 shell の包みや連結の文字を持つ、 空である、 先頭語が vessel 宣言repo の宣言 fileの allowlist撃ってよい命令名 (上限は rules 行裁定つきの規則の行 runner実装役の Claude.allowed_commands = cargo・git・bats) に無い、 repo の外を指す語を持つ、 閉じた集合の外の穴 (波括弧の埋め字) を持つ、 禁じる語列撃ってはいけない語に当たる、 の 6 つである。 受付が読む禁じる語列は command guardBash の実行前の見張り と共有する和集合の読み手 1 本で、 rules 行 runner.denied_commands (cargo mutants・cargo publish) と host の見張りの語列 3 行 (git push --force などの git・tmux・台帳) の 4 行を読む。 禁じる語列は「絶対にやらない」側の表で、 人に聞けば通してよい「先に聞く」側の表は manifest に 1 本も無い。 ∴ verify 行に git push を書いた行は、 classes が空のままこれらの門を通り、 gate がそのまま撃つ。 契約表の検査は contracts check (docs PR の CI) と受付が同じ関数 1 本 (check_table) を撃つ。 ただし禁じる語列の材料は、 受付が和集合の 4 行、 contracts check が runner.denied_commands の 1 行だけで、 受付の方が広い (resume の組み直しと land の追随も 1 行を読む)。 また、 手で書いた契約 file は受付が断るので、 すべての契約はこの 1 本を通る。 語列の照合は command guard・受付・host の見張りが共有する 1 本 (hook の matched) である。 母集団 (main e5da320) は、 契約表の verify 行 553 本はすべて cargo nextest で、 git や bats で始まる行は 0 本である。

CTX3

憲法と既存の決定の向き

A1 は 3 クラスの操作の前に対話面人と器が話す窓口で承認を取ることを、 A4.2 は取り消せない操作 (destroy・publish・追加課金) を先に聞くことを、 A4.3 は merge・自 repo への dispatch・依存なしの code 変更を A4.2 の目的で可逆と扱うことを求める。 A4 の機構欄は 3 クラスの判定を「rules 行 + enforcer」と書き、 MVP は契約の自己申告と rules 行の deny list、 enforcer は次の版とする (本 ADR は条文と機構欄を変えない)。 C1 と C14 は執行する規則の値を manifest 1 つに置くことを、 C5 は rules 行の追加と変更に user 裁定の id を要することを、 C16 は逸脱を編集の時点で止め、 事後の検査で止めの代わりにしないことを、 C17.2 は仕組みを足す前に消すものを名指すことを、 N2 は散文だけの規則を規則と扱わないことを求める。 器の極性一覧 (ADR-0014) は、 契約表の検査 (docs PR の CI) を事後 (post-hoc・fail-closed) に、 受付の断りを便を作る前 (in-loop・fail-closed) に分類する。 ADR-0008 は、 自 repo への branch の push と PR 作成を A4.3 の可逆として「出す」から外し、 seam (--pr-cmd) の使用からクラスを導く形を廃止した。 廃止の理由は、 それが操作の可逆性でなく道具の名前で止めていたことである (他 repo へ push する道具を渡しても自 repo へ PR を出す道具を渡しても同じ判定になる)。 同 ADR は判定の面を契約の自己申告 + rules 行の deny list のまま (deny list は未着) とした。 却下案 (ii) は、 --pr-cmd の文面や remote の URL から宛先 (自 repo か) を判定する enforcer を、 宛先の解決は道具の側に在り器が道具の方言を追うことになるとして退け、 判定の面を次の版の enforcer (A4 機構欄) へ置いた。 同 ADR の Negative は、 名乗り間違いを機械が捕まえられない例として、 classes を空にした契約が --pr-cmd に他 repo へ push する道具を渡せば器は止めずに通す、 を挙げ、 起票時に classes を名乗る書き手の規律に預けた。 本 ADR は、 同 ADR が次の版の enforcer に置いた席のうち、 契約の verify 行の分に座る。 ADR-0025 は禁じる語列を rules 行に置き、 同じ照合を command guard と受付の verify 行に掛けた。 ADR-0023 は契約の正本を設計 doc の契約表の行と決めた。

CTX4

契約の字面が見せるものと見せないもの

契約表の行は write-set触ってよい file の列・verify 行・classes などを持つ。 write-set の項目は 6 つの形を持つ。 素の file、 末尾 / の dir、 + (宣言した新規 file)、 - (縮む面)、 ~ (着地で消える file)、 = (置き場だけの file) で、 どれも対象 repo の中の path を指し、 受付と契約表の検査が形ごとに解けることを確かめる。 ∴ write-set の編集は対象 repo の中の code 変更で、 依存の変更でなければ A4.3 の可逆に当たり、 依存の変更は A3 の門 (cargo deny と依存の差分の検査) が別に持つ。 ~ は自 repo の tracked file を着地で消す宣言だが、 消えた file は git の履歴から戻せる。 憲法 A4 の語釈の「消す」(データ / repo / 履歴 / live 成果物の破壊) のどれにも当たらず (履歴は残り、 repo もデータも壊さず、 main 上の file は merge を戻せば戻る)、 A4.3 の可逆 (依存なしの code 変更) に当たるので、 A1 の「消す」に数えない。 これは本 ADR が置く解釈である (ADR-0008 は「消す」の範囲に触れていない)。 land の口は契約の外に在る。 push 先の remote と CI の判定を読む行は vessel 宣言が持ち、 --pr-cmd は pipe land を撃つ側が渡す CLI 引数である。 vessel 宣言の共通 verify と検出線の行も宣言の側に在り、 現物はすべて cargo で始まる。 契約の字面に現れないものが 2 つある。 runner が便の中で撃つ Bash (allowlist の git の中の push を含む) と、 cargo や bats が起こす code の中の操作である。 前者は command guard の領分、 後者は審査と write-set の領分である。 3 クラスの「使う」の正規の語釈は憲法 A4 の追加課金で、 本 ADR の語列表の「使う」はその語列だけを持つ。 allowlist の上限 (cargo・git・bats) に追加課金の command は無く、 今の母集団に当たる語列が無いので、 要素は 0 個で足りる。 ADR-0049 の Context は、 器が口座を消費する session を起こすことを一般に「使う」と読み、 決定は席の口座の群の常設の承認だけである (群の移動を A1 の「使う」とする ADR-0055 も同じ系譜)。 逆向きに pipeline.md §2 は、 runner と lens は定額の中で走り追加課金の口を持たない (「使う」= 追加課金だけ) と書く。 便の spawn の起動への当てはめは両者が割れたままで、 本 ADR では決めない (射程外・契約の verify 行に無いので語列の外)。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。 契約の表の検査が検証の命令から導いて名乗り忘れを断る案、 導いた種を名乗りに自動で足して止める案、 実行の時点で命令を止める案、 名乗りの欄を必ず書かせるだけの案、 語の表を規則の行でなく code の表に置く案、 道具や land の送り出しまで材料にする案です。 却下した 5 案にも利点を並べ、 退けた決め手が user の決定か憲法か前の決定か分析かを各案に書きます。 自動で足す案は書き手の手戻りが無い点で、 実行の時点で止める案は実装役の命令まで覆う点で、 必ず書かせる案は仕組みが最小で済む点で、 code の表の案は値を後で変えるとき user の決定を待たずに済む点で、 送り出しまで見る案は実際に外へ出るかまで見る点で、 選んだ案に勝ちます。

OPT1契約表の検査が行の verify 行を rules 行の語列に当ててクラスを導き、 行が名乗っていないクラスが在れば断る採用

3 クラスの名を閉じた型 1 つにし、 クラスごとの command の語列を rules 行 1 つ (クラスの語列表3 種の語の表) に置く。 契約表の検査 (docs PR の CI と受付の同じ 1 本) が行ごとに verify 行を語列表の各要素に禁じる語列と同じ照合で当て、 当たったクラスの集合が行の classes に含まれなければ、 行番号・verify 行・語列付きで断る。 クラスは命令の語列 (名) で決め、 宛先は解かない。 止めるのは受付 (in-loop) で、 CI は事後の早い知らせである。 導出の入力は verify 行だけで、 write-set・land の口・宣言の行は入力にしない。 申告の口と承認の口は変えない。 決め手は裁定。

契約の表を検査する仕組みが、 行ごとに検証の命令を規則の行 (クラスの語列表) の語に当て、 当たった種を行が名乗っていなければ断る案です。 検査は受付が撃って仕事を作る前に止め、 同じ 1 本が文書を直す段 (docs PR の CI) で先に知らせます。 種は命令の語の並び (名前) で決め、 送り先は調べません。 材料は検証の命令だけで、 触ってよい file の列、 自分の repo へ送り出す口、 repo が名乗る宣言の命令は材料にしません。 名乗る欄と許可の仕組みは変えません。 名乗り忘れを仕事を作る前に止め、 自分の repo への PR を取り違えず、 値は規則の行 1 つに在ります。 代わりに、 字面に現れない操作は見えず、 表の中身に user の決定が要り (2026-09-24T00:13Z に決まりました)、 git push のような広い語は自分の repo への送り出しにも当たります。 名前で決まる点は前の決定が退けた性質と同じで、 当たり過ぎは、 CI に止められて名乗りを書き足す手間と便ごとの許可の手間として引き受け、 表を狭く保って許可が形だけになるのを防ぎます。 決め手は user の決定です。

+ 利点

  • 名乗り忘れた行を受付 (便を作る前・in-loop・fail-closed) で止め、 同じ 1 本が docs PR の CI で事後に早く知らせる (DR1・DR3)
  • 自 repo への PR は入力に現れず宛先も判定しないので、 ADR-0008 の判定と承認の節約をそのまま保つ (DR2)
  • 値は rules 行 1 つに置かれ、 照合は禁じる語列と同じ 1 本で、 承認の関門と既存の承認の歯は変わらない (DR4・DR5)

− 欠点

  • 字面に現れない操作 (runner が便の中で撃つ Bash・cargo や bats が起こす code の中の操作) は見えない
  • 語列表の値に user 裁定が要る (値は裁定 id user 2026-09-24T00:13Z で決まった)。 判定は命令の語列 (名) で決まり、 ADR-0008 が seam の導出で退けた「可逆性でなく名前で止める」性質を verify 行の面で持つ。 照合は語の包含なので、 git push のように宛先を問わず広く当たる語列は、 自 repo への push を verify 行に書いた行にも承認を求める。 過検出の費用は docs PR の CI の赤とその PR での classes の書き足し (CI を経ない行は受付の断り) と便ごとの承認で、 承認が増えれば ADR-0008 が案 (i) で退けた摩耗 (承認が安く大量に要求されると儀式化し、 止まる機能が薄まる) が戻る
OPT2導出したクラスを申告に自動で足して Blocked にする (断らない)不採用

契約表の検査は断らず、 受付か spawn が導出したクラスを行の classes に足した集合で承認の関門を判定する。 決め手は分析 (行が実際と食い違ったまま残り、 書き手が気づくのが承認の要求の時点になる)。

検査では断らず、 導いた種を行の名乗りに自動で足してから、 仕事を始める前の関門で止める案です。 書き手の手戻りが無く、 名乗り忘れても許可なしでは始まらない利点があります。 けれども契約の正本である表の行が「3 クラスに当たらない」と書いたまま残り、 作業の記録や審査や人が読む名乗りと器の判定が食い違います。 書き手が気づくのも仕事を始める直前の許可の要求の時点で、 受付の断りも文書を直す段の知らせも出ません。 決め手は分析です。

+ 利点

  • 書き手の手戻りが無く、 名乗り忘れても承認なしでは起動しない (関門は fail-closed のまま)
  • 契約表の検査に断りの型を足さない。 過検出の費用が承認だけで、 CI の赤と classes の書き足しが無い

− 欠点

  • 契約の正本の行 (FR47) が「3 クラスを名乗らない」と書いたまま残り、 台帳・審査・人が読む classes と器の判定が食い違う
  • 書き手が気づくのは spawn の手前の承認の要求の時点で、 受付の断りも docs PR の CI の知らせも出ない。 止まる位置は OPT1 の受付と同じく実行の前 (in-loop) なので、 差は正本の食い違いと気づく時点にある
OPT3verify 行の判定を実行の時点に置く (gate が verify 行を撃つ直前に照合を掛けるか command guard を広げ、 撃つ command を実行の時点で止める)不採用

hook の command guard に 3 クラスの語列を足して便の中で当たった command を止めるか、 gate が verify 行を撃つ直前に同じ照合を掛けて止める。 決め手は分析 (止まるのは便を作った後の便の中で、 実装に使った token と手戻りが出る。 verify 行に当たる分については、 結局は行に classes を書き足すので、 OPT1 が受付で先にする断りを token を使った後に遅れて行うのと同じになる。 gate の変種は既存の質問の経路 (pipeline-question.md §5 の A 系) に乗れず、 gate から質問の段へ移る遷移を新しく要する。 command guard の変種は乗せうるが、 今の command guard は deny しか返さない)。 runner が便の中で撃つ Bash の分は OPT1 では見えず、 command guard を広げる形は CSQ-N1 の後続の決定に残す。 本 ADR が退けるのは、 verify 行の判定を実行の時点に置く形である。

命令を実行する時点で 3 クラスの語を当てて止める案です。 Bash の命令を実行の前に止める見張り (command guard) に語を足すか、 検査の段が検証の命令を撃つ直前に同じ当て方を掛けます。 実装役が便の中で撃つ命令まで覆え、 表の検査に手を入れずに済みます。 けれども止まるのは便の中で、 実装役が token を使った後 (検証の直前に掛ける形では実装を終えた後) になり、 手戻りも出ます。 検証の命令に当たる分は、 結局は行に 3 クラスを書き足すので、 選んだ案が仕事を作る前にする断りを、 token を使った後で遅れて行うのと同じです。 いまある問いの段の道 (便を止め、 契約の持ち主の席が行に 3 クラスを書き足し、 機械の回答を記して起こし直し、 起こす手前で人の許可を待つ道) に乗せれば、 許可を受ける口は増えません。 けれども当たる便ごとに、 止まる・書き足す・回答を記す・起こし直す・許可を待つという往復が起きます。 問いの段へ入れるのは実装役が問いを返して終えたときだけなので、 検証の直前に掛ける形はこの道に乗れず、 新しい移り方が要ります。 見張りに語を足す形は乗せうるものの、 いまの見張りは止めることしかできず、 止めた命令を問いへつなぐ形に変える手間が要ります。 見張りを広げる形では、 検証の命令は Claude の外で撃たれるので見張りが掛かりません。 実装役が便の中で撃つ命令の分は選んだ案では見えないので、 見張りを広げる形は後の決定に残します。 この記録が退けるのは、 検証の命令の判定を実行の時点に置く形です。 決め手は分析です。

+ 利点

  • runner が便の中で撃つ Bash も覆う (OPT1 の字面では見えない面)
  • 契約表の検査に手を入れない

− 欠点

  • 止まるのは便の中で、 実装に token を使った後 (gate の変種では実装を終えた後) になる。 verify 行に当たる分については、 結局は行に classes を書き足すので、 OPT1 が受付で先にする断りを、 token を使った後の便の中で遅れて行うのと同じになる。 既存の質問の経路 (pipeline-question.md §5 の A 系) に入る口は、 runner が質問 record を付けて rc 76 で終えた周の spawn の 1 つだけである。 gate の変種は実装を終えた後の gate で止まるのでこの経路に乗れず、 gate から質問の段へ移る遷移を新しく要する。 command guard の変種は乗せうるが、 今の command guard は deny しか返さないので、 deny を質問 record へ導く形に変えないと、 先に聞く操作を「絶対にやらない」操作に変える。 経路に乗った周は、 orchestrator (契約の所有者の席) が行に classes を足し、 機械由来の回答を記して resume し (回答が無い周の resume は rc 3 で何も書かない)、 写しを行から取り直して spawn の手前の関門で Blocked になり、 承認の subcommand が承認 event を記す。 承認の口は増えない (回答は機械由来で、 user の言葉は承認 event にだけ載る・C7.2) が、 当たる便ごとに停止・書き足し・回答の記帳・写しの取り直し・再 spawn・Blocked・承認の往復が起きる
  • command guard を広げる形では、 gate が撃つ verify 行は Claude の session の外で sh -c で撃たれ、 hook が掛からない (gate の直前の照合を足せば見えるが、 止まるのは同じく便の中である)
OPT4classes を必須の key にし、 3 クラスに当たらない行にも明示の 1 語を書かせる不採用

契約表の行と契約 file の classes を必須にし、 空の代わりに「当たらない」を表す 1 語を書かせる。 決め手は裁定 (判定が書き手の申告のままで、 機械が決める形にならない)。

3 クラスの欄を必ず書く欄にし、 当たらない行にも「当たらない」を表す 1 語を書かせる案です。 足す仕組みが最小で、 規則の行も user の決定も要らず、 書き手が行ごとに 3 クラスを考える機会が必ず生まれます。 けれども判定は名乗りのままで、 誤って「当たらない」と書いた行はそのまま通ります。 238 行すべてに書き足す手間が出るのに、 止められる名乗り忘れは増えません。 決め手は user の決定 (仕組みで守らせる) です。

+ 利点

  • 足す仕組みが最小で、 rules 行も裁定も要らない
  • 書き手が行ごとに 3 クラスを考える機会が必ず 1 回生まれる

  • 判定は依然として申告で、 誤って「当たらない」と書いた行はそのまま通る (DR1)
  • 既存の 238 行すべてに 1 語を書き足す手間が出るが、 止められる名乗り忘れは増えない
OPT5語列の判定表を rules 行でなく code の閉じた表に置く不採用

クラスごとの語列を core の const の表に置き、 型で網羅させる。 決め手は憲法 (C1 / C14 は執行する規則の値を manifest に置くことを、 C5 は値の変更に裁定 id を求める)。

種ごとの語の表を規則の行でなく、 器の code の中の閉じた表に置く案です。 値を後で変えるときに規則の行の決定を待たずに済み (今回の値は決定済みなので、 差はそこにだけ出ます)、 綴り違いを compile が捕まえる利点があります。 けれども器が執行する規則の値が規則の file の外に在ることになり、 値の変更が user の決定の印なしの code 変更で通ってしまいます。 憲法が求める「規則の値は規則の file 1 つ・変更には決定の印」を迂回し、 憲法の説明欄が書く「規則の行 + 判定の仕組み」の形からも外れます。 決め手は憲法です。

+ 利点

  • rules 行の裁定を待たずに実装を着地できる (今回の値は裁定済みなので、 差は値を後で変える周に出る)
  • 表の要素が型で閉じ、 綴り違いを compile が捕まえる

− 欠点

  • 執行する規則の値が manifest の外に在り、 値の変更が裁定 id なしの code 変更で通る (C1 / C14 / C5 を迂回する)
  • A4 の機構欄が書く「rules 行 + enforcer」の形から外れる
OPT6道具や seam の使用、 land の push まで導出の入力にする不採用

verify 行に加えて、 --pr-cmd の文面や vessel 宣言の remote への push を入力にし、 外へ出る操作をすべて導く。 決め手は憲法 (A4.3) と ADR-0008 (自 repo への PR は可逆で「出す」ではない)。

検証の命令に加えて、 PR を出す道具の文面や、 repo が名乗る送り先への送り出しまで材料にし、 外へ出る操作をすべて導く案です。 land が実際に repo の外へ出るかまで機械が見て、 送り先が他の repo を指すときも捕まえうる利点があります。 けれども自分の repo への branch の送り出しと PR 作成を「出す」と分類し、 便ごとに許可を消費します。 これは前の決定が廃止した形の持ち込みで、 憲法の「自分の repo への PR は取り消せる」に反します。 送り先の解決は道具の側に在り、 器が道具ごとの書き方を追いかけることにもなります。 決め手は憲法と前の決定です。

+ 利点

  • land が実際に repo の外へ出るかまで機械が見る
  • 宣言の remote が他 repo を指す周を捕まえうる

− 欠点

  • 自 repo への branch の push と PR 作成を「出す」に分類し、 便ごとに承認を消費する (ADR-0008 が廃止した形の再導入・A4.3 に反する)
  • 宛先の解決は道具の側に在り、 器が道具の方言を追う実装を抱え込む (ADR-0008 の却下案 (ii) の理由)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 3 種の操作の名前を 1 つの閉じた型にし、 種ごとの命令の語の並びを規則の行 1 つ (クラスの語列表) に置きます。 表の各要素は撃ってよい命令の上限の内の語で始まり、 受付が読む禁じる語列の全体 (禁じる側の規則の行と host の見張りの 3 行) のどれもまるごと含みません (含む要素は受付が先に断るので、 当たる行が無いためです)。 契約の表の検査は、 行ごとに検証の命令を表の各要素に、 禁じる語列と同じ関数で当て、 当たった種の集まり (クラスの導出) が行の名乗りに含まれなければ、 行番号と命令と当たった語を付けて全部を名指して断ります。 種は命令の語の並び (名前) で決め、 送り先は調べません。 止めるのは仕事を作る前の検査 (受付) で、 文書を直す段の CI は先に知らせる役です。 名乗りが広い行は通します。 表の行が無い・読めない・切られているときも断ります。 材料は検証の命令だけで、 触ってよい file の列、 自分の repo へ送り出す口、 repo が名乗る宣言の命令は材料にしません。 名乗る欄と、 許可を待つ段と許可の記録は変えません。 要件書では、 3 クラスを名乗る契約が止まる要件 (FR15) がこれで検証の命令が表に当たる契約すべてに届くこと (表が空なら何も変わりません)、 契約の不備を全部行番号付きで断る要件 (FR1)・禁じる語列を検証の命令に当てる要件 (FR56)・契約を表の 1 行だけから取る要件 (FR47) が形の根拠になること、 読めない入力を黙って通さない要件 (NFR4) がこの判定にも効くことを示します。

器 SHALL 3 クラスの名を閉じた型 1 つ (消す = delete・出す = publish・使う = consume) で持ち、 契約表の行と契約 file の classes の受理集合をこの型から取る。 器 SHALL クラスごとの command の語列を manifest の rules 行 1 つ (クラスの語列表) に置き、 行の kind は規則の閉じた型の variant 1 つ、 値の各要素は先頭の 1 語がクラスの名で残りの語が語列とする。 rules の読み SHALL 各要素の語列の先頭語が runner.allowed_commands の値に在ることを確かめ、 要素の語列が禁じる語列を含む (禁じる語列の先頭語が要素の語列の先頭語と同じで、 残りの語がすべて要素の語列に在る) 値を断る。 ここでの禁じる語列は、 受付が読む和集合 (runner.denied_commands と host の見張りの語列 3 行・command guard と共有する読み手 1 本) とする (上限の外の先頭語の要素と和集合の語列を含む要素は、 受付が先に断るので当たる行が無く死に値になるため)。 禁じる語列と一部だけ重なる要素 (例 git push と git push --force) は通し、 禁じる側の断りが先に立った残りの行だけに当たる。 値は裁定 id 付きの user 裁定でだけ変わり (C5)、 本 ADR は値を決めない。 クラスの語列表は契約表の検査を撃つ全経路 (contracts check・受付・resume の組み直し・land の追随) が同じ行 id の 1 行を読む (land の追随だけは --rules の差し替えを受けず常に埋め込みの manifest を読む・禁じる語列と同じ差)。 契約表の検査 (contracts check と受付が撃つ同じ 1 本) SHALL 行ごとに各 verify 行を語列表の各要素に禁じる語列と同じ照合の 1 本で当て、 当たった要素のクラスの集合 (クラスの導出字面から導いた 3 種) を作り、 導出に在って行の classes に無いクラスを行番号・verify 行・当たった語列付きで全件名指して断る (契約表の検査の断りの型に variant 1 つ・受付は既存の契約表の断りとして便を作らない)。 止めるのは受付 (in-loop) で、 contracts check (docs PR の CI) は事後の早い知らせとし止めの代わりにしない。 classes が導出より広い行は通す (字面に現れない操作を書き手が名乗る余地を残す)。 語列表の行が無い・読めない・不発効の周 SHALL 断る側へ倒す。 クラス SHALL verify 行の命令の語列 (名) で決め、 宛先を解かない (ADR-0008 の却下案 (ii) の宛先の判定を持ち込まない)。 導出の入力 SHALL 契約表の行の verify 行だけとする (約束の行から受付が生成する verify は cargo nextest の固定形なので入力にしない)。 器 SHALL NOT write-set を入力にしない (項目の 6 形はどれも対象 repo の中の path を指し、 その編集は A4.3 の依存なしの code 変更か A3 の門が持つ依存の変更である。 ~ の着地での削除も git で戻せるので「消す」に数えない)。 器 SHALL NOT land の口 (vessel 宣言の remote への push と CI の判定を読む行・pipe land の CLI 引数 --pr-cmd) と vessel 宣言の共通 verify・検出線の行を入力にしない。 ∴ land の口での自 repo への branch の push と PR 作成は導出に現れず、 ADR-0008 の判定 (A4.3 で可逆・承認を前提としない) は不変である。 承認の口 (spawn の手前の Blocked・逐語の承認 event・承認の subcommand) と申告の口 (行の classes) SHALL 不変とする。 runner が便の中で撃つ command と、 verify 行が起こす code の中の操作は本 ADR の導出の射程外とする。

3 種の操作の名前 (消す = delete・出す = publish・使う = consume) を 1 つの閉じた型で持ち、 契約の表の行と契約 file が名乗れる値をこの型から取ります。 種ごとの命令の語の並びは、 規則の file の行 1 つ (クラスの語列表) に置きます。 この行の種類は規則の閉じた型に 1 つ足し、 値の各要素は先頭の 1 語が種の名前で、 残りが語の並びです。 その集まりに在って行の名乗りに無い種があれば、 行番号と命令と当たった語を付けて全部を名指して断ります (検査の断りの種類に 1 つ足し、 受付は既存の表の断りとして仕事を作りません)。 止めるのは受付で、 CI は先に知らせる役です。 名乗りが導出より広い行は通します。 表の行が無い・読めない・切られているときは断ります。 材料は検証の命令だけです。 触ってよい file の列は材料にしません (項目の 6 つの形はどれも自分の repo の中の path を指し、 その変更は取り消せる code の変更か、 別の門が持つ依存の変更です。 着地で file を消す形も git から戻せるので「消す」に数えません)。 自分の repo へ送り出す口、 PR を出す口、 CI の結果を読む命令、 repo が名乗る宣言の命令も材料にしません。 ∴ 送り出す口での自分の repo への PR は導出に現れず、 前の決定 (取り消せる・許可を前提にしない) はそのままです。 種は検証の命令の語の並び (名前) で決め、 送り先は調べません。 許可を待つ段、 許可の記録、 許可の命令、 そして名乗る欄は変えません。 実装役が便の中で撃つ命令と、 検証の命令が起こす code の中の操作は、 この記録の導出の外です。 user の決定は、 決まりを書き手の作法でなく仕組みで守らせることでした。 3 クラスの関門を名乗りだけで立てている限り、 名乗り忘れた契約には関門が一度も立たず、 許可を記録する堅い仕組みが空回りします。 検証の命令は器が自分で撃つ命令で、 契約の表の行にそのまま書かれているので、 撃つ前に字面から種を導けます。 導いた種を名乗りに足すのでなく断るのは、 契約の正本である表の行を実際と合わせるためです。 止めるのは仕事を作る前の検査 (受付) で、 文書を直す段の CI は後からの検査なので、 先に知らせる役に留めて止めの代わりにしません。 名乗りが広い行を通すのは、 字面に現れない操作を書き手が名乗れる余地を残すためです。 材料を検証の命令だけにしたのは、 触ってよい file の列は自分の repo の中の変更しか指さず、 憲法がそれを取り消せる変更と扱うからです。 自分の repo へ送り出す口は契約の外 (repo の宣言と、 land を撃つ側が渡す引数) に在り、 前の決定が取り消せると決めたので、 材料にしないことで取り違えが構造の上で起きません。 種は命令の語の並び、 つまり名前で決めます。 これは前の決定が PR の道具からの導出で退けた「取り消せるかでなく名前で止める」性質を、 検証の命令の面で持ちます。 それでも受け入れるのは、 当たり過ぎても黙って通さず、 文書を直す段の CI の赤とその場での名乗りの書き足し・便ごとの許可の手間に倒れること、 決まった 3 つの語 (どれも git で始まる) はいまの表で当たる行が 0 本であること、 表の値を user の決定で狭く保てることの 3 つからです。 許可が安く大量に求められると形だけになって止まる力が薄れる (前の決定が気にした摩耗) ので、 表を狭く保つことがその備えになります。 この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、 代わりに引き受けることです。 名乗りを書き忘れた行でも、 検証の命令が表に当たれば仕事を作る前の検査 (受付) で止まり、 文書を直す段の CI が先に知らせます。 自分の repo への PR は材料に無いので許可を消費せず、 許可の仕組みと既存の test はそのまま効きます。 判定の値は規則の行 1 つに在って user の決定で変わり、 前の決定が書き手に預けた「名乗る作法」のうち、 検証の命令に現れる分だけを機械が引き受けます。 代わりに引き受けることは 6 つです。 実装役が便の中で撃つ命令や、 命令が起こす code の中の操作は見えません。 表の中身は user の決定 (2026-09-24T00:13Z) で決まりました。 出す = git push、 消す = git push --delete と git push -d、 使う = なしです。 値の正本は規則の行 1 つで (設計の文書の行はそれを載せる実装の契約です)、 この記録は値の正本になりません。 いまの表の行で当たるものは 0 本です。 撃ってよい命令の上限を広げるときは表も決め直します。 語の当て方は名前で決まり送り先を見ないので、 広い語は自分の repo への送り出しにも当たり、 そのときは CI に止められて名乗りを書き足す手間と、 便ごとの許可の手間になります。 器の中で上限の材料を組み立てる全部の箇所に欄が 1 つ増え、 憲法の説明欄の「次の版」の文は現物と食い違います。 repo が名乗る宣言の命令は材料の外に残ります。 PR を出す道具に他の repo へ送り出す道具を渡す穴 (前の決定が弱い点に挙げた例) も、 送り出しの口が材料の外なので開いたままです。
