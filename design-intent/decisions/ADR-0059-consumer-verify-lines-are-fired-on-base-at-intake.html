設計判断記録 (ADR) scribe2 — 入口の RED の受付での計測

消費側の契約の検証行を受付で base の木でも撃ち、 base で緑のままの行の本数を記録に残す (断るか記すだけかは宣言の名乗りの語が選ぶ・ADR-0054 の値の集合を部分 supersede)

ADR-0054 は、 入口の flip (test 差分だけを base に当てて RED を確かめる検査) を撃つ手段を持たない Rust の消費側が、 宣言の任意 key で「測らない」と名乗れる欄を開けた。 名乗った消費側の便は入口の RED を測らないまま進む (ADR-0054 CSQ-N1)。 本 ADR は、 消費側の契約の検証行そのものを受付の段で base の木でも撃ち、 base でも緑のままの行の本数を記録に残す形と、 断るか記すだけかを宣言の名乗りの語が選ぶ形を決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は器が自動で進める 1 つの作業、 「消費側」は器を使う別の repo、 「台帳」は作業の記録簿、 「宣言 file」は repo が器に渡す設定 file (.vessel.toml) のことです。 題の「検証行」は歯 (自動テスト) を撃つ命令、 「受付」は作業を便にする前の検査です。 台帳の決まりでは、 歯は作業の前の状態 (base) では落ち、 作業の後で通るはずです。 ところが器の検査の段は、 作業の後で通ることしか見ていません。 先の記録 (ADR-0054) は、 それを確かめる道具を持たない消費側が「測らない」と名乗れる欄を開けました。 この記録は、 宣言 file に「記す」か「止める」と書いた消費側の作業について、 器が受付の時点で歯の命令のうちテストの専用道具 (nextest) の命令を作業の前の状態でも実際に撃ち (ほかの命令と、 歯の名を絞らない命令と歯が無いときに落ちる旗を持たない命令は撃たずに測れなかったと記し、 該当する歯が無いと確かめられる命令も撃ちません)、 前の状態でも通ってしまう命令の本数を残す形を決めます。 止めるか記すだけかは、 消費側が宣言 file の 1 語で選びます。 「測らない」のままの消費側と、 名乗りの無い repo (本 repo を含む) の受付の結果は今までどおりです (読む順を入れ替えるので、 断りの理由の出る順が入れ替わる周だけは除きます)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 実測と器の中身から説明します。 消費側 1 号で、 作業の前の状態でも通ってしまう歯を持つ作業が検査を通りました。 器の受付は host 全体の鍵を取ってから材料を読み、 判定して、 通った作業にだけ記録の置き場と出来事の記録を作ります。 断る周はどちらも作りません。 判定は受付・便を作らずに検査だけ撃つ口・便を配る 1 周の 3 か所が共有する 1 本です。 作業の前の状態 (base) は受付では決まらず、 受付の後の審査を経て作業の木を切るときに読み直されます。 検査の段は作業の後の木で、 歯の命令を 1 本ごとに host の混み具合の遮断器に通してから囲いの中で撃ち、 その囲いは命令の終わり方を数字 (rc) で返します。 歯の命令を前の状態で撃ったときの答えは、 前の状態が同じ commit なら受付で撃っても検査の段で撃っても同じなので、 実装役を動かす前の受付で撃つのが筋です。 消費側は「base で撃つ検査は要るか」に「要る」と答え、 止めるか記すだけかは宣言で選びたいと言っています。

CTX1

実測 — 消費側器を使う別の repo 1 号で、 base でも緑の歯違反を機械で止める検査が gate を通った

消費側 1 号の席の報告 (2026-09-22・要旨) — 台帳の規則は「検証は base で RED になる歯」だが、 器の gate は便の木で検証行が緑になることしか見ない。 base (便が分かれた元の commit の木) でも緑のままの歯を持つ便が gate を通った実例が在る。 消費側は xtask (本 repo だけが持つ開発用の道具) を持たないので、 本 repo の入口の flip をそのまま撃つことはできない。 消費側が求める形は「契約の検証行そのものを base の木作業の前の状態の木で撃つ」で、 test 差分を base に重ねて測る本 repo の flip とは別の形である (ADR-0054 CTX3)。

CTX2

現物 — 受付・preflight・gate・dispatch・閉じ込めと base の所在

受付便にする前の検査は host 全体の入口の lock (ADR-0019 §2.1) を取ってから、 上限の読み・材料の読み (base の tracked file の走査と宣言の読み・1 周に 1 回)・行の生成と表の検査・判定・作成を撃ち (judge は設計 doc の行を作業木から write-set の弁別と行の事実で 2 回読む)、 通った周だけ run dir を作って event を記す。 断る周は run dir も event も作らない。 判定 (judge) は受付・preflight・dispatch の候補の判定が共有する 1 本で (C2)、 その先頭の上限との突き合わせ (freeze) は HEAD の commit の宣言を読み直す。 材料は sha を持たない (tracked は index から、 本文は作業木から読む)。 preflight は judge を run dir も event も作らずに撃ち、 置き場が解けない周も通る。 受付と preflight は --repo に渡した木 (dispatch が起こす受付では anchor) の HEAD を読むが、 便の base は受付では決まらず、 受付の後の契約の審査 (lens) を経た spawn の初回の周が対象 repo の HEAD を読み直して決め、 event に記す。 gate は便の木で契約の検証行歯を撃つ命令を 1 行ごとに器の健康の遮断器 (health::pass・待ちの上限を超えた行とそれ以後の行は撃たずに閉じる) に通してから閉じ込めの 1 関数で 1 本ずつ撃ち、 行ごとの rc と秒を verify の記録に残す。 その関数は行を sh -c で撃ち、 子が signal で死ぬと rc は 128+N、 無い command は 127、 起動できない周は -1 になり、 箱の oom_kill の数を別に返す。 契約の検証行は穴を持たず、 admission (ADR-0021・host の memory と CPU の枠) の札を取らずに host の memory から予備を引いた箱で撃たれる (札を取るのは {jobs} を持つ共通の検証と検出線だけ)。 gate の便の本数は受付の同時本数の上限 (pipe.max_live) が抑える。 時間の上限は持たない。 便が main を追随する周は base が新しい sha に移り、 land は対象 repo の main を update-ref で進める。 closure の nextest の行の読み (nextest_read) は cargo nextest run で書き出し filter 語を持つ行だけを読み、 -p の無い行の crate を器自身の crate 名に倒す (本 repo の閉包のための既定値)。 ADR-0054 の名乗り (宣言の任意 key entrance-flip・値は unmeasured の 1 語) は受付と契約表の検査の NoEntranceRed の断りを外し、 契約表の検査の判定行結果を 1 行で出す口に entrance=unmeasured を出す。

CTX3

何を捕まえるか — base の sha が同じなら結果は受付でも gate でも同じ

歯 (test) は便の実装役が書くので、 base の木には便の新しい歯が無い。 検証行を base の木で撃つと、 base に既に在る通る歯に当たる行は rc 0 で「base で緑」になる。 消費側の実例 (CTX1) はこれである＝検証行が base の既存の緑の歯で満たされ、 便の実装が無くても通る行。 新しい歯だけを名指す行は、 歯が base に既に在る test binary に入るなら該当 0 本 (--no-tests=fail の nextest の rc 4)、 test target や crate ごと新しいなら base に無い target の断りになり、 どちらも「base で緑」ではない。 rc で歯の有無と落ち方を弁別できるのは nextest の行だけで (0 = 通った・4 = 該当 0 本・100 = 歯が落ちた・101 = build の失敗)、 cargo test は該当 0 本でも rc 0 を返し、 他の言語の test 走者や script は build・収集・file の不在も 1 や 2 などの rc で返す。 test 差分を base に重ねない限り、 base の sha が同じならこの結果は便の木が在る gate の段でも変わらない。 ただし便の base は受付の後の spawn で読み直されるので、 審査の段の間に main が進めば、 受付で測った base と便の base は違う。 それでも測る段は、 便を起こす前で実装役の費用を払わない受付が適し、 その費用は受付を撃つたびに base の実走 1 回である (dispatch の候補の判定には載せない・build は入口の lock の外で撃つ)。 便の木に歯が在る段で歯の単位まで測るのは入口の flip (差分の重ね合わせ・ADR-0054 OPT3) の領分である。

CTX4

消費側の要望と憲法の向き

消費側 1 号の席は「base で撃つ検査は要るか」に「要る」と答えた (2026-09-23・要旨)。 求める形は、 契約の検証行を base の木で撃ち、 1 本も落ちなければ記録に残し、 断るか通すかは消費側の宣言 (.vessel.toml の key) で選べること。 この形は契約の単位 (全行が base で緑のときだけ RED 無しと記す) で、 本 ADR は行の単位 (1 本でも base で緑なら数える) を採る (理由は decision)。 ADR-0010 §2.1 は宣言が値を持ち器の行は上限だけを持つと決め、 ADR-0047 / ADR-0054 は任意 key を宣言の側に置く分担を決めた。 断るか記すだけかを宣言の 1 語で選ぶ形はこの分担の延長で、 器の rules 行の追加でも憲法 C12.4 の昇格 (変異の生存の検出線を裁定 id で deny にする) でもない。 C10 は実測値を型で分け、 測っていない値を実測として通さない。 C2 は同じ仕事の口を 2 つ作らない。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 消費側の歯の命令そのものを前の状態で撃つこと、 止めるか記すだけかを宣言の側が選ぶこと、 終わり方の数字で歯の有無と落ち方を見分けられる命令だけを撃って結果の全部を 4 通りに写し、 測れない周を成功に倒さないこと、 そして命令を撃つ口は検査の段と同じ 1 つを使い、 止める判定は既存の判定の 1 本に置き、 便を配る 1 周では撃たず、 重い build を受付の鍵の中に入れず、 本 repo 自身の宣言と入口の検査と名乗りの無い repo の受付の結果は 1 字も変えないことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 名乗りの語を 3 語に広げて受付で前の状態でも撃つ案、 検査の段で撃つ案、 本 repo の入口の検査を器に内蔵する案、 AI の審査に読ませる案、 何もしない案です。 却下した 4 案も利点を持ち、 それを含めて秤に掛けます。

OPT1名乗りの語宣言に書く 1 語の値を 3 語に広げ、 名乗った契約の受付 (と preflight) が入口の lock の前に検証行を base の木でも撃ち、 4 値の結果を記録と 1 行に出す採用

宣言の任意 key entrance-flip の値を unmeasured (現行) に detect と deny を足した閉じた 3 語にする。 受付は上限の読み・材料の読み・上限との突き合わせを入口の lock の前へ移して 1 周に 1 回撃ち、 撃つ行を決める行の生成と表の検査も lock の前に撃ち、 lock の中の judge は突き合わせの結果 (有効値と名乗りの語) を借りて宣言を読み直さない (行は今までどおり作業木から 2 回読み直す)。 材料の読みの前に名乗りに依らず HEAD の sha を読み、 detect か deny を名乗った宣言では、 その sha の木を state dir の一時 dir に detach した worktree として用意して、 契約の検証行のうち nextest の行 (nextest_read の読み方で filter 語を持つ行・読み手は既存の 1 本のまま広げない・共通の検証は撃たない) だけを、 gate の契約の検証行と同じ健康の遮断器を 1 行ごとに通して同じ閉じ込めの 1 関数・同じ箱 (admission の札は取らない) で 1 本ずつ撃ち、 撃ち終えたら木を片付ける。 nextest の行でない行と --no-tests=fail を持たない nextest の行は撃たずに測れないとする。 語の全体を読み切れる行 (行の全体が ASCII の英数字と _-.:=/ と space だけ・-p と --test が space で区切った旗と値で丁度 1 つずつ・値は - で始まらない・他の旗は --no-tests=fail と -- の後ろの libtest の引数だけ・= の形の -p と --test は不可) で、 -p の名が sha の木の members の glob でない項の dir の package と逐語で一致し、 その dir に --test の target が無いと決まる行だけを撃たずに不在とし、 他の行 (-p の無い行・読み切れない行・root の package・[workspace] の無い単一 crate・glob の members・新しい crate を名指す行を含む) は既定の crate を当てずに撃つ (該当 0 本は nextest の rc 4 が不在を返す)。 撃った行は 0 = base で緑・4 = 不在・100 = 落ちた・他 (101・signal・-1 を含む) = 測れない に写し、 oom_kill が 1 以上の行と、 遮断器が閉じた行とそれ以後の行も測れないとする。 木を用意できない周・置き場の解けない preflight の周・実走の後に読み直した HEAD の sha が違う周は全行を測れないとする。 受付の 1 行と preflight の行に entrance=green-on-base:<本数>/<行数> (行数は契約の検証行の全本数・測れない行があれば unmeasurable:<本数> を添える) を出し、 通った周は run dir に測った sha と行ごとの 4 値・rc・秒の記録を残す。 detect は記すだけで受付を変えず、 deny は base で緑か測れない行が 1 本以上あれば judge の判定関数 1 本が typed な理由 1 つで断り、 便も run dir も event も作らない。 dispatch の候補の判定では撃たない。 unmeasured と key の無い宣言は現行のとおり (本 repo は撃たない)。

宣言 file の 1 語を、 今ある「測らない」に「記す」と「止める」を足した 3 語にします。 受付は、 上限の読みと repo の材料の読みと許す命令の検査を鍵を取る前へ移して 1 回だけ撃ち、 撃つ命令を決める表の検査も鍵の前に撃ち、 鍵の中の判定はその結果を借りて宣言を読み直しません (表の行は今までどおり鍵の中で 2 回読み直します)。 受付は名乗りに関わらず材料を読む前の時点の前の状態 (commit) を控え、 「記す」か「止める」を名乗った消費側の作業では、 その木を一時的に用意して、 検査を通った歯の命令のうちテストの専用道具 (nextest) の命令だけを、 検査の段と同じ混み具合の遮断器に通して同じ囲い (memory の札は取らない) で 1 本ずつ撃ち、 撃ち終えたら木を片付けます。 専用道具の命令だけを撃つのは、 それだけが終わり方の数字で「歯が無い」「歯が落ちた」「build が落ちた」を分けて返すからです。 専用道具でない命令と、 歯の名を絞らない専用道具の命令と、 歯が無いときに落ちる旗を持たない専用道具の命令は撃たずに「測れなかった」とします。 撃たずに「該当する歯が無い」とするのは、 命令の全体を読み切れて (命令の全体が半角の英数字と少しの記号 (_ - . : = /) と半角の空白だけで書かれ、 部品と置き場の名指しが半角の空白で区切って 1 つずつで、 その名が - で始まらず、 歯が無ければ落ちる旗と、 歯の名のあとに添える試験の引数のほかに旗を持たない)、 部品が前の木の部品の一覧にそのまま書かれていて、 置き場だけが無いと確かめられた命令だけです。 確かめられない命令 (読み切れない命令、 部品の一覧の書き方が読めない repo の命令、 新しい部品を名指す命令を含みます) は撃って、 専用道具自身の答えに任せます。 撃った命令の結果は 4 通りに写します。 通ってしまった (前の木でも合格)、 該当する歯が無い、 落ちた、 測れなかった (build の失敗・途中で殺された・memory が溢れた・遮断器の待ちが上限を超えた) です。 木を用意できなかった周と、 撃った後に前の状態が動いていた周は、 全部を測れなかったとします。 通った作業では記録の置き場に控えた commit と命令ごとの結果を残し、 受付の 1 行に「前の木でも通った本数 / 命令の本数」を出し、 測れなかった命令があればその本数も添えます。 「記す」は結果を残すだけで受付の合否は変えず、 「止める」は通ってしまった命令か測れなかった命令が 1 本でもあれば既存の判定の 1 本で理由を 1 つ付けて断り、 便も記録の置き場も出来事の記録も作りません。 便を配る 1 周の判定では撃ちません。 「測らない」と名乗りの無い repo (本 repo を含む) は受付の結果が今までどおりで、 前の木は作りません。 利点は、 便を起こす前に実装役の費用を払わずに捕まえられ、 器の規則を増やさないことです。 代償は、 受付のたびに前の木を作って撃つ時間と memory と遮断器の待ちが載り、 それが同時本数の上限にも memory の枠にも数えられずに並びうること、 命令の単位でしか測れないこと、 専用道具でない命令と、 歯の名を絞らない専用道具の命令と、 確かめられずに撃った新しい部品や置き場を名指す命令は測れないに写ること、 結果が受付の時点の前の状態のもので作業の木を切るときの前の状態とは違いうること、 撃つ間に他の作業が着地して前の状態が動くと全部が測れなかったになり、 「止める」では正当な作業も断られて受付の撃ち直しを待つこと、 便を配る 1 周は止める判定を見ずに便を起こすことです。

+ 利点

  • 消費側の「検証は base で RED になる歯」が、 消費側の道具を増やさず、 便を起こす前に器の記録と断りになる (DR1・CTX3)
  • 断るか記すだけかは宣言の 1 語で選び、 器の行も schema も event の種類も増えない (DR2)
  • rc で歯の有無と落ち方を弁別できる nextest の行だけを撃ち、 他の行と build の失敗・signal を測れないに写し、 撃たずに決める不在は語の全体を読み切れ、 members の glob でない項の dir の package に --test の target が無いと決まる行だけに限り、 読み切れない行と解けない構造の行は撃つので (撃たずに決めた不在が base で緑 (rc 0) の行を含まないのは、 cargo の差し替えの無い木で、 読み切れる行に限ることで成り立つ)、 測れない周が緑にも落ちたにも倒れず、 deny は測れない周を断る側に倒す (DR3)
  • 撃つ口は gate の 1 関数の再利用で、 deny の断りは judge の 1 本に在り preflight と受付が同じ断りを出し、 build は入口の lock に載らず、 key の無い宣言と unmeasured の結果は 1 字も変わらない (断りの先後の入れ替わりは除く・DR4)

− 欠点

  • 受付を撃つたびに、 名乗った契約 1 本につき base の木の用意と検証行の実走 (Rust なら target の無い木での cold build) が 1 回載り、 preflight も同じ実走を撃つ。 実走は入口の lock と同時本数の上限 (pipe.max_live) より前で admission の枠の外に在り、 host の memory を上限にした箱で受付の数だけ同時に走りうる (gate の便の本数は max_live が抑えるのと非対称)。 1 行ごとに gate と同じ健康の遮断器を通るので、 host が重い周は受付がその待ちの分だけ延び、 待ちの上限を超えた行とそれ以後の行は測れないになる (deny では断られる)。 lock の中の断りで断られた受付を撃ち直すと実走も繰り返される
  • 粒度は検証行の単位で、 1 本でも base で緑なら deny は断る。 既存の族の接頭辞・外形 snapshot の歯・回帰を守る既存の歯を名指す行は base で緑と数えられる (消費側は新しい接頭辞で書き、 回帰の歯を共通の検証に置く運用が要る)
  • nextest の行でない行 (cargo test・clippy・他の言語の test 走者・script・filter 語を持たない cargo nextest run の行〔test target を丸ごと撃つ行〕・cargo nextest run で書き出さない行〔timeout や env の前置きを持つ行〕) と --no-tests=fail を持たない nextest の行は撃たずに測れないになり、 deny ではどちらも断られる。 事前判定で読み切れない行と解けない構造の行が base に無い crate か test target を名指すと、 撃たれて cargo が落ち、 測れないになる (新しい crate や target の歯の行は deny で断られる)。 glob の members を展開して解く形は、 行の読み手に Cargo の glob と exclude の規則を足すので採らない。 読み切れる条件は行の字面だけを見て、 受付は base の木の cargo の差し替え (.cargo の config の alias・rust-toolchain の toolchain の path など) を読まないので、 それで cargo か cargo nextest が差し替えられる周は測れない側に倒れない可能性が残り、 撃たずに不在と決めた行も差し替えた木で撃てば rc 0 になりうる (限界・alias も path も偽の cargo を指す木で rc 0 を実測)。 読み切れる行でも引数の誤りの行 (撃てば rc 96・rc 2) は撃たずに不在と決まりうる (rc 0 にはならず、 便の木の gate が落とす)。 cargo 以外の言語の消費側は detect で本数を読むだけになる
  • 結果は受付で測った sha のもので、 受付の後の審査の段で main が進むと spawn が決める便の base と違う。 便が main を追随すると gate はやり直すが、 base の実走は受付の 1 回のまま測り直さない (違いは記録の sha と spawn の event の base の突き合わせで弁別できる)。 実走の間に land などで HEAD が動いた周は全行が測れないになり、 deny の repo では契約の中身に関わらず断られ、 便が続けて land する時間帯ほど起きやすい。 撃った行は lock の前に読んだ行のもので、 lock の中の judge が作業木から読み直す行とは、 その間に設計 doc が書き換わると違いうる。 時間の上限は無く、 止まった行は受付を止め続ける
  • dispatch の候補の判定は base を撃たないので deny の断りを見ずに便を起こし、 受付で断られた bead は Launched の印で止まり release を待つ
OPT2gate の段で検証行を base の木でも撃つ不採用

便の木が在る gate で、 便の base の sha の木を用意し同じ検証行を撃つ。

検査の段 (作業の後の木がある時点) で、 前の状態の木を用意して同じ命令を撃つ案です。 受付に何も足さず、 記録が検査の記録 1 か所に揃い、 作業の木を切ったときの実際の前の状態を測れ、 検査をやり直すたびに測り直せる (作業が最新に追随した後の前の状態も測れる) うえ、 撃つ前の状態が作業の前の状態に固まっているので撃つ間に最新が進んでも結果を捨てず、 前の状態で撃つ実走が便の同時本数の上限の内に収まり、 受付の読む順を変えることも、 検査だけ撃つ口が一時の木を書くことも要らない利点はあります。 しかし前の状態が同じ commit なら、 歯の差分を重ねない純粋な前の木で撃つ答えは受付で撃った場合と同じです。 便を起こして実装役を動かした後に答えを得ることになり、 「止める」の断りも作業の木と席の費用を払ってからになります。 受付より新しい前の状態を測れるのは、 審査の間や追随で最新が進んだ周だけです。

+ 利点

  • 受付に何も足さず、 記録が gate の verify の記録 1 か所に揃う
  • spawn の時点の便の実際の base を測り、 再 gate のたびに測り直せるので、 追随で base が移った後の base も測れる。 撃つ sha が便の base に固まっているので、 撃つ間に main が進んでも結果を捨てない
  • base の実走が gate の便の本数の上限 (pipe.max_live) の内に収まり、 受付の読みを lock の前へ移すことも、 preflight が一時の木を書くことも要らない

− 欠点

  • base の sha が同じなら純粋な base の木での結果は受付と同じで、 便を起こして実装役を動かした後に答えを得る (実装役の費用を払ってから断る・CTX3)。 受付より新しい base を測れるのは、 審査の段や追随で main が進んだ周だけである
  • deny の断りが Gated FAIL になり、 便の木と席の費用を払ってから断る

ADR-0054 OPT3 と同じ。 xtask の flip を器の口にして消費側の gate でも撃つ。

  • 読みの結果は再現せず、 記録にも同じ形で残らない (C10)

− 欠点

  • 測らなかったことは判定行に残るが、 測った結果はどこにも残らない
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 宣言 file の 1 語 (測らない / 記す / 止める) で消費側が選び、 記すか止めるかを選んだ作業では、 受付が鍵を取る前に材料を読んで表と許す命令を検査し、 その時点の前の状態の木を一時的に用意して、 テストの専用道具 (nextest) の命令だけを検査の段と同じ混み具合の遮断器に通して 1 本ずつ撃ち、 結果を 4 通り (前の木でも通った・該当する歯が無い・落ちた・測れなかった) に写して、 通った本数を受付の 1 行に出します。 専用道具でない命令と、 歯の名を絞らない命令と歯が無いときに落ちる旗を持たない専用道具の命令は撃たずに測れなかったとし、 撃たずに「該当する歯が無い」とするのは、 命令の全体を読み切れて、 部品の一覧にそのまま書かれた部品のテストの置き場を名指し、 それが前の木に無いと確かめられた命令だけで、 確かめられない命令は撃ちます。 止めるを選んだ場合は、 通った命令か測れなかった命令が 1 本でもあれば既存の判定の 1 本で断り、 便も記録の置き場も出来事の記録も作らず、 理由を断りの行と便を作らない検査の行に出します。
