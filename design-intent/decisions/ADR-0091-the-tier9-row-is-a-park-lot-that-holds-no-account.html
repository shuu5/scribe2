設計判断記録 (ADR) scribe2 — park の区画

群の表の名 Tier9 の行は群でなく park の区画で、 口座を占めない — 区画は群の今の口座・種・予約・群の移動の判定・移動を頼む記録を持たず、 どの口座選定からも口座を除かず、 席は行が並べた口座からの session 用の選定の口座に居て、 park の移り先の判定が口座を返した周だけ移る (ADR-0069 の群の名の句と ADR-0049 の便用の row の除外の範囲を部分 supersede)

群は宣言した置き場の席を群の今の口座 1 つに集め、 その口座を占める。 席は残すが日々は動かさない repo を置く場所が無く、 群に入れても群の外に置いても口座を占めていた。 本 ADR は群の表の名 Tier9 の行を、 口座を占めず pipeline を妨げない park の区画と決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「便」は契約 1 本を実装から着地まで運ぶ 1 回の走り、 「口座」は席や便が使う Claude Code の login 単位、 「群」は同じ口座を共有する project のかたまりです。 群は自分の席をいま使う口座 1 つに集め、 その口座を占めます。 席は残しておくが日々は動かさない repo を置く場所が無く、 群に入れても群の外に置いても口座を占めていました。 この記録は、 群を宣言する表の名 Tier9 の行を、 群ではない「park の区画」と決めます。 区画は口座を占めず、 どの口座の選び方からも口座を外さず、 群の移動や便を待たせません。 区画の席は、 名指した口座か、 行に並べた口座から選んだ余裕のある口座に居て、 いまの口座の使った割合が線以上になった新しい記録があり、 移り先の候補がある周だけ、 別の口座へ移ります。 行に並べた口座の宣言は、 群の宣言と同じく、 その口座を使うことの前もっての承認と読みます。 移り先は席を起こすときと同じ口座の選び方で決まるので、 席の起動が承認を記録しないのと同じく、 移るたびの承認も記録しません。 要件書では、 区画の要件 FR95 と、 表の名・口座の選び方・見回り・席の起動・doctor の数え・公開の見張り・席の入力欄への差し込み・host の宣言の読みの要件 (FR38・FR36・FR27・FR59・FR73・FR80・FR44・FR57) を支えます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (群は口座を 1 つ占める)・事象 (休ませる置き場の行き場が無い)・持ち主の裁定・要件書の側・憲法の向き・この判断の範囲の 6 つから説明します。 群に入れても、 群の外に置いても、 休ませたい置き場は口座を占めていました。 憲法の向きには、 行に並べた口座の宣言を、 その口座を使うことの前もっての承認と読む解釈も含みます。

CTX1

経緯 — 群は口座を 1 つ占める

ADR-0049 は席の口座を持つ単位を project の群とし、 群の宣言 (名・置き場の列・候補の口座の列) を host の面の表 1 つに置き、 群の今の口座かたまりがいま使う口座を host の根の記録 1 件で持つと決めた。 群の置き場の席はどの置き場からでも群の今の口座に居て、 便用の口座選定は群の口座を host 全体で候補から外す (ADR-0049 の群の候補の口座の全部は、 ADR-0068 で群の今の口座だけになった)。 ADR-0069 は群の名を Tier<数字> (数字は重複しない・宣言順は数字の昇順) に固定し、 移り先を残量の鍵で並べ、 群を宣言順に見て群ごとの予約を導く形にした。 群の移り先と予約は他の群の今の口座を避け、 群の移動の判定は host の lock の内側で撃つ (ADR-0066)。 こうして群は口座を 1 つ占め、 他の群の移動と便の選定はその口座を使えない。

CTX2

事象 — 休ませる置き場の行き場が無い

席は残すが日々は動かさない repo の置き場が無い。 群に入れると、 その群が口座を 1 つ占め、 他の群の移り先と予約と便の選定からその口座が外れる。 群の外に置くと、 席の登録 row の口座席の登録の口座が他の席の session 用の口座選定から外れる (FR36 の、 自席の鍵の外の登録 row の除外) ので、 やはり口座を占める。 群の外の席は群の移動の判定の外に在り、 口座が逼迫しても管理 tick周期で席を見回る仕事 は row の口座のまま起こし直すだけで移さず、 heartbeat の合図も既定で届く。 今の読み手は群の名の形 (Tier と先頭に 0 の無い数字・昇順) だけを見るので、 Tier9 の行を宣言すると群として読まれ、 口座を 1 つ占める。 当座は、 休ませたい置き場を群から外し、 口座の替えは人が手で行っている。

CTX3

裁定 — 口座を占めず、 pipeline を妨げない

持ち主は 2026-09-28T01:55Z に、 名 Tier9 の置き場を口座を占めない特別な置き場として器に載せ (便を撃ってよく、 他の群の移り先にも使ってよい)、 heartbeat の合図の既定を off にするよう指示した。 02:00Z には論点 4 つ (名 Tier9 をこの置き場に予約する・予約も排他もせず口座は session 用の口座選定で決める・heartbeat の明示の記録・行ごとの既定) を推奨で決着した。 2026-09-29T00:54Z には、 判断の要る点を推奨で進めるよう常設で指示した。 05:01Z には、 この置き場は pipeline を妨げず、 他の Tier と違って口座を占めないことを再び確かめた。 05:44Z には、 席の口座の候補を行が並べた口座だけにすると決めた。 要旨だけを写し、 逐語は台帳が持つ (記録は memo s2-07l.730)。

CTX4

要件の側 — SRS v0.30 が区画の手を FR95 に集めた

SRS v0.30 は park の区画口座を占めない休ませ場所の手を新しい FR95 に集め、 FR38 に群の表かたまりを宣言する表の名の句 (Tier1〜Tier9 に限り、 Tier9 の行は park の区画) と、 群の手 (逼迫の通知・移動を頼む記録・移動・予約) は群だけに掛かる句を置いた。 FR57 は群の表の名の断りを host の面の読みの断りの列に置く。 FR36 は park の区画の置き場の席の row の口座を便用と session 用の除外に入れず、 session 用の閾値候補にできる使用率の上限の rules 行は今は R-C9-1 の 1 本で、 窓別の行は user 裁定で足す枠として FR36 に在る。 FR59 は区画の席の起動の口座を引数か FR95 の候補からの選定で決め、 FR27 は管理 tick の周に park の移り先の判定区画の席の移り先の決め方を撃たせ、 FR44 は器の差し込みの閉じた一覧に park の区画の移動の退避の合図を入れる。 FR73 は doctor が数える登録 row の anchor の件数を、 群の表のどの行 (群と park の区画) の anchor にも無いものに限り、 FR80 は隣の private repo と可視性を問う anchor を群の表の行 (群と park の区画) の anchor から導く。 区画の heartbeat の既定 (off) は FR78 が持ち、 本 ADR の外に在る。 SRS の glossary は、 修飾の無い「群」を Tier1〜Tier8 の行の群だけに限る。

CTX5

憲法の向き (本 ADR の解釈)

A1 (使う): Tier9 の行が並べた口座の宣言を、 その口座を「使う」ことの常設の承認と読む (ADR-0049 の群の宣言と同じ形)。 区画の席の移り先は席の起動と同じ session 用の口座選定 (FR36) で決まり、 起動の口座選定が承認 event を書かないのと同じく、 区画の移動も承認 event を書かない。 群の移動が群の今の口座の記録を書き換える周に承認 event を書くこと (ADR-0049) は変えない。 移った事実は管理 tick の判定行 (次の周で上書きされる) と、 起こし直し (FR59) が event log に記帳する席の登録に残る。 この読みは裁定 02:00Z (口座は session 用の口座選定で決める) と 05:44Z (候補は行が並べた口座だけ) に沿い、 裁定 00:54Z の下で推奨のまま決めた。 N3 (host 固有の値で分岐しない): 器が分けるのは名 Tier9 という器の文法が固定する名で、 どの置き場を区画に置くかは host の面の宣言値のまま (C10.2) なので、 名を host 固有の値とは読まない。 C2 (選定は 1 本の関数): 区画の席の口座は既存の session 用の口座選定 1 本を、 候補を行が並べた口座に絞って呼ぶだけで、 選定の関数を足さない。 行が群か区画かは名から導く閉じた 2 種で決まる。 C9.2 (R-C9-1 の選定規則に従って口座を窓の終わりまで使う): 区画の席が移る線を選定と同じ session 用の閾値の rules 行に置く。 C17 (決定はしご): 区画を表すのに新しい表・key・rules 行・記録を足さず、 足す仕組みは park の移り先の判定 1 本で、 消すのは休ませたい置き場の口座を人が手で替える手順である。

CTX6

射程 — 動かすのは 4 つ、 群の仕組みは動かさない

動かすのは (1) 群の表の名の句 (Tier1〜Tier9 に限り、 Tier9 の行を park の区画にする)、 (2) 区画の置き場の席の row の口座を便用と session 用の除外に入れないこと、 (3) 区画の席の起動と起こし直しの口座と park の移り先の判定 (row の口座が同じ間は移り先が変わっても退避の合図を重ねないことを含む)、 (4) 区画の席の hook の告げ方と doctor の kind=park の行、 の 4 つ。 動かさないのは、 群の今の口座の記録と種・残量の鍵・群の予約と排他・群の移動の判定と契機と lock・群の移動の承認 event・退避の合図と猶予 (ADR-0079)・起こし直しが会話 id を運ぶこと・便用の並べ鍵・閾値の rules 行の値・doctor の群の行の欄・宣言の表の数 (群の表 1 つのまま)。 heartbeat の決め方は本 ADR の外に在る。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 口座を占めないこと。 pipeline (群の移動と便の流れ) を待たせないこと。 種類を 1 語で読め、 宣言の形と仕組みを増やさないこと。 口座の選び方の決まりと同じ線で移り、 移った先ですぐ移り直す往復をしないこと。 席の口座の候補を行に並べた口座だけにすること。

DR1口座を占めない — 区画は口座の記録も予約も持たず、 どの選定からも口座を除かない CTX2・CTX3
DR2pipeline を妨げない — 区画の手は host の lock を取らず計測を起こさず、 群の移動と便を待たせない CTX1・CTX3
DR3種類を 1 語で読め、 宣言の形と仕組みを増やさない — 名で種類が決まり、 区画を表すのに表・key・rules 行・記録を足さない (C2・C17) CTX5
DR4選定の規則の線で移る — 移る線と移り先を選ぶ線を、 選定の規則 (R-C9-1) の session 用の閾値の rules 行に揃え、 移った先ですぐ移り直す往復も起こさない (C9.2) CTX5
DR5候補は行が並べた口座だけ — 区画の席は宣言の外の口座へ、 引数で名指されない限り行かない CTX3
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 4 つ並べます。 名 Tier9 の行を park の区画にする案 (選んだ案) と、 選ばなかった 3 つです。 選ばなかったのは、 群の行に種類の欄を足す案、 区画を作らず群の外に置いたままにする案、 区画の席が移る線を群の逼迫の線にする案です。

OPT1名 Tier9 の行を park の区画とし、 口座を占めず、 移り先の判定で移る採用

群の表の行の名を Tier1〜Tier9 に限り、 Tier9 の行を群でなく park の区画とする。 区画は群の今の口座の記録・種・予約・群の移動の判定・移動を頼む記録を持たず、 行が並べた口座と区画の席の row の口座をどの選定からも除かない。 席の口座は引数か、 行が並べた口座だけを候補にした session 用の選定で決め、 管理 tick の周に park の移り先の判定 (row の口座の記録の最新値が session 用の閾値の rules 行のいずれか以上の周だけ口座を返す・計測を起こさない・lock を取らない) が口座を返した周だけ移る。 行が並べた口座の宣言を A1 の常設の承認と読み (ADR-0049 の群の宣言と同じ形)、 移り先は席の起動と同じ session 用の選定で決まるので、 起動と同じく移る周に承認 event を書かない。 hook は告げるが移動を頼む記録を置かず、 doctor の行は kind=park を持つ。 決め手は分析 (群の仕組みに触れず、 区画を名 1 語で読める)。

群を宣言する表の Tier9 の行を、 群ではない park の区画にする案です。 区画は、 いま使う口座の記録も、 次に移る口座の予約も持ちません。 行に並べた口座も区画の席の口座も、 群の移り先・便・他の席の選び方から外れないので、 口座を占めません。 区画の席は、 口座を名指されればその口座に、 名指されなければ行に並べた口座から選んだ余裕のある口座に居ます。 見回りの周に、 いまの口座の使った割合の記録が選び方と同じ線以上のときだけ別の口座を選んで移り、 そのとき新しく測ったり host の鍵を取ったりしません。 行に並べた口座の宣言は前もっての承認と読み、 移り先は席の起動と同じ選び方で決まるので、 起動と同じく移るたびの承認の記録は書きません。 代わりに、 群は 8 本までになり、 記録が古いと移らず、 告げる線と移る線が違うので告げられても移らない周があり、 区画の席が他の席と同じ口座に並びえます。 doctor の行が 1 種増えるので外の読み手に知らせる要があり、 移った事実は承認の記録でなく、 見回りの判定の行 (次の周で上書きされる) と、 起こし直しが残す席の登録の記録から読むことになります。 分析で選びました。

+ 利点

  • 区画は口座の記録も予約も持たず、 どの選定も区画の口座を使えるので、 口座を占めない (DR1)
  • 区画の手は lock を取らず計測を起こさないので、 群の移動と便を待たせない (DR2)
  • 種類は名 1 語で決まり、 区画を表すのに新しい表・key・rules 行・記録を足さず、 選定は既存の session 用の 1 本を呼ぶだけ (DR3)
  • 移る線と選ぶ線が同じ session 用の閾値の rules 行なので、 選定の規則の線で口座を替え、 移った先ですぐ移り直さない (DR4)
  • 候補を行が並べた口座に絞り、 宣言の外の口座へは引数でしか行かない (DR5)

− 欠点

  • 群は Tier1〜Tier8 の 8 本までになり、 Tier10 以上は宣言できない
  • 移るかは計測の記録だけで決まるので、 記録が無いか古い周は移らない
  • 告げる線 (群の逼迫の閾値) と移る線 (session 用の閾値) が別で、 告げられても移らない周がある
  • 区画の席の row の口座を他の席も選べるので、 区画の席と他の席が同じ口座に並びうる
  • doctor に kind=park の行が加わり、 doctor の出力を読む外の読み手 (別 project の画面) へ変化を知らせる要がある
  • 区画の移動は承認 event を書かないので、 移った事実は群の移動の承認 event の列からは追えず、 管理 tick の判定行 (次の周で上書きされる) と、 起こし直し (FR59) が event log に記帳する席の登録から読む
OPT2群の行に種類の key を足し、 どの番号の行でも区画にできる不採用

群の行に明示の key (kind = park など) を足し、 どの Tier の番号の行でも park の区画にできる形。 決め手は分析 (番号と種類の 2 軸になる)。

群の行に「この行は区画」という種類の欄を足し、 どの番号の行でも区画にできる案です。 名が優先の順だけを表し、 群の数に上限を置かない点で勝ります。 けれども、 番号と種類の 2 つの軸になり、 宣言の順が優先という決まりが区画の行に何を意味するかを別に決める要が出ます。 行の形に欄が 1 つ増え、 読み手は名と欄の 2 つを見て種類を知ることになります。 持ち主の呼び名は Tier9 で、 名で決めれば 1 語で足ります。 退けました。

+ 利点

  • 名は優先の順だけを表し、 区画の数と位置に名の制限が無い
  • 群の名に上限を置かず、 Tier10 以上の群も宣言できる

− 欠点

  • 番号と種類の 2 軸になり、 宣言順が優先という規則が区画の行に何を意味するかを別に決める要が出る (DR3)
  • 行の形に key が 1 つ増え、 読み手 (doctor・別 project の画面) は名と key の 2 つを見て種類を知る (DR3)
  • 持ち主の呼び名は Tier9 で、 名で決めれば 1 語で足りる
OPT3区画を宣言せず、 群の外の席として置く不採用

区画の仕組みを作らず、 休ませる置き場を群の外に置いたままにする。 決め手は分析 (群の外の席も口座を占める)。

区画の仕組みを作らず、 休ませたい置き場を群の外に置いたままにする案です。 器を変えず、 群の仕組みにも触れない点で勝ります。 けれども、 群の外の席の口座は他の席の選び方から外れるので、 やはり口座を占めます。 口座の残りが尽きかけても移らず、 口座の替えは人の手に残ります。 候補を行に並べた口座に絞ることも表せません。 置き場が表に無いので、 非公開の隣の repo の数えに群の表の置き場として入らず、 表のどの行にも無い置き場として doctor に数えられます。 退けました。

+ 利点

  • 器を変えず、 今の読み手のまま動く
  • 群の仕組みに一切触れない

− 欠点

  • 群の外の席の row の口座は他の席の session 用の選定から外れる (FR36) ので、 口座を占める (DR1)
  • 群の外の席は口座が逼迫しても移らず、 口座の替えが人の手に残る
  • 候補を行が並べた口座に絞る制限を表せない (DR5)
  • 置き場が群の表に無いので、 隣の private repo の数え (FR80) と群の外の anchor の数え (FR73) で群の表の置き場として扱えない
OPT4区画の移る線を群の逼迫の閾値にする不採用

OPT1 と同じ区画を作り、 移る条件の線だけを群の逼迫の閾値の rules 行 3 本 (5 時間窓・7 日窓・モデル別窓) にする。 決め手は分析 (選定の規則と別の線で口座を替え、 移り先を選ぶ線と食い違えば往復する)。

選んだ案と同じ区画を作り、 移る条件の線だけを群の逼迫の線 (5 時間・7 日・model 別の 3 本) にする案です。 告げる線と移る線が揃い、 告げられた席が移る点で勝ります。 けれども、 口座の選び方の決まり (R-C9-1) と別の線で口座を替えることになります。 移り先も群の逼迫の線で選べば往復は起きませんが、 その形でも別の線で替えることは変わりません。 移り先をいまの選び方で選ぶ形では、 群の逼迫の 5 時間の線 (いまの値 85) が選び方の線 (いまの値 95) より低いので、 選ばれた移り先もその線以上でありえ、 移った先ですぐ移り直す往復が起きえます。 退けました。

+ 利点

  • hook が告げる線と移る線が揃い、 告げられた席が移る
  • 群と区画で逼迫の読みが 1 つになる

− 欠点

  • 選定の規則 (R-C9-1) と別の線で口座を替えることになる (DR4・C9.2)。 移り先も群の逼迫の閾値で選ぶ形にすれば往復は起きないが、 その形も R-C9-1 と別の線で口座を替える
  • 移り先を session 用の選定で選ぶ形では、 群の逼迫の閾値の 5 時間窓の行 (今の値 85) が session 用の閾値 (今の値 95) より低いので、 選ばれた移り先もその線以上でありえ、 移った先ですぐ移り直す往復が起きうる (DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 群を宣言する表の行の名を Tier1〜Tier9 に限り、 Tier9 の行を区画とします。 区画は口座の記録も予約も持たず、 行に並べた口座と区画の席の口座はどの選び方からも外れません。 席は行に並べた口座から選んだ口座に居て、 見回りの周に、 記録の上で線以上になった周だけ移ります。 支えるのは FR95 (区画) と、 FR38・FR36・FR27・FR59・FR73・FR80・FR44・FR57 の区画に掛かる句で、 どれもこの判断が中身を決める側 (主張) です。

群を宣言する表の行の名は Tier1〜Tier9 に限り、 Tier1〜Tier8 の行を群、 Tier9 の行を park の区画とします。 それ以外の名・同じ数字の重複・数字の小さい順でない並びの表は、 読む時点で断ります。 優先は宣言の順のままです。 区画は、 群がいま使う口座の記録・その種・予約・群の移動の判定・移動を頼む記録を持ちません。 区画の行に並べた口座と区画の席の口座は、 便と席の口座の選び方・群の移り先・群の予約のどれからも外れません。 行に並べた口座の宣言は、 その口座を使うことの前もっての承認と読みます。 区画の席を起こす口座は、 名指しがあればその口座 (行に無くても)、 無ければ行に並べた口座だけから選んだ口座で、 候補が無ければ決まった語で断ります。 見回りの周には区画の移り先の判定を撃ちます。 判定は、 いまの口座の使った割合の最新の記録が選び方の線のどれか 1 つ以上のときだけ、 行に並べた他の口座から選んだ口座を返し、 記録が無い・古い・候補が無いときは返しません。 返したときだけ、 席は群の移動と同じ退避の合図と、 画面が shell に戻った周の起こし直し (直前の会話の続きから再開する。 会話の記録そのものは写さない) で移ります。 いまの口座が同じ間は、 移り先が周ごとに変わっても、 退避の合図を画面が shell に戻るまで重ねて送りません。 候補が無ければ理由の語を出します。 画面が shell に戻った席は、 判定が返せばその口座、 返さなければ席の記録にある口座で起こし直し、 起こし直しは同じ判定の結果を使います。 区画の手は新しく測らず、 host の鍵を取らず、 群の記録と承認の記録を書きません (移り先は席の起動と同じ選び方で決まり、 起動も承認の記録を書かないため)。 移った事実は見回りの判定の行 (次の周で上書きされる) と、 起こし直しが残す席の登録の記録に残ります。 区画の席の hook は、 群の逼迫の線のどれか 1 つ以上になった周に 1 行で告げますが、 移動を頼む記録は置きません。 doctor の区画の行は kind=park を持ち、 今の口座・次の口座・断りの欄は - 05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 3 つと、 代わりに引き受けること 5 つです。 良くなるのは、 区画が口座を占めないこと、 群の移動と便を待たせず区画の席が線に達した周に人の手を待たずに移ること、 種類が名 1 語で読めて Tier9 の行が群と読まれて口座を占める誤りが起きないことです。 引き受けるのは、 群が 8 本までになること、 移るかが記録だけで決まり告げられても移らない周があること、 doctor の行が 1 種増えて外の読み手に知らせること、 区画の席と他の席が同じ口座に並びうること、 区画の移動は承認の記録を残さず、 移った事実を見回りの判定の行 (次の周で上書きされる) と、 起こし直しが記録する席の登録から読むことです。

✓ 良い結果

  • ●区画の置き場は口座を占めず、 行が並べた口座は群の移り先と予約と、 便と他の席の選定にそのまま使われる
  • ●区画の手は lock を取らず計測を起こさないので、 群の移動と便を待たせず、 区画の席は row の口座の使用率が session 用の閾値に達した周に人の手を待たず移る
  • ●種類は名 1 語で読め (doctor の kind=park)、 区画を表すのに新しい表・key・rules 行・記録を足さない。 Tier9 を宣言しても群として口座を占める誤りが、 読みの形で起きない

⚖ トレードオフ・代償

  • ●群は Tier1〜Tier8 の 8 本までになり、 Tier10 以上の群は宣言できない (既存の群の名 Tier1 / Tier2 は合う)
  • ●区画の席の移動は計測の記録だけに依るので、 記録が無いか古い周は移らない (計測を起こさない代償)。 告げる線 (群の逼迫の閾値) と移る線 (session 用の閾値) が別で、 告げられても移らない周がある
  • ●doctor に kind=park の行が加わる (群の行の欄の形は変えない)。 doctor の出力を読む外の読み手 (別 project の画面) は kind の有無で種類を分ける要があり、 変化を知らせる
  • ●区画の席の row の口座を他の席も選べるので、 区画の席と群の席や便が同じ口座に並び、 その口座が早く逼迫しうる
