本 dir (design-intent/decisions/) はこの project の Architecture Decision Records (ADR) を保持する cluster です。 各 ADR は ADR-NNNN-<slug>.html の命名で配置します。

§1. Purpose

設計判断の理由 (WHY) を 1 決定 = 1 file で残す場所です。 決定時点の記録なので、 今の仕様は spec/ を見ます。

decisions/ は architectural decision の WHY を記録します。 spec (WHAT) の背景にある意思決定とその根拠を trace します。 主な人間読者は設計の経緯を時系列で辿る維持者です — ADR は決定時点の記録 (frozen) であり、 現在の WHAT は spec/ を参照してください。

§2. ADRs

ADR は 15 本です。 1 本目は実装言語と構成を Rust の単一 static binary に決めた記録、 2 本目は test / lint の toolchain を決めた記録、 3 本目は v1 の完全放棄に伴って憲法の 4 か所 (対話面・拘束条件・自己開発の既定・改訂の手続き) を書き換えた記録、 4 本目は MVP の状態の置き場と前の版と共有する接点の file の形 (追記だけの JSONL・環境変数を使わない・TOML subset) を決めた記録、 5 本目は 3 本目で決めた「承認を受け取る窓口は 1 つ」を、 適用し漏れていた A3 (依存 OSS の追加・削除) へ揃えた記録、 6 本目は構造検査が測る項目の一覧を、 実際に動いているもの (11 本) に合わせて差し替えた記録、 7 本目は「統合 test の file は 3 つまで」という決まりの数え方を、 cargo がテスト用に build するかたまり (integration test target) の数で数えると決めた記録、 8 本目は自分の repo への branch push と PR 作成は「出す」に当たらない (取り消せる) と決めた記録、 9 本目は実装役 (runner) に何を実行してよいかと「test が本当に測っているか」の検証を、 人の口座設定や repo の外の script でなく器が manifest から与えると決めた記録、 10 本目は「実装役が使ってよい command」と「どの便にも共通の検証」の値を器の規則 file でなく相手の repo の宣言 file (目印の隣) に置き、 器の規則 file は宣言が名乗ってよい上限だけを持つと決めた記録、 11 本目は器が起こす claude (実装役と審査役) が起動した人の設定 file も相手の repo の設定 file も 1 つも読まないと決めた記録、 12 本目は口座の使用上限の検出を claude が出す専用の record の構造化 field だけで行うと決めた記録、 13 本目は一覧の正本を動いているコードとその出力に置き文書は pointer だけを持つと決めた記録、 14 本目は「止める仕組み」の性質 (その場で止めるか・迷ったら止めるか) を型で持ち、 その一覧を器の出力の固定 file として残し、 「その場で止める仕組みが無い」状態を構造検査が拒むと決めた記録、 15 本目は席が手を止めているかを画面の見た目でなく席自身が押す判子 (hook の打刻) で決め、 判子の無い席には何も送らないと決めた記録です。
