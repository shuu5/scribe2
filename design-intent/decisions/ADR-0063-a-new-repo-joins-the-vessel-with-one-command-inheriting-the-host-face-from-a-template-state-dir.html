設計判断記録 (ADR) scribe2 — 導入の口を 1 つに

新しい repo を器に載せる口は 1 発で、 host の面は git の global 設定が指す既存の置き場 (雛形) から継承する — 人が打つのは host init・init・doctor の 3 語、 席は引数なしで立つ (ADR-0026 の「役割は必須」の 1 文を部分 supersede・ADR-0049 が後続に送った導入の口)

今は新しい repo を器に載せるのに、 人が 7 手 (置き場の dir・口座の配線・host の面の写し・git の設定・marker・宣言・tmux と席の長い起動) を打ち、 1 つ抜けると席は黙って動かない。 user は、 導入は 1 コマンドで終わること、 人が打つ command を最小にすること、 人間向けの説明を持つことを裁定した (裁定 id user 2026-09-24T13:02Z / 13:04Z)。 本 ADR は、 人が打つのを host に 1 回の host init・repo ごとに 1 回の init・困ったときの doctor の 3 語に閉じ、 host の面は git の global 設定の pointer 1 つが指す既存の置き場 (雛形) から写し、 席は引数の無い seat launch で立て、 doctor が欠落と次の 1 手を名指すと決める。 ADR-0026 の「役割は必須」の 1 文を、 引数の無い形に限って置き換える。 口座が repo を信じた印 (trust) を器が埋めるかは別の裁定で決め、 後続の ADR に送る。

この判断が約束すること (1 文サマリ)

この記録で「置き場 (state dir)」は器 (scribe2) が 1 つの repo のための状態と設定を置く dir、 「host の面」は置き場ごとの設定 file (どの口座・どの plugin・どの起動引数を使うか) のことです。 今は新しい repo を器に載せるのに、 人が 7 つの手作業 (置き場の dir を作る・口座をつなぐ・設定 file を別の置き場から写す・git の設定・目印の file・repo の名乗りの file・tmux と席の長い起動) を打ち、 1 つ抜けると席は黙って動きません。 user は 2026-09-24 に、 導入は 1 コマンドで終わること、 人が打つ command を最小にすること、 人間向けの説明を持つことを決めました。 この記録は、 人が打つのを 3 つ (host に 1 回の host init・repo ごとに 1 回の init・困ったときの doctor) に閉じると決めます。 host init は、 すでに動いている置き場 1 つを「雛形」として git の全体の設定に登録します。 init は、 雛形の隣に新しい置き場を作って設定を写し、 口座をつなぎ、 目印と名乗りの file を書いて 1 commit にし、 tmux の画面を用意して席を立てるところまでを、 順に 1 段ずつ行います。 席は引数なしで立ち、 doctor は抜けているものと次にやる 1 手を言います。 前の決定 (ADR-0026) の「役割は必ず指定する」の 1 文を、 引数の無い形に限って置き換えます。 口座がその repo を一度も「信じる」と答えていないと席の起動が確認の画面で止まる件は、 別の決定で決めるので、 この記録では扱いません。 この記録は、 受け入れられるまで何も拘束しない発効前 (proposed) の記録です。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 user の決定と、 実際に起きたことと、 器の今の部品と、 これまでの決まりから説明します。 user は 2026-09-24 に、 新しい project の導入は 1 コマンドで終わるべきこと、 人が打つ command を最小にしてそれで器が十分に動くこと、 人間向けの説明が要ることを決めました。 同じ日の新しい project の立ち上げは 7 つの手作業で、 そのうち目印の file と repo の名乗りの file が抜け、 席は指示文を受け取れずに保留で止まりました。 別の 2 つの project の移行も、 repo の外に書いた 15 段の手順を人が辿りました。 点検の doctor はこの抜けを言いません。 器には目印を書く口・設定 file の読み手・口座を足す口・席を立てる口がすでに在りますが、 それらをつなぐ口と、 引数を省いたときの既定がありません。 決まりの側では、 host ごとの値で分岐する code を書かないこと、 環境変数の差し込み口を新しく作らないこと、 口座を使う判断は人に聞くこと、 口座の鍵を読まないことが効いています。 口座がその repo を信じていないと席の起動が止まる件は、 別の決定に送ります。

CTX1

経緯 — 導入は 1 コマンドで、 人が打つ command は最小限、 という裁定

2026-09-24 に user は 3 つを裁定した。 1 つ目 (裁定 iduser の決定の印 user 2026-09-24T13:02Z) は、 新しい project を器に載せるのは 1 コマンドで終わる簡便さが要る、 である。 2 つ目と 3 つ目 (裁定 id user 2026-09-24T13:04Z) は、 器には制御の道具が多いのに人間向けの説明が無く初見の人が知りようがないこと、 人が打つ command を最小にしてそれで器が十全に動くようにすること、 である。 要旨だけを写し、 逐語は非公開の作業記録簿 (台帳 s2-07l.609) に在る。 ADR-0049 は群の決定の射程外として「導入の口」と「外部 API の鍵の欄」を後続の決定記録に送っている。 本 ADR はそのうち導入の口を決め、 鍵の欄は決めない。

CTX2

実測 — 手作業 7 手のうち 2 つが抜け、 席は黙って止まった

2026-09-24 の新しい project の立ち上げは手作業 7 手 (置き場の dir を作る・口座の dir を symlink で結ぶ・host の面を別の置き場から写す・起動行の雛形・git の local 設定・tmux の session と窓・seat launch の長い引数) で、 marker を書く vessel initrepo を載せる口 と vessel 宣言repo の名乗りが抜けた。 抜けた状態では SessionStart の hook が「仕えない repo」として 0 byte で黙り、 席に指示文が入らず、 seat launch は launch-unconfirmed の保留になった (memo s2-07l.604 の実地試験でも同じ)。 別の 2 つの project の移行も、 repo の外の散文の手順 (15 段) を人が辿った (memo s2-07l.491 の notes)。 doctor点検の 1 コマンド はこれらの欠落を名指さない。

CTX3

現物 — 部品は揃っているが、 つなぐ口と既定が無い

base 0b6af26 で、 vessel init は git の local 設定 (NAME から導いた key に置き場の path) と marker (.vessel・name と version の 2 行) を書き、 別の名乗りの marker が在る周は 1 byte も書かず断る。 env も HOME も読まない。 host の面 (state dir器の状態の置き場 の host.toml) は口座・plugin・起動引数・vessel・群の 5 表を受け、 面が無い周は 0 宣言で止めない。 口座の dir は account add が実 dir として作り、 host では複数の置き場が同じ口座を使うので、 置き場の口座の dir は既存の設定 dir への symlink になっている (host の運用で、 器は知らない)。 seat launch は置き場・役割・target を必須に受け、 tmux の session は在る前提で、 無ければ断る (窓は無ければ作る)。 doctor は席の登録・口座・導入先・配線の行を出すが、 marker・宣言・host の面の欠落を名指す行は無い。 vessel 宣言の必須の key は 3 つ (schema・許す command・共通の検証) で、 cargo の行を持つ宣言は入口の flip の行か「測らない」の名乗りを要る。 子 process は core が起動の記述何を起こすかの記述で記述し、 境界 crateprocess を起こす箱 が撃つ (ADR-0062)。

CTX4

後続 — 口座の trust は別の裁定で決める

口座がその repo を一度も信じていない (trust していない) と席の起動席を立てる口が Claude Code の確認で止まる穴は、 別の裁定で決めて後続の ADR に送り、 本 ADR は決めない。

CTX5

憲法と既存の決定の向き (本 ADR の解釈)

N3 は host 固有の値で分岐する code を拒み、 C10 は host ごとの値を manifest (host の面) に置き、 C2.2 と ADR-0004 §2.4 は env の差し込み口を新設しない (置き場の差し替えは CLI 引数だけ)。 xtask の env-reads の門は src の env の読みを数える。 A1 は消す・出す・使うの 3 クラスを実行前に user に聞き、 ADR-0049 は群の宣言を A1 の「使う」の常設の承認とする。 FR58 は口座の登録口座を足す口で credential を読まず書かないことを、 FR59 は席の起動が役割を必須で受け tmux の session は作らないことを、 FR61 は doctor が導入先ごとに実測を typed な語で名指し推測で埋めないことを求める。 ADR-0026 は host の面を置き場ごとの 1 file とし、 seat launch の役割を必須とした。 ADR-0045 は席の役割を orchestrator 1 つにした。 ADR-0010 / ADR-0047 は vessel 宣言の形を決めた。 C17 は足す前に要るか・既に在るかを順に問う。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 人が打つ command を最小にすること、 置き場の在り処を host ごとの値で分岐せず環境変数も固定の場所も使わずに知ること、 今の設定 file・名乗りの file・席を立てる口の形を変えないこと、 口座の鍵 (credential) を読まず、 口座を使う判断を人に残すこと、 黙って止まる席を作らず抜けを名指すこと、 そして新しい口は今の口を順に呼ぶだけにして外部の部品を足さないことです。

DR1人が打つ command を最小にする — host に 1 回・repo ごとに 1 回・困ったら 1 回、 残りは器が導く CTX1 (裁定)・CTX2 (7 手と抜け)
DR2置き場の在り処を host 固有の値で分岐せずに知る — env を読まず、 固定の path も焼かない CTX5 (N3・C2.2・ADR-0004 §2.4・env-reads の門)
DR3既存の外形を変えない — host の面は置き場ごと、 宣言・marker・seat launch の長い形・既存の置き場と repo は無変更 CTX3・CTX5 (ADR-0026・ADR-0049・ADR-0010 / ADR-0047)
DR4credential と A1 の境を越えない — credential を読まず写さず、 口座を使う判断 (群) は人が持つ CTX5 (FR58・A1・ADR-0049)
DR5黙って止まる席を作らない — 欠落は doctor が次の 1 手で名指す CTX2・CTX5 (FR61)
DR6足すものを最小にする — 新しい口は既存の口を順に呼ぶだけにし、 依存を足さない CTX3・CTX5 (C17)
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。 git の全体の設定の印 1 つと段の列で導入する案 (選んだ案)、 環境変数か固定の場所で置き場を知る案、 雛形を host 全体の置き場に置く案、 口座の dir を丸ごと写す案、 init が質問して 1 つずつ決める案、 init が口座のかたまり (群) へ自動で入れる案です。 却下した 5 案にも利点を並べ、 退けた決め手が現物か分析かを各案に書きます。 環境変数の案は host init が要らず人の手が 2 語で済む点で、 host 全体に置く案は雛形が 1 か所で写しが増えない点で、 写す案は置き場ごとに独立する点で、 質問する案は選択肢を見ながら決められる点で、 自動で群へ入れる案は人が引数を打たずに済む点で、 選んだ案に勝ちます。

OPT1host に 1 回の pointer と repo ごとに 1 回の段の列 — 雛形の置き場写しの元の置き場から写し、 席は引数なしで立つ採用

host init が git の global 設定に雛形の置き場の絶対 path を 1 つ書き、 init が段の順 (置き場・host の面・口座・marker と local 設定・宣言・群・commit・tmux と席) を冪等に通して段ごとに 1 行と次の 1 手を出す。 seat launch は引数なしで既定を解き、 doctor は host-template雛形を指す印 と init の 2 行で欠落を名指す。 依存は足さない。 決め手は分析 (裁定の 3 点を、 既存の口と外形を変えずに満たす形のうち、 人の手が最小で env を読まない形)。

host に 1 回だけ、 すでに動いている置き場の場所を git の全体の設定に書き (host init)、 repo ごとに 1 回、 その雛形から新しい置き場を作って段を順に通す (init) 案です。 段は、 置き場・設定 file の写し・口座のつなぎ・目印と git の設定・名乗りの file・(指定したときだけ) 群・commit・tmux と席で、 すでに在る段は飛ばし、 段ごとに 1 行と次の 1 手を出します。 席は引数なしで立ち、 doctor が抜けを名指します。 人が打つのは 3 語になり、 環境変数も固定の場所も読まず、 今の設定 file や席を立てる口の形も変えず、 口座の鍵も読まず、 外部の部品も足しません。 代わりに、 引数の無い起動は今いる repo に頼り、 置き場の名付けを器に焼き、 仕事が 4 つの契約に割れ、 口座が repo を信じていないと席が確認で止まる穴は残ります。 決め手は分析で、 user の決定の 3 点を、 今の口と形を変えずに満たす形のうち、 人の手が最小で環境変数を読まない形でした。

+ 利点

  • 人が打つのは host init (host に 1 回)・init (repo ごとに 1 回)・doctor (困ったら) の 3 語で、 7 手の手作業と repo の外の散文の手順が消える (DR1)
  • 置き場の在り処は git の global 設定の pointer 1 つで知り、 名は雛形から導くので、 env も固定の path も読まない (DR2)
  • host の面の loader・vessel init・宣言の形・seat launch の長い形を再利用し、 外形を変えない。 既存の置き場と repo は 1 字も変わらない (DR3)
  • 口座は symlink で結ぶだけで credential を読まず写さず、 群へ入れるのは --group を打つ人だけ (DR4)
  • 各段が冪等で、 途中で失敗しても段を名指して続け、 next= が次の 1 手を言う。 doctor が欠落を宣言順に名指す (DR5)
  • 既存の口を順に呼ぶだけで、 依存を足さない (DR6)

− 欠点

  • 引数の無い seat launch は cwd の repo の設定に頼り、 ADR-0026 の「役割は必須」の文を置き換える
  • 置き場の名付け (雛形の dir 名 - repo の dir 名) を器の関数に焼き、 別の名付けを持たない
  • init は段が多い 1 つの口で、 契約は 4 行 (host init・init・席・doctor) に割れる
  • 口座が repo を信じていない周の trust の確認で席が止まる穴は残り、 後続の ADR に送る
OPT2env か固定の path (XDG の置き場) で雛形の置き場を知る不採用

SCRIBE2_HOME のような env か、 XDG の規約の固定の dir を雛形の置き場として読む。 決め手は分析 (env-reads の門と N3・C2.2 に反する)。

環境変数 (例: SCRIBE2_HOME) か、 決まった場所 (XDG の規約の dir) を雛形の置き場として読む案です。 git の設定を書かずに済むので host init が要らず、 人が打つのは init と doctor の 2 語になります。 他の道具でも広く使われる形で、 初見の人に説明しやすい点も勝ります。 けれども、 環境変数を読むのは器の検査 (env-reads) と、 環境変数の差し込み口を新しく作らないという決まりに反します。 決まった場所は、 host ごとに置き場の親が違う運用を code に焼くことになり、 host ごとの値で分岐しないという決まりに反します。 決め手は分析です。

+ 利点

  • git の設定を 1 つも書かずに済み、 host init が要らない (人が打つのは init と doctor の 2 語)
  • 他の道具でも広く使われる形で、 初見の人に説明しやすい

− 欠点

  • env を読むと xtask の env-reads の門と C2.2 (env の差し込み口を新設しない) に反する (DR2)
  • 固定の path は host ごとの置き場の運用 (置き場の親が host で違う) を code に焼き、 N3 に反する (DR2)
OPT3雛形を host の根の host.toml に置く不採用

置き場の親の下の host 用 dir (host の根) に共通の host.toml を置き、 各置き場はそれを継承する。 決め手は分析 (host の面を置き場ごと 1 file とした ADR-0026 / ADR-0049 の外形を変える)。

置き場の親の下にある host 全体の置き場 (host の根) に共通の設定 file を置き、 各置き場がそれを受け継ぐ案です。 雛形が host に 1 か所で、 そこを直せば全部の置き場に効き、 写しが増えません。 host の根は置き場から環境変数なしで導けます。 けれども、 設定 file は置き場ごとに 1 つという前の決定 (ADR-0026) と、 群の宣言をその file の表にした決定 (ADR-0049) の形が変わり、 読み手の全部に受け継ぎの規則が要ります。 host の根は状態の記録の置き場で、 宣言を置くと、 宣言と実際の値を別の file に分ける決まりも崩れます。 決め手は分析です。

+ 利点

  • 雛形が host に 1 か所で、 写しが増えない (host の面を直せば全置き場に効く)
  • host の根は既に受付札と群の今の口座の記録を持ち、 置き場から env なしで導ける

− 欠点

  • host の面を置き場ごとの 1 file とした ADR-0026 と、 群の宣言をその面の表とした ADR-0049 の外形が変わり、 loader と全読み手に継承の規則が要る (DR3)
  • host の根は状態の記録の置き場で、 宣言を置くと宣言と実効を file で分ける形 (C10) が崩れる
OPT4口座の credential の dir を新しい置き場へ copy する不採用

雛形の口座の dir を symlink でなく丸ごと写す。 決め手は分析 (FR58 の柵の外で、 可逆でない)。

雛形の口座の dir を、 symlink でつながずに丸ごと新しい置き場へ写す案です。 置き場ごとに口座の dir が独立するので、 雛形の置き場を消しても新しい置き場が動きます。 けれども、 口座の鍵 (credential) を読んで写すことになり、 鍵を読まず書かないという要件 (FR58) の外に出ます。 login を更新しても写しには届かず、 同じ口座の dir が host の中に複数に割れ、 消すのも戻すのも手作業になります。 決め手は分析です。

+ 利点

  • 置き場ごとに口座の dir が独立し、 雛形の置き場を消しても新しい置き場が動く

− 欠点

  • credential を読んで写すことになり、 FR58 (credential は読まず書かない) の外に出る (DR4)
  • login の更新が写しに届かず、 同じ口座の dir が host に複数に割れる。 消すのも戻すのも手作業になる
OPT5init が対話で聞く不採用

置き場の名・写す口座・群・宣言の形を init が端末で 1 つずつ聞く。 決め手は分析 (席からは撃てず、 1 発にならない)。

init が置き場の名前・写す口座・群・名乗りの file の形を、 端末で 1 つずつ質問して決める案です。 初見の人が選択肢を見ながら決められ、 器が既定を推測しなくて済みます。 けれども、 席 (AI の session) は質問に答えられないので、 撃てるのが人の端末だけになります。 人が打つ回数も質問の数だけ増え、 「1 コマンドで終わる」「人が打つ command を最小に」という user の決定に反します。 決め手は分析です。

+ 利点

  • 初見の人が選択肢を見ながら決められる
  • 既定を器が推さずに済む

− 欠点

  • 席 (AI の session) からは対話の入力に答えられず、 撃てる口が人の端末だけになる
  • 人が打つ回数が問いの数だけ増え、 裁定の「1 コマンドで終わる」と「人が打つ command を最小に」に反する (DR1)
OPT6init が群へ自動で入れる不採用

雛形の置き場が属する群へ、 新しい repo を init が黙って足す。 決め手は分析 (A1 の「使う」を器が決める形になる)。

雛形の置き場が入っている群 (口座を共にする project のかたまり) へ、 新しい repo を init が黙って足す案です。 人が --group を打たずに済み、 群の口座で席が立ちます。 けれども、 どの口座を使うかは人に聞く決まり (A1 の「使う」) で、 群の宣言がその承認にあたるので、 器が勝手に承認の範囲を広げることになります。 雛形が複数の群に入っているときに、 どこへ入れるかを器が推測することにもなります。 決め手は分析です。

+ 利点

  • 人は --group を打たずに済み、 群の口座で席が立つ

− 欠点

  • 口座を使う判断 (A1 の「使う」・ADR-0049 では群の宣言がその常設の承認) を器が勝手に広げる (DR4)
  • 雛形が複数の群に属する周に、 どの群へ入れるかを器が推すことになる
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 host init は、 すでに在る置き場 1 つの場所を git の全体の設定に書くだけです。 init は、 置き場を作る・設定 file を写す・口座をつなぐ・目印と git の設定を書く・名乗りの file を書く・(指定したときだけ) 群に足す・書いた file だけを 1 commit にする・tmux の画面を用意して席を立てる、 の段を決まった順に通り、 すでに在る段は飛ばし、 段ごとに 1 行と最後に次の 1 手を出します。 席を立てる口は、 引数が無ければ置き場と役割と画面の場所と口座を自分で解き、 引数があればそちらを使います。 doctor は雛形の印の行と導入の行で、 抜けを決まった順に並べて次の 1 手を 1 つ言います。 要件書では、 席の起動の要件 (FR59) を満たす形を示し、 口座の鍵を読まない要件 (FR58) を口座のつなぎの段へ、 点検が実測を名指して推測で埋めない要件 (FR61) を doctor の新しい行へ広げる根拠になります。

採用 — OPT1

器 SHALL 新しい repo を載せる人の手を host init (host に 1 回)・init (repo ごとに 1 回)・doctor (困ったとき) の 3 語に閉じる。 host init SHALL 既存の state dir 1 つを雛形の置き場として受け、 git の global 設定 host-template (key は NAME から導く) に絶対 path を書き (同じ値なら書かない)、 dir が無い・host の manifest が読めない周は 1 byte も書かず断る。 器 SHALL 雛形の置き場をこの pointer 1 つだけで知り、 env と HOME を読まない。 init SHALL 段の順を置き場・host の面・口座・marker と local 設定・vessel 宣言・群・commit・tmux と席に固定し、 各段は在れば skip し、 段ごとに 1 行と最後に次の 1 手 (next=) を 1 つ出し、 段の失敗はその段だけ書かずに名指して続きへ進む。 git の repo でない・host-template が無い周は 1 段目の前に断る。 置き場 SHALL 雛形の親の下の「雛形の dir 名 - repo の dir 名」とする。 host の面 SHALL 雛形の口座・plugin・起動引数・vessel の 4 表を写し、 群の表は写さず、 既存の loader で検査してから rename で置く。 口座の dir SHALL 雛形の口座の dir (link ならその先) への symlink とし、 credential SHALL 読まず写さない。 vessel 宣言 SHALL Cargo.toml の有無で cargo の形か git の形を選び、 値は上限の内側に置く。 群 SHALL --group を打った周だけ足し、 群を宣言する同じ親の下の全面の anchors に repo を足し、 1 面でも検査に落ちれば 1 面も書かない。 commit SHALL init が書いた marker と宣言だけを 1 commit にする。 init SHALL tmux の session が無ければ作り、 引数の無い seat launch を 1 回撃つ。 引数の無い seat launch SHALL 置き場を cwd の repo の local 設定から、 役割を orchestrator、 target を repo の dir 名の session の orchestrator の窓、 口座を群の今の口座か session 用の選定から解き、 明示の引数は既定に勝ち、 長い形の判定と断りを変えない。 doctor SHALL host-template の行と init の行 (欠落を宣言順に並べ次の 1 手を 1 つ) を出し、 SessionStart の hook の 0 byte は変えない。 子 process SHALL 全部を起動の記述 (ADR-0062) で記述する。 器 SHALL NOT 群へ自動で入れず、 対話で聞かず、 本 ADR で依存を足さない。 口座の trust を器が埋めるか SHALL 本 ADR で決めない (後続の ADR)。

器は、 新しい repo を載せるために人が打つのを、 host init (host に 1 回)・init (repo ごとに 1 回)・doctor (困ったとき) の 3 つに閉じます。 host init は、 すでに在る置き場 1 つを雛形として受け、 その場所を git の全体の設定の 1 項目 (host-template) に書きます。 同じ値ならもう書かず、 dir が無いか設定 file が読めないときは何も書かずに断ります。 器は雛形の置き場をこの 1 項目だけで知り、 環境変数も HOME も読みません。 init は、 置き場・設定 file・口座・目印と git の設定・名乗りの file・群・commit・tmux と席の順に段を通り、 すでに在る段は飛ばし、 段ごとに 1 行と最後に次の 1 手を出し、 失敗した段はそこだけ書かずに名指して先へ進みます。 git の repo でないか雛形の登録が無いときは、 最初の段の前に断ります。 新しい置き場は雛形の隣に「雛形の名前 - repo の名前」で作ります。 設定 file は雛形の口座・plugin・起動引数・vessel の 4 つの表を写し、 群の表は写さず、 今の読み手で確かめてから置きます。 口座の dir は雛形の口座の dir への symlink にし、 口座の鍵は読まず写しません。 名乗りの file は Cargo.toml の有無で Rust の形か git だけの形を選び、 値は器の上限の内側に置きます。 群は --group を打ったときだけ足し、 同じ親の下でその群を宣言している全部の設定 file に repo を足し、 1 つでも確かめに落ちれば 1 つも書きません。 commit は init が書いた目印と名乗りの file だけを 1 つにまとめます。 最後に tmux の画面が無ければ作り、 引数の無い席の起動を 1 回撃ちます。 引数の無い席の起動は、 置き場を今いる repo の git の設定から、 役割を orchestrator、 画面の場所を repo の名前から、 口座を群の今の口座か席用の選び方から解き、 引数があればそちらを使い、 引数を全部書いた形の判定と断り方は変えません。 doctor は雛形の登録の行と導入の行 (抜けを決まった順に並べて次の 1 手を 1 つ) を出し、 席が立ち上がるときの hook が黙る動きは変えません。 起こす道具 (git や tmux など) は全部「何を起こすかの記述」(ADR-0062) で書きます。 器は群へ勝手に入れず、 質問で決めず、 この記録で外部の部品を足しません。 口座が repo を信じた印を器が埋めるかは、 この記録では決めず後の決定に送ります。 user の決定は、 導入を 1 コマンドにし、 人が打つ command を最小にし、 人間向けの説明を持つことでした。 すべてを 1 語にできない理由は、 どの置き場を雛形にするかという host ごとの値が 1 つだけ残るからです。 それを環境変数や決まった場所で知れば、 環境変数の差し込み口を作らない・host ごとの値で分岐しないという決まりに反します。 そこで、 すでに器が置き場の紐づけに使っている git の設定と同じ道具で、 host の全体に 1 つだけ印を書く口 (host init) を置き、 残りは repo ごとに 1 回の init が雛形から導く形にしました。 init が今の口 (目印を書く口・設定 file の読み手・名乗りの file の形・席を立てる口) を順に呼ぶだけにしたのは、 今の形を変えずに既存の置き場と repo を 1 字も触らず、 外部の部品も足さないためです。 各段を飛ばせる形にしたのは、 途中で失敗しても撃ち直すだけで済み、 次の 1 手を必ず言えるようにするためです。 口座を symlink でつなぐのは、 口座の鍵を読まないという要件の内側に留まるためで、 群へ入れるのを --group に限るのは、 口座を使う判断を人に残すためです。 雛形を host 全体の置き場に置く案は、 設定 file を置き場ごとに 1 つとした前の決定の形を変えるので退けました。 質問で決める案は席から撃てないので退けました。 引数の無い席の起動で役割を orchestrator と解くのは、 席の役割が 1 つになったので (ADR-0045) 省いても曖昧にならないからで、 前の決定の「役割は必ず指定する」はこの形に限って置き換えます。 口座が repo を信じていないと席が確認で止まる穴は残りますが、 それを器が埋めるかは別の裁定が要るので、 この記録には入れず後の決定に送ります。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR59claimFR59 は席の起動が役割を受け、 口座を群の今の口座か選定で決め、 tmux の session は作らずに窓へ起動行を差し込むことを求める。 本 ADR の引数の無い seat launch は役割を orchestrator (ADR-0045 の唯一の席の役割) に解いてから受け、 口座の決め方と session を作らないことは変えない (session は init の段が seat launch の前に作る)。 「役割を必須で受け」を「役割が決まらないまま起動しない」と読むのは本 ADR の解釈で、 SRS の文面の改訂は user の手番に残る。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 4 つと、 代わりに引き受けること 5 つです。 良くなるのは、 人が打つのが 3 語になって 7 つの手作業と repo の外の手順が消えること、 抜けを doctor が順に名指して次の 1 手を言うこと、 init を何度撃っても壊れず途中で失敗しても続けられること、 環境変数を読まず今の形も変えないことです。 引き受けるのは、 引数の無い席の起動が今いる repo に頼り前の決定の 1 文を置き換えること、 置き場の名付けを器に焼くこと、 群を指定したときは他の置き場の設定 file も書き換えること、 名乗りの file の雛形は最小の値で init の仕事が 4 つの契約に割れること、 そして口座が repo を信じていないと席が確認で止まる穴が残り、 後の決定に送ることです。

✓ 良い結果

  • ●人が打つ command が host init・init・doctor の 3 語になり、 置き場の dir・口座の配線・host の面の写し・git の設定・marker・宣言・tmux と席の長い起動の 7 手と、 repo の外の散文の手順が消える。 人間向けの説明は 3 語の説明で足りる長さになる
  • ●marker・宣言・host の面・口座・session・登録の欠落を doctor が宣言順に名指し、 次の 1 手を 1 つ言う。 SessionStart の hook が 0 byte で黙る極性は変えずに、 黙った理由が doctor の 1 行で分かる
  • ●init の各段は冪等で、 2 度撃っても全段 skip になり、 段の途中の失敗は名指されて続きの段が進む。 群の面の書き換えは全部か皆無かで、 置き場ごとの宣言が食い違う周を作らない
  • ●置き場の在り処は git の global 設定の pointer 1 つで、 env も HOME も固定の path も読まない。 host の面・vessel 宣言・marker・seat launch の長い形の外形は変わらず、 既存の置き場と repo は無変更で動く

⚖ トレードオフ・代償

  • ●--group の周は、 init が他の置き場の host の面を書き換える初めての口になる。 全部か皆無かで守るが、 書く面の数は同じ親の下で群を宣言する置き場の数だけ増える

器が状態 (event log・受付・席の登録など) と host の manifest を置く dir。 repo の git の local 設定がどの state dir に仕えるかを指す。 本 ADR の init は雛形の置き場の隣に新しい state dir を作る。
host の manifesthost manifest
state dir の host.toml。 口座・plugin・起動引数・vessel・群の 5 表を持つ host 固有の宣言値の置き場 (ADR-0026・ADR-0049)。 本 ADR の init は群を除く 4 表を雛形から写す。
vessel 宣言vessel declaration
対象 repo の root の tracked file .vessel.toml。 許す command と共通の検証などを repo 自身が名乗る (ADR-0010 / ADR-0047)。 本 ADR の init は Cargo.toml の有無で形を選んだ雛形を書く。
project の群project group
席の口座を持つ単位 (ADR-0049)。 名・置き場の列・候補の口座の列を host の manifest の表 1 つが宣言する。 群の宣言は A1 の「使う」の常設の承認で、 本 ADR の init は --group を打った周だけ repo を足す。
席の起動seat launch
器の subcommand seat launch が役割と口座から起動行を導き、 席の登録を先に書いて tmux の窓へ差し込むこと (ADR-0026)。 本 ADR の後は引数の無い形が既定を解く。
口座の登録account registration
器の subcommand account add が口座の設定 dir と host の manifest の宣言を揃え、 login の起動行を user へ渡すこと (ADR-0026・FR58)。 credential は読まず書かない。 本 ADR の init は口座を登録せず、 既に在る口座の dir を結ぶだけ。
