設計判断記録 (ADR) scribe2 — 上限の余地の見積の粒度

契約表の行は file ごとの見込み行数を任意の欄 growth で宣言でき、 受付の上限の余地は file ごとの見込みで測る (size は既定の見込み・宣言は受付の先読みだけ・上限は gate が守る)

便の受付は、 契約の size (S / M / L) が表す 1 file あたりの増分の見積を、 触る file の全部に一律に当てて、 file の上限までの余地と比べる。 複数の file を触る契約では、 実際には数十行しか増えない file まで size の値で測られ、 余地の内側に入る契約が断られていた。 本 ADR は、 契約表の行に file ごとの見込み行数を宣言できる任意の欄 growth を足し、 受付は file ごとの見込みと余地を比べる形を決める。 size は既定の見込みのまま、 上限の値と size の 3 段は変えず、 宣言を信じるのは受付の先読みだけで、 上限そのものは gate の測定が守る。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は器が自動で進める 1 つの作業、 「余地」は file の上限 (1 file 1500 行) までの空き、 「見込み」はこの作業でその file が増えそうな行数のことです。 器は作業を始める前に、 触る file のそれぞれについて「この作業で増える行数が file の空きに入るか」を見積で確かめます。 今の見積は契約の大きさ (S / M / L) 1 つを触る file の全部に同じ値で当てるので、 増える見込みが数十行の file まで大きな値で測られ、 空きに入る作業が入口で断られていました。 この記録は、 契約の行に file ごとの見込みを書ける欄 growth を足し、 入口の検査は file ごとの見込みと空きを比べることを決めます。 大きさの 3 段と上限の値は変えません。 見込みを信じるのは入口の先読みだけで、 上限そのものは着地前の門が実際に数えて守ります。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 実際に起きたことと現物の仕組みと user の決定から説明します。 2026-09-23 に、 11 の source file を触る作業が入口で断られました。 断られた理由は 3 つの file の空きが足りないことでしたが、 その 3 つの file は実際には 10 行・30 行・45 行しか増えない見込みで、 空きには十分入ります。 今の仕組みは契約の大きさ 1 つを全部の file に同じ値で当てるので、 増えない file まで大きく見積もられます。 断られた作業を通すために、 AI の席が file を分割 (挙動を変えずに file を割る純移動) して空きを作る場当たりの運用も起きていました。 user は、 file ごとの見込みを書ける口を足し、 上限の値は変えないと決めました。 契約の行に欄を足すのは、 これまでに 3 回踏まれた作法です。

CTX1

実測 — 余地の内側に入る契約が受付便にする前の検査で断られた

2026-09-23 に、 口座の群の契約表設計 doc の中の契約の表の行 i (size L・write-set触ってよい file の列 は 17 file・うち source file は 11) が受付の上限の余地file の上限までの空きで断られた。 断りが名指した file は 3 つで、 余地は 297 行・642 行・677 行、 L の見積は 800 行である。 同じ行を形と done から file ごとに見積もると、 その 3 file の増分の見込みは 10 行・30 行・45 行で、 どれも余地の内側に在る (見込みは見積であって実測ではない)。 file 単位の見込みの最大は約 370 行 (群の段の file) で、 source 全体の合計も約 740 行と L の 1 段分に収まる。 行を M (300 行) に割っても、 余地 297 行の file で 3 行足りない。 つまり断りは見積の粒度の問題で、 file ごとの見込みを宣言できれば行は割らずに通る。 実測の数と 2 候補の比較は設計 § 46 の出所に在る。

CTX2

現物 — 受付の式は size を全 file に一律に当てる

受付の上限の余地は、 write-set の source file (file の上限 R-C4-2 の測定範囲と同じ crates 配下の src の .rs) について、 base の行数と file の上限 (rules 行裁定つきの規則の行 R-C4-2・1500 行) の差を余地とし、 契約の size が表す 1 file あたりの増分の見積 (rules 行 pipe.size_s_lines / m / l・100 / 300 / 800 行・user 裁定 2026-09-14) を write-set の全 .rs に一律に当て、 見積が余地を超える file を名指して断る。 core器の本体の source の合計 (rules 行 R-C4-1) も同じ式で 1 回で、 core の見積は size の値 × write-set の .rs の本数である。 縮む面 (接頭辞 - の項目)・着地で消える file (接頭辞 ~)・置き場だけの file (接頭辞 =) は余地も本数も求めない。 撃つのは受付だけで、 契約表の検査 (CI) は撃たない (表は履歴を持ち、 landed 済みの行の file はその後も育つ)。 宣言を信じるのは受付の先読みだけで、 上限そのものは gate着地前の合格の門 の測定 (xtask check の file-lines / core-lines・deny 線) が守る。 契約表の欄の正本は 17 欄 (任意 10) で、 rules manifest の読み手は欄の正本から知っている key を引き、 知らない key を持つ行は doc ごと拒む。 生成の写し (契約 file) は行の任意 key を 4 つ運ぶ (classes / opens / touches / targets)。 表の検査の理由の型は 15 値である。

CTX3

運用の型 — 席AI との対話の場が場当たりの純移動で余地を作り、 戻す経路が無い

満杯に近い file を触る契約が受付で断られると、 席は分割 (挙動を変えずに file を割る純移動) の便自動で進む 1 つの作業を先に起こして余地を作っていた。 その純移動は設計の責務の群で切るのでなく、 断られた契約を通すための場当たりの分割になりがちで、 純移動の便自身が同じ上限の余地で断られる型も在った。 断られた契約を orchestrator契約を書く役割の席 に戻し、 少し増やせば収まるのか、 上限を大きく超えるので責務ごとに設計し直すのかを決める経路も無かった。 受付の断りの 1 行と preflight の headroom の列は file と余地を既に出すが、 見積は size の語だけで file ごとの数を持たない。

CTX4

裁定と憲法の向き

2026-09-23 の user 裁定 (要旨) は、 契約表の行に file ごとの見込み行数file ごとの増分の見込みを宣言できる口を器scribe2 の本体に足し、 受付は file ごとの見込みと余地を比べ、 上限の値 (size の行数と file の上限) は変えない、 とした。 逐語は非公開の作業記録簿 (台帳 s2-07l.578 の description) に在る。 憲法の向きは次の 4 つである。 上限の値 (R-C4-1 / R-C4-2) は C4 の閾値で A2 の手続きの下に在り、 size の 3 段は裁定 iduser の決定を指す印 つきの rules 行 (C5) で、 本 ADR はどちらも変えない。 宣言値は測定を経ずに有効値にならない (C10) ので、 見込みは受付の先読みにだけ効き、 gate の測定を緩めない。 受付と契約表の検査が同じ 1 本の読み手を撃ち、 写しは欄を運ぶだけ (C2)。 決定はしご (C17) の段 2「既に在る」により、 断られた周を orchestrator に返す新しい問いの型は足さず、 受付の理由の 1 行が file と余地と size を出し、 preflight の headroom の列が file ごとの余地と見積を出す形に留める。 C17.2 (仕掛けを足すときは除くものを名指す) には次のように答える。 code から除くものは無い (size の意味は既定値として残る)。 除くのは運用の側で、 設計 § 24 / § 43 の純移動を余地づくりの回避策として使う運用 (CSQ-P3) が要らなくなる。 C17.2 の「何を除くか」は code の重複と場当たりの対象で、 本 ADR は足すもの (欄 1 つ・形の検査 1 語・読み手 1 本) と除く運用を名指して条を満たす。 契約表の欄の追加は、 表を読む古い版と新しい版のプログラムの間の約束 (契約表の形・ADR-0004) に触れるので、 ADR を書く条件に当たる。

CTX5

前例 — 任意の欄の追加は踏まれた作法

契約表の形の版 1 の下で、 後から任意の欄を足す形は 3 度踏まれている (surfaces・creates / tests / also・targets の 5 欄)。 いずれも欄の正本に足し、 生成物 contracts/schema.toml を描き直して着地し、 形の版の数字は動かなかった。 xtask の台帳の計画は自前の行の読み手を持ち、 知らない key は読まないので、 欄の追加で動かない。 一方で古い binary は知らない key を持つ行を doc ごと拒むので、 新しい欄を持つ doc を読ませるには PATH の binary の入れ替えを伴う (縮む面や置き場だけの file の接頭辞を足したときと同じ型)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 見積の粒度を測る単位 (file) に合わせること、 上限の値と大きさの 3 段を変えないこと、 入口の検査と表の検査が同じ 1 つの読み手を使い写しは欄を運ぶだけにすること、 見込みは入口の先読みだけで上限は門が守ること、 表を読むプログラムが古い版から新しい版へ移るときの形をこれまで 3 回使ってきた「任意の欄を足す」やり方に合わせること、 そして断られた作業を戻す経路を持ちつつ新しい仕掛けを足さないことです。

DR1見積の粒度を測る単位 (file) に合わせる — 余地は file ごとに測るのだから、 見積も file ごとに宣言できなければ、 実増分の小さい file が満杯の file の隣に在るだけで契約が断られる CTX1 (余地の内側に在る契約の断り)・CTX2 (一律の式)
DR2上限の値と size の 3 段は変えない — file と core の上限は A2 の閾値、 S / M / L の行数は裁定 id つきの rules 行で、 本件は粒度の問題であって値の問題ではない CTX4 (裁定・A2・C5)
DR3受付と表の検査が同じ 1 本を撃つ — 欄の項目を path と行数へ分ける読み手は 1 本で、 受付 (1 行) と契約表の検査 (全行) が同じ関数を撃ち、 写しは欄を運ぶだけ (憲法 C2) CTX2 (受付だけが撃つ式・写しの任意 key)・憲法 C2 (経路は 1 本)
DR4宣言は先読みだけで、 上限は gate が守る — 見込みが偽でも上限は超えられない (憲法 C10・宣言値は測定を経ずに有効値にならない) CTX2 (gate の deny 線)・CTX4 (C10)
DR5表を読むプログラムが古い版から新しい版へ移るときの形を、 これまで 3 回使ってきた「任意の欄を足す」やり方 (surfaces・creates / tests / also・targets) に合わせ、 write-set の項目の文法 (6 形・接頭辞 1 字) に触れない CTX5 (前例)・CTX2 (項目の文法を読む site の広さ)
DR6断られた契約を戻す経路を持ち、 新しい問いの型は足さない — 断りが file・余地・見込みを名指し、 orchestrator が growth を書くか純移動を先に通すか設計に戻るかを決める (憲法 C17 の段 2) CTX3 (戻す経路の不在)・CTX4 (C17 の段 2・OPT6 を退ける根拠)
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。 契約の行に file ごとの見込みの欄を足す案、 触る file の列の各項目の末尾に見込みを添える案、 大きさを作業全体の合計と読み替える案、 大きさに段を足すか上限を上げる案、 何もせず分割で空きを作り続ける案、 断られたときに器が新しい問いの型で orchestrator に返す案です。 却下した 5 案にも利点を並べ、 退けた決め手が user の決定か分析かを各案に書きます。 末尾に添える案は欄を足さずに済む点で、 合計と読み替える案は数を 1 つのまま保てる点で、 問いの型を足す案は戻す経路が器の型として残る点で、 選んだ案に勝ります。

OPT1契約表の行に任意の欄 growth を足し、 受付は file ごとの見込みと余地を比べる採用

行に任意の欄 growth (list・項目は path と行数をコロンで結んだ 1 語・path は write-set の項目から接頭辞を剥がした素の path・行数は 0 以上の整数) を足す。 size は今までどおり既定の 1 file あたりの見込みで、 growth は名指した file だけをその値で上書きする。 写しは欄をそのまま運び、 項目の読み手は 1 本で受付と表の検査が同じ関数を撃つ。 core の見積は file ごとの見込みの和。 表の検査は項目の形の崩れ 5 つを理由の型 1 値 (GrowthForm) で行番号つきに名指す。 preflight の headroom の列の見積が file ごとの値になる。

契約の行に、 file ごとの見込みを書ける任意の欄 growth を足します。 書き方は「file の場所と行数」の対の並びで、 場所は触る file の列の項目から記号を外した素の場所、 行数は 0 以上の整数です。 大きさ (S / M / L) は今までどおり既定の見込みで、 欄に書いた file だけがその値で上書きされ、 書かない file は大きさのままです。 作業に渡す写しは欄をそのまま運び、 欄を読む部品は 1 つで、 入口の検査と表の検査が同じものを使います。 本体全体の見積は file ごとの見込みの合計です。 表の検査は、 欄の書き間違い (形が違う・触る file の列に無い・Rust の file でない・縮む file や消える file や置き場だけの file・同じ file が 2 回) を行番号つきで名指します。 事前確認の出力は file ごとの見積を出します。 利点は、 触る file の列の書き方に触れないので影響する場所が少なく、 欄を足す作法は 3 回踏まれていて、 大きさ (既定) と欄 (上書き) の意味が分かれて事前確認の 1 行で file ごとの見積が読め、 一番小さい大きさの作業 1 つに収まることです。 代わりに、 手で書く宣言が増え、 見込みと実際の差は門でしか捕まらず、 古いプログラムの入れ替えが要り (入れ替えるまでは欄を書いた作業が同じ理由で断られ続けます)、 触る file の列を器が自動で作る行と約束の行は欄を使えません。 入口を直す file 自身の空きが小さいので、 この作業は末尾に添える案と同じく一番小さい大きさでしか出せません。

+ 利点

  • write-set の項目の文法 (6 形・接頭辞 1 字・剥がす関数 1 本) に触れず、 交差・guard・gate・導出・xtask の項目を読む site (11 file 49 か所) が不変で、 赤になる既存の歯自動の検査は欄の pin (FIELDS 17 → 18・任意 10 → 11・TABLE_ERRORS 15 → 16) と Contract の構築点 3 か所 (intake.rs の歯・pipe/mod.rs の歯の fixture・e2e/polarity.rs の fixture) と ContractRow の歯の fixture 2 か所 (table/check.rs・contract.rs) と CapHeadroom の samples (refuse.rs) に閉じる (全部 write-set の中) (DR5)
  • 表の形の版 1 の下で任意の欄を足す、 という踏まれた前例 3 回 (5 欄) に乗る (DR5)
  • 意味が size (既定) と growth (上書き) に分かれ、 preflight の headroom の列 1 行で file ごとの見積が読める (DR1・DR6)
  • 触る面が S の契約 1 本に収まる (DR1)

− 欠点

  • 行ごとに file と行数の対を手で書く宣言が増え、 宣言と実増分の乖離は受付では捕まらず、 gate の上限の測定でしか捕まらない (DR4 の裏)
  • 古い binary は growth を持つ行を doc ごと拒む (知らない key) ので、 着地は PATH の binary の入れ替えを伴い、 入れ替えるまでは growth を書いた行の受付が同じ理由で断り続ける
  • write-set の欄を持たない行 (write-set を器が導出する行と約束の行) は growth の path を照らす相手が無く、 growth を持てない
  • 本便自身は受付の余地が 133 行の file を触るので、 S でしか受付を通らない (OPT2 と同じ制約・触る行は 15 行で足りる)
OPT2write-set の項目の末尾に見込みを添える (path=+N の形)不採用

行の write-set の項目に見込みを添え、 項目 1 つで file と見積を並べる。 決め手は分析 (項目の文法が 7 形になり、 = と + の字を別の位置で別の意味に使い、 項目を読む site 全部に波及する)。

触る file の列の各項目の末尾に、 見込みの行数を添える案です。 file と見込みが同じ項目に並び、 欄を足さずに済む利点があります。 けれども項目の書き方が 6 種類から 7 種類に増え、 既に別の意味で使っている記号 (= と +) を末尾で別の意味に使うことになります。 項目を読む場所は 11 の file に 49 か所あり、 その全部と「素の場所で照らす」という決まりを書き直すことになります。 古いプログラムは項目ごと読めずに断り、 直す file の空きが小さいので作業も通りにくく、 赤になる既存の検査も多くなります。 決め手は分析です。

+ 利点

  • file と見積が同じ項目に並び、 欄を足さずに済む
  • 宣言の置き場が write-set 1 つに閉じる

− 欠点

  • 項目の文法が 7 形になり、 置き場だけの接頭辞 = と新規 file の接頭辞 + の字を末尾で別の意味に使う。 接頭辞を剥がす site (11 file 49 か所) と、 交差・guard・gate の「素の path」の規則を書き直す (DR5)
  • 古い binary は項目ごと解けないと断り、 受付を直す file と導出の file の余地 (133 行・188 行) が M に足りず、 便自身が S でしか通らない上に赤になる既存の歯が多い (項目の形の母集団・剥がし方・受付の理由の字面)
OPT3size を契約全体の合計の見込みと読み替え、 file ごとの判定を外す不採用

size の値を「契約全体で増える行数」と読み、 file ごとの余地の判定を外して core の合計だけを測る。 決め手は分析 (1 file の満杯を測れない)。

大きさ (S / M / L) を「作業全体で増える行数」と読み替え、 file ごとの判定をやめて本体全体の合計だけを測る案です。 欄も書き方も足さず、 数が 1 つのままで済む利点があります。 けれども 1 つの file が満杯かどうかを入口で測れなくなり、 満杯の file に大きな作業を当てて入口を通り、 着地前の門で落ちる型が戻ってきます。 上限は file ごとに在るのに、 見積が作業ごとになるのは噛み合いません。 決め手は分析です。

+ 利点

  • 欄も文法も足さず、 数は 1 つのまま
  • 複数 file の契約が一律の見積で断られる型は消える

− 欠点

  • 1 file の満杯を受付で測れなくなり、 満杯の file に M を当てる契約が受付を通って gate で落ちる型 (受付の式の出所 3 件) が戻る (DR1・DR4)
  • 見積の粒度が file から契約へ粗くなり、 file ごとの余地を測る意味 (上限は file ごと) と噛み合わない
OPT4size に段を足す・上限の値を上げる不採用

S / M / L に段を足すか、 file の上限や core の上限を上げて、 断られる契約を減らす。 決め手は裁定 (値は user 裁定で本件では変えない・A2)。

大きさに段を足すか、 file や本体の上限の値を上げて、 断られる作業を減らす案です。 契約の表も書き方も変えず、 規則の行の値を変えるだけで済む利点があります。 けれども上限の値は憲法が定める閾値で、 変えるには user への諮問と裁定が要ります。 大きさの 3 段の値は user の決定の印つきの規則の行にあります。 どちらも今回の決定では動かしません。 どの段を足しても「1 つの値を全部の file に当てる」粒度は変わらないので、 増えない file が満杯の file の隣に在るだけで断られる型は解けません。 決め手は user の決定です。

+ 利点

  • 契約表の欄も文法も変えず、 rules 行の値の変更だけで済む

− 欠点

  • 上限の値 (R-C4-1 / R-C4-2) は憲法 C4 の閾値で A2 の手続きの下に在り、 size の 3 段の値は裁定 id つきの rules 行の user 裁定で、 どちらも本 ADR で動かさない (DR2)
  • どの段を足しても 1 file あたりの見積を全 file に一律に当てる粒度は変わらず、 実増分の小さい file が満杯の file の隣に在る型は解けない (DR1)
OPT5何もしない (純移動で余地を作り続ける)不採用

受付の式を変えず、 断られた契約のたびに席が純移動の便を先に起こして余地を作る。 決め手は裁定 (戻す経路を持つべきとの問題提起) と分析 (純移動が場当たりになる)。

何もせず、 断られた作業のたびに AI の席が file を分割して空きを作り続ける案です。 器を触らず、 分割は挙動を変えないので門と検査の守りは効く利点があります。 けれども分割が断られた作業を通すための場当たりになり、 分割の作業自身が同じ理由で断られることもあり、 満杯の file が固定されます。 今も断りは file と空きを出しますが、 打てる手は分割だけです。 見込みの欄ができると、 少し増えるだけなら欄を書く・大きく超えるなら分割か設計のやり直し、 と選べるようになり、 これが戻す経路です。 決め手は user の問題提起と分析です。

+ 利点

  • 器を触らず、 今日の運用のまま
  • 純移動は挙動を変えない分割なので、 gate と歯の守りは効く

− 欠点

  • 純移動が断られた契約を通すための場当たりの分割になり、 純移動の便自身が同じ余地で断られる型も在る。 満杯の file が固定される (DR1・DR6)
  • 断られた契約を orchestrator に戻して、 少し増やせば収まるか設計し直すかを決める経路が無い (DR6)
OPT6断られた周に dispatcher便を自動で起こす部品 が Questioned の新しい型で orchestrator に返す不採用

受付が上限の余地で断った周に、 dispatcher が質問 record の新しい型を起こし、 file ごとの見込み・余地・不足を orchestrator に返す。 決め手は分析 (憲法 C17 の段 2「既に在る」)。

入口で断られたときに、 器が新しい種類の問いを起こして orchestrator に file ごとの見込み・空き・不足を返す案です。 戻す経路が器の仕組みとして残り、 席が断りの 1 行を読み落とさず、 既に在る質問と回答の配送に乗る利点があります。 けれども入口の断りの 1 行が file と空きと大きさを出し、 事前確認の列が file ごとの空きと見積を出すので、 同じ数を運ぶ問いの種類を増やすことになります。 断られた作業はまだ便になっていないので、 便の質問に載せるには触らないと決めた面に手を入れることにもなります。 決め手は分析 (既に在るものを使う) です。

+ 利点

  • 戻す経路が器の型として残り、 席が断りの 1 行を読み落とさない
  • 質問と回答の既存の配送 (FR31 / FR32) に乗る

− 欠点

  • 受付の理由の 1 行が file と余地と size を出し、 preflight の headroom の列が file ごとの余地と見積を出すので、 同じ数を運ぶ問いの型を増やすことになる (C17 の段 2・DR6)
  • 受付で断られた契約は便を持たない (run dir も event も作らない) ので、 便の質問 record に載せるには dispatch の理由の型 (触らない面) に値を足すことになる
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 契約の行は file ごとの見込みを任意の欄 growth に書けます。 大きさ (S / M / L) は今までどおり既定の見込みで、 欄に書いた file だけがその値で上書きされます。 入口の検査は file ごとの見込みと空きを比べ、 本体全体の見積は file ごとの見込みの合計にします。 表の検査は欄の書き間違い 5 種類を行番号つきで名指します。 断られた作業は、 入口の断りの 1 行 (file・空き・見込み) と、 便を起こす前の事前確認 (preflight) が出す file ごとの空きと見積の列を読んで、 orchestrator が欄を書くか分割を先に通すか設計に戻るかを決めます。 上限の値・大きさの 3 段・門の測定・触る file の列の書き方は変えません。

採用 — OPT1

契約表の行 SHALL 任意の欄 growth を持てる。 値は list で、 項目は path と行数をコロンで結んだ 1 語 (path は write-set の項目から接頭辞を剥がした素の path・行数は 0 以上の整数) とする。 size SHALL 今までどおり既定の 1 file あたりの見込みで、 growth は名指した file だけをその値で上書きし、 名指さない file は size のままとする。 欄の正本 (FIELDS) に 1 欄 (任意・list) を足し、 契約表の行の型に field を 1 つ足し、 生成物 contracts/schema.toml を描き直す。 生成の写し (契約 file) SHALL 行の growth をそのまま運び (写しの任意 key に 1 つ足す・行に無ければ写しにも書かない)、 写しの読み手が読む。 項目を path と行数へ分ける読み手 SHALL 1 本で、 受付と契約表の検査が同じ関数を撃つ。 受付 SHALL file ごとの見込み (growth に在ればその値・無ければ size の値) が上限の余地を超える file を名指して断り、 core の見積は core に属する write-set の .rs ごとの見込みの和とする。 接頭辞 - / ~ / = の項目は今までどおり余地も本数も求めない。 断りの理由の 1 行 SHALL file の見込みの値も出す。 契約表の検査 SHALL growth の項目が (a) path と行数の形でない (b) path が行の write-set の file の項目に無い (dir の項目は展開しない・write-set の欄を持たない行は growth を持てない) (c) path が .rs でない (d) path が接頭辞 - / ~ / = の項目 (e) 同じ path が 2 回、 のどれかに当たる周に、 理由の型の 1 値 GrowthForm で行番号と項目と理由を名指す (contracts check は全件・受付は 1 行に同じ関数)。 preflight の headroom の列 SHALL 見積を file ごとの値で出す (形は不変)。 戻す経路は受付の理由の 1 行 (file・余地・見込み) と preflight の headroom の列 (file ごとの余地と見積) とし、 orchestrator は実増分が余地に入るなら行に growth を書き、 超えるならその file を接頭辞 - で宣言する純移動の行を先に通すか責務を割る設計に戻る。 器に新しい問いの型は足さない。 足すのは任意の欄 1 つと形の検査 1 語 (GrowthForm) と読み手 1 本で、 code から除くものは無い (size の意味は既定値として残す)。 除くのは運用の側で、 純移動を余地づくりの回避策として使う運用が要らなくなる (C17.2)。 触らないものは次の 7 つで、 size の 3 段の値と rules 行・file と core の上限の値・gate の測定 (宣言を信じるのは受付の先読みだけで、 宣言が偽でも上限は超えられない)・write-set の項目の文法 (6 形・接頭辞 1 字・剥がす関数)・xtask の台帳の計画・dispatch の理由の型・断りの語である。 契約表の形の版は 1 のまま任意の欄を 1 つ足す形とし、 古い binary が growth を持つ doc を拒む期間は PATH の binary の入れ替えで閉じる。

契約の行に、 file ごとの見込みを書ける任意の欄 growth を足します。 書き方は「file の場所と行数」の対の並びで、 場所は触る file の列の項目から記号を外したそのままの場所、 行数は 0 以上の整数です。 大きさ (S / M / L) は今までどおり既定の見込みで、 欄に書いた file だけをその値で上書きし、 書かない file は大きさのままです。 契約の表の欄の一覧に 1 欄を足し、 生成物の一覧も描き直します。 作業に渡す写しは欄をそのまま運び (行に無ければ写しにも書きません)、 欄を読む部品は 1 つで、 入口の検査と表の検査が同じものを使います。 入口の検査は、 file ごとの見込み (欄に在ればその値・無ければ大きさの値) が空きを超える file を名指して断り、 本体全体の見積は file ごとの見込みの合計にします。 縮む file・消える file・置き場だけの file は今までどおり数えません。 断りの 1 行は file の見込みの値も出します。 表の検査は、 欄の書き間違い 5 種類 (形が違う・触る file の列に無い・Rust の file でない・縮む file や消える file や置き場だけの file・同じ file が 2 回) を行番号つきで名指します。 便を起こす前の事前確認 (preflight) が出す列は、 file ごとの空きと見積を出します。 断られた作業を戻す経路は、 入口の断りの 1 行 (file・空き・見込み) と事前確認の列 (file ごとの空きと見積) です。 orchestrator はそれを読んで、 実際の増分が空きに入るなら欄を書き、 超えるならその file を縮める分割 (挙動を変えずに file を割る純移動) の行を先に通すか、 責務を割る設計に戻ります。 器に新しい問いの型は足しません。 プログラムに足すのは欄 1 つと書き間違いの検査 1 種類と欄を読む部品 1 つで、 プログラムから除くものはありません (大きさの意味は既定値として残します)。 除くのは運用の側で、 空きを作るために場当たりの分割を使う運用が要らなくなります。 変えないものは、 大きさの 3 段の値と規則の行・file と本体の上限の値・門の測定・触る file の列の書き方・台帳の計画の読み手・起動の理由の型・断りの語です。 表の形の版は変えずに任意の欄を 1 つ足す形で、 古いプログラムが新しい欄を持つ設計 doc を拒む期間はプログラムの入れ替えで閉じます。 空きは file ごとに測っているのに、 見込みは作業に 1 つしか書けません。 それでは、 増えない file が満杯の file の隣に在るだけで、 空きに入る作業が入口で断られます。 見込みを file ごとに書けるようにすれば、 測る単位と見積の単位が揃い、 断られるのは、 見込みが空きを超える file と、 見込みの合計が本体全体の空きを超える契約になります (見込みは宣言で、 実際の行数は門が測ります)。 触る file の列を器が自動で作る行と約束の行は欄を使えません。 上限の値と大きさの 3 段を変えないのは、 それらが user の決めた値であり、 今回の問題は値ではなく粒度だからです。 見込みを信じるのは入口の先読みだけにして、 上限は着地前の門が実際に数えて守ります。 これは、 人が書いた宣言は測定を経てはじめて効力を持つという憲法の線に沿っています。 欄を読む部品を 1 つにして入口と表の検査で共有し、 写しは欄を運ぶだけにするのは、 判定の経路を 1 本にする憲法の線です。 欄を足す形を選んだのは、 触る file の列の書き方に触れず、 表を読むプログラムの版が移るときの形も、 これまで 3 回使ってきた「任意の欄を足す」やり方に乗るからです。 断られた作業を戻す経路に新しい仕掛けを足さないのは、 入口の断りの 1 行が file と空きと大きさを出し、 事前確認の列が file ごとの空きと見積を出すからです。 今は打てる手が分割だけですが、 欄ができると「欄を書く・分割する・設計し直す」から選べるようになります。 末尾に添える案は欄を足さずに済みますが、 項目の書き方が増えて記号の意味が重なり、 影響する場所が広いので退けました。 合計と読み替える案は数が 1 つのままですが、 1 つの file の満杯を測れなくなるので退けました。 段を足す・上限を上げる案は値の変更だけで済みますが、 値は user の決定で今回は変えず、 粒度の問題も解けないので退けました。 何もしない案は器を触らずに済みますが、 分割が場当たりになり、 打てる手が分割だけで選ぶ経路が無いので退けました。 器が新しい問いの型で返す案は経路が仕組みとして残りますが、 同じ数を運ぶ問いの種類を増やすことになるので退けました。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR47rationale本 ADR は、 契約の正本である契約表の行に file ごとの見込み行数の任意の欄を足す根拠 (見積の粒度を測る単位に合わせる・size は既定のまま・項目の文法には触れない) を与える。 行が持つ欄の集合は広がるが、 正本が契約表の 1 行だけである線は変わらない。
FR68rationale本 ADR は、 dispatcher の受付が測る write-set の余地の判定 (file ごとの見込みと余地を比べ、 core は見込みの和) の根拠を与える。 受付が断った契約は今までどおり列に留まり、 断りの 1 行が file・余地・見込みを名指す。
FR55implementationFR55 は CI が全行に intake と同じ検査を回すことを求める。 growth の形の検査 (形の崩れ 5 つを行番号つきに名指す) もその同じ 1 本に載る。 上限の余地そのものは受付時点の事実なので CI では撃たない線は不変。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、 代わりに引き受けることです。 空きに入る作業は行を割らずに通り、 見積の粒度が file に揃い、 版を跨ぐ形は欄 1 つで済み、 場当たりの分割が要らなくなります。 代わりに引き受けることは 5 つあります。 file と行数を手で書く宣言が増え、 見込みと実際の差は門でしか捕まりません。 古いプログラムは新しい欄を持つ設計 doc を丸ごと拒むので、 入れ替えが要り、 入れ替えるまでは欄を書いた作業が入口で同じ理由で断られ続けます。 触る file の列を器が自動で作る行と約束の行は欄を使えません。 入口の検査を直す file 自身の空きが小さいので、 この作業自体は一番小さい大きさで出します。 本体全体の見積は file ごとの見込みの合計になるので、 file ごとには空きに入っても本体全体の空きで断られることはあります。 見込みと実際の差の記録は、 この記録では決めません。

✓ 良い結果

  • ●実増分が余地の内側に在る契約 (行 i の型) は、 行を割らずに file ごとの見込みを書くだけで受付を通る。 見積の粒度が測る単位 (file) に揃う
  • ●変わる面は任意の欄 1 つで、 write-set の項目の文法と接頭辞を剥がす関数と項目を読む site は不変。 赤になる既存の歯は欄の pin (FIELDS 17 → 18・任意 10 → 11・TABLE_ERRORS 15 → 16) と Contract の構築点 3 か所 (intake.rs の歯・pipe/mod.rs の歯の fixture・e2e/polarity.rs の fixture) と ContractRow の歯の fixture 2 か所 (table/check.rs・contract.rs) と CapHeadroom の samples (refuse.rs) に閉じる (全部 write-set の中)
  • ●断られた契約を戻す経路が定まり、 席が場当たりの純移動で余地を作る運用が要らなくなる。 純移動は設計の責務の群で切る便に戻る

⚖ トレードオフ・代償

  • ●行ごとに file と行数の対を手で書く宣言が増える。 宣言と実増分の乖離は受付では捕まらず、 gate の上限の測定でしか捕まらない (宣言を信じるのは受付の先読みだけ)
  • ●古い binary は growth を持つ doc を知らない key として doc ごと拒む。 着地は PATH の binary の入れ替えを伴い、 入れ替えるまでは growth を書いた行の受付が同じ理由で断り続ける
  • ●write-set の欄を持たない行 (write-set を器が導出する行と約束の行) は growth を持てず、 その行は今までどおり size の一律の見積で測られる
  • ●本便自身は受付の余地が 133 行の file を触るので、 S でしか受付を通らない。 core の見積が和になるので、 多くの file に大きな見込みを書く行は core の余地で断られうる
  • ●見込みは受付の 1 時点の先読みで、 着地時の実増分は記録しない。 乖離の記録 (検出線に載せるか) は本 ADR では決めず、 要るなら別の決定で行う
