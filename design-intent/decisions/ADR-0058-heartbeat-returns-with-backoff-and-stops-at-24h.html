設計判断記録 (ADR) scribe2 — 席の heartbeat (管理 tick) の復活

heartbeat (管理 tick) を器に戻す — 席が黙ったら器が続きを促し、 変化が無ければ合図の間隔を倍々に伸ばし、 待ちが 24 時間を超えたら送らない (ADR-0045 の一部を戻す)

席 (人と AI が話す session) が黙っても、 器を使う他の project では誰も続きを促さず、 席は止まったままになる。 本 ADR は、 席の外から周期で席を見て、 黙った席に続きを促す 1 行を差し入れる仕組み (heartbeat = 管理 tick) を器に戻す。 席に変化が無ければ合図の間隔を倍々に伸ばし (backoff)、 次の待ちが 24 時間を超える段では送らず、 席に変化があれば初段の待ちへ戻す。 前の決定 (ADR-0045) が消した仕組みのうち、 戻すのは管理 tick・続きを促す合図 (打刻の合図)・周期を作る host の登録 (tick の unit) の 3 つで、 他の仕組みは消したままにする (ADR-0045 の一部だけを置き換える = 部分 supersede)。 本 repo では、 便 (契約 1 本の 1 往復) が終わるたびに器が席の画面 (pane) へ知らせるので席が動き続け、 この仕組みが要らないように見えただけである。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「heartbeat」は席の外から周期で席を見て、 黙った席に続きを促す 1 行を差し入れる見回り (管理 tick) のことです。 前の決定 (ADR-0045) はこの見回りを消しました。 この repo では作業が次々に流れ、 作業が 1 つ終わるたびに器が席へ知らせるので、 席は促されなくても動き続け、 見回りが要らないように見えたのです。 けれども器を使う他の project では、 席が黙ると続きを促すものが無く、 席は黙ったままになります。 この記録は、 見回りを「無駄に動かない形」で器に戻すことを決めます。 席に変化が無ければ次の合図までの待ちを倍々に伸ばし、 待ちが 24 時間を超えたらそれ以上は送りません (合図は最大 6 本・最後は最初からおよそ 41 時間後)。 席に変化があれば最短の待ち (40 分) に戻します。 戻すのは、 見回り・続きを促す合図・周期を作る host の登録の 3 つだけで、 前の決定が消した他の仕組みは消したままにします。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 user の決定と器の現物と前の器の形から説明します。 user は「heartbeat は要らない」という前の結論を覆し、 器を使う他の project では席が黙ったままになる、 と決めました。 条件は、 無駄に動き回らないこと、 つまり席に変化が無ければ合図の待ちを伸ばし、 24 時間まで伸びたら打ち切ることです。 前の決定で消えた code は git の履歴に残り、 いまの要件書は「持たない」と書いています。 一方で、 席が自分で押す判子 (状態の打刻) と、 席の画面へ 1 行を差し入れる経路は器に残っています。 前の器は、 待ちの長さだけで合図を止めていたので、 無変化の席に同じ合図が送られ続けました (席が受けたのは約 30 本・器の記録は 12 件・差は未解明)。 その実測から、 待ちを倍々に伸ばして打ち切る形を決めていました。 憲法は席の停止を器が検知して再開させることを求め、 仕組みを足すときは先に消すものを名指すことも求めます。 器を使う他の project の席は、 器の plugin の hook から判子を押しているので、 新しい配線は要りません。

CTX1

裁定 — 器を使う他の project では席が黙ると止まる

2026-09-23 の user 裁定は、 heartbeat席を促す見回りの呼び名 (管理 tick席を周期で見る仕組み) は要らないという前の結論を覆した。 本 repo では要望が縦に連なり、 便が終わるたびに dispatcher便を起こす器の口 の周が席の pane へ通知を出すので、 席は続きを促されなくても動き続けた。 それで管理 tick が要らないように見えただけで、 器を使う他の project (導入先器を使う他の repo) では、 席が黙ると続きを促す機構が無く、 席は黙ったままになる。 裁定の条件は、 無駄に動き回らないこと = 席に変化が無ければ合図の間隔を徐々に伸ばし、 間隔が 24 時間に達したら合図を打ち切ること、 である (本 ADR はこれを「次の待ちが 24 時間を超える段では送らない」と読む)。 逐語は非公開の作業記録簿 (台帳 s2-07l.580 の本文) に在る。

CTX2

現物 — ADR-0045 で消えたものと、 器に残っているもの

ADR-0045 §2 (2) (user 裁定 2026-09-18) は、 席の自律機能ごと管理 tick・打刻の合図の注入・合図の backoff間隔を倍々に伸ばす形・tick の unit・tick-stamp の file を削除し、 席の状態動いているか待っているかの打刻席が押す判子のうち読み手が消えるもの (UserPromptSubmit / Stop の Busy / Idle) も削除の対象に名指した。 削除の直前の code は git の履歴に在り、 rules 行裁定つきの規則の行 seat.tick_stale_s / seat.signal_backoff_s / seat.pointer_backoff_factor / seat.pointer_backoff_max_s も manifest から消えた。 ADR-0030 が決めた unit の口 (seat tick install / uninstall) と間隔の行 seat.tick_interval_s は、 削除の直前の現物にも無い (決定は在ったが land せず、 器を使う project の unit は人が手で書いていた)。 いまの SRS (v0.20) は FR27 (管理 tick を持たない)・FR43 (続きの pointer を注入しない)・FR64 (tick の unit周期を作る host の登録 の口を持たない)・FR44 (入力欄への合図の注入を持たない・差し込みは席の起動の起動行だけ) が「持たない」を要求し、 AC18 の不在を測る歯がそれを確かめる。 一方で器に残っているものが在る。 席の状態の打刻 (hook決まった瞬間に動く口 が UserPromptSubmit / Stop / SessionStart の周に state.jsonl へ 1 行を append する・ADR-0015) は 3 つとも現物に在るが、 最終行を席の状態として読む型は消えている。 席の pane へ 1 行を注入する経路 (入力欄の門・器自身の目印との一致で通す) は、 便の終端の pane 通知・群の逼迫の通知 (ADR-0055)・席の起こし直しが使うので在る。 systemctl は便の閉じ込めの scope の片付けで既に撃っており、 unit を reload / enable する口だけが無い。

CTX3

前の器の backoff の形 (削除前の最後の版・user 裁定 2026-09-17)

前の器の合図の brake は時間だけ (前の合図から seat.tick_stale_s 未満なら送らない) で、 席の状態が変わったかを見なかった。 器を使う別の project の実測 (台帳 s2-07l.423・2026-09-17) では、 承認待ちで無変化の席に同じ合図が約 6 時間送られ続け、 席が受けた合図は約 30 本、 器の注入の記録は 12 件で、 差は前の器では未解明のままである。 合図を受けるたびに席は 1 turn (1 手番) を消費した。 tick の周期は刻みが細かくても token を消費しない = 消費するのは合図に応える席の turn だけである。 user 裁定 2026-09-17T00:55Z (逐語は台帳 s2-07l.423 の notes) は、 tick は 1 分・合図は初段 40 分・無変化なら間隔を伸ばして最後は止める、 と定めた。 前の器の設計 (削除前の最後の版の §14) の形は次のとおり。 (1) 変化の digest席が動いたかの目印 は 2 値 = 席の状態の打刻の最終行の ts と、 置き場の fleet の event log出来事の記録 file の最終行の ts。 context は入れない (合図に応える turn ごとに増えるので無変化の席でも毎回変わる)。 台帳は読まない (毎周 bd を子 process で撃つ費用を tick に持ち込まない・台帳の動きは席の turn になって状態の打刻に現れる)。 (2) 合図を送った周は席の置き場に梯子の記録 1 行 (送った時刻 sent_at・段 step・基準の digest) を書くが、 送った周の digest は基準にしない (合図に応える席の turn が状態の打刻を必ず 1 行進めるので、 それと比べると毎回「変化あり」になり梯子が登らない)。 基準は席が合図に応えて Idle に戻った最初の周に取る (settle)。 settle しないまま初段の待ちを過ぎた周は、 その周の digest を基準にする (応えない席へは梯子が登る側に倒す)。 (3) 以後の周は基準と今の digest を比べ、 違えば段 0 (待ち = 初段 40 分)、 同じなら段 + 1 で待ち = 初段 × 係数 ^ 段 (sent_at から測る)。 待ちが上限 (86,400 秒) を超える段は送らない。 (4) 打ち切りの後も毎周 digest を測り、 変化した周に段 0 へ戻して送る。 (5) 床 (前の合図から初段の待ちの内側は送らない) は tick-stamp の mtime で、 梯子の記録とは別の file だった。 (6) rules 行は係数 (2) と上限の秒 (86400) を足し、 初段は seat.tick_stale_s (2,400 秒) を流用した。 §14 で却下済みの形は、 席 (AI) に「変化が無ければ heartbeat を打たない」と判断させる形 (席を起こす行為自体が合図の消費・自由文を判定入力にする) と、 固定の「3 回無変化で中断」(応答に依存して永久停止しうる) で、 本 ADR は比べ直さない。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C9 (席の停止の検知と再開) は席の停止の検知と再開を器に求める。 ADR-0045 は席 (orchestrator人と話す唯一の席 1 席) の面を「人と話す席は人が起こす」と解釈し、 便の側は dispatcher の起こし直しが担うとした。 本 ADR は、 席の面のうち「黙った席に続きを促す」だけを器へ戻し、 席の作り直し (cycle) は戻さない。 C2.2 (env を読まない) / C3 (状態は 1 つの置き場) は設定と状態の置き場を manifest と 1 つの DB に限る。 本 ADR が足す file は席の置き場 (state dir器の状態の置き場 の既存の席の dir) の梯子の記録 1 つだけで、 tick-stamp と席が自分で打つ生存の判子の file は戻さず、 rules 行の値は manifest に、 host 固有の値 (unit dir・binary) は引数にだけ置く (C1 規則は manifest の行 / N3 host 固有の分岐を持たない)。 SRS の上位要求 N-2 (無駄な消費は害) は、 席の turn を消費する合図を無変化の席へ繰り返さないことを求める。 C17.2 (足す前に消すものを名指す) に対して本 ADR が足すのは、 tick の判定と梯子の記録と unit の導出の 3 つで、 消すのは前の器の判定条件のうち退避物・context・cycle の 3 条件と、 席が自分で打つ生存の判子の file と口 (戻さない) である。 ADR-0015 (席の状態は hook の打刻) は席の状態を hook の打刻で持ち、 pane の字面を判定入力にしない (C3.3)。 ADR-0045 は Busy / Idle の打刻を「読み手が消える分」として部分 supersede したが、 打刻は現物に残っており、 本 ADR で tick がその読み手として戻り、 ADR-0015 §2.3 (打刻が無い・読めない・Busy が古い周は注入しない・古さの閾値は seat.tick_stale_s) がそのまま効く。 ADR-0030 (tick の unit は器が書く) は unit を器が 1 関数で導出して host へ書き、 有効化を 3 クラス非該当と読む形を決めた (ADR-0045 で丸ごと superseded)。 本 ADR はその形を pointer で写して戻す (ADR-0030 の状態は superseded のまま)。 ADR-0055 (群の逼迫は時計で測らない) は群の逼迫を timer で測らず便の終端の周と席の hook で測ると決め、 管理 tick の廃止は不変と書いた。 「時計で測らない」の前提は群の逼迫の計測についてのもので、 本 ADR の tick の timer は逼迫を測らないので、 その決定は崩れない (「管理 tick の廃止は不変」と書いた記述だけが本 ADR で古くなる)。 ADR-0055 CTX2 が 2026-09-22 に据え置きと書く「拍」(host の timer 1 本が dispatch の 1 周を撃つ案) は便の契機の話で、 席を促す tick とは目的が違うので選択肢に並べない。 ADR-0034 / FR68 の dispatcher は周期の timer を持たず、 本 ADR はこれも変えない。 C11 (判定は閉じた enum) は判定を閉じた enum で持つことを、 C13 (依存を足さない) は依存を足さないこと (systemctl は host の道具・git / tmux と同種) を求める。

CTX5

器を使う他の project の配線

器を使う project (導入先) の席は、 host の面 (host.toml) の [[plugin]] が名指す器の plugin dir を起動行に積み、 その plugin の hooks.json が UserPromptSubmit / Stop / SessionStart の周に器の hook を呼んで状態の打刻を書く (ADR-0026 / ADR-0028)。 席の登録席の記録 row row (役割・target・anchor席が仕える repo・口座) は fleet の event log に在り、 tick の unit の母集団はこの登録 row である (ADR-0030 §2.5・FR40)。 unit は host の systemd user の unit dir に器が書き、 その host の doctor器の健康診断 が席ごとに unit の有無と一致を名指す。 口座の設定 file の hook 行 (ADR-0056 の配線) はここでは要らない = 打刻は器の plugin の hook が既に書いている。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 黙った席を器が続きへ促すこと、 無駄に動かないこと (席の手番を使うのは変化があったときだけ。 毎分の見回り自体は AI を起こさず費用がかかりません)、 戻す仕組みは 3 つだけにすること、 席の変化は判子で測って画面の文字を読まないこと、 そして周期は host の timer で作り、 その登録は器が組んで書くことです。 向き (heartbeat を戻す・無変化なら伸ばして打ち切る) は 2026-09-23 の user の決定で決まっており、 ここで比べるのはその形です。

DR1黙った席を続きへ促す — 器を使う他の project でも、 席が黙ったら器が席の外から続きを促し、 人が気づいて促す必要を無くす (憲法 C9 の席の面) CTX1 (裁定)・憲法 C9 (席の停止の検知と再開)
DR2無駄に動かない — 席の turn を消費するのは変化があった周だけ。 無変化なら合図の間隔を倍々に伸ばし、 次の待ちが 24 時間を超える段では送らず、 変化で初段へ戻す。 毎分の見回り自体は席 (AI) を起こさず費用を持たない CTX1 (裁定の条件)・CTX3 (無変化の席に合図が送られ続けた実測)・SRS の上位要求 N-2 (消費は害)
DR3戻すのは 3 つだけ — 管理 tick・打刻の合図・tick の unit に閉じ、 ADR-0045 が消した残りは消したままにし、 状態の置き場と rules 行を最小に保つ (増殖の防止) CTX2・CTX4 (C17.2 / C2.2 / C3)・憲法の順位 2 位 (増殖の防止)
DR4席の変化は hook の打刻で測り、 pane の字面と自由文を判定入力にしない CTX4 (ADR-0015・C3.3)・CTX3 (digest の材料)
DR5周期は host の systemd user の timer で作り、 unit は器が 1 関数で導出して書く。 host 固有の値は引数だけで、 env と home は読まない CTX4 (ADR-0030・C2.2・N3)・CTX5
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 見回りを「待ちを伸ばして打ち切る形」で戻す案、 作業が終わったときの周に相乗りして timer を持たない案、 席 (AI) に自分で heartbeat を打たせて器は測らない案、 固定の間隔で無期限に合図を送る案、 何もしない案です。 却下した 4 案にも利点を並べ、 退けた決め手が user の決定か分析かを各案に書きます。 相乗りの案は、 判定は足すものの timer と host の登録を足さない点で選んだ案に勝ちます。 席に打たせる案と何もしない案は、 器に仕組みを 1 つも足さない点で勝ちます。 固定間隔の案は、 本当に黙っている席にも合図が届き続ける点で勝ちます。 前の器が退けた 2 つの形 (席に判断させる・固定回数で中断) は前の設計の §14 で却下済みなので、 ここでは比べ直しません。

OPT1管理 tick を backoff つきで戻す — unit は器が導出し、 変化は hook の打刻で測り、 無変化なら間隔を伸ばして待ちが 24 時間を超えたら送らない採用

器の subcommand seat tick を戻し、 判定の列は前の器の列から退避物・context・cycle の 3 条件を除き、 登録 row の門を先頭に足し、 入力欄の門を床の前に置く (登録の無い席へは注入せず、 門で断られた周を「送っていない」扱いにして梯子に数えないため)。 変化の digest は席の状態の打刻の最終行の時刻の 1 値。 合図を送った周は席の置き場に梯子の記録 1 行を書き、 席が応えて Idle に戻った周の digest を基準にし、 以後は無変化なら段を登って待ちを倍にし、 待ちが 24 時間を超える段は送らず、 変化で段 0 に戻す。 床の出所も梯子の記録で、 記録が無い周は初段として送り、 読めない周は送らない。 unit は ADR-0030 の形で器が導出して host へ書き、 rules 行 4 本 (間隔・初段の待ち・係数・上限) が値を持つ。

見回りを、 無駄に動かない形で器に戻す案です。 器の口 1 つが 1 分ごとに席を見て、 席の登録・席が押した判子・画面と入力欄・最短の待ち・間隔の列、 の順に条件を確かめ、 全部そろったときだけ続きを促す 1 行を差し入れます。 席に変化があったかは、 判子の最終行の時刻だけで測ります。 合図を送ったら「間隔の列と最後に送った時刻の記録」を 1 行書き、 席が応え終わった時刻を起点にして、 以後は変化が無ければ次の合図までの待ちを倍にし (80 → 160 → 320 → 640 → 1,280 分)、 その次の待ち (2,560 分) が 24 時間を超えるので送りません。 合図は最大 6 本で、 最後は最初からおよそ 41 時間後です。 打ち切った後も毎回測り、 変化があれば最短の待ち (40 分) に戻して送ります。 周期を作る host の登録は器が組んで書き、 値は規則の行 4 本が持ちます。 代わりに、 host に timer が戻り、 規則の行と記録 file が戻り、 要件書の改訂が要り、 合図に応えない席への合図も最大 6 本で打ち切られます。

+ 利点

  • 器を使う他の project でも、 席が黙れば器が続きを促す (DR1)
  • 席の turn を消費するのは変化の周だけで、 無変化の席への合図は最大 6 本 (最後は初回から約 41 時間後) で打ち切られる (DR2)
  • 判定入力は打刻の時刻だけで、 pane の字面も台帳も読まない (DR4)。 unit の導出と値の置き場は決定済みの形の再利用 (DR5)

− 欠点

  • host に timer が戻り、 systemd user session の無い host では効かない
  • rules 行 4 本と席の置き場の梯子の記録 1 file が戻り、 SRS の FR27 / FR43 / FR64 / FR44 の改訂と AC18 の不在の歯の書き換えが要る (user の手番)
  • 送った合図が入力欄に残ったまま消費されない・席が固まっている周は梯子が登る側に倒すので、 本当に黙っている席への合図も最大 6 本で打ち切られる (打ち切りは判定行と doctor から人が拾う)

+ 利点

04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 見回りを器の口 1 つで戻し、 判定は「席の登録 → 判子 → 画面と入力欄 → 最短の待ち → 間隔の列」の順に固定します。 席の変化は、 判子の最終行の時刻だけで測ります。 合図を送ったら「間隔の列と最後に送った時刻の記録」(梯子の記録) を 1 行書き、 席が応え終わった時刻を起点に、 以後は無変化なら次の待ちを倍にし、 待ちが 24 時間を超える段では送らず、 変化があれば最短の待ちに戻します。 周期を作る host の登録は、 前に決めた形 (ADR-0030) のまま器が組んで書きます。 値は規則の行 4 本 (周期・最短の待ち・倍率・上限) が持ちます。 要件書の 4 本 (FR27・FR43・FR44・FR64) は「持たない」から「待ちを伸ばして打ち切る形で持つ」へ改訂する根拠になり、 席の登録 (FR40) の記録をそのまま読みます。

採用 — OPT1

器 SHALL 管理 tick を subcommand seat tick 1 つで戻し、 打刻の合図続きを促す 1 行と、 tick の unit を器が導出して host へ書く口 (seat tick install / uninstall) を戻す。 戻す機構はこの 3 つで、 それに伴い状態の打刻の読み手の役 (ADR-0015 §2.3) と rules 行 seat.tick_stale_s の Busy の古さの閾値としての役が戻り、 seat.tick_interval_s は新設する。 作業記憶の退避と復元・context の計測と cap guard・強制 cycle・退避の合図・statusline・席間の連絡・hook 集合の食い違いの検知・tick-stamp の file・席が自分で打つ生存の判子の file と口 SHALL NOT 戻さない。 tick の判定 SHALL 順序固定の AND で、 前の器の列から退避物・context・cycle の 3 条件を除き、 登録 row の門を先頭に足し、 入力欄の門を床の前に置いた列 = 登録 row → 状態の打刻の最終行 (無い・読めない・Busy・Busy が seat.tick_stale_s より古い周は注入しない) → pane の取得と入力欄の門 (断られた周は送らず記録も書かない) → 床 → 変化の梯子、 の順に評価し、 最初に立たなかった条件を理由にし、 判定 SHALL 閉じた enum で持つ。 変化の digest SHALL 席の状態の打刻の最終行の時刻の 1 値とし、 fleet の event log・context・台帳・pane の字面 SHALL NOT 材料にしない。 backoff の梯子 SHALL 合図を送った周に席の置き場へ梯子の記録 1 行 (送った時刻 sent_at・段 step・基準の digest) を書き、 基準は席が合図に応えて Idle に戻った最初の周の digest に取り (初段の待ちを過ぎても応えない周はその周の digest)、 以後の周は基準と今の digest が違えば段 0、 同じなら段 + 1 とし、 待ち = 初段 × 係数 ^ 段 を sent_at から測り、 待ちが上限を超える段は送らない。 打ち切りの後も毎周 digest を測り、 変化した周に段 0 で送る。 床 (前の合図から初段の待ちの内側は送らない) の出所 SHALL 梯子の記録の sent_at だけとし、 記録が無い周 SHALL 初段として合図を 1 本送って記録を作り、 記録が読めない周 SHALL 送らず判定行に理由を出す (fail-closed)。 足す file SHALL 梯子の記録 1 つだけとする。 値 SHALL rules 行 4 本 (間隔 60 秒・初段の待ち 2,400 秒・係数 2・上限 86,400 秒・裁定 id つき) が持ち、 host の面と env SHALL NOT 読まない。 打刻の合図 SHALL 台帳の現在地から続きを進めるよう促す 1 行 (器自身の目印つき) を既存の注入の経路 (入力欄の門) で注入し、 席の応答 SHALL Stop の打刻で測る。 tick の unit SHALL ADR-0030 §2.1〜§2.5 と同じ形 (登録 row のある席ごとの service と timer を 1 関数で導出・置き場と binary と unit dir は引数・一時 file と rename・器の生成物でない file は上書きせず動かさない・有効化と撤去は 3 クラス非該当・撤去は退役消さずに脇へ移す dir への移動・doctor が席ごとに tick-unit の語を出す) とする。 判定行 SHALL 既存の注入の記録に pointer の語 (sent / settling / wait / stopped) と段を足す。 群の逼迫の計測 (ADR-0055) と便の起動の契機 (FR68) SHALL 不変で、 tick に載せない。 SRS の FR27 / FR43 / FR64 / FR44 と AC18 SHALL user が /folio-architect で改訂し、 本 ADR SHALL 改訂と rules 行の裁定 iduser の決定を指す印 の後に発効し、 それまで proposed のまま何も拘束しない。

見回り (管理 tick) を、 器の口 1 つで戻します。 一緒に戻すのは、 続きを促す 1 行 (判子ではありません) と、 周期を作る host の登録を器が組んで書く口で、 戻す仕組みはこの 3 つです。 それに伴い、 席が押す判子を読む役と、 判子の古さの閾値が戻り、 周期の値は新しく置きます。 前の決定が消した残り (記憶の退避と復元、 文脈の量の計測と上限の見張り、 強制の作り直し、 退避を促す合図、 画面の下の 1 行、 席どうしの連絡、 hook の食い違いの検知、 前の器の見回りが打っていた印の file、 席が自分で打つ生存の判子の file と口) は戻しません。 判定の順序は固定です。 席の登録が在るか、 判子の最終行が「応え終わって待っている」か (判子が無い・読めない・「動いている」・「動いている」のまま古い席には差し入れない)、 画面と入力欄が空いているか (人の文字が在れば送らず記録も書かない)、 最短の待ち (40 分) を過ぎたか、 間隔の列で送ってよい段か、 の順で、 最初に満たさなかった条件を理由にします。 席の変化は判子の最終行の時刻だけで測り、 出来事の記録 file・文脈の量・台帳・画面の文字は使いません。 合図を送ったら、 席の置き場に「間隔の列と最後に送った時刻の記録」を 1 行 (送った時刻・何本目か・起点の値) 書きます。 起点は、 席が合図に応え終わって待ちに戻った最初の見回りの値です (40 分たっても応えなければその時の値)。 以後の見回りでは、 起点と今の値が違えば最初の段に戻り、 同じなら段を 1 つ上げ、 待ちは 40 分 × 2 の段乗、 待ちが 24 時間を超える段では送りません。 打ち切った後も毎回測り、 変化があれば最初の段で送ります。 最短の待ちを測る出所もこの記録だけで、 記録が無ければ 1 本送って記録を作り、 記録が読めなければ送らずに理由を判定の行に出します。 足す file はこの記録 1 つだけです。 値は規則の行 4 本 (周期 60 秒・最短の待ち 2,400 秒・倍率 2・上限 86,400 秒) が持ち、 machine ごとの設定や環境変数は読みません。 続きを促す 1 行は、 台帳の現在地から続きを進めるよう促す文で、 器の目印をつけて既存の差し入れの経路 (入力欄の門) から入れ、 席が応え終わったことは「待っている」の判子で測ります。 周期を作る host の登録は、 前に決めた形 (ADR-0030) のままです。 登録された席ごとに service と timer を器が 1 つの関数で組み、 置き場と実行 file と書き先は引数で受け、 途中の状態を残さず書き、 器が作ったのでない file は上書きも移動もせず、 有効化と撤去は人の承認を要さず、 撤去は退役の場所への移動で、 健康診断が席ごとに host の登録の有無と一致を 1 語で出します。 判定の行には、 合図の状態 (送った・起点待ち・待ち・打ち切り) と段を足します。 口座の残りを測る仕組み (ADR-0055) と便を起こす契機は変えず、 見回りに載せません。 要件書の 4 本と受入基準は user が改訂し、 この記録は改訂と規則の行の決定の印が揃ってから効きます。 それまでは何も拘束しません。 器を使う他の project では、 席が黙ると誰も続きを促さず、 席は黙ったままになります。 席の外から周期で見て促す見回りを器に戻せば、 人が気づいて促す必要が無くなります。 毎分の見回り自体は席 (AI) を起こさないので費用がかかりません。 費用がかかるのは合図に応える席の 1 手番だけです。 前の器は待ちの長さだけで合図を止めていたので、 無変化の席に同じ合図が送られ続け、 席が受けるたびに 1 手番を消費しました。 だから合図の頻度は席の変化で決め、 変化が無ければ待ちを倍々に伸ばし、 24 時間を超えたら打ち切り、 変化があれば戻します。 席の変化を判子の時刻だけで測るのは、 画面の文字や自由な文章を判定に使わないという既存の決定 (ADR-0015) を守るためです。 文脈の量を入れないのは、 合図に応えるたびに増えて無変化の席でも毎回「変化あり」になるからで、 出来事の記録 file を入れないのは、 作業が 1 つ流れるだけで全部の席の待ちが最短に戻ってしまうからです。 台帳を読まないのは、 毎回の子 process の費用を見回りに持ち込まないためで、 台帳の動きは席の手番になって判子に現れます。 合図を送ると、 席はそれに応えて必ず判子を 1 席が応え終わったことは既にある「待っている」の判子で測れ、 状態の置き場を増やさずに済むからです。 周期を作る host の登録を器が組むのは、 前に決めた形 (ADR-0030) をそのまま使え、 machine ごとの値を引数だけで受けて環境変数を読まずに済むからです。 相乗りの案は timer を足しませんが、 黙った席では作業も流れず契機が来ないので退けました。 席に自分で打たせる案は器に何も足しませんが、 黙った席は自分を起こせず、 起きている席の判断も消費になるので退けました。 固定間隔の案は本当に黙っている席にも届き続けますが、 user の決定の条件に反するので退けました。 何もしない案は、 器を使う他の project で席が黙ったままになるので退けました。

FR43rationaleFR43 は続きの pointer を注入せず、 黙った席の続きは user が促すと書く。 本 ADR は、 続きを促す 1 行 (打刻の合図) を器が backoff つきで注入する形へ改訂する根拠を与える。 席が抱える次の仕事が台帳の現在値に在ることは不変で、 合図はそれを読んで続きを進めるよう促すだけである。
FR44rationaleFR44 は入力欄への差し込みを席の起動の起動行に限る。 本 ADR は打刻の合図の注入 (既存の入力欄の門を通る) を差し込みに足す改訂の根拠を与える。 席間の連絡の経路を持たないことは不変である。
FR64implementationFR64 は tick の unit の導入と撤去の口を持たないと書く。 本 ADR は ADR-0030 §2.1〜§2.5 の形 (器が 1 関数で導出して host へ書き、 有効化まで撃ち、 撤去は退役 dir への移動) の口を戻す実装の形を与える。 改訂は /folio-architect の段。
FR40rationaleFR40 は席の登録 row (役割と anchor を鍵に target・口座 label・雛形を持つ) を定める。 本 ADR の tick の unit の母集団と、 tick の判定の先頭の門は、 この登録 row である。 FR40 の文面は変えず、 同じ row を読む理由 (登録の無い席へは注入せず unit も書かない) を与える。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、 代わりに引き受けることです。 器を使う他の project でも席が黙れば器が促し、 席の手番を使うのは変化があったときだけで、 無変化の席への合図は待ちが 24 時間を超えたら打ち切られます (最大 6 本・最後は最初からおよそ 41 時間後)。 戻す仕組みは 3 つに閉じ、 判定に画面の文字も台帳 (作業記録簿) も使いません。 代わりに引き受けることは 6 つです。 host に timer が戻り、 systemd の無い host では動きません。 規則の行 4 本と記録 file 1 つが戻り、 要件書の改訂が user の手番で要ります。 判子が出なくなった席には届かないか合図が空回りし、 合図に応えない席への合図も最大 6 本で打ち切られます。 合図に応える 1 手番の消費は残り、 変化は席自身の判子でしか測らないので作業の終わりでは待ちが戻りません。 入力欄に人の打ちかけの文字が在る周は差し入れが次の見回りへ送られます。

✓ 良い結果

  • ●器を使う他の project でも、 席が黙れば器が席の外から続きを促し、 人が気づいて促す必要が無くなる
  • ●席の turn を消費するのは変化があった周だけになる。 無変化の席では、 最初の合図の後の待ちが 80 → 160 → 320 → 640 → 1,280 分と伸び、 その次の待ち (2,560 分) が 24 時間を超えるので送らない = 合図は最大 6 本で、 最後は初回から約 41 時間後。 変化があれば初段 (40 分) へ戻る
  • ●戻す機構が 3 つに閉じ、 判定入力は打刻の時刻だけで、 pane の字面も台帳も読まない形で戻る。 unit の導出と値の置き場は決定済みの形の再利用で、 新しい依存も新しい env の継ぎ目も無い

⚖ トレードオフ・代償

  • ●host に systemd user の timer が戻る。 systemd user session の無い host では unit の有効化が断られ、 tick は回らない (代わりの駆動は本 ADR の射程外)
  • ●rules 行 4 本 (間隔・初段の待ち・係数・上限) と席の置き場の梯子の記録 1 file が戻り、 SRS の FR27 / FR43 / FR64 / FR44 の改訂と AC18 の不在の歯の書き換えが要る (user の手番)。 それまで SRS と本 ADR は食い違い、 本 ADR は proposed で何も拘束しない
  • ●席の変化の測り方は状態の打刻の最終行の時刻に依存する。 hook が死んで打刻が出なくなった席は、 最終行が Busy なら古さで放置され (合図は出ない)、 最終行が Idle なら合図が出て梯子が登り打ち切られる。 打刻の無い席 (器の plugin を積まない席) には届かない (fail-closed の代償・判定行と doctor から人が拾う)
  • ●送った合図が入力欄に残ったまま消費されない・席が固まっている周は梯子が登る側に倒すので、 本当に黙っている席への合図も最大 6 本で打ち切られる。 打ち切りの後は変化が無い限り器は促さず、 人が seat launch か対話面で起こす
  • ●合図に応える 1 turn の消費は残る (変化があった周ごとに 1 回)。 変化は席自身の打刻だけで測るので、 便の終端や他の席の動きでは梯子は戻らず、 承認や回答の記帳のように対話面の席の turn で行われ打刻が進むものだけが初段へ戻す
  • ●打刻の合図の注入は既存の入力欄の門を通るので、 席の入力欄に人の打ちかけの文字が在る周は注入されず、 記録も書かず、 次の周へ送られる。 この周の梯子は登らず、 待ちも伸びない
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この記録が版の系譜のどこに在るかと、 判断が最後に行き着く原則です。 前の決定 (ADR-0045) のうち、 見回り・続きを促す合図・周期を作る host の登録の 3 つを消した部分と、 判子の読み手を消した部分だけを置き換え、 残りは変えません。 判子の決定 (ADR-0015) は読み手が戻るのでそのまま効き、 host の登録の決定 (ADR-0030) は置き換えられたままで、 その形をここから指して戻します。 口座の残りを作業の終わりで測る決定 (ADR-0055) と、 便 (作業の 1 往復) を起こす仕組みに timer を持たない決定は変えません。 この記録は発効前 (proposed) で、 系譜の上では現行 (current) ですが、 要件書の改訂と規則の行の決定が揃うまで何も拘束しません。 原則は「促すのは器・頻度は変化で決まり・変化が無ければ打ち切る」です。
