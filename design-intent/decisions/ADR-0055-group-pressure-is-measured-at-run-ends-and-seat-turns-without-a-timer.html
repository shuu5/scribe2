設計判断記録 (ADR) scribe2 — 群の逼迫の契機

群の逼迫は時計で測らず、 便の終端の周と席自身の hook で測る (通知は席の画面へ 1 行・移動は host の鍵の内側で 1 回)

ADR-0049 は席の口座を群 (project のかたまり) で持ち、 閾値を越えたら群ごと別口座へ移ると決めたが、 通知と移動の契機 (いつ測るか) は別の記録に委ねた。 常駐の時計で席を見回る仕組み (管理 tick) は ADR-0045 で廃止され、 器の timer で 1 周を撃つ案 (拍) も据え置かれた。 本 ADR は、 時計を持たずに逼迫を測る契機を決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「便」は器が自動で進める 1 つの作業のことです。 席の口座を project のかたまり (群) で持ち、 残りが少なくなったら群ごと別の口座へ移る、 という決定は先の記録で決まっています。 決まっていなかったのは「いつ測るか」です。 器は見回りの時計を持たないと決めているので、 この記録は、 作業が 1 つ終わった直後の 1 周と、 席が話す番のたびに動く仕組みの 2 つを計測の契機にすることを決めます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 決まっていることと無いものから説明します。 群と閾値と移り方は先の記録で決まりました。 見回りの時計は廃止され、 timer の案も据え置かれました。 器が持つ契機は、 作業の終端の 1 周と席自身の仕組みの 2 系統だけです。 測る口・知らせる口・記録の置き場は既に器の中に在ります。 要件書の 1 条 (口座の使用率を理由にした通知と立て直しの禁止) は、 この記録と同じ改訂で群の形へ書き換わりました。

CTX1

決まっていること — 群・閾値・移動の形 (ADR-0049)

席の口座を持つ単位は project の群 (かたまり) で、 宣言は host (この machine) の面の表 1 つ (第 1 段 = 作る順番の 1 番目・着地済み)。 閾値は 5 時間窓 85・7 日窓 95・モデル別窓 95 の rules 行裁定つきの値を持つ設定の行 (値と裁定は既に在る裁定の引き継ぎ)。 移動は群単位で host の lock1 度に 1 つしか通さない鍵 の内側で 1 回だけ判定し、 移り先は他の群が使っていない ∧ 便 (pipeline の 1 走行) が使っていない ∧ 閾値未満の候補の先頭、 候補が無ければ移らず user へ通知する。 移動は新しい口座で新しい席を起こすことで行い、 対話の記録は運ばず復帰は機械の注入に任せる。 ADR-0049 は通知と移動の契機を決めていない。

CTX2

無いもの — 時計の契機

管理 tick (常駐の時計で席を見回る仕組み) は ADR-0045 §2 (2) で廃止され、 拍 (器の timer一定の間隔で動く時計 が dispatch の 1 周器が次の作業を配る 1 巡を撃つ案) は 2026-09-22 に据え置かれた。 器が今持つ契機は 2 系統だけである。 1 つは dispatch の 1 周 (設計 dispatcher.md §5) で、 便の終端 (便が終わった直後)・手動 (人が撃った周)・印の直後 (承認などの記録の直後) に撃たれる。 もう 1 つは席自身の hook席の番ごとに自動で動く仕組み で、 席の開始・圧縮の直前・道具の直前に動き、 話す番の直前と終わりの口も宣言されている。

CTX3

現物 — 計測・通知・記録の口は既に在る

口座の使用率 (残りの割合) は便用と lens 用の選定が usage API口座の残りを返す外部の口 を撃って event log器が出来事を追記する記録の列 に実測として残し、 鮮度の rules 行の内側 (直近に測った周) では測り直さない (ADR-0020・設計 account-autonomy.md §13)。 dispatch の 1 周は「起こす便 0 ∧ 候補あり」を orchestrator の席の pane席の画面 へ 1 行で知らせる注入の口を持つ (設計 dispatcher.md §19)。 host の根machine に 1 つの共通の置き場は受付札と lock を既に置いている。 群の今の口座の記録は ADR-0049 が host の根の 1 件と決め、 まだ書かれていない＝記録が無い周の「今の口座」は種 (候補の先頭) で、 群の席が実際に居る口座 (登録 row の口座) は種と違いうる。 その口座は doctor の群の行が既に導いている。

CTX4

要件文との関係

SRS FR38 は管理 tick の廃止に合わせて「器は口座の窓の使用率を理由に開発 session へ退避の合図古い席に「作業をまとめて終えて」と伝える 1 行や妥協の通知を注入せず、 強制サイクルの印を書かず、 席を立て直さず、 窓ごとの強制の rules 行を持たない」と書かれ、 AC18 の不在の歯がその機構の不在を測る。 ADR-0049 の群の移動 (通知・席の起こし直し・窓ごとの閾値の rules 行) はこれと食い違った (ADR-0049 CSQ-N4)。 FR38 は spec の編集の口を通る user の手で本 ADR と同じ改訂で改稿され、 群の閾値越えの通知と群単位の席の起こし直しと窓ごとの閾値の rules 行 3 本を許し、 強制サイクルの印と timer は持たないままとなった (AC18 の不在の歯は管理 tick と cycle の機構を測り続ける)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 時計も常駐の仕組みも足さないこと、 測る口と知らせる口と記録の置き場を既存の 1 本ずつで済ませること、 残りが減る周に契機が在ること、 そして移動は群ごとに 1 回で記録と承認を伴うことです。

DR1時計の契機を足さない (足すなら先に消すものを名指す・憲法 C17.2)・常駐 process (立ちっぱなしの見張り) を持たない (ADR-0034 / ADR-0045) CTX2・憲法 C17
DR2測る口と通知の口と記録の置き場は既存の 1 本ずつを使い、 新しい系統を増やさない (同じ仕事の口を 2 つ作らない・憲法 C2 / C17) CTX3・憲法 C2
DR3逼迫は席が動いている周に進み、 席が動いている周には契機が在る (席の話す番・便の終端) CTX2 (2 系統の契機)・ADR-0020 §2.4
DR4移動は 1 回・群単位・記録つき・承認 event (承認の記録) つき (憲法 A1「使う」・C10) CTX1・憲法 A1 / C10
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 4 つ並べます。 作業の終端の 1 周と席自身の仕組みの 2 系統で測る案、 timer で 1 周を撃つ案、 席自身が測って自分で起こし直す案、 表示の行に出して人が見る案です。 却下した 3 案も利点を 2 つずつ持ち、 それを含めて秤に掛けます。

OPT1便の終端の周作業の終端などに器が回す 1 周と席自身の hook の 2 系統で測り、 通知は席の画面への 1 行、 移動は dispatch の 1 周が host の鍵の内側で行う採用

第 1 段〜第 3 段は作る順番の段階 (宣言 → 通知 → 移動) で、 1 周の中の手順ではない。 (1) dispatch の 1 周 (便の終端・手動・印の直後) が、 宣言された群ごとに、 群の今の口座とその群の席が実際に居る口座 (登録 row の口座・重複は畳む) の使用率を鮮度つきで読み、 どれかが閾値以上なら席の画面へ 1 行を注入して event に 1 件記し (第 2 段)、 第 3 段では同じ周が host の lock の内側で移り先を決めて記録と承認 event を書き、 新しい口座の席を起こし古い席へ退避の合図を送る。 (2) 席自身の hook (席の開始と、 話す番ごとの hook) は自席の口座を同じ読み手で読み、 閾値以上なら指示文の 1 行で告げ、 移動を頼む記録「そろそろ別の口座へ」と席が置いておくメモ 1 件を host の根に置く (移動そのものは次の dispatch の 1 周が行う＝席は自分を起こし直さない)。 計測は既存の 1 本で、 鮮度の内側では usage API を撃たない。 鮮度の外は席の hook が器を子として起こして待たず、 値は次の話す番で読む。

作業が 1 つ終わった直後 (と手で撃ったとき・承認などの記録の直後) に器が回す 1 周が、 かたまりごとに、 今の口座とそのかたまりの席が実際に居る口座の残りを読みます。 閾値以上なら、 第 2 段では席の画面に 1 行を差し込んで知らせ、 その 1 件を記録に残します。 第 3 段では同じ 1 周が鍵をかけて移り先を 1 回だけ決め、 今の口座の記録と承認の記録 (event) を書き、 新しい口座で新しい席を起こし、 古い席には「まとめて終えて」の 1 行を送ります。 席自身の仕組みは、 自分の口座の残りを読んで、 閾値以上なら指示文で告げ、 「そろそろ移して」の記録を machine 共通の置き場 (host の根) に 1 件置くだけです。 自分で起こし直しません。 残りの読みは既存の 1 本で、 直近に測った周は測り直しません。 測り直しが要る周は、 席の仕組みは測り直しを起こすだけで待たず、 次の番で読みます。

+ 利点

  • 時計も常駐 process も足さず、 増えるのは既存の口の読み手だけ (DR1 / DR2)
  • 席が動いている周 (話す番) と便が動いている周 (終端) の両方で測るので、 逼迫が進む周に契機が在る (DR3)
  • 移動は dispatch の 1 周に閉じ、 host の lock の内側で 1 回・記録と承認 event つき (DR4)

− 欠点

  • 席も便も動いていない周は測らない (逼迫も進まないので実害は無いが、 user が手で 1 周を撃つ周が在る)
  • 鮮度が切れた周は hook が計測を起こして待たないので、 告げるのが次の話す番に 1 つ遅れる
OPT2器の timer (拍) が dispatch の 1 周を撃つ不採用

一定の間隔で 1 周を撃ち、 その周が群の逼迫口座の残りが決めた線に届くことも測る。

一定の間隔で器が 1 周を撃つ timer を足す案です。 席も作業も動いていない周も測れ、 契機が 1 系統で済む利点はありますが、 見回りの時計を廃止した決定を一部戻すことになり、 足すなら先に消すものを名指す憲法の決まりにも当たります。 据え置きの裁定が既に在り、 覆すには新しい裁定が要ります。

+ 利点

  • 席も便も動いていない周も測れる (人が 1 周を撃つ手間が要らない)
  • 契機が 1 系統で済み、 席の hook に何も足さない

− 欠点

  • 時計の契機を足す (ADR-0045 §2 (2) の廃止を一部戻す・C17.2 で先に消すものが要る・DR1)
  • 据え置きの裁定が既に在り (2026-09-22・逐語は台帳 s2-07l.490)、 覆すには新しい裁定が要る
OPT3席自身の hook だけで測り、 席が自分を起こし直す不採用

席の話す番ごとの hook が閾値を測り、 閾値以上なら席が自分で別口座の席を起こして終わる。

席自身の仕組みだけで測り、 閾値以上なら席が自分で別の口座の席を起こして終わる案です。 器の 1 周に何も足さず、 席が話した直後に移れる利点はありますが、 同じかたまりの席が置き場ごとに別々に判断して同じ口座へ殺到する問題が戻り、 席は自分を起こす権能を持たない柵ともぶつかります。

+ 利点

  • dispatch の 1 周に何も足さず、 作るものが hook の側だけで済む
  • 席が話した直後に移れるので、 便が無い周でも待ちが無い

− 欠点

  • 同じ群の席が置き場ごとに別々に判定し、 同時に同じ口座へ殺到する (ADR-0049 が群単位の 1 回の判定で消した問題が戻る・DR4)
  • 席が自分を起こし直す口は権能の柵 (席は起動を撃てない・ADR-0045) と衝突する
OPT4statusline (席の表示行) で測って表示だけする不採用

席の statusline が話す番ごとに使用率を出し、 閾値を越えた表示を人が見て手で移る。

席の表示の行に残りを出して、 人が見て手で移る案です。 作るものがほぼ無く今日から使え、 器が席を動かさないので誤って移る事故も起きませんが、 知らせることも移ることも人の目に頼り、 群ごと一斉に移る要求を満たしません。 表示の字面に判定を置くことにもなります。

+ 利点

  • 作るものがほぼ無く、 今日から使える (器の変更が最小)
  • 器が席を動かさないので、 誤って移る事故が構造として起きない

− 欠点

  • 通知も移動も人の目に頼り、 第 2 段・第 3 段の要求 (一斉の移動) を満たさない
  • 表示の面に判定を置く (憲法 C3・判定の入力を表示の字面にしない)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 「第 2 段」「第 3 段」は作る順番の段階 (第 1 段 = 宣言・第 2 段 = 通知・第 3 段 = 移動) で、 1 周の中の手順ではありません。 作業の終端の 1 周が群ごとに残りを読み、 閾値以上なら第 2 段では席に 1 行で知らせて記録に残し、 第 3 段では鍵の内側で移り先を 1 回だけ決めて新しい席を起こします。 席自身の仕組みは告げて頼むだけで、 自分を起こし直しません。

採用 — OPT1

器 SHALL 群の逼迫を時計で測らず、 便の終端の周 (dispatch の 1 周) と席自身の hook の 2 系統で測る。 dispatch の 1 周 SHALL 宣言された群ごとに、 群の今の口座とその群の席が居る口座 (登録 row の口座・重複は畳む) の使用率 (5 時間窓・7 日窓・モデル別窓) を既存の計測の 1 本で鮮度つきで読み、 閾値の rules 行 (5 時間窓 85・7 日窓 95・モデル別窓 95・裁定 id つき) 以上になった群について、 第 2 段では席の画面へ 1 行を注入し event に 1 件記し、 第 3 段では host の lock の内側で移り先 (他の群が使っていない ∧ 便が使っていない ∧ 閾値未満の候補の先頭) を 1 回だけ決め、 群の今の口座の記録と承認 event を書き、 新しい口座で席を起こし、 古い席へ退避の合図を送る。 席自身の hook SHALL 自席の口座を同じ読み手で読み、 閾値以上なら指示文の 1 行で告げ、 移動を頼む記録を host の根に 1 件置き、 席 SHALL NOT 自分を起こし直さない。 候補が無い群 SHALL 移らず、 user へ通知し、 妥協の移動を作らない。 計測 SHALL 鮮度の内側では usage API を撃たず、 席の hook SHALL 鮮度の外の計測を待たない (器を子として起こし、 値は次の話す番で読む)。 器 SHALL NOT timer・常駐 process・窓ごとの強制の印を持たない。

器は、 かたまりの残りを時計で測りません。 作業が 1 つ終わった直後の 1 周 (手で撃った周と承認などの記録の直後の周も同じ) と、 席自身の仕組みの 2 つで測ります。 1 周は、 かたまりごとに今の口座と席が居る口座の残りを 3 つの窓 (5 時間・7 日・モデル別) で読み、 閾値 (85・95・95) 以上なら、 第 2 段では席に 1 行で知らせてその 1 件を記録に残します。 第 3 段では、 鍵の内側で移り先を 1 回だけ決めます。 移り先は、 他のかたまりが使っておらず、 走っている作業も使っておらず、 残りがどの窓でも線を越えていない候補の先頭です。 今の口座の記録と承認の記録 (event) を書き、 新しい口座で席を起こし、 古い席に終えるよう伝えます。 席自身の仕組みは、 告げて machine 共通の置き場に記録を 1 件置くだけで、 測り直しを待たず、 自分を起こし直しません。 移り先が無ければ移らず、 人に知らせ、 妥協の移動は作りません。 timer も常駐の process も、 窓ごとに強制で移す印も持ちません。 残りは、 席が話すか作業が走るかしたときにだけ減ります。 その 2 つには器の契機が既に在るので、 時計を足さなくても減る周に測れます。 測る口も知らせる口も記録の置き場も既に 1 本ずつ在り、 新しい系統を増やさずに済みます。 測る集合に席が実際に居る口座も入れるのは、 記録が無い周の「今の口座」は候補の先頭にすぎず、 席の現物と違いうるからです。 移動を 1 周に閉じ、 鍵の内側で群ごとに 1 回だけ決めるのは、 同じかたまりの席が同時に同じ口座へ向かう事故を構造で消すためです。 席自身に起こし直させる案は、 作るものが少なく待ちも無い利点はありますが、 同じかたまりの席の殺到が戻り、 席の権能の柵も破るので退けました。 timer は、 動いていない周も測れる利点はありますが、 廃止した決定を一部戻すことになり、 据え置きの裁定も在るので退けました。 表示だけの案は、 作るものが最も少ない利点はありますが、 一斉に移る要求を満たさないので退けました。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR38rationaleFR38 は群の逼迫を便の終端の周と席自身の hook で測り、 閾値の rules 行 3 本以上になった群の席へ通知し、 群単位で 1 回移動し、 timer・管理 tick・cycle・強制サイクルの印は持たないと書く。 本 ADR はその文言の根拠 (契機を時計に置かない理由と、 移動を 1 周に閉じる理由) を与える。 FR38 の改稿は本 ADR と同じ改訂で行われた。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、 代わりに引き受けることです。 時計も常駐の process も無いまま群ごと一斉に移れ、 新しい系統は増えません。 移動は 1 周に閉じてかたまりごとに 1 回だけ起き、 殺到が起きません。 代わりに、 席も作業も動いていない周は測らず、 鮮度が切れた周は告げるのが次の番に 1 つ遅れ、 移った後の席は機械が戻せるぶんの文脈しか持ちません。

✓ 良い結果

  • ●時計も常駐 process も無いまま、 席が動いている周と便が動いている周に逼迫が測られ、 群ごと一斉に移れる
  • ●測る・通知・記録・起動の口が既存の 1 本ずつで、 新しい系統が増えない
  • ●移動は dispatch の 1 周に閉じ、 群単位で 1 回・記録と承認 event つきで、 同じ群の席の殺到が構造で起きない

⚖ トレードオフ・代償

  • ●席も便も動いていない周は測らず、 手で 1 周を撃つまで通知も移動も起きない (逼迫も進まないので実害は限定的)
  • ●鮮度が切れた周は席の hook が計測を起こして待たないので、 告げるのが次の話す番に 1 つ遅れる
  • ●移動の後の席は対話の記録を持たず、 機械の注入で戻せるぶんしか文脈が残らない (ADR-0049 CSQ-N1 と同じ代償)
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この記録が版の系譜のどこに在るかと、 判断が最後に行き着く原則です。 群の記録の未決の契機を決めるもので、 時計の廃止は戻しません。 原則は「動いた周にだけ測る」です。

ADR-0049 (群・閾値・移動の形) の未決の契機を決める。 ADR-0045 §2 (2) (管理 tick の廃止) は不変で、 本 ADR は時計を戻さない。 ADR-0020 §2.4 (候補なしの周は立て直さない) は群の移動にもそのまま効く。

照会終端 — PRIN-MEASURE-WHEN-SOMETHING-MOVES

逼迫は何かが動いた周にだけ進むので、 動いた周に測る。 時計で見回らず、 動きの終端と席の話す番を契機にする。

本 ADR が timer を退け、 便の終端と席の hook の 2 系統に契機を置いたのはこの原則に行き着く (これ以上は遡らない照会終端)。
