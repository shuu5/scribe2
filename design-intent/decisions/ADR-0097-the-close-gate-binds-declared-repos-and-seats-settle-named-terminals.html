設計判断記録 (ADR) scribe2 — close の門の射程と決着の権能

close の理由の門は vessel 宣言の任意 key close-check を true で持つ repo にだけ掛け、 止まった終端を閉じる名指しの 2 形は席の決着の権能 settle で撃てる — 宣言が在って読めない repo は同じ判定を掛けて形の閉じは通し、 key は読み手を持つ binary の後でだけ書く。 settle は pipe land の --terminal-only つきの名指しの窓と pipe retire の名指しの窓に結び、 他の形は merge と launch のまま (ADR-0089 の門の射程・ADR-0094 の撃ち手・ADR-0048 の退役の権能を部分 supersede)

bead を閉じる理由の形を確かめる門 (起票の門の close の段) は、 今の要件の字では器を積む全部の repo の席に掛かる。 全部に掛けると、 器の便でない着地で memo を閉じる運用の消費側の repo では席の閉じがほぼ全部止まり、 本 repo では席が契約を着地の形で閉じられなくなって、 止まった便の終わりを閉じられるのが持ち主だけになる。 本 ADR は、 門を repo が宣言で加わった所にだけ掛けることと、 止まった便の終わりを閉じる 2 つの器の口を、 便 1 本を名指す形に限って席の新しい権能で撃てるようにすることを決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して取り込む 1 回の流れ、 「席」は人と AI が話す session、 「起票の門」は台帳 (bead の置き場) への書き込みを実行の前に確かめて止める器の門です。 bead を閉じるとき、 閉じる理由は決まった形でだけ書く決まりがあり、 今の要件の字では、 この形を確かめる門が器を積む全部の repo の席に掛かります。 けれども器を積む別の repo には、 自分の PR で仕事を取り込み、 memo を自由な字で閉じる運用の repo があり、 全部に掛けるとその席の閉じがほぼ全部止まります。 また本 repo では、 門が入ると席は契約を「着地した」の形で閉じられず、 取り込みは済んだのに閉じ待ちの便を閉じられるのが持ち主だけになります。 この記録は 2 つを決めます。 1 つ目に、 門は repo が自分の設定 file (vessel 宣言) に close-check = true と書いて加わった所と、 設定 file が在って読めない所にだけ掛けます。 2 つ目に、 閉じ待ちの便を閉じる器の口 2 つ (終わりだけの撃ち直しと、 PR の便の後始末) を、 便 1 本を名指す書き方に限って、 席の新しい許可 (決着の権能 settle) で撃てるようにします。 代わりに、 close-check を書いていない repo では形の外の閉じがそのまま通ることと、 設定 file に key を書くのは器の binary を入れ替えた後だけになることを引き受けます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 7 つから説明します。 閉じる理由の形と門が全部の repo に掛かる形で決まった経緯・全部に掛けると別の repo の席の閉じが止まる事象・門が入ると閉じ待ちの便を持ち主しか閉じられなくなる事象・設定 file の key の読み方と古い器が新しい key を断る性質・許可の表と 2 つの口の中身・憲法の向き・この判断で動かす範囲です。

CTX1

経緯 — close の理由の文法と門は、 器を積む全部の repo の席に掛かる形で決まっている

SRS FR81 (d) は、 器の plugin を積む席の session の道具の呼び出しの close のうち、 理由が close の理由の文法 (FR91) の外であるもの (理由の無い close を含む) と、 着地の形の理由を持つものを、 起票の門台帳の書き込みを止める門 (台帳の書き込みを止める hook の門) が実行の前に断ると決める。 ADR-0089 は文法の頭の字 (9 つ) を、 ADR-0094 は着地の形の尾と、 着地の形を書く器の 3 つの経路 (push の後の CI の照合・remote を宣言しない repo の照合なしの閉じ・PR で着地した便の pipe retire の照合) を決めた。 どちらも門の射程を repo で分けていない。 起票の門は PreToolUse の hook で、 器の plugin を積む全部の repo の席に、 同じ binary と同じ埋め込みの rules で効く。 close の段の設計 (設計 ledger-form.md の §16 と契約表の行) はまだ main に無く、 門は今 close の理由を見ていない。

CTX2

事象 — 全部の repo に掛けると、 消費側の席の閉じが止まる

器の plugin を積む消費側の repo には、 器の便でなく自前の PR の merge で仕事を着地させ、 memo と形の無い bead を自由な字の理由で閉じる運用の repo が在る。 2026-09-29 の実測では、 門を全部の repo に掛けると、 そうした repo の席の閉じがほぼ全部断られる (repo ごとの件数は台帳の memo にだけ在る)。 本 repo でも 2026-09-25 以後 (UTC) の close 167 本のうち、 器の終端が書いた着地の形が 124 本、 文法に合う席の閉じが 5 本、 門が断る形が 38 本 (memo 26・契約 7・形の無い bead 5) だった (2026-09-30 の実測)。 持ち主は、 門をまず本 repo だけに掛け、 他の repo は宣言して加わる形にすると裁定した (裁定 user 2026-09-29T21:53Z・逐語は台帳)。

CTX3

事象 — 門が入ると、 止まった終端閉じ待ちの便の終わりを閉じられるのは持ち主だけになる

land の終端が止まった便 (main の CI の初回の失敗・forge の問いの上限で運転手が止まった周・先端でない便の CI の結果が無い周) は、 着地は済んだのに契約が開いたまま残る。 2026-09-25 から 5 日で 7 件あり、 席が手で閉じていた。 門が入ると、 席は契約を着地の形で閉じられない (FR81 (d))。 止まった終端を閉じる器の口は 2 つ — 終端だけを撃ち直す pipe land --run <run> --terminal-only と、 PR で着地した便を merge の後に照合して閉じる pipe retire --run <run> — で、 権能の表は前者を merge の権能に、 後者を launch の権能に結ぶ。 どちらも席の rules 行 role.orchestrator に無い (ADR-0045 §2 (1)・ADR-0048) ので、 撃てるのは持ち主だけになる。 持ち主は、 この 2 つを便 1 本を名指す形に限って席の権能で撃てるようにすると裁定した (同じ裁定)。

CTX4

現物 — vessel 宣言器に名乗る設定の任意 key と、 古い読み手が新しい key を断る性質

vessel 宣言 (対象 repo の root の .vessel.toml・ADR-0010) は HEAD の tree から 1 本の読み手で読まれ、 作業ツリーの字は読まない。 任意 key は無ければ現行の値で動き、 在れば器がその値を読む (ADR-0047 の path の種別・ADR-0054 の entrance-flip・ADR-0084 の question-route)。 question-route の読み口は、 宣言した値・無い (宣言 file が HEAD に無い・git を撃てない・key が無い)・読めない (宣言が在って不備) の閉じた 3 値を返し、 読めないを無いに倒さない (C10)。 値の読みは文字列・整数・文字列の列の 3 種で、 真偽は読まない (SRS FR83 の ruling-check は true で加わりを名乗る key として要件にだけ在る)。 読み手は未知の key を宣言ごとの不備にし、 宣言が不備の repo では受付が便を起こさず、 権能 guard は repo の全 file を code に倒し、 land の終端は unreadable で止まる。 したがって新しい key は、 その key を知る binary に入れ替えた後でしか宣言に書けない。

CTX5

現物 — 権能 guard の表と名指しの窓、 2 つの口の中身

権能 guard の Bash 面は、 器の binary の直後の 2 語を表 (8 行・口 → 権能) と照合し、 pipe land を merge に、 pipe retire を launch に結ぶ。 停止だけは 2 語の後ろの窓も読み、 窓が --run・--state-dir・--repo・--rules とその値の対だけから成り、 --run がちょうど 1 回で、 値が - で始まらず shell の字を含まない呼び出しだけを stop に結び、 他の停止を launch へ降ろす (ADR-0048・設計 seat-roles.md §25)。 降りた周の断り文は通る名指しの形を 1 句で添える (§29)。 pipe land --terminal-only は段が Landed の便の終端だけを撃ち直す冪等の口で、 着地した sha を記録から読み、 撃った時点の宣言で経路 (push と CI の照合・照合なしの閉じ) を選び直す。 pipe retire は、 PR で着地した便には merge の祖先と先端の CI を照合して着地の形で閉じてから worktree を畳み、 他の終端の便 (Failed の一部・判定 FAIL の Gated・Stopped・判定 PASS でない Reviewed) は worktree を可逆な move で畳むだけで、 段は動かさない。 --fold-only は照合も close もせずに畳む。

CTX6

憲法と既存の決定の向き (本 ADR の解釈)

C16 は仕様からの外れを編集の時点で止める。 C10 は測れないものを測ったことにせず、 読めないを無いに倒さない。 C11.2 は境界ごとの失敗を開くか閉じるかの極性で持ち、 起票の門は閉じる側 (FailClosed) である。 C5 は rules 行の値の変更に裁定 id を要る。 C17 は足すものを決定はしごで最小にし、 C17.2 は先に消すものを名指す — 本 ADR が消すのは、 止まった終端を閉じるたびに持ち主が撃つ手と、 全部の repo に掛けたときに消費側の席が閉じのたびに受ける断りである。 A1 の「出す」は push を名指し、 終端の撃ち直しの push は vessel 宣言の key remote が名指す repo だけに撃たれる (宣言が承認している範囲で、 本 ADR は広げない)。 N1.2 は退役を可逆な move で行う (pipe retire の畳みは worktree を可逆な move で退かすので、 A1 の「消す」に当たらない)。 ADR-0048 は権能を操作の向きと誤射の大きさで分け、 席には便 1 本を名指す停止だけを戻し、 起動・再開・受付・退役・着地・merge を dispatcher の口に残した。 本 ADR はその分け方の規則 (名指しの窓・操作の向き) を保ったまま、 止まった終端を閉じる向きの 2 形を席に戻す。

CTX7

射程 — 動かすのは 2 つの決定だけ

動かすのは (1) 起票の門の close の段の射程を、 vessel 宣言の任意 key close-check閉じの門への加わり を true で持つ repo に限ること (key・値・読めない周の極性・着地の順)、 (2) 権能の列に決着の権能終わった便を閉じ畳む許可 settle を足し、 名指しの 2 形をそれに結び、 rules 行 role.orchestrator に足すことの 2 つである。 動かさないのは、 close の理由の文法の頭と値の形 (ADR-0089・設計 ledger-form.md §16)、 着地の形の書き手と 3 つの経路 (ADR-0094)、 台帳 write の 6 形と問いの形と引き金の行の断り (全部の repo のまま)、 2 つの口の本体と撃ち方、 停止の窓と stop、 他の口の権能、 着地・起動・merge を器の dispatcher が行うこと、 極性一覧、 要件書 (直すのは持ち主の SRS の改訂の回)。 決めないのは、 宣言していない repo の和の外の閉じを局面の出力が数えるかで、 SRS の改訂の回と局面の出力の設計に委ねる。 設計 ledger-form.md §16 (契約表の行 l・l1・l2・l3) と seat-roles.md §32 (行 z) が実装する。 ADR を書く条件のうち 1 (C11.2・C10・A1 の読み)・3 (宣言の key の形)・4 (却下案を残す価値) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 7 本のものさしです。 close-check を書いていない (設定を読める) repo の閉じ方を変えないこと。 加わった repo では形の外れを書く時点で止めること。 読めない設定を「無い」と読まず、 それでも形に合う閉じは止めないこと。 照合できる閉じ待ちの便を持ち主の手なしに閉じられること。 許可は操作の向きで分け、 名が操作と食い違わないこと。 取り込み・起動・merge と一括の片付けを席に戻さないこと。 足すものを最小にすることです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 9 つ並べます。 設定 file で加わった repo にだけ門を掛け、 名指しの 2 つの形を新しい許可 settle で席に渡す案 (選んだ案) と、 選ばなかった 8 つです。 選ばなかった案は、 全部の repo に掛ける案・別の repo の閉じ方を決めるまで門を起こさない案・掛ける repo を器の規則の行か host の設定で選ぶ案・読めない設定の repo の閉じを全部止める案・読めない設定を無いと読んで通す案・取り込みと起動の許可を丸ごと席に渡す案・止める許可 stop に載せる案・2 つの形を別々の許可にする案です。

OPT1門は close-check を宣言した repo にだけ掛け、 名指しの 2 形を新しい権能 settle で席に渡す採用

起票の門の close の段は、 台帳の repo の HEAD の vessel 宣言が任意 key close-check を true で持つ repo でだけ掛かる (宣言が在って読めない repo も同じ判定を掛け、 断るときは読めない旨の語で当たった形を名指す)。 権能の列に settle を足し、 pipe land の --terminal-only つきの名指しの窓便 1 本だけを指す書き方と pipe retire の名指しの窓を settle に結び、 rules 行 role.orchestrator に settle を足す。 決め手は裁定 user 2026-09-29T21:53Z と分析 (宣言は repo が PR の review を通して名乗る tracked な面で、 名指しの窓は ADR-0048 の規則をそのまま使える)。

門の閉じる段を、 台帳の repo の設定 file (vessel 宣言) が close-check = true を持つ repo にだけ掛け、 閉じ待ちの便を閉じる 2 つの口を、 便 1 本を名指す書き方に限って新しい許可 settle で席に渡す案です。 設定 file が在って読めない repo には同じ判定を掛け、 断るときは「設定を読めない」の語で当たった形を名指し、 形に合う閉じは通します。 close-check を書いていない repo の閉じ方を 1 字も変えず、 本 repo では形の外れを書く時点で止め、 読めない設定を無いと読まず、 照合できる閉じ待ちの便を持ち主の手なしに席の 1 行で閉じられ、 許可の名が操作と揃い、 取り込みと起動は席に戻らず、 足すものが最小な点で勝ります。 代わりに、 close-check を書いていない repo では形の外の閉じが通り、 古い器は新しい key を持つ設定を丸ごと読めないので key は器を入れ替えた後にしか書けず、 名指しの後始末は他の終わった便も畳め、 畳むだけの指定では PR の便を契約を開いたまま畳め、 止める書き方の規則に口ごとの指定の許可が 2 つ増え、 書き方から 1 語でも外れた 1 行は断られます。 持ち主の裁定と分析で選びました。

+ 利点

  • 宣言を読めて close-check を書いていない repo の席の閉じは 1 字も変わらない (DR1)
  • 本 repo は宣言の 1 行で門に入り、 閉じの形の外れを書く時点で止まる (DR2)
  • 読めない宣言は無いと読まず、 形の外れだけを断って形に合う閉じは通す (DR3)
  • 止まった終端の撃ち直しと PR の便の閉じを、 席が名指しの 1 行で撃てる (DR4)
  • 権能の名が操作と揃い、 断り文の名が操作を取り違えさせない (DR5)
  • 着地・起動・merge・一括の停止・道具の差し替えは席に戻らない (DR6)
  • 足すのは key 1 つ・権能 1 つ・rules 行の値の 1 語・断りの語 1 つと断り文の句 1 つ (DR7)

− 欠点

  • 宣言していない repo では、 和の外の close と席の着地の形の close がそのまま通る
  • key を知らない古い binary は key を持つ宣言を丸ごと読めないので、 入れ替えの前に key を書けない (着地と入れ替えの順を手順と列の保留で守る)
  • 名指しの退役は、 PR の便のほかに終端の他の便の worktree も可逆な move で畳め、 畳むだけの指定では PR の便を契約を開いたまま畳める
  • 名指しの形から 1 語でも外れた 1 行 (後ろの redirect や pipe) は merge か launch を要って断られる (断り文の句が通る形を示す)
  • 停止の窓の規則に、 口ごとの値なしの flag の許可 (撃ち直しの --terminal-only・退役の --fold-only) が 2 つ増える (DR7)
OPT2門を全部の repo に掛ける (今の FR81 の字のまま)不採用

器の plugin を積む全部の repo の席の close に、 宣言に依らず同じ門を掛ける。 決め手は実測と裁定 (消費側の席の閉じがほぼ全部断られる)。

設定に依らず、 器を積む全部の repo の席の閉じに同じ門を掛ける案です。 要件と前の記録の字を変えずに済み、 どの repo の閉じも同じ形に揃う点で勝ります。 けれども、 自分の PR で閉じる運用の別の repo では席の閉じがほぼ全部断られ、 その repo は閉じ方を変える時期を自分で選べません。 退けました。

+ 利点

  • FR81 と ADR-0089 の字を変えずに済む
  • どの repo の閉じも同じ文法に揃い、 局面の出力の読みが 1 通りになる

− 欠点

  • 自前の PR の merge で閉じる運用の消費側の repo では、 席の閉じがほぼ全部断られる (DR1)
  • 消費側は閉じ方を変えるまで台帳を閉じられず、 変える時期を自分で選べない (DR1)
OPT3消費側の閉じの形を決めるまで門を起こさない不採用

消費側の repo の閉じの形 (器の便でない着地の閉じ方) を持ち主に問い、 決まるまで close の段を実装しない。 決め手は裁定 (本 repo だけ先に掛ける)。

別の repo の閉じ方をどう揃えるかを持ち主に問い、 決まるまで門の閉じる段を作らない案です。 運用を決めてから 1 度で全部に掛けられ、 設定の key を足さずに済む点で勝ります。 けれども、 決まるまで本 repo の形の外れが書く時点で止まらず、 repo ごとに運用が違うので決める問いが長引きます。 退けました。

+ 利点

  • 消費側の運用を決めてから 1 度で全部の repo に掛けられる
  • 宣言の key を足さずに済む

− 欠点

  • 本 repo の閉じの形の外れが、 決まるまで書く時点で止まらない (DR2)
  • 消費側の repo ごとに運用が違い、 1 つの形に決める問いが長引く (DR2)
OPT4掛ける repo を rules 行か host の面で選ぶ不採用

器の rules 行か state dir ごとの host の面に、 門を掛ける repo の列か掛け外しの値を置く。 決め手は分析 (repo の名乗りを repo の外の面に置く)。

門を掛ける repo の一覧か掛け外しの値を、 器の規則の行か host ごとの設定に置く案です。 対象の repo の file を変えずに掛け外しでき、 1 か所で全部を見渡せる点で勝ります。 けれども、 repo の一覧を器の規則の行に置くと、 変えるたびに持ち主の裁定が要り、 公開の repo の器の規則の表に別の repo の名が載ります。 host の設定は repo の追跡される履歴に残らず review も通らず、 host ごとに食い違いえます。 退けました。

+ 利点

  • 対象 repo の file を 1 行も変えずに掛け外しできる
  • host の持ち主が 1 か所で全部を見渡せる

− 欠点

  • repo の列を rules 行に置くと、 列を変えるたびに裁定 id が要り (C5)、 PUBLIC の manifest に消費側の repo の名が載る (DR7)
  • host の面は tracked でなく PR の review を通らず、 host ごとに食い違いうる (DR1・N2)
OPT5宣言を読めない repo の close を全部断る不採用

宣言が在って読めない repo では、 理由の形に依らず close を全部、 読めない旨の語で断る。 決め手は分析 (加わっていない repo の形に合う閉じまで止める)。

設定 file が在って読めない repo では、 理由の形に依らず閉じを全部断る案です。 設定の不備が閉じの時点で必ず見え、 判定が 1 語で済む点で勝ります。 けれども、 加わる意思を名乗っていない repo でも設定の字の誤り 1 つで閉じが全部止まり、 形に合う閉じまで止めるのは読めないことの帰結として過大です。 退けました。

+ 利点

  • 宣言の不備が閉じの時点で必ず見える
  • 判定が 1 語で済む

− 欠点

  • 加わる意思を名乗っていない repo でも、 宣言の字の誤り 1 つで閉じが全部止まる (DR1・DR3)
  • 形に合う閉じまで止めるのは、 読めないことの帰結として過大である (DR3)
OPT6宣言を読めない repo を、 宣言の無い repo と同じに通す不採用

宣言が在って読めない repo では門を掛けない。 決め手は分析 (C10・C11.2)。

設定 file が在って読めない repo を、 設定の無い repo と同じに通す案です。 設定の不備で閉じが止まらず、 読めないと無いを分けずに済む点で勝ります。 けれども、 読めないを無いと読むことになり、 加わった repo が設定の字の誤り 1 つで黙って門の外へ出ます。 門は測れないときに止める側の向きなので、 その向きにも反します。 退けました。

+ 利点

  • 宣言の不備で閉じが止まることが無い
  • 読めないと無いを分けずに済む

− 欠点

  • 読めないを無いに倒し、 加わった repo が宣言の字の誤り 1 つで黙って門の外へ出る (DR3・C10)
  • 起票の門は閉じる側の極性で、 測れない周に通す向きを持ち込む (DR3・C11.2)
OPT7merge と launch を丸ごと席の行に渡す不採用

rules 行 role.orchestrator に merge と launch を足し、 席が land と retire を全部撃てるようにする。 決め手は分析 (着地と起動を席に戻す)。

取り込みの許可 (merge) と起動の許可 (launch) を丸ごと席の規則の行に足す案です。 許可の列も書き方の照合も足さずに済み、 閉じ待ちの便のほかの詰まりも席で解ける点で勝ります。 けれども、 取り込み・起動・再開・受付・一括の停止まで席に戻り、 起動と取り込みは器が行うという役割分担を崩します。 撃ち間違えたときの被害が大きい口を、 1 本の名指しなしに渡すことにもなります。 退けました。

+ 利点

  • 権能の列も guard の窓も足さずに済む
  • 止まった終端のほかの詰まりも席で解ける

− 欠点

  • 着地・起動・再開・受付・一括の停止まで席に戻り、 ADR-0045 §2 (1) の役割分担を崩す (DR6)
  • 誤射の被害の大きい口 (便を起こす・全部を止める) を名指しの窓なしに渡す (DR5・DR6)
OPT8名指しの 2 形を停止の権能 stop に載せる不採用

名指しの撃ち直しと退役を、 新しい名を足さずに stop へ結ぶ。 決め手は分析 (断り文の権能の名が操作と食い違う)。

名指しの 2 つの形を、 新しい名を足さずに止める許可 stop に結ぶ案です。 許可の列と規則の行の値を変えずに済み、 行は既に stop を持つので値の裁定が要らない点で勝ります。 けれども、 断り文と記録の「stop」が止める操作でなく閉じる操作を指すので、 読み手が操作を取り違えます。 規則の行の値を変える裁定を通らずに、 止めるだけとして席に戻した stop の範囲が閉じる操作まで黙って広がることにもなります。 退けました。

+ 利点

  • 権能の列と rules 行の値を変えずに済む
  • 席の行は既に stop を持つので、 行の値の裁定が要らない

− 欠点

  • 断り文と記録の「(stop)」が、 止める操作でなく閉じる操作を名指し、 読み手が操作を取り違える (DR5)
  • stop を持つ行 (ADR-0048 が止めるだけとして席に戻した射程) が、 行の値の変更 (C5 の裁定 id) を通らずに閉じる操作まで黙って広がる (DR5)
OPT9撃ち直しと退役を別々の新しい権能にする不採用

終端の撃ち直しと退役に、 それぞれ別の権能の名を足す。 決め手は分析 (2 つは同じ向きの操作で、 席の行に並ぶのは常に対)。

終わりだけの撃ち直しと後始末に、 別々の新しい許可の名を足す案です。 片方だけを席から外すことが規則の行ででき、 断り文が口ごとに違う名を指せる点で勝ります。 けれども、 2 つは「閉じ待ちの便の終わりを閉じる」同じ向きの操作で、 行には常に対で並ぶので名が 1 つ増えるだけです。 許可の列と読み手と断り文への波及も 2 倍になります。 退けました。

+ 利点

  • 片方だけを席から外す値の変更が行でできる
  • 断り文が口ごとに違う名を名指す

− 欠点

  • 2 形は「止まった便の終わりを閉じる」同じ向きの操作で、 行の値は常に対で並び、 名が 1 つ増えるだけになる (DR7)
  • 権能の列と loader と断り文の面への波及が 2 倍になる (DR7)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 門の閉じる段は、 台帳の repo の設定 file が close-check を true で持つ repo でだけ掛かり、 読めない設定の repo には同じ判定を掛けて形に合う閉じは通します。 許可の列に settle を足し、 終わりだけの撃ち直しと後始末を便 1 本を名指す書き方に限って結びます。 FR81 (起票の門)・FR30 (便を運ぶ仕組み)・FR41 (許可の置き場)・FR45 (許可の執行)・FR50 (取り込みの終わり)・FR96 (PR の便の閉じ) への主張で、 FR91 (閉じる理由の形) の断りの射程の読みと、 NFR5 (hook の時間の予算) を退行させない読みを添えます。

採用 — OPT1

起票の門の close の段 (SRS FR81 (d)・設計 ledger-form.md §16) SHALL、 台帳の repo (payload の cwd から上へ辿った最初の .beads の dir を持つ dir) の HEAD の vessel 宣言が任意 key close-check を true で持つ repo でだけ掛かる。 key が無い・false・宣言 file が HEAD に無い・git を撃てない repo と、 .beads の dir を持つ祖先が無い周は掛けない。 宣言が在って読めない repo SHALL 同じ判定を掛け、 断る周は理由の語 close-declaration-unreadable で当たった形を名指し、 形に合う閉じは通す。 close-check の値は真偽だけで、 他の値は key と行番号を名指す宣言の不備とする。 宣言の読みは HEAD の tree の 1 本で、 門は台帳を読まない。 repo SHALL key の読み手を持つ binary に入れ替えた後でだけ宣言に key を書く (古い読み手は未知の key を宣言ごと断る)。 本 repo は §16 の行の着地と入れ替えの後に key を書く。 器 SHALL 権能の閉じた列に決着の権能 settle を足し (宣言順は stop の直後)、 rules 行 role.orchestrator の値に settle を足す (裁定 user 2026-09-29T21:53Z)。 権能 guard SHALL、 pipe land の窓が --terminal-only をちょうど 1 回と、 --run・--state-dir・--repo の値の対だけから成り --run がちょうど 1 回の呼び出しと、 pipe retire の窓が同じ 3 つの flag の値の対と値なしの --fold-only (0 か 1 回) だけから成り --run がちょうど 1 回の呼び出しを settle に結ぶ。 値は - で始まらず shell の字を含まない (ADR-0048 の窓と同じ規則)。 settle の窓の --state-dir の値は hook が解いた置き場と、 --repo の値は hook が解いた anchor と、 payload の cwd から絶対にした字で同じ周だけを許し、 --rules は許さない (置き場か repo か規則を差し替えた呼び出しは、 偽の置き場の記録から任意の bead を着地の形で閉じうる)。 停止の窓は台帳を書かないので ADR-0048 のまま。 退役の窓に値なしの --fold-only を許すのは裁定の字の外の設計の追加で、 照合の道が unmeasured になる PR の便の出口として足す。 窓がそれ以外の呼び出しは今どおり land は merge、 retire は launch を要る。 窓が名指しでない呼び出しの断り文は、 通る名指しの形を 1 句で添える。 2 つの口の本体・終端の経路・畳み・close の字は変えない。 実装は設計 ledger-form.md §16 (契約表の行 l・l1・l2・l3) と seat-roles.md §32 (行 z)。

器の門のうち bead を閉じる理由を確かめる段は、 台帳の repo (いまの作業場所から上へ辿って最初に .beads の dir を持つ dir) の、 commit 済みの最新 (HEAD) の設定 file (vessel 宣言) が close-check = true を持つ repo でだけ掛かります。 key が無い・false・設定 file が無い・git を撃てない repo と、 .beads の dir が見つからない周には掛けません。 設定 file が在って読めない repo には同じ判定を掛け、 断るときは「設定を読めない」の語 (close-declaration-unreadable) で当たった形を名指し、 形に合う閉じは通します。 close-check の値は true か false だけで、 他の値は設定の不備です。 門は台帳を読まず、 設定 file を 1 回読むだけです。 key は、 それを知る器の binary に入れ替えた後でだけ設定 file に書きます。 本 repo は、 設定の読み手を持つ行を取り込んで器を入れ替えた後に、 最後の行で書きます。 また器は、 許可の列に決着の許可 settle を足し (止める許可 stop の直後)、 席の規則の行 role.orchestrator に settle を足します。 席は、 pipe land を --terminal-only つきで便 1 本を名指す書き方 (--run と置き場・repo の値の対だけ・--run はちょうど 1 回・置き場と repo は器の門が解いた値と同じものだけで、 規則の差し替えは持たない) で撃つときと、 pipe retire を同じ名指しの書き方 (畳むだけの指定 --fold-only を 1 つ足してもよい) で撃つときに、 settle の許可で通ります。 --fold-only を許すのは裁定の字の外の設計の追加で、 照合できない PR の便の出口として足します。 値は - で始まらず、 shell が意味を変える字を含みません。 それ以外の書き方は今どおり取り込みの許可か起動の許可を要り、 断り文は通る書き方を 1 句で添えます。 2 つの口の中身は変えません。 門を設定 file の key で掛けるのは、 設定 file が repo の追跡される履歴に残り PR の review を通る名乗りの場所で、 repo ごとに加わる時期を選べるからです。 器の規則の行に repo の一覧を置くと変えるたびに裁定が要り別の repo の名が公開の表に載り、 host の設定は review を通りません。 読めない設定を加わったと読むのは、 門が測れないときに止める側の向きで、 読めないを無いと読むと、 加わった repo が字の誤り 1 つで黙って門の外へ出るからです。 ただし git を撃てない周は設定の無い周と同じに読みます。 設定の読み手は 1 本で 2 つを分けず、 前の記録の読み口と同じだからです。 それでも形に合う閉じまでは止めないのは、 加わる意思を名乗っていない repo の閉じを全部止めるのは過大だからです。 key を入れ替えの後にしか書かないのは、 古い器が知らない key を持つ設定を丸ごと断り、 便の受付と取り込みの終わりが止まるからです。 閉じ待ちの便の 2 つの口を新しい許可で渡すのは、 門が入ると席は着地の形で閉じられず、 持ち主の裁定がその 2 つを名指しの形に限って席へ渡すと決めたからです (裁定 user 2026-09-29T21:53Z)。 畳むだけの指定を名指しの後始末に許すのは裁定の字の外の設計の追加で、 照合できない PR の便の出口として足します。 止める許可に載せないのは、 断り文の名が操作と食い違い、 裁定を通らずに stop の範囲が広がるからで、 取り込みと起動の許可を丸ごと渡さないのは、 撃ち間違えの被害が大きい口まで席に戻るからです。 名指しの書き方は止める許可と同じ値の対と字の規則を使い、 口ごとに要る値なしの指定だけを足します。

FR81claimFR81 (起票の門の断り) の (d) の射程の側。 本 ADR は、 門の close の段を、 台帳の repo の HEAD の vessel 宣言が任意 key close-check を true で持つ repo と、 宣言が在って読めない repo に限ると主張する。 (a)〜(c) の断りは変えず、 (d) の告げる中身に、 宣言を読めない旨の語 close-declaration-unreadable と当たった形を足す。 FR81 の字 (器の plugin を積む席の session の全部) は land の後も残り、 射程を宣言した repo に直すのは持ち主の SRS の改訂の回 (同じ束の改訂の依頼文) である。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 5 つと、 代わりに引き受けること 10 こです。 良くなるのは、 close-check を書いていない repo の閉じ方が変わらないこと、 本 repo の形の外れが書く時点で止まること、 照合できる閉じ待ちの便を席が 1 行で閉じられること、 取り込みと起動と一括の操作は席に戻らないこと、 足すものが最小なことです。 引き受けるのは、 close-check を書いていない repo では形の外の閉じと席の着地の形の閉じが通り、 memo の自動の閉じがそれも着地と読むこと、 古い器は新しい key を持つ設定を読めないこと、 git を撃てない周は門を掛けないこと、 読めない設定の repo では形の外の閉じが断られること、 後始末で他の終わった便や照合できない PR の便も契約を開いたまま畳めること、 撃ち直しが設定の remote へ push しうること、 名指しから外れた 1 行は断られること、 許可が host の全部の席に届くこと、 検出だけの指定と、 道具・規則・別の置き場や repo を差し替えた書き方は持ち主の手のままなこと、 key を書く前の commit を持つ作業場所の閉じには門が掛からないことです。

✓ 良い結果

  • ●宣言を読めて close-check を書いていない repo の席の閉じ方は 1 字も変わらず、 消費側は自分の PR で宣言に 1 行を足して加わる時期を選べる
  • ●本 repo は宣言の 1 行で門に入り、 理由の無い閉じ・形の外の閉じ・席の着地の形の閉じが書く時点で止まる
  • ●止まった終端 (CI の撃ち直しの後・forge の上限の後・PR の merge の後) を、 席が名指しの 1 行で閉じられ、 持ち主の手を要らない (照合できる便に限る。 照合できない PR の便は畳めても契約は開いたまま残る)

  • ●宣言の git を撃てない周は宣言が無いと同じに読み、 門を掛けない。 宣言の読み手は 1 本で git を撃てない周と宣言 file の無い周を分けず (ADR-0084 の question-route と同じ読み)、 加わった repo でも git が落ちた 1 回は門の外になる
