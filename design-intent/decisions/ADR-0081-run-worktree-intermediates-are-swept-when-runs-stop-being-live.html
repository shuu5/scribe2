設計判断記録 (ADR) scribe2 — 便の worktree の掃除

便の worktree の中間生成物 (git が無視する file) は、 便が live でなくなった周に器が消す — 木と toolchain から作り直せるので憲法 N1 の「戻せない削除」に当たらない

器は便ごとに worktree を切り、 着地した便の worktree を退役の置き場へ可逆に move するが、 build の中間生成物を消す手を持たず、 host の disk が尽きて便が落ちた。 本 ADR は便の終端の周ごとに、 live でない便の worktree で git が無視する file だけを消すと決め、 それが N1 の戻せない削除に当たらないと読む。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して着地させる 1 往復、 「worktree」は便ごとに git が切る別の作業 dir です。 器は着地した便の worktree を消さずに退役の置き場へ移しますが、 中の build の産物 (Rust の target/ など) を消す手を持たず、 2026-09-28 に host の disk が尽きて 3 つの project の便が落ちました。 本 ADR は、 便の終端の周ごとに、 まだ終わっていない便を除いた各便の worktree で、 git が無視する file だけを消すと決めます。 それらは commit した木と道具から作り直せるので、 憲法 N1 の「戻せない削除」には当たらないと読みます。 席の手が撃つ git clean -f を断る門はそのまま残します (要件 NFR6・FR56・FR68・FR77 に結びます)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (worktree は可逆に移すが中の産物を消す手が無い)・事象 (disk が尽きて便が落ちた)・機序 (何を消してよいかは無視の規則が既に宣言し、 便の生死は器が既に測る)・憲法の向き・射程・既存の門 (席の手の git clean -f は断られ続ける) の 6 つで示します。

CTX1

経緯 — 器は便ごとに worktree便ごとの作業場所 を切り、 着地した便の worktree を可逆に move するが、 中間生成物作り直せる途中の産物を消す手は無い

器は便 1 本ごとに対象 repo の .worktrees/<NAME>/<run> に git の worktree を切り (FR4)、 着地した便や畳んだ便の worktree は .worktrees/<NAME>/retired/<run> へ git worktree move で寄せる (N1.2 の可逆な move)。 move は中身ごと運ぶので、 build の中間生成物 (Rust の target/ など) は退役戻せる形で外すことした worktree に残り続け、 それを消す手は器にも手順にも無い。 同時に走る便は rules 行 pipe.max_live で最大 16 本 (ADR-0035)。 ADR-0038 は退役の worktree が 174 GB に達していたことを却下案の利点として記したが、 消す手は決めなかった。

CTX2

事象 — 2026-09-28、 host の disk が尽き、 3 つの project の便が落ちた

2026-09-28、 host の root の filesystem (1.8 TB) の空きがほぼ 0 になった。 非公開の隣の project では便の worktree 140 本が 597 GB を持ち、 うち 540 GB は退役した 117 本の build dir だった。 本 repo の worktree も 80 GB を持っていた。 3 つの project の便が ENOSPCdisk の空き切れ で落ち、 本 repo の便 s2-07l.731 は test が一時 dir を作れなかっただけで Gated FAIL になった (契約の赤ではない)。 持ち主は退役した worktree の中の build dir を手で消すことを承認し (裁定 user 2026-09-28T04:45Z)、 続けて器で直すことを最優先に指示した (裁定 user 2026-09-28T04:46Z)。

CTX3

機序 — 何が中間生成物かは無視の規則git が見ない物の宣言が既に宣言し、 便の生死は器が既に 1 関数で測る

各 project の無視の規則 (.gitignore) は、 どの file が commit しない生成物かを既に宣言している (Rust の target/・node_modules/・.venv/ など)。 git clean -d -X は無視された file と dir だけを消し、 tracked の file と無視されない untracked の file には触れず、 -f が 1 つなら入れ子の git repo も残す (中身の在る repo は飛ばし、 空の .git の dir しか持たない dir は repo と見なされず消える・orchestrator が dry run で確かめた)。 器は便が live か (終端でないか) を、 段と判定と運転手の札から 1 関数で測り、 判定や札を読めない便は「測れない」と返す。

CTX4

憲法の向き (本 ADR の解釈)

N1 は器の管理する物を戻せない形で消す操作を断れと言い、 N1.2 は退役を可逆な move に限る。 本 ADR は、 無視される file は commit した木と toolchain から build や test の実行で作り直せるので、 それを消すのは戻せない削除に当たらないと読む。 便の情報 (branch の commit・木・state dir の log と判定) は残り、 退役そのものは move のまま。 A1 と A4.2 (消す操作・不可逆な操作の前に user に聞く) には同じ読みを当て、 掃除の 1 手を器に持たせること自体は裁定 user 2026-09-28T04:46Z が指示した。 C17.2 に沿い、 足す 1 手が消すものは、 満杯のたびに人が撃つ手の掃除である。 C2 (同じ事実の読みは 1 本) から、 生死は既存の 1 関数で測り、 中間生成物の宣言は無視の規則 1 つに置く。

CTX5

射程 — 動かすのは便の終端の周便が止まった直後の 1 周の 1 手だけ

動かすのは、 便の終端の周 (pipe の run・resume・land・stop・retire が段を記帳した後) に、 live でない便の worktree で無視された file を消す 1 手を足すことだけである。 動かさないのは、 退役の move・worktree と branch の置き場・tracked の file と commit・無視されない untracked の file・stdout と event の形・rules 行 (host_guard.git を含む)・要件書である。 設計 dispatcher.md §30 (契約表の行 ae) が実装する。

CTX6

既存の門 — host-guardsession の手の門 は session の手が撃つ git clean -f を断り、 今後も断る

rules 行 host_guard.git は禁じる語列に git clean -f を持ち、 session と runner の Bash が撃つ git clean -f を実行の前に断る (口座の設定を読む session には host-guard、 席と runner には器の plugin の command guard も同じ語列で掛かる・FR56・ADR-0025・ADR-0056・N1・C16)。 席の手は消す対象を絞れず、 素の -f は無視されない untracked の仕事も消し、 それは戻せない。 器の掃除は別の狭い操作である — -X で無視された file だけを消し、 live でないと測れた便の worktree だけで、 器自身の子 process だけが撃つ。 ゆえに rules 行は変えず、 session への断りも緩めない。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 disk を器が自分で取り戻すこと。 便の情報を失わないこと。 言語に依らないこと。 足すものを最小にすること。 並列の便を遅くしないこと。 席の手に掛かる門を緩めないこと。

DR1disk を器が自分で取り戻す — 満杯を人の気付きに頼らず、 便を ENOSPC で落とさない CTX1・CTX2
DR2便の情報を失わない — 退役は可逆な move のまま、 作り直せない物は消さない (N1・N1.2) CTX3・CTX4
DR3言語に依らない — 何が中間生成物かを器が言語ごとに決めない CTX3
DR4足すものを最小にする — 口・rules 行・跨版の key を足さず、 既に在る宣言と判定を使う (C2・C17) CTX3・CTX4
DR5並列の便を遅くしない — 最大 16 本の便が互いの build を待たない CTX1
DR6session の手の門を緩めない — host-guard が git clean -f を断る行はそのまま (N1・C16) CTX6
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。 終わった便の worktree で git が無視する file を消す案 (選んだ案)、 今のまま人が手で消す案、 build の出力先を repo ごとに 1 つ共有する案、 退役した worktree を丸ごと消す案、 disk の空きが少ないと便の起動を断る門の案、 消してよい dir を宣言 file に書かせる案です。

OPT1便の終端の周ごとに、 live でない便の worktree で git clean -d -X -f を撃つ採用

便の終端の周 (pipe の run・resume・land・stop・retire が段を記帳した後) ごとに、 state dir の便のうち live でないと測れた便の worktree (元の場所か退役の置き場のうち在る方) で git clean -d -X -f を撃つ。 消すのは無視の規則が無視と宣言する file だけで、 生死を測れない便は飛ばす。 決め手は裁定 user 2026-09-28T04:46Z (器で直す) と分析。

便が 1 本止まるたびに撃たれる器の 1 周で、 もう終わった便の worktree ごとに、 git が無視すると宣言された file と dir だけを消す案です。 何を消してよいかは各 project の無視の規則が決めるので、 Rust の target/ も node_modules/ も .venv/ も同じ手で消え、 tracked の file と commit には触れず、 生死を測れない便は飛ばします。 何度撃っても同じ結果になるので、 最初の周で既に溜まった分も取り戻し、 退役は可逆な移動のまま残ります。 代わりに、 落ちた便を regate したり後で調べたりするときは build を 0 からやり直す時間が掛かり、 無視の規則に書かれない dir や入れ子の repo は残り、 周ごとに小さな費用が掛かることを引き受けます。 掃除は器自身の子 process だけが撃つ狭い操作なので、 席の手の git clean -f を断る門 (rules 行 host_guard.git) は変えません。

+ 利点

  • disk を実際に取り戻す — 非公開の隣の project では退役した 117 本の build dir だけで 540 GB だった (DR1)
  • 冪等で、 着地後の最初の周が既に溜まった worktree の分も取り戻す (DR1)
  • 退役は可逆な move のまま、 branch の commit・木・state dir の記録は残る (DR2)
  • 何が中間生成物かは project の無視の規則が決め、 Rust の target/ も node_modules/ も .venv/ も同じ 1 手で消える (DR3)
  • 口・rules 行・跨版の key を足さず、 既存の生死の判定を使う (DR4)
  • 便ごとの worktree は分かれたままで、 並列の便は互いの build を待たない (DR5)
  • 掃除は器自身の子 process だけが撃つ狭い操作で、 rules 行 host_guard.git は変えず、 session と runner の git clean -f は今どおり断られる (DR6)

− 欠点

  • Gated FAIL の便を regate すると build を 0 からやり直す (数分かかるが正しさは変わらない)
  • 落ちた便の worktree を後で調べるには build し直しが要る
  • build dir を無視の規則に書かない project では何も取り戻せない
  • 無視される dir の下の入れ子の git repo (test の fixture など) は残り、 その分は取り戻せない
  • 便の終端の周ごとに数十本の worktree へ git clean を撃つ小さな固定の費用が掛かる
OPT2今のまま — disk が満ちたら人が手で消す不採用

器には消す手を足さず、 disk が満ちたら持ち主や席が手で build dir を消す。 決め手は分析 (満杯まで誰も気付かず便が落ちる)。

器には何も足さず、 disk が満ちたら持ち主や席が手で build の産物を消す案です。 器に消す手を足さないので憲法 N1 の読みを決めずに済み、 何を消すかを人が毎回見て決められる点で勝ります。 けれども、 満杯になるまで誰も気付かず 3 つの project の便が落ち、 手の掃除は文章にしか無い手順で満杯のたびに繰り返し、 席の手の git clean -f は門が断るうえ、 断りを緩めれば無視されない仕事まで消せる手を席に渡すことになるので退けました。

+ 利点

  • 器に消す手を足さないので、 N1 の読みを決める必要が無い
  • 何を消すかを人が毎回見て決められる

− 欠点

  • 満杯になるまで誰も気付かず、 3 つの project の便が ENOSPC で落ちた (DR1)
  • 手の掃除の手順は散文にしか無く、 満杯のたびに繰り返す (DR1・N2)
  • 席の手の git clean -f は host-guard が断り、 断りを緩めると無視されない untracked の仕事まで消せる手を session に渡す (DR6)
OPT3repo ごとに便を跨いで build dir を 1 つ共有する不採用

便ごとの worktree の build の出力先を repo ごとに 1 つの dir へ向ける (cargo の target dir の指定など)。 決め手は分析 (言語に依り、 並列の便が直列になる)。

便ごとの build の出力先を、 repo ごとに 1 つの dir へ向けて共有する案です。 build を使い回せるので disk も時間も大きく減り、 産物が 1 か所にまとまる点で勝ります。 けれども、 出力先の指定は言語ごとに違い (cargo の指定は Rust 専用)、 cargo はその dir に鍵を掛けるので最大 16 本の並列の便の build が 1 本ずつになり、 test の一時 dir などは各 worktree に溜まり続けるので退けました。

+ 利点

  • build の再利用で disk も build の時間も大きく減る
  • 中間生成物が 1 か所にまとまり、 量を測りやすい

− 欠点

  • 出力先の指定は言語ごとに違い (cargo の target dir は Rust 専用)、 器が言語ごとの手を持つことになる (DR3)
  • cargo は build dir に lock を取るので、 最大 16 本の並列の便の build が直列になる (DR5)
  • test の一時 dir などは各 worktree に溜まり続ける (DR1)
OPT4退役した worktree を git worktree remove で丸ごと消す不採用

着地や畳みの後、 退役の置き場へ move する代わりに (または move の後で) worktree を丸ごと消す。 決め手は分析 (N1.2 の可逆な退役を破る)。

着地や畳みの後、 退役した worktree を git worktree remove で丸ごと消す案です。 取り戻す量が最大で、 実装も 1 手で単純な点で勝ります。 けれども、 退役を可逆な移動に限る憲法 N1.2 を破り、 後で調べるための便の木も失うので退けました。

+ 利点

  • 取り戻す量が最大になる (中間生成物に加えて木も消える)
  • 実装が 1 手で単純

− 欠点

  • 退役を可逆な move に限る N1.2 を破る (DR2)
  • 後で調べるための便の木を失う (DR2)
OPT5disk の空きが閾値を下回ったら便の起動を断る門不採用

受付で disk の空きを測り、 閾値を下回る周は便を起こさない。 決め手は分析 (何も取り戻さない・閾値は新しい rules 行で user 裁定が要る)。 後続の候補として残す。

便を起こす前に disk の空きを測り、 閾値を下回る周は起こさない門の案です。 便が次々落ちる連鎖を防ぎ、 何も消さないので憲法 N1 の読みが要らない点で勝ります。 けれども、 それだけでは空きを 1 byte も取り戻さず、 閾値は新しい rules 行の値として持ち主の裁定が要るので、 この判断では退け、 後続の候補として残します。

+ 利点

  • ENOSPC で便が次々落ちる連鎖を防ぐ
  • 何も消さないので N1 の読みが要らない

− 欠点

  • 何も取り戻さず、 空きを作るのは人の手の掃除のまま (DR1)
  • 閾値は新しい rules 行の値で、 user 裁定が要る (C5・DR4)
OPT6project ごとに .vessel.toml で生成物の dir を宣言する不採用

器の宣言 file .vessel.toml に消してよい dir の列を足し、 器はその dir だけを消す。 決め手は分析 (跨版の新しい key・無視の規則と二重)。

器の宣言 file .vessel.toml に、 消してよい dir の列を project ごとに書かせる案です。 消す dir を器がはっきり知り、 無視の規則に無い dir も対象にでき、 何を消すかが宣言として読める点で勝ります。 けれども、 版を跨ぐ新しい key になり全ての導入先が書くまで取り戻せず、 無視の規則が既に同じことを宣言しているので同じ事実の宣言が 2 つになるため退けました。

+ 利点

  • 消す dir を器が明示に知り、 無視の規則に無い dir も対象にできる
  • 何を消すかが宣言として読める

− 欠点

  • 跨版の新しい key になり、 全ての消費側が宣言を書くまで取り戻せない (DR4)
  • 無視の規則が既に同じことを宣言しており、 同じ事実の宣言が 2 つになる (C2・DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 便の終端の周ごとに、 まだ終わっていない便と生死を測れない便を除いた便の worktree で、 git が無視する file と dir だけを消します。 退役は可逆な移動のままで、 席の手の git clean -f を断る門も変えません。

採用 — OPT1

器 SHALL 便の終端の周 (pipe の run・resume・land・stop・retire が段を記帳した後) ごとに、 state dir の各便の生死を既存の 1 関数で測り、 live でないと測れた便の worktree (元の場所か退役の置き場のうち在る方) で git clean -d -X -f を撃つ。 -f は 1 つだけとし、 入れ子の git repo は残す。 消すのは対象 project の無視の規則が無視と宣言する file と dir (中間生成物) だけで、 器 SHALL tracked の file・commit・無視されない untracked の file に触れない。 生死を測れない便 SHALL 飛ばす (残す側へ倒す)。 掃除は冪等で、 着地後の最初の周が既に溜まった worktree の分も取り戻す。 退役 SHALL 今どおり可逆な move のままとし、 worktree そのものは消さない。 何かを消した周だけ stderr に 1 行を出し、 stdout と event の形は変えない。 本 ADR は憲法 N1 を、 無視される file は commit した木と toolchain から作り直せるので、 それを消すのは戻せない削除に当たらない (便の情報〔branch の commit・木・state dir の log と判定〕は残る) と読む。 掃除は器自身の子 process だけが撃ち、 rules 行 host_guard.git (session と runner が撃つ git clean -f の断り) SHALL 変えず、 session への断りを緩めない。 口・rules 行・跨版の key・要件書は変えない。 実装は設計 dispatcher.md §30 (契約表の行 ae)。
