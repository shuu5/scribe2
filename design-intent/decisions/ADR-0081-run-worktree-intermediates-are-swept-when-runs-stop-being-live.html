設計判断記録 (ADR) scribe2 — 便の worktree の掃除

便の worktree の build と依存の置き場を、 便が live でなくなった周に器が消す — 名が閉じた列に在り追跡されている file を持たない dir だけを消し、 作り直せるので憲法 N1 の「戻せない削除」に当たらない

器は便ごとに worktree を切り、 着地や畳みの後の worktree を退役の置き場へ可逆に move するが、 build と依存の置き場を消す手を持たず、 host の disk が尽きて便が落ちた。 本 ADR は運転手の終端の周ごとに、 live でないと測れた便の木から、 名が閉じた 8 つの列に在り追跡されている file を持たない dir だけを消すと決める。 無視の規則は読まず、 git clean も撃たない。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して着地させる 1 往復、 「worktree」は便ごとに git が切る別の作業 dir です。 器は着地や畳みの後の worktree を消さずに退役の置き場へ移しますが、 中の build の産物と依存の取り込み (Rust の target など) を消す手を持たず、 2026-09-28 に host の disk が尽きて 3 つの project の便が落ちました。 本 ADR は、 運転手の終端の周ごとに、 終わったと測れた便の worktree だけで (生死を測れない便は残して)、 名が閉じた 8 つの列に在り追跡されている file を持たない dir だけを消すと決めます。 無視の規則は読まず git clean も撃たないので、 鍵や local の設定のような作り直せない file は消えません。 消す dir は作り直せるので憲法 N1 の戻せない削除に当たらないと読み、 消す操作の承認 (A1) は裁定 user 2026-09-28T04:46Z をこの種類への常設の承認と読みます。 席と runner の手が撃つ git clean -f を断る門はそのまま残します (要件 FR68・FR30 に結び、 NFR6・FR56・FR77 を壊さないことを示します)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (worktree は可逆に移すが中の置き場を消す手が無い)・事象 (disk が尽きて便が落ちた)・機序 (無視の規則は「作り直せる」の宣言ではなく、 作り直せる置き場は名で分かる)・憲法の向き (N1・A4.2 と A1 を分けて読む)・射程・既存の門 (席の手の git clean -f は断られ続ける) の 6 つで示します。

CTX1

経緯 — 器scribe2 の本体は便ごとに worktree便ごとの作業場所 を切り、 着地や畳みの後は可逆に move するが、 build と依存の置き場を消す手は無い

器は便 1 本ごとに対象 repo の .worktrees/<NAME>/<run> に git の worktree を切り (FR4)、 着地した便や畳んだ便の worktree は .worktrees/<NAME>/retired/<run> へ git worktree move で寄せる (N1.2 の可逆な move)。 move は中身ごと運ぶので、 build の産物と依存の取り込み (Rust の target など) は退役戻せる形で外すことした worktree に残り続け、 それを消す手は器にも手順にも無い。 同時に走る便は rules 行 pipe.max_liveまだ終わっていない で最大 16 本 (ADR-0035)。 ADR-0038 は退役の worktree が 174 GB に達していたことを却下案の利点として記したが、 消す手は決めなかった。

CTX2

事象 — 2026-09-28、 host の disk が尽き、 3 つの project の便が落ちた

2026-09-28、 host の root の filesystem (1.8 TB) の空きがほぼ 0 になった。 非公開の隣の project では便の worktree 140 本が 597 GB を持ち、 うち 540 GB は退役した 117 本の build の置き場で、 退役していない 23 本も 58 GB を持っていた。 本 repo の worktree も 80 GB を持っていた。 3 つの project の便が ENOSPCdisk の空き切れ で落ち、 本 repo の便 s2-07l.731 は test が一時 dir を作れなかっただけで Gated FAIL になった (契約の赤ではない)。 持ち主の承認 (裁定 user 2026-09-28T04:45Z) で退役した worktree の build の置き場を手で消すと、 空きは 401 GB に戻った。 続けて持ち主は、 掃除しながら進める器の直しを最優先で入れるよう指示した (裁定 user 2026-09-28T04:46Z)。

CTX3

機序 — 無視の規則git が見ない物の宣言は「作り直せる」の宣言ではない。 作り直せる置き場は名で分かる

無視の規則 (.gitignore) が宣言するのは「commit しない」で、 「作り直せる」ではない。 本 repo の .gitignore も鍵 (.beads-credential-key)・手書きの local の script (*.local.sh)・session の作業記憶 (/.claude-session/)・local の設定 (.claude/*) を無視する。 さらに git clean -X は project の .gitignore に加えて repo の info/exclude と host の個人設定の除外も読むので、 消す集合が host ごとに変わる (orchestrator と review が scratch の repo で実測)。 一方、 器が対応する言語 (Rust、 TypeScript、 Python、 React Native + Expo) の build と依存の置き場は名が決まっていて、 commit した木と toolchain と lock file から作り直せる。 器は便が live か (終端でないか) を段と判定と運転手の札から 1 関数で測り、 判定や札を読めない便は「測れない」と返す。 置き場 (state dir) ごとの lock は既存の 1 実装 (acquire_with) が在る。

CTX4

憲法の向き (本 ADR の解釈)

N1 は器の管理する物を戻せない形で消す操作を断れと言い、 A4.2 は不可逆な操作の前に user に聞けと言う。 本 ADR が消すのは閉じた列器が消す dir の名の build と依存の置き場だけで、 commit した木と toolchain と lock file から作り直せるので、 N1 の戻せない削除にも A4.2 の不可逆にも当たらないと読む。 便の情報 (branch の commit・木・追跡されている file・state dir の log と判定) は残り、 退役は N1.2 の可逆な move のまま。 A1 は戻せるかどうかを問わず「消す」という種類に掛かる。 本 ADR は、 裁定 user 2026-09-28T04:46Z (逐語は RulingReceived の event) を、 まさにこの狭めた種類 — 閉じた列の dir を、 live でない便の worktree から、 終端の周ごとに消すこと — への A1 の常設の承認と読む。 その前の裁定 user 2026-09-28T04:45Z は手で 1 回消すことの承認で、 器の掃除の承認ではない。 C17.2 に沿い、 足す 1 手が消すものは、 満杯のたびに人が撃つ手の掃除である。 C2 から、 生死は既存の 1 関数で測る。

CTX5

射程 — 動かすのは運転手の終端の周運転手の一区切りの後の 1 手だけ

動かすのは、 運転手の終端の周 (pipe の run・resume・land・stop・retire が段を記帳した後・列の 1 周の前) に、 live でない便の木から閉じた列の dir を消す 1 手を足すことだけである。 動かさないのは、 退役の move・worktree の clean の判定・live の判定・列の判定と起こす契機・worktree と branch の置き場・追跡されている file と commit・stdout と event と rc・rules 行 (host_guard.git を含む)・event の kind・要件書である。 設計 dispatcher.md §30 (契約表の行 ae) が実装する。

CTX6

既存の門 — host-guardsession の手の門 は session の手が撃つ git clean -f を断り、 今後も断る

rules 行 host_guard.git は禁じる語列に git clean -f を持ち、 session と runner の Bash が撃つ git clean -f を実行の前に断る (口座の設定を読む session には host-guard、 席と runner には器の plugin の command guard も同じ語列で掛かる・FR56・ADR-0025・ADR-0056・N1・C16)。 席の手は消す対象を絞れず、 素の -f は無視されない untracked の仕事も消し、 それは戻せない。 器の掃除は git clean を撃たない別の狭い操作で、 閉じた列の dir だけを、 live でないと測れた便の木だけで、 運転手の process の中だけで消す。 ゆえに rules 行は変えず、 session への断りも緩めない。 v2 までの草稿の git clean -X が host の個人設定の除外を読む問題は、 除外を読まない本 ADR の形では起きない。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 7 本のものさしです。 disk を器が自分で取り戻すこと。 作り直せない物を消さないこと。 器が対応する言語の全部に 1 つの仕組みで効くこと。 足すものを最小にすること。 並列の便を遅くしないこと。 席の手に掛かる門を緩めないこと。 消す操作を承認の範囲に閉じること。

DR1disk を器が自分で取り戻す — 満杯を人の気付きに頼らず、 便を ENOSPC で落とさない CTX1・CTX2
DR2作り直せない物を消さない — 消すのは作り直せると分かっている置き場だけ、 退役は可逆な move のまま (N1・N1.2・A4.2) CTX3・CTX4
DR3器が対応する言語の全部に 1 つの仕組みで効く — 言語ごとの設定や build の手順を器が持たない CTX3
DR4足すものを最小にする — 口・rules 行・跨版の key を足さず、 既存の生死の判定と lock を使う (C2・C17) CTX3・CTX4
DR5並列の便を遅くしない — 最大 16 本の便が互いの build を待たない CTX1
DR6session の手の門を緩めない — host-guard が git clean -f を断る行はそのまま (N1・C16) CTX6
DR7消す操作は承認の範囲に閉じる — A1 の常設の承認が名指す種類の外を消さない (A1) CTX2・CTX4
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 8 つ並べます。 名が閉じた列の dir を終わった便の木から消す案 (選んだ案)、 今のまま人が手で消す案、 git clean で無視された file を全部消す案、 退役した worktree だけを掃除する案、 build の出力先を repo ごとに 1 つ共有する案、 退役した worktree を丸ごと消す案、 disk の空きが少ないと便の起動を断る門の案、 消してよい dir を宣言 file に書かせる案です。

OPT1名が閉じた列に在り追跡されている file を持たない dir を、 live でない便の木から消す採用

運転手の終端の周ごとに、 置き場の全便のうち live でないと測れた便の木 (元の場所か退役先の在る方) を .git に降りずに歩き、 名が閉じた 8 つの列に在り追跡されている file を持たない dir を std の remove_dir_all で消す。 無視の規則は読まず git clean は撃たない。 決め手は裁定 user 2026-09-28T04:46Z (器で直す・A1 の常設の承認) と、 fidelity-adr の review を受けた分析。

運転手が一区切りするたびに、 もう終わったと測れた便の worktree を歩き、 名が決まった 8 つの dir (Rust の target、 TypeScript の node_modules、 Python の仮想環境 .venv と cache 4 つ、 Expo の .expo) のうち、 追跡されている file を 1 つも持たないものだけを消す案です。 無視の規則は読まず git clean も撃たないので、 鍵や local の設定のような作り直せない file は消えず、 消す物は裁定 04:46Z の常設の承認の種類にちょうど収まります。 置き場の全便を毎周見るので、 最初の周で既に溜まった分も取り戻し、 退役は可逆な移動のまま残ります。 代わりに、 起こし直す便は build をやり直す時間が掛かり、 列に無い置き場は残り、 列の名の dir は中に人が置いた物ごと消え、 周ごとに小さな費用が掛かることを引き受けます。

+ 利点

  • disk を実際に取り戻す — 非公開の隣の project では退役した 117 本の build の置き場だけで 540 GB だった (DR1)
  • 置き場の全便を毎周見るので、 器の入れ替えの後の最初の周が既に溜まった分も取り戻す (DR1)
  • 消すのは作り直せると名で分かる置き場だけで、 鍵・手書きの script・local の設定のような無視された file は消えない (DR2)
  • 退役は可逆な move のまま、 branch の commit・木・追跡されている file・state dir の記録は残る (DR2)
  • 列が器の対応する言語の全部を覆い、 言語ごとの設定を器が持たない (DR3)
  • 口・rules 行・跨版の key を足さず、 既存の生死の判定と lock を使う (DR4)
  • 便ごとの worktree は分かれたままで、 並列の便は互いの build を待たない (DR5)
  • git clean を撃たないので rules 行 host_guard.git は変わらず、 session と runner の git clean -f は今どおり断られる (DR6)
  • 消す物が裁定 04:46Z の常設の承認の種類にちょうど収まる (DR7)

− 欠点

  • Gated FAIL の便を regate で撃ち直す周や Stopped の便を resume で起こし直す周は、 build と依存の取り込みを最初からやり直す (数分・正しさは変わらない)
  • 列に無い build の置き場 (dist や build のような汎い名・言語の外の道具の cache) は消えず、 言語を足す便は同じ型の ADR で列を足す
  • 列の名の dir は、 中に人が置いた未追跡の file や入れ子の git repo ごと消える
  • 木ごとに git ls-files 1 回と木の走査の小さな固定の費用が掛かる
OPT2今のまま — disk が満ちたら人が手で消す不採用

器には消す手を足さず、 disk が満ちたら持ち主や席が手で build の置き場を消す。 決め手は分析 (満杯まで誰も気付かず便が落ちる)。

器には何も足さず、 disk が満ちたら持ち主や席が手で build の置き場を消す案です。 器に消す手を足さないので憲法の読みを決めずに済み、 何を消すかを人が毎回見て決められる点で勝ります。 けれども、 満杯になるまで誰も気付かず 3 つの project の便が落ち、 手の掃除は文章にしか無い手順で満杯のたびに繰り返し、 席の手の git clean -f は門が断るうえ、 断りを緩めれば無視されない仕事まで消せる手を席に渡すことになるので退けました。

+ 利点

  • 器に消す手を足さないので、 N1 と A1 の読みを決める必要が無い
  • 何を消すかを人が毎回見て決められる

− 欠点

  • 満杯になるまで誰も気付かず、 3 つの project の便が ENOSPC で落ちた (DR1)
  • 手の掃除の手順は散文にしか無く、 満杯のたびに繰り返す (DR1・N2)
  • 席の手の git clean -f は host-guard が断り、 断りを緩めると無視されない untracked の仕事まで消せる手を session に渡す (DR6)
OPT3git clean -d -X -f で無視された file を全部消す不採用

live でない便の木で git clean -d -X -f を撃ち、 無視の規則が無視と宣言する file と dir を全部消す (v2 までの草稿の形)。 決め手は fidelity-adr の review の再現と分析 (無視の規則は作り直せない物も持ち、 host の個人設定の除外も読む)。

終わった便の木で git clean -d -X -f を撃ち、 無視の規則が無視と宣言する file と dir を全部消す案で、 この記録の前の草稿の形です。 列を持たず、 dist や build のような汎い名の置き場も消せ、 言語を足すときに器の列を足さずに済む点で勝ります。 けれども、 無視の規則は鍵・手書きの local の script・local の設定・session の作業記憶のような作り直せない物も持ち、 git clean は host の個人設定の除外まで読むので消す物が host ごとに変わり、 承認の種類も越えるので退けました。

+ 利点

  • 列を持たず、 どの言語の project でも無視の規則に書かれた build の置き場を消せる (dist や build のような汎い名も含む)
  • git の 1 命令で済み、 言語を足すときに器の列を足す便が要らない

− 欠点

  • 無視の規則は鍵・手書きの local の script・local の設定・session の作業記憶のような作り直せない物も持ち、 それも消える (DR2)
  • git clean -X は repo の info/exclude と host の個人設定の除外も読み、 消す集合が host ごとに変わる (DR2)
  • 消す物が作り直せる物に閉じないので、 A1 の常設の承認の種類を越える (DR7)
OPT4退役した worktree だけを掃除する不採用

掃除の対象を退役先の木に限り、 退役していない終端の便 (Failed・Stopped・Gated の FAIL) の木には触れない。 決め手は分析 (退役しない終端の木が溜まり続ける)。

掃除の対象を退役した worktree に限り、 退役していない終わった便の木には触れない案です。 起こし直す便の build のやり直しが無く、 取り戻す量の約 9 割を得られ、 持ち主が手で消した範囲と同じ形で読みやすい点で勝ります。 けれども、 退役しない終わった便の木は溜まり続け (非公開の隣の project では退役していない 23 本が 58 GB)、 その分は人の手の掃除に戻るので退けました。

+ 利点

  • regate や resume で起こし直す便の木に触れないので、 build のやり直しの手戻りが無い
  • 取り戻す量の約 9 割を得る (非公開の隣の project で 597 GB のうち 540 GB が退役した木の分)
  • 裁定 04:45Z が手で消した範囲 (退役した worktree) と同じ形で読みやすい

− 欠点

  • 退役しない終端の木は溜まり続ける — 非公開の隣の project では退役していない 23 本が 58 GB を持っていた (DR1)
  • 畳まれずに残る便の木ほど長く残り、 その分は人の手の掃除に戻る (DR1)
OPT5repo ごとに便を跨いで build の置き場を 1 つ共有する不採用

便ごとの worktree の build の出力先を repo ごとに 1 つの dir へ向ける (cargo の target dir の指定など)。 決め手は分析 (言語に依り、 並列の便が直列になる)。
