設計判断記録 (ADR) scribe2 — 群の移動の判定を tick が撃つ

管理 tick が群の移動の判定を撃つ — dispatch の 1 周の群の段と同じ 1 本の判定 (逼迫の読み → 移り先 → 記録 → 承認 event) を、 席ごとの管理 tick が host の lock の内側で群ごとに鮮度の窓に 1 回まで撃ち、 便の無い host でも群が移る。 判定は 1 本に切り出して周と tick が同じ 1 本を呼び、 退避と起こし直しは便の終端の周の群の段 (自分の置き場の席) と各席の tick の移動の門 (他の置き場の席) が撃ち、 dispatch の 1 周を timer で撃たない線は保つ (ADR-0055 の契機の部分を supersede・要件 FR38 の改訂を伴う)

ADR-0055 は群の逼迫の契機を「便の終端の周 (dispatch の 1 周) と席自身の hook の 2 系統」に置き、 timer を持たないと決めた。 その後 ADR-0058 が管理 tick を席ごとの周期の見回りとして器に戻し、 tick は「群の記録と自席の口座が違う周」に退避と起こし直しの続きを自席に撃つ (設計 seat-heartbeat.md §4 / §7) が、 判定 (逼迫の読み・移り先・記録・承認 event) は今も dispatch の 1 周にしか無い。 2026-09-25 の実測で、 群の記録が動いたのは pipeline が 1 周を撃った瞬間だけで、 pipeline を持たない project (設計だけの repo) は誰も移さず、 席の hook は通知と「移動を頼む記録」までで判定は撃たないことが分かった。 本 ADR は、 群の移動の判定を dispatch の群の段から 1 本の関数に切り出し (置き場は群の記録の読み手と lock と同じ)、 dispatch の 1 周と管理 tick が同じ 1 本を host の lock の内側で呼ぶと決める。 tick はその判定を群ごとに鮮度の窓 (rules 行 fleet.usage_fresh_s) に 1 回まで撃ち、 判定の周だけ計測を起こしてよい。 判定の 1 本は退避も起こし直しも撃たず、 便の終端の周の群の段は自分の置き場の席に今まで通り撃ち、 他の置き場の席は各席の tick の移動の門が撃つ。 要件 FR38 の契機に tick の周期を足す改訂を伴う (SRS の改訂は持ち主が spec の編集の口で行う)。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「口座」は席が使う Claude Code の login 単位、 「群」は同じ口座を共有する project のかたまり、 「群の移動」は残りが少なくなった口座から群ごと別の口座へ移ることです。 前の決定 (ADR-0055) は、 群の残りを測って移すきっかけを「作業 (便) が 1 つ終わった直後に器が回す 1 周」と「席が話す番のたびに動く仕組み (hook)」の 2 つに置き、 時計は持たないと決めました。 その後、 席ごとに周期で回る見回り (管理 tick) が器に戻り、 見回りは「移動が決まった後の続き」(古い席を終えて、 新しい口座で席を起こし直す) を自分の席に撃つようになりましたが、 「移るかどうかを決める判定」(残りを読む → 移り先を決める → 記録と承認を書く) は今も 1 周の中にしかありません。 2026-09-25 の実測で、 群の記録が動いたのは pipeline が 1 周を撃った瞬間だけで、 pipeline を持たない project (設計だけの repo) は誰も移さないことが分かりました。 この記録は、 その判定を 1 周の中から 1 本の関数に切り出し、 1 周と見回りが同じ 1 本を鍵 (lock) の内側で呼ぶと決めます。 見回りはその判定を群ごとに「計測をやり直さない窓」(鮮度) に 1 回までしか撃たず、 判定の周だけ口座の残りを測ってよいことにします (席が「移してほしい」と置いたメモがある群は窓に関係なく測り、 無い群は窓の外だけ測ります)。 判定の 1 本は、 古い席を終える手も席を起こし直す手も撃ちません。 その 2 つの手は 2 系統のままです: 便の終端の 1 周は自分の置き場の席にこれまで通り撃ち、 他の置き場の席には各席の見回りが自分の席にだけ撃ちます。 便の終端の 1 周の判定は残り、 1 周を時計で撃たない線も保ちます。 要件書では、 群の逼迫の通知と移動 (FR38) のきっかけに見回りの周期を足し、 見回りは測らない (FR27・受入基準 AC18) の文を改める改訂を伴います (改訂は持ち主が要件書の編集の口で行います)。 この記録は、 受け入れられ要件書が改訂されるまで何も拘束しない発効前 (proposed) の記録です。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯・実測・器の今の部品・要件書との関係・これまでの決まり・この判断の範囲の 6 つから説明します。 前の決定 (ADR-0049) は席の口座を群 (project のかたまり) で持ち、 残りが線を越えたら群ごと別の口座へ移ると決め、 次の決定 (ADR-0055) はそのきっかけを「便が終わった直後の 1 周」と「席が話す番の hook」の 2 つに置き、 時計を持たないと決めました。 その後 ADR-0058 が席ごとの見回り (管理 tick) を器に戻し、 ADR-0064 が見回りの時計を席の起動が入れる形にし、 設計 doc は見回りに「移動が決まった後の続き」(古い席を終える・新しい口座で起こし直す) を自分の席に撃たせました。 けれども判定そのものは 1 周の中にしかありません。 2026-09-25 の実測では、 群の記録が動いたのは pipeline が 1 周を撃った瞬間だけで、 pipeline を持たない project は誰も移さず、 席の hook は知らせて「移動を頼むメモ」を置くまでで、 見回りは「測らない・子 process を起こさない」ままでした。 器の部品を見ると、 1 周の群の手番 (群の段) は鍵を取り、 群ごとに今の口座と測る集合を決め、 口座ごとに 1 回だけ計測し、 逼迫なら移り先を決めて記録と承認を書き、 古い席へ合図を送って起こし直します。 逼迫は今の口座のいちばん新しい実測で読みますが、 移り先には窓の内側の新しい実測が要るので、 測らない周は移り先を持てません。 「便が使っていない」の条件は、 呼んだ側の置き場の記録で判じます。 群の記録の読み手・移動を頼むメモ・鍵・逼迫の判定は同じ場所にあり、 見回りの移動の門はその鍵と読み手をすでに呼んでいます。 要件書では、 FR38 がきっかけを 2 つと書き、 FR27 と受入基準 AC18 が「見回りは測らない・計測の起動 0 件」と書いているので、 この判断はそれらの改訂を伴います。 決まりの側では、 経路は 1 本 (判定を 2 か所に書かない)・状態は型で運ぶ、 が効き、 「足す前に外す物を名指す」決まりについては、 判定は場所を移すだけ (純移動) で、 足すのは判定の時刻の file 1 種と見回りが計測を撃つきっかけ 1 つ、 rules 行は足さない、 と読みます。 動かすのは判定の置き場ときっかけだけで、 移り先の決め方・記録の形・鍵・便の終端の 1 周の群の手番 (残る・同じ 1 本を呼ぶ)・hook の役目・見回りの梯子と合図・退避と起こし直しの 2 系統は動かしません。

CTX1

経緯 — 契機を 2 系統に置いた決定と、 その後に戻った tick

ADR-0049 は席の口座を project の群で持ち、 閾値を越えたら群ごと別の口座へ移ると決め、 ADR-0055 はその契機を「便の終端の周 (dispatch の 1 周器が次の作業を配る 1 巡) と席自身の hook席の節目に自動で動く仕組み の 2 系統」に置き、 timer・常駐 process を持たないと決めた (OPT2「timer で dispatch の 1 周を撃つ」と OPT3「席自身の hook が判定して起こし直す」は却下)。 その後 ADR-0058 が管理 tick席を周期で見る仕組み (席ごとに systemd の timer で周期に回る見回り) を器に戻し、 ADR-0064 が tick の unit を席の起動が入れる形にした。 設計 seat-heartbeat.md §4 / §7 は tick に「群の記録と自席の口座が違う周」の続き (自席への /exit・shell に戻った窓への起こし直し・会話の resume) を持たせたが、 判定 (逼迫の読み・移り先・記録・承認 event) は dispatch の 1 周の群の段1 周の中の群の手番にしか無い。 2026-09-25T04:13Z の裁定は、 群の口座の移動を含めて器が完全に自律する方針を受諾した。 要旨だけを写し、 逐語は非公開の作業記録簿 (台帳 s2-07l.629) に在る。

CTX2

実測 — 便の無い host では群は移らない

2026-09-25 の実測で、 群の今の口座の記録が動いたのは、 scribe2 の pipeline が便の終端か手動で 1 周を撃った瞬間だけであった。 pipeline を持たない project (設計だけの repo など) の席は、 同じ群に属していても、 その置き場で誰も判定を撃たない。 席自身の hook は SessionStart と UserPromptSubmit で自席の口座の逼迫を読んで告げ、 移動を頼む記録席が置く移動のメモを host の根machine 共通の置き場に置くまでで (account-lifecycle.md §19 形 5・§20 形 4)、 判定は撃たない。 管理 tick は席ごとに周期で回っているが、 今は「測らない・子 process を起こさない」(seat-heartbeat.md §2 形 4・AC18 の「tick の周に計測の起動が 0 件」) で、 移動の門tick が自席を移す手は群の記録を読むだけである。 つまり ADR-0055 CSQ-N1 の「席も便も動いていない周は測らず、 手で 1 周を撃つまで移動は起きない」が、 便の無い host では「永久に待つ」に化けている。

CTX3

現物 — 判定は群の段の中に、 続きは tick の中に、 別々に在る

base 67e74ff で、 dispatch の 1 周の群の段は 1 関数 (round) が、 host の面を合わせた manifest → 閾値の行 (Caps) → host の群用 dir の lock1 度に 1 つ通す鍵 (create_new) → 群ごとの計画 (今の口座の解決・測る集合 = 今の口座 ∪ 群の置き場の席の登録 row の口座・移動を頼む記録の有無) → 口座ごとに 1 周に 1 回の計測 (頼みの在る群は鮮度計測をやり直さない窓に依らず、 他は鮮度の外だけ・口は計測の鮮度つきの 1 本) → event log の読み直し → 群ごとの 1 手 (記録が在って登録 row が遅れた席が在れば起こし直しの続き / 逼迫なら移り先を 1 回決めて記録・承認 event・退避の合図・起こし直し / 候補なしなら断りの event と席への断りの 1 行 / 逼迫でなければ通知) の順で撃つ。 逼迫は群の今の口座の最新の実測 (鮮度を問わない) で読み、 移り先には候補の 3 窓とも閾値未満の鮮度の内側の実測が要る＝計測を起こさない周は移り先を持てない。 「便が使っていない」の条件は呼び手の置き場の event log の live 便で判じる。 保留の event は起こし直し (relaunch) が記し、 断りの 1 行・逼迫の通知・退避の合図は群の置き場の席の pane へ送る。 群の記録の読み手 (current_of・記録 > 種)・移動を頼む記録 (put_request)・lock・逼迫の判定 (pressed) は群の記録と同じ module に在り、 tick の移動の門はその lock と読み手を既に呼ぶ。 tick の判定の列は front (登録 row → 窓が shell か → 打刻 → 梯子) → moving (群の記録と自席の口座の比較・lock・shell なら起こし直し・claude なら /exit か Enter) → back (黙り・上限・床・口座の門・入力欄・記録・注入) で、 計測の鮮度の内側の最新の回 (fresh_rows) を読むだけで計測は起こさない。 rules 行裁定つきの値を持つ設定の行は fleet.usage_fresh_s (計測の鮮度・300 秒)・fleet.group_pressure_5h_pct / _7d_pct / _model_pct (閾値 85 / 95 / 95)・seat.tick_interval_s (tick の周期・60 秒) が在る。 host の群用 dir は置き場の親の下＝置き場を跨いで同じ 1 dir で、 群ごとに今の口座の記録 1 file と移動を頼む記録 1 file を持つ。

CTX4

要件文との関係 — FR38 の契機と、 tick の「測らない」の文

SRS FR38 は群の逼迫の契機を「便の終端の周 (dispatch の 1 周) と席自身の hook の 2 系統」と書き、 「管理 tick (FR27) の timer (FR64) は群の逼迫を測らず計測も起こさず、 tick の口座の門は計測の記録の最新値を読むだけ」と書く。 FR27 は「群の逼迫 (FR38) は測らず」と書き、 AC18 は「tick の周に計測 (FR33) の起動が 0 件」を歯の受入に持つ。 本 ADR は FR38 の契機に tick の周期を足し、 FR27 と AC18 の「測らない・計測の起動 0 件」を「判定の周 (群ごとに鮮度の窓に 1 回まで) だけ計測を起こしてよい」に改める改訂を伴う。 SRS の改訂は持ち主が spec の編集の口で行い、 本 ADR は改訂までは proposed で何も拘束しない (ADR-0055 CTX4 と同じ順)。

CTX5

憲法と既存の決定の向き (本 ADR の解釈)

C2 は経路を 1 本にする (判定の関数は 1 つ・契機ごとに書かない)。 C17.2 は record・rules 行・mechanism を足すときに何を外すかを名指させる。 本 ADR の読みでは、 判定は純移動 (場所を移すだけで写しを作らない) で、 足すのは判定の打刻最後に判定した時刻の file 1 種 (群ごとに 1 file) と tick が計測を撃つ契機 1 つであり、 rules 行は足さない (判定の間隔は鮮度の行で足りる)。 C3 は状態を型で運び、 端末の見た目や自由文を判定に使わない。 C10 は宣言値と実測値と導出値を型で分け、 C11 は失敗と極性を型で持つ。 A1 は消す・出す・使うの 3 クラスを user に聞くが、 口座を使うこと自体は群の宣言の常設の承認 1 回で以後は都度聞かない (ADR-0049 §2・移動の承認 event はその写し)。 ADR-0055 の原則「逼迫は何かが動いた周にだけ進むので、 動いた周に測る」は、 便の無い host では「動いた周」が席の話す番しか無く、 席は自分を起こす権能を持たない (ADR-0045・ADR-0055 OPT3 の却下) ので、 判定の契機が消える。 ADR-0058 は tick を「席の外から周期で回り、 見回り自体は席を起こさず費用を持たない」仕組みとして戻し、 ADR-0055 と衝突しない理由として「tick の timer は逼迫を測らない」という前提の文を置いた。 ADR-0049 (群・鍵・記録・移り先の 3 条件) と ADR-0020 §2.4 (候補なしの周は立て直さない) は不変。 ADR-0065 は移り先の口座の trust の印を席の起動が置くと決め、 起こし直しの人の手を消した＝本 ADR の完全自律はその上に立つ。

CTX6

射程 — 動かすのは判定の置き場と契機だけ

動かすのは (1) 判定を 1 本の関数に切り出す置き場 (群の記録の読み手と lock と同じ module)、 (2) tick がその判定を群ごとに鮮度の窓に 1 回まで撃つ契機と、 その打刻の file (host の群用 dir に群ごとに 1 file・rules 行は足さない)、 (3) 判定の周に計測を起こしてよいこと、 の 3 つ。 1 本の範囲は「測る集合 → 計測 → 判定 → 移動の記録と承認 event・候補なしの断りの event・頼みの履歴化」までで、 出力は閉じた enum (移った / 移らない / 候補なし)。 退避と起こし直しは 2 系統で、 便の終端の周の群の段は自分の置き場の席に今まで通り (退避の合図古い席へ「終えて」の 1 行 → 起こし直し・保留の event) 撃ち、 他の置き場の席は各席の tick の移動の門 (§4 / §7) が自席に撃つ。 判定の 1 本はどちらも撃たず、 席の pane にも触らない — 他の置き場の席の pane に触る形は設計 §9 が退け (tick が判定だけして退避も自分で全席に送る案)、 列に無い置き場の席を列が起こす形は設計 §4 が退けた (登録 row の書き手が置き場の外に増える)。 動かさないのは、 移り先の 3 条件と記録の形と承認 event の kind と detail (ADR-0049・§20 形 5 / 6)、 lock の 1 本、 便の終端の周の群の段の外形 (通知・断りの 1 行・退避・起こし直し・event)、 席の hook の通知と移動を頼む記録 (§19 形 5・§20 形 4)、 tick の梯子と打刻の合図と口座の門 (ADR-0058)、 tick の移動の門、 tick の unit と周期の rules 行 (ADR-0064)、 dispatch の 1 周の契機 (timer で撃たない・ADR-0055)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 便の無い host や project でも群が移ること (きっかけが pipeline の有無に依らない)。 判定は 1 本で、 1 周と見回りが同じ関数を呼び、 きっかけごとに判定を書かないこと。 殺到しないこと (判定は鍵の内側で群ごとに 1 回、 見回りの周は鮮度の窓で上限し、 置き場の数だけ走らせない)。 変えない線を保つこと (1 周を時計で撃たない・記録と移り先の形・見回りの梯子と口座の門・群の手番の外形・退避と起こし直しは 1 周が自分の置き場に、 各席の見回りが他の置き場に撃つ 2 系統で、 判定の 1 本は席の画面に触らない)。 見回りの計測は判定の周だけにすること (判定は新しい実測で残りを読むが移り先には窓の内側の実測が要るので判定の周は測ってよく、 メモのある群は窓に関係なく、 無い群は窓の外だけ、 他の周は起こさない。 要件の「測らない」は改訂で置き換える) です。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 判定を 1 本に切り出して見回りが群ごとに鮮度の窓に 1 回まで鍵の内側で撃つ案 (選んだ案・1 周の群の手番も同じ 1 本を呼ぶ)、 時計で 1 周を撃つ案、 席自身の hook が判定して起こし直す案、 人が見る案、 見回りは判定せず「移動を頼むメモ」を 1 周が拾うまで待つ案 (今の形) です。 却下した 4 案にも利点を並べ、 退けた決め手が現物か分析かを各案に書きます。 時計で 1 周を撃つ案は判定の置き場を動かさずに済む点で、 hook が判定する案は時計も見回りも要らない点で、 人が見る案は器が周期で計測の子 process を起こさない点で、 今の形のまま待つ案は見回りが計測も判定も持たない点で、 選んだ案に勝ります。

OPT1判定を 1 本に切り出し、 管理 tick が群ごとに鮮度の窓に 1 回まで lock の内側で撃つ (dispatch の群の段も同じ 1 本を呼ぶ)採用

群の移動の判定移るかを決める 1 本 (測る集合 → 計測 → 逼迫の読み → 移り先 → 移動の記録と承認 event・候補なしの断りの event・頼みの履歴化) を dispatch の群の段から 1 本の関数に切り出し、 群の記録の読み手と lock と同じ module に置く。 dispatch の 1 周の群の段はその 1 本を呼び (今と同じ lock・同じ順)、 退避の合図と起こし直しと保留の event と席への行は群の段に残る。 管理 tick は、 自席の anchorrepo の本体の場所 が群に属する周に、 host の群用 dir の群ごとの判定の打刻 (1 file) を読み、 前の判定から fleet.usage_fresh_s 以上が経っていれば (か打刻が無ければ) 同じ lock の内側で同じ 1 本を撃って打刻を書く。 判定の周だけ計測を起こしてよい (口は群の段と同じ鮮度つきの 1 本・頼みの在る群は鮮度に依らず・無い群は鮮度の外だけ)。 lock を取れない周は撃たずに今の列へ進む。 判定の後の続き (他の置き場の席の退避と起こし直し) は各席の tick の移動の門が今のまま自席に撃つ。 決め手は分析 (裁定の完全自律を、 判定を増やさず契機を 1 つ足す形で満たす)。

群の移動の判定 (測る集合 → 計測 → 残りを読む → 移り先を決める → 移動の記録と承認の記録、 候補なしの断りの記録、 メモの履歴化) を 1 周の群の手番から 1 本の関数に切り出し、 群の記録の読み手と鍵と同じ場所に置く案です。 1 周の群の手番はその 1 本を今と同じ鍵の内側・同じ順で呼び、 古い席への合図・起こし直し・保留の記録・席の画面への行は自分に残します。 見回り (管理 tick) は、 自分の席の repo が群に属する周に、 共通の置き場にある群ごとの「最後に判定した時刻」を読み、 時刻が無いか鮮度の窓 (fleet.usage_fresh_s) より古ければ鍵の内側で同じ 1 本を撃って時刻を書き直します。 判定の周だけ口座を測ってよく (口は 1 周と同じ鮮度つきの計測の 1 本・メモのある群は窓に関係なく・無い群は窓の外だけ)、 鍵を取れない周は撃たずに今の列へ進みます。 判定の後の続き (他の置き場の席を終える・起こし直す) は、 各席の見回りの移動の門が今のまま自分の席に撃ちます。 便の無い host でも群が移り、 判定は 1 本のまま、 鍵と時刻で殺到せず、 変えない線は保たれ (群の手番の外形は動かず、 判定の 1 本は席の画面に触らない)、 見回りの計測は判定の周だけで rules 行は足しません。 代わりに、 見回りが計測の子 process を起こす周が生まれ要件 (FR27・AC18) の改訂を伴うこと、 要件 FR38 のきっかけの文の改訂を伴い改訂までは何も拘束しないこと、 見回りの時計が無い席は今まで通り移らないこと、 共通の置き場に時刻の file が群ごとに 1 つ増え判定行に欄が増えること、 判定の切り出しが 1 周の群の手番の歯の範囲に及ぶこと、 見回りの判定は自分の置き場の記録しか読まず別の置き場の「便が使っている」を見ないことを引き受けます。 決め手は分析で、 完全自律の決定を、 判定を増やさずきっかけを 1 つ足す形で満たす案でした。

+ 利点

  • 便の無い host / project でも、 席が居る限り tick が判定を撃ち、 群が移る (DR1)
  • 判定は 1 本で、 群の段と tick が同じ関数を呼ぶ。 契機ごとに判定を書かない (DR2)
  • lock の内側で群ごとに 1 回、 打刻で鮮度の窓に 1 回まで＝置き場の数だけ tick が居ても判定は群ごとに鮮度の窓に 1 回で、 同じ口座へ殺到しない (DR3)
  • dispatch の 1 周の契機・記録と移り先の形・tick の梯子と口座の門・群の段の外形 (退避・起こし直し・通知・event) は動かず、 判定の 1 本は席の pane に触らない (DR4)
  • tick の計測は判定の周だけ (頼みの在る群は鮮度に依らず・無い群は鮮度の外だけ・群の段と同じ) で、 他の周は起こさない。 rules 行は足さない (DR5)

− 欠点

  • 管理 tick が計測の子 process を起こす周が生まれる (鮮度の窓に群ごとに 1 回まで)。 要件 FR27 / AC18 の「測らない・計測の起動 0 件」の改訂を伴う
  • 要件 FR38 の契機の文の改訂を伴い、 改訂までは何も拘束しない
  • tick の unit が無い席は今まで通り移らない (unit は席の起動が入れる・ADR-0064)
  • host の群用 dir に判定の打刻の file が群ごとに 1 つ増え、 tick の判定行に判定の結果の欄が増える (外形 snapshot が動く)
  • 判定の関数の純移動は群の段の歯の write-set に及ぶ (置き場を移すだけで判定の形は変えない)
  • tick の判定は自席の置き場を入力にするので、 「便が使っていない」の条件は自席の置き場の live 便でしか判じられず、 別の置き場の live 便は見えない
OPT2timer で dispatch の 1 周を撃つ不採用

置き場ごとに timer を立て、 dispatch の 1 周 (群の段を含む) を周期で撃つ。 ADR-0055 OPT2 と同じ形。 決め手は分析 (周は pipeline と repo に結びつく)。

置き場ごとに時計を立て、 1 周 (群の手番を含む) を周期で撃つ案です。 前の決定 (ADR-0055) の却下案と同じ形です。 判定の置き場を動かさず、 群の手番をそのまま周期で撃てる点で勝ります。 けれども、 1 周は pipeline と repo (置き場の台帳と契約表) に結びついていて、 便の無い host には周そのものが無く、 pipeline を持たない project は撃つ相手を持ちません。 置き場ごとに周を立てると、 群の判定が置き場の数だけ走り、 計測の子 process と記録が置き場の数だけ増えます。 決め手は分析です。

+ 利点

  • 判定の置き場を動かさず、 群の段をそのまま周期で撃てる

− 欠点

  • dispatch の 1 周は pipeline と repo (置き場の台帳と契約表) に結びつき、 便の無い host では周そのものが無い。 pipeline を持たない project は撃つ相手を持たない (DR1)
  • 置き場ごとに周を立てると、 群の判定が置き場の数だけ走る (lock で直列にはなるが、 計測の子 process と event が置き場の数だけ増える) (DR3)
OPT3席自身の hook が判定して起こし直す不採用

SessionStart / UserPromptSubmit の hook が逼迫を読んだ周に、 移り先を決めて記録を書き、 自分を起こし直す。 ADR-0055 OPT3 と同じ形。 決め手は分析 (席は自分を起こす権能を持たない)。

席が話す番の hook が残りを読んだ周に、 移り先を決めて記録を書き、 自分を起こし直す案です。 前の決定 (ADR-0055) の却下案と同じ形です。 きっかけが席の話す番にあり、 時計も見回りも要らない点で勝ります。 けれども、 席は自分を起こす権能を持たず (ADR-0045)、 hook の席は作業中で退避の合図と起こし直しの門を通りません。 置き場ごとに判断が割れ、 同じ群の席が同じ口座へ殺到します。 話す番の無い席 (黙っている席・便の無い host で待つ席) には判定が届きません。 決め手は分析です。

  • 置き場ごとに判断が割れ、 同じ群の席が同じ口座へ殺到する (群単位の 1 回にならない) (DR3)
  • 話す番の無い席 (黙っている席・便の無い host で待つ席) は判定に届かない (DR1)

04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 器は、 群の移動の判定 (測る集合を取る → 計測する → 群の今の口座の残りを読む → 移り先を決める → 群の今の口座の記録と承認の記録を書く、 候補が無ければ断りの記録を書く、 「移動を頼むメモ」を履歴へ移す。 結果は「移った / 移らない / 候補なし」の 3 値) を 1 周の群の手番から 1 本の関数に切り出し、 群の記録の読み手と鍵と同じ場所に置きます。 1 周の群の手番はその 1 本を今と同じ鍵の内側・同じ順で呼び、 判定を別に持たず、 古い席への合図・起こし直し・保留の記録・席の画面への行は今まで通り自分で撃ちます。 見回り (管理 tick) は、 自分の席の repo が群に属する周に、 machine 共通の置き場にある群ごとの「最後に判定した時刻」を読み、 時刻が無いか鮮度の窓 (rules 行 fleet.usage_fresh_s) より古ければ、 同じ鍵の内側で同じ 1 本を自分の置き場を入力にして撃ち、 時刻を書き直します。 窓の内側の周と鍵を取れない周は、 判定を撃たず今の列へ進みます (理由の語で止めません)。 rules 行は足しません。 判定の周だけ、 1 周と同じ鮮度つきの計測の口で口座を測ってよく (メモのある群は窓に関係なく、 無い群は窓の外だけ)、 それ以外の見回りの周は計測を起こしません。 判定の 1 本は古い席を終える手も起こし直す手も撃たず、 席の画面に触りません。 その 2 つは 2 系統のまま: 便の終端の 1 周は自分の置き場の席に今まで通り、 他の置き場の席には各席の見回りの移動の門が自分の席にだけ撃ちます。 便の終端の 1 周の群の手番は残り、 席の hook は通知とメモまでで判定は撃たず、 見回りの判定行には judged= の欄 (移った / とどまる / 候補なし / 止まった理由・撃たない周は -) が載り、 記録は判定の 1 本が書いて見回り自身は書きません。 1 周を時計で撃つことはしません。 要件書では、 群の逼迫の通知と移動 (FR38) のきっかけに見回りの周期を足す根拠になり、 見回り (FR27) と受入基準 AC18 の「測らない・計測の起動 0 件」を「判定の周だけ鮮度の窓に 1 回まで測ってよい」に改める根拠になり、 口座残量の計測 (FR33) の 1 本をそのまま使うことを主張します。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 4 つと、 代わりに引き受けること 6 つです。 良くなるのは、 便の無い host や project でも席と見回りがある限り群が移り「移動を頼むメモ」が永久に待つ形が消えること、 判定が 1 本のままきっかけが 3 つになること、 置き場の数だけ見回りがいても判定は群ごとに鮮度の窓に 1 回で殺到が構造で起きないこと、 退避と起こし直しが 2 系統 (1 周は自分の置き場・各席の見回りは他の置き場) のままで判定の 1 本は席の画面に触らず、 記録と移り先の形や 1 周のきっかけと群の手番の外形が動かないことです。 引き受けるのは、 見回りが計測の子 process を起こす周が生まれ、 前の決定 (ADR-0058) の「見回りは費用を持たない」と「見回りは残りを測らない」という前提の文が判定の周に限って古くなること、 要件書 (FR38・FR27・AC18) の改訂を伴い改訂まで何も拘束しないこと、 見回りの時計が無い席は今まで通り移らないこと、 共通の置き場に判定の時刻の file が群ごとに 1 つ増え判定行に欄が増えること (1 本が止まった周は理由の語を載せて今の列へ進み、 移動は起きない)、 判定の切り出しが 1 周の群の手番の歯の範囲に及ぶこと (判定の形は 1 字も変えない)、 見回りの判定は自分の置き場の記録しか読まないので「便が使っていない」を別の置き場については判じられないことです。

✓ 良い結果

  • ●便の無い host / project でも、 席が居て tick の unit が在る限り、 群の移動の判定が群ごとに鮮度の窓に 1 回まで撃たれ、 群が移る。 移動を頼む記録が永久に待つ形が消える
  • ●判定は 1 本で、 dispatch の 1 周の群の段と管理 tick が同じ関数を同じ lock の内側で呼ぶ。 契機が 3 つになっても判定の写しは 1 つのまま (C2・純移動)
  • ●置き場の数だけ tick が居ても、 判定は群ごとに鮮度の窓に 1 回で、 lock が同じ周の二重の判定を止める。 同じ群の席が同じ口座へ殺到する形は構造で起きない (ADR-0055 CSQ-P3 のまま)
  • ●退避と起こし直しは 2 系統のまま — 便の終端の周の群の段は自分の置き場の席に今まで通り撃ち、 他の置き場の席は各席の tick の移動の門が自席に撃つ。 判定の 1 本は席の pane に触らず、 記録と移り先の形・tick の梯子と口座の門・dispatch の 1 周の契機と群の段の外形は動かない

⚖ トレードオフ・代償

  • ●管理 tick が計測の子 process を起こす周が生まれる (群ごとに鮮度の窓に 1 回まで・判定の周だけ)。 ADR-0058 の「見回り自体は費用を持たない」と、 ADR-0058 が ADR-0055 と衝突しない理由に置いた「tick の timer は逼迫を測らない」という前提の文は、 判定の周に限って古くなる
  • ●要件 FR38 の契機と FR27 / AC18 の「測らない・計測の起動 0 件」の改訂を伴う。 改訂が land するまで本 ADR は何も拘束せず、 実装の便は改訂の後にしか出せない
  • ●tick の unit が無い席 (unit は席の起動が入れる・ADR-0064) は今まで通り移らない。 群の判定は「席が居る host」でだけ進む
  • ●host の群用 dir に判定の打刻の file が群ごとに 1 つ増え、 tick の判定行に judged= の欄が増える (外形 snapshot が動く)。 1 本が typed に止まる周 (面・閾値の行・event log・打刻が読めない) は judged=error:<語> で今の列へ進み、 移動は起きない
  • ●判定の関数の切り出しは純移動で、 群の段の歯の write-set に及ぶ。 判定の形 (移り先の 3 条件・記録・承認 event・断り) は 1 字も変えない
  • ●tick の判定は自席の置き場を入力にするので、 移り先の「便が使っていない」の条件は自席の置き場の live 便でしか判じられない。 pipeline を持たない置き場の tick は別の置き場の live 便を見ない (置き場を跨いで live 便を読む形は本 ADR では足さない)
