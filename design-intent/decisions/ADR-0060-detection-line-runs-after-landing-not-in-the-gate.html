設計判断記録 (ADR) scribe2 — 検出線を着地の後へ

検出線 (変異検査) は gate で撃たず、 便が着地した後に器が切り離して 1 回撃つ — gate の判定は止める段だけで決まり、 変異の生存は record と event に残る (ADR-0009 §2.3・ADR-0021 §2.4・ADR-0039・ADR-0043・ADR-0052 の一部を置き換える)

便 (契約 1 本の 1 往復) は gate (着地の前の検査) を通るたびに、 落ちても止めない検査 (検出線 = 変異検査) の終わりを待っていた。 2026-09-21 以後に起こした便の 164 周の実測では、 検出線が gate 1 周の検査の行の秒の約半分 (周ごとの割合の中央値 53%) を占めた。 本 ADR は、 gate の判定を「落ちたら止める段」と審査役だけで出し、 検出線は便が着地した後に器が本線とは切り離した子 process で 1 回だけ撃つと決める。 検出線は止めない線のままなので、 生存が出ても着地は戻さず、 結果は便の記録 (record) と出来事の記録 (event) に残る。 前の決定のうち「検出線は gate の中 (と着地直後の検査) で撃つ」と定めた部分だけを置き換え、 変異を当てる歯の選び方 (ADR-0052) と、 木が同じなら着地直後の検査を record 1 本で済ませる形 (ADR-0043) は変えない。

この判断が約束すること (1 文サマリ)

この記録で「便」は契約 1 本を実装して本線 (main) に載せるまでの 1 往復、 「gate」は載せる前の検査、 「検出線」は落ちても便を止めずに結果を記録するだけの検査のことです。 ここで扱う検出線は変異検査で、 code をわざと壊して test がそれに気づくかを測ります。 これまで gate は、 止めない検出線の終わりまで待ってから判定を出していました。 2026-09-21 以後に起こした便の 164 回の実測 (host が止まった事故の日の 09-20 とそれより前を除く) では、 検出線が gate 1 回の検査の時間のおよそ半分 (1 回ごとの割合の中央値 53%・秒の中央値 97.5 秒) を占めていました。 この記録は、 gate の判定を「落ちたら止める検査」と審査役だけで出し、 検出線は便が本線に載った後に、 器 (scribe2 の本体) が本線の流れとは切り離して 1 回だけ撃つと決めます。 撃つ前には、 これまで gate の変異検査が取っていたのと同じ順番待ちの札を取るので、 混んだ machine では待ちます。 検出線は止めない線のままなので、 壊した code を test が見つけられなかった回 (生き残り) があっても本線は戻さず、 結果は便の記録と出来事の記録に残します。 作業記録簿 (台帳) の項目には写しません。 前の決定のうち「検出線は gate の中で撃つ」と定めた部分だけを置き換え、 検出線が使う test の選び方などは変えません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 user の決定と実測と器の現物と前の決定から説明します。 user は、 変異検査を gate の待ちの列から外し、 本線に載った後に撃ち、 結果は後から記録に載せる、 と決めました。 2026-09-21 以後の 164 回の実測では、 変異検査が gate 1 回の検査の時間のおよそ半分 (1 回ごとの割合の中央値 53%) を占め、 その期間の 1 つの便は変異検査を平均 1.3 回ほど撃っていました。 決定の根拠はこの割合なので、 数え方や数える期間を直しても向きは変わりません。 1 時間を超えた長い回は、 すべて 2026-09-20 に起こした便でした (6 回は host が止まっていた時間に重なり、 3 回はその日の回復の後です)。 これまで順番待ちの仕組み、 撃ち直しや使い回し、 当てる test を絞る形を順に足してきました。 器の現物では、 変異検査が測れなかったときに gate が判定できずに便が居座る経路や、 同じ gate の中の撃ち直し、 前の結果の使い回しが変異検査のために在ります。 一方で審査役は変異検査の結果を読んでおらず、 生き残りが出ても止めない約束なので、 本線に載った後に撃っても本線を赤にしません。 前の決定は同じ案を、 混んだ machine で重い検査が走り続けるという理由でも退けていたので、 この記録は今の変異検査と同じ順番待ちの札と混み具合の見張りを通してから撃つ形で答えます (待ちの上限を過ぎたら並列 1 に絞って撃つのは今と同じです)。 本線に載った木を別の作業場所に出して検査を撃つ形や memory の囲いは器に在りますが、 検査の行を組む関数の一部は gate の中にしか無く、 変異検査だけを撃つ入口と、 測れなかった回や撃たなかった回の理由を残す置き方はまだ無いので、 足す必要があります。

CTX1

裁定 — 検出線止めずに記録する線を gate着地の前の検査 の臨界路着地までに待つ段の列から外し、 着地の後に撃つ

2026-09-23 の user 裁定は、 変異検査 (vessel 宣言repo が名乗る宣言 fileの detection-verify の行 = xtask mutants-diff の検出線) を gate の臨界路 (便が着地までに必ず待つ段の列) から外し、 gate は止める段だけで判定を出し、 変異検査は便が Landed に達した後に非同期で撃ち、 結果は後から記録と event に載る、 とした (選択肢のうち推奨の案)。 裁定は ADR-0009 §2.3 と ADR-0021 §2.4 を置き換える新しい ADR を求め、 憲法 C12.4 / C13.5 の型の解釈を伴う。 裁定の文の「判定行」は、 本 ADR では run dir の verify の record (kind=detection の行) と読む (語彙の判定行は構造検査の 1 行で別の実体)。 逐語は非公開の作業記録簿 (台帳作業と裁定の記録簿 s2-07l.465 の notes) に在る。

CTX2

実測 — 検出線は gate 1 周の検査の秒の約半分を占める

orchestrator人と話す唯一の席 の実測 (2026-09-23・run dir の verify.jsonl) は、 gate で検出線を撃った 175 便 (verdict は PASS 138・FAIL 34・INCONCLUSIVE 3) の 241 周を数えた。 主の実測は 2026-09-21 以後に起こした便の 164 周 (凍結の日の 09-20 とそれより前を除く) で、 検出線の段の秒は中央値 97.5 秒・上位 1 割は 517 秒以上・最大 2,542 秒 (約 42 分) だった。 同じ周の verify 行の秒の和 (lensdiff を読む審査役 の時間と受付・遮断器の待ちを含まない) は中央値 202 秒で、 周ごとの検出線の割合の中央値は約 53% である (同じ測り方で 241 周全体では約 59%)。 1 時間を超えた 9 周 (最大 28,508 秒) はすべて 2026-09-20 に起こした便である。 そのうち 6 周の gate は host の凍結の窓 (ADR-0050 の根) に重なり、 残る 3 周 (1.2〜1.5 時間) は同じ日の回復の後で、 受付の core の項と歯の絞り込みが効く前の周である。 241 周の受付の欄に縮退 (slot=degraded) は 0 周だった。 検出線を撃った回数は便あたり平均 1.38 回 (175 便・持ち越しと面の外の省略の後) で、 09-21 以後の 129 便では 1.27 回である。 planner の実測 (2026-09-17・着地 37 便) では Implemented から Gated までの gate は中央値 24 分・1 便あたり平均 2.3 周で、 それとは別に main が crates 等で進んだ周の追随の再 gate が 41 回あった。 裁定の根拠は割合 (止めない検出線が gate の検査の秒の約半分〜6 割を占める) で、 数え方と母集団を直しても変わらない。 これまで検出線の費用には、 並列度の受付 (ADR-0021)・木が同じ主実測の省略 (ADR-0021 §2.4・ADR-0043)・rc 2 の同じ gate の中での撃ち直し (設計 gate-cost.md §21)・候補の木での持ち越し (ADR-0039)・mutant の test の fail-fast (設計 §33)・契約の歯と単体の歯だけを当てる形 (ADR-0052) を順に足してきた。 ADR-0052 の着地後の 2 便は検出線 161 秒・161 秒・157 秒 (3 周) だった。 その前の形で縮退した周 (.511 / .517 の追随の周) は席が途中で止めたので record が無く、 上の 241 周に入っていない (.517 の 1 周目は入っている)。

CTX3

現物 — 検出線の段と記録と、 着地の後の列

gate は ① write-set の照合 → ② 共通 verifyどの便にも撃つ検証 → ③ 検出線 (detection-verify の行・穴は {base} {jobs} {threads} {teeth}) → ④ 契約 verify の順で撃ち、 行ごとの record を run dir の verify.jsonl に書く (検出線の record は kind=detection で、 道具の 1 行の line と秒の secs を持ち、 出力の写しは run dir の detection の周の dir に置く)。 検出線の rc は 3 値で、 rc 0 は測定 (生存は record に載るだけ)、 rc 1 は R-C12-1 が deny に昇格した周だけ現れる赤、 rc 2 は測れなかった (道具の不在・baseline 落ち) で、 赤が 0 の周の gate を INCONCLUSIVE に倒す (赤が在る周は FAIL が先・設計 §28)。 rc 2 の周は同じ gate の中で 1 回撃ち直す (設計 §21)。 gate の中の検出線は閉じた 3 値 (撃つ・面の外なので撃たない・patch-id が前周と同じなので前周の record を持ち越す) を持ち、 追随の再 gate と主実測は main の差分が検出線の面 (crates と Cargo の file と rules と vessel 宣言) に触れた周だけ撃つ (pipeline.md §30 / §40)。 この面の判定は 1 本で 2 つの役を持ち、 追随で面の外だけが動いた周は検出線を撃たないだけでなく、 再 gate を丸ごと省いて前周の PASS を引き継ぐ (pipeline.md §33)。 gate は宣言の写しの検出線の行をそのまま撃たず、 契約が的を持つ便では的の file を渡す引数 (設計 §16) を、 純移動の便では母集団を絞る diff の引数 (設計 §14) を足してから撃つ。 この 2 つの付け足しと、 出力の写しの周の番号は gate の材料 (Gate) を引数に取る関数が持ち、 主実測の側には無い。 並列の枠変異検査の並列の枠 (受付札) を取るのも gate だけで、 主実測の行は受付を通らず並列度 1 で撃つ。 land は squash → 主実測 (着地した commit を tmp worktree に出して撃つ・木が gate と同じ周は record 1 本・ADR-0043) → 面 5 の 1 行と Landed の event → 便の worktree の退避 → land の終端着地の後の 3 手 (push → 着地 commit の CI の照合 → 台帳の close) の順に進み、 終端の各手は RunDone stage=Landed の detail の 1 語で記す。 審査役 (lens) の雛形は審査の材料を契約と diff だけと定め、 検出線の record を読んでいない。 runner実装役の Claude は禁じる語列で cargo mutants を撃てない。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C12.4 は、 変異の生存を検出線 (R-C12-1) として記録し、 deny への昇格は裁定 iduser の決定を指す印 付きの user 裁定でだけ行うことを求める。 C12.4 は検出線を撃つ時点を定めていない。 C13.5 は、 compile の秒を間隔ごとに記録する検出線とし、 劣化したら自動で起票し、 それで PR を止めないことを求める。 本 ADR は、 止めない線は PR の待ちにも載せない、 という C13.5 と同じ型で C12.4 を読む (止めない線が臨界路に座ると、 止めないはずの線が時間で便を止める)。 C13.5 の起票の半分 (生存の劣化で起票するか) は本 ADR の射程外で、 別の決定に残す。 C12.6 は main を常に緑に保つことを求める。 検出線は deny しないので、 着地の後に生存が出ても main は赤にならず、 着地を戻す経路は要らない (ADR-0043 が却下した「主実測を着地の後に非同期で撃つ」案は、 止める段を後回しにして main が赤のまま残る形で、 本 ADR の対象ではない)。 C15 は台帳を作業と裁定だけに使うことを、 SRS FR50 は land の終端が台帳へ close の 1 行以外を書かないことを求めるので、 着地後の結果を bead の notes と close の行へは写さない。 C10 は測定値と持ち越した値と測れなかった周を型で分けることを、 C17.2 は仕組みを足す前に消すものを名指すことを求める。 SRS の NFR6 / AC20 は変異検査の行を封じ込めの箱memory 上限の囲いの中で撃ち並列度を枠から取ることを、 FR46 は枠や箱が使えない周に並列度 1 で進むことを求め、 撃つ時点は定めない。 ADR-0009 §2.3 は変異検査を共通 verify に置き、 ADR-0021 §2.4 がそれを gate の③の段 (detection-verify) に移し、 木が同じ主実測では撃ち直さないと決め、 deny に昇格した行は共通 verify へ戻すと決めた。 ADR-0039 は候補の木で patch-id が不変の便の検出線を持ち越すと決めた。 ADR-0052 は mutant に当てる歯を契約の歯と単体の歯に閉じ、 その却下案に「検出線を gate の外へ出し着地した木に後追いで 1 回当てる」を置いた (2026-09-21 の裁定は A = 歯を絞る案を採り、 B = gate の外へ出す案を採らなかった)。 却下の理由は、 審査役が審査の時点で生存を見られなくなることと、 着地の後に生存が出た周の戻し方が要ることだった。 現物では審査役は生存を読んでおらず、 生存は deny しないので戻し方も要らない。 2026-09-23 の裁定は、 A が着地して尾が残った後に B の形を採った。 ADR-0050 も同じ案 (変異検査を着地の後へ回す) を OPT2 として退け、 理由を 3 つ挙げた。 ① 歯が空虚なまま main に入る窓ができる、 ② 着地後に生存が出た周の戻し方が要る、 ③ 混んだ host で行を撃ち続ける面が残る。 本 ADR の答えは次のとおり。 ① の窓は今も在る (生存は gate を止めず審査役も読まない) ので、 着地の後へ移しても新しく開く窓ではない。 ② は、 生存が deny しないので要らない。 ③ は、 着地後の検出着地の後の変異検査が今の gate の検出線の行と同じ受付札 (並列の枠) を取り、 同じ待ちの上限 (gate.slot_wait_s) と同じ遮断器を通ることで答える。 同時に走る本数は札の上限に数えられ、 混んだ host では待つが、 待ちの上限を過ぎた周は gate と同じく縮退して並列度 1 で撃つ (FR46)。 本 repo の共通 verify は並列度の穴 ({jobs}) を持たないので、 本 ADR の後の gate は札を取らず、 札を取り合うのは着地後の検出どうしになる。 gate との干渉は札でなく、 host の memory と遮断器を通る。 ADR-0050 の決定 (新しい宣言値の rules 行裁定つきの規則の行で同時本数の上限を作らない・便の同時本数の上限は ADR-0035 の行が持つ) は変えない。 ただし ADR-0035 の上限 (pipe.max_live) は終端でない便だけを数え、 Landed は終端なので、 着地後の検出はその上限の外に出る。 ADR-0053 は検出線を 1 段のまま残す判断を gate 1 本の時間と、 生存を「週次記録と審査役の材料である」とする読みで支えた。 本 ADR はその 2 つの前提 (時間は臨界路の外へ出る・審査役は生存を読まない) を動かすが、 ADR-0053 の決定 (段を足さない) とは矛盾しない。

CTX5

着地の後に撃つための材料は器に揃っている

着地した commit を tmp worktree に出して宣言の写しの行を撃つ形は主実測に在る (pipe/land/verify.rs)。 封じ込めの箱と器の健康の遮断器混んだら待つ仕組みは gate と主実測が同じ関数 (行を撃つ 1 本) で使っている。 並列の枠 (受付札・Admit) は gate だけが持ち、 主実測は通らないので、 着地後の検出は gate と同じ材料で受付を組む。 {teeth} の導出 (契約の写しの verify 行から) と穴の置換は gate と主実測が共有する。 検出線の record の形 (kind=detection・line・secs・skip の reason) と出力の写しの置き場も在る。 撃った段の record は tree を持たない (skip record だけが持つ) ので、 着地後の検出では任意 field として足す (ADR-0021 §2.4 が許す足し方)。 便の diff は着地した commit とその親の差分と同じで、 候補の木で着地した後続の便も自分の squash commit の親との差分が便の diff になる。 足りないものは 5 つある。 着地の後に検出線を撃つ口、 それを land から切り離して起こす 1 か所、 的と純移動の付け足しと写しの周の番号を gate の材料から剥がして両方から呼べる形にすること、 ③だけを受付・箱・遮断器ごと撃つ入口 (今の入口は ① と ④ を必ず撃ち、 行を撃つ関数は外から呼べない)、 そして写しの置き方 (測れなかった周と撃たなかった周の理由の file) である。 今の器に verify-main.jsonl を読む箇所は無い。 pipe show は出所を写し 1 本に閉じており (設計 gate-cost.md §15 (3)・C2)、 写しの dir の判定行と秒を出すが、 遮断器が閉じた周は道具が何も出さなかった周と同じ不在の 1 行になり、 撃たなかった周は写しを置かない (§15.1)。 pipe report は gate の秒と event だけを読む。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 便が本線に載るまでに待つ検査を「落ちたら止める検査」と審査役だけにすること、 変異検査を止めない線として測り続け、 測れなかったことを「通った」や 0 に化けさせないこと、 本線を常に緑に保ち、 載せた変更を戻す経路を足さないこと、 足す仕組みを 1 つの経路に閉じて消すものを名指すこと、 そして作業記録簿 (台帳) を作業と決定だけに保つことです。 向き (gate から外して本線に載った後に撃つ) は 2026-09-23 の user の決定で決まっており、 ここで比べるのはその形です。

DR1便が着地までに待つ段 (臨界路) を、 落ちたら止める段と審査役だけにする — 止めない線の秒 (2026-09-21 以後の gate 1 周で中央値 97.5 秒・検査の秒の約半分) を便 1 本の待ちから外す CTX1 (裁定)・CTX2 (実測)
DR2検出線の極性 (記録・PR を止めない) を保ち、 変異の生存を測って記録に残す。 測れなかった周を 0 や通ったに化けさせない CTX4 (C12.4 / C13.5 / C10)
DR3main を常に緑に保ち、 着地を戻す経路を足さない CTX4 (C12.6・ADR-0043 の却下との違い)
DR4足すものを 1 経路に閉じ、 消すものを名指す — 枠・箱・遮断器・record の形・event の種別は既存のものを使う CTX3・CTX5・CTX4 (C17.2)
DR5台帳を作業と裁定だけに保つ — 着地の後の測定を bead の notes と close の行に写さない CTX4 (C15・FR50)
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 gate から外して本線に載った後に器が切り離して撃つ案、 gate に残して時間だけ短くする案、 変異検査をやめる案、 実装役 (runner) に自分で撃たせる案、 別の列が本線に載った便を拾って撃つ案です。 却下した 4 案にも利点を並べ、 退けた決め手が user の決定か憲法か分析かを各案に書きます。 gate に残す案は、 審査の時点で結果が揃い器を変えずに済む点で、 やめる案は費用が丸ごと消える点で、 実装役に撃たせる案は同じ便の中で test を直せる点で、 別の列の案は同時に撃つ本数を 1 本ずつに絞れる点で、 選んだ案に勝ちます。

OPT1検出線を gate から外し、 便が Landed に達した後に land が器の子 process を切り離して 1 回撃つ採用

gate は ① write-set の照合・② 共通 verify・④ 契約 verify と審査役だけで判定を出す。 land は Landed の event を書いた後に、 着地後の検出の口を切り離した子 process で起こし、 その終わりを待たずに land の終端 (push → CI の照合 → close) へ進む。 子は着地した commit を tmp worktree に出し、 base を着地した commit の親にして、 宣言の写しの検出線を gate と同じ構築関数で組み (的と純移動の付け足しを含む)、 今の検出線の行と同じ受付札を取ってから、 同じ箱と遮断器で 1 回撃ち、 結果を主実測の record の file と run dir の写しと event に残す。 決め手は裁定。

変異検査を gate から外し、 便が本線に載った後に器が切り離して 1 回だけ撃つ案です。 gate は、 触ってよい file の照合、 どの便にも撃つ検証、 契約の検証の行、 審査役だけで判定を出します。 本線に載ったことを記録した後、 器は変異検査を撃つ口を別の process として切り離して起こし、 その終わりを待たずに、 本線を remote へ送って CI を確かめ作業記録簿の項目を閉じる続きへ進みます。 切り離した process は、 本線に載った commit を別の作業場所に出し、 載る前の本線との差分に対して、 gate と同じ関数で検査の行を組み、 これまで gate の変異検査が取っていた順番待ちの札を取ってから、 同じ memory の囲いの中で変異検査を撃ち、 結果を便の記録と出来事の記録に残します。 gate の 1 回から変異検査の時間が消え、 変異検査のためだけに在った経路も消え、 止めない線なので本線は赤になりません。 代わりに、 生き残りが分かるのは本線に載った後で、 本線に載った後の変異検査が gate と memory や混み具合の見張りを分け合って gate を待たせ、 同時に走る便の本数の上限の外で積み上がりえて、 切り離した process が死ぬと結果が欠け、 着地のたびに build をやり直します。 決め手は user の決定です。

+ 利点

  • gate の 1 周から検出線の秒が消え、 追随の再 gate も同じだけ軽くなる (DR1)
  • 検出線の rc 2 で gate が判定できずに便が居座る周、 同じ gate の中の撃ち直し、 持ち越しの record、 gate の中の検出線の閉じた 3 値 (撃つ・面の外で省く・持ち越す) が器から消える (面の判定は再 gate の省略と着地後の検出の skip に残る・DR4)
  • 検出線は同じ箱と枠で撃たれて記録に残り、 deny しないので main を赤にしない (DR2・DR3)

− 欠点

  • 生存が分かるのは着地の後で、 便の契約は close 済み。 歯の補強は orchestrator が record を読んで起こす次の契約になる
  • 着地後の検出は gate と host の memory と遮断器を分け合い、 走る間は gate の行が遮断器で待ち、 待ちの上限を超えた gate は INCONCLUSIVE になりうる。 Landed は便の同時本数の上限 (pipe.max_live) の外で、 着地後の検出どうしは札の上限で抑えられるが、 待ちの上限を過ぎると縮退して撃つ
  • 切り離した子や、 Landed の後で起こす前の land が死ぬと結果が欠ける (撃ち直しは人が同じ口を撃つ)。 着地のたびに tmp worktree で冷えた build を払う
OPT2検出線を gate に残し、 時間だけ短くする不採用

検出線を gate の verify 列に残したまま、 道具の時間の上限や枠の待ちの値を変えて尾を切る。 決め手は裁定 (臨界路から外す)。

変異検査を gate に残したまま、 道具の時間の上限や枠の待ちの値を変えて、 長い尾だけを切る案です。 審査の時点で結果が揃い、 器の経路を変えずに済む利点があります。 けれども中央値 97.5 秒 (2026-09-21 以後) の待ちは gate のたびに残り、 打ち切ったときは「測れなかった」になって判定できない gate が増えます。 打ち切りの秒を決める規則の行と user の決定も 1 つ増えます。 決め手は user の決定 (待ちの列から外す) です。

+ 利点

  • 審査の時点で生存が record に揃う
  • 器の経路を変えず、 足す口も消すものも無い

− 欠点

  • 中央値 97.5 秒 (2026-09-21 以後の周ごと) の待ちは gate の周ごとに残る (DR1)
  • 打ち切った周は測れなかった周になり、 判定できない gate が増える。 打ち切りの秒は rules 行と裁定を 1 つ増やす (設計 §33 で退けた形と同じ)
OPT3検出線を廃止する不採用

detection-verify の行を撃たず、 変異の生存を測らない。 決め手は憲法 (C12.4 は変異の生存を記録することを求める)。

変異検査をやめてしまう案です。 gate も host も変異検査の費用を払わず、 枠や記録の経路が丸ごと消えます。 けれども憲法は、 test が壊れた code に気づくかを記録し続けることを求めており、 やめるには憲法の改訂 (user の決定) が要ります。 変異検査を「止める線」に格上げするかを決める材料も無くなります。 決め手は憲法です。

+ 利点

  • gate も host も変異検査の費用を払わない
  • 枠・受付札・record・写しの経路が丸ごと消える

− 欠点

  • C12.4 に反し、 憲法の改訂 (user の裁定) が要る (DR2)
  • deny への昇格の裁定材料 (R-C12-1 の週次記録) が無くなる
OPT4runner に実装の段で検出線を撃たせる不採用

runner が gate へ出す前に自分で変異検査を撃ち、 生存を見て歯を補強する。 gate からは検出線を外す。 決め手は分析 (費用が runner へ移り、 測定が器の外になる)。

実装役 (runner) が gate へ出す前に自分で変異検査を撃ち、 生き残りを見て test を補強してから出す案です。 同じ便の中で test を直せ、 gate の時間からも変異検査が消えます。 けれども実装役の Claude が変異検査を待つ間も手番と文脈を消費し、 便 1 本の token が増えるので、 費用は gate から実装役へ移るだけです。 撃ったか、 何が生き残ったかが実装役の自己申告になり、 器が測った記録になりません。 実装役に変異検査を禁じている決まりも外すことになります。 決め手は分析です。

+ 利点

  • 生存を着地の前に、 同じ便の中で直せる
  • gate の 1 周から検出線の秒が消える

− 欠点

  • runner の Claude が変異検査を待つ間も手番と文脈を消費し、 便 1 本の token が増える (費用は gate から runner へ移るだけ・DR1)
  • 撃ったか・何が生き残ったかが runner の自己申告になり、 器の測定と record にならない (C10・DR2)。 runner に cargo mutants を禁じる語列も外すことになる
OPT5別の列 (dispatcher便を起こす器の口 の周か常駐の process) が着地済みの便を拾って撃つ不採用

着地済みで検出線の record の無い便を、 dispatcher の 1 周か host に常駐する process が拾い、 1 本ずつ撃つ。 決め手は分析 (拾う走査と待ちの状態が増え、 周が来ないと撃たれない)。

本線に載った便のうち変異検査の記録が無いものを、 便を起こす器の口 (dispatcher) の 1 周か、 host に常駐する process が拾って、 1 本ずつ撃つ案です。 同時に撃つ本数を 1 本ずつに絞れ、 本線に載せる process と撃つ主体が分かれる利点があります。 けれども dispatcher は時計を持たないので、 便が流れない間は周が来ず撃たれません。 常駐にすれば host に常駐の process と起動の登録が増えます。 記録の無い便を毎回探す仕組みと、 撃ち待ちの状態も器に増えます。 決め手は分析です。

+ 利点

  • 同時に撃つ着地後の検出を列が 1 本ずつに絞れる
  • land の process と撃つ主体が分かれる

− 欠点

  • dispatcher は timer を持たないので、 便が流れない間は周が来ず撃たれない。 常駐にすれば host に常駐の process と起動の登録が増える (DR4)
  • 「検出線の record の無い Landed の便」を毎周探す走査と、 撃ち待ちの状態が器に増える (C17.2・DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 gate は、 触ってよい file の照合、 どの便にも撃つ検証、 契約の検証の行、 そして審査役だけで判定を出し、 変異検査を撃ちません。 便が本線に載ったことを記録した後、 器は変異検査を撃つ口を本線の流れから切り離した別の process で起こし、 その終わりを待たずに、 本線を remote へ送り CI の結果を確かめて作業記録簿の項目を閉じる、 という続きの 3 手へ進みます。 切り離した process は、 本線に載った commit を別の作業場所に出し、 載る前の本線との差分に対して、 gate と同じ関数で検査の行を組み、 これまで gate の変異検査が取っていた順番待ちの札を取ってから、 同じ memory の囲いの中で変異検査を 1 回撃ち、 結果を便の記録と出来事の記録に残します。 測れなかったときや混み具合の見張りに止められたときもそのまま記録し、 自動では撃ち直しません。 生き残りが出ても本線は戻さず、 作業記録簿の項目には写しません。 変異検査が「止める線」に格上げされたときだけ、 その行は gate の検証へ戻ります。 本線の差分が器の code と設定に触れない回に再検査を省く仕組みは残します。 要件書では、 gate が契約の検証で判定する要件 (FR8) と、 本線に載った後の 3 手と作業記録簿に 1 行だけ書く要件 (FR50) の根拠になり、 追随の再検査 (FR34)・枠が無いときの縮退 (FR46)・memory の囲い (NFR6) がそのまま効くことを示します。

採用 — OPT1

器 SHALL gate の判定を ① write-set の照合・② 共通 verify・④ 契約 verify と lens だけで出し、 vessel 宣言の detection-verify の行 (検出線) を gate でも主実測でも撃たない。 検出線 SHALL 便が Landed に達した後に器が 1 回だけ撃つ (着地後の検出)。 land SHALL Landed の event を書いた後に着地後の検出を器の口 1 つ (名は設計 doc が決める) の子 process として切り離して起こし、 その終わりを待たずに land の終端へ進む。 着地後の検出 SHALL 着地した commit を tmp worktree に出し、 {base} を着地した commit の親とし、 {teeth} を便の契約の写しから導き、 行を intake が凍結した宣言の写しから取って、 的 (設計 §16) と純移動の母集団 (設計 §14) の付け足しを gate と同じ構築関数で行う。 撃つ前に今の検出線の行と同じ受付札 (並列の枠) を取り、 同じ待ちの上限 (gate.slot_wait_s)・封じ込めの箱・器の健康の遮断器を通す (縮退は FR46 のまま)。 着地した diff が検出線の面に触れない周 SHALL 撃たず理由付きの skip record を残す。 結果 SHALL 主実測の record の file (verify-main.jsonl) に kind=detection の record (schema 1 のまま・tree・line・secs を持つ) を追記し (任意 field 1 つで主実測の record と本 ADR 以前の kind=detection から分ける・名は設計 doc)、 出力の写しを設計 gate-cost.md §15 の置き場 (run dir の detection の周の dir) に置き、 測れなかった周と撃たなかった周はその置き場に理由の file を置く。 record は撃った便自身の run dir の verify-main.jsonl に追記する (列の後続の便は新しく作る)。 起こした周と終えた周に RunDone stage=Landed の detail を 1 件ずつ記す (detection で始まる閉じた 1 語・着地の sha と終端の前置き (sha と terminal) を含まない・event の種別は足さない)。 rc 2 と遮断器が閉じて撃たなかった周 SHALL 測れなかった record (理由付き) のまま残し、 自動で撃ち直さない。 pipe show SHALL 今の読み手のまま写しから 1 行を出し、 record の行は足さない (出所は写し 1 本のまま・§15 (3))。 起こせなかった周 SHALL 着地を取り消さず理由を記す。 main-red と main-unmeasured で進んだ commit には SHALL NOT 撃たない (Landed に達していない)。 器 SHALL NOT 着地後の検出の結果を bead の notes と close の行へ写す (C15・FR50)。 検出線の生存と rc 1 SHALL 着地を戻さない (C12.4)。 R-C12-1 が deny に昇格した周、 その行 SHALL 同じ便で共通 verify へ移り gate で撃たれる (ADR-0021 §2.4 の移し方は不変)。 これに伴い gate SHALL 検出線の rc 2 を INCONCLUSIVE に倒す判定・同じ gate の中の撃ち直し・検出線の持ち越し (patch-id の record)・追随と候補の木の検出線の要否の判定・主実測の面の判定を持たない (面の判定は、 追随の再 gate の省略 (§33) と着地後の検出の skip の 2 か所に残る)。 追随で main の差分が面の外だけの周に再 gate を省いて前周の PASS を引き継ぐ判定 (pipeline.md §33) SHALL 不変とする。 ADR-0052 の穴 {teeth} と検出の母集団、 ADR-0043 の同じ木の主実測同じ木なら撃たないの record 1 本、 ADR-0050 の決定、 R-C12-1 の極性と値 SHALL 不変とし、 本 ADR は rules 行を足さない。

gate の判定は、 触ってよい file の照合、 どの便にも撃つ検証、 契約の検証の行、 そして審査役だけで出します。 変異検査 (検出線) は gate でも、 本線に載った直後の検査でも撃ちません。 変異検査は、 便が本線に載ったことを記録した後に、 器が 1 回だけ撃ちます。 本線に載せる手順 (land) は、 載ったことを記録した後に、 変異検査を撃つ器の口 1 つを本線の流れから切り離した別の process として起こし、 その終わりを待たずに、 本線を remote へ送り CI の結果を確かめ作業記録簿の項目を閉じる続きの 3 手へ進みます。 切り離した process は、 本線に載った commit を別の作業場所に出し、 載る前の本線を比べる起点にし、 当てる test の名前を便の契約の写しから導き、 撃つ行を受付で凍結した宣言の写しから取り、 狙う file や、 移しただけの変更で検査の範囲を絞る付け足しを gate と同じ関数で行います。 撃つ前に、 これまで gate の変異検査が取っていた順番待ちの札を取り、 同じ待ちの上限と memory の囲いと混み具合の見張りを通します (枠が無いときは並列 1 で進みます)。 本線に載った差分が変異検査の対象の場所に触れないときは撃たず、 理由付きの記録を残します。 結果は、 本線に載った直後の検査の記録 file に変異検査の行として追記し (直後の検査の行とは種類で分けます)、 道具の出力の写しを便の置き場に置き、 起こしたときと終えたときに出来事の記録を 1 件ずつ書きます (出来事の種類は増やさず、 書く語は決まった 1 語で、 着地の sha の読み取りと混ざる語は使いません)。 測れなかったときや、 混み具合の見張りに止められて撃てなかったときは、 理由付きでそのまま記録し、 自動では撃ち直しません (撃ち直すのは人です)。 起こせなかったときも、 本線に載せたことは取り消さず理由を書きます。 本線が赤いまま進んで着地に至らなかった commit には撃ちません。 結果を作業記録簿の項目の注記や閉じる行には写しません。 生き残りが出ても、 本線は戻しません。 変異検査の規則の行が user の決定で「止める線」に格上げされたときは、 その行を同じ便でどの便にも撃つ検証へ移し、 gate で撃ちます。 これに伴い、 gate からは、 変異検査が測れなかったときに判定できないとする扱い、 同じ gate の中の撃ち直し、 前の結果の使い回し、 変異検査のための対象の場所の判定を消します。 本線の差分が器の code と設定に触れない回に再検査を省いて前の合格を引き継ぐ仕組みは残します。 変異検査の出力の写しは今と同じ置き場に置き、 測れなかった回と撃たなかった回はそこに理由の file を置くので、 便ごとの記録を見る道具は今のまま写しから 1 行を出します (記録の出所は写しの 1 本のままです)。 列でまとめて着地した後ろの便も、 自分の記録 file に書きます。 当てる test の選び方 (ADR-0052)、 木が同じなら直後の検査を記録 1 行で済ませる形 (ADR-0043)、 同時本数の上限を規則の行で作らない決定 (ADR-0050)、 変異検査の規則の行の向きと値は変えず、 規則の行も足しません。 変異検査は、 生き残りが出ても便を止めない約束の検査です。 止めない検査の終わりを gate が待つと、 止めないはずの検査が時間で便を止めることになります。 2026-09-21 以後の実測では変異検査が gate 1 回の検査の時間のおよそ半分 (1 回ごとの割合の中央値 53%) を占めていたので、 待ちの列から外せば、 便が通る gate のたびに待ちが縮みます。 憲法は変異検査の結果を記録することを求めますが、 撃つ時点は決めていません。 compile の時間を記録するだけの線を PR の待ちに載せないのと同じ型で、 変異検査も待ちの列の外で記録します。 本線に載った後に撃っても、 変異検査は本線を止めない線なので、 生き残りが出ても本線は赤にならず、 載せた変更を戻す経路は要りません。 前の決定は、 審査役が審査の時点で生き残りを材料にできることを理由に gate の中に残しましたが、 現物の審査役は契約と差分だけを読み、 変異検査の結果を読んでいません。 別の前の決定は、 混んだ machine で重い検査が走り続けることも理由に同じ案を退けました。 この記録は、 本線に載った後の変異検査にも今の変異検査と同じ順番待ちの札と待ちの上限と混み具合の見張りを通させ、 同時本数を札の上限に数えることで答えます。 待ちの上限を過ぎたら並列 1 に絞って撃つのは今と同じです。 新しい規則の行で本数の上限を作らない、 という前の決定もそのまま守れます。 検査の行を組む関数、 札、 memory の囲い、 記録の形は器に在るので、 足すのは切り離して起こす 1 か所と撃つ口と、 gate の中にしか無い行の組み立てを取り出すことと、 変異検査だけを撃つ入口と、 測れなかった回と撃たなかった回の理由を写しの置き場に残す置き方の 5 つで、 変異検査のためだけに gate に在った経路 (測れなかったときの扱い・撃ち直し・使い回し・gate の中の場所の判定) は消せます。 変異検査のための場所の判定は、 本線に載った後に 1 回だけ行います。 同じ判定は、 追随の再検査を省くかを決めるためにも残ります。 器の code と設定に触れない回に再検査を省く仕組みを残すのは、 それが変異検査とは別に着地の列の飢えを防いでいるからです。 測れなかったときに自動で撃ち直さない理由は 2 つの面から見ます。 今の撃ち直しは、 便の待ちを減らすだけでなく、 判定できない gate が測り直させることで、 載る便に必ず結果を持たせていました。 待ちの外では撃ち直しても便の待ちは減らないので自動の撃ち直しは足しませんが、 その代わりに結果を持たない便が残りえます。 記録を見る道具は写しだけを読むので、 測れなかった理由を写しの置き場に残せば、 今の道具のまま 1 行で見えます。 それが見えるようにしたうえで、 撃ち直すのは人の手番にします。 結果を作業記録簿の項目に写さないのは、 作業記録簿を作業と決定だけに使い、 本線に載った後に書くのは項目を閉じる 1 行だけ、 という決まりを守るためです。 gate に残して時間だけ削る案は待ちが残り、 やめる案は憲法に反し、 実装役に撃たせる案は費用が移るだけで記録が自己申告になり、 別の列で拾う案は周が来ないと撃たれず探す仕組みが増えるので退けました。

便が Landed に達した後に、 器が land から切り離した子 process で検出線の行を 1 回撃つこと (本 ADR)。 着地した commit を tmp worktree に出し、 base は着地した commit の親で、 gate と同じ並列の枠と封じ込めの箱を通る。 撃つ前に今の検出線の行と同じ受付札を取る。 結果は record と event に残し、 着地は戻さない。
臨界路critical path
便が着地までに必ず待つ段の列 (runner → gate → land)。 この列に座る段の秒は便 1 本の待ちに足される。 本 ADR は検出線をこの列から外す。
gategate
便の成果物を独立に検証して Verdict を返す機構。 MVP は契約の verify の実走 + lens 1 本 (SRS FR8 / FR9)。 crate の gate module が担う。 歯 (test / lint / CI) とは別の entity。
共通 verifycommon verify
どの便にも共通の deny する検証 (flip check・test・lint・依存監査) を対象 repo の vessel 宣言に置き、 intake が便ごとに凍結した写しを gate が契約 verify の前に撃つもの (C2・ADR-0009 / ADR-0010)。 検出線の行は別の列 (detection-verify・ADR-0021 §2.4) に置き、 契約の verify は便固有の行だけを持つ。
land の終端land terminal
着地の後に器が続ける 3 手 (remote への push・着地 commit の CI の結果の照合・台帳の close) と、 その typed な記帳 (SRS FR50)。 着地の事実の正本は器の record で、 commit の trailer はそこからの導出面 (ADR-0023 §2.5)。
同じ木の主実測same-tree main check
便が main に着地した直後の検査 (主実測) のうち、 着地する commit の木の sha が gate の verdict の tree と一致する周のもの。 木の sha の一致を gate の測定の再現と見なし、 全段を撃たず record 1 本で残して着地を進める (ADR-0043)。
検出の母集団detection population
mutant ごとに走らせる歯の集合 (ADR-0052)。 package の lib の歯と bin の歯と、 契約が名指した歯。 この集合が捕まえない mutant が変異の生存として記録される (C12.4・R-C12-1)。
契約の歯の穴contract teeth hole
宣言 file の検出線の行に置く 4 つ目の穴 {teeth} (ADR-0052)。 器が契約の verify 行から導いた歯の名の列で埋め、 道具は受けた語をそのまま filter に使う。 語が無い周は空を表す閉じた 1 語で埋める。
並列の枠mutation parallel slot
host 単位で便の変異検査に配る並列の枠 (SRS NFR6)。 契約を便にする前の検査の段 (受付) とは別。 置き場は state dir の親の下の host 用 dir で project をまたぎ、 枠 1 組は受付札 1 つで表す (ADR-0021 §2.3)。 器が管理する状態ではなく受付の一時的な印。
封じ込めの箱confinement box
封じ込めが process を閉じ込める memory 上限付きの囲い (systemd-run --user --scope で作る transient scope)。 上限を超えると殺されるのはその中の process だけ (ADR-0021 §2.2・ADR-0040)。
器の健康の遮断器vessel health breaker
verify の行を撃つ前に走行可能な process と待ちの process を読み、 閾値と比べて空いている / 混んでいる / 測れないの 3 値を返す境界 (ADR-0050)。 混んだ周は待ち、 待ち切れなかった周は行を撃たない。 行為を止めうるので極性一覧に載る guard。
vessel 宣言vessel declaration
対象 repo の root に marker の隣として置く tracked file .vessel.toml。 その repo の allowlist と共通 verify を repo 自身が名乗る宣言値で、 intake が manifest の上限と突合して便ごとに写しへ凍結する (C10・ADR-0010)。 marker そのものは変えない。
rules 行rules row
manifest に置く規則の値 1 行 (閾値・有効/無効・裁定 id・裁定時刻・逐語)。 数値の置き場 (C1) で、 変更の手続きは C5。 変異の生存の極性は R-C12-1 の行が持ち、 本 ADR は行を足さない。
裁定 idruling id
user 裁定を一意に指す id。 器が打った裁定 event の ts (UTC) で、 rules 行の ruling 欄が指す。 rules 行の変更 (C5)、 閾値変更 (A2)、 憲法改訂 (N4) が要求する。
台帳ledger
作業 (issue) と裁定の記録。 実体は beads で、 v2 は自前の台帳を持たない。 本 ADR の着地後の検出の結果は bead の notes と close の行に写さない (C15・FR50)。
event logevent log
1 行 1 出来事を追記する file。 fleet の現在地はこれを replay して導く (C3・SRS FR3)。 本 ADR の着地後の検出は、 起こした周と終えた周をここに 1 件ずつ記す。
lenslens
diff を読んで verdict (PASS / FAIL / INCONCLUSIVE) を返す headless の Claude process (SRS FR9)。 MVP の gate は lens 1 本。 審査の材料は契約と diff で、 検出線の record は読まない (現物)。
runnerrunner
契約 1 本を worktree で実装する headless の Claude process (SRS FR4 / FR5)。 席ではなく使い捨て。 禁じる語列で変異検査を撃てない。
dispatcherdispatcher
台帳から起動の列を導き、 便の終端の直後・手動の 1 周・介入の印の直後に便を起こし、 gate を通った便を land する器の口 (SRS FR68 / FR50)。 周期の timer を持たず、 本 ADR でも変えない。
orchestratororchestrator
席の唯一の役割。 user と話し、 承認と裁定を受け取り、 契約・設計・落ちる歯を書く。 本 ADR では、 着地後の検出の record を読んで歯を補強する次の契約を起こす。
