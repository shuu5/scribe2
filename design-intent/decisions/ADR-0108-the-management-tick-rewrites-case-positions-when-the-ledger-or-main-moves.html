設計判断記録 (ADR) scribe2 — 管理 tick の全部の書き直し

管理 tick の全部の書き直し — 台帳か main の印が局面の出力の印と等しくない周に、 rules 行 lifecycle.full_min_s の下限を空けて既存の書き手 1 本を撃ち、 台帳 client の場所は host の面の宣言で渡す (ADR-0088 の管理 tick の句・ADR-0064 の 3 句・ADR-0058 が戻した unit の形の 2 句を部分 supersede)

局面の出力を全部書き直すのは、 便を回す周・land の終端・口を撃った時だけで、 便を回さない置き場では台帳が変わっても出力が古いまま残る。 本 ADR は、 管理 tick の周に台帳と main の印 (小さい file の読みだけ) を出力の印と等しさで比べ、 違っていて前の書き直しから rules 行の下限 (300 秒) が経った周だけ、 既存の書き手 1 本で全部を書き直すと決める。 systemd の timer には台帳 client の bd が見えないので、 その場所は seat tick の flag と host の面の表 [[tick]] の任意の key で渡し、 宣言を受けた unit だけ起動の行の末尾に載せ、 器は env を読まない。

この判断が約束すること (1 文サマリ)

この決定で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session、 「便」は契約 1 本を実装して main へ入れる 1 回の走り、 「台帳」は作業と裁定を記録する beads です。 器は、 仕事の一つ一つが今どこにいるか (局面) を置き場ごとに 1 つの file (局面の出力) に書き、 画面や知らせはそれを読みます。 この file を丸ごと作り直す (全部の書き直し) のは、 便を回す周・器が台帳を書いた直後 (着地の終わりなど)・作り直しの口を撃った時だけなので、 便を回さない置き場では、 台帳が変わっても file が古いまま残ります。 この決定は、 席を周期で見ている時計 (管理 tick) が、 台帳と main の小さな目印だけを毎回 file の目印と比べ、 違っていて前の作り直しから 300 秒 (規則の表 (rules) の値・user の裁定) が経った回だけ、 今と同じ書き手で作り直しを 1 回撃つと決めます。 時計からは台帳を読む道具 (bd) が見えないので、 その場所は時計の flag と host ごとの設定 file の宣言で渡し、 宣言を受けた時計だけが起動の行の末尾にそれを持ち、 器は環境変数を読みません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 5 つで示します。 便を回さない置き場では台帳が変わっても file が古いまま残り、 隣の project の設計席が数分の遅れで出してほしいと頼んだ経緯。 作り直し 1 回の重さと、 目印の読みの軽さの実測。 時計と作り直しの書き手の今の形。 時計からは台帳を読む道具が見えないという実測。 憲法と前の決定の向きと、 この決定が動かす範囲です。

CTX1

経緯 — 便を回さない置き場では、 台帳が変わっても局面の出力案件の今を書いた fileが古いまま残る

局面の出力の全部の書き直し出力を丸ごと作り直すは、 dispatch の周・器が台帳を書いた直後 (land の終端の close など)・全部を書き直す口の 3 つの契機でだけ撃たれ (設計 case-lifecycle §12)、 管理 tick席を周期で見る時計 の周は event log と時刻で決まる部分だけを書き直す (§13)。 ADR-0088 と FR90 は、 管理 tick の周が台帳も git も撃たないと決めた。 dispatch の周は timer を持たない (FR68) ので、 便を回さない置き場では、 台帳が変わっても、 次に便が回るか誰かが口を手で撃つまで出力は書き直されない。 2026-10-01、 隣の project の設計席が、 その project の画面 (板の一覧) は局面の出力を読むので、 便を回していない間も台帳の変化を出力に出してほしいと頼んだ。 5 分ほどの遅れなら足りるという条件つきである (memo s2-07l.738.42.1)。

CTX2

現物 — 全部の書き直しは 1 回 4〜14 秒かかり、 入力の印読んだ元の目印の読みは bd も git も撃たない

全部の書き直し 1 回は、 本 repo の台帳 (chunk 約 36 万)・event log 9.3 MB・設計 doc 30 本で、 空いた host で wall 4.3 秒・user 3.8 秒・最大 RSS 275 MB、 gate が走る host で wall 14.3 秒・user 3.7 秒だった (2026-10-01 の実測)。 全部の書き直しは台帳を bd の読み (--readonly) で読むので台帳の印を動かさず、 同じ置き場へ 2 回続けて撃つと 2 回目は Coalesced で generated が進まなかった (同日の実測)。 入力の印の読みは、 台帳は .beads の manifest の 1 file (embedded の形) か issues.jsonl の stat (files の形)、 main は refs/remotes/origin/main の loose の ref か packed-refs の読みで、 bd も git も撃たない。 印の順の比べのうち main の祖先の関係を見る比べだけが git を撃つ。 局面の出力は、 最後の全部の書き直しの時刻 full_at と、 読んだ入力の印 (欄 inputs の ledger・events・main) を持つ。

CTX3

現物 — 管理 tick は席ごとの timer で 15 秒ごとに回り、 全部の書き直しの書き手と口は 1 本に揃っている

管理 tick は、 器が席ごとに導出した systemd の user の service と timer の対 (ADR-0058 が戻した ADR-0030 の形・ADR-0064 が席の起動で入れる) が rules 行 seat.tick_interval_s (今の値 15 秒) ごとに撃つ oneshot である。 tick の 1 周は判定と打刻の後に部分の書き直し時刻で動く所だけ直すを撃ち、 その返りを捨てる (tick の rc と字は変えない)。 全部の書き直しの書き手は 1 本で、 置き場の lifecycle.lock を死んだ所有者だけ外す取り方で取り、 撃った時の印より今の出力の印が古くなければ書かず (Coalesced)、 返りは閉じた 6 値 (Written・Unchanged・Coalesced・Discarded・Busy・Unreadable) である。 口 fleet lifecycle write は、 同じ 1 本を観測の 1 周 (便を起こさない列の判定) と共に撃ち、 --bd で台帳 client台帳を読み書きする道具 を受け、 lock を既定の時間まで待つ (--wait-ms N で待つ時間を変えられる)。 口の text は、 Written・Unchanged・Coalesced・Discarded の 4 つの返りで同じ show の字を出し、 ほかは lifecycle=busy か lifecycle=unreadable の 1 行を出す。 入力を読めない周は書き直さず、 出力に読めない印 (理由の 1 語・台帳なら ledger) を付ける。

CTX4

現物 — systemd の user の PATH に台帳 client が無く、 tick の unit は env を持たない

tick の unit の ExecStart は <binary> seat tick --state-dir S --target S:W (rules の写しを渡す周だけ --rules F) で、 Environment= も WorkingDirectory= も持たない (path は全部引数の値・C2.2)。 host の面host ごとの設定 fileの表 [[tick]] は unit を置く dir と器の場所の 2 つの欄を絶対 path で持ち (ADR-0064)、 既知の key と必須の key が同じ 2 つの列なので、 任意の key を持てず未知の key を行番号つきで断る。 器はそれらを env・home・自分の実行 file の場所から解かない。 unit を手で入れる口 seat tick install と uninstall は引数だけで導出し (面を読まない)、 印は在るが bytes の違う file を unit-exists で断って動かさない。 doctor は --unit-dir と --binary の flag の組が在ればそれを、 無ければ面の [[tick]] を導出の引数に使う (flag が勝つ)。 systemd の user の PATH には台帳 client の bd が無い。 PATH に bd の無い env で口 fleet lifecycle write を撃つと lifecycle=unreadable (理由 ledger) で、 --bd に bd の絶対 path を渡すと書けた (2026-10-01 の実測)。 tick の周から全部の書き直しを撃つには、 台帳 client の場所を器に渡す道が要る。

CTX5

憲法と既存の決定の向き — 閾値は裁定つきの rules 行・env は読まない・足す前に消すものを名指す、 と本 ADR の射程

C1 と C5 により、 書き直しの下限次に試すまでの最短 (全部の書き直しの間の最短の秒数) は rules 行 1 本に置き、 user の裁定 id を要る。 下限の値は 300 秒と裁定された (台帳の問い s2-07l.738.42.3・裁定 id s2-07l.738.42.3:20261001T1527Z-1・行の裁定の字 user 2026-10-01T15:27Z)。 C2.2 により器は env を読まず新しい env の口を作らず、 C10.2 により host 固有の値は host の面と引数にだけ置く。 C17.2 により、 rules 行・記録・仕組みを足す前に消すものを名指す。 N2 により、 散文の手順にしか無い規則は規則と認めない。 ADR-0088 の決定 (3) は、 管理 tick の周は台帳も git も撃たず部分だけを書き直すと定め、 FR90・FR27・AC60 も同じ向きの字を持つ。 本 ADR が動かすのは、 管理 tick の周に条件つきの全部の書き直しを足すこと・その下限の rules 行・撃った記録の file・seat tick の flag --bd・host の面の表 [[tick]] の任意の key bd・bd を受けた unit の導出だけ ExecStart の末尾に --bd を載せること・seat tick install と uninstall と doctor の --bd・席の起動が面の bd を導出に渡すことである。 動かさないのは、 ほかの契機・書き手・部分の書き直し・印の読みと順の比べ・古さの印・読み手・tick の判定の列と rc と字で、 SRS の字の直しは別の round が持つ。 ADR を書く条件のうち 1 (C2.2・C5・C17.2 の読み)・3 (rules 行の kind・記録の file・host の面の key)・4 (却下案を残す価値のある分岐) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 便を回さない置き場でも変化を数分で file に入れること。 変化の無い回は重い読みを撃たないこと。 重い作り直しの頻度を裁定つきの値で縛ること。 書き手と書き方を 1 本のまま使い、 新しい書き手も時計も足さないこと。 道具の場所を器が見える宣言で受け、 環境変数を読まないこと。 時計の結果と読み手を変えず、 足す前に消すものを名指すことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 8 つ並べます。 時計が目印を等しさで比べ、 裁定した間隔を空けて今の書き手を撃ち、 道具の場所を宣言で渡す案 (選んだ案) と、 選ばなかった 7 つです。 選ばなかった案は、 出来事の log (event log) の目印も比べる案・目印を git の前後関係で比べる案・file を読む側が自分で周期に撃つ手順にする案・作り直し専用の時計を足す案・間隔を持たないか code の定数で持つ案・時計が作り直しの口を別の process で撃つ案・systemd の環境の file で道具を見つけさせる案です。

OPT1管理 tick が印を等しさで比べ、 rules 行の下限を空けて既存の書き手 1 本を撃ち、 台帳 client の場所は宣言で渡す採用

管理 tick の周の終わりに、 登録 row の anchor の台帳の印と main の sha を出力の inputs と等しさで比べ、 どちらかが違い、 出力の full_at と撃った記録試した時刻の記録の新しい方から rules 行 lifecycle.full_min_s 秒が経った周だけ、 口 fleet lifecycle write と同じ書き手 1 本を lock を待たずに撃ち、 記録に 1 行残す。 台帳 client は seat tick の --bd と host の面の表 [[tick]] の任意の key bd で渡し、 宣言を受けた unit の ExecStart だけが末尾に --bd を持つ。 決め手は実測の費用と軽い印の読み (CTX2・CTX4) と頼みの遅れの条件 (CTX1)。

時計 (管理 tick) が毎回、 台帳と main の目印を file の目印と比べ、 どちらかが違い、 前の作り直しと前の試みの新しい方から 300 秒が経った回だけ、 今と同じ書き手で作り直しを 1 回撃ちます。 書き手が使用中なら待たずに次へ回し、 撃った記録に 1 行残します。 台帳を読む道具の場所は、 時計の新しい flag と host の設定 file の key で渡し、 受けた時計だけが起動の行の末尾にそれを持ちます。 便を回さない置き場でも変化が数分で file に入り、 変化の無い回は小さい file を読むだけで済み、 作り直しは 300 秒に 1 回までで、 書き手も時計も増えず、 器は環境変数を読みません。 時計を入れる口と外す口は引数だけで組むので、 設定 file を書き換えた前後でも同じ引数で古い時計を外せ、 確かめる口は flag で入れた時計を flag の組で確かめられます。 時計の結果の字と file の読み手は変わらず、 file を直すために口を手で撃つ手番も消えます。 代わりに、 最長で 300 秒と時計の周期の和の遅れがあり、 席が動く間は台帳がよく動くので 300 秒ごとに 4 秒から 14 秒の作り直しが掛かり、 その間はほかの書き手が待つか飛びます。 撃つ回の時計は約 275 MB と数秒から十数秒を抱え、 書き手が異常に終われば時計も異常に終わります。 失敗した回も次の試みは 300 秒後になり、 1 つの置き場に repo の違う席が在ると作り直す repo が入れ替わりえ、 道具の場所を宣言せず時計の PATH にも bd が無い host では作り直しが台帳を読めないまま残り、 時計が既に在る host で設定 file に道具の場所を足すには、 古い引数で時計を外してから入れ直す順が要り、 設定 file に道具の場所を書くのは本体を新しい版に入れ替えた後になります。

+ 利点

  • 便を回さない置き場でも、 台帳か main の変化が最長で下限と tick の周期の和の後に出力に入る (DR1)
  • 印が動かない周は小さい file の読みと等しさの比べだけで、 bd も git も撃たない (DR2)
  • 重い書き直しは下限ごとに 1 回までで、 下限の値は裁定 id つきの rules 行が持つ (DR3)
  • 書き手・lock・coalesce・返りの 6 値は既存の 1 本のままで、 新しい unit も書き手も足さない (DR4)
  • 台帳 client の場所は host の面の宣言と引数で器に見え、 器は env を読まない (DR5)
  • install と uninstall は引数だけで導出するので面の書き換えの前後でも同じ引数で古い unit を外せ、 doctor は flag で入れた unit を flag の組で確かめられる (DR5)
  • tick の rc と字と読み手は変わらず、 便を回さない置き場で口を手で撃つ手番が消える (DR6)

− 欠点

  • 台帳か main の変化が出力に入るまで、 最長で下限と tick の周期の和 (今の値で 300 秒と 15 秒) かかる
  • 席が動く間は台帳がよく動くので、 全部の書き直しは 300 秒ごとに 1 回 4〜14 秒かかる
  • 書き直しの間 (空いた host で約 4 秒・gate が走る host で約 14 秒) は lock を持つので、 ほかの書き手は待つか Busy で飛ぶ
  • 撃つ周は tick の process が書き直しを抱え、 最大 RSS 約 275 MB を持ち、 1 周が 4〜14 秒延びる。 書き手が panic すると tick が異常に終わり、 rc を変えない約束の外になる
  • 撃った記録は返りに依らず書くので、 Busy や Unreadable で終わった周も次の試みは下限の後になる
  • 1 つの置き場に anchor の違う席が 2 つ以上在ると、 tick ごとに違う repo の印と比べ、 下限ごとに違う repo で書き直しうる
  • 台帳 client を宣言せず timer の PATH にも bd が無い host では、 撃った記録が wrote=unreadable のままになる
  • unit の既に在る host で面に bd を足すと導出の bytes が変わるので、 古い引数での uninstall から入れ直す順が要る
  • 古い binary は面の key bd と flag --bd を断るので、 面に bd を書くのは binary を新しい版に入れ替えた後になる
OPT2event log の印も比べる不採用

台帳と main の印に加えて、 出力の inputs.events (event log の長さ) も今の長さと比べ、 違えば全部を書き直す。 決め手は event log の伸び方と部分の書き直しの受け持ち (CTX2・CTX3)。

台帳と main に加えて、 出来事の log (event log) の長さも file の目印と比べる案です。 3 つの目印を全部比べるので形がそろい、 長さも 1 file の大きさを見るだけで取れる点で勝ります。 けれども、 出来事の log は席や便が動く間ほぼ毎回伸びるので、 台帳も main も動かない間も 300 秒ごとに 4 秒から 14 秒の作り直しを撃ち続けます。 選んだ案でこの費用が掛かるのは、 台帳か main が動いた間だけです。 出来事の log と時刻で決まる部分は、 すでに一部の書き直しが毎回書いています。

+ 利点

  • 出力が持つ入力の印 3 つを全部比べるので、 比べの形が対称で、 どの入力が動いた周も全部の書き直しで揃う
  • event log の長さも 1 file の大きさの読みで取れ、 bd も git も撃たない

− 欠点

  • event log は席と便が動く間ほぼ毎周伸びるので、 台帳も main も動かない間も下限ごとに 1 回 4〜14 秒の書き直しと lock を使う。 OPT1 でこの費用が掛かるのは台帳か main が動いた間だけである (DR2・DR3)
  • event log と時刻で決まる部分は、 既に部分の書き直しが毎周書いている (DR4)
OPT3印を順 (git の祖先の関係) で比べる不採用

等しさでなく、 今の印が出力の印より新しいかを順で比べ、 新しい周だけ撃つ。 main の順の比べは git を撃つ。 決め手は比べの費用と書き手の受け持ち (CTX2・CTX3)。

目印が違うかどうかでなく、 今の目印が file の目印より新しいかを git の前後関係で比べる案です。 目印が古い側へ戻った回を動いたと数えず、 書き手が捨てるだけの作り直しを撃たずに済み、 書き手と同じ判じ方になる点で勝ります。 けれども、 main の目印が違う間、 この比べを 300 秒の判定より前に置くと時計の回ごと (今は 15 秒ごと) に git を撃つことになり、 毎回の比べが軽くなくなります (判定の後に置けば撃つ回だけです)。 動いたかどうかは等しさで足り、 古い書きは書き手が自分で捨てるので、 同じ比べを時計に写すだけになります。

+ 利点

  • 印が古い側へ戻った周 (順で古い印) を動いたと数えず、 書き手が捨てるだけの書き直しを撃たない
  • 書き手が lock の中で古い書きを捨てる判じ方と同じ順の読みになる

− 欠点

  • main の印が違う間、 順の比べを下限の判定より前に置くと tick の周 (今の値で 15 秒) ごとに git を撃ち、 毎周の比べが軽くなくなる。 下限の判定の後に置けば git は撃つ周だけになる (DR2)
  • 「動いた」は等しさで足り、 順は書き手が lock の中で比べて古い書きを捨てる (Discarded) ので、 tick の側に同じ比べを写すだけになる (DR4)
OPT4消費側が口 fleet lifecycle write を周期で撃つ手順にする不採用

器は変えず、 局面の出力を読む消費側の project が、 自分の timer か手順で全部を書き直す口を周期で撃つ。 決め手は N2 と器が測れるか (CTX1・CTX5)。

器は変えず、 file を読む側の project が自分の時計や手順で作り直しの口を周期で撃つ案です。 器に code も規則の表 (rules) の行も足さず、 読む側が周期と置き場を選べる点で勝ります。 けれども、 文章の手順にしか無い決まりで、 器は撃たれたかも周期も測れず、 守られなかった回も見えません。 読む側ごとに同じ時計と手順を持ち、 置き場が増えるたびに写す手が要り、 道具の場所の問題もそのまま残ります。

+ 利点

  • 器に code も rules 行も足さず、 口は既に在る
  • 消費側が要る周期と置き場を自分で選べる

− 欠点

  • 散文の手順にしか無い規則で、 器は撃たれたかも周期も測れず、 守られなかった周も見えない (N2・DR6)
  • 消費側ごとに同じ timer と手順を持ち、 便を回さない置き場が増えるたびに写す手が要る (DR4)
  • 消費側の timer にも台帳 client の場所の問題が同じ形で残る (DR5)
OPT5書き直し専用の timer unit を足す不採用

管理 tick と別に、 置き場ごとに全部の書き直しだけを周期で撃つ systemd の unit を器が導出して入れる。 決め手は unit の数と既存の形 (CTX3・CTX4)。

時計とは別に、 置き場ごとに作り直しだけを周期で撃つ専用の時計 (systemd の unit) を器が入れる案です。 作り直しの周期を時計と別に決められ、 時計の 1 回を重くせず、 時計の判定に手を入れない点で勝ります。 けれども、 置き場ごとに 2 本目の時計が要り、 席ごとに時計を 1 組持つ今の形を崩し、 入れる・外す・確かめるの手間が倍になります。 目印の比べと間隔はどちらにも要り、 道具の場所の問題も残ります。

+ 利点

  • 書き直しの周期を tick の周期と別に決められ、 tick の 1 周を重くしない
  • tick の判定の列と 1 周の流れに手を入れない

− 欠点

  • 置き場ごとに 2 本目の unit が要り、 席ごとに service と timer を 1 組持つ今の形 (ADR-0058・ADR-0064) を崩す (DR4)
  • unit の導出・入れ・撤去・doctor の一致の行が倍になり、 印の比べと下限は結局どちらにも要る (DR4)
  • 2 本目の unit にも台帳 client の場所の問題が同じ形で残る (DR5)
OPT6下限を持たないか、 下限を code の定数で持つ不採用

印が違えば tick の毎周に撃つ (下限なし)、 または下限を rules 行でなく code の定数にする。 決め手は実測の費用と C5 (CTX2・CTX5)。

目印が違えば時計の毎回に撃つ (間隔を持たない)、 または間隔を規則の表 (rules) の行でなく code の定数で持つ案です。 間隔が無ければ台帳の変化が次の回 (今は 15 秒) で file に入り、 code の定数なら規則の表の行も裁定も要らない点で勝ります。 けれども、 台帳は席が動く間数秒ごとに動くので、 間隔が無いと時計の回ごとに数秒から十数秒の作り直しと鍵 (lock) の持ちが続き、 ほかの書き手が飛び続けます。 code の定数は裁定を通らない値で、 決まりの値に裁定を求める憲法の門を逃れます。

+ 利点

  • 下限が無ければ、 台帳の変化が次の tick の周 (今の値で 15 秒) で出力に入る
  • code の定数なら、 rules 行と裁定 id が要らず、 足す物が減る

− 欠点

  • 台帳は席が動く間数秒ごとに動くので、 下限が無ければ tick の周ごとに 4〜14 秒の書き直しと lock が続き、 ほかの書き手が Busy で飛び続ける (DR2・DR3)
  • code の定数は裁定を通らない閾値で、 C5 の門を逃れる (DR3)
OPT7管理 tick が口 fleet lifecycle write を子 process で撃つ不採用

tick の周に、 器自身の口 fleet lifecycle write を子 process として撃ち、 書き手を直に呼ばない。 決め手は読みの同一性と結果の受け取り方 (CTX3)。

時計が、 器自身の作り直しの口を別の process として撃つ案です。 口の目印の先読みや結果の字をそのまま使えて足す code が少なく、 作り直しの失敗が時計に及ばない点で勝ります。 けれども、 口の出力は、 書いた・同じだった・重ねた・捨てたの 4 つの結果で同じ字なので、 撃った記録に残す 6 つの結果の語を子の出力から得られません。 記録が 3 つの状態に縮むか、 口の出力の形を変えることになります。

+ 利点

  • 口の印の先読み・coalesce・字の形をそのまま使え、 tick に足す code が少ない
  • 書き直しが tick と別の process で走るので、 書き直しの失敗が tick の process に及ばない

− 欠点

  • 口の出力は返りの 4 つ (Written・Unchanged・Coalesced・Discarded) で同じ字なので、 撃った記録の 6 つの語を子の出力から得られず、 記録が 3 つの状態に縮むか、 口の出力の形を変えることになる (CTX3・DR4・DR6)
OPT8systemd の user の env (environment.d) で PATH に台帳 client を足す手順にする不採用

器は変えず、 host ごとに systemd の user の環境の設定 file で PATH に bd の dir を足し、 tick の unit が素の bd を見つけるようにする。 決め手は C2.2 と器が見えるか (CTX4・CTX5)。

器は変えず、 host ごとに systemd の環境の file (environment.d) で道具の dir を探し先 (PATH) に足し、 時計が素の bd を見つけるようにする案です。 器に flag も key も足さず、 host に 1 file を置けば時計の全部とほかの unit にも効き、 今の時計の中身が変わらないので、 時計を外して入れ直す手番も、 本体を先に入れ替える順も要らない点で勝ります。 けれども、 器は環境変数を読まないので、 PATH に何が在り、 どの bd が撃たれるか (PATH の順で決まります) は器から見えず、 host ごとの値が設定 file の外に置かれます。 host に置く file は文章の手順にしか無い前提で、 器の宣言になりません。

+ 利点

  • 器に flag も key も足さず、 host に 1 file を置けば tick の unit の全部で bd が見つかる
  • systemd の user のほかの unit にも同じ PATH が効く
  • 今の unit の bytes が変わらず、 uninstall から入れ直す手番も、 binary を先に入れ替える順も要らない (OPT1 の CSQ-N6・CSQ-N7 の費用が無い)

− 欠点

  • 器は env を読まないので、 PATH に何が在り、 どの bd が撃たれるか (PATH の順で決まる) は器から見えず、 host 固有の値が host の面の外に置かれる (C2.2・C10.2・DR5)
  • host に置く file は散文の手順にしか無い host の前提で、 器の宣言にならない (N2・DR6)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 時計は毎回、 台帳と main の目印を file の目印と比べ、 file が在って読めること・裁定した 300 秒が経ったこと・どちらかの目印が違うことなどが全部そろった回だけ、 今と同じ書き手で作り直しを 1 回撃ち、 撃った記録に時刻と結果を 1 行残します。 時計の結果の字は変えません。 道具の場所は時計の新しい flag と host の設定 file で渡し、 時計を入れる口・外す口・確かめる口 (doctor) も同じ flag を受けます。 支える要件は 7 つで、 そのうち 3 つは要件書の字を別の改訂で直します。

採用 — OPT1

管理 tick SHALL 1 周の判定・打刻・部分の書き直しの後に、 次を全部満たす周だけ局面の出力の全部の書き直しを 1 回撃つ: manifest を読めて target の登録 row が在る・置き場の出力が在って読める (無いか読めない周は撃たず出力を作らない)・tick の manifest (--rules の写しか埋め込み) に rules 行 lifecycle.full_min_s が在る・今が出力の full_at と撃った記録の ts の新しい方から lifecycle.full_min_s 秒以上後 (full_at が null か読めない周は 0 と読み、 記録が無いか読めない周は記録を数えない)・登録 row の anchor の台帳の印か main の sha が出力の inputs.ledger か inputs.main と等しくない。 比べは値の等しさだけで bd も git も撃たず、 どちらかの印を読めない周は撃たず、 event log の印は比べない。 撃つのは口 fleet lifecycle write と同じ書き手 1 本で、 観測の 1 周を撃ち、 撃った時の印より古くない出力には書かず (coalesce)、 lock は待たずに Busy で返る。 repo は登録 row の anchor、 台帳 client は seat tick の新しい flag --bd B (無ければ bd) である。 撃った周は返りの 6 値に依らず、 置き場の fleet/lifecycle.tick を 1 行 ts=<epoch 秒> wrote=<返りの語> で一時 file から rename して書き、 撃たない周は書かない。 記録を読むのは管理 tick の下限の判定だけである。 管理 tick の rc・判定行・stderr は撃った周も撃たない周も変えない。 rules 行 lifecycle.full_min_s (kind 1 つ・形 Int・値 300 秒・裁定の字 user 2026-10-01T15:27Z・裁定 id s2-07l.738.42.3:20261001T1527Z-1) を足す。 host の面の表 [[tick]] SHALL 任意の key bd (台帳 client の絶対 path) を受け、 必須の key は unit-dir と binary のままとする。 unit の導出 SHALL bd を受けた周だけ service の ExecStart の末尾 (--rules F の後) に --bd <path> を載せ、 受けない導出の 2 file は今と同じ bytes とする。 席の起動は面の bd を導出に渡し、 seat tick install と uninstall は [--bd B] を受け (面は読まない)、 doctor は --unit-dir と --binary がそろった周だけ --bd を受け、 flag の組か面の組の一方を丸ごと使って欄ごとに混ぜない。 器は台帳 client の場所を env・home・自分の実行 file の場所・PATH の探索から解かず、 在るかも確かめない (C2.2)。 消すのは、 便を回さない置き場で古い出力を直すために全部を書き直す口を手で撃つ手番である (C17.2)。 本 ADR は ADR-0088 の決定 (3) のうち管理 tick の周を部分の書き直しに限り台帳も git も撃たないとする句を、 この条件つきの全部の書き直しの分だけ置き換え、 ADR-0064 の 3 句 (表 [[tick]] の欄を 2 つとする句・doctor の flag が勝つ句・席の起動が面の値で install を撃つ句) を key bd を足した形に、 ADR-0058 が pointer で戻した unit の形の 2 句 (ExecStart の固定の形・install と uninstall の口の引数) を --bd を受ける形に改める。 ほかの契機・書き手・部分の書き直し・印の読みと順の比べ・古さの印・読み手・tick の判定の列は変えない。 FR90・FR27・FR64・AC60 の字の直しは別の SRS の round が持つ。

時計 (管理 tick) は、 毎回の判定と一部の書き直しの後に、 次が全部そろった回だけ、 局面の出力の作り直しを 1 回撃ちます: 席の登録が在る・file が在って読める・時計の読む規則の表 (rules) に間隔の行が在る・前の作り直しと前の試みの新しい方から 300 秒が経った・台帳か main の目印が file の目印と違う。 目印は小さい file を読むだけで取り、 台帳の道具も git も撃たず、 出来事の log の長さは比べません。 撃つのは今の作り直しの口と同じ書き手で、 file が既に新しければ書かず、 使用中なら待たずに次へ回します。 撃った回は結果に依らず撃った記録に時刻と結果の語を 1 行残し、 次の試みの間隔の判定だけがそれを読みます。 時計の結果の字は変えません。 間隔の値 300 秒は user の裁定です。 台帳を読む道具の場所は、 時計の新しい flag で受け、 host の設定 file の時計の表に任意の key で宣言でき (必須の key は 2 つのまま)、 受けた時計だけが起動の行の末尾 (規則の表の写しの指定の後) にそれを載せ、 受けない時計は今と 1 byte も変わりません。 席の起動は設定 file の key を渡し、 時計を入れる口と外す口は同じ flag を受けて設定 file を読まず、 確かめる口 (doctor) は時計の dir と本体の場所の flag がそろった時だけ受け、 flag の組か設定 file の組の一方を丸ごと使って混ぜません。 器は道具の場所を環境変数・home・自分の場所・PATH の探索から解かず、 在るかも確かめません。 消すのは、 便を回さない置き場で古い file を直すために口を手で撃つ手番です。 置き換えるのは、 ADR-0088 の時計の回は一部だけを書き直すとした句、 ADR-0064 の 3 句 (時計の表の欄を 2 つとした句・確かめる口が flag を優先する句・席の起動が時計を入れる句)、 ADR-0058 が戻した 2 句 (時計の起動の行の固定の形・時計を入れる口と外す口の引数) で、 それ以外は変えません。 等しさで比べるのは、 動いたかどうかは等しさで分かり、 目印の読みが小さい file の読みだけで済むからです。 前後関係の比べは git を撃ち、 古い書きは書き手が自分で捨てます。 出来事の log の長さを比べないのは、 それが席や便の動く間ほぼ毎回伸び、 比べると台帳が動かなくても 300 秒ごとに重い作り直しを撃つからで、 出来事の log と時刻で決まる部分は一部の書き直しが既に持っています。 間隔を置くのは、 作り直しが 1 回 4 秒から 14 秒かかり、 台帳は席が動く間数秒ごとに動くからで、 間隔を規則の表 (rules) の行に置いて user の裁定を取ったのは、 閾値に裁定を求める憲法の線に沿うためです。 今の書き手を使うのは書き手を増やさないためで、 時計の中から撃つのは、 席ごとに時計を 1 組持つ形を保つためです (専用の時計を足す案との違い)。 口を子の process として撃たずに時計の中で書き手を呼ぶのは、 口の出力が 4 つの結果で同じ字を出し、 子では撃った記録に残す 6 つの結果の語を得られないからで、 代わりに撃つ回の時計は約 275 MB と数秒から十数秒を抱え、 書き手の異常終了は時計の異常終了になります。 道具の場所を host の設定 file の宣言と flag で受けるのは、 systemd の時計からは素の bd が見えず (実測)、 器は環境変数を読まず host ごとの値を設定 file と引数にだけ置くからです。 時計を入れる口と外す口に設定 file を読ませないのは、 設定 file を書き換えた前後でも同じ引数で古い時計を外せるようにするためで、 確かめる口が組を混ぜないのは、 flag で入れた時計を flag の組で確かめられるようにするためです。 読む側の手順や systemd の環境の file に任せると、 器が測れない文章の決まりになります。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR90claimFR90 (局面の出力) の全部の書き直しの契機に、 管理 tick の周のうち本 ADR の条件を満たす周を足すと主張する。 管理 tick の周の部分の書き直しが台帳も git も撃たない字はそのまま残す (字の直しと AC60 の契機の数え方の直しは SRS の round)。
FR27claimFR27 (管理 tick) の「管理 tick の周は局面の出力の部分の書き直しの契機である」に、 条件を満たす周の全部の書き直しを足すと主張する。 alarm を置き場の file だけで決める字 (台帳も git も撃たない) は変えない (字の直しは SRS の round)。
FR64claimFR64 (管理 tick の駆動) の unit の導出の入力に、 host の面か install の口の引数が渡す台帳 client の path を足し、 受けない導出の unit は変えないと主張する (字の直しは SRS の round)。
FR57rationaleFR57 (host の面) の、 host 固有の宣言値を host の面 1 file だけから読み、 schema 外の項目を行番号つきで断る形を保ち、 台帳 client の path をその面の表 [[tick]] の任意の key に置く。
FR17rationaleFR17 (rules manifest) の、 規則の種類を閉じた enum に持ち値を manifest から読む形を保ち、 下限を rules 行 1 本と kind 1 つで足す。
FR94rationaleFR94 (局面の出力の読み手) の約束は変えない。 全部の書き直しの出力は同じ 1 file で、 読み手は今までどおり印を比べて古さを示す。
NFR4rationaleNFR4 (fail-closed) を保つのは撃つ周に限る。 撃つ周は返りに依らず撃った記録を書き、 台帳 client が見つからない周は書き直さずに出力へ読めない印 (理由 ledger) を付けて記録に wrote=unreadable を残す。 印を読めない周・出力が無いか読めない周・rules 行の無い周は、 管理 tick が記録を残さずに黙って撃たない (tick の rc と字も変えない・CSQ-N9)。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 5 つと、 代わりに引き受けること 9 つです。 良くなるのは、 便を回さない置き場でも変化が数分で file に入ること、 変化の無い回は軽い読みだけで済むこと、 書き手も時計も増やさないこと、 道具の場所が器に見えて宣言の無い host の時計は 1 byte も変わらないこと、 file を直すために口を手で撃つ手番が消えることです。 引き受けるのは、 最長で 300 秒と時計の周期の和の遅れ、 作り直しの間ほかの書き手が待つか飛ぶこと、 失敗した回も次の試みが 300 秒後になること、 1 つの置き場に repo の違う席が在ると作り直す repo が入れ替わりうること、 道具の場所を宣言せず時計の PATH にも bd が無い host では作り直しが台帳を読めずに終わり file に読めない印が付くこと、 古い本体が設定 file の新しい key と新しい flag を断るので入れ替えの順が要ること、 時計が既に在る host で設定 file に道具の場所を足すと時計を外して入れ直す順が要ること、 撃つ回の時計が約 275 MB と数秒から十数秒を抱え、 書き手の異常終了が時計の異常終了になること、 目印か間隔の行を読めない置き場では時計が何もせず何も残さず、 file はほかの契機でしか新しくならないことです。

✓ 良い結果

  • ●便を回さない置き場でも、 台帳か main の変化が最長で下限と tick の周期の和の後に局面の出力に入り、 出力を読む画面が古いまま残らない
  • ●印が動かない周は小さい file の読みと等しさの比べだけで、 bd も git も撃たない
  • ●書き手・lock・coalesce・返りの 6 値・読み手は既存のままで、 新しい書き手も新しい unit も足さない
  • ●台帳 client の場所は host の面の宣言で器に見え、 宣言の無い host の unit は 1 byte も変わらない
  • ●便を回さない置き場で、 古い出力を直すために口を手で撃つ手番が消える

⚖ トレードオフ・代償

  • ●台帳か main の変化が出力に入るまで、 最長で下限と tick の周期の和 (今の値で 300 秒と 15 秒) かかる
  • ●書き直しの間 (空いた host で約 4 秒・gate が走る host で約 14 秒) は lock を持つので、 ほかの書き手は待つか Busy で飛び、 飛んだ分は次の周が拾う
  • ●撃った記録は返りに依らず書くので、 Busy や Unreadable で終わった周も次の試みは下限の後になる
  • ●1 つの置き場に anchor の違う席が 2 つ以上在ると、 tick ごとに違う repo の印と比べ、 下限ごとに違う repo で書き直しうる (判じ方は後の行)
  • ●台帳 client を宣言せず timer の PATH にも bd が無い host では、 台帳が動いた周の撃った記録が wrote=unreadable で、 出力は理由 ledger の読めない印を持つ (印は次に全部の入力を読めた全部の書き直しが消す)。 宣言した path が在るかは器が確かめず、 違う path も同じ記録で見える
  • ●古い binary は表 [[tick]] の key bd を未知の key として断り、 前の版の seat tick は --bd を未知の引数として断る (timer の毎周が落ちる) ので、 面に bd を書くのは PATH の binary と面の binary を新しい版にした後になる
  • ●unit の既に在る host で面に bd を足すと導出の bytes が変わるので、 席の起動の install は unit-exists で断り、 doctor の面の組は foreign を名乗る。 古い引数で uninstall し、 面に bd を足し、 席を起こし直すか --bd つきで install する順が要る
  • ●撃つ周は tick の process が書き直しを抱え、 最大 RSS 約 275 MB を持ち、 1 周が 4〜14 秒延びる。 書き手が panic すると tick が異常に終わり、 rc を変えない約束の外になる
  • ●登録 row の anchor の台帳の印か main の ref を読めない置き場と、 tick の manifest に rules 行 lifecycle.full_min_s の無い置き場では、 管理 tick は撃たず何も記録しない (撃たない形の fail-closed)。 その置き場の出力は、 ほかの契機の全部の書き直しでしか新しくならない
