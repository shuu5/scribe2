設計判断記録 (ADR) scribe2 — 席の起草の置き場の量の上限

席の起草の置き場の build の置き場に state dir ごとの量の上限を持たせ、 越えた周は書きの新しさの古い順に上限まで消す — 組み立て中の窓の内は消さず、 測れない木は数えずに名指し、 越えたままなら掃除の行と doctor の行で知らせる (ADR-0096 の書きの線だけで消す決定と原則を部分 supersede)

器の掃除は、 席 (人と AI が話す session) が試作のために作る repo の写しから、 書きが 6 時間無い build と依存の置き場を消す。 線は時間だけで量を見ないので、 席が写しを並列に作って組み立てると、 6 時間の中でも置き場が溜まって disk の大きな割合を占める。 本 ADR は、 置き場の合計に state dir ごとの上限を持たせ、 越えた周だけ最後の書きが古い順に上限まで消し、 書いたばかりの置き場は消さず、 越えたままなら知らせると決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す作業の画面、 「起草の置き場」は席が試作のために repo の写しを置く器の中の場所です。 器の掃除は、 写しの中の組み立ての産物 (build と依存の置き場) のうち、 6 時間書かれていない物を消します。 けれども時間しか見ないので、 席が写しをたくさん並べて組み立てると、 6 時間の中でも産物が溜まり、 disk の大きな割合を占めました。 この記録は、 産物の合計に state dir ごとの上限 (100 GiB) を持たせ、 越えた周だけ、 最後に書かれたのが古い物から上限を下回るまで消し、 30 分以内に書かれた物は組み立て中とみなして消さず、 それでも越えたままなら知らせると決めます。 持ち主が推奨に同意した裁定に基づく決定です。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 4 つから説明します。 6 時間の線だけでは量に限りが無いという経緯・掃除が線より新しい物を黙って残し、 量を測る口を持たないという現物・写しは便の記録と結びを持たず、 置き場の共有は言語ごとに違うという事情・決める範囲です。

CTX1

経緯 — 書きの線消してよい古さの線だけでは量が有界にならない

ADR-0096 は、 席ごとの起草の置き場を state dir の下に持ち、 運転手 (便を段から段へ運ぶ器の process) の終端の周の掃除が、 置き場の .git を持つ写し (起草の木) から、 名が閉じた 8 つに在り追跡される file を持たない dir のうち、 書きが rules 行 seat.drafts_stale_h の時間 (6 時間) 無いものだけを消すと決めた。 線は時間だけで、 量は見ない。 席が起草の係 (subagent) ごとに写しを作って並列に組み立てると、 6 時間の中で作られた写しの build の置き場は、 消える前に溜まる。 2026-09-30、 消費側の席で、 6 時間の窓の中の写しの build の置き場が host の disk の大きな割合を占めた (量は台帳の memo s2-07l.737.27 にだけ在る)。 持ち主は CI を通った後に写しを消せないかと問い、 量の上限置き場の大きさの上限と組み立て中の窓書いたばかりの間の推奨に裁定を与えた (user 2026-09-30T07:18Z)。

CTX2

現物 — 掃除は線以後の dir を黙って残し、 量を測る口を持たない

掃除の 1 関数 (pipe/sweep.rs の sweep) は、 置き場ごとの lock の中で便の木を掃いた後に起草の木を掃く。 起草の木では、 書きの線以後の entry を 1 つでも持つ dir を残し、 残した dir を呼び手へ返さない。 dir の大きさを測る口は無い (verified)。 結果は stderr の 1 行 (消した数・便の木の数・失敗の数と名・起草の木の数・.git を持たない写しの数) だけで、 dir を消した周・失敗が在る周・lock を取れない周・行を読めない周にだけ出し、 その字は 6 本の歯が逐語で固定している (verified)。 doctor は置き場の量を出さない。 起草の置き場の根の直下を読むのは掃除だけで、 dir でない子は飛ばす (verified)。

CTX3

写しの一生 — 写しは便の記録と結びを持たず、 置き場の共有は言語ごとに違う

起草の写しは、 席が試作のために git の worktree か clone で置く物で、 便の記録も PR も持たない。 席は同じ写しで試作を続けることがあり、 CI を通った後も写しを使いうる。 器は、 写しがいつ使い終わったかを知る結びを持たない。 build と依存の置き場は言語ごとの道具が作り、 置き場を写しの間で共有する仕組み (Rust の target の置き場の環境変数など) は言語ごとに違う。 器は限られた言語の集合に対応し、 どれかの言語だけの仕組みを採らず、 席の環境変数を配らない (N2)。

CTX4

射程 — 量の線を足すだけで、 書きの線と写しの扱いは変えない

決めるのは、 (1) 起草の木の build の置き場の合計に state dir ごとの上限を持たせること、 (2) 越えた周に消す物・順・止め所、 (3) 組み立て中とみなす窓、 (4) 測れない物の扱い、 (5) 越えたままの知らせの口 (掃除の行と、 置き場の根の直下の記録の file と doctor の行)、 (6) rules 行 2 本。 変えないのは、 書きの線と行 seat.drafts_stale_h、 消す名の閉じた 8 つの列、 追跡の判じ、 lock の名と取り方、 撃つ周 (運転手の終端の周だけ)、 便の木の掃除 (ADR-0081)、 起草の置き場の場所と席の指示文 (ADR-0096)。 ADR を書く条件のうち 1 (A1 の承認の読み)・3 (記録の file の形)・4 (却下案を残す価値) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 量に限りを持たせること。 組み立て中の物を消さないこと。 承認の範囲の外の物を消さないこと。 仕組みを増やさず言語に依らないこと。 測れない物を 0 と読まないこと。 越えたままを人が知れることです。

DR1量を有界にする — 写しの数に依らず、 置き場の build と依存の置き場が host の disk を満たさない CTX1
DR2組み立て中の物を消さない — 書いている最中の置き場は、 量を越えていても残す CTX1・CTX3
DR3承認の範囲に閉じる — 消すのは作り直せる名の dir だけで、 木の写しと追跡される file と commit していない変更は消さない (A1・N1) CTX1・CTX4
DR4仕組みを増やさない — 2 つ目の消す仕組みと lock を足さず、 言語と道具に依らない (C17・N2) CTX2・CTX3
DR5測れない物を 0 と読まず、 読めない行を既定値に倒さない (C10) CTX2
DR6越えたままを人が知れる — 消しても越えた周を黙らない CTX2
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 量の上限を持って古い順に消す案 (選んだ案) と、 選ばなかった 4 つです。 選ばなかった案は、 6 時間の線を短くする案・CI を通った後か merge の時に消す案 (持ち主の問いの案)・写しの間で組み立ての置き場を共有する案・写しごと消す案です。

OPT1量の上限を持ち、 越えた周は書きの新しさ最後に書いた時の古い順に上限まで消す採用

書きの線が残した起草の木の build と依存の置き場を候補とし、 大きさ (lstat の st_blocks の和) と書きの新しさ (mtime の最新) を測る。 合計が rules 行の上限 (100 GiB) を越える周だけ、 新しさの古い順に、 組み立て中の窓 (rules 行・30 分) の内を飛ばして消し、 上限以下で止める。 測れない木は数えずに名指し、 越えたままなら掃除の行と doctor の行で知らせる。 決め手は裁定 user 2026-09-30T07:18Z と分析 (量は時間の線でなく量の線でしか有界にならない)。

組み立ての産物の合計に上限を持たせ、 越えた周だけ、 最後に書かれたのが古い物から上限を下回るまで消す案です。 写しがいくつ並んでも量は上限の近くに保たれ、 30 分以内に書かれた物は消さないので走っている組み立てを壊さず、 写しそのものや追跡される file は消さず、 仕組みも 1 つのままです。 代わりに、 越えた周には 6 時間より新しい産物も消えることがあり、 席が戻ると組み立てを作り直します。 掃除の時間も、 産物を全部測る分だけ延びます。

+ 利点

  • 写しの数に依らず、 置き場の合計は上限に近く保たれる (組み立て中の分を除く) (DR1)
  • 組み立て中の窓の内の置き場は消えない (DR2)
  • 書きの新しさの古い順に消して上限以下で止まるので、 書く手が止まってから長い物から要る分だけ空く (DR2)
  • 消すのは書きの線と同じ名の dir だけで、 木の写しと追跡される file は残る (DR3)
  • 消す仕組みと lock は 1 つのままで、 測りは mtime と lstat だけ (DR4)
  • 測れない木は数えずに名指し、 行を読めない周は撃たない (DR5)
  • 越えたままの周は掃除の行と doctor の行に出る (DR6)

− 欠点

  • 上限を越えた周には、 書きの線より新しくても窓の外の置き場が消え、 席が戻ると組み立てを作り直す
  • 終端の周ごとに候補の全部の entry を lstat で歩く時間が掃除に足される
  • 上限は state dir ごとで、 同じ disk の state dir の数だけ量が積まれる
  • 知らせは掃除の行と doctor の行で、 席へは押し出さない
OPT2書きの線を短くする不採用

rules 行 seat.drafts_stale_h の値を 6 時間より短くし、 量の線は足さない。 決め手は分析 (量は写しの数に比例する)。

6 時間の線を 1 時間などへ短くし、 量の上限は足さない案です。 仕組みも行も足さず、 値を変えるだけで済む点で勝ります。 けれども、 量は写しの数に比例するので、 写しをたくさん並べれば短い線の中でも溜まり、 限りになりません。 量が少ないときも短い線で消えるので、 戻ってくる写しの組み立てを作り直す回数が増えます。

+ 利点

  • 足す仕組みも行も無く、 値の裁定 1 つで済む
  • 判じは時間の 1 つのままで済む

− 欠点

  • 並列の写しが多ければ、 短い線の中でも量は有界にならない (DR1)
  • 量が少ない周にも短い線で消え、 戻ってくる写しの組み立てを作り直す (DR2)
OPT3CI を通った後か merge の契機で消す不採用

持ち主の問いの案で、 写しの CI が通った時か merge の時に、 その写しの build の置き場を消す。 決め手は分析 (写しは便の記録も PR も持たない)。

持ち主が問うた案で、 写しの CI が通った時か merge の時に、 その写しの組み立ての産物を消します。 使い終えたと分かる時に消せ、 時間や量の値が要らない点で勝ります。 けれども、 器は写しと CI や merge の結びつきを持っておらず、 作るには写しを登録する仕組みが要ります。 CI を通った後も同じ写しで試作を続けることがあり、 その組み立てを消してしまいます。 CI にも merge にも届かない試作の写しは残り続けます。

+ 利点

  • 使い終えたと分かる時に消せる
  • 時間と量の値が要らない

− 欠点

  • 器は写しと CI・merge の結びを持たず、 結びを作るには写しを便か PR へ登録する仕組みが要る (DR4)
  • CI を通った後も同じ写しで続く試作の組み立てを消す (DR2)
  • 便にも PR にもならない試作の写しは残り続ける (DR1)
OPT4写しの間で build の置き場を 1 つに共有する不採用

Rust の target の置き場の環境変数などで、 写しの build の置き場を state dir の 1 か所に集める。 決め手は分析 (言語ごとの仕組みで、 器が環境変数を配る)。

写しの間で組み立ての置き場を 1 か所に共有する案です (Rust の置き場を環境変数で 1 か所に向けるなど)。 同じ依存の組み立てを使い回せ、 量が写しの数に比例しない点で勝ります。 けれども、 共有の仕組みは言語と道具ごとに違い、 器が言語ごとの知識を持って席の環境変数を配ることになります。 並列の組み立ては同じ置き場の鍵で 1 本ずつになり、 枝の違う写しの間では作り直しが続き、 共有の置き場そのものの量にも限りがありません。

+ 利点

  • 同じ依存の組み立てを写しの間で使い回せ、 量が写しの数に比例しない
  • 消す場所が 1 か所になる

− 欠点

  • 仕組みは言語と道具ごとに違い、 器が言語ごとの知識と環境変数の配りを持つ (DR4・N2)
  • 並列の組み立てが同じ置き場の lock で直列になり、 枝の違う写しの間で作り直しが続く (DR2)
  • 共有の置き場そのものの量は有界にならない (DR1)
OPT5木の写しごと消す不採用

量を越えた周に、 古い写しを build の置き場だけでなく写しごと消す。 決め手は裁定の範囲と分析 (N1)。

量を越えた周に、 古い写しを組み立ての産物だけでなく写しごと消す案です。 取り戻せる量が最大になる点で勝ります。 けれども、 持ち主の裁定は写しそのものを消すことを承認しておらず、 写しには commit していない試作が在りうるので、 消すと作り直せません。

+ 利点

  • 取り戻す量が最大になる (写しの本体の分も空く)
  • 置き場が使い終えた写しで埋まらない

− 欠点

  • 裁定は木の写しの削除を承認していない (DR3)
  • 写しには commit していない試作が在りえ、 作り直せない (DR3・N1)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 候補は 6 時間の線が残した組み立ての産物だけで、 大きさと最後の書きを測り、 合計が上限を越える周だけ、 最後の書きが古い順に、 30 分以内に書かれた物を飛ばして消し、 上限を下回った所で止めます。 測れない写しは数えずに名指し、 越えたままなら掃除の行と doctor の行で知らせます。

採用 — OPT1

器 SHALL 席の起草の置き場の build と依存の置き場に、 state dir ごとの量の上限を持つ。 候補は、 運転手の終端の周の同じ掃除が同じ lock の中で書きの線 (ADR-0096) を掛けた起草の木から、 線以後の entry を持つので残した名の dir だけで、 便の木・追跡される file を持つ dir・.git を持たない写し・木の本体は候補にならない。 候補ごとに dir 自身と下の全 entry を symlink を辿らずに lstat し、 大きさを st_blocks の和 (disk の上の使用量)、 書きの新しさを mtime の最新とする。 合計が rules 行 seat.drafts_cap_mb の上限を越える周だけ、 候補を書きの新しさの古い順 (同じ時刻は名の順) に見て、 新しさが rules 行 seat.drafts_busy_s の窓の内の候補 (組み立て中) を飛ばして消し、 合計が上限以下になった所で止める。 書きの線の掃きで失敗した木と、 候補の中に読めない entry を持つ木は、 木ごと候補と合計から外して失敗として名指し、 外した数を記録に残す。 掃除の stderr の行は、 量で消した周か越えたままの周だけ末尾に消した数と越えた量を足し、 越えたままの周は消す物が無くても行を出し、 それ以外の周の字は変えない。 掃除は起草の置き場が在る周ごとに、 置き場の根の直下の 1 file に使用量・上限・越えた量・窓の内の数・外した数の 1 行 (行を読めない周は no-rule) を書き、 doctor はそれを 1 行で出す。 行は seat.drafts_cap_mb (102400 MiB = 100 GiB) と seat.drafts_busy_s (1800 秒 = 30 分) の 2 本 (裁定 user 2026-09-30T07:18Z)。 書きの線の行と本 2 行のどれかを読めない周は量の線を撃たず、 既定値に倒さない。 消す名の閉じた 8 つの列・書きの線・lock・撃つ周・便の木の掃除は変えず、 木の写しと追跡される file は消さない。 実装は設計 doc dispatcher.md §39 の行 an。

器は、 席の起草の置き場の組み立ての産物に、 state dir ごとの量の上限を持ちます。 候補は、 同じ掃除が 6 時間の線を掛けた後に、 線より新しいので残った産物だけです。 便の作業場所・追跡される file を持つ dir・.git を持たない写し・写しの本体は候補になりません。 候補ごとに、 中の全部を symlink を辿らずに測り、 disk の上の大きさと最後の書きの時刻を取ります。 合計が上限を越える周だけ、 最後の書きが古い順 (同じ時刻は名の順) に見て、 30 分以内に書かれた物を飛ばして消し、 上限を下回った所で止めます。 6 時間の線の掃除で失敗した写しと、 中に読めない物を持つ写しは、 数えずに外して失敗として名指し、 外した数を記録に残します。 掃除の行は、 量で消した周か越えたままの周だけ末尾に消した数と越えた量を足し、 越えたままなら消す物が無くても行を出します。 それ以外の周の行は変えません。 掃除は置き場の量を 1 行の記録に書き、 doctor がそれを出します。 上限 100 GiB と 30 分は rules 行 2 本が持ち、 6 時間の行とこの 2 本のどれかが読めない周は量で消しません。 量の上限を選んだのは、 量が写しの数に比例するので、 時間の線を短くしても限りにならないからです。 CI や merge の時に消す案は、 器が写しと CI の結びつきを持たず、 CI の後も続く試作の組み立てを消すので退けました。 置き場の共有は言語ごとの仕組みで、 器が環境変数を配ることになるので退け、 写しごと消すのは承認の外で作り直せない仕事を失うので退けました。 最後の書きが古い順に消し、 上限を下回った所で止めるのは、 書く手が止まってから長い物から要る分だけ消し、 要る分より多くは消さないためです。 30 分の窓を設けるのは、 走っている組み立てを消して落とさないためです。 測れない写しを数えないのは、 測れない量を 0 と読んで上限の判断を誤らないためで、 外した数を記録に残して、 合計が一部の和だと分かるようにします。 越えたままを知らせるのは、 消せなかった周を黙らないためです。
