設計判断記録 (ADR) scribe2 — 口座の墓標の判定と群の移動

口座の墓標は器が credential の file から 1 本の関数で判じ、 群は今の口座が墓標なら移動の判定の 1 本で移り、 管理 tick は墓標の席に合図を送らずに群の判定へ進む — 知らせは doctor と管理 tick の行の語で持ち、 席へ押し出す口は足さない (ADR-0058 の判定の列・ADR-0026 の credential を読まない句・ADR-0049 と ADR-0066 の移動の契機・ADR-0074 の予約の読みを部分 supersede)

口座の login が切れると、 口座の credential の file に使えない印 (墓標) が現れ、 その口座の席は止まる。 器の計測は墓標を名指すが、 doctor の行にも群の移動にも管理 tick の門にも結ばれておらず、 2026-09-29 に席が止まったまま人が気づくまで戻らなかった (量は台帳 memo s2-07l.737.2)。 本 ADR は、 墓標を file から判じる関数を 1 本にすること、 今の口座が墓標の群を群の逼迫と同じ手で移すこと、 墓標の席に合図を送らないこと、 知らせを doctor と管理 tick の行の語で持つことを決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す session、 「口座」は席が使う Claude の契約 1 つ、 「群」は同じ口座をまとめて使い、 口座を移るときは一緒に移る席のまとまりです。 口座の login が切れると、 口座の鍵の file (credential) に「もう使えない」という印 (墓標) が現れ、 その口座で動く席は止まります。 器の計測はこの印を見つけていましたが、 doctor の表示にも、 群を別の口座へ移す判定にも、 黙った席に合図を送る周期の仕事 (管理 tick) にも結ばれておらず、 2026-09-29 に席が止まったまま人が気づくまで戻りませんでした (止まった長さは台帳の memo に在ります)。 この記録は、 印を鍵の file から読む関数を 1 本にし、 今の口座に印がある群を使用率の閾値越え (群の逼迫) と同じ手で別の口座へ移し、 印のある席には合図を送らず、 知らせは doctor と周期の仕事の既存の行の語で出すと決めます。 まだ要件書の改訂を待つ提案の段です。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 7 つから説明します。 鍵の file の印が計測にだけ名指されてどの判断にも結ばれていない経緯・印のせいで席が人の気づきまで止まった事象・群の移動の判定が測れなかった口座を群の逼迫と読まず移らない現物・周期の仕事が古い「作業中」の状態の記録で止まり口座の門が記録の無い周を通し起こし直しが印のある口座で起こす現物・doctor と口座の一覧が印と未計測を見分けない現物・憲法と前の記録の向き・動かす範囲です。

CTX1

経緯 — 墓標は計測が名指すが、 どの判断にも結ばれていない

口座の credential の file (Claude Code の私有の形) には、 claudeAiOauth.expiresAt が 0 の形が現れることがある。 これを墓標と呼び、 戻すのは user の再 login だけである (ADR-0017 の背景の実測)。 どの時に Claude Code がこの形を書くかは器の外の振る舞いで、 refresh に失敗した時と読むのは推測 (inferred) である。 器の計測 (SRS FR33) は token を読む前に墓標を見て、 測れなかった理由 tombstone を記録し、 HTTP も refresh も撃たない。 前の設計 (台帳 s2-07l.420) は墓標を口座の一覧の語と管理 tick席を見回る周期の仕事 の呼び鈴で名指す形を決めたが、 呼び鈴の送り先の口が ADR-0045 で消えたので超過として閉じ、 実装は 1 行も無い。 ADR-0026 は credential の失効の後の再 login を user の手番とし、 doctor が示すと書いたが、 doctor はそれを示す語を持たない。

CTX2

事象 — 1 口座の墓標再 login が要る印で、 席が人の気づきまで止まった

2026-09-29、 ある口座に墓標が置かれ、 その口座で立つ orchestrator の席が止まった。 墓標の記録の行の数と止まった長さは台帳 memo s2-07l.737.2 に在る (口座の特定と量は台帳にだけ置く)。 墓標の記録の時刻は、 その席の turn の始まりの打刻と一致した (orchestrator の実測)。 墓標の席の turn は終わりの打刻を打たずに落ちて Busy を残し、 管理 tick は 3600 秒より古い Busy を作業待ち (Idle) と読んで 1 時間ごとに合図を送り、 そのたびに hook の計測が墓標を記した (deduced)。 群の移動の判定移すかを決める関数はその周も移らないと答え、 doctor・alarm・席の知らせのどれにも出なかった。 持ち主は、 口座の板で認証の切れを見分けたいと問うた (2026-09-29・逐語は台帳)。

CTX3

現物 — 群の移動の判定は、 測れなかった口座を逼迫と読まない

群の移動の判定 (ADR-0066・1 本の関数) は、 群の今の口座の最新の実測の使用率が閾値の rules 行 3 本のどれか以上 (群の逼迫使用率が閾値越え) のときだけ移り、 測れなかった行は数えない (0 に読み替えない)。 墓標の今の口座は測れない行しか持たないので、 判定は移らないと答える。 判定は群の今の口座と席の口座を判定を撃つ回ごとに測るので、 墓標の口座も測られて測れなかった記録が増える。 移り先の候補の門は鮮度の窓 (300 秒) の内側の実測を読むので、 墓標の候補は墓標を記した回が最新になるまで外れず、 直前の実測から 300 秒は予約されうる。 先の群が予約を持つかの読み (ADR-0074) も同じ読みである。

CTX4

現物 — 管理 tick は打刻で止まり、 口座の門口座で合図を止める条件は記録が無ければ開き、 起こし直しは群の今の口座で起こす

管理 tick の判定の列 (ADR-0058) は、 登録の門 → 窓が shell か → 移動の門 → 状態の打刻 → 梯子 → 停止の記録の門 → 黙りの門 → 口座の門 → 入力欄の門 → 注入の順で、 群の移動の判定 (ADR-0066) は打刻を通った周にだけ撃つ。 最終行が Busy の席は黙りの初段 (1800 秒) の 2 倍より古く入力欄が空くまで止まるので、 墓標の席の周で群の判定が撃たれるのは最長 3600 秒の後である。 口座の門は計測の記録の鮮度の内側の最新値だけを読み、 記録が無い・古い周は通す (門は正の証拠でだけ閉じる) ので、 墓標の口座の席には合図が届く。 窓が shell に戻った席は、 群の今の口座 (記録 > 種) で打刻と梯子を読まずに起こし直す (SRS FR59) ので、 群の今の口座が墓標なら墓標の口座で起こす。

CTX5

現物 — 見える面は、 墓標と未計測を分けない

doctor と口座の一覧 (account ls) の口座の行は 1 本の関数で組まれ、 credential= は file が在るか無いかの 2 値だけで、 墓標の口座も present と出る。 doctor の群の行の pressure= は墓標の今の口座で unmeasured、 席の status の reopens= も unmeasured で、 どちらも測っていないと死んでいるを分けない。 群の行は今の口座を current= で名指す。 墓標の語が出るのは計測の一覧 (fleet usage --show) の reason=tombstone だけで、 これは最新の計測の写しなので、 計測が撃たれるまで再 login の後も墓標のまま残る。 消費側の板はこれらの text の key を読む。 doctor の席の行は席の口座の label を持つ。 agent view と trust の読みの語は、 file が無い・読めない・形が違う周を unreadable と出して on や missing に潰さない (C11)。

CTX6

憲法と既存の決定の向き (本 ADR の解釈)

C9 は、 席が止まったら人手なしに検出し、 仕事を再開し、 成果を保つことを求める。 本 ADR は墓標で止まった席もこの止まった席に含めて読む。 C2 は判じ手を 1 本の関数にし、 新しい理由を 1 つの variant で表す。 C10 は測った値を出所つきで持ち、 測れないを別の値に読み替えない。 C17 は既に在る仕組みを使って足すものを最小にし、 C17.2 は先に消すものを名指す — 本 ADR が消すのは、 墓標に人が気づくまでの停止と、 墓標の席へ 1 時間ごとに届く合図と計測の記録と、 消費側が credential を自分で読んで判定を写す手である。 A1 の使うの承認は群の宣言の行 (候補の列) で、 移動の承認 event は宣言の逐語を持つ (ADR-0049)。 本 ADR は契機の種類に依らず同じ承認を読む。 ADR-0017 §2.2 は token をどの出力にも出さない。 ADR-0026 §2.2 は「器 SHALL NOT credential を読まず・書かず・代筆せず」と主語を器に置いて書き、 字のままでは口座を足す口の外の読みも縛る。 同じ節は「ls SHALL doctor の口座行 (台帳 s2-07l.233) と同じ関数の行に retired= と最新の実測行の要約 (event log を読むだけ・計測は撃たない) を足し、 判定を持たない (C10.2)」とも決めており、 ls の口座の行が credential=dead を出すことはこの句に触れる。 C3.2 の doctor は口座を照合する 1 つの口である。

CTX7

射程 — 動かすのは 4 つの決定だけ

動かすのは (1) 墓標の判定を credential の file を読む 1 本の関数にし、 語を present・missing・dead の 3 つにすること、 (2) 群の移動の判定の契機に墓標を 1 つ足し、 墓標の口座を測らず、 移り先と予約の候補から外すこと、 (3) 知らせを doctor と口座の一覧の口座の行と管理 tick の判定行の語で持つこと、 (4) 管理 tick が墓標の席の打刻と梯子を読まずに群の判定へ進んで合図を送らず、 窓が shell の席は群の今の口座が墓標なら起こす前に群の判定を撃つこと、 の 4 つである。 動かさないのは、 計測の理由と記録・event の種類と形・rules 行・群の記録と承認 event の形・群の行の欄・退避の合図と猶予と /exit と起こし直しの字面 (ADR-0067・ADR-0079)・便用と session 用の口座選定・park の区画の判定・極性一覧である。 要件書は持ち主の SRS の改訂の回に直し、 FR38・FR27・FR58 の字の改訂と、 判定と語を名指す要件 1 つ (受入 1 つ) の追加と、 AC41 と AC18 に数を足すことを頼む。 設計 account-lifecycle.md §38 (契約表の行 ab・ac・ad) が実装し、 3 行とも SRS の改訂の後に起こす。 ADR を書く条件のうち 1 (C9 と A1 の読み) と 4 (却下案を残す価値) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 印で止まった群の席を人の気づきを待たずに別の口座で続けること。 印の判定を 1 本の関数にし判じる時の実物を読むこと。 期限切れや読めない file では止めず移さないこと。 人と板が既に読む面で印と未計測を見分けられること。 口・規則の行・記録の種類・依存・欄を足さないこと。 鍵を出さず鍵の file に書かないことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 9 つ並べます。 鍵の file を読む 1 本の関数で印を判じ、 群を移し、 印のある席に合図を送らず、 doctor と周期の仕事の行の語で知らせる案 (選んだ案) と、 選ばなかった 8 つです。 選ばなかった案は、 印を計測の記録から読む案・移さずに知らせるだけの案・印を群の逼迫に含める案・席の画面へ知らせを押し出す案・語を 4 つにして期限切れも名指す案・合図の門を今のままにする案・読めない file に 4 つ目の語を足す案・群の行に dead を出す案です。

OPT1file の 1 関数で墓標を判じ、 群を移し、 墓標の席に合図を送らず、 doctor と管理 tick の行の語で知らせる採用

credential の file を読み計測の墓標の読みを使う 1 本の関数が present・missing・dead を返す。 群の移動の判定は墓標の口座を測らず、 今の口座が墓標なら群の逼迫と同じ予約・記録・承認 event・退避・起こし直しで移り、 墓標の口座を移り先と予約から外す。 管理 tick は墓標の席の打刻と梯子を読まずに群の判定へ進み、 合図は送らない。 窓が shell の席は、 群の今の口座が墓標なら起こす前に群の判定を撃つ。 知らせは同じ 1 本の判定から出る語 (doctor と口座の一覧の口座の行は credential=dead・判定行は account-dead) で持ち、 群の行は今の欄のまま (current= と credential= で引ける)。 決め手は分析 (移す仕組みと見える面は既に在り、 移す手そのものは足さない)。

鍵の file を読み、 計測と同じ印の読み方を使う 1 本の関数が present・missing・dead を返す案です。 群の移動の判定は印のある口座を測らず、 今の口座に印があれば群の逼迫と同じ予約・記録・承認の記録・退避の合図・起こし直しで移り、 印のある口座を移り先と予約から外します。 周期の仕事は印のある席の状態の記録と合図の間隔の記録を読まずに群の判定へ進み、 合図は送りません。 窓が shell に戻った席は、 群の今の口座に印があれば起こす前に群の判定を撃ちます。 知らせは同じ 1 本の判定から出る語 (口座の行は credential=dead・判定行は account-dead) で持ち、 群の行は今の欄のままです。 代わりに、 期限の内に無効にされた鍵は捉えず、 群の外の席と park の区画の席は再 login まで止まり、 印の席の終了は猶予の上限を待ち (login の画面で止まった席には合図も /exit も届かないかもしれない)、 鍵の file を読む回数が増える (周期ごとに席の口座 1 つ・判定の周に候補の全口座・doctor と一覧は全口座) ことと、 判定済みの窓の内側と移り先の無い群では窓が shell の群の席を印の口座で起こすことを引き受けます。

+ 利点

  • 移り先が在る群の席は墓標から十数分で別の口座で会話を続ける (login の画面で止まった席を除く・CSQ-N4) (DR1)
  • 判じ手は計測の墓標の読みと同じ 1 本で、 判じる時の file を読む (DR2)
  • 期限切れと読めない file は present で、 門も移動も墓標の正の証拠でだけ動く (DR3)
  • 板と doctor が墓標を 1 語で見せ、 板は判定を写さない (DR4)
  • rules 行・event・口・依存・極性・群の行の欄は増えない (DR5)
  • 関数は閉じた語だけを返し、 token を出さず書かない (DR6)

− 欠点

  • 期限の内に無効にされた token (HTTP 401) は file が墓標にならず捉えない
  • 群の外の席と park の区画の席は移らず、 再 login まで止まる
  • 墓標の席は退避の合図に応えられないので、 /exit は猶予の上限 (300 秒) の後になり、 login の画面で止まった席には合図も /exit も届かないかもしれない
  • credential の file を読む回数が増える (管理 tick の周ごとに登録 row の口座 1 つ・群の判定を撃つ周に測る集合と候補の全口座・doctor と口座の一覧は全口座)
  • 鮮度の窓の内側で判定済みの周と移り先の無い群では、 窓が shell の群の席を墓標の口座で起こす
OPT2死を計測の記録から読む不採用

最新の計測の回の測れなかった理由 tombstone を墓標と読み、 file は読まない。 決め手は分析 (記録は測った時の写しで、 doctor と口座の一覧は計測を撃たない)。

印を、 最新の計測の回の「測れなかった理由 tombstone」から読み、 鍵の file は読まない案です。 計測のほかで鍵の file を読まずに済み、 計測が HTTP の結果を記録するように広がれば無効にされた鍵も同じ読みで拾える点で勝ります。 けれども、 記録は測った時の写しなので計測が撃たれるまで古く、 login し直した後も死と読み、 測られていない口座の印は出ません。 記録は置き場ごとに割れ、 doctor と口座の一覧は計測を撃たないので読める記録が無いこともあります。

+ 利点

  • credential の file を計測のほかで読まずに済む
  • 計測が HTTP の status を記録するように広がれば、 401 も同じ読みで拾える

− 欠点

  • 計測が撃たれるまで古く、 再 login の後も死と読み、 測られていない口座の死は出ない (DR2)
  • 置き場ごとの記録に割れ、 doctor と口座の一覧は計測を撃たないので読める記録が無いことがある (DR2・DR4)
OPT3移さずに知らせるだけにする不採用

墓標を口座の一覧の語 (credential=dead) で知らせ、 群は移さず、 人の再 login を待つ。 決め手は分析 (C9 を群の席で満たせない)。

印を口座の一覧の語 (credential=dead) で知らせ、 群は移さずに人の login し直しを待つ案です。 群の移動の判定を変えずに済み、 口座の移り変わりが人の判断だけで起きる点で勝ります。 けれども、 群の席は人が気づいて login し直すまで止まり、 止まった席を人手なしに立て直す憲法の条を群の席で満たせません。 人が板か doctor を見るまで気づかれないので、 気づくまでの停止も消えません。

+ 利点

  • 群の移動の判定を変えずに済む
  • 口座の移り変わりが人の判断だけで起きる

− 欠点

  • 群の席は人が気づいて再 login するまで止まる (DR1)
  • 人が板か doctor を見るまで気づかれず、 気づくまでの停止が消えない (DR1・DR4)
OPT4墓標を群の逼迫に含める不採用

墓標の口座を、 窓の使用率が閾値以上の口座と同じ逼迫の値として判定に渡す。 決め手は分析 (窓も使用率も無い値を窓の型に偽る)。

印のある口座を、 使用率が閾値以上の口座と同じ「群の逼迫」の値として判定に渡す案です。 判定の出力の型を変えずに済み、 群の逼迫の通知と doctor の表示の形をそのまま使える点で勝ります。 けれども、 窓も使用率も無い状態を窓の値に偽ることになり、 測った値と導いた値の型が混ざります。 「群の逼迫」の語の意味が割れ、 群の逼迫の通知が印でも出ます。

+ 利点

  • 判定の出力の型を変えずに済む
  • 通知と doctor の pressure= の形がそのまま使える

− 欠点

  • 窓と使用率の無い状態を窓の値に偽り、 測った値と導いた値の型を混ぜる (DR2・C10)
  • 群の逼迫の語の意味が割れ、 逼迫の通知が墓標でも出る (DR4)
OPT5席へ押し出す (合図の alarm か起こし直しの行に載せる)不採用

管理 tick の合図の末尾の alarm の語か、 起こし直しの初手の 1 行に墓標の口座を載せ、 席から人へ伝えさせる。 決め手は分析 (墓標の席は読めず、 他の席も再 login できない)。

周期の仕事の合図の末尾の語か、 起こし直しの最初の 1 行に印のある口座を載せ、 席から人へ伝えさせる案です。 人が板や doctor を見ていなくても席の画面に出て、 席が人に login し直しを頼める点で勝ります。 けれども、 印のある席は合図を読めず、 他の席への合図は黙った席にしか出ません。 合図の語と差し込みの閉じた一覧を広げ、 席の画面の行も増えます。

+ 利点

  • 人が板や doctor を見ていなくても、 席の画面に出る
  • 席が人に再 login を頼める

− 欠点

  • 墓標の席は合図を読めず、 他の席の合図は黙った席にだけ出る (DR4)
  • 合図の語の閉じた列と差し込みの閉じた一覧 (FR27・FR44) を広げ、 席の画面の行が増える (DR5)
OPT6語を 4 つにして期限切れも名指す不採用

判定の語を ok・expired・dead・missing にし、 期限の過ぎた token も expired として出す。 決め手は分析 (期限切れは Claude Code が使う時に refresh する一時の形)。

判定の語を ok・expired・dead・missing の 4 つにし、 期限の過ぎた鍵も expired として出す案です。 鍵の file の状態を細かく見せられ、 期限の近さを板で追える点で勝ります。 けれども、 期限切れは Claude Code が使う時に自分で更新する一時の形で、 期限の時刻を根拠にした知らせは誤報の源として前の裁定が退けています。 既存の語 present を割るので、 板の読み方も変わります。

+ 利点

  • file の状態を細かく見せられる
  • 期限の近さを板で追える

− 欠点

  • 期限の時刻を根拠にした知らせは false alarm の源で、 前の裁定が退けた (DR3)
  • 既存の語 present を割り、 消費側の板の読みが変わる (DR4)
OPT7合図の門を今のままにする不採用

管理 tick の判定の列を変えず、 墓標の席にも合図を送り、 群の判定は打刻を通った周にだけ撃つ。 決め手は分析 (無駄な turn が続き、 群の判定が最長 3600 秒遅れる)。

周期の仕事の判定の並びを変えず、 印のある席にも合図を送り、 群の判定は状態の記録を通った周にだけ撃つ案です。 判定の並びと理由の語を変えずに済み、 login し直した後の最初の合図が人の手なしに席の続きを促す点で勝ります。 けれども、 印のある席に 1 時間ごとに合図が届き、 そのたびに落ちる turn と計測の記録が増えます。 最後の状態の記録が「作業中」のままなので、 印のある席の周の群の判定は最長 3600 秒遅れます。

+ 利点

  • 判定の列と理由の語を変えずに済む
  • 再 login の後の最初の合図が、 人の手なしに席の続きを促す

− 欠点

  • 墓標の席に 1 時間ごとに合図が届き、 そのたびに落ちる turn と計測の記録が増える (DR5)
  • 最終行の Busy のせいで、 墓標の席の周の群の判定が最長 3600 秒遅れる (DR1)
OPT8読めない file に 4 つ目の語 unreadable を足す不採用

file が在るのに読めない・JSON でない・形が違う周を present でなく unreadable と出す (agent view と trust の読みと同じ形)。 決め手は分析 (present は「file が在り墓標と読めない」までしか言わず、 unreadable で決まる判断が無い)。

鍵の file が在るのに読めない・形が違う周を、 present でなく 4 つ目の語 unreadable と出す案です。 agent view と trust の読みの語と形が揃い、 読めない file を板で見分けて人が早く見に行ける点で勝ります。 けれども、 agent view と trust の語は判断の前提の値なので、 読めないを on や missing に潰すと偽の値になりますが、 present は「file が在り印と読めない」までしか言わないので、 読めない file を入れても偽になりません。 門を閉じ群を移すのは dead だけで、 unreadable の語で決まる判断が無く、 既存の試験の期待も動きます。

+ 利点

  • agent view と trust の読みの語の形と揃い、 読めない file を板で見分けられる
  • 読めない file の口座を人が早く見に行ける

− 欠点

  • agent view と trust の語は判断の前提の値なので読めないを on や missing に潰すと偽の値になるが、 credential の present は「file が在り墓標と読めない」までしか言わないので、 読めない file を入れても偽にならない (C11 は破れない)
  • 門を閉じ群を移すのは dead だけで、 unreadable の語で決まる判断が無く、 既存の fixture の期待も動く (DR5・C17)
OPT9doctor の群の行の pressure= に dead を出す不採用

群の今の口座が墓標なら、 群の行の pressure= を unmeasured でなく dead にする。 決め手は分析 (current= と口座の行の credential= で既に引ける)。

群の今の口座に印があれば、 doctor の群の行の pressure= を unmeasured でなく dead にする案です。 群の行 1 行だけで印で移る群と移れない群が見え、 板が口座の行を引かずに済む点で勝ります。 けれども、 群の行の current= と口座の行の credential= で既に引けるので、 足すのは既に在る事実の写しになります。 pressure= は使用率の値の欄で、 印の語を混ぜると欄の意味が割れます。

+ 利点

  • 群の行 1 行だけで、 墓標で移る群と移れない群が見える
  • 板が口座の行を引かずに済む

− 欠点

  • 群の行の current= と口座の行の credential= で既に引け、 足すのは既に在る事実の写しになる (DR5・C17)
  • pressure= は使用率の値の欄で、 墓標の語を混ぜると欄の意味が割れる (DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 印の判定は鍵の file を読む 1 本の関数で、 返す語は present・missing・dead の 3 つだけです。 群の移動の判定は移る理由を「群の逼迫」と「印」の 2 つで持ち、 印のある口座を測らず、 移り先と予約から外します。 周期の仕事は印のある席に合図を送らず、 判定行の理由を停止の記録の席なら今どおり heartbeat-off、 そうでなければ account-dead とし、 窓が shell に戻った群の席は起こす前に群の判定を撃ちます。 知らせは同じ 1 本の判定から出る語で、 doctor と口座の一覧の口座の行は dead、 周期の仕事の判定行は account-dead と出します。

採用 — OPT1

器 SHALL 口座の credential の墓標 (claudeAiOauth.expiresAt が 0) を、 口座の設定 dir の credential の file を読む 1 本の関数で判じる。 墓標の判じは計測 (SRS FR33) の token の読みと同じ 1 本で、 関数は閉じた語 present・missing・dead だけを返す。 file が無ければ missing、 墓標と読めれば dead、 それ以外 (期限切れ・読めない・形が違う・token が無い) は present とする。 関数は計測を起こさず、 file に書かず、 token をどの出力にも出さない。 器が credential を読むのは計測とこの判定の 2 つに限り、 口座を足す口は credential を読まず書かない。 群の移動の判定 (ADR-0066) SHALL 契機を閉じた 2 値 (群の逼迫・墓標) で持ち、 群の今の口座が墓標なら群の逼迫と同じ予約・群の記録・承認 event (群の宣言の逐語)・退避の合図・猶予・/exit・起こし直しで移る。 判定 SHALL 墓標の口座を測らず、 移り先の候補と予約の読みから外す。 先の群の今の口座が墓標なら、 その群も予約を持つ。 event の種類と形・記録の形・承認の逐語は変えず、 契機を記録しない。 管理 tick SHALL 登録 row の口座が墓標の周、 状態の打刻と梯子の記録を読まずに群の判定 (鮮度の窓に 1 回まで) へ進み、 移った周は同じ周の移動の門が退避を撃ち、 移らない周は合図を送らず、 判定行の理由は停止の記録の席なら今どおり heartbeat-off、 そうでなければ account-dead とする。 窓が shell の周は、 群の今の口座が墓標なら起こす前に同じ群の判定を撃ち、 群の今の口座 (移った周は移り先) で起こす。 file は周ごとに読むので、 墓標でなくなった次の周から今の列に戻る。 知らせ SHALL 同じ 1 本の判定から出る語 (doctor と口座の一覧の口座の行は credential=dead・管理 tick の判定行は理由 account-dead) の 2 か所で持ち、 群の行の欄と席へ押し出す口は足さない。 rules 行・event・口・依存・極性一覧は足さない。 実装は設計 account-lifecycle.md §38 (契約表の行 ab・ac・ad)。

器は、 口座の鍵の file の期限の値が 0 の印を、 口座の設定 dir の鍵の file を読む 1 本の関数で判じます。 印の読み方は計測と同じ 1 本で、 関数は present (在る)・missing (無い)・dead (印) の 3 語だけを返します。 file が無ければ missing、 印と読めれば dead、 期限切れ・読めない・形が違う・鍵が無いといったそれ以外は present です。 関数は計測を起こさず、 file に書かず、 鍵を出しません。 器が鍵の file を読むのは計測とこの判定の 2 つだけで、 口座を足す口は読みも書きもしません。 群の移動の判定は、 移る理由を「群の逼迫 (使用率の閾値越え)」と「印」の 2 つで持ち、 今の口座に印がある群も群の逼迫と同じ予約・群の記録・承認の記録 (群の宣言の文)・退避の合図・猶予・/exit・起こし直しで移ります。 判定は印のある口座を測らず、 移り先と予約の候補から外します。 先の群の今の口座に印があれば、 その群も予約を持ちます。 移る理由は記録に書きません。 周期の仕事は、 席の口座に印がある周は状態の記録と合図の間隔の記録を読まずに群の判定 (鮮度の窓に 1 回まで) へ進み、 移った周は同じ周の移動の門が退避を撃ちます。 移らない周は合図を送らず、 判定行の理由は、 合図を止める記録 (停止の記録) の在る席なら今どおり heartbeat-off、 そうでなければ account-dead です。 窓が shell に戻った周は、 群の今の口座に印があれば起こす前に同じ群の判定を撃ち、 群の今の口座 (移った周は移り先) で起こします。 鍵の file は周ごとに読むので、 login し直した次の周から今の並びに戻ります。 知らせは同じ 1 本の判定から出る語 (doctor と口座の一覧の口座の行は credential=dead・周期の仕事の判定行は account-dead) の 2 か所で持ち、 群の行の欄と席へ押し出す口は足しません。 鍵の file を読む 1 本の関数を選んだのは、 計測の記録は測った時の写しで、 login し直した後も古い死を見せ、 測られていない口座の印を出せないからです。 file を読めば判じる時の実物になり、 計測と同じ印の読み方を共有するので判じ手は 1 本のままです。 読めない file を present に入れるのは、 present が「file が在り印と読めない」までしか言わないので読めない file を入れても偽にならず、 agent view と trust の語のように判断の前提を潰す形と違って、 門を閉じ群を移すのを確かな印の dead に限るためです。 印のある群を移すのは、 群を移す手 (予約・記録・承認・退避・起こし直し) が群の逼迫のために既に在り、 移す手そのものを足さずに済むからで、 知らせるだけでは人が気づくまで席が止まります。 印を群の逼迫に含めないのは、 窓の値を偽ると測った値と導いた値が混ざるからです。 印のある席に合図を送らないのは、 印の席は合図を読めず、 送るたびに落ちる turn と計測の記録が 1 時間ごとに増えるからです。 印のある席で状態の記録を読まずに群の判定へ進むのは、 印の席の最後の状態の記録が「作業中」のまま残り、 読んでから進むと群の判定が最長 3600 秒遅れるからです。 窓が shell に戻った群の席で起こす前に群の判定を撃つのは、 起こし直しは群の今の口座で起こすので、 判定を待つと印の口座で起こして席が login の画面で止まり、 後の判定で移っても退避の合図と /exit が届かないかもしれないからです。 群の行の pressure= に dead を出さないのは、 群の行の current= と口座の行の credential= で既に引け、 使用率の値の欄に印の語を混ぜると欄の意味が割れるからです。 期限切れを present にするのは、 門を確かな印でだけ閉じ、 期限の時刻での誤報を避けるためです。 知らせを既存の行の語に置くのは、 印のある席は合図を読めず、 新しい口と語の一覧と欄を足さずに人と板が見る面で見分けられるからです。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR38claimFR38 (群の逼迫の通知と移動) の契機と候補の門の側。 本 ADR は、 群の今の口座が墓標の群も群の逼迫と同じ移り先の決め方と記録と承認と退避と起こし直しで移り、 墓標の口座を測らず、 移り先と予約の候補から外し、 先の群の今の口座が墓標ならその群も予約を持つと主張する。 FR38 の字 (閾値のどれか以上の群について移る・候補は鮮度の内側の実測を持ち閾値未満) に墓標の契機と候補の門を書き足すことと、 判定と語を名指す要件 1 つ (受入 1 つ) を足すことは、 持ち主の SRS の改訂の回である。
FR27claimFR27 (管理 tick) の判定の列の側。 本 ADR は、 登録 row の口座が墓標の席には合図を送らず (判定行の理由は停止の記録の席なら今どおり heartbeat-off、 そうでなければ account-dead)、 その席は状態の打刻の門で止めずに群の移動の判定へ進み、 窓が shell の群の席は群の今の口座が墓標なら起こす前に判定を撃つと主張する。 FR27 の送る条件は必要条件の列なので送らない条件の追加とは矛盾しないが、 条件の並びの正本を ADR-0058 とする字を本 ADR へも向けるのは SRS の改訂の回である。
FR58rationaleFR58 (口座の登録・退役・復帰) は、 口座を足す口が credential を読まず書かないと決める。 本 ADR はその口の振る舞いを変えず、 器が credential を読むのを計測と墓標の判定の 2 つに限る根拠に使う。 FR58 の平易の層の「器は credential を読みも書きもしない」を口座を足す口に閉じた字へ直すのは SRS の改訂の回である。
FR33rationaleFR33 (口座残量の計測) は、 読めない回を理由つきで測れなかったと記録し、 0 に読み替えない。 本 ADR はその墓標の読みを判定の 1 本として共有し、 群の移動の判定が墓標の口座を測らないだけで、 計測の理由・記録の形・計測の口は変えない。
FR59rationaleFR59 (席の起動) は、 起こし直しの口座を、 置き場が群に属する周は群の今の口座に決める。 本 ADR は窓が shell の周に、 起こす前に群の判定を撃つだけで、 口座の決め方は変えない (移った周は群の今の口座が移り先になる)。
