設計判断記録 (ADR) scribe2 — 発話の仕分けと席の問い

user の発話は要望・答え・会話の 3 つに仕分け、 席の問いは台帳の問いにする — 仕分けの event・未仕分けの発話を告げる turn の終わりの 1 度の止め・裁定面の答えの口・問いの asked と後付けの数え (ADR-0083 の 7 点 〔発話の使い道と席へ運ばない線・結び済みの断り・裁定の行の形・問いの門・計測の欄と、 裁定面の経路について C7.2 の読み・DR1・決定 (2)・原則〕 を部分 supersede)

ADR-0083 は user の打った字を全部記帳し、 席の問いを台帳の問いに立てて答えの字を結ぶ形を決めた。 けれども要望になるべき発話を bead にするかは席の判断のままで、 しなかったことを誰も数えず、 席の問いの多くは平文のまま台帳に立たず、 1 つの発話で複数の問いに答える形も、 裁定面で答える形も無い。 本 ADR は、 発話を要望・答え・会話の 3 つのどれかに仕分けさせ、 まだ告げていない未仕分けの発話が在る turn の終わりを 1 度止めて告げ、 席の問いに問いのきっかけの印を持たせ、 画面の答えを器の口 1 つで裁定にする形を決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session、 「user」は器を使って決める人、 「台帳」は仕事と裁定を記録する beads、 「裁定面」は別の project が持つ、 user が裁定を書き込む画面です。 前の決定 (ADR-0083) で、 器は user が打った文 (発話) を一字一句全部記録し、 席から user への問いを台帳の決まった形 (台帳の問い) に立てて答えの文と結ぶことにしました。 けれども、 発話を要望として控え (memo) にするかは席の判断のままで、 しなかったことを誰も数えず、 席の問いの多くはチャットの平文の中だけに在り、 1 つの発話で複数の問いに答える形も、 裁定面で答える形もありませんでした。 本 ADR は、 user の発話を 要望・答え・会話 の 3 つのどれかに仕分けさせ (仕分けないものは未仕分けと数えて見せ)、 まだ告げていない未仕分けの発話が残ったまま席が turn (1 回の応答) を終えようとしたら器が 1 度だけ止めて未仕分けの発話の番号を全部告げること (告げ済みの発話だけなら止めません)、 席の問いに問いのきっかけの印 (asked) を持たせ、 答えの後に立てた問いの結びを器が印ごとに数える (seat の印の分が、 席がチャットだけで問うてから問いを立てた形です。 印は席が付け、 器は正しさを判じません) こと、 裁定面の答えを器の口 1 つで裁定として記録し、 答えの行と記録にチャットか画面かの経路を残すことを決めます。 その口は承認を受ける口ではありません。 要件 FR88・FR89 を支え、 FR82・FR65・FR22・FR44 の改訂の理由を持ち、 FR81・FR27・FR90・FR94・NFR5 に実装の形を与え、 ADR-0083 の一部を置き換えます。 裁定面の答えを裁定と認めることは、 user が裁定 (2026-09-28T13:47Z) で決めました。 その代わり、 画面の答えについては「言葉は user が打った文だけ」という信頼の線を画面の分だけ下げます (席が起こした別の process や器の plugin を積まない session から撃てば答えを作れ、 器は経路で分けて数えるだけです)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 7 つで示します。 経緯 (前の決定は user の文を全部記録し、 問いと答えを結ぶ口を置いたが、 記録の使い道を 2 つに閉じた)・事象 (要望が控えにならずに落ち、 席の問いはチャットの中だけで、 1 つの文で答えた複数の問いを結べない)・現物 (器の hook の口は 6 つで、 turn の終わりの hook は席を「空いた」と記録し、 定期の見回りは記録を全部読む)・隣の形 (別の project は自分の画面の答えを自分の台帳に書き、 チャットの文は席が控えへ手で写す)・前の器の直命の表との線・憲法の向き (裁定面の字も user の言葉と読むか、 承認を受ける面、 編集の時点で止める約束の読み方)・射程 (動かすものと動かさないもの) です。

CTX1

経緯 — ADR-0083 は user の全 prompt を記帳し、 台帳の問い台帳に立てる問いと発話を結ぶ口を置いたが、 発話の使い道を結びと計測の分類に閉じた

ADR-0083 は、 器の名を言う repo で器の plugin を積む対話の session に user が打った prompt を、 問いの有無に依らず event kind UtteranceReceived (actor が human・発話を指す値は ts) に逐語で記帳し (範囲は裁定 user 2026-09-28T09:04Z)、 席は口 seat ruling bind で台帳の問いと発話を結び、 器が裁定 id を発行して裁定の行問いに書く答えの 1 行 (裁定 id・問い・発話の ts・逐語の 4 欄) と close と裁定 event裁定を結んだ記録 (RulingReceived に key ruling と utterance) を書く形を決めた。 bind は、 その ts の発話がちょうど 1 つ在って未だ結ばれていない周だけ結ぶ。 決定 (4) は発話 event人が打った字の記録 を直命の表user の発言の旧い表でないとし、 状態を持たせず、 使い道を bind の写し元と到達点の計測の分類 (結ばれない発話の本数を別の欄に出す) に閉じた。 DR1 は「裁定の字は持ち主が打った字だけで、 席はその字を打てない」 (持ち主は本 ADR の語では user) で、 発話 event の書き手は prompt の入口の hook だけである。 同じ ADR は、 消費側の裁定面裁定を書く画面の server だけが id を発行して台帳へ書き器は発話を記録しない案を、 scribe2 の user はその面を通らないことと、 器の門の働きが器の外の server の在否に依ることで退けた。 1 つ目の理由 (scribe2 の user はその面を通らない) は、 2026-09-28T13:14Z の裁定 (scribe2 の問いもその画面の決定待ちの一覧に並ぶ) で変わった。

CTX2

事象 — 要望が bead にならずに落ち、 席の問いは平文のまま台帳に立たず、 1 つの発話で答えた複数の問いを結べない

発話を要望として memo にするかは席の判断で、 しなかったことを誰も数えない。 2026-09-28 の実測では、 発話から bead への辺は器の台帳でも消費側の project の台帳でも 0 本で、 同じ日に、 消費側の席から頼まれていた整理が memo にならずに落ちた。 器の台帳の問いは全期間で 0 本 (2026-09-28 に初めて 1 本) で、 席から user への問いはチャットの平文の中にだけ在り、 圧縮で消え、 待っている問いの数も年齢も出ない。 FR82 を実装しても結ぶ先は台帳の問いだけで、 要望の取りこぼしは残る。 user は 1 つの発話で 3 つの問いに答えることがあるが (2026-09-28T13:14Z の裁定がそれ)、 bind は結び済みの発話を断るので 2 つ目からは結べない。 user は問われる前に指示を出すことも多く、 問いを後から起こして結ぶ形は正しい後付けでもあるので、 後付けを全部数えると、 席が対話の session だけで問うてから問いを起こした形を測れない。

CTX3

現物 — hook の口は 6 つで、 Stop の hook は idle を打ち、 管理 tick は event log を全部読み、 event の行は key を足せる

器の plugin の hooks.json の hook は SessionStart・PreToolUse・PermissionRequest・UserPromptSubmit・Stop・PreCompact の 6 つで、 PostToolUse は無い。 UserPromptSubmit の hook は今は席の状態の打刻と群の合図の行だけで、 発話 event は仕様だけ (event の kind の閉じた型は 24 値で UtteranceReceived はまだ無い)。 Stop の hook は席の状態を idle と打刻し、 管理 tick はこの打刻を読んで黙った席に合図を送る。 管理 tick は周ごとに event log を全部読み (この host で 2026-09-28 に約 7.4 MB)、 台帳と git は撃たない。 hook の呼び出しは道具 1 回につき 2 回以内・各 2.0 秒以内で重い I/O を持たない (NFR5)。 event の行は schema 1 の flat な JSON で、 任意の key を足す変更は同じ schema 番号のまま読め、 kind は閉じた型の末尾に足す (ADR-0004 §2.5)。 起票の門台帳の書き込みを止める門 (ADR-0056) は席の道具の呼び出しの bd / bdw の command の字面だけを読み、 台帳を読まない (ADR-0085)。 memo の子に問いを起こすと label intake:memo を継ぐ (2026-09-28 の実測)。 器が台帳へ書くのは、 land の終端の close (ADR-0051) と、 bind の裁定の行と close (ADR-0083) だけである。

CTX4

隣の形 — 消費側の project の 1 つは、 自分の画面の答えを自分の台帳の問いの notes に書き、 user の発話は席が memo に手で写す

消費側の project の 1 つは、 画面で問いに答えると、 その server が自分の台帳の問いの notes に裁定の行を 1 行足して問いを閉じる (新しい bead は作らない)。 問いの bead そのものは、 その project の席が Bash から起こす。 server は自分の repo の台帳だけに書き、 その server は席が Bash から起こす常駐の process として走りうる。 チャットでの user の発話は、 席が memo の notes へ手で写すだけで、 どの bead へも辺を持たない。 user は 2026-09-28T13:14Z に、 席の問いを必ず台帳の問いにし、 チャットで答えても画面で答えても同じ裁定の行になる形を採り、 scribe2 の問いもその画面の決定待ちの一覧に並ぶ。 その画面から scribe2 の台帳の問いに答える口は器に無く、 FR82 の末文は、 席が逐語を打って裁定 event を記帳する口を器は持たない、 と書いていた。

CTX5

直命の表との線 — 仕分けの判定と名指しの読みは発話 event の新しい使い道で、 状態と運びの線を引き直す要がある

ADR-0031 の直命の表は、 user の発言を 1 件ずつ状態 (有効か・閉じたか) 付きで event に持ち、 復元の DATA で逐語を席へ運んだ。 ADR-0045 §2 (2) はこれを消し、 ADR-0083 (4) は発話 event がその復活でない線を、 状態を持たないことと使い道を 2 つに閉じることで引いた。 仕分けには、 発話が仕分け済みかを判じる読み手 (turn の終わりの判定と局面の出力・その出力を読む doctor) と、 前の session の発話の中身を席が読む口が要る。 どちらも ADR-0083 (4) の使い道の外で、 黙って足すと廃止した表が戻ったと読まれる。 ADR-0083 の DR5 は「記録を席へ運ばず」、 原則の note は「席へは id だけを返す」と書く。 違いを決めるのは、 仕分け済みかが発話 event の欄の書き換えでなく別の event から導かれるか、 逐語が席の指示文・復元・合図・通知・一覧へ運ばれるか、 席へ押し込まれるか席が名指して引くか、 である。

CTX6

憲法の向き — C7.2 の逐語を裁定面の答えにも読むか、 C7 の受理面、 C16 の編集の時点、 C2 の 1 つの関数、 C17.2 の消すもの

C7 は承認をちょうど 1 つの対話面 (rules 行 R-C7-1) で受け、 C7.2 は受けた承認を user の逐語を運ぶ承認 event に記録する。 ADR-0016 §2.3 は承認の対話面を R-C7-1 のままとし、 対話面を増やさないと決めている。 ADR-0083 は、 裁定の行について C7.2 の逐語を器の hook が prompt の入口で記録した字と読み、 結びの口を承認の受理面と読まない (承認は便の承認 pipe approve が受ける) と決めた (ADR-0083 CTX6)。 裁定面 (消費側の project が持つ、 user が裁定を書き込む画面と server) への書き込みは、 これまで器の裁定 event でも承認 event でもなかった (ADR-0077)。 画面の答えを裁定にするには、 この逐語の読みを画面の字へ広げる要があり、 それは「逐語は user が打った prompt だけ」という信頼の線を画面の分だけ下げる (user は 2026-09-28T13:47Z にこれを認め、 裁定の行・裁定 event・計測に経路を区別して残す推奨を採った・裁定 id s2-07l.739.1:20260928T1347Z-1)。 C16 は仕様からの逸脱を編集の時点で止め、 後の確かめで代えない。 席の返答の平文は道具の呼び出しを経ずに user へ出るので、 出る前に止める hook は無い。 C2 は選択と除外と振り分けをちょうど 1 つの関数に置く。 C3 は host・口座・席・lease・退役の状態を 1 つの DB に置く (管理 tick の梯子の記録のような hook と tick の控えは席の置き場の file に在る・FR27)。 C15 は台帳を task と裁定に限る。 C17.2 は記録・走査・仕組みを足す前に消すものを名指させ、 N2 は散文にしか無い規則を規則と認めない。 本 ADR は C7.2・C7・C16 の読みを決める (ADR を書く条件 1)。

CTX7

射程 — 動かすのは発話の key・仕分けの event と口・turn の終わりの止め・名指しの読み・1 発話 n 問と裁定の行の経路の欄・裁定面の答えの口・問いの asked問いのきっかけ と数えの 7 つ

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を測る 7 本のものさしです。 user の発話は 1 つ残らず仕分け済みになるか未仕分けと数えられ、 席の判断で黙って落ちないこと。 台帳の記録の種類を増やさず、 器が台帳へ書く範囲を広げないこと。 前の器の直命の表を戻さないこと。 文を打つ経路と turn の終わりを軽く保つこと。 チャットでも画面でも同じ裁定の行になり、 どちらの経路かを数えで分けられること。 席がチャットだけで問うてから問いを立てた形を、 字面の推測でなく記録の前後で数えること。 足すものを最小にし、 消すものを名指すことです。

DR1user の発話は 1 つ残らず、 3 つの仕分けのどれかで仕分け済みになるか、 未仕分けと数えられ、 席の判断で黙って落ちない CTX2・CTX4

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 8 つ並べます。 3 つの仕分けと 1 度の止めと裁定面の答えの口と問いの印を置く案 (選んだ案)、 記録だけにする今の形、 要望を控えと別の種類の記録にする案、 要望に仕分けるときに器が控えの欄へ発端 (どこから来たか) を書く案、 席はチャットで問い答えの後に問いを立てる今の形、 重い問いだけを台帳に立てる案、 裁定面の server が scribe2 の台帳へ直に書く案、 scribe2 の問いはチャットだけで答える案です。

OPT1発話を要望・答え・会話の 3 つに仕分け、 未仕分けの発話行き先の無い発話を告げる turn の終わりを 1 度止め、 画面の答えは器の口 1 つで裁定にし、 問いに asked を持たせる採用

発話 event に session と発話の経路 (chat＝対話の session・gui＝裁定面) を足し、 裁定の行に経路の欄を足して 5 欄にする。 発話の ts は器が発話ごとに一意に振る (同じ秒は秒より下の桁で分ける)。 要望と会話は仕分けの口が仕分けの event を 1 件記帳するだけで台帳を書かず (3 クラスの承認・runner への回答・go に使った発話も会話で、 承認 event と回答 event には結ばない)、 答えは bind か裁定面の答えの口の裁定 event で仕分け済みになる。 1 つの発話は複数の memo と問いへ仕分けてよい。 仕分け済みかは event だけを読む 1 つの関数が導き、 発話を記帳する対話の session (runner と lens を除く) で未仕分けの発話のうちまだ告げていないものが在る turn の終わりは、 turn の終わりの判定の hook が 1 度だけ止めてその session の未仕分けの発話の ts を全部並べ、 告げ済みだけなら止めず、 判定の入力を読めない周は止めずに読めないことを記帳する。 席は ts を名指して 1 件の逐語を読める。 画面の答えは器の口 1 つが標準入力で逐語を受け、 断る周は発話 event も書かず、 通る周は経路 gui の発話と bind と同じ書きを 1 周で行い、 席の道具の呼び出しとしての撃ちは器の hook の入口が断る。 台帳の問いは asked (seat・user) を持ち、 裁定 event が asked と問いの起票の時刻を持ち、 問いの起票が発話より後の結びを doctor が asked の値ごと (asked 無しは前後に依らず別) に数える。 決め手は分析 (OPT2〜OPT8 の欠点) と裁定 13:12Z・13:14Z・13:47Z (推奨の案を採る)。

選んだ案です。 user の発話の記録に、 チャット (対話の session) か画面 (裁定面) かの経路を足し、 チャットの発話にはどの session で打たれたかも足し、 答えの行にも経路の欄を足します。 発話は 3 つの仕分けのどれかで仕分け済みにします。 要望は、 席が仕分けの口で開いた控え (memo) を名指し、 器が記録に 1 件足して結びます。 答えは、 台帳の問いへ結んで裁定にします。 会話は、 同じ口で台帳を変えずに仕分け済みにします (承認や go の返事に使った発話も会話です)。 発話の番号は器が 1 つずつ別に振り、 同じ秒の発話も分けます。 1 つの発話は複数の控えと問いへ仕分けてよく、 会話は他の仕分けを持つ発話には付けられず、 後から要望か答えを足すと会話の仕分けは外れます。 仕分け済みかどうかは記録だけを読む 1 つの関数が決め、 まだ告げていない未仕分けの発話が残ったまま席が turn を終えようとすると、 器が 1 度だけ止めて未仕分けの発話の番号を全部並べて口を告げます (中身は運ばず、 告げ済みの発話だけなら止めません)。 席は番号を名指して 1 件の中身を自分で読めます。 裁定面の答えは、 器の口 1 つが文を受けて画面の経路の発話として記録し、 同じ周に裁定にして番号を返します (空白だけの文や閉じた問いへの答えは何も記録せずに断ります)。 席が自分の道具でこの口を撃つことは器の hook の入口が止めます。 台帳の問いは問いのきっかけ (席が user の判断を求めたか、 user の先立つ指示や方針を受けるためか) の印を持ち、 答えの後で立てた問いの結びを器が印ごとに数えます。 良い点は、 発話が黙って落ちず、 器が台帳へ書く範囲も台帳の記録の種類も増えず、 中身を席へ押し込まず、 turn の終わりの判定が軽く、 チャットと画面が同じ形の裁定になって経路で分けて数えられ、 席が問うた後付けと正しい後付けを混ぜずに数えられることです。 代わりに、 裁定面の答えは信頼の線を下げ (席が起こした別の process や器の plugin を積まない session からは口を撃て、 席は任意の文を渡して答えを作れる)、 問いの印と仕分けの正しさは器が判じず、 turn が延び控えの置き場が増え (止めの理由を Claude Code がどう扱うかは未実測です)、 版を跨ぐ約束が増え、 止めの判定に要る記録を読めない回は止めずに通し、 合図を送らない席には定期の知らせの語が届かず doctor の行だけが知らせることを引き受けます。

+ 利点

  • 未仕分けの発話は turn の終わり・doctor・管理 tick の alarm に必ず出て、 席の判断で黙って落ちない (DR1)
  • 要望の結びも会話の仕分けも event 1 件で、 器は台帳を書かず、 台帳の記録 (bead) の種類も増えない。 発端どこから来たかの結びの正本は仕分けの event の 1 か所 (DR2)
  • 仕分け済みかは別の event から導き、 発話 event の欄を書き換えない。 turn の終わりに告げるのは ts の列だけで、 逐語は席が名指して引いたときだけ読む (DR3)
  • turn の終わりの判定は台帳を読まず、 session の開始から後ろの event だけを読むので、 event log の全体の大きさに依らない (読みの形は設計 doc) (DR4)
  • チャットの答えも裁定面の答えも同じ形の裁定の行と裁定 event になり、 行と記録の経路の欄で数えを分けられる (DR5)
  • 後付けの結び後から立てた問いの結びを asked の値ごとに分けて出すので、 席が user へ問うた問いの後付け (seat) と、 方針や問われる前の指示の正しい後付け (user) を混ぜない (DR6)
  • 消すもの (計測の結ばれない発話の欄・bind の結び済みの断りの広さ) を名指して足す (DR7)

− 欠点

  • 画面の答えの口は、 逐語の信頼の線を画面の分だけ下げる。 器の hook の入口は器の plugin を積む session の道具の呼び出しの command の字面だけを見るので、 席が起こした子 process (常駐の server・script を経た撃ち) と器の plugin を積まない session からは撃て、 席は起こした server へ任意の字を渡して経路 gui の発話と裁定を作れる。 器はそれを経路で分けて数えるだけで止めない
  • asked の値は席が問いの create で書くので、 席が後付けの問いを user と書けば seat の数えに出ない。 器は asked の正しさも、 仕分けの正しさ (要望を会話に仕分ける誤り) も判じない
  • turn の終わりの止め告げていない分で止めるは、 まだ告げていない未仕分けの発話が現れた turn の終わりごとに席の turn を 1 回ぶん延ばす。 告げ済みの ts の控えと session の開始の位置を state dir の session ごとの置き場に持つ (跨版でない置き場が 1 つ増える)。 止めの理由を Claude Code が transcript でどう扱うか (入力欄への差し込み〔FR44〕と同じに扱わないか) は未実測 (AC58 の歯は偽の hook の入力で撃つので Claude Code の扱いは測らない。 器が止めの理由を差し込みと数えないことだけを AC19 と AC58 が確かめ、 本物の session での確かめは設計 doc が置く)
  • 跨版の面が増える: event kind 2 (UtteranceSorted・TurnEndUnjudged)・発話 event の key 2 (session・channel) と ts の秒より下の桁・裁定 event の key 3 (asked・question_ts・channel)・台帳の問いの metadata 1 (asked)・裁定の行の欄 1 (経路・4 欄の既存の行は対話の session と読む)・口 3 (utterance sort・utterance show・seat ruling answer)。 古い版の読み手は未知の kind と key を読めない
  • turn の終わりの判定の入力 (event log・告げ済みの控え) を読めない周は止めずに通し (fail-open)、 読めないことを TurnEndUnjudged に記帳するだけなので、 その周の未仕分けの発話は doctor と局面の出力でしか見えない
  • 管理 tick が合図を送らない席 (梯子の列が尽きた席・FR78 で止めた席) には alarm の unsorted も届かず、 doctor の行だけが知らせる
OPT2記録だけにする (ADR-0083 と FR82 のまま)不採用

発話は全部記帳し、 仕分けるかは席の判断に任せ、 計測は結ばれない発話の本数を別の欄に出すだけにする。 決め手は分析 (今日と同じ取りこぼしが残る) と裁定 13:12Z (3 つの仕分けの推奨を採る)。

今の決定のまま、 発話は全部記録するが仕分けるかは席に任せ、 結ばれない発話の数を計測に出すだけにする案です。 器に新しい event の種類も口も足さず、 席の turn も止めず、 記録の使い道も狭いままで済む点で勝ります。 けれども、 要望を控えにするかは席の判断のままで、 しなかったことを誰も数えず、 2026-09-28 と同じ取りこぼしが残ります。 結ばれない数は会話と要望が混ざって取りこぼしの数と読めず、 どの発話がどの要望になったかも辿れないので退けました。

+ 利点

  • 器に新しい kind も口も hook の働きも足さず、 跨版の面が増えない
  • 席の turn は止められず、 user との往復が延びない
  • 仕分けの判定という新しい読み手を持たないので、 発話 event の使い道が ADR-0083 (4) のまま狭い

− 欠点

  • 要望を bead にするかは席の判断のままで、 しなかったことを誰も数えず、 2026-09-28 と同じ取りこぼしが残る (DR1)
  • 結ばれない発話の本数は会話と要望が混ざり、 取りこぼしの数として読めない (DR1)
  • 発話から memo への辺を置く場所が無く、 どの発話がどの要望になったかを辿れない (DR1)
OPT3要望を memo と別の種類の bead にする不採用

要望に仕分けた発話ごとに、 memo と別の label の bead (要望の記録) を台帳に起こし、 後で memo か契約へ上げる。 決め手は分析 (種類が増え、 memo との境目の判断がまた要る) と裁定 13:12Z。

要望に仕分けた発話ごとに、 控え (memo) とは別の種類の記録を台帳に作る案です。 要望が台帳の中で独立に見え、 裁定面も台帳だけで一覧を出せ、 発話と要望の対を台帳の欄で辿れる点で勝ります。 けれども、 台帳の記録の種類が 1 つ増え、 要望と控えの境目の判断が席にまた要り、 要望ごとに記録が増えて台帳が膨らみ、 器が作るなら器の台帳の書きが広がり、 既存の控えに足すだけの要望にも別の記録が要るので退けました。

+ 利点

  • 要望が台帳の中で独立の記録として見え、 裁定面も台帳だけを読めば要望の一覧を出せる
  • 発話と要望の対が bead の欄に残り、 event log を読まずに辿れる
  • 要望の段と memo の段を別に数えられる

− 欠点

  • 台帳の記録 (bead) の種類が 1 つ増え、 要望と memo の境目 (どこから memo に上げるか) の判断が席にまた要る (DR2)
  • 要望ごとに bead が増えて台帳が膨らみ、 起こす書き手が器なら器の台帳の書きが close の外へ広がる (DR2)
  • 1 つの発話が既存の memo に足すだけの要望でも、 別の bead を起こす手が要る (DR7)
OPT4要望の仕分けで、 器が memo の metadata に発端を書く不採用

仕分けの口が発話を要望に仕分ける周に、 器が名指した memo の metadata へ発端 (発話の ts) を追記する。 決め手は分析 (器の台帳の書きが close と裁定の行の外の update へ広がる)。

要望に仕分けるときに、 器が名指した控えの欄 (metadata) へ発端 (どこから来たか) の発話の番号を書き足す案です。 発端が台帳の控えに在り、 裁定面も席も台帳 1 か所を読めば辿れ、 仕分けの記録を足さずに済む点で勝ります。 けれども、 器が台帳へ書くのは land の終端の close と、 裁定の行と close だけという線を越えて、 欄の書き足しへ広がります。 入れ子の欄を合わせて書く道具が器に無く (外の依存を使わない約束)、 台帳の道具の書きが置き換えか合わせかも測っておらず、 席の別の書き足しとも競り、 発端の置き場が本文の節と欄の 2 つになるので退けました。

+ 利点

  • 発端が台帳の memo の欄に在り、 裁定面も席も台帳 1 か所を読めば辿れる
  • 仕分けの event を足さずに済む
  • memo を開けば、 どの発話から来たかがすぐ分かる

− 欠点

  • 器の台帳の書きが、 land の終端の close と bind の裁定の行と close の外の update へ広がる (ADR-0045 §2・ADR-0051 の線) (DR2)
  • 入れ子の JSON を併合して書く道具が器に無く (実行時の依存は 0 本・NFR3)、 bd の metadata の書きが置換か併合かも実測されていない。 席が書く別の metadata の書きとも競る (DR2)
  • 発端の置き場が memo の本文の 1 つ目の節 (人が読む写し) と metadata の 2 つになり、 どちらが正本かの判断が要る (DR7)
OPT5席はチャットの平文で問い、 答えの後に問いを起こして結ぶ (今の形のまま)不採用

席の問いを台帳に先に立てることを求めず、 user が答えた後に席が問いを起こして bind で結ぶ。 決め手は分析 (待っている問いが見えない) と裁定 13:14Z (席の問いは必ず台帳の問いにする推奨を採る)。

席の問いを台帳に先に立てることは求めず、 席はチャットの平文で問い、 user が答えた後に問いを立てて結ぶ、 今の形のままの案です。 問いを立てるときの欄も門も足さず、 席の問い方が今のままで、 答えは今でも裁定の行になる点で勝ります。 けれども、 待っている問いが台帳に無く、 圧縮で消え、 数も年齢も裁定面の決定待ちの一覧にも出ず、 席が平文で問うたことと正しい後付けを分けて数えられないので退けました。

+ 利点

  • 問いの create に新しい欄も門も足さず、 席の問い方が今のまま
  • 答えは今でも bind で裁定の行になり、 裁定の証拠は変わらない
  • 問いを立てる手間が答えの後にしか要らず、 答えられなかった問いが台帳に残らない

− 欠点

  • 待っている問いが台帳に無く、 圧縮で消え、 数も年齢も裁定面の決定待ちの一覧にも出ない (DR5)
  • 席が平文で問うたことと正しい後付けを分けられず、 平文の問いを数えられない (DR6)
OPT63 クラスと憲法の問いだけを台帳に立て、 ほかはチャットで問う不採用

重い問い (消す・出す・使う・憲法と閾値) だけを台帳の問いに立て、 軽い問いは平文で問う。 決め手は分析 (軽重の境目の判断がまた要る) と裁定 13:14Z。

消す・出す・使うの操作と憲法や閾値の問いのような重い問いだけを台帳に立て、 軽い問いはチャットで問う案です。 台帳の問いが少なく、 user の決定待ちの一覧が重い問いだけになり、 軽い問いは速く済む点で勝ります。 けれども、 どの問いが重いかの判断が席にまた要り、 その誤りは誰も数えず、 軽い問いへの答えは台帳に残らず、 チャットと画面で同じ裁定になる形が一部の問いにしか効かないので退けました。

+ 利点

  • 台帳の問いの数が少なく、 user の決定待ちの一覧が重い問いだけになる
  • 軽い問いはチャットの往復で速く済む
  • 重い問いは必ず記録に残る

− 欠点

  • どの問いが重いかの判断が席にまた要り、 境目の誤りは誰も数えない (DR6)
  • 軽い問いへの答えは台帳に残らず、 チャットと画面で同じ裁定の行になる形が一部の問いにしか効かない (DR5)

消費側の project が自分の台帳に対して今している形を scribe2 の問いにも広げ、 その server が scribe2 の問いの notes に裁定の行を書いて問いを close する。 決め手は分析 (画面の答えに器の口の断りも裁定 id の発行も記帳も効かない・ADR-0083 が退けた形に近い) と裁定 s2-07l.739.1:20260928T1347Z-1。

選んだ案と、 それが支える要件です。 user の発話は、 要望 (開いた控えを名指して結ぶ)・答え (台帳の問いへ結んで裁定にする)・会話 (台帳を変えずに仕分け済みにする) のどれかに仕分け、 要望と会話は器の記録に 1 件足すだけで台帳を書きません。 仕分け済みかどうかは 1 つの関数が決め、 まだ告げていない未仕分けの発話が残る turn の終わりは 1 度だけ止めて番号を全部告げ、 告げ済みの発話だけなら止めません。 席は番号を名指して前の発話の中身を自分で読めます。 1 つの発話で複数の問いに答えられ、 答えの行はチャットか画面かの経路の欄を持つ 5 欄になります。 裁定面の答えは器の口 1 つが受けて裁定にし (承認は受けず、 断るときは何も記録しません)、 席が自分の道具でその口を撃つことは器の hook の入口が止めます (席が起こした別の process からの撃ちは門の外です)。 台帳の問いは問いのきっかけの印を持ち、 答えの後で立てた問いを器が印ごとに数えます。 記録の使い道は広げますが、 中身を席へ押し込むことはしません。

発話 event (FR82) の key channel が持つ閉じた 2 値 (対話の session・裁定面。 機械の値は chat と gui)。 対話の session (chat) は prompt を発話の記帳の hook が記帳したもの、 裁定面 (gui) は画面の答えを器の答えの口が標準入力で受けたもの。 裁定 event と裁定の行も経路を持ち、 計測は裁定 event を経路ごとに数え (FR22)、 4 欄の既存の裁定の行は対話の session と読む。 選択式の問いを止めた周に告げる問いの経路 (ADR-0084) とは別。
発話の仕分けutterance sorting
user の発話の行き先を決める閉じた 3 つの形 (SRS の語は 仕分け・FR88)。 要望 (開いた memo へ発端として結ぶ・event kind UtteranceSorted の sorting=request)・答え (台帳の問いへ結んで裁定にする・裁定 event)・会話 (台帳を変えずに仕分け済みにする・sorting=chat。 3 クラスの承認・runner への回答・go に使った発話も会話で、 承認 event と回答 event には結ばない)。 要望と会話は仕分けの口 utterance sort が記帳し (actor は machine で人由来の数えに入らない)、 器は台帳を書かない。 仕分けが正しいかは器が判じない。
未仕分けの発話unsorted utterance
発話 event のうち、 仕分けの event も裁定 event の結びも持たないもの。 判定は event だけを読む 1 つの関数で、 turn の終わりの止めと局面の出力が同じ入力に同じ結果を出し、 doctor の行と管理 tick の alarm の語 unsorted は局面の出力の判定の結果を読む (FR94)。
turn の終わりの止めturn-end stop
器が発話 event を記帳する対話の session (runner と lens を除く) で席の turn が終わる周に、 その session の未仕分けの発話のうち止めでまだ告げていないものが 1 つ以上在れば、 turn の終わりの判定の hook が 1 度だけ終わりを止め、 その session の未仕分けの発話の ts を全部並べて仕分けの口を告げること。 判定の入力を読めない周は止めずに TurnEndUnjudged を記帳する (fail-open)。 止めた周は、 登録された席の session なら idle を打たない。 告げ済みの未仕分けの発話だけの周は止めない。 入力欄への差し込み (FR44) ではなく、 逐語は運ばない。
答えの口answer mouth
裁定面が台帳の問いへの答えを器に渡す器の口 (seat ruling answer)。 逐語を command の字面の外 (標準入力) で受け、 空白だけ・問いが閉じている・bead が問いでない周は発話 event も書かずに断り、 通る周は経路 gui の発話 event と bind と同じ書きを 1 周で行って裁定 id を 1 行返す。 bind と同じく裁定の行を書く口で、 承認の受理面でなく承認 event を記帳しない。 席の道具の呼び出しとしての撃ちは器の hook の入口 (起票の門とは別) が断るが、 席が起こした子 process の撃ちは門の外。
裁定面ruling surface
消費側の project が持つ、 user が裁定を書き込む画面と server (器の外の置き場・ADR-0077)。 面への書き込みは器の裁定 event でも承認 event でもないが、 本 ADR 以後、 scribe2 の台帳の問いへの答えを答えの口へ渡した分だけは器の裁定 event になる。 承認 event はどの分も受けない。
裁定の行ruling line
台帳の問いの notes に器の口 (bind と答えの口) だけが書く 1 行 (ADR-0083)。 本 ADR で裁定 id・問い・発話の ts・発話の経路・逐語の 5 欄にする。 裁定 id を 1 つ目の欄に、 逐語を最後の欄に置く (user の字の中の区切りの字で欄が割れない) のは ADR-0083 のまま。 4 欄の既存の行は経路を対話の session と読む。
台帳の問いledger question
席から user への問いを記録する台帳の bead (label intake:question・ADR-0083)。 本 ADR で metadata asked を持ち、 label intake:memo を併せ持たず、 親を名指す create は親の label を継がない指定を持つ。 形は起票の門が検査する。
askedasked
台帳の問いの metadata の key (問いのきっかけ・値の意味は FR89)。 閉じた 2 値 seat (席が user の判断を求めた問い) と user (user の先立つ指示や方針を受けるために席が起こした問い)。 欠けと値の外は起票の門が断る。 値の正しさは器が判じない。
後付けの結びlate-raised binding
台帳の問いが、 結んだ発話より後に起票された結び。 doctor が asked の値ごとの件数と裁定 id で出し、 asked を持たない問いの結びは、 後付けか否かに依らず asked 無しとして別に数える。 asked が seat の分は席が対話の session だけで問うてから問いを起こした形 (FR89)、 user の分は先立つ指示や方針を受けた後付け。
裁定 eventruling event
bind か答えの口が問いと発話を結んだときに 1 件記帳する event (kind RulingReceived・ADR-0083)。 欄とその列挙は FR82 が持ち、 本 ADR が機械の key asked・question_ts・channel を足して key の名の一覧の正本を持つ。 到達点の計測では承認の側に数え、 経路ごとに分ける。 承認 event とは別の kind。
直命の表directive table
前の器が user の発言を 1 件ずつ状態付きで持ち、 復元で席へ運んだ記録 (ADR-0031)。 ADR-0045 §2 (2) で消えた。 発話 event は状態の欄を持たず、 仕分け済みかは別の event から導き、 逐語を席へ押し込まないので、 これの復活でない。
部品part
局面の出力 (FR90) が局面と手番を導く単位で、 閉じた 9 種 (発話・台帳の問い・memo・契約・開いた契約の最新の便・契約表の行・要件・epic・器の便でない着地の commit)。 本 ADR が触るのは発話の部品で、 ts・session・行き先だけを持ち逐語を持たない。
発端origin
部品を生んだ上流。 memo なら生んだ user の発話で、 その結びの正本は仕分けの event (sorting=request・FR88)、 memo の本文の 4 つの節の 1 つ目は人が読む写し。 器の便でない着地の commit なら発端の trailer が名指す台帳の bead (FR92)。
起票の門ledger write gate
器の plugin を積む席の hook が bd / bdw の書きに掛ける門 (ADR-0056)。 本 ADR で、 台帳の問いの create の asked の欠けと値の外・label intake:memo の併せ持ち・親を名指して親の label を継がない指定を持たない書きを断る形を足す。 command の字面だけを読み、 台帳を読まない。 答えの口の撃ちを断る器の hook の入口の判定とは別。
