設計判断記録 (ADR) scribe2 — 問いと裁定の記録

席から持ち主への問いは台帳の問いに立て、 裁定は器が記帳した持ち主の発話に結ぶ — 発話 event と seat ruling bind・裁定 id の実在の門 (ruling-check の opt-in)・未反映の裁定は関わる契約だけを待たせる (ADR-0037 の書き手の口・時刻の id・doctor の突合と、 ADR-0016 §2.3 の逐語の置き場を部分 supersede)

ADR-0037 は便の無い裁定を、 席が逐語を打つ口で記録し、 器が打った時刻を裁定 id にした。 その字が持ち主のものか、 引かれた id が本当の裁定を指すか、 決めたことが文書に写されたかを、 器は確かめられない。 本 ADR は、 問いを台帳の問いの形に閉じ、 持ち主の打った字を器が全部記帳し、 席は問いと発話を結ぶだけにし、 引用の実在と未反映を字の数えで判じる形を決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session、 「持ち主」は器を使って決める人 (user)、 「台帳」は仕事と裁定を記録する beads です。 これまで持ち主の決め (裁定) は、 席が持ち主の言葉を自分で打ち直して記録していたので、 本当に持ち主の字か、 文書が引く裁定の番号が本当に在るか、 決めたことが文書に写されたかを、 器は確かめられませんでした。 本 ADR は、 席から持ち主への問いを台帳の決まった形 (台帳の問い) に立てること、 器の名を書いた目印を持つ repo で、 持ち主が器の plugin を積む対話の session に打った文を器が一字一句そのまま全部記録すること (発話 event・器が差し込んだ行と別の session から届いた文は除く)、 席は問いとその記録を結ぶだけで言葉を打てないこと、 宣言で選んだ repo では文書が引く裁定の番号が本当に在るかを、 どの repo でも文書へ写していない裁定を、 器が文字を数えて確かめることを決めます。 台帳の問いは、 台帳の点検にも便を起こす列にも数えません。 結びの口は承認を受ける口ではなく、 便の承認とその言葉は今のままです。 要件 FR81〜FR84 を支え、 FR22・FR65 の改訂の理由を持ち、 FR10・FR27・FR51・FR68 の改訂に実装の形を与え、 ADR-0037 と ADR-0016 の一部を置き換えます。 記録する範囲は持ち主が裁定 (2026-09-28T09:04Z) で全部と決め、 記録は文を打つたびに伸びます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 7 つで示します。 経緯 (裁定は、 席が言葉を打つ口と時刻の番号で記録してきた)・事象 (字が持ち主のものか、 番号が本当に在るか、 文書に写されたかを確かめていない)・現物 (持ち主の文は器の hook を通り、 台帳の書き込みは門を通り、 列と着地には待たせる形がある)・隣の形 (別の project は自分の画面と server で同じ役を持つ)・前の器の直命の表との線・憲法の向き (逐語と裁定の番号と承認を受ける面の読み方、 検査を選ぶ印の置き場の読み方)・射程 (動かすものと動かさないもの) です。

CTX1

経緯 — 裁定は ADR-0037 で「席が逐語を打つ口」と「器が打つ時刻の id」になり、 席から持ち主への問いは記録の形を持たない

ADR-0037 は便の無い裁定を event kind RulingReceived (actor が human・便を持たない) として持ち、 書き手を対話面の席の口 seat ruling add 1 つに限り、 裁定 id裁定を指す番号 をその event の ts とし、 doctor が rules 行の裁定の欄 (user <分までの時刻>) ごとに同じ分の event の有無を読む形を決めた。 逐語はこの口の引数で、 席が打つ。 ADR-0016 §2.3 は user の逐語を承認 event にだけ載せると定めた。 席から持ち主への問いを記録する形は器に無く (EventKind の 24 値にも台帳の label にも無い)、 裁定が「どの問いへの答えか」を指す欄も無い。 runner の質問 record (ADR-0016 §2.2) は便の中の問いで、 持ち主への問いではない。 現物の実測 (main d6d9513・2026-09-28): rules manifest の 77 行のうち裁定の欄が時刻の形の行は 60 行 (分まで在る 54 行・分の 1 桁が x の 6 行)、 別の番号の形 12 行、 そのほか 5 行で、 分まで在る 54 行のうち同じ分の RulingReceived を持つのは 2 行だけ (この host の event log)。 追跡された file 423 本のうち時刻の形の引用を持つものは 70 本で、 うち 32 本は凍った決定記録 (書き換えず、 改訂は supersede する新しい記録で行う) である。 同じ main の .rs の行のうち policy: の字を含むものは 74 行で、 どれも code の名前付きの引数か型注釈である。

CTX2

事象 — 裁定の字が持ち主の字か、 引かれた id が本当の裁定か、 決めたことが文書に写されたかを、 器は確かめない

器の検査は、 rules 行の裁定の欄が空でないこと、 値を変えて裁定の字が同じ行を断ること (rules-diff)、 doctor の同じ分の突合 (数えるだけ) の 3 つで、 引かれた裁定 id が実在の裁定を指すかを確かめる検査は 0 である。 seat ruling add の逐語は席が打つ字なので、 持ち主の言い換え・記憶違い・会話で聞いた気がする判断も同じ形で記録される。 消費側の project の 1 つの実測では、 台帳の bead の id に「席の判断」を添えた字が裁定の欄として形の検査を通った。 持ち主が決めたことが文書に写されたかを数える面も無く、 写し忘れは、 次の設計と契約が古い文書を正として読むまで見えない。 持ち主は問われる前に指示を出すことも多い。

CTX3

現物 — 持ち主の prompt は器の hook を通り、 台帳の書きは起票の門台帳の書き込みを止める門を通り、 列と tick と着地には待たせる型が在る

器の plugin の hooks.json は UserPromptSubmit で器の hook を撃つ (今は席の状態の打刻と群の合図の行だけ)。 hook は prompt の経路で走るので、 台帳も git も読まない形が要る (台帳の読み 1 回は約 0.35 秒・ADR-0045 の実測)。 器が席の入力欄へ差し込む行は閉じた一覧 (FR44: 起動行・管理 tick の打刻の合図・群の通知と合図・便の終端の周の通知・裁定の指し示し) で、 どれも器の雛形の形を持つ。 起票の門 (ADR-0056) は席の道具の呼び出しの bd / bdw の書きに掛かり (席が Bash から起こした子 process の書きは見ない)、 memo の 4 節の判定を持つ。 起動の列は memo を label で外し、 台帳の lint は epic と decision の型を契約に数えない。 vessel 宣言repo の宣言 (.vessel.toml・ADR-0010) は任意 key を持て、 検査を測らないと repo が名乗る key の前例が在る (ADR-0054)。 起動の列の待ち理由は閉じた 8 値、 受付の断りは閉じた 23 値で、 列の全部を待たせる先例 HostBusy が在る。 着地の前提 (FR10) には push の走査が着地を止める間 (FR50) の留めが在り、 SRS 版 0.28 はこの留めを、 便を Gated に留めて理由の event を便ごとに 1 件だけ記帳し (同じ理由が続く周は記帳し直さない)、 撃ち直しの上限 (FR11) に数えず Failed にしない形に書く (FR50 の留めの code は main に未着地)。 dispatch の周が置き場へ file を書き、 管理 tick は台帳も git も撃たずにそれを数えるだけ、 という型が事前審査に在る。

CTX4

隣の形 — 消費側の project の 1 つは、 自分の台帳と自分の裁定面の server で同じ役を持つ

消費側の project の 1 つは、 型 task で label intake:question の bead・notes の裁定の行問いに書く答えの 1 行 (裁定 id・問い・逐語の欄をこの順に持ち、 裁定 id は <問い>:<UTC の年月日と時分>-<n> の形)・close_reason「裁定 <裁定 id>」を使い、 id は自分の裁定面の server だけが発行して、 自分の経路で台帳へ書く (その server は席が Bash から起こす常駐の process として走りうる)。 その台帳は batch: と policy: で始まる id の形も使い、 裁定の行に裁定 id の欄と別の束の欄 (batch: の形の id を持つ) を持つこともある。 その repo の決まった done の文は、 台帳に解けない batch: などの形の字面を fixture として持ち、 scribe2 自身の FR82 と FR83 の歯 (未着地) も、 台帳に無い裁定 id の形を fixture に持つことになる。 scribe2 の持ち主は端末の対話の session で答え、 その server を通らない。

CTX5

直命の表持ち主の発言の旧い表との線 — 前の器は持ち主の発言を 1 件ずつ状態付きで持って席へ運び、 ADR-0045 がそれを消した

ADR-0031 の直命の表は、 持ち主が対話面で言った発言のうち席の行動を拘束するものを 1 件ずつ event (DirectiveIssued / DirectiveClosed) に持ち、 状態と前提 pointer を typed に持ち、 復元の DATA が有効な直命を逐語で並べて席へ運んだ。 ADR-0045 §2 (2) はこれを席の自律機能と共に消し (状態の置き場を増やす・C3 / C2.2)、 SRS の FR65 は「器は user の発言を event log に持たない」と書いていた。 持ち主の打った字を全部記帳する形は、 字面だけ見ればこの表の復活に見える。 違いを決めるのは、 記録が席へ運ばれるか (起動行・圧縮の直前の枠・合図・通知・一覧) と、 記録が状態 (有効か・閉じたか) を持つかである。

CTX6

憲法の向き — C7.2 の「逐語」・C5 と A2 の「裁定 id」と C7 の経路の読み、 C1 の下での opt-in の key の置き場の読みが要る

C7 は承認をちょうど 1 つの対話面 (rules 行 R-C7-1・値は orchestrator) で受け、 C7.2 は受けた承認をすべて user の逐語を運ぶ承認 event として記録する。 C7 の人の層は「会話の記憶を承認の根拠にしない」と書く。 ADR-0037 は C7.2 の「承認」に裁定を含めて読み、 裁定の記帳も R-C7-1 の席の権能 (SRS FR41 の「承認の記帳」) に数えて、 書き手の口で席の役割を確かめた。 ADR-0016 §2.3 も承認の対話面を R-C7-1 のままとし、 対話面を増やさないと決めている。 C5 は裁定 id の無い rules 行の変更を CI が落とすと定め、 C14.2 は裁定 id を正本の側 (原則と裁定は文書の版・規則は manifest の行) に付け、 C15 / C15.2 は台帳を task と裁定に限り、 規則を変える PR と台帳の項目が裁定 id を引くことを求める。 CI は private な台帳に届かない。 C1 は規則の値 (有効 / 無効の旗を含む) を manifest 1 つに置く。 ADR-0010 は、 repo が自分について名乗る値を vessel 宣言に置き manifest は上限を持つ、 と C1 を適用した。 C3 は状態を 1 つの DB (event log) に置く。 N1 は不可逆な削除をしない。 C17.2 は走査・記録・rules 行・仕組みを足すなら先に消すものを名指させる。 N2 は散文にしか無い規則を規則と認めない。 本 ADR は、 裁定の行についての C7.2 の逐語と C5 の裁定 id の読み、 C7 の受理面の読み (結びの口 seat ruling bind は台帳の問い台帳に立てる問いに裁定の行を書く口で、 承認の受理面ではない。 承認は便の承認 pipe approve が受け、 FR41 の承認の記帳の権能と役割の確かめもそこに残る)、 ruling-check の置き場の読みを決める (ADR を書く条件 1)。 便の承認の逐語は本 ADR の読みの外に置き、 変えない。 A2 と C7 の経路の読み (orchestrator の読み・持ち主の常設の指示 2026-09-28T00:54Z の下・持ち主が異を唱えれば改める): 憲法の規範文は、 A1・A3・A4.2 では承認を C7 の対話面を通して取ると書き、 A2 では裁定 id を伴う user 裁定を取ると書く (A2 の機構は rules 行の diff と裁定 id・C5 が CI で強制)。 C7 の機構の欄の「A1 / A2 / A3 / A4 の承認はすべてこの経路を通る」と §2.2 の「確認の経路は C7 が定める 1 つの対話面だけ」(どちらも出所は SPEC §2・ADR-0003) は、 承認 (relay 印と承認 event) の受理面を 1 つに保つ文と読み、 A2 の裁定 id を発行する口を縛る文とは読まない。 よって結びの口 seat ruling bind は A2 の型の裁定と裁定の行の裁定 id を発行し、 C7 の単一の受理面 (pipe approve が記帳する承認 event) は変えない。

CTX7

射程 — 動かすのは門の形・発話の記帳・結びの口・引用の数え・未反映の待ちの 5 つ

動かすのは、 (1) 起票の門の断りの形 (台帳の問いの形・席が書く裁定の行) と、 台帳の問いを台帳の lint と起動の列から外すこと、 (2) 発話 event人が打った字の記録 の kind と記帳と計測での数え方、 (3) 結びの口 seat ruling bind と裁定 id の形と裁定の行、 seat ruling add と doctor の同じ分の突合の退役、 (4) vessel 宣言の任意 key ruling-check と ruling-fixtures と引用の実在の判定 (受付・着地・doctor)、 (5) 未反映の裁定文書が引いていない裁定の判定と待ち (置き場の file・doctor・tick の alarm・起動の列・着地) の 5 つで、 要件は SRS 版 0.28 の FR81〜FR84 と FR10・FR22・FR27・FR51・FR65・FR68 の改訂が持つ。 動かさないのは、 R-C7-1 の値、 便の承認 (pipe approve の逐語と役割の確かめ・FR15 / FR16 / FR41)、 裁定の指し示しの口 (ADR-0077) と裁定面の記帳 id、 RulingReceived の kind と到達点の計測での承認の側、 event log の schema 版、 memo の引き金の形と審査・床の検査・選択式の問いの遮断 (どれも別の決定記録) である。 ADR を書く条件のうち 1 (C7.2・C5・C1 の読み)・3 (event の kind と key・notes の裁定の行の形・vessel 宣言の key は版を跨ぐ形)・4 (却下案を残す価値のある分岐) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を測る 7 本のものさしです。 裁定の字は持ち主が打った字だけで、 席は打てないこと。 問われる前の指示も後から結べること。 引かれた番号が本当に在るかを器の門が確かめ、 文書の意味は読まないこと。 決めたことが文書に写されるまで関わる契約は進まず、 関わらない契約は止めないこと。 前の器の直命の表を戻さないこと。 持ち主の文の経路を軽く保ち、 器の外の server や道具に依らず、 問い・結び・実在・未反映の段の順に着地できること。 足すものを最小にし、 消すものを名指すことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 7 つ並べます。 台帳の問いと持ち主の全部の文の記録と結びの口を置き、 引用を文字で数える案 (選んだ案)、 席が言葉を打つ今の口を残して引用の確かめだけを足す案、 別の project の裁定の画面の server だけが番号を出す案、 文書の道具が書き出す引用の一覧を読む案、 写していない裁定がある間は全部の便を止める案、 問いが開いている間だけ持ち主の文を記録する案 (持ち主は裁定で全部を記録する案を採りました)、 写し先の種類を 5 つに分ける案です。

OPT1台帳の問いと、 持ち主の全 prompt の発話 event と、 結びの口を置き、 引用の実在と未反映を字の数えで判じる採用

器が問いとして読む記録を label intake:question の台帳の問い (4 行と effect の 2 値) に閉じ、 台帳の lint と起動の列はこの label の bead を契約にも memo にも数えない。 起票の門は席の道具の呼び出しの 3 形を断り、 席が起こした子 process の書きは門の外で通す。 器の hook が持ち主の prompt を問いの有無に依らず発話 event に記帳し、 その turn に発話の ts だけを返す。 席は seat ruling bind で問いと発話を結び、 器が裁定 id を発行して裁定の行・close・裁定 event を書く。 席が逐語を打つ口 seat ruling add は消す。 ruling-check を宣言した repo では、 FR83 と FR84 が共有する閉じた規則が追跡された file の字から裁定 id の形を数え (問い id の形は台帳の接頭辞のものだけ・batch: と policy: の形と線の後の時刻の形は ruling-fixtures の一覧に在る字面を外す・batch: と policy: の形は束の欄にも解ける)、 受付で断り、 着地では FR10 の留めに掛ける。 未反映の裁定は、 それを引く契約と問いに blocks される契約だけを待たせる。 決め手は分析 (OPT2〜OPT7 の欠点) と裁定 00:05Z・00:54Z、 記録の範囲は裁定 09:04Z (全 prompt を記録する推奨を採る)。

選んだ案です。 席から持ち主への問いは、 台帳に決まった形 (概要・技術・理由・推奨の 4 行と、 答えを文書へ写すべきかの印) で立てます。 器の名を書いた目印を持つ repo で、 持ち主が器の plugin を積む対話の session に打った文は、 問いの有無に依らず、 AI が読む前に器が一字一句そのまま記録し (器が自分で差し込んだ行・別の session から届いた文・実装役と審査役の AI の文は除きます)、 席にはその記録の番号だけを返します。 席は結びの口で問いと記録を結び、 器が裁定の番号を出して、 問いに答えの 1 行 (持ち主の言葉は記録から写す) を書き、 問いを閉じます。 席が言葉を打つ今の口は消します。 問いの印を持つ記録は、 台帳の点検にも便を起こす列にも数えません。 選んだ repo では、 文書が引く裁定の番号を器が文字の形で数えて台帳に本当に在るかを確かめ、 文書へ写していない裁定は関わる契約だけを待たせます。 数えるのは、 この repo の台帳の番号の頭 (接頭辞) で始まる問いの番号と、 宣言の見本の一覧 (ruling-fixtures) に無い batch: と policy: の形と、 同じ一覧に無い、 選んだ後に足した時刻の形だけで、 batch: と policy: の形は台帳の答えの行の束の欄にも解けます。 良い点は、 裁定の字が器の記録した持ち主の字からだけ写って席の手順に字を打つ口が無く、 問われる前の指示も結べ、 ほかの便を止めず、 test の見本は断られず、 持ち主の文の経路で台帳も git も読まないことです。 代わりに、 持ち主の文が全部手元の記録に残って打つたびに伸び (消す口は無い)、 打つたびに記録の鍵を取るので鍵の待ちが長い host では遅れうり、 結ばれない文の数は会話の量を映すだけで、 版を跨ぐ約束が増え、 席が記録へ偽の発話を直に書き足すか器の hook を偽の入力で撃てば偽の発話を作れ、 席が起こした別の process からの書き込み (台帳の書き込みの門の外) も塞がず、 文字の数えは意味を読まず (番号を引くだけで写したことになり、 形の偶然の一致も数える)、 結びの口は撃つ人の役割を見ず、 便の承認の言葉は席が打つまま残り、 同じ秒の文は結べず、 器の便でない変更が足す裁定の欄は doctor の数えでしか見えず、 止めた便は解く手が来るまで待ち続け、 見本の字を一覧に並べる手が要り (古い項目が残るとその字はいつまでも数えられない)、 一覧へ足すのに裁定は要らないので一覧は裁定なしに開く抜け道でもあり (歯止めは足した差分が見えることと一字違わない一致だけ)、 頭を打ち違えた番号も数えずに通ることを引き受けます。

+ 利点

  • 裁定の逐語は hook が記録した持ち主の字からだけ写り、 席の手順の中に字を打つ口が無い (DR1)
  • 問われる前の指示も発話として残り、 問いを後から起こして結べる (DR2)
  • 引用の実在を受付と着地が確かめ、 bead の id だけの判断の欄裁定を書く欄や opt-in の線検査を始めた commitの後の時刻の形を通さない。 数えは id の形だけを見るので文書の書式に依らない (DR3)
  • 未反映は関わる契約だけを待たせ、 写す変更 (器の便でない変更) は止めない (DR4)
  • 発話の記録は状態を持たず、 逐語を席へ運ぶ読み手を持たない。 席へ返すのは発話の ts だけ (DR5)
  • hook は台帳も git も読まず event を 1 行足すだけで、 器の外の server にも道具の書き出しにも依らず、 段の順に着地できる (DR6)
  • 消すもの (席が逐語を打つ口・新しい裁定の時刻の id・doctor の同じ分の突合) を名指して足す (DR7)
  • test の code の見本と決まった done の文の見本は、 ほかの接頭辞の問い id の形か ruling-fixtures の一覧で外れて門に断られず、 束の欄にも解くので消費側の台帳の束の欄の id も引ける (DR3・DR6)
  • 台帳の問いは型でなく label で lint と起動の列から外すので、 問いを型 task で立てる消費側の台帳でも、 問いが設計 pointer の無い契約として名指されも待たされもしない (DR6)

− 欠点

  • 持ち主の prompt が全部、 長さに依らず手元の event log に逐語で残り (雑談や誤って打った秘密の字も)、 log は prompt のたびに 1 件ずつ伸びる。 log は host の置き場に在り、 追跡も公開もしないが、 記録を消す口は器に無い (N1)
  • prompt のたびに hook が event log の lock を取って 1 行足すので、 lock の待ちが長い host では prompt が遅れうる (hook の時間の予算は無い)
  • 結ばれない発話が大半になり、 計測の別の欄の本数は会話の量を映すだけで、 指示の量とは読めない
  • event の kind 1 つ・裁定 event の key 2 つ・vessel 宣言の key 2 つ (ruling-check と ruling-fixtures)・起動の列の待ち理由 1 つ・受付の断りが増え、 跨版の面が広がる。 古い版の読み手は未知の kind と key を読めない (ADR-0037 と同じ代償)
  • 席が event log を直に書くか、 hook の口を偽の入力で撃てば、 偽の発話を作れる。 器はこの経路を塞がず、 塞ぐのは手順の中の口 (字を打つ口の不在と起票の門) だけである。 起票の門は席の道具の呼び出しにだけ掛かり、 席が Bash から起こした子 process の書き (消費側の裁定面の server など) は門の外で通るので、 子 process を通した裁定の行も塞がない
  • 字の数えは意味を読まないので、 id を引くだけで未反映は解け、 引用が本当に裁定を写したかは確かめない。 形の偶然の一致も数える
  • ruling-check を選んだ repo (器自身も) は batch: と policy: の形と線の後の時刻の形の見本を ruling-fixtures に並べる手が要り、 一覧に古い項目が残るとその字面はいつまでも数えられない。 一覧に項目を足す差分は裁定を要らないので、 一覧は裁定なしに開く免除の口で、 載せた字面は台帳に解けなくても受付と着地を抜ける。 歯止めは、 足した項目が差分として着地の審査に見えることと、 載せた字面が一字違わない完全一致でしか外れないことの 2 つだけである (どの版の宣言を読むか・差分が自ら足した項目で自分を外せるかは設計 § が決める)。 自分の接頭辞の問い id の形の見本は一覧で外せず、 ほかの接頭辞の問い id の形は、 接頭辞を打ち違えた引用でも数えずに通る
  • 結びの口は承認の受理面でないので撃ち手の役割を確かめない (証拠は発話で、 断りは 4 形に閉じる。 R-C7-1 の役割の確かめは便の承認 pipe approve にだけ残る)。 登録 row の無い、 持ち主が自分で開いた session の発話も裁定になる
  • 便の承認 (pipe approve) の逐語は席が打つ形のまま残り、 同じ秒に 2 つの session で打たれた発話は id で一意に指せず結べない
  • 器の便でない変更は着地の判定を通らないので、 そこで足した判断の欄の引用は doctor の数えでしか見えない
  • 着地の留めは撃ち直しの上限に数えないので、 解く手 (裁定を結ぶ・文書へ写す) が来るまで便は Gated に留まり続ける (理由の event は便ごとに 1 件で増えない)
OPT2席が逐語を打つ今の口 (seat ruling add) を残し、 引用の実在の検査だけを足す不採用

seat ruling add と時刻の id をそのまま使い、 追跡された file の引用が RulingReceived に解けるかだけを確かめる。 決め手は分析 (字が持ち主のものかを確かめられない)。

席が持ち主の言葉を打つ今の口を残し、 文書が引く番号が記録に在るかだけを足して確かめる案です。 器の変更が小さく、 持ち主の文を全部は記録せず、 口を撃てる席を対話の席に限る確かめも残る点で勝ります。 けれども、 言葉は席が打つので、 言い換えや記憶違いも同じ形で通り、 字が持ち主のものかは確かめられません。 答えが何の問いへのものかも残らず、 写し忘れを数えられず、 時刻の番号は同じ分の裁定を区別できないので退けました。

+ 利点

  • 器の変更が小さい。 hook に記帳を足さず、 口・歯・doctor の突合をそのまま使う
  • 持ち主の prompt を全部は記録しないので、 手元の log に持ち主の字が溜まらない
  • 口の撃ち手を対話面の席に限る確かめ (R-C7-1) が残る

− 欠点

  • 逐語は席が打つ字で、 言い換え・記憶違い・聞いた気がする判断も同じ形で通る。 実在の検査は「その event が在るか」までで、 字が持ち主のものかは確かめない (DR1)
  • 裁定が何への答えかが残らず、 文書へ写すべきかも分からないので、 未反映を数えられない (DR4)
  • 時刻の id は分までで、 同じ分の裁定を一意に指せない (ADR-0037 の代償のまま)
OPT3裁定面の server だけが裁定 id を発行する (消費側の project の形に加わる)不採用

持ち主は裁定面の画面に答えを書き、 その server が id を発行して台帳へ書く。 器は発話を記録しない。 決め手は分析 (scribe2 の持ち主はその面を通らず、 器の門が器の外の server に依る)。

別の project が既に使う形に加わり、 持ち主が裁定の画面に答えを書くと、 その server だけが番号を出して台帳へ書く案です。 席は字を打てず、 番号を出す所が 1 つに閉じ、 器は持ち主の文を記録せず hook に記帳も足さず、 答える場所が会話と分かれて明快な点で勝ります。 けれども、 その画面と server は器の外の別の project のもので、 scribe2 の持ち主は端末の対話で答えるので加われません。 器の門の働きが外の server の有無に依り、 server の無い repo では記録できず、 会話の中で出た指示は画面へ書き直さない限り結べないので退けました。

+ 利点

  • 消費側の project の 1 つが既に使う形で、 持ち主が画面に書いた字を server が記録するので、 席は字を打てない
  • id の発行が 1 か所に閉じ、 器は hook に記帳を足さない
  • 答えを書く面が会話から分かれ、 何に答えたかが画面で明快

− 欠点

  • 裁定面は消費側の project が持つ器の外の server で、 scribe2 の持ち主は端末の対話の session で答える。 scribe2 はその面に加われない (DR6)
  • 器の門の働きが器の外の server の在否に依り、 server を持たない repo では裁定を記録できない (DR6)
  • 会話の中で出た指示は画面へ写し直さない限り記録されず、 問われる前の指示を結べない (DR2)
OPT4引かれた id の集合を、 文書の道具の側 (隣の project) の書き出しから読む不採用

字の数えを器に置かず、 文書を生成する道具が引用の集合を書き出し、 器はそれを読む。 決め手は分析 (書き出しの着地を待つと段の順が崩れる)。

文書が引く番号を器が文字で数えるのでなく、 文書を作る道具 (隣の project) が引用の一覧を書き出し、 器はそれを読む案です。 文書の構造を知る読み手が拾うので偶然の一致を数えず、 読み手が 1 つに揃って器は字を数える仕組みを持たずに済み、 どの欄の引用かまで分かる点で勝ります。 けれども、 書き出しが出来上がるのを待つので、 確かめと未反映の段の着地が後ろへずれて順が崩れ、 器が隣の project の版に依り、 その道具を使わない repo や、 規則の表と code の中の番号を数えられないので退けました。

+ 利点

  • 文書の構造を知る読み手が引用を拾うので、 形の偶然の一致を数えない
  • 文書の読み手が 1 つに揃い、 器は字を数える関数を持たない
  • 引用がどの節のどの欄に在るかまで分かる
  • 文書の構造で見本と引用を分けるので、 見本の一覧も接頭辞の限りも要らない

− 欠点

  • 書き出しの着地が先に要り、 実在と未反映の段の着地がその後になる (段の順が崩れる) (DR6)
  • 書き出しの形式が器の跨版の約束に加わり、 器が隣の project の版に依る (DR6)
  • その道具を使わない repo の引用と、 rules manifest や code の中の字は数えられない (DR3)
OPT5未反映の裁定が在る間は起動の列の全部を待たせる不採用

床の検査と同じく、 未反映が 1 件でも在れば列の全部を待たせる。 決め手は分析 (関わらない契約まで止まる)。

文書へ写していない裁定が 1 つでも在る間は、 起こす便を全部待たせる案です。 写す手が最優先になり、 判定が単純で、 全部を待たせる前例と同じ形の点で勝ります。 けれども、 その裁定に関わらない契約まで止まり、 写す手 1 つの遅れが全部の便を止めます。 写す変更の多くは器の便でないので、 便を止めても写す手は速くならないので退けました。

+ 利点

  • 写す手が最優先になり、 未反映が長く残らない
  • 判定が単純で、 引く bead や blocks の辿りが要らない
  • 列の全部を待たせる先例 (HostBusy) と同じ型

− 欠点

  • 裁定に関わらない契約まで止まり、 写す手 1 つの遅れが host の全部の便を止める (DR4)
  • 写す変更の多くは器の便でないので、 列を止めても写す手は速くならない (DR4)
OPT6発話を、 開いた台帳の問いが在る周だけ記録する (grill の推奨)不採用

hook が prompt ごとに開いた問いが在るかを見て、 在る周だけ発話を記録する。 grill の論点 6 の推奨で、 00:54Z の常設の指示が承けていた形。 問われる前の指示は、 問いを起こした後に持ち主が言い直せば結べる。 決め手は分析 (問われる前の指示を言い直さずには結べず、 開いた問いを prompt の経路で知る手が要る) と裁定 09:04Z (持ち主は全 prompt を記録する推奨を採った)。

持ち主の文を、 台帳の問いが開いている間だけ記録する案です。 議論の中で最初に推された形です。 手元に残る持ち主の文が少なく (雑談や誤って打った秘密の字が残りにくい)、 記録の多くが答えの候補になり、 「問いへの答えだけを記録する」と目的が明快で、 発言を全部持った前の器の直命の表との違いが誰にも分かり、 問われる前の指示も、 問いを立てた後に言い直せば結べる点で勝ります。 けれども、 持ち主は問われる前に指示を出すことが多く、 結ぶには言い直してもらう手が要ります。 また、 問いが開いているかを知るには、 文を打つたびに台帳を読む (1 回約 0.35 秒かかる) か、 便を起こす周に器が書く一覧を読む (問いを立てた直後の答えが次の周まで記録されない) かのどちらかになり、 結果が問いの立て方の順に依ります。 持ち主は裁定 (2026-09-28T09:04Z) で全部を記録する推奨を採ったので退けました。

+ 利点

  • 記録が問いの在る周に限られ、 手元の event log に残る持ち主の字が少ない (雑談や誤って打った秘密の字が残りにくい)
  • 記録した発話の多くが答えの候補になり、 結ばれない発話の本数が小さく、 計測の別の欄が読みやすい
  • 「問いへの答えだけを記録する」と目的が字面で明快で、 発言を全部持った直命の表との違いが誰にも分かる
  • 問われる前の指示も、 問いを起こした後に持ち主が言い直せば結べる

− 欠点

  • 持ち主は問われる前に指示を出すことが多く、 その字は残らず、 結ぶには持ち主に言い直してもらう手が要る (DR2)
  • hook が開いた問いを知るには、 prompt ごとに台帳を読む (1 回約 0.35 秒が prompt の経路に入る) か、 dispatch の周が書く置き場の file を読む (問いを起こした直後の答えが次の周まで記録されない) かのどちらかになる (DR6)
  • 答えが問いを開く前か後かで扱いが分かれ、 結果が席の問いの起こし方の順に依る (DR2)
OPT7effect を 5 値 (srs / rules / adr / note / none) にする不採用

問いの時点で答えを写す置き場の種類を名指す。 決め手は分析 (器の判定に要るのは写すべきかだけ)。

問いの時点で、 答えを写す先の種類を 5 つ (要件書・規則の表・決定記録・メモ・写さない) から選ぶ案です。 写す先が早く分かり、 置き場ごとに数えられ、 写さない理由を分けて持てる点で勝ります。 けれども、 器は main の文字を数えて写したかを判じるので、 写す先の種類は判定を変えません。 要るのは写すべきかどうかの 2 つだけで、 値が増えると門と test が増え、 1 つの答えを複数の場所へ写す問いに合わず、 選ぶ時の迷いも増えるので退けました。

+ 利点

  • 写す先の種類が問いの時点で分かり、 写す手が迷わない
  • 置き場ごとに件数が見え、 写しの確かめを置き場に絞れる
  • 写さない理由 (note・none) を分けて持てる

− 欠点

  • 未反映は main の追跡された file の字で判じるので、 置き場の種類は判定を変えない。 器に要るのは「文書へ写すべきか」の 2 値だけ (DR7)
  • 閉じた値と起票の門の歯が増え、 1 つの答えを複数の置き場へ写す問いに合わない
  • note と none と operation の違いが曖昧になり、 起票の時点の迷いが増える
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが支える要件です。 問いは台帳の問いの形に閉じ、 問いの印を持つ記録は台帳の点検にも便を起こす列にも数えません。 台帳の書き込みの門は、 席が自分の道具で撃つ書き込みだけを見ます。 持ち主の文は問いの有無に依らず器が一字一句記録し、 席にはその記録の番号だけを返します。 席は結びの口で問いと記録を結び、 器が裁定の番号を出して問いに答えの 1 行を書き、 問いを閉じます。 この記録は前の器の直命の表ではなく、 席へは運びません。 結びの口は承認を受ける口ではなく、 便の承認の言葉は席が打つ今の形のまま変えません。 選んだ repo では文書が引く裁定の番号が本当に在るかを器が確かめ (test などの見本は、 ほかの頭の番号か宣言の一覧で外します)、 確かめられない変更の着地は止めて待たせ、 文書へ写していない裁定は、 それに関わる契約だけを待たせます。

台帳の点検にも便を起こす列にも数えません。 2 つ目、 器の名を書いた目印 (.vessel) を持つ repo では、 持ち主が対話の session に打った文を、 問いの有無に依らず、 AI が読む前に器が一字一句記録し、 席にはその記録の番号だけを返します。 器が自分で差し込んだ行・別の session から届いた文・実装役と審査役の AI の文は記録しません。 3 つ目、 席は結びの口で問いと記録を結び、 器が裁定の番号 (問いの番号・持ち主が打った時分・末尾の 1) を出し、 問いに答えの 1 行を書いて閉じ、 裁定の記録を残します。 1 つの記録は 1 つの裁定にだけ使い、 席が言葉を打つ旧い口は消します。 4 つ目、 この記録は前の器の直命の表ではなく、 状態を持たず、 席へは運びません。 人の手の数えには入れず、 結んだものは承認の側に、 結ばれない数は別の欄に出します。 5 つ目、 宣言の file で ruling-check を選んだ repo では、 文書が引く裁定の番号を器が文字の形で数え、 台帳に無い番号や、 選んだ後に足した旧い時刻の形を受付で断り、 着地でも止めます (止めた便はそのまま待たせ、 理由を 1 回だけ記録し、 撃ち直しの回数には数えません。 ruling-check (接頭辞) で始まる問いの番号だけで、 ほかの頭の番号は引用に数えず、 設計の節などに在っても断りません。 batch: と policy: の形と選んだ後の時刻の形は、 宣言の file の ruling-fixtures (見本の字をそのまま並べた決まった一覧) に一字違わず在れば数えず、 backtick などで囲んでも外れません。 batch: と policy: の形は、 消費側の台帳の答えの行の裁定の番号の欄か束の欄に一致すれば解けます。 6 つ目、 文書へ写すべき裁定を main のどの file も引いていない間は、 それを引く契約と問いを待つ契約だけを待たせ、 doctor と tick の合図で知らせます。 器の便でない写す変更は止めず、 経った時間では判じません。 裁定の証拠を持ち主が打った字だけにしたのは、 憲法 C7.2 が承認に持ち主の逐語を求め、 そうした問いは出さない決まり (要件カタログ R-F7) だからです。 代わりに、 見本を一覧に並べる手と、 裁定なしに足せる免除の口と、 古い項目が残る間その字が数えられないことと、 頭を打ち違えた番号が数えずに通ることは引き受けます。 batch: と policy: の形を束の欄にも解くのは、 消費側の台帳がその欄にも同じ形の id を書くからで、 結びの口が書く行は束の欄を持たないので本 repo の数えは変わりません。 問いの印を型でなく label で見るのは、 消費側の台帳が問いを型 task で立てるからです。 門を席の道具の呼び出しにだけ掛けるのは、 消費側の裁定面の server のように席が起こした別の process が自分の経路で答えの行を書くのを止めないためで、 その経路の偽造は代償として引き受けます。 未反映で関わる契約だけを待たせ、 着地の留めを撃ち直しの回数に数えないのは、 解く手 (裁定を結ぶ・文書へ写す) の多くは便の外に在り、 撃ち直すだけでは解けないからで、 理由は便ごとに 1 回だけ記録して周ごとに増やしません。 経った時間を使わないのは、 時間は写したかどうかと関係が無いからです。

この判断で良くなること 4 つと、 代わりに引き受けること 9 つです。 良くなるのは、 裁定の字が器の記録した持ち主の字からだけ写り、 席の手順に字を打つ口が無いこと、 問いと答えと写すべきかが台帳に残り写し忘れを器が数えること、 選んだ repo で確かめられない引用が成果に入らず、 test などの見本は断られないこと、 直命の表を戻さずに言葉を結べ、 結ばれない文の数も見えることです。 引き受けるのは、 持ち主の文が全部手元に残って打つたびに記録が伸び、 消す口が無いこと、 版を跨ぐ約束が増えること、 席が記録へ偽の発話を直に書き足すか器の hook を偽の入力で撃てば偽の発話を作れ、 席が起こした別の process からの書き込みも塞がないこと、 文字の数えは意味を読まず、 裁定を実装する契約は文書が先に番号を引くまで待つこと、 結びの口は承認を受ける口でなく撃つ人の役割を見ないこと、 便の承認や同じ秒の文などの穴が残り、 止めた便は解く手が来るまで待ち続けること、 旧い突き合わせが消え、 一度選ぶと裁定なしには外せないこと、 旧い口を使う test と設計を先に書き換える要があること、 見本の字を宣言の一覧に並べる手が要り、 その一覧へは裁定なしに足せ (歯止めは差分が見えることと一字違わない一致だけ)、 古い項目や頭を打ち違えた番号は数えずに通ることです。

⚖ トレードオフ・代償

  • ●字の数えは意味を読まないので、 id を引くだけで未反映は解け、 形の偶然の一致も数える。 裁定を実装する契約がその id を引くと、 設計の節など器の便でない変更が先に id を main に載せるまで待つ (設計 → 契約の順を拘束する)。 batch: と policy: の形の字句は設計 § が閉じ、 code の名前付きの引数と型注釈 (main の .rs に 74 行) を拾わないようにする
  • ●結びの口は承認の受理面でなく撃ち手の役割を確かめない (R-C7-1 の役割の確かめは便の承認 pipe approve にだけ残る) ので、 持ち主が自分で開いた登録 row の無い session の発話も裁定になる

  • ●doctor の同じ分の突合は消え、 ruling-check を持たない repo では裁定の引用を数えない。 一度選んだ repo は、 問い id の形の裁定なしに門を外せない
  • ●seat ruling add を使う歯・使い方の行・外形の snapshot と、 設計 dialogue-surface.md §4 の作法の行・fleet-event-log.md §9 を、 bind の実装より先に書き換える要がある
  • ●ruling-check を選んだ repo (器自身も) は batch: と policy: の形と線の後の時刻の形の見本を ruling-fixtures に並べる手が要り、 一覧に古い項目が残るとその字面はいつまでも数えられない。 一覧に項目を足す差分は裁定を要らないので、 一覧は裁定なしに開く免除の口で、 載せた字面は台帳に解けなくても受付と着地を抜ける。 歯止めは、 足した項目が差分として着地の審査に見えることと、 載せた字面が一字違わない完全一致でしか外れないことの 2 つだけである (どの版の宣言を読むか・差分が自ら足した項目で自分を外せるかは設計 § が決める)。 自分の接頭辞の問い id の形の見本は一覧で外せず、 ほかの接頭辞の問い id の形は、 接頭辞を打ち違えた引用でも数えずに通る
