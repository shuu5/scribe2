設計判断記録 (ADR) scribe2 — 憲法の置き場の宣言

憲法の置き場 — vessel 宣言の任意 key constitution が repo 相対の file の列を名乗って既定の docs/constitution.md を置き換え、 lens は名乗った file を 1 本ずつ §47 の 3 値で測り、 頼みの文の憲法の path の句をその列に差し替える

lens は起こす前に木の docs/constitution.md を測るが (設計 gate-cost §47)、 この path は器が自分の repo の作り方 (憲法から生成する写し) を決め打ちしたもので、 憲法の正本を別の形の file で持つ消費側の置き場は、 写しか正本を名指す file を 1 つ足さないと diff の審査を通れない。 本 ADR は、 vessel 宣言の任意 key constitution が repo 相対の file の列を名乗り、 その列が既定を置き換え、 lens はその列を 1 本ずつ測って頼みの文の 1 句を差し替えると決める。 key を書かない repo の prompt と雛形の hash は 1 byte も変わらない。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して main へ入れる 1 回の走り、 「審査役 (lens)」は便の差分を観点ごとに読んで判定する AI です。 観点の 1 つは「憲法に反していないか」で、 器は審査役を起こす前に、 木の docs/constitution.md が在るかを測っています。 けれども、 この場所は器が自分の repo の作り方 (憲法から生成した写し) を決め打ちしたもので、 憲法の正本を別の形の file で持つ repo は、 写しか正本を指す file をもう 1 つ置かないと審査を通れません。 この記録は、 repo が自分の設定 file に「憲法はこの file」と書けるようにし、 書いた repo では器がその file を測って、 審査役への依頼文の「憲法はどこか」の句をその file に差し替えると決めます。 書いた file は既定の docs/constitution.md の代わりになり、 書かない repo の依頼文は 1 字も変わりません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 4 つで示します。 器が今、 審査役を起こす前に docs/constitution.md の有無を測り、 依頼文もその場所を名指していること。 その場所は器の repo の作り方 (生成した写し) の決め打ちで、 憲法の正本を別の形で持つ repo が現れたこと。 repo が自分の形を設定 file で名乗る口と、 項目を「足す」と「置き換える」の 2 つの先例。 憲法の向きと、 この記録が動かす範囲です。

CTX1

現物 — lens審査役の AI は起こす前に木の docs/constitution.md を 3 値に測り、 頼みの文審査役への依頼文もその path を名指す (§47)

設計 gate-cost §47 で、 lens は diff の審査の周に限り、 claude を起こす前に --worktree の木の docs/constitution.md を 在る・無い・読めない の 3 値に測る (中身は読まない)。 無い周と読めない周は claude を起こさず、 rc 0 で置く物か直す物を名指す INCONCLUSIVE判定できず の 1 行を返す。 path は lens.rs の private な定数 1 つで、 雛形 lens.txt の観点の行は憲法を「起動 cwd の生成 file docs/constitution.md」と書く。 契約の審査と memo の段は測らない。 §47 は別の path を名乗る宣言の key を見送り、 消費側の置き場器を使う別の repoには docs/constitution.md (全文・正本を名指す数行・symlink のどれか) を置かせ、 別の path を要る消費側が現れたら ADR を立てて足すと却下に書いた。

CTX2

正本の形 — 器の repo の docs/constitution.md は生成の写しで、 正本を別の形の file で持つ消費側の置き場が現れた

器の repo の憲法の正本は design-intent/spec/constitution.html の機械層で、 docs/constitution.md は cargo xtask gen-claude-md の生成物である (ADR-0046)。 つまり docs/constitution.md という path は、 器が自分の repo の作り方を決め打ちしたものになる。 憲法の正本を md でない別の形の file で持ち、 md の写しを作らない消費側の置き場が現れ、 §47 の形のままでは、 正本と別に写しか正本を名指す file を 1 つ置かないと diff の審査の gate が通らない (memo s2-07l.738.42.9)。 §47 の却下が残した条件が満ちた。

CTX3

宣言の口と先例 — vessel 宣言repo の設定 fileの任意 key書かなくてよい項目 には「足す」と「置き換える」の両方の先例が在る

vessel 宣言 (.vessel.toml) は、 対象 repo が自分の形を器に名乗る tracked file で (ADR-0010)、 読み手は未知の key を宣言全体の不備として断る。 任意 key には、 既定に足す先例 (契約表の置き場の contract-tables・ADR-0109) と、 書けば既定を置き換える先例 (path の種別の key・ADR-0047) が在る。 名指した rev の宣言を読み、 既定だけの周・key の在る周・読めない周を閉じた 3 値3 つに限った答えで返す口には、 契約表の置き場の読み TablePlaces の先例が在る。 新しい key は、 古い binary が未知の key として断るので、 跨版版の違いをまたぐの形を持つ。

CTX4

憲法の向きと本 ADR の射程

C10 は宣言値と導出値を型で分け、 その読み (ADR-0047) では読めない宣言を既定に倒さない。 §47 は同じ C10 から、 測れていない観点の 0 を測った 0 に混ぜない線を引いた。 C2 は名前を 1 つの定数から導くことを求める。 FR9 は測れない周に PASS を名乗らず INCONCLUSIVE とし、 NFR1 は lens 1 本の材料に上限を置く。 雛形 lens.txt の hash は --print-version に載り、 雛形を変えると binary の入れ替えの後に全部の行の審査の記録が撃ち直しになる。 本 ADR が動かすのは、 宣言の key 1 つ・それを読む口 1 つ・lens が測る file の列・頼みの文の 1 句の差し替えの 4 つである。 ADR を書く条件のうち 1 (C10 の読み)・3 (宣言の key と跨版の形)・4 (却下案を残す価値のある分岐) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 憲法の在りかは repo が名乗ること。 書かない repo の依頼文と雛形の指紋を 1 byte も変えないこと。 憲法の写しを repo にも依頼文にも重ねないこと。 測れない回を「違反 0」にも既定にも倒さないこと。 古い本体と新しい設定が出会ったときの壊れ方を名指すことです。

DR1出所 — 憲法の在りかは対象 repo の事実で、 repo が自分の宣言で名乗る (器が自分の repo の作り方を決め打ちしない) CTX2・CTX3
DR2無変更 — key を書かない repo の prompt と雛形の hash雛形の指紋 は 1 byte も変わらず、 行の審査の記録を撃ち直させない CTX1・CTX4
DR3写しを重ねない — 正本の写しを置き場にも prompt にも重ねない (C2・NFR1) CTX2・CTX4
DR4fail-closed — 名乗った file の無い周・読めない周・宣言の読めない周を、 測れていない 0 にも既定にも倒さない (C10・FR9) CTX1・CTX4
DR5跨版 — 古い binary と新しい key が出会ったときの壊れ方を名指す CTX3
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 設定 file の書かなくてよい項目 constitution で file の列を名乗り、 既定を置き換え、 依頼文の 1 句を差し替える案 (選んだ案) と、 選ばなかった 4 つです。 選ばなかった案は、 項目を既定に足す案・repo の側が自分の正本から docs/constitution.md を生成する案・依頼文の雛形に差し込み口を足す案・器が憲法の本文を依頼文に差し込む案です。

OPT1vessel 宣言の任意 key constitution が file の列を名乗り、 既定を置き換え、 頼みの文の 1 句を差し替える採用

vessel 宣言に任意 key constitution (repo 相対の file の path の配列・字は英数字と . _ / - に閉じる) を足し、 名乗った列が既定の docs/constitution.md を置き換える。 名指した rev の宣言を閉じた 3 値で読む口を 1 つ置き、 lens は --worktree の HEAD の宣言を読んで列を 1 本ずつ §47 の 3 値で測り、 key の在る周だけ頼みの文の憲法の path の句を列に差し替える。 決め手は repo の形を repo が名乗る先例と、 写しを作らせない向き (CTX2・CTX3)。

repo の設定 file (vessel 宣言) に、 書かなくてよい項目 constitution を足します。 値は repo の中の file の場所の一覧で、 字を英数字と . _ / - に限り、 書いた一覧が既定の docs/constitution.md の代わりになります。 審査役は commit 済みの設定を読み、 一覧の file を 1 本ずつ在る・無い・読めないに測って、 全部が在る回だけ依頼文の「憲法はどこか」の句を一覧に差し替えて審査役を起こします。 どんな形の正本も写しを作らずに名指せ、 書かない repo の依頼文と雛形の指紋は 1 byte も変わらず、 測れない回は直す物を名指して「判定できず」になり、 本文を依頼文に入れないので審査役の読む量の上限も食いません。 代わりに、 古い本体は新しい項目を知らずに設定全体を断ること、 契約表の置き場の項目 (足す) と向きが逆になること、 名乗った file が憲法かは器が確かめないこと、 設定を壊すと直すまで審査が止まること、 dir や glob を書けず複数の file は並べて書くことを引き受けます。

+ 利点

  • 正本をどんな形の file で持つ置き場も、 宣言 1 行で正本の file を lens の観点に名指せ、 写しを作らずに済む (DR1・DR3)
  • key を書かない repo の prompt と雛形の hash は 1 byte も変わらず、 行の審査の記録が撃ち直しにならない (DR2)
  • 名乗った file の無い周・読めない周・宣言の読めない周は claude を起こさず、 直す物を evidence が名指す INCONCLUSIVE になる (DR4)
  • 字を閉じるので、 差し込んだ字が雛形の穴や backtick を作らない
  • 本文を prompt に入れないので、 材料の byte は今と同じで cap を食わない (DR3)

− 欠点

  • 宣言の key が 1 つ増え、 古い binary は key を未知として宣言全体を断る (DR5)
  • 任意 key の向きが contract-tables (足す) と逆になり、 key ごとに足すか置き換えるかが分かれる
  • 中身は読まないので、 名乗った file が憲法かは置いた席が負い、 木の外の file は名乗れない
  • key を持つ置き場で宣言を壊すと、 直すまで diff の審査の gate が全部 INCONCLUSIVE で止まる (DR4)
  • dir と glob は名乗れず、 正本が複数 file の置き場は file を列で並べて書く
OPT2key が既定に足す (contract-tables と同じ向き)不採用

key の列を既定の docs/constitution.md に足し、 既定と列の両方を測る。 決め手は既定の写しを持たない置き場の扱い (CTX2)。

項目に書いた一覧を既定の docs/constitution.md に足し、 両方を測る案で、 契約表の置き場の項目と同じ向きです。 項目ごとの向きが揃って覚えやすく、 設定 1 行で既定の測りを外せない点で勝ります。 けれども、 既定の写しを持たない repo は既定の測りで落ちて審査を通れず、 結局写しを作らせることになり、 書いた repo にも消すべき写しが残ります。

+ 利点

  • 任意 key の向きが契約表の置き場の key と揃い、 key ごとの意味を覚える手間が減る
  • 宣言 1 行で既定の docs/constitution.md の測りを外せない

− 欠点

  • 既定の写しを持たない置き場は既定の測りで落ちて審査を通れず、 写しを作らせることになる (DR1・DR3)
  • key を書いた置き場にも、 消すべき既定の写しが残る (DR3)
OPT3消費側が自分の正本から docs/constitution.md を生成する (器は変えない)不採用

宣言の key を足さず、 消費側の置き場が自分の正本から docs/constitution.md の写しを生成して置く (§47 の置き場の決まりのまま)。 決め手は写しの数と統合の向き (CTX1・CTX2)。

器は変えず、 repo の側が自分の正本から docs/constitution.md の写しを生成して置く案で、 前の設計 (§47) の決まりのままです。 器の変更が無く、 設定の項目も版の違いの壊れ方も増えず、 器の repo と同じ形 (正本から生成した写し) に揃う点で勝ります。 けれども、 写しが 1 つ増えて正本と写しの食い違いを見張る面が増え、 器の repo の作り方を相手に写させるので、 統合の向きと逆になります。

+ 利点

  • 器の変更が 0 で、 宣言の key も跨版の壊れ方も増えない (DR5)
  • 器の repo と同じ形 (正本から生成した写し) に揃う

− 欠点

  • 写しが 1 つ増え、 正本と写しの食い違いを見張る面が増える (DR3)
  • 統合の向きと逆で、 器の repo の作り方を消費側に写させる (DR1)
OPT4雛形 lens.txt に穴 {constitution} を足して埋める不採用

句の差し替えでなく、 雛形の観点の行に穴を足し、 既定の周も key の周も同じ埋めで組む。 決め手は雛形の hash (CTX4)。

句を差し替えるのでなく、 依頼文の雛形 lens.txt の観点の行に差し込み口 {constitution} を足して埋める案です。 差し替える句を雛形の外に持たずに済み、 憲法の置き場が雛形の中で差し込み口として見え、 既定の回も項目の回も同じ埋め方で組める点で勝ります。 けれども、 雛形が 1 字でも変わると雛形の指紋が変わり、 本体の入れ替えの後に全部の行の審査の記録が撃ち直しになります。 項目を書かない repo の雛形も変わります。

+ 利点

  • 差し替えの句を雛形の外の定数に持たず、 憲法の置き場が雛形の中で穴として見える
  • 既定の周も key の周も同じ 1 走査の埋めで組めて、 分岐が 1 つ減る

− 欠点

  • 雛形 lens.txt の hash が変わり、 binary の入れ替えの後に全部の行の審査の記録が撃ち直しになる (DR2)
  • key を書かない repo の雛形も 1 字変わる (DR2)
OPT5器が憲法の本文を読んで prompt に差し込む不採用

file の path を名指すのでなく、 器が名乗った file の本文を読んで頼みの文に差し込む (§47 の却下と同じ形)。 決め手は cap と写しの重なり (CTX4)。

file の場所を名指すのでなく、 器が憲法の本文を読んで依頼文に差し込む案です (前の設計 §47 でも退けた形)。 審査役が木を読みに行かなくても憲法の中身が確実に依頼文に在り、 審査役の読みの道具の届き方に依らない点で勝ります。 けれども、 本文の分だけ審査役 1 本の読む量の上限 (NFR1) を食い、 審査役は木を読めるのに本文の写しを依頼文に重ねます。 項目を書かない repo の依頼文も変わります。

+ 利点

  • lens が木を読みに行かずに、 憲法の中身が確実に prompt に在る
  • lens の読みの道具の届き方に依らない

− 欠点

  • 材料の byte が cap (NFR1) を食う (DR3)
  • lens は木を読めるのに、 本文の写しを prompt に重ねる (DR3)
  • 頼みの文の中身が変わり、 key を書かない repo でも prompt が変わる (DR2)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 設定 file の項目 constitution は repo の中の file の場所の一覧で、 字を英数字と . _ / - に限り、 dir・親へ上る段・絶対の場所・home の略記は断ります。 書いた一覧は既定の docs/constitution.md の代わりになります。 器は設定を 3 つに限った答え (書いていない・書いてある・読めない) で読み、 審査役は commit 済みの設定を読んで、 file を 1 本ずつ在る・無い・読めないに測ります。 無い・読めない・設定が読めない回は、 審査役を起こさずに「判定できず」を返して直す物を名指します。 書いた repo だけ依頼文の 1 句を差し替え、 書かない repo の依頼文は変えません。 支える要件は 2 つで、 どちらも向きを保つ側です。

採用 — OPT1
