設計判断記録 (ADR) scribe2 — 消費側の plugin の枠と runner の印

席の起動行の 1 つ目の plugin の枠は anchor の plugin で、 runner に写す消費側の plugin には器が印の file を置く — 消費側の席と便の plugin の置き場と、 席と runner を見分ける印を跨版の面にする (ADR-0038 の 1 つ目の枠の読みを消費側の anchor へ広げる)

ADR-0038 は席の起動行の 1 つ目の plugin の枠を anchor の下の生成 dir と決めたが、 器自身の repo を前提にしていた。 消費側の project が自分の plugin をそこに置き、 同じ plugin の名札と hook が runner にも写って積まれることが分かった。 本 ADR はこの枠と runner の写しを版を跨いで保つ約束にし、 runner に写した消費側の plugin の置き場にだけ器が空の印の file を 1 つ置く。 環境変数は足さない。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session、 「runner」は契約 1 本を実装する使い捨ての AI、 「消費側」は器を使う別の project です。 席を立てる 1 行は、 最初に積む plugin の置き場を anchor (席の repo の置き場) の下の plugin/ にしています。 消費側の project が自分の plugin をそこに置くと、 その plugin の名札と hook が runner にも写って積まれます (写るのはその 2 つだけで、 中身は便の作業場所のその時の版なので、 席の今の版とずれることがあります)。 本 ADR は、 この置き場・runner への写し方・写しに置く印の file の 3 つを、 版を跨いで保つ約束にします。 印は runner に写した消費側の plugin の置き場にだけ器が置く空の file で、 消費側の hook はこれが在るかで runner の中かを判じます。 環境変数は足しません (要件 FR59 と FR4 を支え、 ADR-0038 の読みを消費側へ広げます)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (最初に積む plugin の置き場は決まっていたが、 消費側での意味は書かれていない)・事象 (消費側の plugin が席と runner の両方に積まれ、 両者を見分ける値を器が渡していない)・機序 (器は runner の plugin を便の置き場へ写し、 AI は hook に読み込んだ plugin の置き場を渡す。 runner の側は 2 つの実測から導く)・憲法と既存の決定の向き (環境変数を足さない線)・射程の 5 つで示します。

CTX1

経緯 — 1 つ目の枠最初に積む pluginは ADR-0038 で anchor席の repo の置き場 の下の生成 dir と決まったが、 消費側器を使う別の projectの anchor での意味は書かれていない

席の起動行席を立てる命令の 1 行は pure な 1 関数が組み、 1 つ目の plugin の枠に anchor の下の生成 dir (名は core の定数 1 つ・今は plugin) を置き、 2 つ目以降に host の面の plugin の dir を宣言順に並べる。 ADR-0038 はこの枠を器自身の plugin の置き場として決め、 設計の § も「器自身の生成 dir」とだけ書く。 消費側の anchor では、 この枠はその project の plugin/ を指す (在れば積まれ、 無くても行には載る)。 これは器の実装の細部で、 跨版の約束ではない。

CTX2

事象 — 消費側の plugin が席と runner実装する使い捨て AI の両方に積まれ、 両者を見分ける値を器が渡していない

消費側の project 1 つが anchor の下の plugin/ に hook道具や turn で走る命令 を持つ plugin を置いた。 席は 1 つ目の枠でその plugin を積み、 runner は便ごとの写しで同じ plugin の名札と hook を積む (runner に写すのは .claude-plugin と hooks の 2 dir だけで、 plugin.json と hooks.json の両方が在り名が器と違う周に限る。 lens審査する使い捨て AI は plugin を 1 つも積まない)。 runner に写るのは spawn の各周の時点の便の worktree の中身 (初回は便の出発点の commit、 再開の周は runner の変更や追随を含みうる) で、 席が積むのは anchor の作業木の今の中身である。 消費側の hook が席でだけ働くには runner の中かを知る必要があるが、 器は正の値を渡していない。 消費側は作業木の形などから推すしかなく、 粗く推すと worktree で作業する席を runner と誤読しうる (推定)。

CTX3

機序 — 器は runner の plugin を便の置き場へ写し、 claude は hook に読み込んだ plugin の置き場を渡す

便ごとの plugin の root は器が state dir の便の dir に spawn の周ごとに書き直し、 器の plugin を必ず置き、 名の違う消費側の plugin を consumer という dir へ写す (repo の外へ写すのは、 読み込んだ plugin の dir の下が自動承認から外れるため)。 root は runner の行の plugin_dir の穴で runner に渡る。 claude は hook に、 読み込んだ plugin の dir を CLAUDE_PLUGIN_ROOT という値で渡し、 器自身の hooks.json もこの値を使う。 席ではこの値が anchor の下の plugin/ になり、 runner に積まれた消費側の hook ではこの値が写しの dir になる、 と 2 つの実測 (2026-09-28) から導く。 (a) 対話の席では、 器の hook が CLAUDE_PLUGIN_ROOT を席の読み込み元の記録に書く。 --plugin-dir に anchor の下の plugin/ を渡して立てた席の記録は、 その path そのままだった (cache の写しではない)。 (b) headless の runner では、 走行中の便の claude が逐次の出力の初めの record に並べる plugin の path が、 --plugin-dir に渡した便の写しの dir (器の plugin の写し) と同じだった。 残る隙間は、 runner の中の hook が受け取る CLAUDE_PLUGIN_ROOT を直に記録した実測が無いことである (runner は pane を持たず、 読み込み元の記録は pane の無い周に書かない)。 lens は plugin を 1 つも積まない (器の lens の口の flag に plugin の dir が無く、 gate が lens の行に置く穴は契約と worktree の 2 つだけ)。 runner の claude の環境変数は、 構築点が口座と agent view の 2 つを置き tmux の pane の変数を外すだけで、 runner を名乗る値は無い。 器自身の hook は pane の変数の無い session を席でないと読む。

CTX4

憲法と既存の決定の向き

C2.2 は、 器は環境変数を直接読まず、 環境変数の継ぎ目 (seam) を新設せず、 環境変数の接頭辞を NAME から導く、 と定める。 ADR-0004 §2.4 (D-4) はこの条を適用し、 器が外へ渡す置き場と方針を、 引数・worktree の git の私有 dir の file・runner の行の穴の 3 つに限った (閉じた列挙で、 file 一般を認めてはいない)。 その出所は、 前の器で器の接頭辞の環境変数が 533 種に増えて改名できなくなった実測である。 設計 gate-cost.md §3.3 も同じ条の精神で、 実効 jobs を環境変数で渡さない (折り返しの裏口を作らない)。 役割は窓名や環境変数の慣習では決めない (ADR-0022)。 N2 から跨版の約束は散文だけで持たず歯で pin し、 N3 から印の値は host に依らない。 C17 から既存の写しの手順を使う。 C17.2 は、 走査・記録・rules 行・仕組みのどれかを足すなら先に消すものを名指す、 と定める。 本 ADR が足すのは器の中に読み手を持たない file 1 つで、 走査・記録・rules 行は足さず、 器の中に仕組み (読む・判じる・止める) も足さないと読む (解釈)。 消費側が読む跨版の合図は 1 つ増える。 消すものとしては、 消費側に推させている今の暗黙の面 (作業場所の形) を、 約束の印に置き換える。

CTX5

射程 — 動かすのは宣言 3 点と写しの手順の file 1 つだけ

動かすのは、 (1) 1 つ目の枠を anchor の下の生成 dir とする約束を消費側の anchor まで広げること、 (2) runner の写しの形 (名の違う plugin だけを便の root の consumer という dir へ写す・lens は積まない) を約束にすること、 (3) その写しの root に空の印の filerunner の写しの目印 を 1 つ書くこと、 だけである。 動かさないのは、 2 つ目以降の枠の順・写しの判定と写し先と写す 2 dir・runner の root の配下の並べ方・lens の起動・席の起動行の外形と環境変数・headless の構築点・便を起こす層の環境変数・状態の打刻・rules 行・要件書である。 写しの中の並びを 2 dir に pin した既存の歯 2 本は、 印の分だけ期待が動く。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 消費側の plugin の置き場が版を跨いで動かないこと。 消費側の hook が、 器の置く正の印 1 つで (無いことや形から推さずに) runner の中かを判じられること。 器は環境変数を読まず、 環境変数の継ぎ目を新しく作らず、 名を器の名から導き、 役割の語と混ぜないこと。 足すものを最小にすること。 既存の約束と器の内部の配置を壊さないこと。

DR2消費側の hook が、 器の置く正の印 1 つで runner の中かを判じられる (無いことや形から推さない) CTX2・CTX3
DR3C2.2 と ADR-0004 §2.4 の線の内側に留まる — 環境変数を読まず、 環境変数の継ぎ目を新設せず、 名は NAME から導き、 役割の語と混ぜない CTX4
DR4足すものを最小にする — 既存の写しの手順と置き場を使い、 読み手を足さない (C17) CTX3・CTX4
DR5既存の約束を壊さない — 席の起動行の外形・便を起こす層の環境変数・lens の plugin 無し・写しの判定・器の内部の配置 CTX3・CTX5
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 8 つ並べます。 置き場と写し方を約束にし写しに印の file を置く案 (選んだ案)、 何も足さず消費側に推させる今のままの案、 tmux の pane の変数が無いことを約束にする案、 plugin の置き場の path で見分ける案、 runner に消費側の plugin を積まない案、 席の側で環境変数を名乗る案、 runner の AI に環境変数を名乗らせる案、 印を作業場所の git の私有の dir に置く案です。

OPT13 点を跨版の面版を跨いで保つ約束にし、 runner に写す消費側の plugin の root に器が空の印の file を置く採用

1 つ目の枠が anchor の下の生成 dir であること (消費側の anchor ではその project の plugin)、 runner の写しの形、 写しの root の印の file を、 版を跨いで保つ約束にする。 印の名は NAME に -runner を付けた語、 中身は空で、 host の値も便の値も載せない。 消費側の hook は CLAUDE_PLUGIN_ROOT の下に印が在るかで判じ、 器は印を読まない。 D-4 との関係は、 印を置く plugin の root は D-4 の 3 つのうち runner の行の穴で runner に渡っており、 印はその root の下の file 1 つである (D-4 が列挙した私有 dir の file そのものではない)。 決め手は、 器が環境変数を足しも読みもせずに正の印を plugin の読み込みに付けられること (消費側の hook は claude が渡す CLAUDE_PLUGIN_ROOT で印を探す) (OPT7・OPT8 の欠点の分析)。

3 つを版を跨いで保つ約束にする案です。 席を立てる 1 行で最初に積む plugin は anchor の下の plugin/ (消費側ではその project の plugin) であること、 runner には名の違う消費側の plugin の名札と hook だけを便の置き場へ写して積むこと、 そしてその写しの置き場に器が空の印の file を 1 つ置くことです。 印の名は器の名に -runner を付けた語で、 中身は空、 器はこれを書くだけで読みません。 消費側の hook は、 AI から受け取る自分の plugin の置き場に印が在るかで判じます。 器は席の置き場に印を書かず、 環境変数のように runner の中の器自身の process へ引き継がれず、 shell の値では偽装されず、 環境変数を足さないので憲法 C2.2 の解釈も要りません。 代わりに、 印の名と置き場が版を跨ぐ約束になり (器の名を変えると印の名も変わる)、 runner 以外は印が無いことで判じ (器の外で起こした AI も runner でないと読む)、 印を見られるのは写しを積んだ hook だけで、 写しの形を固めた既存の歯 2 本の期待が動きます。 anchor の plugin/ に同じ名の file を置けば席も runner と読まれ (環境変数の偽装と同じ型で、 手間が file 1 つに変わるだけ)、 runner の中の hook が受け取る置き場を直に測ってはいない (席の記録と runner の起動の record の 2 つの実測から導いている) であることも引き受けます。

+ 利点

  • 1 つ目の枠と写しの形と印が歯で pin され、 消費側の plugin の置き場が黙って動かない (DR1)
  • 正の印で判じられ、 器は席の枠 (anchor の下の plugin/) に印を書かない。 印は plugin の読み込みごとに決まり、 cwd に依らない (DR2)
  • 環境変数を足さないので C2.2 の解釈を要さない。 印は D-4 の runner の行の穴で渡る plugin の root の下の file で、 環境変数のように runner の中の器自身の process へ引き継がれず、 shell の値では偽装されない (偽装するには anchor の plugin/ に同じ名の file を置く必要があり、 git の状態に見える) (DR3)
  • 既存の写しの手順が file を 1 つ書くだけで、 読み手も呼び出しの欄も足さない (DR4)
  • 席の起動行の外形も、 headless の構築点も、 便を起こす層の環境変数も動かない (DR5)

− 欠点

  • 印の名 (NAME から導く) と置き場 (写しの root) が跨版の面になり、 NAME を改名すると印の名も変わる (ADR-0004 が防いだ改名の費用が 1 つ分残る)
  • runner 以外は印が無いことで判じる。 器の外で起こした headless や人が起こした claude は写しを積まないので、 runner でないと読む
  • 印を見られるのは写しを積んだ claude の hook だけで、 hook でない process (道具が撃つ子) は印を知らない
  • 写しの中の並びが 2 dir から「2 dir と印」になり、 写しの形を pin した既存の歯 2 本の期待が動く
  • anchor の plugin/ に同じ名の file を人か席の AI が置くと、 席も runner と読まれ、 器はそれを止めない (OPT7 の shell での偽装と同じ型で、 手間が repo の中の file 1 つに変わるだけ)
  • runner の中の hook が受け取る CLAUDE_PLUGIN_ROOT が写しの dir を指すことは、 2 つの実測 (席の読み込み元の記録・runner の初めの record の plugin の path) から導いたもので、 runner の中の hook の値そのものは直に記録していない。 外れると消費側の hook は runner の中でも印を見つけられない (小さく残るリスク)
OPT2何も足さない (今のまま) — 消費側の hook が作業木の形などから推す不採用

1 つ目の枠も写しも実装の細部のままにし、 印も環境変数も足さない。 消費側の hook は runner の作業場所の形などから推す。 決め手は分析 (推し方は、 誤読するか、 器の内部の配置を凍らせるかのどちらか)。

何も足さず、 今のままにする案です。 器の変更が無く、 約束も増えず、 環境変数も足さない点で勝ります。 けれども、 最初に積む plugin の置き場は実装の細部のままで将来の版が黙って動かしうるうえ、 推し方の精度が器の内部の配置に依ります。 作業場所の形で粗く推すと worktree で作業する席を runner と誤読しうる (推定) 一方、 runner の作業場所の形まで精確に推すと器の内部の配置を消費側の約束に凍らせるので退けました。

+ 利点

  • 器の変更が 0 で、 跨版の約束が増えない
  • 環境変数を足さず、 C2.2 の解釈を要さない

− 欠点

  • 1 つ目の枠の意味が実装の細部のままで、 将来の版が黙って動かしうる (DR1)
  • 推し方の精度は器の内部の配置に依る。 作業木の形で粗く推すと worktree で作業する席を runner と誤読し (推定)、 runner の作業場所の形まで精確に推すと器の内部の配置を消費側の約束に凍らせる (DR2・DR5)
OPT3pane の変数の不在を跨版の面にする — runner は tmux の pane の変数を持たない不採用

runner の子から tmux の pane の変数を外す今の形を約束にし、 消費側の hook は pane の変数が無い周を runner と読む。 器自身の hook と同じ読みを消費側にも渡す形。 決め手は分析 (無いことからの推論で runner 以外も含む)。

runner の AI からは tmux の pane の変数が外されている今の形を約束にし、 消費側はその変数が無い周を runner と読む案です。 器の code を変えず、 器自身の hook と同じ読み方で済み、 環境変数も足さない点で勝ります。 けれども、 変数が無いことから推すので、 tmux の外で動く session (人が素の端末で起こした AI など) も runner と読んでしまいます。 また、 変数を外すのは runner の hook が席の記録へ書かないための別の目的の形で、 その細部を消費側の約束に凍らせるので退けました。

+ 利点

  • 器の code の変更が 0 で、 外す形は既存の歯が既に pin している
  • 器自身の hook と同じ読みで、 環境変数を足さず C2.2 の解釈も要さない

− 欠点

  • 無いことからの推論で、 tmux の外で動く session (人が素の端末で起こした claude など) も runner と読む (DR2)
  • pane の変数を外すのは runner の hook が席の記録へ書かないための形で、 別の目的の細部を消費側の約束に凍らせる (DR5)
OPT4消費側の hook が plugin の root の path で見分ける不採用

器は何も足さず、 runner の写し先の path の形 (便の置き場の下) を約束にする。 消費側の hook は plugin の root が anchor の下の plugin/ でない周を runner と読む。 決め手は分析 (器の置き場の内部を凍らせ、 否定の推論になる)。

器は何も足さず、 消費側の hook が自分の plugin の置き場の path を見て、 anchor の下でなければ runner と読む案です。 環境変数も file も足さず、 値は AI が既に hook に渡している点で勝ります。 けれども、 器の作業場所の中の配置を版を跨ぐ約束に凍らせるうえ、 「anchor の下でなければ runner」という推し方なので、 別の経路で入れた消費側の plugin も runner と読むので退けました。

+ 利点

  • 環境変数も file も足さず、 値は claude が既に hook に渡している。 C2.2 の解釈も要さない

− 欠点

  • 器の置き場 (state dir の便の dir) の内部の配置を跨版の約束に凍らせる (DR5)
  • 「anchor の下でなければ runner」という否定の推論で、 別の経路で入れた消費側の plugin も runner と読む (DR2)
OPT5runner に消費側の plugin を積まない (写しを止める)不採用

便の root へ消費側の plugin を写すのをやめ、 消費側の hook を席だけで撃たせる。 決め手は分析 (runner の中で撃ちたい消費側の hook を失う)。

runner に消費側の plugin を積むのをやめ、 消費側の hook を席だけで撃たせる案です。 見分ける必要そのものが消え、 約束も 1 つ減る点で勝ります。 けれども、 消費側が runner の中で撃ちたい hook を失い、 名の違う plugin を写す既存の約束を壊し、 runner でも撃つ hook と席だけの hook を分けられなくなるので退けました。

+ 利点

  • 見分ける必要そのものが消え、 跨版の面も 1 つ減る。 C2.2 の解釈も要さない

− 欠点

  • 消費側が runner の中で撃つ hook を失い、 名の違う plugin を写す既存の約束を壊す (DR5)
  • runner でも撃ちたい hook と席だけで撃つ hook を消費側が分けられない (DR2)
OPT6席の起動行に席の名乗りの環境変数を置く不採用

runner でなく席の側で名乗り、 消費側の hook は席の名乗りが在る周だけ働く。 決め手は分析 (起動行の外形が動き、 環境変数を足し、 起動行を通らない session を区別できない)。

runner でなく席の側に名乗りの環境変数を置き、 消費側の hook は席の名乗りが在る周だけ働く案です。 消費側が席を正の値で知れ、 runner の側を触らない点で勝ります。 けれども、 席を立てる 1 行の形が変わって外形の歯が動き、 器の 1 行を通らずに起こした session は名乗りを持たず runner と区別できず、 環境変数を足すので憲法の条と ADR-0004 の線に触れ、 席の種類を環境変数で表す形にも近づくので退けました。

+ 利点

  • 消費側の hook が席を正の値で知り、 runner の側を触らない

− 欠点

  • 席の起動行の外形 (起動行の構成は決定記録が正本) が動き、 外形の歯が動く (DR5)
  • 器の起動行を通らない session (人が手で起こした claude など) は名乗りを持たず、 名乗りの無いことからは runner と区別できない (DR2)
  • 環境変数を足すので C2.2 と ADR-0004 §2.4 の線に触れ、 席の種類を環境変数で表す形 (ADR-0022 が退けた慣習) に近づく (DR3)
OPT7runner の claude に名乗りの環境変数を置く (名は NAME の大文字に _HEADLESS、 または _ROLE)不採用

headless の唯一の構築点が、 plugin を積む呼び出し (今は runner だけ) の子に環境変数を 1 つ置く。 草稿 v1 の採用案で、 名を役割の語にする形も含む。 決め手は審査と分析 (条の解釈を要し、 ADR-0004 と gate-cost.md の前例に逆らう)。

runner の AI を起こす唯一の場所で、 plugin を積む呼び出しの子に名乗りの環境変数を 1 つ置く案です (名は器の名の大文字に _HEADLESS、 または役割の語の _ROLE)。 この記録の最初の草稿が選んでいた案です。 runner の中の全ての process が値を読め、 数行で済む点で勝ります。 けれども、 憲法 C2.2 は環境変数の継ぎ目を新しく作ることを禁じ、 ADR-0004 はその適用として器の外への受け渡しから環境変数を外しました (前の器で器の環境変数が 533 種に増え、 名を変えられなくなったのが出所です)。 この案は「子へ書くだけなら継ぎ目でない」という条の解釈を要し、 実効 jobs を環境変数で渡さないとした gate-cost.md §3.3 の前例にも逆らい、 名乗りは器自身の process にも引き継がれます。 席の shell に人が同じ名を置くと席が runner と読まれ、 役割の語を使うと席の種類の語と混ざるので退けました。

+ 利点

  • runner の中の全 process (hook でない子も) が値を読める
  • 構築点の数行で済み、 呼び出しの欄を足さない

− 欠点

  • 環境変数の継ぎ目を新設しない (C2.2) の線に触れ、 「子へ書くだけの環境変数は継ぎ目でない」という条の解釈を要する。 ADR-0004 §2.4 はこの条を適用して器の外への受け渡しから環境変数を外しており、 出所は前の器で器の接頭辞の環境変数が 533 種に増えて改名できなくなった実測である (DR3)
  • gate-cost.md §3.3 は同じ条の精神で実効 jobs を環境変数で渡さない (折り返しの裏口を作らない)。 名乗りは runner の中の器自身の process にも継承され、 同じ懸念が当たる (DR3)
  • 席の shell に人が同じ名を置くと席が runner と読まれ、 runner 以外は名乗りの無いことで判じる (DR2)
  • 名を役割の語 (_ROLE) にすると、 runner は席でないのに席の種類の語と混ざり、 器の歯がその名を読まない値の見本に使っている (DR3)
OPT8印の file を便の worktree の git の私有 dir に置く (ADR-0004 の列挙した経路)不採用

印を写しの root でなく、 ADR-0004 §2.4 が器の受け渡しに挙げた worktree の git の私有 dir に置き、 消費側の hook は git で私有 dir を引いて在否を見る。 決め手は分析 (印が plugin の読み込みでなく worktree に付く)。

印の file を、 写しの置き場でなく、 ADR-0004 が器の受け渡しに挙げた作業場所の git の私有の dir に置く案です。 ADR-0004 が列挙した経路そのもので、 環境変数も足さず、 正の印で判じられる点で勝ります。 けれども、 印が plugin の読み込みでなく作業場所に付くので、 便の作業場所へ移って作業する席も runner と読んでしまいます。 消費側の hook は git を撃って私有の dir を引く必要があり、 器の私有の dir の配置を消費側の約束に凍らせるので退けました。

+ 利点

  • ADR-0004 §2.4 が列挙した経路そのもので、 環境変数を足さず C2.2 の解釈も要さない
  • 正の印で判じられる

− 欠点

  • 印が plugin の読み込みでなく worktree に付くので、 便の worktree へ移って作業する席 (人が cd した session) も runner と読む (DR2)
  • 消費側の hook は git を撃って私有 dir を引く必要がある (hook の読みが重い) (DR4)
  • 器の私有 dir の配置 (runner の触ってよい file の一覧の隣) を消費側の約束に凍らせる (DR5)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 席を立てる 1 行で最初に積む plugin は anchor の下の plugin/ で、 消費側ではその project の plugin です。 runner への写し方と、 写しの置き場にだけ器が置く空の印の file (名は器の名に -runner を付けた語) を、 版を跨いで保ちます。 環境変数は足しません。

採用 — OPT1

席の起動行の 1 つ目の --plugin-dir SHALL anchor の下の生成 dir (名は core の定数 1 つ) とし、 器の repo の anchor では器の plugin、 消費側の anchor ではその project の plugin を指す。 器 SHALL この枠の中身を読まず、 plugin.json の名で差し替えも除外もしない。 2 つ目以降の枠 (host の面の plugin の dir・宣言順) と起動引数の順 SHALL 変えない。 便の plugin の root SHALL 器の plugin を必ず持ち、 worktree の生成 dir が plugin.json と hooks.json の両方を持ち名が器と違う周だけ、 その 2 つの dir を root の下の consumer という dir へ写す (写すのは spawn の各周の時点の便の worktree の中身で、 初回は便の出発点の commit、 再開の周は runner の変更や追随を含みうる。 anchor の今の中身ではない)。 器 SHALL その写しの root に印の file を 1 つ書く。 印の名は NAME に -runner を付けた語、 中身は空で、 host の値も便の値も載せない。 器 SHALL 器の plugin の写し・anchor の下の生成 dir・便の worktree の生成 dir に印を書かない。 lens は今の形のまま plugin を積まない (器の lens の口は plugin の dir を受けず、 gate は lens の行へ plugin の root を渡さない。 これは跨版の 3 点の外で、 今の形を書き留めるだけ)。 器 SHALL 印を読まず、 役割の判定にも使わない。 器 SHALL この見分けのために環境変数を足さない。 以上の 3 点 (1 つ目の枠・runner の写し・印の名と置き場と空の中身) SHALL 跨版の面とし、 変えるときは新しい ADR を要する。 席の起動行の外形と環境変数・headless の構築点・便を起こす層の環境変数・状態の打刻・要件書は変えない。

席を立てる 1 行で最初に積む plugin は anchor の下の plugin/ で、 器の repo では器の plugin、 消費側ではその project の plugin です。 器はこの中身を読まず、 名で差し替えも除外もしません。 2 つ目以降の並びは変えません。 runner の plugin の置き場には器の plugin を必ず置き、 消費側の plugin は名札の file (plugin.json) と hook の一覧の file (hooks.json) の両方を持ち名が器と違うときだけ、 その 2 つの dir を写します。 写すのは起こす周ごとの便の作業場所の中身で (初回は作業を始めた時点の commit、 再開の周は runner の変更を含みうる)、 anchor の今の中身ではありません。 器はその写しの置き場にだけ空の印の file を 1 つ書き、 名は器の名に -runner を付けた語です。 器の plugin の写し・anchor の plugin/・作業場所の plugin/ には書きません。 審査の AI は今の形のまま plugin を積みません (これは約束の外)。 器は印を読まず、 役割の判定にも使わず、 環境変数も足しません。 席を立てる 1 行と AI を起こす場所と状態の記録は変えません。 置き場・写し方・印の 3 点を版を跨いで保ち、 変えるときは新しい ADR を書きます。 消費側の project が自分の plugin を最初に積む置き場に置き、 その名札と hook が runner にも写って積まれることが分かりました。 置き場が実装の細部のままだと将来の版が黙って動かしうるので、 歯で保つ約束にしました。 消費側の hook が席でだけ働くには runner の中かを知る値が要ります。 推し方 (作業場所の形・pane の変数が無いこと・置き場の path) は、 別の session を runner と読むか、 器の内部の配置を凍らせるので、 器が正の印を 1 つ渡します。 消費側が知りたいのは runner の中かなので、 正の印は runner の側に置きます。 席の側に置くと runner の方が無いことからの推論になり、 環境変数で名乗るなら席を立てる 1 行の形も動きます。 どちらの側に置いても器の外で起こした session は印の無い側に数えられ、 runner の側に置くとそれは席として読まれます。 渡し方を環境変数でなく写しの中の file にしたのは、 憲法 C2.2 が環境変数の継ぎ目を新しく作ることを禁じ、 ADR-0004 §2.4 がその適用として器の外への受け渡しを 3 つの経路に限っているからです。 印を置く置き場はその 1 つの runner の行の穴で渡っており、 印はその中の file なので、 器は環境変数を足さずに済み (消費側は claude が渡す置き場の値で印を探します)、 器自身の process へ引き継がれることも shell の値での偽装もありません。 置き場を作業場所の git の私有の dir でなく写しの中にしたのは、 印を plugin の読み込みに付けて、 作業場所へ移った席を runner と読まないためです。 引き受ける代償のうち、 印の名が器の名に連なることと既存の歯の期待が動くことは、 消費側の書き換えか歯の直しで済みます。 印の無いことで runner 以外を判じること・印を見られるのが hook だけであること・anchor に同じ名の file を置けば席も runner と読まれること・runner の中の hook が受け取る置き場を直に測っていないことは、 限界として残します。 環境変数を足さないので、 C2.2 の解釈も改訂の裁定も要りません。

FR59claimFR59 (席の起動・起動行の構成は決定記録が正本) の起動行のうち 1 つ目の plugin の枠の意味を、 消費側の anchor ではその project の plugin と決め、 跨版の約束にすると主張する。
FR4implementationFR4 (runner の起動・spawn が worktree を切り runner を起こす) の spawn の実装 (runner の plugin の写し) を広げ、 写しに印の file を 1 つ書き足す。 FR4 が求めたものではなく、 起動の形 (FR5 の headless の 1 形) は変えない。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 3 つと、 代わりに引き受けること 7 つです。 良くなるのは、 消費側の plugin の置き場が黙って動かず、 消費側の hook が印 1 つで runner の写しかを判じられ、 器の変更が小さく環境変数も足さないことです。 引き受けるのは、 置き場の dir の名が約束になること、 印の名が器の名に連なること、 席と runner で plugin の版がずれうること、 印を見られるのは写しを積んだ hook だけで器の外で起こした AI は runner でないと読まれること、 写しの形を固めた既存の歯 2 本の期待が動くこと、 runner に届くのは名札と hook の 2 つだけであること、 anchor に同じ名の file を置くと席も runner と読まれることです。

✓ 良い結果

  • ●消費側は anchor の下の plugin/ に置いた plugin が席に積まれ続けると頼れ、 置き場や印が動くときは新しい ADR で知らされる
  • ●消費側の hook は自分の plugin の置き場に印が在るかで runner の写しかを判じられ、 印は環境変数の継承や shell の値では偽装されない
  • ●器の変更は写しの手順の数行と歯で、 環境変数も呼び出しの欄も席の起動行の外形も動かず、 C2.2 の解釈を要さない

⚖ トレードオフ・代償

  • ●生成 dir の名が消費側の置き場の約束になり、 変えると消費側の plugin が席から外れる (変えるには新しい ADR)
  • ●印の名は NAME から導くので、 NAME を改名すると印の名も変わり、 消費側の hook の書き換えが要る
  • ●席と runner で plugin の版がずれうる。 runner には spawn の各周の時点の便の worktree の中身が写り、 席は anchor の作業木の今の中身を積む。 anchor にあって便の worktree に無い変更 (未 commit の変更や、 便を切った後に入った commit) は席にだけ効き、 便の worktree で runner が変えた plugin は再開の周の runner にだけ効く
  • ●印を見られるのは写しを積んだ claude の hook だけで、 器の外で起こした headless や手で起こした claude は runner でないと読まれる
  • ●写しの中の並びを 2 dir に pin した既存の歯 2 本の期待が、 印の分だけ動く
  • ●runner に写るのは消費側の plugin の 2 dir (.claude-plugin と hooks) と印だけで、 skills や hook が呼ぶ他の dir の file は runner に届かない。 この部分集合も跨版の約束になる
  • ●anchor の plugin/ に同じ名の file を人か席の AI が置くと席も runner と読まれ、 器はそれを止めない
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この記録が版の系譜のどこに在るかと、 判断が最後に行き着く原則です。 この記録は他の ADR を置き換えず、 ADR-0038 の決めた置き場の読みを消費側の project まで広げ、 環境変数を外した ADR-0004 の線に従います。

改訂状態current

置き換える ADRなし (新規)

置き換えられたなし (現行)

置き換える ADR は無い。 ADR-0038 の「席の起動行の --plugin-dir は anchor の下の生成 dir」の読みを、 器の plugin の置き場から、 その anchor の project の plugin の置き場へ広げる (ADR-0038 の決定は 1 字も変えない)。 runner の写しは既存の形をそのまま跨版の約束として宣言し、 写しの root の印の file は新しく足す。 ADR-0004 §2.4 (環境変数を足さない) には従い、 変えない。
