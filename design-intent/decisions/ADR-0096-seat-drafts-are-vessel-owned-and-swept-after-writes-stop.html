設計判断記録 (ADR) scribe2 — 席の起草の置き場の掃除

席の起草の置き場は器が持ち、 書きが rules 行の時間無い中間生成物を運転手の終端の周の同じ掃除で消す — 置き場は state dir の席の置き場の子で、 席の指示文の 12 行目が新しい穴でその path を渡す。 消すのは置き場の git の木の閉じた 8 つの名の dir だけで、 木の写しと退役の即時の削除は射程の外 (ADR-0081 の射程と承認の読み・ADR-0045 §2 (3) の行の構成・ADR-0022 §2.4 の穴を部分 supersede)

器の掃除は、 便が終わった作業場所 (worktree) から作り直せる build と依存の置き場を消すが、 席 (人と AI が話す session) が試作のために作る repo の写しは見ない。 写しは別の道具の一時 dir に置かれ、 組み立ての産物が溜まって host の disk を満たした。 本 ADR は、 席ごとの起草の置き場を器の state dir の下に持ち、 席の指示文でその場所を渡し、 同じ掃除が同じ周・同じ lock で、 置き場の写しから書きが一定の時間無い build と依存の置き場だけを消すと決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して取り込む 1 回の流れ、 「席」は人と AI が話す session、 「運転手」は便を段から段へ運ぶ器の process です。 器は、 便が終わった作業場所から、 作り直せる組み立ての産物 (Rust の target など、 名の決まった 8 種の dir) を消す掃除を持っています。 ところが席が試作のために作る repo の写しは、 別の道具の一時 dir に置かれ、 掃除の対象に入っていません。 写しの組み立ての産物が溜まり、 disk を満たしました。 この記録は、 席ごとの「起草の置き場」を器の state dir の下に持ち、 席への最初の案内 (席の指示文) でその場所を渡し、 同じ掃除が同じ周・同じ鍵 (lock) で、 置き場の写しから、 書きが一定の時間無い産物だけを消すと決めます。 時間は設定の値 (6 時間) で持ちます。 写しそのもの、 追跡されている file、 退役の時の即時の削除は、 持ち主の承認の外なので行いません。 代わりに、 読むだけの使用は書きに数えないことと、 席が置き場の外に写しを置けば掃かれないことを引き受けます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 6 つから説明します。 掃除が便の作業場所だけを見る経緯・席の写しの産物が溜まって disk を満たした事象・一時 dir と席の置き場と書きの時刻の性質・憲法の向き (消す承認の範囲と、 作り直せる物の読み)・席の指示文の行と穴の決まり・この判断で動かす範囲です。

CTX1

経緯 — 器の掃除は便の作業場所だけを見て、 席の作業場所は見ない

ADR-0081 は、 運転手 (便を段から段へ運ぶ器の process) の終端の周ごとに、 live でないと測れた便の worktree から、 名が閉じた 8 つの列 (target、 node_modules、 .venv、 __pycache__、 .mypy_cache、 .pytest_cache、 .ruff_cache、 .expo) に在り追跡されている file を持たない dir を消すと決めた。 母集団は置き場の記録を持つ便の木だけで、 置き場ごとの lock の中で撃ち、 残すのは stderr の 1 行だけである。 席 (人と AI が話す session) が試作のために作る repo の写しは、 便の記録を持たないので母集団に入らない。 ADR-0081 は、 裁定 user 2026-09-28T04:46Z を「閉じた列の dir を live でない便の worktree から終端の周ごとに消すこと」への A1 の常設の承認と読み、 その範囲の外を消さないこと (DR7) を決めた。

CTX2

事象 — 席の起草の写しの build の置き場が溜まり、 disk を満たした

席は起草の係 (subagent) ごとに repo の写しを作って試作を組み立て、 写しごとに build の置き場ができる。 写しの置き場は Claude Code の session ごとの一時 dir で、 器も人も消さない。 2026-09-29、 消費側の席で写しの build の置き場が溜まって host の disk を満たし、 持ち主の承認で手で消した (量は台帳の memo s2-07l.737.14 にだけ在る)。 組み立てを最初からやり直す費用は小さい (同じ memo)。 本 repo でも、 席が切った worktree が anchor の .worktrees の下に 19 本在り、 そのうち 1 本の target は 1.1 GB で、 最新の書きは 6 時間より前だった (2026-09-29 の実測)。 持ち主は、 席の起草の置き場席の試作の置き場の書きが 6 時間無い中間生成物作り直せる産物を器の掃除で消してよいと裁定した (裁定 user 2026-09-29T11:43Z・逐語は台帳)。

CTX3

機序 — 一時 dir は別の道具の内側の形で、 器は席の置き場を既に持ち、 組み立て中の置き場は書きが続く

Claude Code の一時 dir の path は、 別の道具が決める内側の形で、 user 名と uid を含む。 器は環境変数も home も読まない (C2.2) ので、 その path を知らない。 一方、 器は state dir の下に席ごとの置き場 (seat/<潰した target>/) を既に持ち、 圧縮の直前の 1 枠などを置いている (FR42 の前例)。 席の退役 (seat retire) は event を 1 件足すだけで、 席の置き場を動かさない。 組み立てと依存の取り込みは、 走っている間は置き場の file と dir の mtime (最後に書いた時刻) を動かし続ける。 test の走行や読むだけの使用は mtime を動かさない。 cargo の lock file のような道具ごとの印は、 言語に依り、 組み立ての後も残る。 席の指示文席への最初の案内は session の開始・clear・圧縮の後のたびに器が注入する唯一の経路で、 雛形の穴を機械が測った値で埋める (FR42)。

CTX4

憲法の向き (本 ADR の解釈)

A1 は「消す」という種類の操作の前に user の承認を要る。 本 ADR は、 裁定 user 2026-09-29T11:43Z を、 狭めた種類 — 閉じた列の名の dir を、 席の起草の置き場の git の木から、 書きが rules 行の時間無いものだけ、 運転手の終端の周運転手の一区切りの後ごとに消すこと — への A1 の常設の承認と読む。 同じ裁定は、 退役の時に即座に消すことと木の写しそのものを消すことを承認していないので、 本 ADR はそれを射程の外に置く。 N1 は器の管理する物を戻せない形で消すことを断れと言う。 本 ADR は ADR-0081 の読み (列の名の dir は慣行として作り直せる置き場で、 戻せない削除に当たらない) を同じ種類の物に広げるだけで、 慣行から外れて列の名で置かれた未追跡の物を失う代償も同じく引き受ける。 A4.2 は不可逆な操作の前に user に聞けと言う。 本 ADR は ADR-0081 と同じく、 消す物は作り直せる置き場なので不可逆に当たらないと読み、 そのうえで A1 の承認は裁定の RulingReceived の event に記録されている (周ごとの承認の event は要らない)。 C17.2 に沿い、 足す rules 行 1 本と走査の範囲が消すのは、 disk が満ちるたびに持ち主や席が撃つ写しの手の掃除 (OPT2) である。 C5 から、 書きの時間は rules 行の値で持ち、 裁定 id を持つ。 C17 から、 2 つ目の消す仕組みと 2 つ目の lock を足さず、 既存の掃除の関数に書きの線消してよい古さの線を 1 つ足す。 N2 と CON2 から、 一時 dir の path や host の値を code と tracked な file に書かない。 CON5 から、 削除の口 (subcommand) は足さない。 掃除は終端の周の副作用のまま。

CTX5

指示文の枠 — 行の構成は ADR-0045、 穴は ADR-0022、 印と器の在処は ADR-0090

ADR-0045 §2 (3) は orchestrator の SessionStart の注入を約 11 行以内とし、 席の同一性 3 行・憲法の効く部分 5 行・役割の特性 3 行に分けた。 SRS FR42 は、 行の構成と行数の上限の正本を ADR-0045 に置く。 ADR-0022 §2.4 は、 雛形の穴を権能の行の値と席の識別子に限った (台帳の現在地の穴は ADR-0045 §2 (3) が足した)。 ADR-0090 は印を → 器の SSOT: にし、 指示文に器の repo の在処 (絶対 path) と器の名の字を書かないと決め、 自分の射程では穴の列 (5 つ) と行数 (11) を変えないとした。 雛形の穴は core の列と xtask の写しの 2 面に在り、 歯が穴の数 5 を pin し、 e2e が行数 11 を 10 か所で pin する。 雛形の pointer は、 rules 行を名指せば manifest にその行が在ることを、 ADR を名指せばその file が在ることを、 歯が要る。

CTX6

射程 — 動かすのは 4 つだけ

動かすのは (1) 掃除の母集団に席の起草の置き場の git の木を足すこと、 (2) 起草の木置き場の git の写しにだけ書きの線 (今から rules 行の時間を引いた時刻) を掛けること、 (3) 書きの時間の rules 行を 1 本足すこと、 (4) 席の指示文に 1 行と穴を 1 つ足すこと。 動かさないのは、 消す名の閉じた 8 つの列、 追跡の判じ、 lock の名と取り方、 撃つ周 (運転手の終端の周だけ・管理 tick と手動の 1 周は撃たない)、 便の母集団と生死の判定、 退役の move、 席の登録と退役、 印と pointer の分類、 前の 11 行の字、 rules 行 host_guard.git、 event の kind、 要件書。 設計 dispatcher.md §33 (契約表の行 ah) と seat-roles.md §31 (行 y) が実装する。 ADR を書く条件のうち 1 (N1 と A1 の読みを広げる) と 3 (state dir の下の新しい置き場の形) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 7 本のものさしです。 disk を器が取り戻すこと。 承認が許した種類だけを消すこと。 組み立て中の置き場を消さないこと。 足すものを最小にすること。 host と道具に依らないこと。 席に場所が確かに届くこと。 重い走査を周期に載せないことです。

DR2承認の範囲に閉じる — 消すのは裁定が許した種類 (書きが時間無い中間生成物) だけで、 退役の即時の削除と木の写しは消さない (A1) CTX2・CTX4
DR3作業中の組み立てを消さない — 書きが続いている置き場は残す CTX3

DR5host と道具に依らない — 別の道具の内側の path に頼らず、 言語ごとの印を判じに使わない (N2・CON2) CTX3・CTX4

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 9 つ並べます。 器が起草の置き場を持ち、 指示文の穴で場所を渡し、 同じ掃除が書きの線つきで写しを掃く案 (選んだ案) と、 選ばなかった 8 つです。 選ばなかった案は、 今のまま人が消す案・一時 dir を器が掃く案・退役の時に即座に消す案・席ごとの周期 (管理 tick) で掃く案・道具の印で組み立て中かを判じる案・写しごと消す案・場所を字で説明して穴を足さない案・2 つ目の掃除を足す案です。

OPT1器が state dir の下に起草の置き場を持ち、 指示文の穴で場所を渡し、 同じ掃除が書きの線つきで写しを掃く採用

席ごとの起草の置き場を state dir の seat/<潰した target>/drafts/ に置き (器は dir を作らない)、 席の指示文の 12 行目がその絶対 path を新しい穴で渡す。 運転手の終端の周の掃除が、 便の木の後に同じ lock の中で、 置き場の直下の .git を持つ写しを木として、 閉じた 8 つの名で追跡されている file を持たず、 自身と下の全 entry の mtime の最新が rules 行の時間より前の dir だけを消す。 決め手は裁定 user 2026-09-29T11:43Z と分析 (同じ関数・同じ lock・値は 1 本)。

器が state dir の下に席ごとの起草の置き場を持ち、 席の指示文の 12 行目がその場所を渡し、 運転手の一区切りの後の掃除が同じ鍵の中で、 置き場の git の写しから書きの止まった産物だけを消す案です。 消すのは名の決まった 8 種の dir のうち、 追跡されている file を持たず、 その dir と下の全部の file と dir の最後に書いた時刻が設定の時間 (6 時間) より前のものだけです。 1 つでも新しい書きが在れば残します。 写しの産物を人の手に頼らず取り戻し、 承認の範囲だけを消し、 組み立て中を消さず、 消す仕組みと鍵は 1 つのまま、 増える値は 1 本だけ、 道具と host に依らず、 席は場所を確かに受け取る点で勝ります。 代わりに、 読むだけの使用は書きに数えず、 判じと消しの間に始まった組み立ては落ちうり、 便を走らせない project の席は掃かれず、 指示文の行は門ではなく、 指示文が 12 行になります。 持ち主の裁定と分析で選びました。

+ 利点

  • 写しの build の置き場が、 終端の周ごとに器の手で取り戻される (DR1)
  • 消すのは裁定の種類 (書きが時間無い中間生成物) だけで、 木の写しと追跡されている file と .git を持たない写しは残る (DR2)
  • 書きの線以後の entry を 1 つでも持つ dir は残るので、 組み立て中の置き場は消えない (DR3)
  • 消す仕組みと lock は ADR-0081 の 1 つのままで、 足す値は書きの時間の rules 行 1 本だけ (DR4)
  • 置き場は器の state dir の下で、 mtime は言語と道具に依らない (DR5)
  • 席は指示文の穴で path を受け取り、 潰し方や state dir を自分で解かない (DR6)
  • 走査は既存の終端の周の 1 回に載り、 管理 tick の周期は変わらない (DR7)

− 欠点

  • 読むだけの使用 (test の走行など) は書きに数えないので、 組み立てずに時間が過ぎた置き場も消え、 次の組み立てで作り直す (数分・正しさは変わらない)
  • 書きの判じと消しの間に組み立てが始まる競合は排他でなく、 その組み立ては落ちうる (撃ち直せば戻る)
  • 便を走らせない置き場 (終端の周が来ない project) の席の起草の置き場は掃かれない
  • 指示文の 1 行は案内で、 席が一時 dir や anchor の下に写しを置くことは止めない
  • 指示文が 12 行になり、 穴の列が 6 つになる (core と xtask の写しと行数の pin を同じ便で動かす)
OPT2今のまま — 満ちたら人が手で消す不採用

器には何も足さず、 disk が満ちたら持ち主か席が手で写しの build の置き場を消す。 決め手は実測 (消費側の席で disk が満ちた)。

器には何も足さず、 disk が満ちたら持ち主か席が手で写しの産物を消す案です。 器に消す手を足さず、 何を消すかを人が毎回見て決められる点で勝ります。 けれども、 満ちるまで誰も気付かず、 消費側の席で実際に disk が満ちました。 手の掃除は文章にしか無い手順で、 満ちるたびに繰り返すことになります。 退けました。

+ 利点

  • 器に消す手を足さず、 承認の読みを広げる必要が無い
  • 何を消すかを人が毎回見て決められる

− 欠点

  • 満ちるまで誰も気付かず、 消費側の席で disk が満ちた (DR1)
  • 手の掃除は文章にしか無い手順で、 満ちるたびに繰り返す (DR1・N2)
OPT3Claude Code の一時 dir を器が掃く不採用

写しの今の置き場 (session ごとの一時 dir) を器が探して掃く。 決め手は分析 (別の道具の内側の path で、 器は知らない)。

写しの今の置き場 (session ごとの一時 dir) を器が探して掃く案です。 席の作法を変えずに、 今溜まっている場所をそのまま掃ける点で勝ります。 けれども、 その path は別の道具が決める内側の形で、 user 名と uid を含み、 器は環境変数も home も読みません。 道具の版で形が変わっても器は気付けず、 host の値を code か公開の file に持つことになります。 退けました。

+ 利点

  • 席の作法を変えずに、 今溜まっている場所をそのまま掃ける
  • 指示文に行を足さずに済む

− 欠点

  • path は別の道具が決める内側の形で、 user 名と uid を含み、 器は環境変数も home も読まない (DR5・C2.2)
  • 道具の版で形が変わっても器は気付けず、 host の値を code か tracked な file に持つことになる (DR5・N2・CON2)
OPT4席の退役の時に起草の置き場を即座に消す不採用

seat retire の周に、 その席の起草の置き場の中間生成物 (または置き場ごと) を消す。 決め手は裁定の範囲と分析。

席を退役させた周に、 その席の起草の置き場の産物を即座に消す案です。 使い終えた席の分を時間を待たずに取り戻せ、 書きの判じが要らない点で勝ります。 けれども、 持ち主の承認は退役の時の即時の削除を含みません。 さらに退役は登録の記録を 1 件足すだけで、 同じ場所の席は起こし直されえます。 退役しないまま使われなくなった席の分も残り続けます。 退けました。

+ 利点

  • 使い終えた席の分を、 書きの時間を待たずに取り戻せる
  • 書きの判じが要らない

− 欠点

  • 裁定は退役の時の即時の削除を承認していない (DR2)
  • seat retire は登録の event を 1 件足すだけで、 同じ target の席は起こし直されうる (退役は置き場の終わりを意味しない)
  • 退役しないまま使われなくなった席の分は残り続ける (DR1)
OPT5管理 tick の周期で掃く不採用

席ごとの管理 tick (15 秒ごと) が、 自席の起草の置き場を掃く。 決め手は分析 (重い走査を周期に載せる)。

席ごとに 15 秒の周期で走る管理 tick が、 自席の起草の置き場を掃く案です。 便を走らせない project の席の置き場も掃け、 取り戻しが早い点で勝ります。 けれども、 大きい組み立ての置き場の走査を 15 秒ごとの周期に載せ、 tick の予算を食います。 掃除の撃ち口と鍵も 2 つになります。 退けました。

+ 利点

  • 便を走らせない project の席の置き場も掃ける
  • 席ごとの周期なので、 取り戻しが早い

− 欠点

  • 大きい build の置き場の走査を 15 秒ごとの周期に載せ、 tick の予算を食う (DR7)
  • 掃除の撃ち口と lock が 2 つになる (DR4・C17)
OPT6道具の lock file の有無で組み立て中かを判じる不採用

cargo の lock file などが在る置き場を組み立て中と読み、 無い置き場を消す。 決め手は分析 (言語に依り、 印は組み立ての後も残る)。

組み立ての道具が置く印 (cargo の lock file など) の有無で、 組み立て中かを判じる案です。 組み立て中かを道具の印から直に読め、 時間の設定の値が要らない点で勝ります。 けれども、 印は言語と道具ごとに違い、 器が言語ごとの知識を持つことになります。 cargo の lock file は組み立ての後も残るので、 在っても組み立て中とは限りません。 退けました。

+ 利点

  • 組み立て中かを道具の印で直に読める
  • 時間の値 (rules 行) が要らない

− 欠点

  • 印は言語と道具ごとに違い、 器が言語ごとの知識を持つことになる (DR5)
  • cargo の lock file は組み立ての後も残るので、 在ることは組み立て中を意味しない (DR3)
OPT7木の写しそのもの (worktree と clone) も消す不採用

書きが時間無い写しを、 中間生成物だけでなく写しごと消す。 決め手は裁定の範囲と分析 (N1)。

書きが時間無い写しを、 産物だけでなく写しごと消す案です。 取り戻す量が最大になり、 置き場が使い終えた写しで埋まらない点で勝ります。 けれども、 持ち主の承認は写しの削除を含みません。 写しには commit していない試作が在りえ、 それは作り直せません。 退けました。

+ 利点

  • 取り戻す量が最大になる (写しの本体の分も空く)
  • 置き場が使い終えた写しで埋まらない

− 欠点

  • 裁定は木の写しの削除を承認していない (DR2)
  • 写しには commit していない試作が在りえ、 作り直せない (N1)
OPT8置き場の path を指示文に字で説明し、 穴を足さない不採用

指示文の行に「state dir の seat/<潰した target>/drafts/」と字で書き、 席に path を組み立てさせる。 決め手は分析 (席が潰し方と state dir を自分で解く)。

穴を足さず、 指示文の行に置き場の場所を「state dir の下の seat の下の、 席の名を潰した dir の drafts」と字で書き、 席に path を組み立てさせる案です。 穴の一覧とその数の検査を動かさず、 雛形の字だけで済む点で勝ります。 けれども、 席が席の名の潰し方と state dir の解き方を自分で行い、 誤れば写しが掃かれない場所に置かれます。 置き場の形が器と指示文の文章の 2 か所に在ることにもなります。 退けました。

+ 利点

  • 穴の列 (core と xtask の写し) と数の pin を動かさない
  • 雛形の字だけで済む

− 欠点

  • 席が target の潰し方と state dir の解き方を自分で行い、 誤れば写しが掃かれない場所に置かれる (DR6)
  • 置き場の形が器と指示文の散文の 2 面に在ることになる (DR4・N2)
OPT9起草の置き場専用の 2 つ目の掃除を足す不採用

席の起草の置き場だけを掃く関数と lock を別に作る。 決め手は分析 (C17)。

席の起草の置き場だけを掃く関数と鍵を、 便の掃除と別に作る案です。 便の掃除の関数と行の字に 1 byte も触れず、 起草の置き場の都合だけで形を決められる点で勝ります。 けれども、 消す仕組みと鍵が 2 つになり、 消す名の一覧や追跡の判じが 2 か所で食い違いえます。 2 つの鍵の順と、 同じ写しを 2 つが掃く競合も別に決めることになります。 退けました。

+ 利点

  • 便の掃除の関数と行の字に 1 byte も触れない
  • 起草の置き場の都合だけで形を決められる

− 欠点

  • 消す仕組みと lock が 2 つになり、 名の列や追跡の判じが 2 か所で分かれうる (DR4・C17)
  • 2 つの lock の順と、 同じ木を 2 つが掃く競合を別に決めることになる (DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 起草の置き場は state dir の席の置き場の子で、 席の指示文の 12 行目がその path を渡し、 運転手の一区切りの後の掃除が、 置き場の git の写しから書きの止まった産物だけを消します。 支えるのは FR42 (席の指示文)・FR68 (便の自動起動の周)・FR30 (配送構造) への主張で、 NFR6 (host の資源) に理由を与え、 FR56 (危ない command の拒否) を壊さないことを示します。

採用 — OPT1

器 SHALL 席ごとの起草の置き場を state dir の seat/<潰した target>/drafts/ に持つ (席の置き場の子・器は dir を作らず席の git が作る)。 席の指示文は役割の特性に 1 行を足して 12 行とし、 その行は新しい穴でその席の起草の置き場の絶対 path を受け、 起草の写しをそこに git の worktree か clone で置くことと、 器が消す物と消さない物を告げ、 出所 pointer は本 ADR と rules 行と設計 doc を指す (穴は 6 つ・値の時間は書かない)。 器 SHALL 運転手の終端の周の掃除 (ADR-0081 の 1 関数・同じ lock・便の木の後) で、 置き場の全部の席の起草の置き場の直下の子のうち .git を持つ dir を起草の木とし、 木ごとに git ls-files の 1 回で追跡を判じ、 名が閉じた 8 つの列に在り追跡されている file を持たない dir のうち、 その dir 自身と下の全 entry (symlink は辿らない) の mtime の最新が、 今から rules 行 seat.drafts_stale_h (値 6・単位は時間・裁定 user 2026-09-29T11:43Z) の時間を引いた線より前のものだけを消す。 線以後の entry を 1 つでも持つ dir と、 mtime か dir を読めない entry を持つ dir SHALL 残す (後者は失敗に数える)。 .git を持たない写し SHALL 消さずに数え、 木の写しそのもの・追跡されている file・.git SHALL NOT 消さない。 席の退役 SHALL NOT 起草の置き場を消す契機にしない。 行を読めない周 SHALL 起草の木を 1 本も撃たない (既定値に倒さない)。 掃除の stderr の 1 行は、 起草の置き場が在る周だけ末尾に drafts= (dir を消した起草の木の数か no-rule) と nogit= を足し、 起草の置き場が無い周の字と stdout・event・rc は変えない。 管理 tick と手動の 1 周は掃除を撃たない。 本 ADR は、 裁定 user 2026-09-29T11:43Z を、 この種類 — 閉じた列の名の dir を、 席の起草の置き場の git の木から、 書きが rules 行の時間無いものだけ、 終端の周ごとに消すこと — への憲法 A1 の常設の承認と読み、 ADR-0081 の N1 の読み (列の名の dir は慣行として作り直せる置き場) を同じ種類の物へ広げる。 実装は設計 dispatcher.md §33 (契約表の行 ah) と seat-roles.md §31 (行 y)。

器は席ごとの起草の置き場を、 state dir の下の席の置き場の子 (drafts) に持ちます。 dir は器が作らず、 席の git が写しを作るときに作ります。 席の指示文には役割の特性の行を 1 本足して 12 行にし、 その行は新しい穴でその席の起草の置き場の場所 (絶対 path) を受け取り、 試作の写しをそこに git の worktree か clone で置くこと、 器が消す物と消さない物を告げます。 運転手の一区切りの後の掃除は、 便の作業場所を掃いた後に同じ鍵の中で、 全部の席の起草の置き場の直下の、 .git を持つ写しを 1 本ずつ見ます。 名の決まった 8 種の dir のうち、 追跡されている file を持たず、 その dir と下の全部の file と dir (symlink は辿りません) の最後に書いた時刻が、 今から設定の値 seat.drafts_stale_h (6 時間) を引いた時刻より前のものだけを消します。 新しい書きが 1 つでも在る dir と、 時刻を読めない物を持つ dir は残します。 .git を持たない写しは消さずに数え、 写しそのもの・追跡されている file・.git は消しません。 退役は消す契機にしません。 設定の値を読めないときは起草の置き場を掃きません。 掃除の 1 行には、 起草の置き場が在るときだけ、 産物の dir を 1 つ以上消した写しの数 (設定の値を読めない周は no-rule の語) と、 .git を持たない写しの数を足します。 置き場を器の state dir の下に置くのは、 器が既に席ごとの置き場を持ち、 別の道具の一時 dir の path は器が知らない形で、 host の値を公開の file に書けないからです。 場所を穴で渡すのは、 席に席の名の潰し方と state dir の解き方を任せると、 誤ったときに写しが掃かれない場所へ散るからです。 掃除を新しく作らず今の関数に「書きの線」を 1 つ渡すのは、 消す仕組みと鍵を 2 つにしない (C17) ためで、 便の作業場所には線を掛けないので、 便の掃除は今と同じに動きます。 書きの時刻で判じるのは、 組み立てと依存の取り込みは走っている間ずっと置き場に書き続け、 その性質はどの言語の道具にも共通だからです。 道具の印は言語に依り、 組み立ての後も残ります。 時間を設定の値にするのは、 値の変更に持ち主の裁定を要らせるため (C5) です。 写しそのものと退役の時の即時の削除を行わないのは、 持ち主の承認 (裁定 user 2026-09-29T11:43Z) が書きの止まった中間生成物だけを許したからで、 写しには作り直せない試作が在りえます。 撃つのを運転手の一区切りの後に限るのは、 大きい置き場の走査を 15 秒ごとの周期に載せないためです。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR42claimFR42 (席の指示文の注入) は、 指示文を席の同一性・憲法の pointer・役割の特性・台帳の現在地の 4 群とし、 行の構成と行数の上限は ADR-0045 が正本だと述べる。 本 ADR は ADR-0045 §2 (3) を部分 supersede して役割の特性に 1 行を足して 12 行とし、 機械が解いた値 (起草の置き場の path) で新しい穴を埋めると主張する。 雛形の外に手書きの規範文を持たないことと、 C 条文を注入しないことは変えない。 FR42 の字は land の後も ADR-0045 を指したまま残り、 12 行の正本は ADR-0045 から本 ADR へ supersede の鎖で辿る (FR42 の字を直すのは持ち主の SRS の改訂の回)。
FR68claimFR68 (便の自動起動) は終端の段の周に列の 1 周を撃つ。 本 ADR は、 同じ周の同じ掃除の 1 手の母集団に席の起草の置き場の写しを足すだけで、 列・順序・契機は変えないと主張する (ADR-0081 と同じ位置・空きを作ってから次の便を起こす)。
FR30claimFR30 (配送構造) は便の起動と着地を席でなく器が行うと決める。 本 ADR は写しの掃除も席の手でなく器の運転手の周に置き、 席に掃除の手順を渡さない (席に渡すのは置き場の場所だけ) と主張する。
NFR6rationaleNFR6 (host の資源) の目標は封じ込めの外で走る器の子 process 0 本と並列度で、 disk は数えない。 本 ADR は label の趣旨 (host の資源を守る) に disk の側から理由を与えるだけで、 目標の文は変えない。 足す仕事は運転手の process の中の git ls-files の子 (木ごとに 1 回・席の起草の木の本数だけ子が増える) と std の fs の読みと削除で、 land や retire が既に撃つ git と同じ種類の短い子である。
FR56rationale非退行の読み。 FR56 (禁じる語列の command の拒否) は席と runner の Bash が撃つ禁じる語列を断る。 本 ADR は rules 行 host_guard.git の git clean -f を変えず、 掃除は git clean を撃たない。 席の手が消す対象を絞れない操作は、 今どおり断られる。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 5 つと、 代わりに引き受けること 8 つです。 良くなるのは、 写しの産物が人の手に頼らず取り戻されること、 組み立て中の置き場と写しそのものは残ること、 消す仕組みが 1 つのままなこと、 席が場所を確かに受け取ること、 増える値が 1 本だけなことです。 引き受けるのは、 読むだけの使用を書きに数えないこと、 判じと消しの間の競合、 便を走らせない project の席は掃かれないこと、 指示文の行が門でないこと、 写しの本体の disk は残ること、 大きい置き場の走査の費用、 慣行から外れた物を失いうること、 指示文が 12 行になることです。

✓ 良い結果

  • ●席の起草の写しの build と依存の置き場が、 人の気付きに頼らず運転手の終端の周ごとに取り戻される
  • ●書きが続いている置き場 (組み立て中) は消えず、 木の写し・追跡されている file・.git を持たない写しも残る
  • ●消す仕組みと lock は 1 つのままで、 起草の置き場が無い置き場では掃除の行の字も 1 byte も変わらない
  • ●席は置き場の path を指示文から受け取り、 潰し方や state dir を自分で解かない
  • ●口 (subcommand)・event の kind・跨版の key は増えず、 増える値は書きの時間の rules 行 1 本だけ

⚖ トレードオフ・代償

  • ●読むだけの使用 (test の走行や依存の読み) は書きに数えないので、 組み立てずに時間が過ぎた置き場の build と依存の置き場は消え、 次の組み立てで作り直す (数分・正しさは変わらない)
  • ●書きの判じと消しの間に組み立てが始まる競合は排他でなく、 その組み立ては落ちうる (撃ち直せば戻る)
  • ●便を走らせない置き場 (終端の周が来ない project) の席の起草の置き場は掃かれない
  • ●指示文の 1 行は案内で門ではない。 席が一時 dir や anchor の下に写しを置けば掃かれない (置き場を強いる門は別の memo の候補)
  • ●木の写しそのものと .git を持たない写しは消えず、 その分の disk は残る
  • ●大きい build の置き場は、 書きの線を判じるのに entry を 1 つずつ読む (消す直前の 1 回と、 新しい entry が深い所に在る周)
  • ●列の名で置かれた未追跡の物と、 写しの中の入れ子の repo の列の名の dir は、 ADR-0081 と同じく中身ごと失いうる (慣行から外れた物を失う代償)
  • ●注入が 12 行になり、 穴の列 (core と xtask の写し) と行数の pin を同じ便で動かす。 新しい行は binary を入れ替えた後に起こし直した席から届く
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この記録が版の系譜のどこに在るかと、 判断が最後に行き着く原則です。 この記録は ADR-0081・ADR-0045・ADR-0022 を一部だけ置き換えます。 置き換えるのは、 掃除の対象を便の作業場所に限る範囲と承認の読みの範囲、 指示文の行の構成 (役割の特性 3 行・約 11 行)、 雛形の穴の範囲です。 消す名の列・鍵・撃つ周・印と参照の見分け方はそのまま保ちます。 行き着く原則は「器が人と AI の作業場所から承認の下で消してよいのは、 慣行として作り直せると名で分かる物のうち、 書く手が止まったと測れた物だけで、 作業場所そのものは消さない」です。
