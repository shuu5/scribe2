設計判断記録 (ADR) scribe2 — 門の読み手と shell が撃たない字

門の読み手は、 外へ出さないと閉じた表で言い切れる gh と、 shell が撃たないと閉じた列で言い切れる字だけを読みから外す — 読みだけの gh の表に当たる包まれた gh には wrapped の印を付けず、 本文を撃たない受け手だけの command 行の、 区切りを引用した heredoc の本文を segment に入れず、 全ての頭が閉じた列に在る command の data の命令の単引用の中の字と逆斜線が逃がした字を語の割りに使わない。 外れる形は今の読みのまま断り、 それでも新しく通る撃ちは限界として名指す (ADR-0078 の読みの補い・supersede なし)

host-guard の公開の門を全口座へ配線した直後に、 外へ何も出さない 3 つの定型 (CI を待つ loop の中の読みだけの gh・file に書く heredoc の本文・echo や printf の単引用の中の字) が全部の session で断られた。 原因は 2 つで、 wrapped の印が gh の動詞を見ないことと、 共有の分割が shell の撃たない字を撃つ字と読むことである。 本 ADR は、 閉じた表と閉じた列で言い切れる形だけを読みから外し、 言い切れない形は今のまま断り、 それでも新しく通る撃ちを限界として名指すと決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「門」は session が撃つ Bash の命令を撃つ前に読んで、 危ない形を止める器の見張りです。 外へ出す命令 (git の push や、 本文を GitHub へ出す gh の命令) を読む公開の門を全部の口座に配線した直後に、 外へ何も出さない 3 つの定型が全部の session で止まりました。 CI を待つ loop の中の読むだけの gh、 cat や python3 に渡す heredoc (命令の中に書く複数行の本文) の本文、 echo や printf の単引用の中の字です。 原因は 2 つで、 疑いの印が gh の動詞を見ないことと、 命令を区切る共通の読みが、 shell が命令として撃たない字を撃つ字と読むことです。 この記録は、 決まった一覧 (閉じた表と閉じた列) で言い切れる形だけを読みから外すと決めます。 1 つ目に、 読むだけの gh の一覧に当たる gh は疑いの印を受けません。 2 つ目に、 本文を shell に渡さない命令 (cat・tee・python3・python) しか無い行の、 区切りを引用した heredoc の本文は命令として読みません。 3 つ目に、 行の全部の命令が字を動かさない命令の一覧 (echo・grep・head・cd など) に在るときだけ、 単引用の中の字を疑いの判じに使いません。 一覧から 1 つでも外れる形 (bash に渡す heredoc・sh -c の中・pipe の先の自作の script・sed の式など) は今のまま止めます。 代わりに、 今は偶然止めている撃ちのうち 2 つが新しく通ることを引き受けます。 python3 に渡す本文の中の撃ちと、 cat や echo で file に書いた字を後の呼び出しで撃つ形です (書いた file の中は、 もともと門が測らない所です)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 6 つから説明します。 公開の門が命令をどう区切って読むかの経緯・配線の直後に 3 つの定型が止まった事象と 2 つの原因・撃たれる形も今は偶然止めている事実・読みが 1 本で字の出所が捨てられている事実・憲法の向き・この判断で動かす範囲です。

CTX1

経緯 — 公開の門は、 共有の分割命令を区切る共通の読みが返す segment と、 その中の細かい語を読む

ADR-0078 は host-guard (口座の設定から呼ばれる器の見張り・ADR-0056) の種類に公開 (publish) を足し、 外へ出す命令 (git の push と、 本文を出す gh の命令) の segment を撃つ前に読む形を決めた。 Bash の command は、 台帳の門の module に在る 1 本の分割が、 引用の外の改行と operator で segment に切り、 引用を解いた語の列にして返す。 この共有の分割を 7 か所 (host-guard の判定・起票の門・台帳のグラフの門・anchor の門・merge の門・live-row の門と公開の門が共有する読み手・公開の印の読み) が読む。 公開の門は、 頭の語が git でも gh でもない segment の細かい語も読み、 command 置換 ($( か backtick) を持つ語を割って、 git と後ろの push か、 gh と後ろの公開の群の語が在れば wrapped の印包まれた公開の疑いを付けて解けない形として断る (設計 vessel-hook.md §17。 割るのは実際に撃たれる command 置換を持つ語だけとする orchestrator の裁定 2026-09-28)。 ADR-0078 は sh -c の中と alias の push を測らない限界を、 設計 vessel-hook.md §17 は script の file の中を測らない限界を引き受けている。

CTX2

事象 — 配線の直後に、 外へ何も出さない定型が 3 つの形で止まった (原因は 2 つ)

公開の種類を全口座の hook へ配線した直後 (2026-09-29T23:15Z) に、 全部の session の定型が 3 つの形で断られた (2026-09-30 に、 main と同じ hook の code の binary へ payload を直に渡して実測)。 (1) CI を待つ loop と command 置換の中の読みだけの gh (x=$(gh pr view …)・for の本体と until の条件の gh pr checks・command 置換の gh api の GET など 10 形)。 (2) 区切りを引用した heredoc の本文の行 (cat で file に書く手順書・python3 に渡す script): 公開の門は本文の x=$(gh pr view 1) と git push の字を、 host-guard の tmux と git の種類は本文の tmux kill-server と git reset --hard を断る。 (3) echo と printf の単引用の中の $( か backtick を持つ字 (echo '$(git push)' など)。 報告された sed の式は、 省かれた字に $( か backtick を持っていたと推定する (報告の字だけでは通る・推定で未測)。 原因は 2 つある。 (1) は wrapped の印が、 gh の後ろに公開の群の語 (pr・issue・api など) が在るだけで、 動詞を見ずに付くこと。 (2) と (3) は共有の分割が heredoc を知らず、 引用を解くときに字の出所を捨てるので、 shell が撃たない字命令として動かない字を撃つ字と読むことである。

CTX3

現物 — 撃たれる形も、 今は $( の字と本文の字で偶然断っている

今の読みは撃たない字と撃つ字を分けないので、 撃たれる形も断っている (同じ実測)。 sh -c・python3 -c・awk の単引用の中の $(git push) と、 GNU sed の e の置換の中の $(git push) は wrapped の印で断られる。 echo と printf の単引用の $(git push) を、 pipe の先の bash・sh・xargs の sh -c・自作の script が撃つ形と、 file に書いて ./f.sh で撃つ形も wrapped の印で断られる。 bash に heredoc で渡す本文・cat の本文を pipe で bash に渡す形・書いた file を後ろの行の bash で撃つ形・.git/hooks の file へ書く形の本文の git push origin main は、 行き先を解けない形で断られる。 python3 に heredoc で渡す本文の os.system の中の $(git push …) は wrapped の印で断られる。 ただし $( を持たない同じ撃ち方 (echo 'git push origin main' | bash・python3 の本文の subprocess.run の git push) は今も通る。 門はこれらの撃ちを測っておらず、 $( の字と本文の字で偶然断っている。

CTX4

現物 — 読みは 1 本で、 字の出所は捨てられている

共有の分割は 1 本 (C2) で、 heredoc を読む直しをそこに置けば 7 か所の読み手が同じ読みを受ける。 公開の門だけを直すと、 同じ本文の偽陽性が他の門に残る。 語の字がどの引用から来たか (字の出所) は、 分割が引用を解くときに捨てていて、 単引用と二重引用を分けられない。 runner の session と verify 行を読む command guard は、 引用を解かない別の分割で、 共有の分割を読まない。 解けない形の断りに添える書き直しの字 (断りの経路) は、 理由が解けない形の全部の断りが共有している。

CTX5

憲法と既存の決定の向き (本 ADR の解釈)

A1 の「出す」は push と公開を名指し、 公開は取り消せない。 C11 は境界ごとの失敗を極性で持ち、 host-guard は閉じる側 (FailClosed・NFR4) で、 決められない形を通す向きに倒さない。 C2 は経路を 1 本にする。 C17 は足すものを最小にし、 消すものを先に名指す。 本 ADR が消すのは、 外へ何も出さない定型が断られるたびに、 session が Bash の呼び出しを分け直すか書き直す手である。 ADR-0078 の限界 (sh -c の中・alias) と §17 の限界 (script の file の中) は、 字面で撃つかどうかを決められない所を測らないと引き受けた線で、 本 ADR が読む ADR-0078 の線もこれであり、 本 ADR の限界もこの線に揃える。

CTX6

射程 — 動かすのは読みの 3 つだけ

動かすのは (1) 包まれた gh のうち読みだけの閉じた表読むだけの gh の一覧に当たる gh に wrapped の印を付けないこと、 (2) 共有の分割が、 本文を撃たない受け手shell に渡さない受け手だけの command 行の、 区切りを引用した heredoc の本文を segment に入れないこと、 (3) 単引用の中の字と、 引用の外か二重引用の中で逆斜線が逃がした字を、 同じ command の全ての segment の頭が閉じた頭の列字を動かさない命令の一覧に在る周だけ、 data の頭shell に渡さない命令の segment の語の割りに使わないことの 3 つである。 (2) は共有の分割を読む全部の門に効く: host-guard の git と tmux の種類 (FR56)・自分の設定の種類 (FR72)・rm の種類 (FR74)・台帳の種類 (FR76)・公開の種類 (FR80)・起票の門 (FR81)・台帳のグラフの門・anchor の門・merge の門・live-row の門。 (1) と (3) は公開の門だけが読む。 sed は data の頭に入れない (GNU sed の e は置換の結果を shell で撃つ)。 動かさないのは、 印と解けない形の閉じた列と宣言順・判定の順・断りの字と経路・rules 行・記録の形・command 置換の中の cat の heredoc の値の読み・command guard の分割と照合・要件書である。 ADR-0078 の決定は変えず、 公開の segment とその中の語の読みを補う。 設計 vessel-hook.md §23 (契約表の行 o・o2) が実装する。 ADR を書く条件のうち 4 (却下案を残す価値) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 外へ何も出さない定型を止めないこと。 今止めている撃たれる形を新しく通さないこと。 撃たないと言い切れない形は撃つ字として読むこと。 同じ本文を全部の門で同じに読むこと。 足すものを最小にし、 断りの字や規則の行や要件を変えないことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 9 つ並べます。 決まった一覧に当たるときだけ読みから外し、 新しく通る撃ちを限界として名指す案 (選んだ案) と、 選ばなかった 8 つです。 選ばなかった案は、 区切りを引用した heredoc の本文を受け手に依らず読まない案・受け手のそばに撃たない命令の一覧を足す案・単引用の字を全部の命令で字のまま読む案・公開の動詞が見えるときだけ止める案・断り文に書き直しの句を足す案・公開の門だけで heredoc を読む案・pipe の先の命令だけで免除を取り消す案・字を命令として動かす命令の一覧 (denylist) で免除を取り消す案です。

OPT1閉じた表と閉じた列に当たるときだけ読みから外し、 新しく通る撃ちは限界として名指す採用

読みだけの gh の閉じた表に当たる包まれた gh には wrapped の印を付けない。 共有の分割は、 本文を撃たない受け手 (cat・tee・python3・python) だけの command 行の、 区切りを引用した heredoc の本文を segment に入れない。 単引用の中の字と逆斜線が逃がした字は、 同じ command の全ての segment の頭が 閉じた頭の列 (data の頭と、 head・tail・wc・sort・uniq・cut・tr と、 cd) に在る周だけ、 data の頭 (echo・printf・grep の仲間・rg・cat・tee・jq・bd・bdw) の segment で語の割りに使わない。 どれも閉じた列から 1 つでも外れる形は今の読みのまま断り、 それでも新しく通る撃ちは限界として名指す。 決め手は実測と分析と orchestrator の裁定 2026-09-30 (同じ command の中で撃たれる形を断ったまま、 止まった定型を通す)。

3 つの読みを、 決まった一覧 (閉じた表と閉じた列) に当たるときだけ変える案です。 読むだけの gh の一覧 (pr の view や checks、 api の GET など) に当たる gh は、 包まれていても疑いの印を受けません。 本文を shell に渡さない命令 (cat・tee・python3・python) しか無い行の、 区切りを引用した heredoc の本文は、 命令として読みません。 行の全部の命令が字を動かさない命令の一覧 (echo・printf・grep・jq・bd などと、 head・wc などの整形と、 cd) に在るときだけ、 字を shell に渡さない命令の単引用の中の字と逆斜線が逃がした字を、 命令の疑いの判じに使いません。 一覧から 1 つでも外れる形は今のまま止めます。 止まっていた定型を通しつつ、 bash に渡す heredoc・pipe の先の bash や自作の script・書いた file を同じ行で撃つ形・sh -c の中・sed の式のような撃たれる形は止めたままにし、 7 か所の読み手が同じ読みを受け、 断りの字や要件を変えない点で勝ります。 代わりに、 今は偶然止めている撃ちのうち、 python3 に渡す本文の中の $( を新しく通し、 cat や echo で file に書いた字は書く時点で読まなくなり、 後の呼び出しで撃つ形は門の外になります。 一覧の外の命令の heredoc と sed の式と、 git や for と並ぶ字では偽の止めが残り、 読みの仕組みに heredoc と字の出所と一覧の読みが増えます。 実測と分析と orchestrator の裁定で選びました。

+ 利点

  • CI を待つ loop と command 置換の中の読みだけの gh が通る (DR1)
  • file に書く heredoc の本文と、 data の命令の単引用の中の字が通る (DR1)
  • bash・sh・sh -c・python3 -c・awk・sed の e と、 同じ command の中で data の字を撃つ列の外の頭 (pipe の先の自作の script・書いた file を ./f.sh で撃つ形・make) は今のまま断る (DR2・DR3)
  • 7 か所の読み手が、 同じ分割から同じ読みを受ける (DR4)
  • 断りの字・経路・rules 行・記録の形・要件を変えない (DR5)

− 欠点

  • python3 と python の heredoc の本文の中の $( (os.system に渡す字など) を新しく通す (今は断っている)(DR2)
  • 受け手だけの行と閉じた頭の列だけの command で file に書いた字は書く時点で読まれず、 後の呼び出しで撃つ形は script の file の中の限界へ移る (.git/hooks や rc file へ書く本文も同じ)(DR2)
  • 受け手と data の頭の列の外の頭 (sudo cat・本文を heredoc で渡す bd create・sed) と、 受け手の後ろに command を足した行と、 列の外の頭 (git・for など) と並ぶ data の字は今のまま読み、 偽陽性が残る (DR1)
  • 分割の状態機械に heredoc の読みと字の出所を足し、 読みだけの表と閉じた頭の列を器の定数で持つ (DR5)
OPT2区切りを引用した heredoc の本文を、 受け手に依らず読まない不採用

区切りを引用した heredoc の本文は shell が展開しないので、 受け手の命令に依らず本文の行を segment に入れない。 決め手は実測 (撃たれる形の本文を通す)。

区切りを引用した heredoc の本文は shell が展開しないので、 どの命令に渡すかに依らず本文を読まない案です。 規則が 1 つで済み、 sudo cat などの偽の止めも消える点で勝ります。 けれども、 bash に heredoc で渡す本文や、 cat の本文を pipe で bash に渡す形、 書いた file を後ろの行で撃つ形の git push を通してしまいます (今は止めています)。 引用した区切りは展開を止めるだけで、 受け手が本文を撃つかは決めません。 退けました。

+ 利点

  • 規則が 1 つで済み、 受け手の列を持たない
  • sudo cat や、 本文を heredoc で渡す bd create の偽陽性も消える

− 欠点

  • bash に heredoc で渡す本文・cat の本文を pipe で bash に渡す形・書いた file を後ろの行で撃つ形の git push を通す (今は断っている)(DR2)
  • 引用した区切り本文を字のまま渡す印は展開を止めるだけで、 受け手が本文を撃つかは決めない (DR3)
OPT3受け手のそばに、 撃たない command の閉じた列を足す不採用

本文を撃たない受け手の後ろに && や ; で続く撃たない command (git add・echo など) の閉じた列を足し、 それだけが続く行も本文を読まない。 決め手は分析 (列の中の命令も撃ちうる)。

本文を shell に渡さない命令の後ろに続く、 撃たない命令 (git add や echo など) の一覧を足し、 それだけが続く行も本文を読まない案です。 本文を書いてすぐ add する定型も 1 回で通り、 通る形が多い点で勝ります。 けれども、 一覧の中の命令も hook や filter で撃ちえます (git add は設定の clean filter を撃ちます)。 一覧を足すたびに、 撃つか撃たないかの裁きも要ります。 退けました。

+ 利点

  • 本文を書いてすぐ add する定型も、 1 回の Bash で通る
  • 受け手だけの条件より、 通る形が多い

− 欠点

  • 列の中の命令も hook や filter で撃ちうる (git add は設定の clean filter を撃つ)(DR2・DR3)
  • 列を足すたびに、 撃つか撃たないかの裁きが要る (DR5)
OPT4単引用の字を、 全部の頭で字のまま読む不採用

単引用の中の字は shell が展開しないので、 頭の語に依らず語の割りに使わない。 決め手は実測 (単引用の字を code として撃つ受け手が在る)。

単引用の中の字は shell が展開しないので、 どの命令でも字のまま読む案です。 規則が 1 つで済み、 一覧に無い命令の単引用でも偽の止めが消える点で勝ります。 けれども、 sh -c や python3 -c や awk の単引用の中の $(git push) を通してしまいます (今は止めています)。 頭の命令に依らないので、 単引用の中を shell や code として撃つ命令を見分けません。 退けました。

+ 利点

  • 規則が 1 つで済み、 data の頭の列を持たない
  • 列に無い data の命令の単引用でも、 偽陽性が消える

− 欠点

  • sh -c・python3 -c・awk の単引用の中の $(git push) を通す (今は断っている)(DR2)
  • 頭の語に依らないので、 単引用の字を shell や code として撃つ受け手を見分けない (DR3)
OPT5包まれた gh を、 公開の動詞の語が見えるときだけ断る不採用

包まれた gh は、 後ろに公開の動詞 (create・merge・edit など) の語が見えるときだけ wrapped の印を付け、 見えないときは通す。 決め手は分析 (表の外を通す)。

包まれた gh を、 後ろに公開の動詞 (create・merge・edit など) の語が見えるときだけ止め、 見えないときは通す案です。 読むだけの一覧を持たずに済み、 一覧に無い読むだけの動詞も通る点で勝ります。 けれども、 知らない並びや変数に入れた動詞、 gh api の書き込み (--input や -f) を通してしまい、 公開の動詞の一覧が漏れた周に公開の命令が黙って通ります。 退けました。

+ 利点

  • 読みだけの表を持たずに済む
  • 表に無い読みだけの動詞も通る

− 欠点

  • 知らない並び・変数の動詞・gh api の書き (--input・-f) を通す (DR2・DR3)
  • 公開の動詞の列が漏れた周に、 公開の命令が黙って通る (DR3)
OPT6断りの経路に、 読みだけの gh の書き直しの句を足す不採用

印の読みは変えず、 解けない形の断りに添える書き直しの字 (断りの経路) に、 読みだけの gh の書き直しの句を足す。 決め手は分析 (経路は全部の断りの字で、 直した後は要らない)。

読みは変えずに、 止めたときの断り文の書き直しの案内に、 読むだけの gh の書き直しの句を足す案です。 読み手の code を変えずに済み、 session が断り文から書き直し方を知れる点で勝ります。 けれども、 定型が止まるたびに session が書き直す手間は残ります。 断り文の案内は解けない形の全部の断りが共有する字で、 既存の test の字が 10 か所以上動きます。 退けました。

+ 利点

  • 読み手の code を変えずに済む
  • session が、 書き直しの形を断り文から知る

− 欠点

  • 定型が断られるたびに、 session が書き直す手は残る (DR1)
  • 経路は、 理由が解けない形の全部の断りが共有する字で、 既存の歯の字が 10 か所以上動く (DR5)
OPT7公開の門の読み手だけで heredoc を読む不採用

共有の分割は変えず、 公開の印の読みだけが heredoc の本文を落とす。 決め手は分析 (同じ本文の偽陽性が他の門に残る)。

命令を区切る共通の読みは変えず、 公開の門の読み手だけが heredoc の本文を落とす案です。 他の門の読みが変わらず、 直す範囲が公開の門の中で閉じる点で勝ります。 けれども、 同じ本文の tmux kill-server や git reset --hard を tmux や git の見張りが、 本文の bd の行を起票の門が、 今のまま止めます。 heredoc の読み手も 2 つになり、 経路を 1 本にする憲法の条に反します。 退けました。

+ 利点

  • 他の門の読みが変わらない
  • 直す範囲が、 公開の module の中で閉じる

− 欠点

  • 同じ本文の tmux kill-server と git reset --hard を host-guard の tmux と git の種類が、 本文の bd の行を起票の門が、 今のまま断る (DR1)
  • heredoc の読み手が 2 つになる (DR4・C2)
OPT8data の頭の免除を、 pipe の先の頭だけで取り消す不採用

data の頭の segment の出力を pipe で受ける segment の頭が閉じた頭の列に無ければ、 その command の免除を取り消す。 ; と && の後ろの頭は見ない。 決め手は分析 (; と && の後ろの頭を見ないので ./f.sh が通る)。

字を shell に渡さない命令の出力を pipe で受ける命令だけを見て、 それが一覧に無いときに免除を取り消す案です。 pipe の先の自作の script が撃つ形も閉じ、 ; や && の後ろの命令を一覧に縛らない点で勝ります。 けれども、 ; や && の後ろの命令を見ないので、 書いた file を ./f.sh で撃つ形や、 && の後ろの make が通ってしまいます (今は止めています)。 行の全部の命令を見る heredoc の条件と形も揃いません。 退けました。

+ 利点

  • pipe の先の自作の script が撃つ形も閉じる
  • ; と && の後ろの頭を列に縛らない

− 欠点

  • ; と && の後ろの頭を見ないので、 書いた file を ./f.sh で撃つ形と、 && の後ろの make が通る (今は断っている)(DR2)
  • 受け手の列 (全ての segment の頭を見る) と形が揃わず、 読みの形が 2 つになる (DR3・DR4)
OPT9実行者の閉じた列 (denylist) が在るときだけ免除を取り消す不採用

同じ command に実行者 (bash・sh・zsh・dash・eval・source・.・xargs と、 -c か - を持つか引数を持たない python3・python) の segment が在るときだけ data の頭の免除を取り消し、 他の頭と並ぶ command は通す。 決め手は実測と orchestrator の裁定 2026-09-30 (列の外の実行者が通る)。

字を命令として動かす命令の一覧 (bash・sh・eval・xargs・python3 -c など) を持ち、 それが行に在るときだけ免除を取り消す案です。 git や for と並ぶ行でも免除が効き、 整形の命令の一覧を持たずに済む点で勝ります。 けれども、 一覧の外で字を撃つ命令 (自作の script や make の recipe) が同じ行で撃つ形を新しく通してしまいます (今は止めています)。 撃つ命令は数え切れず、 一覧が漏れた周に撃たれる形が黙って通り、 止める側へ倒す向き (FailClosed) に反します。 orchestrator の裁定で、 行の全部の命令を見る一覧 (allowlist) を選び、 退けました。

+ 利点

  • git や for など、 撃たない頭と並ぶ command でも免除が効く
  • 整形の頭の列を持たずに済む

− 欠点

  • 列の外の実行者 (自作の script・make の recipe) が data の字を撃つ形を新しく通す (今は断っている)(DR2・C11.2)
  • 撃つ頭は開いた集合で、 列が漏れた周に撃たれる形が黙って通る (DR3)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 読むだけの gh の一覧に当たる包まれた gh は疑いの印を受けず、 本文を shell に渡さない命令しか無い行の、 区切りを引用した heredoc の本文は命令の区切りに入らず、 行の全部の命令が字を動かさない命令の一覧に在るときだけ、 単引用の中の字と逆斜線が逃がした字が語の割りに使われません。 FR80 (公開の字面の走査)・FR81 (起票の門)・FR56 (禁じる語列の拒否)・FR72 (見張りの設定の編集の拒否)・FR74 (rm の拒否)・FR76 (台帳の破壊の拒否) への主張で、 NFR4 (決められない形は止める) と NFR5 (hook の時間の予算) を退行させない読みを添えます。

採用 — OPT1

門の読み手 SHALL、 外へ出さないと次の閉じた表で言い切れる gh と、 shell が撃たないと次の閉じた列で言い切れる字だけを読みから外し、 1 つでも外れる形は今の読みのまま断る。 (1) 公開の門 SHALL、 頭の語が git でも gh でもない segment の中の gh が、 -R か --repo とその値を読み飛ばした後に読みだけの表の群と動詞 (pr の view・list・status・checks・diff、 issue の view・list・status、 release と gist と repo の view・list、 label の list) を持つか、 api の後ろが対象 1 つ (graphql でない) と読みの flag (-q・--jq・-t・--template・--paginate・--slurp・-i・--include・--silent・--verbose・--cache・--hostname と、 値が大文字の GET ちょうどの -X と --method) だけのとき、 その gh に wrapped の印を付けない。 値を取る読みの flag は空白書きと長い名の = 書きだけを読み、 短い flag の続け書きは知らない flag と読む。 表の外の動詞・変数の動詞・知らない flag・書きの flag (-f・-F・--raw-field・--field・--input・-H・--header)・GET ちょうどでない method を持つ gh が 1 つでも在れば、 今のまま印を付ける。 (2) 共有の分割 SHALL、 command 行の heredoc が全て引用した区切りで、 全ての本文が区切りの行で閉じ、 本文と区切りの行を除いた全ての segment の頭の語が本文を撃たない受け手 (cat・tee・python3・python) で heredoc の operator を持ち、 生きた command 置換と process 置換を持たない周だけ、 本文の行と区切りの行を segment に入れない。 pipe の先・; と && の後ろ・区切りの後ろの行に command が 1 つでも在れば今の読みのまま。 共有の分割を読む全部の門が同じ読みを受け、 分割の返りの型と呼び手は変えない。 (3) 共有の分割 SHALL 語ごとに、 単引用 ($ 付きの単引用を含む) の中の字と、 引用の外か二重引用の中で逆斜線が逃がした字を撃たない字と印し、 公開の門 SHALL segment の頭の語が data の頭 (echo・printf・grep・egrep・fgrep・rg・cat・tee・jq・bd・bdw) の周だけ、 撃たない字の $( と backtick と process 置換を語を割る判じに数えない。 この免除は、 同じ command の全ての segment の頭の語が 閉じた頭の列 (data の頭と、 head・tail・wc・sort・uniq・cut・tr と、 cd) に在る周だけ効き、 1 つでも列の外の頭が在れば、 その command の全ての segment で取り消す。 sed と他の頭の周は今の割りのまま。 python3 と python の heredoc の本文の中の撃ちと、 受け手だけの行と閉じた頭の列だけの command で file に書いた字を後の呼び出しで撃つ形は、 読みから外れる限界として引き受ける。 印と解けない形の閉じた列と宣言順・判定の順・断りの字と経路・rules 行・記録の形・command guard の分割は変えない。 実装は設計 vessel-hook.md §23 (契約表の行 o・o2)。

門の読み手は、 外へ出さないと決まった表で言い切れる gh と、 shell が撃たないと決まった一覧で言い切れる字だけを読みから外し、 1 つでも外れる形は今のまま止めます。 1 つ目に、 公開の門は、 先頭が git でも gh でもない命令の中の gh が、 読むだけの一覧の群と動詞 (pr の view・list・status・checks・diff、 issue の view・list・status、 release と gist と repo の view・list、 label の list) を持つか、 api の後ろが対象 1 つ (graphql でない) と読むだけの flag だけのとき、 疑いの印 (wrapped) を付けません。 method の値は大文字の GET ちょうどだけを読むだけと見て、 短い flag の続け書き (-XPATCH など) は知らない flag と読みます。 一覧の外の動詞・変数に入れた動詞・知らない flag・書き込みの flag を持つ gh が 1 つでも在れば、 今のまま印を付けます。 2 つ目に、 命令を区切る共通の読みは、 行の heredoc が全て区切りを引用していて本文が閉じ、 本文を除いた全部の命令が本文を shell に渡さない命令 (cat・tee・python3・python) で、 どの命令も heredoc の記号を持ち、 生きた command 置換も process 置換も持たないときだけ、 本文と区切りの行を命令の区切りに入れません。 pipe の先や ; と && の後ろ、 区切りの後ろの行に命令が 1 つでも在れば、 今のまま読みます。 この読みは、 共通の読みを使う全部の門に同じく効きます。 3 つ目に、 共通の読みは単引用の中の字と、 引用の外か二重引用の中で逆斜線が逃がした字に「撃たない字」の印を付けます。 公開の門は、 行の全部の命令が字を動かさない命令の一覧 (echo・printf・grep の仲間・rg・cat・tee・jq・bd・bdw と、 head・tail・wc・sort・uniq・cut・tr と、 cd) に在るときだけ、 字を shell に渡さない命令の周の、 その印の付いた $( と backtick を疑いの判じに数えません。 一覧の外の命令 (bash・sh・eval・xargs・python3・自作の script・make・git など) が 1 つでも在れば、 行の全部で今のまま読みます。 sed も一覧に入れません。 印の一覧・判定の順・断りの字・規則の行・記録の形・runner の見張りの読みは変えません。 一覧に当たるときだけ読みを変えるのは、 今の読みが止めている撃たれる形 (bash に渡す heredoc・pipe の先の bash や自作の script・書いた file を同じ行で撃つ形・sh -c や python3 -c や awk の中・sed の e) を止めたままにして、 止まっていた定型を通せるからです。 区切りを引用した heredoc の本文を受け手に依らず読まない案は、 bash に渡す本文の git push を通すので退けました。 引用は展開を止めるだけで、 撃つかどうかは受け手が決めるからです。 単引用の字を全部の命令で字のまま読まないのも同じ理由で、 sh -c や awk は単引用の中を撃ちます。 sed は GNU sed の e が置換の結果を shell で撃つので、 一覧に入れません。 単引用の字の免除を、 行の全部の命令が字を動かさない命令の一覧に在るときだけ効かせるのは、 字を撃つ命令は数え切れず、 撃つ命令の一覧 (denylist) では一覧の外の自作の script や make が同じ行で撃つ形を通すからで、 heredoc の条件 (行の全部が受け手) と同じ allowlist の形で止める側へ倒します (C11.2)。 python3 に渡す本文の中の撃ちと、 file に書いた字を後の呼び出しで撃つ形は新しく通ります。 どちらも $( を持たない同じ撃ち方 (本文の中の subprocess の git push・書いた script を後で撃つ形) を今も通していて、 門が測っていない所を $( の字で偶然止めていただけで、 本 ADR が読む ADR-0078 の線 (sh -c の中は測らない) と §17 の線 (script の file の中は測らない) と同じ所です。 python3 を本文を shell に渡さない命令に置くのは、 python3 に heredoc で script を渡す形が日常の定型で頻度が高いからです。 公開の動詞が見えるときだけ止める案は、 知らない並びや gh api の書き込みを通し、 止める側へ倒す向き (FailClosed) に反します。 heredoc の読みを共通の読みに置くのは、 同じ本文の偽の止めが公開の門のほかに tmux や git の見張りや起票の門にも出ていて、 読み手を 2 つにすると経路を 1 本にする条 (C2) に反するからです。 誤って止めた命令は書き直せば通りますが、 誤って通した公開は取り消せないので、 言い切れない形は撃つ字として読みます。

本文に出てくる専門語のやさしい説明

本文に出てくる専門語 8 個を、 やさしい言葉で説明します。

共有の分割shared splitter
Bash の command を、 引用の外の改行と operator (; や && や pipe) で segment に切り、 引用を解いた語の列にして返す器の 1 本の読み。 台帳の門の module に在り、 7 か所 (host-guard の判定・起票の門・台帳のグラフの門・anchor の門・merge の門・live-row の門と公開の門が共有する読み手・公開の印の読み) が読む。 command guard の分割は別で、 引用を解かない。
撃たない字unexecuted text
shell が command として撃たない字。 本 ADR が読みから外すのは、 本文を撃たない受け手だけの command 行の区切りを引用した heredoc の本文と、 全ての頭が閉じた頭の列に在る command の data の頭の segment の、 単引用 ($ 付きの単引用を含む) の中の字と、 引用の外か二重引用の中で逆斜線が逃がした字だけで、 閉じた列で言い切れない字は撃つ字として読む。
引用した区切りquoted delimiter
heredoc の operator (<< か <<-) の後ろの区切りの語のうち、 単引用・二重引用・逆斜線のどれかを含むもの。 shell は本文の変数と command 置換を展開せずに字のまま受け手へ渡す。 展開を止めるだけで、 受け手が本文を撃つかは決めない。
本文を撃たない受け手non-shell sink
heredoc の本文を shell の command として撃たずに受け取る命令の閉じた列 cat・tee・python3・python (頭の語の basename)。 cat と tee は本文を字のまま書き、 python3 と python は本文を Python として撃つ (本文の中の os.system と subprocess の撃ちは限界として測らない)。 command 行の全ての segment がこの列の命令で、 他の条件も満たす周だけ、 共有の分割は本文を segment に入れない。
data の頭data head
単引用の中の字を shell の command として撃たない命令の閉じた列 echo・printf・grep・egrep・fgrep・rg・cat・tee・jq・bd・bdw。 この頭の segment だけ、 公開の門は撃たない字の $( と backtick を語を割る判じに数えない。 同じ command に閉じた頭の列の外の頭が 1 つでも在れば取り消す。 sed は GNU sed の e が置換の結果を shell で撃つので列に入れない。
閉じた頭の列closed head list
data の頭の免除が効くための、 command の全ての segment の頭の語の閉じた列 (allowlist)。 data の頭 (echo・printf・grep・egrep・fgrep・rg・cat・tee・jq・bd・bdw) と、 撃たない整形の頭 head・tail・wc・sort・uniq・cut・tr と、 cd から成る。 列の外の頭 (bash・sh・eval・xargs・python3・自作の script・make・git・for などの予約語) が 1 つでも在れば、 その command の全ての segment で免除を取り消す。 撃つ頭の列 (denylist) は持たない。
wrapped の印wrapped mark
