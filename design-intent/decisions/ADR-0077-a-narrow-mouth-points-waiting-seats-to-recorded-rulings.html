設計判断記録 (ADR) scribe2 — 裁定の指し示しの口

待ちの席へ裁定の指し示しを送る狭い口を開ける — seat deliver は裁定面の記帳 id 1 つだけを受け、 指し示しの雛形の 1 行を管理 tick と同じ門で待ちの席へ送り、 送る行に入る外からの値は記帳 id だけにする (ADR-0045 の注入の口の削除を部分 supersede)

別の project の裁定面が持ち主の裁定を書き込んでも、 待っている席は次の管理 tick の合図まで気づかない。 ADR-0045 は席の入力欄へ任意の文を送る口 (seat inject) を消した。 本 ADR は、 裁定面の記帳 id 1 つだけを受けて指し示しの雛形の 1 行を送る狭い口を開け、 送る行に入る外からの値を 1 語に絞る形を決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「裁定面」は別の project が持つ、 持ち主が裁定を書き込む画面と server です。 持ち主が裁定を書き込んでも、 待っている席は次の定期の合図まで気づきません。 器は以前、 席の入力欄へ好きな文を送る口 (seat inject) を消し、 席どうしが連絡し合う経路を断ちました。 この記録は、 裁定面が裁定に付けた識別子 (裁定面の記帳 id) を 1 つだけ受けて「裁定が届いた」の決まった形の 1 行を送る狭い口 (seat deliver) を開け、 送る行に入る外からの値をその 1 語だけにする形を決めます。 送る前の確かめは定期の合図と同じで、 考え中の席には送りません。 この記録は要件 FR79 (裁定の指し示し) の根拠になり、 FR44 (席間の連絡の廃止) の差し込みの列に 1 つ足しても好きな文は運ばず、 続きを促す差し込みにも当たらない (短い語は運べ、 撃ち手は絞らない) ことを主張し、 ADR-0045 の注入の口の削除を一部だけ置き換えます。 持ち主は 2026-09-27 に口を開けることを裁定しました。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (好きな文を送る口は以前に消した)・事象 (待っている席は裁定の書き込みに気づかない)・機序 (好きな文を運ぶ口は席どうしの連絡の経路になる)・憲法と既存の決定の向き・この判断の範囲の 5 つから説明します。 送る仕組みそのもの (入力欄の確かめ・送達の窓) は消えずに残っていて、 定期の合図・席の起動・群の通知・便の終わりの通知が使っています。

CTX1

経緯 — ADR-0045 は席の入力欄へ任意の文を送る口を消した

ADR-0045 は席の役割を orchestrator の 1 つにし、 席が自分を保つために積んだ機構を消した。 消えたものの列の inject 系統には注入の口任意の文を送る口 (seat inject・任意の文を席の入力欄へ送る subcommand) が在り、 不在は歯が測る。 送達の機構そのもの (入力欄の門・送達の窓・Enter の再送) は残り、 ADR-0058 が戻した管理 tick席を周期で見る仕組み と、 席の起動と群の通知と便の終端の周の通知が内側で使う。 要件 FR44 は、 器から席の入力欄への差し込みを列に挙げた用途に限る。

CTX2

事象 — 待っている席は裁定の書き込みに気づかない

消費側の project は、 持ち主が裁定を書き込む画面と server (裁定面裁定を書く画面) を持つ。 書き込みの後、 席が待っているなら「裁定が届いた」と 1 行知らせたい。 今は外から撃てる口が無く、 待っている席は管理 tick の黙りの初段 (最後の打刻から既定 30 分) か梯子の今の段まで気づかず、 梯子の列が尽きた席と heartbeat を止めた席には合図が来ない。 席が考え中なら、 席の停止の hook が未読を拾う経路で足りる (消費側の設計)。

CTX3

機序 — 任意の文を運ぶ口は席どうしの連絡の経路になる

任意の文を受ける口は、 別の席の process からも撃てるので、 ADR-0045 が消した席間の連絡の経路を名前だけ変えて戻すことになる。 送る行に入る外からの値が閉じた文字種の 1 語 (裁定面の記帳 id) だけなら、 運べるのは短い識別子までで、 席が受け取るのは「どこを読めばよいか」の指し示しになる。 それでも識別子の形の中の短い語は運べ、 口は別の席の process からも撃てる。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C17 (決定はしご) から、 送達は既に在る 1 本 (入力欄の門・送達の窓) を使い、 門を二重に持たない。 N2 (散文にしか無い規則を規則として扱わない) から、 「記帳 id だけを送る行に入れる」は口の引数の閉じた列と記帳 id の文字種の検査で構造として守り、 注意書きに頼らない。 ADR-0058 の管理 tick と同じ門 (打刻の最終行が idle・入力欄が空) を通すので、 考え中の席の turn を割らない。

CTX5

射程 — 動かすのは口 1 つと要件の限定句だけ

動かすのは (1) seat の subcommand に裁定の指し示し裁定が届いた知らせの口を 1 つ足すこと、 (2) 要件 FR44 の差し込みの用途の列に裁定の指し示しを 1 つ足し、 新しい要件 FR79 と受入基準 AC49 を置くこと。 雛形は届いたことの指し示しだけで続きの指示を持たないので、 FR44 の「台帳の現在地から続きを進めるよう促す差し込みは打刻の合図だけ」は保つ。 動かさないのは、 注入の口 seat inject の不在 (戻さない)・送達の機構・管理 tick と群の通知の差し込み・席の起動・裁定の逐語の置き場 (消費側)。 同じ要件の改訂で FR44 の列に既存の便の終端の周の通知も足すが、 それは本 ADR の決定ではない (持ち主の裁定 2026-09-27T00:59Z)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 待っている席が書き込みの直後に知ること。 席どうしの連絡の経路を戻さないこと (送る行に入る外からの値を口の形で絞る)。 考え中の席の作業を割らないこと (定期の合図と同じ確かめを通す)。 足すものを最小にすること (既に在る送達の 1 本を使い、 確かめを二重に持たない)。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 4 つ並べます。 裁定面の記帳 id だけを受ける狭い口 (選んだ案)、 好きな 1 行を送る口 (消した口を戻す案)、 口を持たず定期の合図で拾う案、 裁定面の server が画面の送り込みを直に撃つ案です。 選ばなかった 3 つは、 席どうしの連絡の経路が戻る・待ちが長い・確かめを二重に持ち考え中の作業を割る事故を器が防げない、 という理由で退けました。
