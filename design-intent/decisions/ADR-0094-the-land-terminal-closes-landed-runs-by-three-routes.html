設計判断記録 (ADR) scribe2 — land の終端の 3 つの経路

land の終端が着地の形の close を書く経路は 3 つ — push の後の CI の照合と close、 vessel 宣言が任意 key remote を持たない repo の CI の照合なしの close、 PR で着地した便の merge の後に pipe retire が merge の祖先と先端の CI を照合してからの close (ADR-0089 の land の終端の範囲を部分 supersede)

着地の形 (契約を着地で閉じる理由の字) は land の終端だけが書き、 席が撃つ着地の形の close は起票の門が断る。 ところが land の終端が close を撃つのは remote へ push して CI を照合した便だけで、 押す先を宣言しない repo の便と、 PR を作って終わる便は、 着地しても契約を閉じる手段が無い。 本 ADR は land の終端が着地の形を書く経路を 3 つに広げ、 どの経路も器が測った事実の後にだけ書くと決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して取り込む 1 回の流れ、 「台帳」は仕事の約束 (契約) と裁定を記録する beads です。 便が main に着地すると、 器は取り込みの最後の手順 (land の終端) で台帳の契約を「着地で閉じた印」(着地の形) を付けて閉じます。 この印を書けるのは land の終端だけで、 席 (人と AI が話す session) が同じ印で閉じようとすると門が止めます。 ところが land の終端が閉じるのは、 remote (押す先) へ push して自動の検査 (CI) を確かめた便だけでした。 押す先を持たない repo の便と、 main を動かさずに PR を作って終わる便は、 着地しても契約を閉じる手段がありません。 この記録は、 land の終端が着地の印を書く経路を 3 つに広げます (要件書の FR50 と FR96)。 押す先を持たない repo の便は、 push も CI の確かめもせずに「CI の確かめなし」と書いて閉じます。 PR を作った便では、 land の終端の 3 つ目の経路として、 merge の後に撃たれた作業場を畳む器の口 (pipe retire) が、 merge と main の先端の CI を確かめてから閉じます。 どの経路も、 器が測った後にだけ印を書きます。 ただし押す先を宣言しない repo の PR の便は確かめる先が無いので閉じられず、 作業場を畳むだけの指定で片付け、 契約は開いたまま残ります。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 7 つから説明します。 経緯 (land の終端は push の後に CI を確かめて閉じ、 ADR-0089 が着地の印を land の終端だけに閉じた)・押す先を宣言しない repo の便が閉じられないこと・PR を作って終わる便も閉じる口を持たないこと・持ち主の裁定と要件書の版 0.30・憲法の向き・この判断の範囲・forge (GitHub などの置き場) へ問える数に上限があることです。

CTX1

経緯 — land の終端取り込みの最後の手順は push の後の CI の照合で閉じ、 ADR-0089 が着地の形着地で閉じた印を land の終端だけに閉じた

ADR-0045 §2 は便の起動・着地・merge を器の dispatcher に置いた。 FR50 の land の終端は、 着地した main を vessel 宣言repo の名乗りの設定の任意 key remote (押す先) へ push する前に出ていく字面を走査し (ADR-0078)、 push の後に push の先端の CI の結果を commit id で照合し、 success の周だけ台帳の便を close する。 理由の字は「landed <着地 commit id> ci=success」で、 並べて着地した便のうち先端でない便は、 先端でない commit には forge の CI の run が付かないので自分を祖先に持つ先端の CI で照合し、 末尾に tip=<先端の commit id> を持つ。 したがって押す経路の ci=success は、 どの便でも「その便を含む着地の後の main の先端の CI が success」を指し、 tip= は「着地した commit が先端でない」を指す。 ADR-0089 は bead の close の理由を種類ごとの閉じた形の和 (close の理由の文法) に閉じ、 契約の 1 つ目の形を着地の形 (landed <着地 commit id> …) とし、 起票の門台帳の書き込みを止める門が席の道具の呼び出しの着地の形の close を断る (FR81 (d)) と決めた。 ADR-0089 はこの land の終端を dispatcher の着地の終端 (push → CI の照合 → close) と読み、 代償に、 器の便の外で着地した契約の閉じは着地の形を持たないことを挙げた。

CTX2

事象 — remote を宣言しない repo の便は、 着地しても契約を閉じられない

vessel 宣言が任意 key remote を持たない repo では、 今の land の終端は push を撃たず (憲法 A1 の「出す」を既定で撃たない)、 event も記帳せず、 close もせずに終わる。 便は Landed で main に着地しているが、 契約は開いたまま残る。 席は着地の形で閉じられず (FR81 (d))、 取り下げの形で閉じると台帳から着地の事実が消える。 memo の自動の close の条件 (辿れる契約の全部が着地の形で閉じる・FR93) も満たされず、 その契約へ分けた memo は器が閉じない。 vessel 宣言を読めない周の今の land の終端は、 push を撃たずに失敗 (unreadable) を記帳して終わり、 着地をやり直さずに終端だけを撃ち直す口 (pipe land --terminal-only) で継げる。

CTX3

事象 — PR で着地した便PR を出して終えた便も、 契約を閉じる口を持たない

--pr-cmd の形の便は、 squash の代わりに便の branch を push して自 repo への PR を作り (main を動かさない・承認 event を前提にしない・ADR-0008)、 Landed を detail=pr で記帳して終わり、 land の終端は撃たれない。 --pr-cmd は任意の shell 行で、 器は PR をどの remote へ出したかを知らない。 merge は PR の上で押され、 その後に pipe retire作業場を畳む器の口 が worktree を可逆 move で畳む (N1.2)。 --pr-cmd の形の便を起こすのも pipe retire を撃つのも便を起こす権能 (launch) の手で、 この権能は席の rules 行に無い (ADR-0048・今は user)。 dispatcher の周は --pr-cmd を使わない。 今の pipe retire は forge に問わず (merge 済みかは撃つ側が確かめる)、 段を動かさず、 台帳に書かず、 worktree が在って clean なら merge の有無に依らず畳む。 畳んだ worktree は元の場所に無いので、 2 度目の pipe retire は worktree が無いとして断られる。 この便の契約も着地の形で閉じる経路を持たない。 merge の方法 (squash など) によっては便の branch の commit が main の祖先にならず、 main に入ったことを確かめられるのは forge が返す merge の commit である。 CTX2 の便もこの便も器の便で、 ADR-0089 の代償が名指す器の便の外の着地ではない。

CTX4

裁定と要件 — SRS 版 0.30 が 2 つの経路を land の終端に入れた

持ち主の裁定 2026-09-29T05:46Z の下で、 SRS 版 0.30 は FR50 に remote を持たない repo の close を、 FR96 に PR で着地した便の close を入れた。 FR50 は main に着地した便に掛かり (PR で着地した便を除き、 その close は FR96)、 land の終端が台帳へ書くのを、 push の後の close・remote を持たない repo の close・PR で着地した便の close・memo の自動の close (FR93) だけとし、 3 つの close の経路と理由の尾閉じる理由の後ろの字の字面を本 ADR に置く。 FR96 は pipe retire の照合と close、 通らない周の閉じた 6 語、 畳むだけの指定閉じずに畳む指定 (--fold-only) を持つ。 FR81 (d) は着地の形を書くのを land の終端 (FR50・FR96) だけとし、 FR91 は close の理由の文法の形の名を持ち (頭の字面は ADR-0089、 尾は本 ADR)、 FR93 と FR90 は land の終端 (FR50・FR96) の close を契機に持つ。 AC65 が 2 つの新しい経路を測る。 SRS と本 ADR の残る分岐は、 常設の裁定 2026-09-29T00:54Z と 04:37Z (分岐は推奨で進める) の下で orchestrator が推奨のまま決めた。

CTX5

憲法の向き (本 ADR の解釈)

C10 (宣言した値は測って初めて実効にする) と C10.2 (手書きの確かめ済みの印を受けない) から、 着地の形は器が測った事実の後にだけ書き、 席の宣言からは書かない。 C16 (仕様の外れを編集の時点で止める) の止めは起票の門 (FR81 (d)) のまま残す。 A1 (出す) から、 remote を持たない repo へは走査も push も撃たない。 C11.2 (失敗の極性) から、 測れない周は close しない側に倒す。 N1.2 から、 畳みは今のまま可逆 move とする。

CTX6

射程 — 動かすのは land の終端の経路の数と、 2 つの新しい経路の形と、 pipe retire の指定だけ

動かすのは (1) land の終端が着地の形の close を書く経路の数 (1 から 3 へ)、 (2) 2 つの新しい経路の close の理由の尾の字 (ci=none と、 PR の経路の tip=)、 (3) pipe retire の、 PR で着地した便への照合と close と、 通らない周の閉じた 6 語と、 照合も close もせずに畳むだけの指定 (--fold-only・本 ADR の前の pipe retire の振る舞いを明示の指定で残す)、 (4) memo の自動の close と局面の出力の書き直しの契機が 3 つの経路のどの close にも掛かること。 動かさないのは、 close の理由の文法の頭の 9 形と種類との組、 memo の 4 つの局面と自動の close の条件、 起票の門の断りの範囲、 remote を持つ repo の push の前の走査と push の後の CI の照合、 pipe retire の他の対象の扱い (畳むだけ・段を動かさない)、 pipe retire を撃つ手 (launch の権能・ADR-0048)、 --pr-cmd の口 (remote を宣言しない repo の PR の便も起動の段では断らない)、 器の便の外の着地 (FR92) の閉じ。 決めないのは PR の merge の commit を forge に問う字面で、 設計 doc に委ねる (今の code は CI の結果を問う行 ci-cmd だけを持ち、 PR の状態を問う行を持たない。 vessel 宣言に新しい key を足すなら on-disk 形式の変更として別の ADR を要する)。 ADR を書く条件のうち 3 (理由の尾の字・retire の理由の語・畳むだけの指定は版を跨ぐ形) と 4 (却下案を残す価値のある分岐) に当たる。

CTX7

制約 — forge への問いには上限があり、 CI の照合の問いで使い切った実例がある

器が forge へ撃つ問い (CI の結果・PR の状態) は、 forge が利用者ごとに課す時間あたりの上限を、 同じ利用者の他の道具の問いと共有する。 過去に、 着地の CI の照合を短すぎる間隔で繰り返す便が並んだ周に上限を使い切り、 同じ利用者の他の道具の問いまで 1 時間ほど断られた実例がある。 問いの数が撃たれた手の数でなく時間 (周の数) に比例する形は、 上限を静かに食う。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 着地の印は器が測った着地にだけ付けること。 main に着地した契約は押す先の有無に依らず、 PR で着地した契約は押す先を宣言する repo で閉じられること。 閉じる理由の頭の形と読み手の数を増やさないこと。 押す先の無い repo へは何も出さず、 測れないときは閉じずに撃ち直せること。 印の意味 (着地の後の main の先端が CI で緑) を経路で割らないこと。 forge への問いを時間に比例して増やさないことです。

DR1着地の形は測った着地にだけ付く — 器が測った事実の後にだけ書き、 席の宣言からは書かない (C10・FR81 (d)) CTX1・CTX5
DR2着地した契約は閉じられる — main に着地した器の便は remote の有無に依らず、 PR で着地した器の便は PR の merge を測れる repo (vessel 宣言が remote を持つ repo) で、 契約に着地の形で閉じる経路がある CTX2・CTX3・CTX4
DR3形を増やさない — close の理由の文法の頭の形と、 局面の出力の読み手の閉じた集合を広げない CTX1・CTX6
DR4出さない既定と閉じない極性 — remote を持たない repo へは何も出さず、 測れない周は閉じずに同じ口で撃ち直せる (A1・C11.2) CTX2・CTX5
DR5印の意味を経路で割らない — 着地の形の ci=success はどの経路でも「その便を含む着地の後の main の先端の CI が success」を指し、 tip= はどの経路でも「着地した commit が先端でない」を指す CTX1
DR6forge の問いを時間に比例させない — forge への問いは撃たれた手の分に限り、 周の数に比例して上限を食わない CTX7
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 8 つ並べます。 着地の印を書く経路を 3 つにし、 どれも器の確かめの後に閉じる案 (選んだ案) と、 選ばなかった 7 つです。 選ばなかった案は、 席が手で閉じるのを許す案・別の理由の形を足す案・確かめずに閉じる案・便を起こす仕組みの回が PR の merge を見張る案・何もしない案・PR の merge の commit 自身の CI で確かめる案・押す先を宣言しない repo では git の既定の押す先に問う案です。

OPT1着地の形を書く経路を 3 つにし、 どれも器の照合の後に閉じる採用

main に着地した便は、 remote を持つ repo なら今の push の後の CI の照合と close のまま、 remote を持たない repo なら走査も push も CI の照合も撃たずに「landed <着地 commit id> ci=none」で閉じる。 PR で着地した便は、 merge の後に撃たれた pipe retire が worktree の前提を確かめた後、 merge の commit を forge に、 それが remote の main の先端の祖先であることを git に、 先端の CI の結果を問い、 全部通った周だけ「landed <merge の commit id> ci=success」(先端でない周は末尾に tip=<先端の commit id>) で閉じて worktree を畳む。 通らない周は何も書かず閉じた 6 語の 1 つを出し、 畳むだけの指定は照合も close もせずに畳む。 決め手は分析 (閉じる経路が器の測りの後にだけ開く)。

着地の印を書く経路を 3 つにする案です。 main に着地した便は、 押す先 (remote) を持つ repo なら今のまま push の後に CI を確かめて閉じ、 押す先を持たない repo なら何も外へ出さず、 着地した時点で「CI の確かめなし」(ci=none) と書いて閉じます。 PR を作った便は、 merge の後に撃たれた pipe retire が、 PR が merge されたこと、 その merge が main の先端の祖先であること、 先端の CI が成功したことを確かめ、 全部通ったときだけ閉じて作業場を畳みます。 通らないときは何も書かずに理由の語を出し、 畳むだけの指定を付ければ確かめも閉じもせずに作業場だけを畳みます。 main に着地した契約と、 押す先を宣言する repo の PR の契約が閉じ、 印は器の確かめの後にだけ付き、 理由の頭の形も増えず、 forge への問いは撃ったときの分だけで済む点で勝ります。 代わりに、 pipe retire が forge と network に依り、 merge の後に誰か (便を起こす権能を持つ人) が pipe retire を撃つまで契約は開いたまま残ります。 押す先の無い repo の便は CI で確かめず、 main の先端が赤いと閉じず、 押す先を宣言しない repo の PR の便は閉じられず、 版を跨ぐ字も増えます。 分析で選びました。

+ 利点

  • main に着地した器の便は remote の有無に依らず、 PR で着地した器の便は remote を宣言する repo で、 契約が着地の形で閉じ、 そこから分けた memo が自動の close まで進む (DR2)
  • 着地の形を書くのは器の照合の後だけで、 席の手の着地の形の close を断る門に穴が開かない (DR1)
  • 理由の頭は landed のままで形も局面も増えず、 ci=success と tip= は押す経路と同じ意味で読める (DR3・DR5)
  • remote を持たない repo へは何も出さず、 測れない周は閉じずに同じ口で撃ち直せる (DR4)
  • forge への問いは pipe retire が撃たれた周の分だけで、 周の数に比例しない (DR6)

− 欠点

  • pipe retire が git と forge に問う口になり、 network と forge の問いの上限に依る
  • remote を持たない repo の便は、 CI で確かめない着地を着地の形で閉じる (尾の ci=none が残す)
  • PR の経路は remote の main の先端の CI で照合するので、 merge の後に入った別の commit で先端が赤い周は閉じない
  • merge の後に launch の権能の手 (今は user) が pipe retire を撃つまで、 契約は開いたまま残る
  • remote を宣言しない repo の PR で着地した便は照合できず (unmeasured)、 畳むだけの指定で worktree を畳めても契約は着地の形で閉じない
  • 版を跨ぐ面が増える (理由の尾の ci=none と PR の経路の tip=・pipe retire の理由の 6 語・畳むだけの指定)。 設計 doc と消費側の読み手が写す要がある (頭で照合する読み手は変わらない)
OPT2席が着地の形の close を手で撃つのを許す不採用

2 つの便の契約だけは、 merge や着地を確かめた席が着地の形で閉じてよいとする。 決め手は分析 (門に穴が開く)。

2 つの便の契約だけは、 merge や着地を確かめた席が手で着地の印を付けて閉じてよいとする案です。 器に新しい口が要らず、 席がすぐ閉じられる点で勝ります。 けれども、 門は字しか見ないので、 2 つの便の閉じだけを通すことができず、 席の着地の印を全部通すことになります。 印が器の確かめでなく席の申告から書かれ、 確かめは散文の手順に戻ります。 退けました。

+ 利点

  • 器に新しい口が要らず、 席は PR の merge を見てすぐ閉じられる

− 欠点

  • 門 (FR81 (d)) は字面しか見ないので、 2 つの便の close だけを通す形を字で分けられず、 席の着地の形の close を全部通すことになる (DR1)
  • 着地の形が器の測りでなく席の宣言から書かれ、 手書きの確かめ済みの印になる (C10.2・DR1)
  • merge と CI の確かめが散文の手順に戻る
OPT32 つの便に別の close の理由の形を足す不採用

例えば remote を持たない repo の便と PR で着地した便に、 着地の形と別の頭の形を足す。 決め手は分析 (形と読み手の集合が増える)。

2 つの便に、 着地の印とは別の頭の理由の形を足す案です。 どの経路で閉じたかが理由の頭で分かる点で勝ります。 けれども、 どちらの便も着地したのは事実で、 形を分けると memo を器が閉じる条件 (全部が着地の印) と、 状態を読む側の決まった集合を広げ直すことになります。 版を跨ぐ 9 つの頭の形も動き、 頭で照合する読み手 (門と memo を閉じる条件) と、 設計の文書と別の repo の読み手が書き換えを要します。 選んだ案のように尾を足すだけなら、 頭で照合する読み手は変わりません。 退けました。

+ 利点

  • どの経路で閉じたかが理由の頭で分かる

− 欠点

  • どちらの便も着地したのは事実で、 形を分けると memo の自動の close の条件 (全部が着地の形) と局面の出力の読み手の閉じた集合を広げ直すことになる (DR3)
  • 版を跨ぐ頭の 9 形が動き、 頭で照合する読み手 (起票の門の FR81 (d)・memo の自動の close の条件の FR93) と設計 doc と消費側の読み手が書き換えを要する。 尾を足すだけなら頭で照合する読み手は変わらない (DR3)
OPT4pipe retire が照合なしで閉じる不採用

PR で着地した便の worktree を畳むときに、 forge にも git にも問わずに着地の形で閉じる。 決め手は分析 (確かめずに着地と書く)。

PR を作った便の作業場を畳むときに、 何も確かめずに着地の印で閉じる案です。 forge に問わず network に依らず、 今の口に閉じる 1 手を足すだけで済む点で勝ります。 けれども、 merge されていない PR や閉じられた PR、 main の先端が赤い便まで着地として閉じえます。 merge 済みかの確かめも「撃つ側が確かめる」散文に残ります。 退けました。

+ 利点

  • forge に問わず network に依らない
  • 今の pipe retire に close を 1 つ足すだけで済む

− 欠点

  • merge されていない PR・閉じられた PR・main の先端が赤い便を着地として閉じうる (DR1)
  • merge 済みかの確かめが「撃つ側が確かめる」散文に残る (DR1)
OPT5dispatch の周が PR の merge を見張って閉じる不採用

dispatch の周ごとに、 開いた PR で着地した便の PR を forge に問い、 merge された周に閉じる。 決め手は分析 (問いが周の数に比例し、 畳みの手番が残るか撃つ手なしに入れ物を動かす)。

便を起こす仕組みの回ごとに、 PR を作った便の PR を forge に問い、 merge された回に閉じる案です。 pipe retire を撃つのを待たずに閉じられる点で勝ります。 けれども、 回ごとに PR を作った便の数だけ forge へ問いを撃つので、 問いの数が時間に比例して forge が許す上限を食います。 回が作業場まで畳むと、 merge の後もその作業場を人が使っているときに、 誰も撃たないまま動かします。 畳まないなら、 閉じた後も作業場が残り、 畳む手番は結局残ります。 退けました。

+ 利点

  • pipe retire を撃つ手番を待たずに閉じられる

− 欠点

  • 周ごとに PR で着地した便の数だけ forge へ問いを撃ち、 問いの数が撃たれた手でなく周の数に比例して forge の問いの上限を食う (DR6)
  • 周が畳みまで撃つと、 merge の後もその worktree を人が使っている周に、 誰も撃たないまま入れ物を動かす。 畳みを撃たないなら、 閉じた後も worktree が残り、 畳む手番は結局残る
OPT6何もしない不採用

land の終端も pipe retire も今のままにする。 決め手は分析 (着地した契約の閉じ方が取り下げしか無い)。

land の終端も pipe retire も今のままにする案です。 口も字も変わらない点で勝ります。 けれども、 2 つの便の契約は着地したのに、 席が選べる閉じ方が「取り下げ」しか無く、 取り下げで閉じると着地した事実が台帳から消えます。 その契約へ分けた memo も、 器が閉じる条件 (全部が着地の印) を満たさず閉じません。 退けました。

+ 利点

  • 口も字も変わらない

− 欠点

  • 2 つの便の契約は、 着地したのに席が選べる閉じ方が取り下げしか無く、 取り下げで閉じると着地の事実が台帳から消える (DR2)
  • その契約へ分けた memo は、 自動の close の条件 (全部が着地の形) を満たさず閉じない (DR2)
OPT7PR の merge の commit 自身の CI で照合する不採用

PR で着地した便は、 remote の main の先端でなく、 PR の merge の commit 自身の CI の結果で照合して閉じる。 決め手は分析 (着地の印の意味が経路で割れる)。

PR を作った便を、 main の先端でなく、 PR の merge の commit 自身の CI の結果で確かめて閉じる案です。 他の人の commit で先端が赤いときも、 自分の merge の commit が緑なら閉じられる点で勝ります。 けれども、 押す経路の「CI 成功」の印は「その便を含む着地の後の main の先端が緑」を意味するので、 PR の経路だけ「自分の commit が緑」を意味すると、 同じ印が経路で別のことを指します。 新しい push で走行中の検査を打ち切る設定の repo では、 続けて merge された commit の検査が終わらず測れないことも残ります。 退けました。

+ 利点

  • 他人の commit で main の先端が赤いか結果がまだ無い周も、 自分の merge の commit が緑なら閉じられる (CSQ-N3 を負わない)
  • main への push ごとに CI が走る repo では、 PR の merge の commit にも自分の CI の run が付くので、 先端を待たずに測れる

− 欠点

  • 押す経路の ci=success は「その便を含む着地の後の main の先端の CI が success」を指すので、 PR の経路だけ「自分の commit の CI」を指すと、 同じ着地の形の印が経路で別の事実を指す (DR5)
  • 新しい push で走行中の run を打ち切る設定を持つ repo では、 続けて merge された PR の merge の commit の run が完了せず、 測れない周が残る
OPT8remote を宣言しない repo は git の既定の remote に問う不採用

vessel 宣言が任意 key remote を持たない repo の PR で着地した便は、 clone の git の設定が既定とする remote (多くは origin) の main で照合する。 決め手は分析 (宣言の外の値で着地を測る)。

repo の名乗りの設定が押す先を持たないときは、 手元の git が既定とする押す先 (多くは origin) の main で確かめる案です。 押す先を宣言しない repo の PR の便も閉じられ、 設定に項目を足さずに済む点で勝ります。 けれども、 PR を作る 1 行は利用者が自由に書くので、 器は PR をどこへ出したかを知らず、 既定の押す先の main が PR の merge された main とは限りません。 違う main を測って閉じるか断ることになり、 測る先も repo の名乗った値でなく手元ごとの git の設定になります。 退けました。

+ 利点

  • remote を宣言しない repo の PR で着地した便も閉じられ、 畳むだけにして契約が開いたまま残る行き止まりが無い (DR2)
  • vessel 宣言に key を足さずに済む

− 欠点

  • --pr-cmd は任意の shell 行で、 器は PR をどの remote へ出したかを知らないので、 既定の remote の main が PR の merge された main と同じとは限らず、 違う main を測って閉じるか断る (DR1)
  • 照合の先が repo の名乗った値 (vessel 宣言・ADR-0010) でなく clone ごとの git の設定になり、 同じ repo でも clone ごとに測る先が変わる (C10)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 main に着地した便は、 押す先を持つ repo なら今の手順のまま、 押す先を持たない repo なら「CI の確かめなし」と書いて閉じます。 PR を作った便はこの 2 つの手順の外で、 pipe retire が merge と先端の CI を確かめてから閉じて作業場を畳みます。 PR を作った便で確かめが通らないときは何も書かず、 決まった 6 つの理由の語の 1 つを出して終わります。 支えるのは FR50 (land の終端)・FR96 (PR で着地した便の閉じ)・FR81 の (d) (席の着地の印を止める門)・FR93 (memo を器が閉じること) への主張と、 FR91 (閉じる理由の決まった形) を根拠にすることです。

採用 — OPT1

land の終端 SHALL 着地の形 (close の理由の文法の契約の 1 つ目の形・頭の字面は ADR-0089、 頭の後ろの理由の尾の字面は本 ADR) の close を次の 3 つの経路でだけ書く。 (1) と (2) は main に着地した便だけに掛け、 PR で着地した便 (Landed の記録が detail=pr の便) には走査も push も CI の照合も close も撃たない (その便の close は (3) だけ)。 (1) vessel 宣言が任意 key remote を持つ repo の便は今のまま、 push の前の走査・push・push の先端の CI の照合を撃ち、 success の周だけ「landed <着地 commit id> ci=success」(着地 commit が先端でない便は末尾に tip=<先端の commit id>) で close する。 (2) vessel 宣言が任意 key remote を持たない repo の便は、 走査も push も CI の照合も撃たず、 着地した周に「landed <着地 commit id> ci=none」で close し (並べて着地した便もそれぞれ自分の着地 commit id で・tip= を付けない)、 走らなかった段の event を積まない。 vessel 宣言を読めない周 SHALL remote を持たない repo と読まず、 close せずに失敗を記帳し、 その便の終端だけを撃ち直す口 (pipe land --terminal-only) で撃ち直せる。 (3) PR で着地した便は、 merge の後に撃たれた pipe retire が、 worktree が在って clean であることを git と forge に問う前に確かめ、 PR の merge の commit を forge に、 それが remote (vessel 宣言の key remote が名指す remote) の main の先端の祖先であることを git に、 先端の commit の CI の結果を vessel 宣言の CI の行で問い、 全部が通った周だけ「landed <merge の commit id> ci=success」(merge の commit が先端でない周は末尾に tip=<先端の commit id>) で close し、 その後に worktree を可逆 move で畳む。 通らない周 SHALL close も畳みも event も台帳の書きもせず、 閉じた 6 語 worktree-unready・not-merged・not-ancestor・ci-not-success (結果がまだ無い周を含む)・unmeasured (git か forge の問いを撃てない周と、 vessel 宣言が key remote を持たないか読めない周)・unwritten (照合が通って close が台帳に届かない周) の 1 つを 1 行出して rc 1 で終わり、 同じ口で撃ち直せる。 pipe retire に畳むだけの指定 (--fold-only) を付けた周 SHALL 照合も close もせずに worktree を可逆 move で畳み、 契約を開いたまま残す。 3 つの経路のどれで契約を close した周も (pipe retire の close を含む) memo の自動の close (FR93) と局面の出力の書き直し (FR90) の契機とする。 pipe retire の他の対象 (squash の形で着地した便・Failed・Stopped・審査が PASS でなく終わった便) SHALL 今のまま畳むだけで forge に問わず台帳に書かない。 起票の門 SHALL 席の道具の呼び出しの着地の形の close を今のまま断る。 close の理由の文法の頭の形と種類との組・memo の局面と自動の close の条件・push の前の走査の判定・pipe retire が段を動かさないこと SHALL NOT 変えない。

着地の印で契約を閉じるのは land の終端だけで、 その経路は 3 つです。 1 つ目と 2 つ目は main に着地した便だけに掛かり、 PR を作った便には撃ちません。 1 つ目、 押す先 (remote) を持つ repo の便は今のまま、 公開前の走査・push・CI の確かめを撃ち、 成功したときだけ閉じます。 2 つ目、 押す先を持たない repo の便は、 走査も push も CI の確かめも撃たず、 着地したときに着地の commit と「CI の確かめなし」を書いて閉じます。 repo の名乗りの設定を読めないときは、 押す先が無いとは読まず、 閉じずに失敗を記録し、 終端だけを撃ち直す口で撃ち直します。 3 つ目、 PR を作った便は、 merge の後に撃たれた pipe retire が、 作業場が在って汚れていないことを先に確かめ、 PR の merge の commit、 それが押す先の main の先端の祖先であること、 先端の CI の結果を問い、 全部通ったときだけ merge の commit を書いて閉じ (merge の commit が先端でないときは先端の commit も書き)、 それから作業場を畳みます。 通らないときは何も書かず、 作業場も畳まず、 決まった 6 つの理由の語 (worktree-unready・not-merged・not-ancestor・ci-not-success・unmeasured・unwritten) の 1 つを出して終わり、 同じ口で撃ち直せます。 畳むだけの指定 (--fold-only) を付けると、 確かめも閉じもせずに作業場だけを畳み、 契約は開いたまま残ります。 どの経路で閉じたときも、 memo を器が閉じる判定を回します。 pipe retire のそれ以外の対象は今のまま畳むだけです。 席が手で着地の印を付けて閉じるのは、 今のまま門が止めます。 閉じる理由の頭の形・memo の局面と閉じる条件・公開前の走査は変えません。 着地の印は「本当に着地した」ことの印なので、 器が測った事実からだけ書くべきで、 席の申告から書くと手書きの確かめ済みの印になります。 そのため席が手で閉じる案は採らず、 門はそのままにして、 器の口の側に経路を足しました。 押す先を持たない repo では、 外へ何も出さないのが既定なので push しません。 push しないので CI の結果も無く、 着地の根拠は取り込みのときの main での検査の再実行だけです。 それでも着地は事実なので着地の印で閉じ、 CI で確かめていないことを「ci=none」として字に残します。 PR を作った便では、 merge の方法によっては便の branch の commit が main の祖先にならないので、 forge が返す merge の commit を main の先端の祖先として確かめます。 CI を merge の commit 自身でなく先端で確かめるのは、 押す経路の「CI 成功」の印が「その便を含む着地の後の main の先端が緑」を意味するからで、 PR の経路でも同じ意味にそろえるためです。 その代わり、 他の人の commit で先端が赤いと閉じないことを引き受けます。 確かめる押す先を git の既定から推さないのは、 PR をどこへ出したかを器が知らず、 違う main を測りうるからです。 閉じてから畳むのは、 畳んだ作業場は元の場所に無く、 同じ口を撃ち直せなくなるからです。 確かめずに閉じる案は、 merge されていない PR を閉じうるので採りませんでした。 回ごとに見張る案には、 pipe retire を撃つのを待たずに閉じられる利点があります。 それでも、 forge への問いが時間に比例して増え、 上限を使い切った実例もあるので採りませんでした。 別の理由の形を足さないのは、 どちらも着地した事実で、 memo を閉じる条件と読み手の集合を広げずに済むからです。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR50claimFR50 (land の終端) の決定の側。 land の終端が台帳へ書く close のうち着地の形の close を、 push の後の CI の照合の close (尾は ci=success と、 先端でない便の tip=)・remote を持たない repo の CI の照合なしの close (尾は ci=none)・PR で着地した便の close (FR96) の 3 つの経路に閉じる。 前の 2 つは main に着地した便だけに掛け、 PR で着地した便には撃たないこと、 remote を持たない repo の便が走査・push・CI の照合を撃たず走らなかった段の event を積まないこと、 vessel 宣言を読めない周を remote を持たない repo と読まずに失敗を記帳して終端だけを撃ち直す口で撃ち直すこと、 理由の尾の字面の正本を本 ADR に置くことを決める。 AC65 の remote なしの close と撃ちの 0 本・読めない宣言・PR の Landed の周の書き 0 はこの決定を測る。
FR96claimFR96 (PR で着地した便の close) の決定の側。 pipe retire が worktree の前提を git と forge に問う前に確かめ、 merge の commit を forge に、 remote の main の先端の祖先であることを git に、 先端の CI の結果を vessel 宣言の CI の行で問う順と、 close の理由「landed <merge の commit id> ci=success」(先端でない周だけ tip=<先端の commit id>)、 照合 → close → 畳みの順、 通らない周の閉じた 6 語と rc 1 と何も書かないこと、 key remote を持たないか読めない周を unmeasured に数えること、 照合も close もしない畳むだけの指定 (--fold-only) を決める。 merge の commit を forge に問う字面は設計 doc に委ねる。 AC65 の PR の close と畳み・閉じない 6 つ・撃ち直し・畳むだけ・書きの件数はこの決定を測る。
FR81claimFR81 (起票の門の 4 つの断り) の (d) の読みの側。 門は席の道具の呼び出しの着地の形の close を今のまま断り、 着地の形を書くのは land の終端の 3 つの経路 (器の口) だけとする。 pipe retire は便を起こす権能 (launch) の口で席の rules 行には無く (ADR-0048)、 着地の形を書く根拠は器の照合で、 撃つ手の宣言ではない。
FR93claimFR93 (memo の自動の close) の契機の側。 land の終端の 3 つの経路のどれが契約を close した周も (pipe retire の close を含む) memo の自動の close の契機とし、 局面の出力の書き直し (FR90) も同じ契機に掛ける。 AC65 の PR の close と同じ撃ちでの memo の昇格済みの形の close はこの決定を測る。
FR91rationaleFR91 (memo の局面と処置) の close の理由の文法は着地の形の頭を 1 つだけ持ち (頭の字面の正本は ADR-0089)、 本 ADR の 2 つの新しい経路はその頭の後ろの理由の尾 (ci=none と、 PR の経路の tip=) だけを決めて (尾の字面の正本は本 ADR)、 頭の形と種類との組を増やさない。 着地の形で閉じた契約は memo の自動の close の条件 (全部が着地の形) に数えられる。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 4 つと、 代わりに引き受けること 7 つです。 良くなるのは、 main に着地した契約と押す先を宣言する repo の PR の契約が閉じること、 印が器の確かめの後にだけ書かれること、 理由の頭の形が増えず印の意味もそろうこと、 PR の確かめが通らないときに同じ口を撃ち直すだけで済むことです。 引き受けるのは、 pipe retire が forge と network に依り、 merge の後に誰かが pipe retire を撃つまで契約が開いたまま残ること、 押す先の無い repo の便は CI で確かめないこと、 main の先端が赤いと自分に依らず閉じないこと、 版を跨ぐ字が増えること、 器の便の外の着地は今のまま印を持たないこと、 押す先を宣言しない repo の PR の便は閉じられず畳むだけになること、 merge されずに閉じた PR の作業場を畳むのに畳むだけの指定が要ることです。

✓ 良い結果

  • ●main に着地した器の便は remote の有無に依らず、 PR で着地した器の便は remote を宣言する repo で、 契約が着地の形で閉じ、 そこから分けた memo が自動の close まで進む
  • ●着地の形は器が測った事実 (main の歯の再実走・merge の祖先・先端の CI) の後にだけ書かれ、 席の着地の形の close を断る門に穴が開かない
  • ●close の理由の頭と局面の出力の閉じた集合は増えず、 ci=success と tip= はどの経路でも同じ意味 (着地の後の main の先端が緑・着地した commit が先端でない) で読める
  • ●PR で着地した便の照合が通らない周は何も書かずに理由の語を 1 つ出すので、 PR の merge か先端の CI を待って同じ口を撃ち直すだけで済む

⚖ トレードオフ・代償

  • ●pipe retire が git と forge (PR の merge・先端の CI) に問う口になり、 network と forge の問いの上限に依る。 問うのは撃たれた周だけなので、 merge の後に launch の権能の手 (今は user) が pipe retire を撃つまで契約は開いたまま残る
  • ●remote を持たない repo の便の着地の根拠は land の main の歯の再実走だけで、 CI の確かめを持たないことが理由の尾 ci=none に残る
  • ●PR の経路は remote の main の先端の CI で照合するので、 merge の後に入った別の commit で先端が赤いか結果がまだ無い周は、 自分の変更に依らず閉じない (先端が緑になった後に撃ち直す)
  • ●版を跨ぐ面が増える (理由の尾の ci=none と PR の経路の tip=・pipe retire の理由の 6 語・畳むだけの指定 --fold-only)。 設計 doc と消費側の読み手が写す要がある
  • ●3 つの経路は器の便だけに掛かり、 器の便の外で着地した契約 (FR92) の閉じは今のまま着地の形を持たない (ADR-0089 の代償のまま)
  • ●vessel 宣言が remote を持たない repo の PR で着地した便は、 照合する remote が無く pipe retire が撃つたびに unmeasured で閉じない。 出口は畳むだけの指定で worktree を畳むことで、 契約は開いたまま残り、 席が選べる閉じ方は着地の形でない形 (取り下げなど) だけになる (remote を宣言すれば閉じられるが、 squash の形で着地する便の main も push されるようになる)
  • ●merge されずに閉じた PR の便の worktree は、 指定なしの pipe retire では not-merged で畳めず、 畳むだけの指定が要る (本 ADR の前は指定なしで畳めた)
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この記録が版の系譜のどこに在るかと、 判断が最後に行き着く原則です。 この記録は ADR-0089 を一部だけ置き換えます。 置き換えるのは land の終端の範囲 (着地の印を書くのは push の後に CI を確かめる手順だけ、 という読み) と、 着地の印を「CI の結果と共に書く」とした用語の定義の句 (CI の確かめなしも書けるように広げる) です。 memo の 4 つの局面・閉じる理由の頭の決まった形・memo を器が閉じる条件はそのまま保ちます。 行き着く原則は「着地の印は、 器が着地を測った後にだけ書き、 測らなかったことも字に残す」です。

置き換えられたなし (現行)

部分 supersede。 ADR-0089 から置き換えるのは land の終端の範囲と、 それに依る着地の形の定義の句だけである。 ADR-0089 は CTX4 で land の終端が台帳へ書く便の close を dispatcher の着地の終端 (push → CI の照合 → close・ADR-0045 §2・FR50) と読み、 決定の「着地の形のもの (land の終端だけが書く)」と FR50 への主張の「land の終端が台帳へ書くのは便の close と memo の自動の close だけ」をその読みで持った。 本 ADR はこの land の終端を、 着地の形の close を書く 3 つの経路 (push の後の CI の照合と close・vessel 宣言が任意 key remote を持たない repo の CI の照合なしの close・PR で着地した便の merge の後の pipe retire の照合と close) と読み替え、 memo の自動の close の契機 (land の終端が契約を close した周) も 3 つの経路のどれの close にも掛ける。 ADR-0089 の glossary の着地の形の定義の「land の終端が CI の結果と共に書く」は、 「land の終端が理由の尾に CI の結果 (ci=success) か CI の照合なし (ci=none) を持たせて書く」に置き換える (頭の字面の正本は ADR-0089 のまま、 理由の尾の字面の正本は本 ADR)。 動かさないもの: ADR-0089 の memo の 4 つの局面と判定・昇格の 2 形・close の理由の文法 (頭の 9 形と種類との組・memo の 3 つの閉じ方)・memo の自動の close の条件・起票の門が席の着地の形の close を台帳を読まずに断ること・器が審査の判定で memo を閉じないこと・器の便の外で着地した契約の閉じが着地の形を持たないこと。

照会終端 — PRIN-LANDED-IS-WRITTEN-ONLY-AFTER-THE-VESSEL-MEASURES

着地の印は、 器が着地を測った後にだけ書き、 測らなかったことも字に残す。 測れない周は印を書かず、 同じ口で撃ち直せる形で待つ。

本 ADR が、 席の手の close・照合なしの close・宣言の外の remote で測る案・別の理由の形・dispatch の周の見張り・何もしないを退け、 3 つの経路をどれも器の照合の後に閉じる形にしたのはこの原則に行き着く (これ以上は遡らない照会終端)。 射程は契約を着地で閉じる印で、 memo の閉じ方と審査の判定には掛けない。

終わった便の worktree を可逆 move で畳む器の口 (N1.2)。 便を起こす権能 (launch) の口で、 席の rules 行には無い (ADR-0048)。 段を動かさない。 本 ADR で、 PR で着地した便に限って merge と先端の CI を照合し、 通った周に契約を閉じてから畳む。
