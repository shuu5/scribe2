設計判断記録 (ADR) scribe2 — 入口の flip の名乗り

入口の flip を撃つ手段を持たない Rust の消費側は、 宣言の任意 key で「入口の flip は測らない」と名乗る (key の不在は現行の要求＝本 repo は無変更・名乗りは受付と契約表の検査の断りを外すだけで、 判定行に測らなかったことを残す・自前 command で満たす案と器への内蔵は採らない)

受付は、 検証行に cargo の行を持つ宣言に入口の flip (test 差分だけを base に当てて RED を確かめる検査) の行を要求する。 xtask を持たない Rust の消費側はこの行を書けず、 受付も契約表の検査も通らない。 本 ADR は、 宣言が任意 key 1 本で「測らない」と名乗れば受付が通し、 黙った宣言は今までどおり断り、 名乗った事実を判定行に残すことを決める。 消費側が自前の command で満たす案と、 器に flip の検査を内蔵する案は退ける (後者は後続の検討)。

この判断が約束すること (1 文サマリ)

器は「変更は落ちる test から始まったか」を入口で検めます。 その検査を撃つ道具を持たない Rust の repo は、 受付にも契約表の検査にも通れず、 古い写しの器に留まっていました。 この記録は、 宣言に 1 行「この検査はしません」と名乗れば受付が通し、 黙った宣言は今までどおり断り、 名乗った事実を判定行に残すことを決めます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 実測と現物から説明します。 消費側 1 号の宣言には入口の検査の行が無く、 同日の器では受付が止まりました。 消費側は前日の写しに器を固定して便を運び、 便を起こす側と実装役の世代がずれたままです。 受付の規則は本 repo の免除経路を閉じるために作られ、 消費側の扱いは設計に書かれていませんでした。

CTX1

実測 — 消費側 1 号が受付を通らず、 古い写しの器に留まっている

受付の規則 (設計 pipeline.md §7 の約束 4・2026-09-22 着地) は、 宣言の検証行 (common-verify) に先頭語 cargo の行を 1 本でも持ちながら入口の flip を撃つ行を持たない宣言を NoEntranceRed で断る。 消費側 1 号 (folio2) の宣言は nextest と clippy の 2 行で、 xtask を持たないので入口の flip の行を書けない。 その結果、 同日の器の世代では契約表の検査が rc 2 で止まり、 preflight も便の起動も通らない。 消費側は前日の写し (48 本の変更の前の世代) に器を固定して便を運び続けており (同日 167 便・終端まで 104 便)、 便を起こす側と実装役の器の世代がずれたまま動いている。

CTX2

現物 — 宣言の key と受付の読み手

宣言 file (.vessel.toml) の key は schema・allowed-commands・common-verify に、 任意の detection-verify・requirements・remote・ci-cmd と path の種別 3 本 (ADR-0047) を足した集合で、 未知の key は読みの誤りとして断る。 検証行の分類 (VerifyKind) は先頭語列だけで閉じた 3 値 (入口の flip・他の cargo・その他) で、 分類の欠け (KindGap) は NoEntranceRed の 1 値。 この規則の目的は本 repo の入口の flip の免除経路を閉じること (監査 2026-09-12) で、 消費側の扱いは設計に書かれていない。

CTX3

消費側の要望 — 名乗りで足りるが、 入口の検査は後で要る

消費側 1 号の席の報告 (2026-09-22・要旨) — 困っているのは「これから」で、 新しい直しが写しのままでは届かないこと。 審査で落ちた便の 8〜9 割は契約側の欠陥で器の世代は 1 割未満。 入口の flip の検査は後で要る — 台帳の規則は「検証は base で RED になる歯」だが、 今それを撃つのは起草役の手作業だけで、 base でも緑の歯が gate を通った実例がある。 xtask は無いので、 契約の検証行そのものを base で撃って落ちることを確かめる形が要る。 まずは名乗りの欄で写しの固定を外せれば足り、 内蔵は次の段以降の要望。

CTX4

user の裁定と憲法の向き

user は 3 案 (自前 command・名乗りの欄・器への内蔵) のうち名乗りの欄を先に開ける裁定をした (逐語は台帳 s2-07l.554 の notes)。 憲法は、 宣言値と測定値を型で分け測定なしに実効へ上げないこと (C10)、 本 repo の CI が入口の flip で全変更を検めること (C12.2)、 足す前に「要るか・既に在るか・既存で足りるか」の段を通ること (C17)、 依存 OSS の増減は先に裁定 id を取ること (A3) を求める。 宣言の値は対象 repo が名乗り、 器の行は上限だけを持つという分担は ADR-0010 §2.1 と ADR-0047 が既に決めている。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 宣言に「測らない」と名乗る欄を足す案、 消費側が自前の command で検査の行を満たす案、 検査そのものを器に内蔵する案、 器の規則の行で消費側を免除する案、 そして何もしない案です。

OPT1宣言の任意 key書いても書かなくてもよい設定の項目 1 本で「入口の flip は測らない」と名乗る採用

宣言に任意 key entrance-flip を足し、 値は閉じた 1 語 unmeasured だけとする。 key を持つ宣言は cargo の行が在っても NoEntranceRed で断られず、 key と入口の flip の行を同時に持つ宣言は矛盾として断り、 key の無い宣言は現行どおり。 契約表の検査の判定行に entrance=unmeasured の欄を出す。

宣言 file に entrance-flip = "unmeasured" の 1 行を書けば、 受付と契約表の検査が入口の検査の行を要求しなくなる案です。 書かない宣言は今までどおり断られ、 名乗りながら検査の行も書いた宣言は矛盾として断られます。 判定行には「測らなかった」と残ります。 読み手 1 か所の分岐で足り、 依存も大きさもほぼ増えません。

+ 利点

  • 黙った宣言は断ったまま (DR1)・本 repo の宣言は key を持たず無変更
  • 値は消費側の宣言が持ち、 器の規則の行は増えない (DR2)
  • 測らなかった事実が判定行に残る (DR3)
  • 読み手 1 か所の分岐で足り、 依存も core の大きさもほぼ増えない (DR4)

− 欠点

  • 名乗った消費側の便は入口の RED を測らないまま gate を通る (現状と同じ・後続で埋める)
  • 宣言の key が 1 本増える (schema は 1 のまま・未知 key の断りは不変)
OPT2消費側が自前の command で入口の flip の行を満たす不採用

入口の flip の行の字面の固定を緩め、 消費側が名指した command を「入口の flip」と読む。

入口の検査の行の字面の固定を緩め、 消費側が自分で名指した command を検査の行として読む案です。 消費側が自分の道具で測れる利点はありますが、 器はその command が本当に検査をしているか確かめられず、 名前だけの行で通る穴になります。 字面を緩めると本 repo の免除経路も緩みます。

+ 利点

  • 消費側が自分の道具で RED を測れる

− 欠点

  • 器はその command が flip を測っていることを確かめられず、 名前だけの行で通る穴になる (DR1 / DR3 に反する)
  • 字面の固定を緩めると本 repo の免除経路も緩む (約束 4 の目的を壊す)
OPT3入口の flip の検査を器に内蔵する (xtask を crate に切り出すか、 器の subcommand にする)不採用

消費側にも同じ入口の flip を配る。 実体は外部依存なし (nextest と git を子 process で撃つ) だが、 上限の読み先 (rules の行) と消費側の crate 配置の前提と allowed-commands の上限の設計が要る。

入口の検査そのものを器に内蔵して消費側にも配る案です。 消費側の便も落ちる test から始まったことを器が測れる、 いちばん強い形です。 ただし規模が大きく今日中には固定を外せず、 消費側の席が求めているのは差分を重ねて測る本 repo の形ではなく「契約の検証行そのものを base で撃つ」形で、 別の設計が要ります。 名乗りの欄が無ければ、 内蔵が着地するまで消費側は断られ続けます。

+ 利点

  • 消費側の便も RED から始まることを器が測れる (DR3 を最も強く満たす)

− 欠点

  • 規模が大きく今日中に固定を外せない (DR4)
  • 消費側の席が求める形は「契約の検証行そのものを base で撃つ」で、 差分の overlay で測る本 repo の flip とは別の設計 (CTX3)
  • 名乗りの欄が無いと、 内蔵が着地するまで消費側は断られ続ける
OPT4器の rules 行で消費側を免除する不採用

免除する repo の集合を器の rules 行 (裁定 id つき) に持つ。

免除する repo の一覧を器の規則の行に持つ案です。 一望できる利点はありますが、 器の規則に相手の repo の事情を積むことになり、 消費側が増えるたびに器の行と承認が増えます。 先の記録 (ADR-0047) が同じ理由で退けた分担です。

+ 利点

  • 免除が rules-diff に載り一望できる

− 欠点

  • 器の規則の行に対象 repo の事実を積む (ADR-0047 が退けた分担・DR2)
  • 消費側が増えるたびに器の行と裁定が増える
OPT5何もせず、 消費側は古い写しに固定し続ける不採用

受付の規則は変えず、 消費側は前日の世代の器で運び続ける。

受付の規則を変えず、 消費側は前日の写しの器で運び続ける案です。 器の変更は 0 ですが、 新しい直しが消費側に届かず、 便を起こす側と実装役の世代がずれたままになります。 消費側が増えるたびに同じ固定が要ります。

+ 利点

  • 器の変更が 0

− 欠点

  • 新しい直しが消費側に届かない (CTX1)・便を起こす側と実装役の世代がずれたまま
  • 消費側が増えるたびに同じ固定が要る
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 宣言の任意 key 1 本で名乗り、 黙った宣言は断ったまま、 名乗りと検査の行を同時に持つ宣言は矛盾として断り、 判定行に測らなかったことを残します。 本 repo の入口の検査と gate の検証は 1 行も減りません。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、 代わりに引き受けることです。 消費側は宣言に 1 行足すだけで最新の器に戻れ、 黙った宣言を断る規則は緩みません。 代わりに、 名乗った消費側の便は入口の検査を受けないまま gate を通り、 宣言の key が 1 本増えます。

✓ 良い結果

  • ●消費側 1 号が宣言に 1 行足すだけで古い写しの固定を外し、 器の最新の世代で便を運べる
  • ●黙った宣言を断る規則と本 repo の入口の flip は 1 mm も緩まない
  • ●測らなかった事実が判定行に残り、 後続 (契約の検証行を base で撃つ形) の要否を記録から判断できる

⚖ トレードオフ・代償

  • ●名乗った消費側の便は入口の RED を測らないまま gate を通る (消費側の席が挙げた「base でも緑の歯」は本 ADR では塞がらない)
  • ●宣言の key が 1 本増え、 読み手と歯がその分増える (schema は 1 のまま)
  • ●名乗りは repo 単位で、 契約 1 本ごとに測る / 測らないを選ぶ形は持たない
