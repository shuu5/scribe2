設計判断記録 (ADR) scribe2 — memo の昇格条件と審査

memo の昇格条件は閉じた 5 形の引き金の行で器が周ごとに判じ、 満ちない memo は起こす便が 0 の周に読むだけの審査へ上限つきで掛け、 処置が付くまで知らせ直す — 器は審査の判定で memo を閉じず台帳に書かず、 常設の memo の型を持たない

memo (設計の前の控えの bead) の昇格条件は散文で、 条件が満ちたかを確かめる手は席の記憶しか無かった。 本 ADR は昇格条件の節に器が読める引き金の行を持たせて 5 つの形に閉じ、 dispatch の周 (FR68 の契機の周) ごとに全部の open な memo を判じる。 引き金が満ちない memo は、 起こす便が 0 の周に rules 行の本数と間隔の内側で、 読むだけの審査の lens に意味から読み直させる。 満ちた memo は一覧と通知と doctor に、 審査の判定は一覧と通知に、 席が処置するまで出し続ける。 器は判定で memo を閉じず、 常設の memo の型も持たない。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session (orchestrator)、 「便」は契約 1 本を実装して取り込むまでの 1 回の流れ、 「memo」は設計に上げる前の気付きを台帳に控えた bead です。 memo には「いつ設計に上げるか」を書く節 (昇格条件) がありますが、 散文なので器は読めず、 条件が満ちたかは席が覚えて読み直すしかありませんでした。 本 ADR は、 この節に器が読める引き金の行を 1 行以上書かせ、 形を 5 つ (同じことの再発・同じ file を触る契約・待っている bead の完了・期日・設計の行の着地) に決めます。 便を起こす仕組み (dispatcher) が回るたびに器が全部の memo を判じ、 満ちた memo を昇格の待ちにします。 引き金が満ちない memo は、 便を起こさない回に、 回ごとの本数と memo ごとの間隔の上限の内側で、 読むだけの審査役の AI に意味から読み直させます。 席が始末を付けるまで、 満ちた memo は一覧・通知・点検の行に、 審査の判定は一覧と通知に出し続けます。 引き金の行の無い memo の書き込みは、 台帳の書き込みの門が止めます (要件 FR81 の 3 つ目の形)。 器は判定で memo を閉じず台帳にも書かず、 閉じない常設の memo の型も持ちません (要件 FR87 を中心に FR81・FR44・FR51 を支えます)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (memo の形は決まったが、 昇格条件の中身は誰も機械で読まない)・事象 (開いている memo 19 本の条件は全部散文)・現物 (便を起こす回・通知・裏で撃つ審査役・書き込みの門は既に在る)・憲法と既存の決定の向き・裁定・射程 (要件書と設計書の分担) の 6 つで示します。

CTX1

経緯 — memo契約の前の覚え書き の形は ADR-0051 で閉じたが、 昇格条件の中身を読む手は席の記憶だけ

ADR-0051 §4 は memo を label intake:memo の 1 つで見分け、 本文に 4 つの節を持たせ (最後の節が昇格条件)、 節の欠けを doctor の台帳作業の記録簿 (beads)の形の行が数える。 昇格条件の節は行き先の 1 語 (要件 id・要 ADR・要 裁定) と散文で、 器は節が在るかだけを数え、 中身を読まない。 memo から契約への遷移は席の手番で、 器が memo を閉じるのは着地の終端で、 その memo から discovered-from で辿れる契約が全部閉じた時だけである。 条件が満ちたかを確かめる手は、 席 (orchestrator) が open な memo の散文を読み直す手番しか無い。 前の器の棚卸しは、 作業記憶の復元の DATA (seat rebrief の出力・/rebrief の skill が復元で読む) に 2 つの印を memo ごとの行で出していた (SessionStart の hook が注入したのは open・in_progress・blocked の件数の 1 行だけ)。 [MEMO-DUE] は blocks 依存を持ちその全部が closed の memo (判定点は memo ごとの依存) で、 [MEMO-STALE] は依存を持たず、 priority が rules 行の値以下で、 updated_at から rules 行の日数が経った memo (古さの閾値は器の全体の規則) である。 印は器が数え、 処置memo への対応の手は印を読んだ席が決めた。 これらは ADR-0045 §2 (2) の作業記憶の削除で読み手ごと消え、 ADR-0051 も古さの閾値を持たないと決めた。

CTX2

事象 — open な memo 19 本の昇格条件は全部散文で、 器の読める行は 0 本

2026-09-28 の起草の時点の本 repo の台帳 (791 本) で label intake:memo を持つ bead は 125 本、 そのうち open は 19 本 (106 本は closed) である。 19 本の昇格条件の節は全部散文で、 本 ADR の文法で読める引き金契約へ上げる条件の行の行は 0 本である (2 本は箇条の行頭「- 引き金: 再発 N」の形を満たすが、 値が 1 語で切れず読めない引き金になる)。 条件の形を草稿が読んで分けると (推定・1 本が 2 つの形を持つことがあり和は 19 を越える)、 同じ形がもう 1 回起きたら (再発) が 10 本、 持ち主の裁定か指示を待つものが 5 本、 別の契約の着地か同じ file を触る便に乗せるものが 3 本、 隣の project の段の進みを待つものが 2 本である。 notes に [再発] の行を持つ memo は 2 本、 discovered-from で契約から辿れる open な memo は 0 本、 状態 pinned の bead は 0 本である。 持ち主の指示 (裁定 id user 2026-09-28T04:20Z) は、 器が memo の昇格条件を自ら判じ、 起こす便の無い周に判定しに行き、 処置が付くまで orchestrator の席へ渡し続けることを求めた。

CTX3

現物 — 周・知らせ・裏で撃つ lens審査する使い捨て AI・起票の門は既に在る

dispatch の周は器の dispatcher便を自動で起こす役 が FR68 の契機 (便の終端・便を運ぶ process の退役・手動の 1 周・介入の印・回答と承認の記帳) でだけ回す周で、 周ごとに台帳を 1 回読み、 契約表の facts も 1 周に 1 回読み、 周期の timer を持たない (ADR-0045 §2 (1)・設計 dispatcher.md §5)。 運転手の終端の周で起こした便が 0 本かつ候補が 1 本以上なら、 orchestrator の席へ idle の 1 行を送る (FR44 の閉じた差し込みの 1 つ・dispatcher.md §19)。 その末尾には、 台帳で開いたまま処置の無い落ちた便を毎周載せ、 処置 (close・release・行の直し) が付くまで同じ行を送り直す形が在る (§29・1 回きりの知らせが席の turn の途中で届かなかった実例から足した形)。 依存を待つ行へ先に撃つ事前審査の lens (§27 の行 aa) は、 1 周の本数の上限を rules 行に持って撃ち中を上限に数え、 裏に起こして周は終わりを待たない。 ただしこの lens は口座を選ばず起こす側の環境を継承し、 封じ込めの箱にも入れない (箱の片付けは作り手の process が死んだ箱を畳むので、 周が終わると裏の lens が殺されるため)。 lens の口は 1 本で、 契約の隣に置いた材料の file で雛形を切り替え、 settings を 1 つも読まない (ADR-0011)。 起票の門台帳の書き込みを止める門は memo の create に 4 節の本文を求める guard で、 command と本文の file だけを読む (ledger-form.md §3 の 9)。 管理 tick (ADR-0058) は置き場の file だけを読み、 台帳も git も撃たない (unit の環境に台帳の client が無い実測・seat-heartbeat.md §16)。

CTX4

憲法と既存の決定の向き

C15 は台帳をタスクと裁定の記帳先に限り、 規律を台帳に置かない。 C2 は選別と経路をそれぞれ 1 つの列挙の上の 1 関数にし、 新しい理由は列挙の 1 つの値として足す。 C14 は規律を文書 (憲法・ADR・SRS) とデータ (rules manifest) の 2 面に置く。 N2 は散文・記憶・会話にだけ在る規則を規則として扱わない。 C1 は規則の値を manifest の 1 file に置き、 C5 は rules 行の変更に user の裁定 id を求める。 C17.2 は走査・記録・rules 行・仕組みを足す前に、 消すものを名指すことを求める。 本 ADR が消すのは、 席が手で撃つ memo の棚卸し (open な memo の昇格条件の散文を読み直す手番) と、 散文だけの昇格条件である。 A1 は token の消費 (使う) に user の承認を求める。 ADR-0051 §4 は、 ADR-0045 §2 の dispatcher の着地を引いて、 器の台帳の書きを close の 1 種に限る。 ADR-0051 §4 は memo から契約への遷移を席の手番に置き、 古さの閾値を持たない。 ADR-0053 は計算できる判断を code に、 意味の判断を lens に、 裁定を人に置く。 同 ADR の射程は「便が受付から着地まで通る判断を 19 本に割」ったもので、 lens の verdict の語彙を 3 値に限るのはその便の審査の語彙であり、 便に属さない memo の審査は別の閉じた語彙を持ってよいと読む (解釈)。

CTX5

裁定 — 指示・消費の承認・常設の memo の否定・推奨で進める常設の指示

裁定 id user 2026-09-28T04:20Z は memo の列 (器が昇格条件を判じ、 起こす便の無い周に審査を掛け、 処置まで渡し続ける) を指示した。 裁定 id user 2026-09-28T07:27Z は審査の lens の token の消費を承認した (1 周に 2 本まで・1 本の memo は 24 時間に 1 回まで)。 裁定 id user 2026-09-28T07:47Z は常設の memo の型を持たないと決めた。 裁定 id user 2026-09-28T00:54Z は決めてほしいことを推奨で進める常設の指示で、 残りの分岐 (5 形の読み・処置の 4 形・通知の送り方・器が判定で閉じないこと) は台帳の設計の推奨のまま決めた。 逐語は台帳にだけ在る。

CTX6

射程 — 要件書は 5 形の意味だけを持ち、 字面は設計 doc が持つ

要件書 (SRS v0.28) は、 FR87 に 5 形の意味と周の判定と審査と知らせを、 FR81 (起票の門の 3 形) の (c) に deny (引き金の行を持たない memo の create と、 昇格条件の節を引き金の行の無い本文へ書き換える update) を、 FR44 の便の終端の周の通知に起こす便が 0 の周の memo の要約を、 FR51 の台帳の lint の項目に処置の付かない昇格memo を契約へ上げることの待ちの本数と最古の年齢を持ち、 scope の項は「memo の昇格条件と審査」である。 引き金の行の字面の文法と notes の行頭は ledger-form.md の改稿が、 通知の memo の要約の字面は dispatcher の設計 doc が持ち、 どちらも SRS には無い。 動かさないのは、 起動の列 (FR68・memo は便を起こさない)・器の台帳の書き (着地の close の 1 種)・memo の 4 節の見出しと 4 象限・台帳 lint の既存の項目・SessionStart の注入・管理 tick の合図・事前審査の lens の本数と上限・便の審査の verdict の語彙である。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 満ちた条件が誰かの記憶に頼らず席に届くこと。 計算できる条件は器の code が 1 本の判定で毎回判じ、 意味を読む判断だけを審査役の AI に回すこと。 消費に上限があり、 便の番と口座を奪わないこと。 memo の始末は席の番のままで、 器の台帳への書きを増やさないこと。 決まりを散文でなく器の仕組みで持ち、 消した棚卸しの形 (復元の文に出す印) を戻さないことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 7 つ並べます。 閉じた 5 つの形の引き金の行を器が判じ、 残りを上限つきの審査に回す案 (選んだ案)、 散文の条件を毎回 AI で全部判じる案、 期日だけを持たせる案、 席の作法の散文で棚卸しを求める案、 管理 tick で判じる案、 閉じる（close）という判定で器が memo を自動で閉じる案、 閉じない常設の memo の型を持つ案です。

OPT1昇格条件に閉じた 5 形の引き金の行を持たせて周ごとに code が判じ、 満ちない memo は起こす便が 0 の周に上限つきで読むだけの審査に掛け、 処置が付くまで知らせ直す採用

memo の昇格条件の節に「引き金: <形> <値>」の行を 1 行以上持たせ、 形を 5 つ (再発・同梱・依存・期日・着地) に閉じる。 dispatch の周 (FR68 の契機の周) が周の 1 回の台帳の読みと周が既に読む契約表で全部の open な memo を判じ、 満ちた memo を昇格（promote）の待ちにする。 満ちない memo は、 処置の待ちを除き、 前の判定から rules 行の時間が過ぎたものだけを、 起こす便が 0 の周に rules 行の本数まで、 読むだけの審査の lens に掛け (口座は FR36 の便用の規則・封じ込めは NFR6)、 判定を置き場の file と event 1 行に残す。 処置が付くまで、 満ちた memo は一覧と起こす便が 0 の周の通知 (FR44) と doctor の台帳の lint の項目 (FR51) に、 判定は一覧と通知に出し続け、 器は判定で memo を閉じない。 引き金の行を持たない memo の書きは FR81 の (c) の形として起票の門が断る。 決め手は、 計算できる条件を毎周 LLM なしで読み、 引き金が満ちない memo を上限つきの LLM で意味から読み直し、 処置を席に残せること (分析)。

memo の昇格条件の節に「引き金: <形> <値>」の行を 1 行以上書かせ、 形を 5 つに決める案です。 5 つは、 notes に [再発] で始まる行が N 行たまったか (再発)、 まだ閉じていない契約がその file を触る予定か (同梱)、 待っている bead が閉じたか (依存)、 その日時を過ぎたか (期日)、 その設計書の行を指す bead が閉じたか (着地) です。 便を起こす仕組みが回るたびに、 1 回だけ読んだ台帳と、 その回が既に読む契約表の上で全部の memo を計算で判じ、 満ちた memo を昇格の待ちにします。 満ちない memo は、 始末を待つものを除き、 前の判定から規則の行の時間が過ぎたものだけを、 便を起こさない回に規則の行の本数まで、 読むだけの審査役 (口座は便用の選び方・封じ込めの箱の中) に読ませ、 判定を置き場の file と出来事の記録 1 行に残します。 始末が付くまで、 満ちた memo は一覧・便を起こさない回の通知・点検の台帳の項目に、 審査役の判定は一覧と通知に出し続け、 器は判定で memo を閉じません。 計算で済む条件を毎回 AI なしで読み、 引き金の満ちない memo を上限つきの AI で意味から読み直し、 始末を席に残せる点で勝ります。 代わりに、 書く人が形を覚える必要があり、 器が読めない条件 (隣の project の進み・持ち主の意向) は期日を見直しの日として書くしかなく、 既存の 19 本は書き足すまで審査だけが読み、 回が回らない間は何もせず、 審査役の判定の誤りは席の手間を増やし、 審査の消費の量は便の記録に載らず、 器の部品と版を跨ぐ約束が増えることを引き受けます。 また、 依存の形は判定の点を依存に置く点で前の器が消した印 ([MEMO-DUE]) と同じで、 審査の順番も経った時間で来るので、 消した形との違いは、 条件を memo 自身の行に置くこと・古さを印として出さないこと・出す先が復元のときに読む memo ごとの行でなく、 既にある便の終わりの通知に数と次の 1 本だけを載せることの 3 つに頼ります。

+ 利点

  • 満ちた条件が、 誰も散文を読み直さなくても次の周の知らせに載る (DR1)
  • 引き金の判定は台帳の 1 回の読みと、 周が既に読む契約表 (同梱の write-set) の上の計算で、 LLM を使わず毎周撃てる。 起票の門・周・一覧が同じ 1 つの読み手を引く (DR2)
  • 審査は起こす便が 0 の周だけで、 撃ち中を含めた 1 周の本数と memo ごとの間隔が rules 行で縛られる (DR3)
  • 器は判定で memo を閉じず台帳に書かない。 処置は席の手番のまま (DR4)
  • 席の作法の散文に頼らず、 門と知らせ直しが器の仕組みとして効く。 SessionStart の注入に 1 語も足さない (DR5)

− 欠点

  • memo を書く人に引き金の行の形を覚えさせる。 器が読めない条件 (隣の project の段・持ち主の意向) は、 期日を見直しの日として書くしかない
  • 既存の open な memo 19 本は引き金の行を持たず、 書き足すまでは審査だけが読む
  • 周は FR68 の契機でだけ回るので、 便が無く手動の 1 周も無い間は判じも審査も知らせもしない
  • 判定の質は lens に依り、 誤った昇格（promote）や閉じる（close）の判定は席の処置の手番を増やす
  • 審査の lens の消費の量は便の消費の記録に載らない (判定の event が回数を残す)
  • 走査 1 つ・記録 2 つ (判定の file・event の種類)・rules 行 2 本・仕組み 1 つ (審査) と、 跨版の面版を跨いで保つ約束 (引き金の行の形・notes の行頭 2 つ・通知の memo の要約の形) が増える
  • 依存の形は判定点を依存に置く点で消した [MEMO-DUE] と同じで (ただし引き金の行ごとに判じ、 どれか 1 つが満ちれば満ちる)、 審査の順番は起票か前の判定からの経過で来る ([MEMO-STALE] と同じく時間の線を持つ)。 違いは条件を memo 自身の引き金の行に置くこと・経過を印として席へ出さないこと・出す面が作業記憶の復元の DATA (memo ごとの行) でなく、 既存の閉じた差し込み (FR44 の便の終端の周の通知) に数と次の 1 本だけを載せて処置まで送り直すことで、 消した形との線はこの 3 つに頼る (DR5)
OPT2散文の昇格条件を毎周 LLM で全部判じる不採用

引き金の行を足さず、 周ごとに open な memo の全部の昇格条件の散文を lens に読ませ、 満ちたかを判じさせる。 決め手は分析 (消費が memo の数と周の数に比例し、 数えれば済む条件まで LLM が読む)。

引き金の行を足さず、 回ごとに開いている memo 全部の散文の条件を審査役の AI に読ませて、 満ちたかを判じさせる案です。 書く人に新しい形を求めず、 どんな散文の条件も読め、 既存の 19 本もそのまま扱える点で勝ります。 けれども、 消費が memo の数と回の数の掛け算で伸び、 上限を置けば「毎回全部を判じる」前提が崩れます。 行の数や bead の状態や時刻のように数えれば済む条件まで AI が読むので、 同じ材料で判定が揺れます。 便を起こす回にも撃てば便の番と口座を奪い、 便を起こさない回だけにすれば毎回ではなくなるので退けました。

+ 利点

  • memo を書く人に新しい形を求めず、 散文のどんな条件も読める (DR1)
  • 既存の 19 本をそのまま扱える

− 欠点

  • 消費が open な memo の数と周の数の積で伸び、 上限を置くと「毎周全部を判じる」前提が崩れる (DR3)
  • 数えれば済む条件 ([再発] の行の数・bead の状態・時刻) まで LLM が読み、 同じ材料で判定が揺れる (DR2)
  • 起こす便の在る周にも撃てば便の手番と口座を奪い、 起こす便が 0 の周だけにすると毎周ではなくなる (DR3)
OPT3期日だけを持たせる不採用

昇格条件に見直しの日付だけを持たせ、 過ぎた memo を知らせる。 条件は memo ごとの日付 1 つで、 消した棚卸しの印 (依存で決まる [MEMO-DUE]・器の全体の古さの閾値で決まる [MEMO-STALE]) のどちらとも違う。 決め手は分析 (日付は条件が満ちたかを映さず、 数えれば分かる条件も読まない)。

昇格条件に見直しの日付だけを持たせ、 過ぎた memo を知らせる案です。 条件は memo ごとの日付 1 つで、 前の器が消した印 (待つ bead が全部閉じた memo の印と、 器の全体の日数の線を越えた memo の印) のどちらとも違う形です。 形が 1 つで判定も門も最も小さく、 AI を使わず消費が無い点で勝ります。 けれども、 同じことの再発や待っていた bead の完了で条件が早く満ちても日付まで知らせず、 満ちていなくても日付で知らせます。 memo の中身も台帳の状態も読まず、 数えれば分かる条件まで日付で近似することになるので退けました (選んだ案でも期日は 5 つの形の 1 つとして残ります)。

+ 利点

  • 形が 1 つで、 判定も門も最も小さい (DR2)
  • LLM を使わず消費が 0 (DR3)

− 欠点

  • 条件が早く満ちても (同じ形の再発・待っていた bead の close) 日付まで知らせず、 満ちなくても日付で知らせる (DR1)
  • memo の中身も台帳の状態も読まず、 数えれば分かる条件 (再発の行の数・待つ bead の状態) まで日付で近似する (DR2)
OPT4席の作法の散文で「待ちの間に棚卸し」を求める不採用

器は何も足さず、 orchestrator の席の作法 (指示文や規則の散文) に、 便の無い間に open な memo の昇格条件を読み直すことを書く。 決め手は憲法 N2 (散文にだけ在る規則は規則として扱わない)。

器は何も足さず、 席の作法の散文 (指示の文や規則の文章) に「便の無い間に開いている memo の条件を読み直す」と書く案です。 器の変更が無く、 約束も規則の行も増えず、 席の AI が散文の条件をそのまま読める点で勝ります。 けれども、 憲法 N2 は散文にだけ在る規則を規則として扱いません。 撃たれたかを誰も測れず、 席が忙しい時や文脈が詰まった時に抜け、 満ちた条件が届くかは結局 席の記憶に依ります。 読み直しの消費にも上限が無いので退けました。

+ 利点

  • 器の変更が 0 で、 跨版の面も rules 行も増えない
  • 席の LLM が散文の条件をそのまま読める (DR1)

− 欠点

  • 散文にだけ在る規則で、 N2 は規則として扱わない。 撃たれたかを誰も測れない (DR5)
  • 席が忙しい周や文脈の詰まった周に抜け、 満ちた条件が届くかは席の記憶に依る (DR1)
  • 読み直しの消費に上限が無い (DR3)
OPT5管理 tick で判じる不採用

周期で撃たれる管理 tick が台帳を読んで引き金を判じ、 合図の末尾に載せる。 決め手は現物 (tick は置き場の file だけを読み、 台帳も git も撃たない)。

時計で定期的に動く管理 tick が台帳を読んで引き金を判じ、 席への合図の末尾に載せる案です。 便が無い間も時計で判じられ、 回が回らない間の穴が無く、 合図は既に席へ届く口なので新しい口が要らない点で勝ります。 けれども、 tick は置き場の file だけを読む作りで、 tick の動く環境には台帳を読む道具が無いと実測されており、 読めば毎回測れないになります。 同梱の読みには契約表 (git の木) が要り、 tick に git を撃たせることになります。 便を起こす仕組みが時計を持たない形の横に、 台帳を読む別の時計が並び、 審査役を起こす本数と口座の判断も 2 か所に割れるので退けました。

+ 利点

  • 便が無い間も時計で判じ、 周が回らない間の穴が無い (DR1)
  • 合図は既に席へ届く差し込みで、 新しい口を要らない

− 欠点

  • tick の unit の環境には台帳の client が無く (実測)、 読めば毎回測れないになる (DR2)
  • 同梱の読みには契約表 (git の木) が要り、 tick に git を撃たせることになる (DR2)
  • dispatcher が周期の timer を持たない形 (ADR-0045 §2 (1)) の横に、 台帳を読む別の周期が並ぶ (DR5)
  • 審査の lens を tick から起こすと、 本数と口座の判断が便の起動の周と 2 か所に割れる (DR3)
OPT6閉じる（close）の判定で器が memo を自動で閉じる不採用

審査が閉じる（close）と判じた memo を、 器が次の周に閉じる (close の理由に判定の file を書く)。 決め手は既存の決定と分析 (器の台帳の書きの意味を変え、 LLM の判定だけで task を捨てる)。

審査役が閉じる（close）と判じた memo を、 器が次の回に自動で閉じる案です。 席の始末の手間が減り、 通知も早く消え、 書きの口は既存の close 1 つで済む点で勝ります。 けれども、 器が台帳へ書くのは着地の終わりの計算で決まる close だけで、 AI の判定で閉じるのは別の意味の書きになります (ADR-0045・ADR-0051)。 審査役の誤りで memo が黙って消え、 取り戻すには誰かが気付く必要があります。 閉じるか残すかは意味と価値の裁定で、 ADR-0053 は裁定を人 (席) に置き審査役に置かないので退けました。

+ 利点

  • 処置の手番が減り、 知らせの行も早く消える
  • 書きの口は既存の close の 1 種で、 新しい書きの種類は要らない

− 欠点

  • 器の close は着地の終端の 1 か所 (計算で決まる close) に限られ、 LLM の判定で閉じる close は別の意味の書きになる (ADR-0045 §2・ADR-0051) (DR4)
  • lens の誤りで memo が黙って消え、 取り戻すには誰かが気付く必要がある (DR1)
  • 閉じるか残すかは意味と価値の裁定で、 ADR-0053 は裁定を人 (席) に置き lens に置かない (DR2)
OPT7常設の memo の型を持つ (bd の状態 pinned で全部の数えから外す)不採用

裁定の控えや方針の一覧のように昇格しない memo を bd の組み込みの状態 pinned にし、 起票の門・周の判定・審査・一覧・doctor の数えの全部から外す (pinned にした時に event を 1 行)。 台帳のグラフの溢れの数えが pinned を外す印 (ledger-form.md §12 の形 5) と同じ 1 つの印で済む。 決め手は裁定 id user 2026-09-28T07:47Z と憲法 C15。

裁定の控えや方針の一覧のように昇格しない memo を、 bd の組み込みの状態 pinned (常設・閉じない) にし、 門・判定・審査・一覧・点検の数えの全部から外す案です。 控えを台帳に置いたまま通知の雑音にせず、 新しい形や label を作らず、 台帳のグラフの数えが既に使う印と同じ 1 つで済み、 隣の project で控えとして使われている memo 2 本も状態を変える 1 手で移せる点で勝ります。 けれども、 方針の一覧は決まりで、 置き場は ADR と設計書であって台帳ではありません (憲法 C15・C14)。 裁定の控えは台帳の問いとその裁定の行が持つので、 同じ裁定を 2 か所に持つことになります。 昇格しない memo は task ではなく memo としての仕事が無く、 pinned にすれば条件が満ちても知らされない memo を作れる抜け道になります。 持ち主も常設の memo の型を持たないと決めたので (裁定 07:47Z) 退けました。

+ 利点

  • 昇格しない控えを台帳に置いたまま、 知らせ直しの雑音にしない
  • 第 6 の引き金の形も別の label も作らず、 既存の組み込みの状態 1 つで表せる
  • 隣の project で昇格しない控えとして使われている memo 2 本を、 状態を変える 1 手で移せる

− 欠点

  • 方針の一覧は規律で、 置き場は ADR と設計 doc (C14 の文書の面) であって台帳ではない (C15) (DR5)
  • 裁定の控えは台帳の問い (FR81) とその裁定の行 (FR82) が持つので、 同じ裁定を 2 か所に持つことになる (DR5)
  • 昇格しない memo は task でなく、 memo の型としての仕事が無い (C15)
  • pinned にすれば判定から外れる抜け道になり、 条件が満ちても知らされない memo を作れる (DR1)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 昇格条件に 5 つの形の引き金の行を持たせ、 書き込みの門が引き金の無い memo を止め、 便を起こす回ごとに全部の memo を判じます。 満ちない memo は便を起こさない回に上限つきで審査役に読ませ (始末を待つものは除きます)、 始末が付くまで、 満ちた memo は一覧・通知・点検の行に、 審査の判定は一覧と通知に出し続けます。 器は判定で memo を閉じません。

採用 — OPT1

memo の昇格条件の節 SHALL 引き金の行を 1 行以上持ち、 形 SHALL 閉じた 5 つとする (FR87) — 再発 (notes の再発の行〔[再発] で始まる行〕が値の数以上)・同梱 (閉じていない契約の行の write-set が値の path を持つ)・依存 (値の bead が closed)・期日 (周の時刻が値の UTC の年月日と時分を過ぎた)・着地 (値の設計 doc の行を設計 pointer に持つ bead が 1 本以上 closed)。 行の字面 SHALL「引き金: <形> <値>」(行頭の「- 」を許す・値は空白を含まない 1 語・後ろの字は読まない) とし、 字面の文法の正本は設計 ledger-form.md の改稿が持ち、 起票の門・周・pipe dispatch ls SHALL 同じ 1 つの読み手を引く。 引き金の行を持たない memo の create と、 昇格条件の節を引き金の行の無い本文へ書き換える update は、 FR81 の (c) の形として起票の門が実行の前に台帳を読まずに断り、 5 形を告げる (門は席の道具の呼び出しにだけ掛かる)。 dispatch の周 (FR68 の契機の周) SHALL 周の 1 回の台帳の読みと周が既に読む契約表で open な (closed でない・pinned と defer も含む) 全部の memo を判じ、 discovered-from で辿れる契約を持つ memo (昇格済み) を除き、 1 つでも満ちた memo を昇格（promote）の待ちとし、 読めない引き金を満ちないとして名指す。 満ちない memo のうち、 処置の待ちの memo を除き、 前の判定 (無ければ起票) から rules 行 memo.triage_interval_h (時間・値は user 裁定 id 付き) が過ぎたものを、 起こす便が 0 の周に限り、 撃ち中を含めて rules 行 memo.triage_per_round (本数・値は user 裁定 id 付き) の本数まで古い順に、 裏の器の process に渡す (周は待たない。 周は timer を持たないので、 審査も契機の周にだけ回る)。 その process SHALL FR36 の便用の規則で口座を選び、 NFR6 の箱の内側で読むだけの memo の審査の lens を撃ち、 判定 (昇格（promote）・close・keep・読めない出力は unparsed) と証拠と昇格なら設計のスケッチを置き場の file に、 event を 1 行書く。 器 SHALL 判定で memo を閉じず台帳に書かない。 処置の待ち SHALL 昇格の待ちと処置の無い昇格・close の判定とし、 処置 SHALL 昇格 (acceptance に設計 pointer を持つ契約へ書き直す)・close・引き金の行の書き直し・keep の記帳 (notes の [keep] で始まる行) の 4 つとする。 pipe dispatch ls SHALL memo の行 (引き金の成否・判定・年齢・前の判定の時刻) を出す。 起こす便が 0 の周の便の終端の周の通知 (FR44 の閉じた一覧の 1 つ) SHALL open な memo の数・昇格の待ちの数・次の 1 本とその判定を名指し (字面は dispatcher の設計 doc が持つ)、 処置の待ちが在る周は候補が 0 本でも送る。 doctor の台帳の lint の項目 (FR51) SHALL 処置の付かない昇格の待ちの memo の本数と最古の年齢を出す。 起動の列 (FR68) は変えない。 常設の memo の型を持たない。 引き金の行の字面・5 形・[再発] と [keep] の行頭・通知の memo の要約の形 SHALL 跨版の面とする。

memo の昇格条件の節には、 器が読める引き金の行を 1 行以上書きます。 行は「引き金: <形> <値>」で、 形は 5 つ (再発・同梱・依存・期日・着地) に閉じます。 行の頭の「- 」は許し、 値は空白を含まない 1 語で、 その後ろの字は器が読みません。 引き金の行の無い memo の起票と、 昇格条件の節を引き金の行の無い本文へ書き換える書き換え (前に引き金の行が在ったかは問いません) は、 台帳の書き込みの門が要件 FR81 の 3 つ目の形として (席が自分の道具で撃つ書き込みだけを見て)、 台帳を読まずに止め、 5 つの形を告げます。 便を起こす仕組みが決まった契機で回るたびに、 1 回読んだ台帳とその回が既に読む契約表の上で閉じていない全部の memo (pinned や棚上げのものも含む) を判じ、 すでに契約へ上がったもの (discovered-from で契約から辿れるもの) を除いて、 1 つでも満ちた memo を昇格の待ちにします。 読めない引き金は満ちないとして名指します。 満ちない memo は、 始末を待つものを除き、 前の判定 (無ければ起票) から規則の行 memo.triage_interval_h の時間が過ぎたものだけを、 便を起こさない回に、 走っている分も含めて規則の行 memo.triage_per_round の本数まで古い順に、 裏の器の process に渡します (回は待ちません。 回は時計を持たないので、 審査も決まった契機の回にだけ回ります)。 その process は便用の選び方で口座を選び、 封じ込めの箱の中で読むだけの審査役を撃ち、 判定 (昇格（promote）・閉じる（close）・保つ（keep）、 読めない出力は unparsed) と証拠と、 昇格なら設計の下書きを置き場の file に、 出来事の記録を 1 行書きます。 器は判定で memo を閉じず、 台帳にも書きません。 始末 (昇格・close・引き金の行の書き直し・notes に [keep] で始まる行を足すこと) が要るのは、 昇格の待ちと、 始末の無い昇格・閉じるの判定です。 一覧 (pipe dispatch ls) には memo の行を、 便を起こさない回の通知の 1 行には memo の数・昇格の待ちの数・次の 1 本とその判定を出し (字面は設計書が持ちます)、 始末の要るものが在る回は候補が 0 本でも送ります。 点検 (doctor) の台帳の点検の項目 (要件 FR51) には、 始末の付かない昇格の待ちの本数と最も古いものの年齢を出します。 便を起こす列は変えず、 常設の memo の型は持ちません。 引き金の行の字面・5 つの形・[再発] と [keep] の行頭・通知の memo の要約の形は、 版を跨いで保ちます。 昇格条件が散文のままだと、 満ちたかを確かめる手は席の記憶しか無く、 開いている 19 本の条件は 1 本も器に読めませんでした。 そこで、 数えれば分かる条件 (再発の行の数・bead の状態・時刻・契約の触る file・行を指す bead の完了) を閉じた 5 つの形の行にして、 器の code が回ごとに判じます。 この計算は 1 回読んだ台帳と、 その回が既に読む契約表の上で済み AI を使わないので、 毎回全部の memo に撃てます。 形を開いたままにせず 5 つに閉じたのは、 書き込みの門と判定と一覧が 1 つの列挙の上の 1 本の読み手で字面を読み、 散文の抜け道を作らないためです (憲法 C2)。 引き金の満ちない memo は、 器が読めない条件 (隣の project の進みや持ち主の意向) を含めて審査役の AI に意味から読み直させ、 便を起こさない回に限って、 回ごとの本数と memo ごとの間隔を規則の行で縛りました。 持ち主が承認した消費 (裁定 07:27Z) の内側に留め、 便の番と口座を奪わないためです。 審査役の口座は便用の選び方に、 箱は封じ込めの要件に揃え、 箱を作る裏の器の process を審査の終わりまで残して、 回が終わっても審査役が殺されないようにしました。 判定で器が memo を閉じないのは、 器の台帳への書きを着地の終わりの計算で決まる close に限った既存の決定 (ADR-0045・ADR-0051) を守り、 閉じるかの判断を席に残すためです (ADR-0053)。 始末が付くまで通知を送り直すのは、 1 回きりの知らせが席の手の途中で届かなかった実例と同じ穴を塞ぐためです。 依存の形は判定の点を依存に置く点で前の器が消した印 ([MEMO-DUE]) と同じで、 審査の順番が経った時間で来る点ではもう 1 つの印 ([MEMO-STALE]) と同じ時間の線を持ちますが、 条件を memo 自身の行に置き、 古さを印として席へ出さず、 出す先も復元のときに読む memo ごとの行でなく既にある便の終わりの通知に数と次の 1 本だけなので、 消した棚卸しの形は戻しません。 常設の memo の型を持たないのは、 方針は ADR と設計書に、 裁定は台帳の問いに置くので、 昇格しない memo には仕事が無いからです (憲法 C15・裁定 07:47Z)。 走査と記録と規則の行と仕組みを足す代わりに、 席が手で撃っていた memo の棚卸しと、 散文だけの昇格条件を消します (憲法 C17.2)。 回は時計を持たず決まった契機でだけ回るので、 便が無く手動の 1 回も無い間は何もしないことを限界として受け入れ、 席は手動の 1 回で撃てます。
