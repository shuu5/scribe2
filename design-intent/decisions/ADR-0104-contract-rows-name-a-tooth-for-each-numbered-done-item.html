設計判断記録 (ADR) scribe2 — done の項目と歯の対応の欄

契約表の行は done の番号つき項目ごとの歯を欄 done-teeth で名指し、 器は表の検査・受付・gate の最初の段でその対応を機械で照らす — 欄の要否は vessel 宣言の任意 key teeth-check と base からの差分で決め、 着地済みの行は書き換えない

契約の done は番号つきの約束を並べるが、 どの約束をどの歯 (落ちる test) が測るかは設計の散文の中にしか無く、 器は数えられない。 そのため約束の 1 つに歯が無い行が列に入り、 便の中の審査で初めて落ちていた。 本 ADR は、 行に約束の番号と歯の名の対応の欄を持たせ、 器が設計の PR の CI・受付・gate の 3 か所で対応の揃いと歯の在りかを数えると決める。 歯が約束を本当に測るかの判断は審査の係に残す。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「契約表の行」は設計の文書の末尾に並ぶ 1 つの仕事の約束、 「歯」はその約束を外した実装で落ちる test です。 行の done には「(1) … (2) …」と番号つきの約束が並びますが、 どの約束をどの歯が確かめるかは文書の散文の中にしか無く、 器は数えられませんでした。 そのため約束の 1 つに歯が無い行がそのまま実装の順番の列に入り、 実装の前の審査で初めて落ちて、 列の順番も崩れていました。 この記録は、 行に「約束の番号と歯の名」の対応の欄を持たせ、 器が設計の変更の PR の CI・受付・実装後の検査の 3 か所で、 対応が揃っているかと歯が在るかを数えると決めます。 歯が約束を本当に確かめるかの判断は、 審査の係に残します。 外した実装でも動きの変わらない決まり (変えないと宣言した file を変えない・既存の枝を使うなど) は、 器の仕組みが確かめる 4 つに限って仕組みの名を書き、 それ以外は約束に載せません。 欄を知らない古い器は、 欄を持つ行が 1 本在るだけで表全体を読めなくなるので、 先に「欄を読むだけ」の版を着地させて器を入れ替えてから、 初めて欄を書きます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 5 つから説明します。 約束に歯が無い行が列に入り、 実装の前の審査で初めて落ちていたという経緯・手書きの行は対応の欄を持たず、 約束の行だけが持つという現物・器は言語に依らず、 歯の名の読み手は検証行の形ごとだという事情・決める範囲・憲法と既存の決定との向きです。

CTX1

経緯 — 約束に歯が無い行が列に入り、 便の中で初めて落ちる

2026-09-28 から 09-30 に起動した便 165 本の FAIL と判断不能の 76 件を 1 件ずつ根で分けると、 done の項目番号つきの約束に落ちる歯が無いか、 歯が判別しない型が 24 件だった。 うち 14 件は、 少なくとも 1 つの項目に歯が 1 本も無い形 (歯は在るが検証行に入っていない形を含む) で、 10 件は、 歯は在るが fixture が約束を外した実装を落とさない形 (空虚) だった。 14 件はどれも、 項目と歯の 1 対 1 の表を書けば起票の前に見える型で、 契約の審査の係 (lens) が材料だけで名指していた。 審査は列に入れた後の便の中に在るので、 落ちた行は列の外へ出て順番が崩れ、 1 周に 1 から 3 個の穴しか名指されないので同じ行が 2 から 4 周した。 設計 doc contract-source.md §64 (行 bs) は、 審査の係に項目ごとの歯の表を 1 周で全部書かせる形を足したが、 表を作るのは係なので、 器は表の歯が在るか・検証行が撃つかを照らせない。 その形が着地して最初の 2 便 (2026-09-30) は、 どちらも構造の制約 (子 module がほかの行の型を名指さない・置き場だけの file を変えない・既存の枝で起こし直す) を done に載せていて、 歯が無いと名指されて落ちた。 同じ型の約束を done に載せないと書いた前例 (設計 §44) は在るが、 規則にはなっていない。 そこで挙動に差が出ないと読んで done から外した直しの後、 同じ行の 2 本目の便は、 runner の子 module がほかの行の touches に在る型を名指して、 その行の閉包が write-set の外へ広がり、 gate の共通の検証の閉包の歯で落ちた。 型を名指さない約束は、 挙動に差の出ない制約ではなく、 器の閉包の検査が測る約束だった。 直しは、 便の木で契約表の検査を撃つ 1 行を検証行の最後に置いて約束の歯にした。

CTX2

現物 — 手書きの行は対応の欄を持たず、 約束の行だけが持つ

契約表の行の欄の正本は core の型 (18 欄) で、 done は 1 本の文字列である。 約束の行 (ADR-0051 §4) は約束 1 つごとに歯の完全名の列を必須で持つが、 手書きの行には項目と歯の対応の欄約束と歯の対応表が無い。 done の項目の読み手 (番号の印 (1) (2) で区切る 1 関数・設計 §64) と、 検証行から歯の名を解く読み手 (nextest の行の crate・scope・filter 語と、 歯の区間の test の fn の名) は既に在る。 表の検査は CI の nextest の歯が base 無しで撃ち、 base を持つ CI の job は PR のときだけの flip check の job である。 表の欄の key・契約 file の key・vessel 宣言の key はどれも閉じた列で、 未知の key を断る。 表では、 未知の key を持つ行が 1 本在るだけで、 その doc の区間が丸ごと読めなくなり、 表の検査は全部の doc の全部の行を読めないと名指し、 受付も全部の契約の材料を読めない。 宣言の未知の key では受付が全部の契約を断る。 gate の最初の段は write-set と約束の行の名を便の木で測る (設計 pipeline.md §58)。 着地の列が行の変化を見る鍵は、 生成した契約 file の sha で、 導出の write-set を含み、 行の欄の値の sha ではない。 設計 doc の契約表の行は 432 で、 done の字に番号の印 (1) を持つ行は 285、 持たない行は 143、 done の無い約束の行は 4 (2026-09-30)。 write-set の置き場だけの印 (=) の file は、 runner の allowlist に接頭辞を剥がして入り、 gate の最初の段も write-set の内と読むので、 中身を変えないという約束はどこでも測られていない。

CTX3

言語 — 器は言語に依らず、 歯の名の読み手は検証行の形ごと

器は限られた言語の集合 (Rust・TypeScript・型付きの Python など) の repo に対応し、 どれかの言語だけの仕組みを必須にしない。 検証行の形の読み手は今 nextest の形の 1 つだけで、 他の形 (別の言語の test の撃ち手・文書の検査・xtask の門) の行からは、 歯の名を 1 本ずつ解けない。 消費側の repo には、 隣の project の生成器が契約表を導出する形もあり、 欄を足す変更を消費側に一斉に求めると、 生成器が追いつくまで消費側の CI が落ちる。

CTX4

射程 — 行の欄と 3 か所の照らしを足し、 審査の判断と done の書き方は変えない

決めるのは、 (0) 欄を読むだけの版を先に着地させる順、 (1) 行の欄の形、 (2) 欄を持つ行に掛ける機械の照らしと掛ける所、 (3) 欄を求める行の範囲と消費側の名乗り、 (4) 契約 file と審査の材料への写し、 (5) gate の最初の段での歯の在りかの測り、 の 5 つ。 変えないのは、 done の 1 本の文字列と番号の書き方、 審査の係の表の倒し方 (設計 §64)、 約束の行の欄と導出、 write-set の導出、 flip check の判定、 検出線の歯の穴である。 実装の行は 5 本で、 欄を読むだけの行は要件書の字を変えずに先に起こし、 残る 4 行は要件書の round (FR47・FR55・FR4・FR20 の改訂と新しい要件) の後に起こす。 足す語のうち「歯」を含む 4 語は要件書の glossary に載せず (glossary の語は互いの部分文字列になれず、 「歯」は既存の語)、 要件の字では開いて書く。 ADR を書く条件のうち 3 (行の欄・契約 file の key・vessel 宣言の key の 3 つの跨版の形) と 4 (却下案を残す価値) に当たる。

CTX5

憲法と既存の決定の向き — 宣言の値・止める段・flip check・跨版の版

C1 は規則の値を manifest 1 つに置き、 C5 は rules 行に裁定 id を求める。 teeth-check は規則の値 (閾値や有効の旗) ではなく、 floor-check (ADR-0084) や ruling-check と同じく repo が器に名乗る宣言の値で、 置き場は vessel 宣言である (ADR-0010 が宣言を repo の名乗りとする読み)。 rules 行を足さないので C5 の裁定 id も要らない。 C16 は逸脱を編集の時に止め、 後の検証で代えないと定める。 欄の照らしは preflight と受付でも撃つが、 欄の要否 (変わった行に欄を求めること) は設計の PR の CI の段でだけ求める。 preflight と受付は main の先端の行を読むだけで、 起票の前の行が base から変わったかを持たず、 要否を出すには main の行と比べる読みを別に持つことになる。 設計の PR の CI は列に入れる前の最後の段で、 そこで止めれば列の後で落ちる周は無いので、 C16 の編集の時の止めを設計の PR の段の止めと読む。 C12.2 について、 flip check の判定 (歯ごとの base の RED を測らない) は変えない。 N4 について、 行の欄・契約 file の key・宣言の key を 1 つずつ足すだけで既存の値の意味を変えないので、 版は同じである (ADR-0004 §2.5 の、 任意の field を足すだけの変更は同じ schema 番号)。 ただし古い版の器は新しい key を読めないので、 読むだけの版を先に着地させて入れ替える。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 6 本のものさしです。 散文でなく器の門で止めること。 列に入れる前に止めること。 名指した歯を実装で守らせること。 言語に依らないこと。 着地済みの行と消費側を書き換えさせないこと。 仕組みを増やさず、 消す物を名指すことです。

DR1機械で塞ぐ — 約束に歯が無い行を、 散文の規律でなく器の門で止める (N2) CTX1
DR2列の前で止める — 設計の PR の段で止め、 便の中の審査に頼らない (C16) CTX1
DR3実装で守らせる — 名指した歯を runner が書き、 検証行が撃つことを gate で測る CTX2
DR4言語に依らない — 欄の文法は言語に依らず、 名の解きは検証行の形ごとの読み手に閉じる CTX3
DR5書き換えさせない — 着地済みの行・開いた行・消費側の表を、 名乗るか変わるまで今のまま通し、 古い版の器が表を読めなくなる周を作らない CTX2・CTX3・CTX5
DR6仕組みを増やさない — 既存の読み手と段を使い回し、 足す物の代わりに消す物を名指す (C17) CTX2
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 8 つ並べます。 行に対応の欄を足して器が 3 か所で数える案 (選んだ案) と、 選ばなかった 7 つです。 選ばなかった案は、 審査の係の表だけで持つ案・done を子行に割る案・全部の行に欄を求める案・今の行を一覧に凍らせて免除する案・動きの変わらない決まりにも字を数える歯を書かせる案・変わった行を着地の列の鍵で決める案・欄の読み手と照らしを一度に足す案です。

OPT1行の欄 done-teeth を足し、 器が 3 か所で照らす (要否は宣言の名乗りと base からの差分)採用

行に「<番号>:<歯>」の列の欄を足す。 歯は、 名 (検証行の読み手が選ぶ test の名)・既存の歯 (= を前に置く)・検証行の番号 (@k)・仕組みの名 (! を前に置く・器が測る構造の制約だけ) の 4 形。 表の検査と受付は、 番号が done の項目をちょうど覆い、 名が検証行に選ばれ、 既存の歯が base の 1 か所に在ることを照らす。 gate の最初の段は、 名の歯が便の木に在り base から動いたことを測る。 欄を求めるのは、 vessel 宣言が teeth-check を名乗った repo で、 base から足された行と done の字が変わった行だけ。 欄と key を書く前に、 読むだけの版を着地させて器を入れ替える。 決め手は分析 (欠けの型 14 件は表を書けば起票の前に見える)。

行に「約束の番号:歯」の列を足し、 器が 3 か所で数える案です。 歯は test の名、 変えない既存の歯 (前に = を置く)、 何本目の検証行か (@ と番号)、 器の仕組みの名 (前に ! を置く・動きの変わらない決まりだけ) の 4 つの書き方があります。 設計の変更の PR の CI と受付は、 全部の約束に歯が在り、 その歯を検証行が撃つかを数え、 実装後の検査は名指した歯が書かれたかを数えます。 欄を求めるのは、 名乗った repo で、 足した行と約束の字を変えた行だけです。 代わりに、 歯は在るが約束を確かめない空虚な形は塞がらず、 設計者は歯の名を先に決めることになります。

+ 利点

  • 約束に歯が無い行は、 設計の PR の CI で名指されて列に入らない (DR1・DR2)
  • 歯が検証行に選ばれず撃たれない形と、 runner が名指した歯を書かない形が機械で止まる (DR3)
  • 欄の文法は言語に依らず、 読み手の無い形の行も検証行の番号で書ける (DR4)
  • 着地済みの行と名乗らない消費側は、 変わるまで今のまま通る (DR5)
  • 項目の読み手・歯の名の読み手・gate の最初の段を使い回し、 監査の手順と係の自由な歯の名を消す (DR6)

− 欠点

  • 歯は在るが約束を外した実装を落とさない空虚の型 (分析の 10 件) は塞がらない
  • nextest でない形の repo は検証行の番号でしか書けず、 項目ごとの歯の在りかを測らない
  • CI の PR の job に step が 1 本増え、 器の binary を組む時間が足される
  • 行の字が増え、 設計者は歯の名を起票の時に決める (runner が名を選ぶ余地が無くなる)
OPT2審査の係の表だけで持つ (設計 §64 のまま)不採用

行に欄を足さず、 審査の係が項目ごとの歯の表を 1 周で全部書く形 (設計 §64) だけで持つ。 決め手は現物 (表を作るのは係で、 器は表の歯の在りかを照らせない)。

行に欄を足さず、 審査の係に約束ごとの歯の表を書かせる今の形だけで持つ案です。 足す欄も版を跨ぐ形も無く、 設計者の手間も今のままな点で勝ります。 けれども、 表を作るのは係なので、 係が材料に無い歯の名を書けばそのまま通り、 器は歯が在るかも検証行が撃つかも確かめられません。 確かめる所も列に入れた後に残り、 落ちた行が列の外へ出て順番が崩れます。

+ 利点

  • 足す欄も跨版の形も無い
  • 設計者の手間が今のまま

− 欠点

  • 係が歯の名を材料の外から書けば通り、 器は歯が在るか・検証行が撃つかを照らせない (DR1・DR3)
  • 照らす所が列に入れた後の便の中に残り、 落ちた行が列の外へ出る (DR2)
OPT3done を子行に割り、 項目ごとに歯の欄を持つ不採用

done の番号つきの項目を、 約束の行と同じ形の子行 (項目の文と歯の列) に割る。 決め手は分析 (書き換えの量と型の数)。

done の約束を、 約束の行と同じ形の子行に割り、 子行ごとに歯を持たせる案です。 約束と歯が 1 つの子行に並んで読みやすく、 番号の印の字面に頼らない点で勝ります。 けれども、 番号つきの done を持つ 285 行を書き換えるか、 2 つの形を並べて持つことになり、 約束の行と並ぶ 2 つ目の子行の型が増えて、 表の読みと検査が 2 通りになります。

+ 利点

  • 項目と歯が 1 つの子行に並び、 読みやすい
  • 項目の区切りを番号の印の字面に頼らない

− 欠点

  • 番号つきの done を持つ 285 行の書き換えか、 2 つの形の併存が要る (DR5)
  • 約束の行と並ぶ 2 つ目の子行の型が増え、 表の読みと検査が 2 通りになる (DR6)
OPT4全部の行に欄を求める不採用

欄を必須にし、 表の検査が全行に求める。 決め手は分析 (着地済みの行の書き換え)。

欄を必須にして、 全部の行に求める案です。 比べる相手の base が要らず、 どの経路でも同じに求められ、 欄の無い行が残らない点で勝ります。 けれども、 着地済みの行と開いた行を全部書き換えるまで CI が落ち、 名乗っていない消費側の repo の表も一斉に落ちます。

+ 利点

  • base が要らず、 どの経路の検査でも同じに求められる
  • 欄の無い行が 1 本も残らない

− 欠点

  • 着地済みの行と開いた行を全部書き換えるまで CI が落ちる (DR5)
  • 名乗っていない消費側の表も一斉に落ちる (DR4・DR5)
OPT5欄を持たない行の sha を tracked な一覧に凍らせて免除する不採用

今の行の done の字の sha を一覧に書いて免除し、 一覧に無い行と sha が変わった行に欄を求める。 決め手は分析 (base からの差分で同じ免除を言える)。

今の行の約束の字の指紋 (sha) を一覧に書いて免除し、 一覧に無い行と指紋が変わった行に欄を求める案です。 base が要らず、 受付でも求められる点で勝ります。 けれども、 行の数だけの一覧と、 古い項目を減らしていく運用を持つことになり、 消費側は名乗るたびに一覧を作る口が要ります。 変わった行は base との差分でも同じに見分けられます。

+ 利点

  • base が要らず、 受付でも要否を求められる
  • 変わった行を base 無しで見分けられる

− 欠点

  • 行の数だけの一覧と、 古い項目を減らす運用を持つ (DR6)
  • 消費側は名乗るたびに一覧を作る口が要る (DR5)
OPT6構造の制約にも落ちる歯を書かせる不採用

file を変えない・既存の枝で起こし直すなどの構造の制約にも、 字面を数える歯を書かせて done に残す。 決め手は分析 (字面を数える検証は repo の規則が禁じ、 観測の変わらない約束は落ちる歯を持てない)。

変えないと宣言した file を変えない・既存の枝を使う、 といった動きの変わらない決まりにも、 字を数える歯を書かせて約束に残す案です。 約束の種類を分けずに済み、 全部の約束が同じ形の歯を持つ点で勝ります。 けれども、 字を数える検証はこの repo の規則が禁じていて、 動きでなく字を確かめる歯になります。 器の仕組みが既に確かめている決まりを、 歯でもう 1 度確かめることにもなります。

+ 利点

  • done の項目の種類を分けずに済む
  • 全部の項目が同じ形の歯を持つ

− 欠点

  • 字面を数える検証 (grep の pin) は repo の規則が禁じ、 挙動の歯でなく字の歯になる (DR1)
  • 器の仕組みが既に測る制約を歯で二重に測る (DR6)
OPT7変わった行を着地の列の鍵 (生成した契約 file の sha) で決める不採用

欄を求める変わった行を、 着地の列が既に持つ鍵 (生成した契約 file の sha) が base と違う行とする。 決め手は現物 (鍵は導出の write-set を含み、 depends などを含まない)。

欄を求める「変わった行」を、 着地の列が既に持つ鍵 (生成した契約の file の指紋) が base と違う行とする案です。 新しい比べ方を足さずに既存の鍵を使い回せ、 着地の列と判断が揃う点で勝ります。 けれども、 その鍵は器が導いた置き場の列を含むので、 code を変える PR だけで字の同じ着地済みの行まで変わった行になり、 欄の後付けを強います。 逆に依存の欄などだけを変えた行は変わった行に数えず、 約束を変えた行と数がずれます。

+ 利点

  • 新しい比べの読みを足さず、 既存の鍵を使い回せる
  • 着地の列と同じ読みで、 変わったかの判断が 1 つに揃う

− 欠点

  • code を変える PR で導出の write-set が動くと、 字の同じ着地済みの行まで変わった行になり、 欄の後付けを強いる (DR5)
  • depends などだけを変えた行は変わった行に数えず、 done を変えた行と母集団がずれる (DR1)
OPT8欄の読み手と照らしを 1 つの版で一度に足す不採用

欄を読むだけの版を置かず、 欄の読み手・照らし・写しを 1 つの行で足し、 その行が自分の欄を持つ。 決め手は現物 (未知の key を持つ行が 1 本在ると、 古い版の器は表の区間を丸ごと読めない)。

欄を読むだけの版を置かず、 欄の読み手と照らしと写しを 1 つの版で一度に足す案です。 行と器の入れ替えが 1 回少なく、 読みと照らしが同じ版で揃う点で勝ります。 けれども、 欄を持つ行を足す設計の PR の時点では、 main の code も手元の器も欄を知らず、 知らない欄を持つ行が 1 本在るだけで表の検査が全部の行を読めないと名指し、 受付も止まります。 vessel 宣言の key も同じで、 key を書いた時から入れ替えまで受付が全部断ります。

+ 利点

  • 行と入れ替えの回数が 1 つ少ない
  • 欄の読みと照らしが同じ版で揃う

− 欠点

  • 欄を持つ行を足す設計の PR の時点で main の code と PATH の器が欄を知らず、 表の検査が全部の行を読めないと名指し、 受付が止まる (DR5)
  • 宣言の key も同じで、 key を書いた周から入れ替えまで受付が全部断る (DR5)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 行は約束の番号ごとに歯を名指し、 器は表の検査と受付で対応の揃いと歯の在りかを、 実装後の検査の最初の段で歯が書かれたかを数えます。 欄を求めるのは、 名乗った repo で、 足した行と約束の字を変えた行だけです。 欄を書く前に、 欄を読むだけの版を着地させて器を入れ替えます。 動きの変わらない決まりは、 器の仕組みの名を書くか約束に載せず、 変えないと宣言した file は実装の時と検査で守らせます。

採用 — OPT1

器 SHALL 契約表の行に任意の欄 done-teeth (文字列の列) を持つ。 要素は「<番号>:<歯>」で、 番号は done の番号つき項目の番号、 歯は名 (その行の検証行の読み手が選ぶ test の名)・既存の歯 (= を前に置き、 base に在り本文を変えない歯)・検証行の番号 (@k・k 本目の検証行の全体)・仕組みの名 (! を前に置き、 閉じた 4 語 write-set・place-only・new-file・closure のどれか) の 4 形のどれか 1 つ。 外した実装で観測が変わる挙動の約束は落ちる歯を持ち、 観測の変わらない構造の制約は 4 つの仕組みが測るものに限って仕組みの名を書き、 それ以外の構造の制約は done に載せない (種類の判じは審査の係が持つ)。 Promised の行と番号つきの項目を持たない行は欄を持てない。 器 SHALL 欄と vessel 宣言の任意 key teeth-check を main に初めて書く前に、 表・契約 file・宣言がその欄と key を読んで効かせない版を着地させ、 PATH の器をその版へ入れ替える。 器 SHALL 欄を持つ行に、 表の検査・受付・preflight の同じ 1 関数で、 要素の形 (4 形)、 番号の集合が項目の 1 から K とちょうど等しいこと、 @k が検証行の本数の内、 名と既存の歯が読み手の在る形の検証行の 1 本に選ばれること、 仕組みの名が 4 語の内で測る物 (closure なら便の木で表の検査を撃つ検証行) を行が持つことを照らし、 base を持つ周 (base を渡した表の検査の変わった行・受付・preflight) では既存の歯が base の選ぶ行の crate と scope の歯の区間にちょうど 1 つ在り、 base に在る名が 1 か所に定まることも照らし、 外れを全件・行番号つきで名指して断る。 器 SHALL teeth-check が true の repo で、 表の検査に base の commit が渡された周だけ、 変わった行 (base の同じ doc に同じ id の行が無い行と、 done の字が base と違う行・Promised の行を除く) に、 番号つきの項目と欄を持つことを求める。 比べるのは表の行の done の字で、 生成した契約 file の sha ではなく、 done 以外の欄だけを変えた行には求めない。 base の無い周と受付は要否を求めない。 本 repo は teeth-check を true と名乗り、 CI は PR のときだけの job で base を渡して表の検査を撃つ。 器 SHALL 受付の生成で欄を契約 file の任意 key へ写し、 欄を持つ契約だけ審査と gate の係に渡す契約の字に欄を載せる。 器 SHALL 欄を持つ便の gate の最初の段で、 名の歯が便の木の選ぶ行の歯の区間にちょうど 1 つ在り、 base に無いか本文が base と違うこと、 既存の歯が同じ区間に 1 つ在ることを測り、 外れた歯を名指して段を落とす (新しい段も理由の型も足さない)。 器 SHALL write-set の置き場だけの印 (=) の file を runner の allowlist から外し、 gate の最初の段で diff に在る = の file を名指して落とす (欄の有無に依らない)。 審査の係の項目ごとの表 (設計 §64) は、 欄を持つ行では宣言の歯の中から選ばせ、 外の歯を形の合わない項目に数える。 歯が約束を本当に測るかは器が測らず、 審査の係と検出線に残す。 消すのは、 起票の前に席が回す done と歯の監査の手順と、 係が材料の外から歯の名を書く余地。 実装は設計 doc contract-source.md §66 の 5 行で、 読むだけの行は要件書の字を変えずに先に起こし、 残る 4 行は要件書の round の後に、 読むだけの行の入れ替えの後で起こす。

器は、 契約表の行に任意の欄 done-teeth を持ちます。 要素は「約束の番号:歯」で、 歯は test の名・前に = を置いた変えない既存の歯・何本目の検証行かを表す @ と番号、 ・前に ! を置いた器の仕組みの名、 の 4 つの書き方のどれかです。 仕組みの名は write-set・place-only・new-file・closure の 4 つだけで、 動きの変わらない決まりにだけ書きます。 約束の行を持つ行と、 番号つきの約束を持たない行は欄を持てません。 欄を持つ行には、 表の検査と受付と事前の確かめが同じ 1 つの関数で、 形が読めること・番号が約束の全部をちょうど覆うこと・番号の検証行が在ること・名の歯を検証行が撃つこと・仕組みの名が 4 つの内で確かめる物を行が持つことを確かめ、 base の在る周では既存の歯が base の 1 か所に在ることも確かめて、 外れを全部名指して断ります。 欄を求めるのは、 vessel 宣言で teeth-check を名乗った repo で、 表の検査に base が渡された周の、 base に無い行と約束の字が base と違う行だけです。 比べるのは表の行の約束の字で、 置き場の列などだけを変えた行には求めません。 本 repo は名乗り、 CI は PR のときだけ base を渡して撃ちます。 受付は欄を契約の file に写し、 欄を持つ契約だけ、 審査と実装後の検査の係に渡る契約の字にも載せます。 実装後の検査の最初の段は、 名の歯が便の木に 1 つ在って base から足されたか変わったこと、 既存の歯が残っていることを測ります。 変えないと宣言した file (= の印) は、 実装役が書ける file の列から外し、 検査の最初の段でも変わっていれば落とします。 審査の係の表は、 宣言した歯の中から選ばせます。 欄と teeth-check を初めて書く前に、 それを読むだけで効かせない版を着地させ、 器をその版へ入れ替えます。 行に欄を選んだのは、 歯の無い約束の型が、 約束と歯の対応を書けば起票の前に見える型で、 数えるのは機械でできるからです。 審査の係の表だけで持つ案は、 器が歯の在りかを確かめられず、 確かめる所が列の後に残るので退けました。 子行に割る案は書き換えと型が増え、 全部の行に求める案は着地済みの行と消費側を一斉に落とすので退けました。 一覧で免除する案は、 base との差分で同じ免除が言えるのに運用の一覧を増やすので退けました。 着地の列の鍵で変わった行を決める案は、 その鍵が導出した置き場の列を含み、 code の変更だけで字の同じ着地済みの行まで変わった行になるので退け、 約束の字が変わった行に絞りました。 欄の読み手と照らしを一度に足す案は、 欄を持つ行を書いた時点で古い器が表全体を読めなくなるので退け、 読むだけの版を先に入れ替える順にしました。 要否を名乗りと差分にしたのは、 変わる行から順に新しい形へ移し、 名乗らない消費側を壊さないためです。 歯の名を検証行が撃つかまで確かめるのは、 歯が在っても検証行に入っていなければ撃たれないからで、 実装後に歯が書かれたかを測るのは、 検証行は名指した歯が無くても他の歯で緑になりうるからです。 歯が約束を本当に確かめるかを器が判じないのは、 それが意味の判断で、 機械の数えでは言えないからです。 動きの変わらない決まりを仕組みの名か約束の外に分けたのは、 外した実装でも動きが変わらない約束は落ちる歯を持てず、 字を数える歯はこの repo の規則が禁じるからです。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR47claimFR47 は契約の正本を設計 doc の契約表の 1 行に置き、 行が少なくとも持つ欄を決める。 本 ADR は、 行が done の項目ごとの歯の対応を任意の欄で持てると主張する (欄を名指す字は要件書の round で FR47 に足す)。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 5 つと、 代わりに引き受けること 7 つです。 良くなるのは、 歯の無い約束が列に入らないこと、 撃たれない歯と書かれない歯が止まること、 審査の係が歯の名を作らなくなること、 名乗らない側が今のまま通ること、 動きの変わらない決まりで落ちる周が無くなることです。 引き受けるのは、 空虚な歯は塞がらないこと、 読み手の無い形は番号でしか書けないこと、 CI が少し延びること、 設計者の手間が増えること、 古い版の器が欄を持つ表を読めないので入れ替えの順を守ること、 base の無い経路では求めないこと、 約束の種類の見分けは審査の係に頼ることです。

✓ 良い結果

  • ●約束に歯が無い行は、 設計の PR の CI で名指され、 列に入らない
  • ●名指した歯が検証行に選ばれない形と、 runner が名指した歯を書かない形は、 機械で止まる
  • ●審査の係は歯の名を作らず、 宣言の歯が約束を測るかだけを判じる
  • ●名乗らない消費側の repo と着地済みの行は、 名乗るまで・変わるまで今のまま通る
  • ●観測の変わらない構造の制約は、 仕組みの名か done の外かの 2 つに閉じ、 歯の無い項目として落ちる周が無くなる。 置き場だけの file の不変も、 編集の時と gate で測られる

⚖ トレードオフ・代償

  • ●歯は在るが約束を外した実装を落とさない空虚の型は塞がらない (審査の係と検出線のまま)
  • ●nextest でない形の repo は検証行の番号でしか書けず、 項目ごとの歯の在りかを測らない
  • ●CI の PR の job に step が 1 本増え、 器の binary を組む時間が足される
  • ●行の字が増え、 設計者は歯の名を起票の時に決める
  • ●読むだけの版より古い器は、 欄を持つ行を含む表の区間と teeth-check を持つ宣言を丸ごと読めない。 読むだけの版を先に着地させて入れ替える順で避け、 入れ替えは前へだけ
  • ●base の無い経路では要否を求めない (merge の門と main の出所の門がその経路を閉じている前提)
  • ●項目が挙動の約束か構造の制約かは器が判じない。 挙動の約束に仕組みの名だけを書いた行は、 審査の係が見つけて初めて落ちる
