設計判断記録 (ADR) scribe2 — 判断の置き場

pipeline の判断は「計算できる判断は code・意味の判断は lens・裁定は人」の 3 分類に置き、 Jev は挿さず (再検討は記録が揃った後の shadow 計測で)、 検出線の 2 段化は足さない (分解表の 5 論点の裁定)

便が受付から着地まで通る判断を 19 本に割り、 誰が決めるべきかを code / lens (LLM) / 人 の 3 つに仕分けた。 審査で落ちた 104 便の 87% は計算できる性質で、 約束の行の生成 (ADR-0051) で code へ移る。 較正された確率を返す判定 API (Jev) は、 5 つの候補のうち実測した 4 つのどれにも今は挿す理由が無く、 残る 1 つは正解を機械で取れるが未計測である。 本 ADR はその置き場と、 再検討の条件と、 検出線を 1 段のまま保つことを決める。

この判断が約束すること (1 文サマリ)

便が受付から着地まで通る間に、 器は 19 の判断をします。 その 1 つ 1 つを「計算で決まるもの」「文章の意味を読まないと決まらないもの」「人が決めるべきもの」に分けました。 審査で落ちた便 104 本を数えると、 87% は計算で決まる性質で落ちていて、 それは約束の行から write-set と検証と done を機械で作る仕組み (ADR-0051) で消えます。 文章の意味を読む判断は歯の空虚さ・目標の矛盾・その他の 3 値に閉じ、 そこは今までどおり審査役 (lens) が担います。 較正された確率を返す判定 API (Jev) は、 5 つの候補のうち 4 つを実測し (残る 1 つは正解を機械で取れますが未計測です)、 今は挿す理由が無いと決めました。 再検討は、 便ごとの時間と token の記録と、 審査役の答えの種別 (3 値) が着地して指摘 1 件ごとの記録が取れる形になった後に、 横で答えを出して正解と突き合わせる測り方 (shadow 計測) で 30 件以上集めてから行います。 変異検査も、 契約の歯と単体の歯だけの 1 段のままにします。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 実測と現物から説明します。 審査で落ちた 104 便の 87% は計算で決まる性質でした。 判定 API を 5 つの候補のうち 4 つに当てた実測では、 正規表現や字面の規則で足りるものと、 比べる基準線が無いものと、 分離できないものと、 母集団が小さすぎるものしかなく、 残る 1 つは未計測です。 変異検査は 1 段に閉じて gate 1 本が 4 分の桁になり、 lens の指摘 1 件ごとの記録と便ごとの費用の記録はまだ在りません。

CTX1

実測 — 審査で落ちる理由の 87% は計算できる性質

run dir の残る全便 (2026-09-21 実測) で審査 (lens) が FAIL か INCONCLUSIVE に倒れた 104 便の内訳は、 write-set の閉包 51・名指しの不在 17・done と約束の 1:1 の崩れ 11・verify の filter 11・snapshot の名 1・歯の空虚 5・その他 8 (goal の矛盾を含む) である。 前の 5 つ (91 便・87%) は契約の行から機械で導ける性質で、 lens の意味の判断が要るのは歯の空虚 5 とその他 8 の 13 便 (13%) だけだった。 直近 7 日は run 302 本で bead 123 本・着地 46 bead、 bead あたりの便は 1 本 39・2 本 35・3 本以上 49 で、 起こし直しの大半がこの 87% から来る。

CTX2

実測 — 判定 API (Jev) を 5 つの候補に当てた結果

RESEARCH-jev (2026-09-18・追補 09-19・正解つき 87 件を日英 3 回ずつの 261 回・§3.1 の shadow 156 回・呼出の総計 444 回・総費用約 $0.10) を分解表の判断に当て直した。 (a) 契約の形 (pointer だけか本文か・q1) は正規表現 1 本で 30/30 と同点。 (c) gate の指摘の種別と重さの仕分け (q2) は Jev が 22/27 で、 比較の基準線は無い (現物に finding 単位の記録が無い)。 (d) 便の結末を着地 / 差し戻し / 人へ上げるの 3 値で決める問い (q3) は Jev が 26/30 で lens の判定語の規則 (28/30) を下回り、 契約側を直すべき 2 件のうち 1 件は 3/3 で当てた (確率 0.76〜0.85) が母集団が小さい。 (e) CI が赤いとき flaky か回帰かは Jev で分離しない (閾値 0.5 で flaky 1/9・0.3 で 6/9 と誤検出 17/29)。 (b) 歯の空虚性は正解 (検出線の生存行) を機械で取れるが未計測。 性質としては段 1〜3 の 261 回で確率 0.9 以上が 422/422 的中・p50 527 ms・失敗 0/444・1 回約 $0.00005 で、 docs は CJK が同等でないこと・多段推論に弱いこと・state 内の文が判定を動かすこと・「code で計算できることを聞くな」を自ら明記する。 研究は当てない問いを 2 つ (CI の flaky / 回帰・runner の問いの宛先) と、 挿す周は state を機械が作った field に限ることを記す。

CTX3

現物 — 検出線と lens の現在値

検出線 (変異検査) は ADR-0052 で契約が名指した歯と package の単体の歯に閉じ、 着地後の実測 2 周は 157 秒 / 66 mutants と 161 秒 / 78 mutants (gate 1 本 4 分の桁)。 生存を止める rules 行 R-C12-1 は enabled = false で、 生存は週次記録と審査役の材料である。 lens は審査 (契約の適合・歯の非空虚性) と gate の diff review の 2 か所で走り、 便ごとの時間と token はまだ記録に無い (契約 s2-07l.462・未着地)。 lens の verdict は finding 単位の record を持たず、 約束の行の審査 (contract-source.md §33 行 ah) が verdict の kind を 3 値 (歯の空虚・goal の矛盾・その他) に限る形は未着地である (行 ah が着地しても kind は verdict 1 つに 1 語で、 finding 単位の記録はまだ無い)。

CTX4

user の裁定 — 分解表の 5 論点を推奨どおり

席は 19 本の判断を code / Jev / lens / 人 に仕分けた分解表と grill の 5 論点 (G1 検出線の 2 段化・G2 終端の通知・G3 Jev の置き場・G4 dispatcher の正帰還・G5 重複の契約) を推奨つきで提示し、 user は 5 論点を推奨どおり進める裁定をした (逐語は台帳 s2-07l.505 の notes)。 本 ADR が記録するのは G1 と G3 (判断の置き場誰が決めるかの割り当てそのもの) で、 G2 と G4 は設計 doc dispatcher.md §17〜§19 の契約の行に、 G5 は台帳の close に写した。

CTX5

憲法の向き

憲法は、 宣言値と測定値と実効値を型で分け測定なしに実効へ上げないこと (C10)、 変異の生存の記録と deny への昇格は user の裁定でだけ行うこと (C12.4)、 足す前に「要るか・既に在るか・標準か既存の依存で足りるか」の段を通ること (C17)、 依存 OSS や外部 service の増減は先に裁定 id を取ること (A3) を求める。 判定 API を挿すのは依存の増加 (A3) であり、 その材料は記録から取った数字でなければならない (C10)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 計算できる判断を model に聞かないこと、 依存を足す前に正解と費用を機械で取れる記録を揃えること、 gate 1 本を数分の桁に保つこと、 そして「保留」のまま置いた研究を数字で決定に変えることです。

DR1判断の置き場は「計算できるか」で決め、 計算できる判断を model (lens も Jev も) に聞かない CTX1 (87% が計算できる)・CTX2 (docs が自ら「code で計算できることを聞くな」)・憲法 C17
DR2依存を足す前に、 正解と費用を機械で取れる記録を先に揃える CTX2 (q2 に基準線が無い)・CTX3 (時間・token・finding 単位の record が未着地)・憲法 C10 / A3
DR3gate 1 本を数分の桁に保つ (検出線の費用を再び数十分に戻さない) CTX3 (実測 2 周)・ADR-0052・裁定 (CTX4 の G1)
DR4決めない研究 (RESEARCH-jev) の「保留」を、 数字を根拠に決定へ変える CTX2・研究の再検討条件・憲法 C10
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 判断を 3 分類に置いて判定 API は挿さない案、 判定 API を gate の指摘の重さの仕分けに挿す案、 人へ上げるべきかの判断に挿す案、 変異検査を 2 段にする案、 そして審査役をまるごと判定 API に置き換える案です。

OPT1判断を 3 分類に置き、 Jev は挿さず、 検出線は 1 段のまま採用

計算できる判断 (write-set の閉包・名指しの実在・done と verify の生成・枠・列・着地) は code に置き、 意味の判断 (歯の空虚・goal の矛盾・その他の 3 値) だけを lens に残し、 裁定 (消す・出す・使う・閾値・依存) は人に置く。 Jev は 5 候補のどれにも今は挿さない。 便ごとの時間と token の記録と、 verdict の kind の 3 値 (行 ah) が着地して finding 単位の記録が取れる形になった後に、 歯の空虚性と escalate の 2 候補を shadow で N ≥ 30 測り、 その数字で別の ADR を書く。 検出線は契約の歯と単体の歯の 1 段のままとし、 生存分に全 suite を当てる 2 段目は足さない。

判断を「計算で決まる」「意味を読む」「人が決める」の 3 つに分け、 計算で決まるものは全部 code に置く案です。 審査役に残るのは歯の空虚さ・目標の矛盾・その他の 3 値で、 判定 API は今は挿しません。 便ごとの時間と token の記録と、 審査役の答えの種別が着地して指摘 1 件ごとの記録が取れる形になったら、 横で答えを出して正解と突き合わせる測り方で 30 件以上集め、 その数字で改めて決めます。 変異検査は契約の歯と単体の歯だけの 1 段のままです。

+ 利点

  • 審査落ちの 87% が約束の行の生成 (ADR-0051) で消え、 lens の判断は 13% 分に絞られる
  • 依存は 0 のまま (A3 の裁定を今は要さない)・gate は 4 分の桁を保つ
  • 再検討の条件が記録の着地 (契約 2 本) という機械で確かめられる形で決まる
  • 研究の「保留」が「挿さない (条件つき)」の決定になり、 席が同じ検討を繰り返さない

− 欠点

  • lens が残す 13% 分の判断の質は測れないままである (finding 単位の record が無い)
  • escalate の判断は runner の問い → 席の turn 待ちのままで、 席が居ない時間は詰まる (通知の口は dispatcher.md §19 の別の契約)
  • 契約が名指さない e2e の歯だけが捕まえる mutant は生存として記録に残るだけ (ADR-0052 CSQ-N1 のまま)
OPT2Jev を gate FAIL の重さの仕分け (severity) に今挿す不採用

gate の lens の findings を Jev に渡し、 重さ (止める / 記録だけ) を確率つきで仕分ける。

gate の審査役が出した指摘の種別と重さを判定 API に仕分けさせる案です。 実測は 27 件中 22 件の一致で、 比べる基準線がありません (指摘 1 件ごとの記録が現物に無いので、 規則との優劣も確率が当てになるかも運用で確かめられません)。 重さの段も研究側が仮に決めたもので器の記録の語ではなく、 依存が 1 つ増えるのに消える判断が無いので採りません。

+ 利点

  • 仕分けが確率つきの型で返り、 閾値を rules 行に置ける

− 欠点

  • 実測 (q2) は 22/27 で、 比較の基準線が無い (現物に finding 単位の記録が無く、 規則との優劣も較正も運用で確かめられない)
  • 重さの段 (0 形式の逸脱 / 1 検査の穴 / 2 挙動の欠陥) は研究の spike が定義したもので、 器の record の語ではない
  • 依存が 1 つ増える (A3) のに、 それで消える判断が無い
OPT3Jev を「人へ上げるべきか」(escalate) に今挿す不採用

runner の問いを Jev に渡し、 席へ上げるか契約を直すかを確率で決める。

実装役の問いを「人へ上げるべきか」判定 API に決めさせる案です。 便の結末を 3 値で決める問いでは審査役の判定語を字面で読む規則の方が当たり (28/30 対 26/30)、 契約側を直すべき 1 件は 3 回とも当てましたが正解つきの母集団は 2 件しか無く、 問いの大半 (19 件中 16 件) は write-set の問いで約束の行の仕組みが消す側です。 残る問いの形が着地後にしか分からないので、 今は採りません。

+ 利点

  • 実測で 1 件を 3/3 で当てた (確率 0.76〜0.85)
  • 席の turn 待ちが減る可能性がある

− 欠点

  • 便の結末の 3 値 (q3) は Jev 26/30 で lens の判定語の規則 28/30 を下回った (規則で足りる)
  • 正解つきの母集団が 2 件で、 問いの 19 件中 16 件は write-set の問い＝ADR-0051 の行 ag で消える側。 残る母集団の形が着地後にしか分からない
  • 問いの本文 (state) が判定を動かす API に、 runner の自由文を渡す形になる (docs が明記する注入の弱点)
OPT4検出線を 2 段にする (契約の歯を先に・生存分だけ全 suite)不採用

ADR-0052 の 1 段目で生き残った mutant にだけ package の全 suite (e2e 込み) を当て、 生存を実態に近づける。

変異検査を 2 段にして、 1 段目で生き残った mutant にだけ package の test を全部当てる案です。 生存の数は実態に近づきますが、 生存 1 本ごとに数十秒から数分が戻って gate 1 本が再び数十分になりえます。 生存は今は記録と審査役の材料であって gate を落とす線ではないので、 近づけた値の使い道もまだ無く、 裁定も足さない側でした。

+ 利点

  • 契約が名指さない e2e の歯が捕まえる mutant を生存に数えなくなる (記録の生存が減る)

− 欠点

  • 生存 1 本あたり全 suite 1 回 (e2e 込みで数十秒〜数分) が戻り、 gate 1 本が再び数十分になりうる (DR3 に反する)
  • 生存は記録と審査役の材料であって gate を落とす線ではない (R-C12-1 無効・C12.4)＝実態に近づける値の使い道が今は無い
  • 裁定 (G1) は足さない側
OPT5lens (LLM) の判断を全面的に Jev に置き換える不採用

審査と gate の review を Jev の型のある判定に置き換え、 LLM を pipeline から外す。

審査役 (LLM) をまるごと判定 API に置き換える案です。 速くて安くて揺れませんが、 残る判断は文章の意味を読む判断で、 判定 API の説明書自身が多段の推論と日本語を弱点に挙げています。 契約も設計も日本語で書かれていて、 日英差は 30 件の実測では見えていない (根拠にも反証にもならない) ので採りません。

+ 利点

  • 判定が速く (p50 約 0.5 秒)・安く (1 回約 $0.00005)・揺れない

− 欠点

  • 残る判断 (歯の空虚・goal の矛盾) は文章の意味の判断で、 Jev の docs 自身が多段推論と CJK を弱点に挙げる
  • 契約も設計 doc も日本語で、 日英差の実測は N=30 では見えていない
  • 正解を後から取れるのは歯の空虚だけで、 goal の矛盾は較正の正解が無い
  • 日英差の実測は N = 30 では見えておらず、 置き換えの根拠にも反証にもならない
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 計算できる判断は code、 意味の判断は lens、 裁定は人に置きます。 判定 API は挿さず、 再検討の条件を記録の着地と shadow 計測の件数で決めます。 変異検査は 1 段のままです。

採用 — OPT1

pipeline の判断の置き場 SHALL 分解表の 3 分類とし、 計算できる判断 (write-set の閉包・名指しの実在・done と verify の生成・受付の枠・列の順序・着地の列) SHALL code に置き、 意味の判断 (歯の空虚・goal の矛盾・その他) SHALL lens に置き、 裁定 (消す・出す・使う・閾値・依存) SHALL 人に置く。 lens の verdict の語彙 SHALL 約束の行の審査 (ADR-0051・contract-source.md §33 行 ah) の 3 値に限る。 器 SHALL NOT 判定 API (Jev) を pipeline の判断に挿さない (依存は 0 のまま・A3 の裁定を本 ADR は求めない)。 Jev の再検討 SHALL 便ごとの時間と token の記録 (gate-cost.md 行 r) と verdict の kind の 3 値 (行 ah) が着地して finding 単位の記録が機械で取れる形になった後に、 歯の空虚性と「人へ上げるべきか」の 2 候補を正解つきで N ≥ 30 の shadow 計測本番には効かせず横で測るで測り、 その数字を根拠に別の ADR で決める。 研究が当てないと決めた 2 つの問い (CI の flaky / 回帰・runner の問いの宛先) SHALL NOT 候補に戻さず、 挿す周の state SHALL 機械が作った field に限る。 検出線 SHALL ADR-0052 の 1 段 (契約が名指した歯と package の単体の歯) のままとし、 器 SHALL NOT 生存分に全 suite を当てる 2 段目を足さない (再考は生存が裁定の材料になった時・R-C12-1 の週次記録 2 周分)。 分解表の他の 3 論点 (終端の通知・dispatcher の正帰還・重複の契約) SHALL 設計 doc dispatcher.md §17〜§19 の契約の行と台帳の close で持ち、 本 ADR は再掲しない。

便の判断は 3 つに分けて置きます。 write-set の閉包や名指しの実在、 検証と done の生成、 受付の枠、 列の順序、 着地の列のような計算で決まる判断は code に置きます。 歯の空虚さや目標の矛盾のような意味の判断は審査役 (lens) に置き、 審査役の答えの語彙は約束の行の審査で決めた 3 値に限ります。 消す・出す・使う・閾値・依存の裁定は人に置きます。 判定 API (Jev) は pipeline の判断に挿しません (依存は 0 のまま)。 再検討するのは、 便ごとの時間と token の記録と、 審査役の答えの種別 (3 値) が着地して指摘 1 件ごとの記録が機械で取れる形になった後に、 歯の空虚さと「人へ上げるべきか」の 2 候補を正解つきで 30 件以上、 横で答えを出して突き合わせてからで、 その数字で別の記録として決めます。 研究が当てないと決めた 2 つの問い (CI の flaky か回帰か・実装役の問いの宛先) は候補に戻さず、 挿すときも判定 API に渡す材料は機械が作った欄に限ります。 変異検査は契約の歯と単体の歯だけの 1 段のままにし、 生き残った mutant に全部の test を当てる 2 段目は足しません。 通知の口や dispatcher の直しや重複の契約は設計 doc と台帳の側で持ち、 ここには書きません。 落ちた便の 87% が計算で決まる性質だったのですから、 まず計算できる判断を code に置くのが順序です。 model に聞くのは意味の判断だけにすれば、 審査役の仕事は 13% 分に絞られます。 判定 API を挿さないのは、 実測で挿す理由が 1 つも出なかったからです。 規則で足りるもの、 比べる基準線が無いもの、 分離しないもの、 母集団が小さすぎるもの、 未計測のものしか無く、 依存を 1 つ増やす裁定を求める数字がありません。 再検討の条件を記録の着地と件数で決めたのは、 次に検討するときに同じ議論を繰り返さず、 数字だけで判断できるようにするためです。 変異検査を 1 段のままにするのは、 gate 1 本を数分の桁に保つためで、 生存は今は記録と材料であって落とす線ではないからです。
