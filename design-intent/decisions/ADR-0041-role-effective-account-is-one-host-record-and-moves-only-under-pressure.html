設計判断記録 (ADR) scribe2 — 役割の実効の口座

役割の実効の口座は host の根の記録 1 件が持ち、 逼迫した周にだけ余裕が最大の口座へ役割ごと移る (宣言は初期値の種で宣言へは戻らない・候補が無い周も妥協の口座で席を立てて user の裁定を待つ・consult は planner の口座を読む・ADR-0036 の DR3 を supersede)

役割の席が実際に使う口座を、 host の根の実効の記録 (役割ごとに高々 1 件・器が書く) が持つ。 記録の口座が使える間は居続け、 宣言の口座に余裕が戻っても戻らない。 記録が無い周は宣言を種にし、 記録の口座が逼迫した周にだけ役割単位で 1 回、 余裕が最大の口座を選び直す。 閾値未満の候補が無い周も断らず、 妥協の口座で席を立てて理由を記録と席の指示文に出す。

この判断が約束すること (1 文サマリ)

役割の席が使う口座は、host に 1 か所だけ在る記録が決めます。同じ役割の席はどの project からでもその記録を読んで同じ口座を使い、その口座が逼迫したときにだけ、役割ごとまとめて余裕が最大の口座へ移ります。宣言の口座は最初の 1 回の種で、余裕が戻っても戻りません。使える口座が見つからないときも席は必ず立て、その旨を席に知らせて user の裁定を待たせます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、現物と user の裁定から説明します。いまは宣言の口座が使えない周に、席が 1 つずつ別々に移り先を選びます。その結果、同じ役割の席が別々の口座へ散り、候補が尽きて席が立たないことが実際に起きました。user は、同じ役割の席は揃って移り、移った先に居続け、候補が無くても席は立てると裁定しました。

CTX1

現物 — 使えない周の選定は席ごとで、 除外は「自席以外の全登録 row の口座」

ADR-0036 と seat-roles.md §15 (2) は、 宣言の口座が使えない周に席ごとに session 用の選定席を起こす口座を残量から選ぶ規則へ落ちる。 その選定 (crates/scribe2/src/seat/cycle/relaunch.rs の choose) は除外集合を「自席 (同じ役割と anchor) 以外の全登録 row の口座」で作る。 同じ役割の他 project の席も除外に入るので、 先に移った席の口座が後続の席の候補から外れる。

CTX2

実測 — 同じ役割の席が別々の口座へ散り、 候補が尽きて席が立たない

(a) 同じ役割の他 project の席が先に移った口座は後続の席の候補から外れるので、 同じ役割の席が別々の口座へ散る = ADR-0036 の「役割の口座を host で揃える」が逼迫時に崩れる。 (b) 席の数が口座の数に近づくと候補が尽き、 選定が no-account を返して席が立たない (実測 2026-09-17・planner の席の立て直しが連続で断られた・口座名は台帳が原本で本 file には写さない・CON2)。 席が立たない間は対話面が無く、 user は進め方を裁定することもできない。

CTX3

user の裁定 — 役割ごと揃って移る・移った先に居続ける・候補が無くても席は立てる

裁定 id = user 2026-09-17T05:50Z (逐語は台帳 s2-07l.418) と user 2026-09-17T06:10Z (逐語は台帳 s2-07l.436)。 逐語は台帳が原本で本 file には写さない (CON2)。 要旨: (1) 役割の口座は project をまたいで共有し、 上限が来たら同じ役割の席は同時に同じ別の口座へ移る。 (2) 移った先には、 そこが逼迫するまで居続ける (宣言の口座に余裕が戻っても戻らない)。 移る先は余裕が最大の口座。 (3) 閾値未満の候補が無い周も席は必ず立て、 妥協で立った席は作業を止めて user の裁定を待つ。 全口座が上限に当たっている周だけは従来どおり断る。 (4) 走行中の便は止めない。 (5) consult の席は planner の口座を使う。 狙い = 便が使える口座が増える・席の管理と予算の見通しが単純になる・行き来の cycle を減らす。

CTX4

host の根同じ host の全 project が共有する置き場と、 宣言値と実効値を型で分ける向き

state dir は project ごとに分かれうる (ADR-0036 CTX2 の実測) ので、 実効の口座を state dir の中に置くと別の state dir の project に届かない。 host の根 (<state_dir の親>/<NAME>-host/) は ADR-0036 の宣言 file と受付札が既に使う project 横断の置き場で、 env を読まずに state dir から導く。 宣言 file は人が書く宣言値で、 器が実測から決めた口座は実効値の側である (憲法 C10 は両者を型で分ける)。 憲法の向き = C10・C2 (選定と除外は 1 関数・順序は宣言順)・C2.2 (env を読まない)・C9 (席が止まったら人手なしで再開する)・C9.2 (口座を窓の終わりまで使い切る)・N1 / N1.2 (消さない・退役は可逆な move)。

CTX5

現物 — 席用と便用は選ぶ順序が別で、 選定の純関数は閾値を入力で受ける

選定の純関数 (crates/scribe2/src/fleet/select.rs) は用途で順序が分かれる: session 用は逼迫度数える窓のうち最大の使用率が最小 (= 余裕が最大) の口座、 便用は reset が最も早い口座から使い切る (ADR-0027)。 当たっている口座 (窓の全量) と測れない口座はどちらの用途でも候補にならず、 session 用だけが閾値 (R-C9-1) 以上の口座も外す。 閾値は入力の 1 項目なので、 閾値に窓の全量を渡せば「当たっていない中で余裕が最大」を同じ関数が返す。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

判断を評価する 5 本のものさしです。同じ役割の席が同じ口座に揃うこと、移るのは逼迫した周だけで行き来しないこと、席は必ず立って妥協は隠さず user に渡すこと、人が書いた宣言と器が決めた口座を分けること、既存の経路と純関数を変えないことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 7 つ並べます。実効の口座を host の根の記録 1 件に持ち逼迫した周にだけ移る案、余裕が戻れば宣言へ戻る案、器が宣言 file 自体を書き換える案、除外だけ直して記録を持たない案、記録を各 project の event に持つ案、候補が無い周は断る案、host に常駐する監視 process を置く案です。

OPT1実効の口座を host の根の実効の記録 1 件 (役割ごと・器が書く) に持ち、 逼迫した周にだけ役割単位で 1 回選び直す。 候補が無い周は妥協の口座で立てる採用

役割の実効の口座を 1 関数で解く: 実効の記録が在りその口座が使えればそれ (居続ける)、 記録が無い周は宣言の口座が使えればそれを記録に書いて使う (宣言 = 初期値の種)、 どちらも使えない周だけ役割単位で 1 回 session 用の順序 (余裕が最大) で選び直して記録を書き換える (前の記録は履歴へ move)。 除外は他の役割の口座だけ。 閾値未満の候補が無い周は、 当たっていない中で余裕が最大の口座、 それも無ければ他の役割の口座との同居も入れて余裕が最大の口座で席を立て、 妥協の理由を記録と席の指示文に出す。 consult は planner の記録を読む。

host に 1 か所だけ「この役割はいまこの口座」という記録を器が持ちます。同じ役割の席は全部それを読むので、いつも同じ口座に揃います。その口座が逼迫したら、最初に気づいた席が役割を代表して余裕が最大の口座を選び、記録を書き換えます。元の口座に余裕が戻っても戻りません。使える口座が見つからないときも、いちばんましな口座で席を立て、席に「妥協で立った」と知らせて user の裁定を待たせます。

+ 利点

  • 同じ役割の席が常に同じ口座に揃い、 席が占める口座が役割の数で頭打ちになる (便が使える口座が増える)
  • 移るのは逼迫した周だけで、 宣言との行き来の cycle が無い
  • 席が必ず立つので対話面が残り、 妥協の周の進め方を user が裁定できる
  • 人が書く宣言は器が触らず、 選定の純関数も変えない (閾値の入力と除外集合の作り方だけで妥協の段を表せる)

− 欠点

  • host の根に器が書く記録が 1 種類増え、 reader・lock・退役の move・doctor の項目・席の指示文の穴・歯が契約に載る
  • 同じ役割の席が 1 つの口座に集まるので、 その口座の窓の減りが速くなる
  • 宣言と実効の口座が長く食い違いうる (宣言は種でしかない)。 人が戻したい周は宣言の書き換えの口を撃つ 1 手が要る
  • 妥協の周は閾値以上の口座や他の役割と同居の口座で席が走る (作業は止まり、 user の裁定待ちになる)
OPT2移り先を記録するが、 宣言の口座に余裕が戻れば宣言へ戻る (ADR-0036 DR3 の後半を残す)不採用

解決の順を宣言 → 移り先の記録 → 選定にし、 宣言の口座が使える周は常に宣言が勝つ。

人が決めた口座を常に優先する案です。宣言どおりに戻るので分かりやすい一方、口座の窓が開くたびに全席が退避と起こし直しを通って戻り、また逼迫して移る、という行き来が起きます。

+ 利点

  • 宣言と実効の口座の食い違いが短い (余裕が戻れば宣言どおりになる)

− 欠点

  • 窓が開くたびに全 project の席が退避と立て直しを通って戻る = 行き来の cycle が役割の席の数だけ増える (user の裁定は「移った先に居続ける」)
  • 戻った直後の宣言の口座は閾値の近くに居やすく、 すぐまた移る
OPT3器が宣言 file (roles.toml) 自体を移り先の口座で書き換える不採用

逼迫を見た席が ADR-0036 の書き換えの口と同じ手順で宣言の行を移り先に書き換え、 全席が宣言を読んで移る。

新しい記録を持たず、宣言そのものを器が書き換える案です。仕組みは増えませんが、人が決めた値と器が測って決めた値が同じ file で混ざり、どちらが書いた値か分からなくなります。

+ 利点

  • 置き場と reader が増えない (ADR-0036 の file と口だけで済む)

− 欠点

  • 宣言値を器の実測で上書きする = 宣言値と実効値を型で分ける憲法 C10 に反する
  • 人が決めた口座が file から消え、 妥協の理由のような器の側の項目を宣言 file に持ち込むことになる
OPT4選定の除外から同じ役割の席を外すだけで、 記録は持たない不採用

除外集合の作り方だけを変え、 使えない周は従来どおり席ごとに選定を撃つ。

候補の削り合いだけを直す案です。席が立たない問題は減りますが、席が 1 つずつ別の時刻に選ぶので、その時々の残量で選ぶ口座が変わり、同じ役割の席が別々の口座へ散ります。

+ 利点

  • 変更が除外集合の 1 か所で済み、 新しい file を持たない

− 欠点

  • 席ごとに別の周の実測で選ぶので、 同じ役割の席が別々の口座へ散る (user の裁定の「同時に同じ口座へ」にならない)
  • 席が占める口座が役割の数で頭打ちにならず、 便が使える口座が減る
OPT5実効の口座を各 state dir の event log の event に持つ不採用

口座を決めた席が自分の state dir の event log に event を 1 件積み、 他の席は replay で読む。

既に在る記録の仕組みに載せる案です。追記だけで履歴も残りますが、記録の置き場は project ごとに分かれうるので、別の置き場を使う project の席には届きません。

+ 利点

  • append のみの既存の store に載り、 履歴が自然に残る

− 欠点

  • state dir が project ごとに分かれた host では、 別の state dir の席に届かない (ADR-0036 CTX2 の実測と同じ穴)
  • host 横断の値を project の state に置くことになり、 ADR-0036 が host の根へ寄せた向きの逆
OPT6閾値未満の候補が無い周は席を起こさず断る (現行)不採用

選定が候補なしを返した周は 1 key も送らず、 次の tick で選び直す。

いまの形です。逼迫した口座で席を走らせずに済みますが、席が立たないので対話の窓口も消え、user が「どう進めるか」を決める場所が無くなります。

+ 利点

  • 閾値以上の口座を席が消費しない。 器の変更が無い

− 欠点

  • planner の席が立たない間は対話面が無く、 裁定も便の起動も止まる (実測 2026-09-17)
  • どの口座をどこまで使うかは user の予算の判断なのに、 器が黙って「使わない」側に倒している
OPT7host 常駐の process が逼迫を監視して全席を同時に移す不採用

host に 1 つ常駐する process が役割の口座の残量を監視し、 逼迫したら移り先を選んで全 project の席を一斉に動かす。

host に常駐して監視する process を置く案です。全席が本当に同時に移りますが、常駐 process を持たない方針と食い違い、ADR-0034 と ADR-0036 で既に退けた形です。

+ 利点

  • 移し替えが即時で、 project ごとの tick を待たない

− 欠点

  • 常駐 process を持たない向き (ADR-0034 の契機は tick と land・ADR-0036 OPT5 の却下) と食い違う
  • 席を動かす手が tick の外にもう 1 本増え、 退避の合図の除外 (FR29) と立て直しの 3 条件を 2 か所で持つことになる
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、それが要件書のどの要件を支えるかを示します。役割の実効の口座は、実効の記録、宣言の種、役割単位の 1 回の選び直しの順に 1 関数で解きます。候補が無い周は 2 段の妥協で席を立て、理由を記録と席の指示文に出します。

採用 — OPT1

器 SHALL 役割の実効の口座その周に役割の席が実際に使う口座を 1 関数で解き、 その順は (1) host の根の実効の記録 (役割ごとに高々 1 件) が在りその口座が使える (ADR-0036 の意味 = 宣言済み・退役でない・最新の実測が在り・session 用の閾値未満) 周はそれ (宣言の口座に余裕が戻っても記録の口座に居続ける)、 (2) 記録が無い周は宣言 (roles.toml) の口座が使えればそれを記録に書いて使う (宣言 = 初期値の種)、 (3) どちらも使えない周だけ役割単位で 1 回選び直して記録を書き換える、 とする。 器 SHALL 実効の記録を host の根 (<state_dir の親>/<NAME>-host/・宣言 file と受付札と同じ導き方・env を読まない) の下の dir 1 つに役割ごとの file 1 つで持ち (schema = 1・項目 = role・口座 label・ts・妥協の理由・宣言 file と同じ TOML subset の reader と同じ拒否形)、 宣言 file とは file も型も分け (宣言 = 人が書く宣言値・記録 = 器が書く実効値・C10)、 記録が在るのに読めない周は typed に止める (FailClosed)。 記録の書きは席を起こす口 (seat launch と立て直し) だけが行い、 lock の下で読み直し → 在って使えればそれを読むだけ → でなければ決めて一時 file → rename (先に書いた席が勝ち、 後続の席は読むだけ = 同じ役割の席は同じ口座へ揃う)、 前の記録は上書きせず履歴の側へ rename してから書く (N1 / N1.2)。 (3) の選び方 SHALL session 用の既存の順序 (逼迫度が最小 = 余裕が最大) であり、 便用の順序 (reset の早い順に使い切る・ADR-0027) とは用途の分岐で分かれたままとする。 (3) の除外 SHALL 他の役割の実効の口座 (記録が無い役割は宣言の口座) と他の役割の登録 row の口座だけであり、 同じ役割の席の口座は除外しない。 選定の純関数とその入力の型は変えない。 (3) で閾値未満の候補が無い周 SHALL NOT 断る: 05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、代わりに引き受けることです。同じ役割の席が常に同じ口座に揃い、行き来が無くなり、席が必ず立ち、便が使える口座が増えます。一方で器が書く記録が 1 種類増え、1 つの口座の減りが速くなり、宣言と実際の口座が食い違い続けることがあり、妥協の周は逼迫した口座で席が走ります。

✓ 良い結果

  • ●同じ役割の席が project をまたいで常に同じ口座に揃い、 席の管理と予算の見通しが役割単位で済む
  • ●移るのは逼迫した周だけで、 宣言との行き来の退避と立て直しが無い
  • ●候補が無い周も席が立ち、 対話面が残る。 妥協の事実は記録と席の指示文に出て、 進め方を user が裁定できる
  • ●席が占める口座が役割の数で頭打ちになり (consult は planner と同じ口座)、 残りの口座を便が使い切れる

⚖ トレードオフ・代償

  • ●host の根に器が書く記録が 1 種類増え、 reader・lock・退役の move・doctor の項目・席の指示文の穴・歯が契約 1 本に載る
  • ●同じ役割の席 (と consult) が 1 つの口座に集まるので、 その口座の窓の減りが速くなる
  • ●宣言は種でしかなく、 宣言と実効の口座が長く食い違いうる (doctor の 1 行が両方を出す・人が戻す周は宣言の書き換えの口)
  • ●妥協の周は閾値以上の口座や他の役割と同居の口座を席が消費し、 席は user の裁定まで作業を止める
