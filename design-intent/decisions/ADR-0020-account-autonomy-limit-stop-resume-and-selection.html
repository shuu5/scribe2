§1. Context

口座には使える量の窓 (5 時間・7 日・モデルごとの 7 日) があり、 当たると claude は止まります。 これまで便が上限に当たると、 器はその便を「失敗」として閉じ、 作業を最初からやり直す形でした。 計画役や管理役の席が上限に当たると、 その席は止まり、 別の席の仕事まで詰まりました。 口座を選ぶのは人で、 前の版の道具の数字を見て手で決めていました。 user の裁定の要旨は、 これを器の仕事にして v2 で解消すること、 便は上限に当たっても途中から続けられるので口座を使い切るための弾と見ること、 席は詰まる前に退避すること、 の 3 点でした (逐語は台帳)。 この記録はその形を決めます。

記録時点 (2026-09-12) の現物: runner は上限 record (ADR-0012 §2.1) を読んで rc 75 で止まり、 pipeline はそれを Failed (detail = rate-limit) に倒す経路を持つ。 ただし ADR-0012 §3 が記録するとおり止める status の集合は記録時点で空で、 実便では rc 75 は一度も立たない (真に当たった周は claude の rc による失敗として残る)＝§2.1 / §2.3 の契機は歯 (偽の runner・AC12) で測り、 実便の 1 件は status を採取して集合に入れた後に成立する。 便の worktree と event は残るが、 段は終端で、 続きは新しい便でしか起こせない。 口座残量は ADR-0017 §2.1 の実測行 (1 口座 1 窓 = 1 行・出所付き) として fleet の event log に在り、 読み手は席と doctor だけで、 器は選定に使っていない。 rules 行 R-C9-1 (kind = 口座の選定規則) は前の版の散文を値に持ち、 enabled = false のまま。 headless は --account-dir で子 process の設定 dir を切り替える口を持つ (FR5)。 席の口座は起動時に人が選び、 席の登録 (ADR-0022 §2.1) は口座を持たない。 管理 tick は context の cap (FR26) で退避の合図を注入する (ADR-0015 §2.1・FR29) が、 口座の残りは見ない。 実測 (2026-09-12・planner 席): 7 日窓に余裕が在ってもモデル別の 7 日窓だけに当たって席が止まった。 前の版の道具はモデル別の窓を表示できず、 v2 の計測 (FR33・台帳 s2-07l.138) がモデル名付きで記録する。

憲法の向き: C9 は席が止まったら人手なしで検知し、 仕事を再開し、 結果を保つと定める。 C9.2 は各口座を allowance の窓の終わりまで使い切り、 選択は R-C9-1 の規則に従うと定める。 C1 / C5 は規則の値を manifest の行に裁定 id 付きで持つ。 C2 は選択を 1 つの enum の上の 1 つの関数にする。 C10 は宣言値・実測値・実効値を型で分ける。 C3.4 は完了条件を 1 つの完了 enum の値で表し、 待つ実装を 1 つに限る。 C11.2 は境界に極性を持たせる。 N1 は器が管理する物を不可逆に消さない (上限で止まった便の worktree は管理する物)。 user の裁定 (2026-09-12・会話面・逐語は台帳 s2-07l.142 の notes): 要旨は decided-by のとおり。

§2. Decision

§2.1 上限で止まった便は Failed にせず、 再開できる段として typed に記帳する

実装役が上限の合図で止まったら、 器はその便を「失敗」ではなく「上限で止まった」という段に置きます。 どの口座のどの窓に当たったかを記録に残し、 作業場所 (worktree) と、 それまでの記録はそのまま保ちます。 この段の便は、 別の口座で続きから起こし直せます (§2.3)。 上限の合図の読み方 (どの record の何を見るか) は前の決定のままで、 変えません。

pipeline SHALL 段 Stage に variant 1 つ (上限停止・宣言順は Questioned の直後・C2「新しい理由は新 variant 1 つ」・ADR-0016 §2.2 と同じ足し方) を足し、 runner が上限の rc (ADR-0012 §2.1 の rc 75) で終わった周 SHALL その段へ倒し、 段の event の detail に口座の label (ADR-0017 §2.3 の不透明な label) と当たった窓 (WindowKind の値) を持つ (FR35)。 器 SHALL NOT その便を Failed に倒さず、 worktree・base・commit・質問と回答の event を保つ (N1・C9「結果を保つ」)。 上限停止の段は終端ではない (live な便として intake の排他の母集団に残る・ADR-0019 §2.1)。 event log の schema 版 SHALL 1 のままとする (値の追加で既存の行は読める・ADR-0004 §2.5)。 上限の判定入力は上限 record の status のみ (ADR-0012 §2.1・不変) で、 本 ADR は判定を足さない。 runner 以外の子 process (lens) が上限で止まった周は FR9 の既存極性 (INCONCLUSIVE) のままとし、 本 ADR は変えない。

§2.2 口座は 1 つの純関数が選ぶ。 便用は使い切る側、 session 用は余裕を残す側。 値は R-C9-1 が typed に持つ

どの口座を使うかは、 manifest に宣言した口座と、 実測した残り (計測の記録) だけを入力にする 1 本の関数が決めます。 関数は 2 つの規則を持ちます。 便に渡す口座は「まだ当たっていない口座のうち、 いちばん残りが少ないもの」です——便は途中から続けられるので、 口座を使い切る側に倒します。 開発 session に渡す口座は「いちばん残りが多いもの」です——席は止まると他の仕事を詰まらせるので、 余裕を残す側に倒します。 便には、 いま席が使っている口座を渡しません。 測れていない口座は選びません。 閾値の値は規則の行 (R-C9-1) が持ち、 この記録は値を決めません。 R-C9-1 はこれまで前の版の文章を値に持っていましたが、 数値の行に改めます。

器 SHALL 口座の選定を 1 つの純関数 (C2・入力 = manifest の [[account]] 行の label 列 (ADR-0017 §2.3・宣言値) と口座 × 窓ごとの最新の実測行 (ADR-0017 §2.1・実測値) と用途 (便 / session) と使う model・出力 = label 1 つまたは「候補なし」の typed な理由) で行い (FR36)、 SHALL NOT 席の判断や pane の字面や前の版の道具の出力を入力にしない。 口座の逼迫度 SHALL その口座の窓のうち最大の使用率 (5 時間窓・7 日窓・用途が使う model のモデル別 7 日窓。 他の model の窓は数えない) とし、 当たっている口座 SHALL 最新の実測行の使用率が窓の全量 (100 %) に達している口座とする (100 は窓の定義〔allowance を使い切った状態〕であって器が持つ閾値ではなく、 rules 行にも core の規則値にも置かない。 §2.1 の段の event が持つ窓は記録用途で、 選定の入力にしない＝選定の入力は実測行だけ)。 便用の規則 SHALL 当たっていない口座のうち逼迫度が最大の口座を選ぶ (使い切る側・C9.2)。 ただし席の登録 row (ADR-0022 §2.1) が持つ口座 SHALL 便用の候補から外す (席の口座を便が食い潰さない・席の生死は問わず登録が在る限り外す。 登録の解除は §2.6 の射程外で、 席の起動の便が同じ口で持つ)。 session 用の規則 SHALL 逼迫度が最小で、 かつ R-C9-1 の値 (session 用の閾値・使用率の百分率) 未満の口座を選ぶ (余裕を残す側)。 実測行が無い・AllowanceUnmeasured・reset 時刻を過ぎた古い行しか無い口座 SHALL 候補から外し (測れない口座を選ばない・C10: 宣言値を実効に上げるのは測定を通してだけ)、 選定の直前に器 SHALL FR33 の計測を 1 回撃つ (実測行の鮮度を選定側が保証する・計測は既存の 1 コマンド)。 同点は label の辞書順 (決定的・C2)。 rules 行 R-C9-1 SHALL 散文の値を捨て、 typed な値 (Int・session 用の閾値) を持って enabled = true とし、 裁定 id は本 ADR の decided-by の裁定 (契約が manifest に書く・C5)。 便用の規則 SHALL 閾値を持たない (「当たっている」は実測行の値が窓の全量に達した事実であって規則値ではない)。 R-C9-1 の kind は既存の AccountSelection のまま値の型だけを改める (RuleKind の variant を足さない)。 本 ADR は値を決めない。

§2.3 別口座での途中再開は同じ worktree と同じ契約で行い、 口座が無ければ最も早い reset まで待つ

上限で止まった便を再開するとき、 器は §2.2 の便用の規則で別の口座を選び、 同じ作業場所と同じ契約 (質問への回答も添えて) で実装役を起こし直します。 それまでの commit は残っているので、 実装役は続きから働きます。 選べる口座が 1 つも無ければ、 便を失敗にはせず、 いちばん早く窓が空く時刻まで待ってからもう一度測って選びます。 人の手は要りません。

上限停止の段の便の再開 (FR37) SHALL §2.2 の便用の規則で口座を選び、 同じ worktree・同じ契約・同じ base で runner を起こし直す (--account-dir に選んだ label の credential dir〔ADR-0017 §2.3 の <state_dir>/accounts/<label>〕を渡す・FR5 の口のまま・env を読まない C2.2)。 prompt SHALL 契約 (再読) に「回答」節 (FR32・Questioned の再開と同じ) と「途中再開」節 (base からの commit の一覧・止まった時刻) を添える。 再開 SHALL 便を運ぶ既存の口 (pipe の run / resume) の内側で人の操作なしに行う (C9・FR22: 人由来の event は approval 以外 0 件)。 候補なしの周、 器 SHALL 完了 enum に variant 1 つ (口座が空く・pid ではなく最も早い reset 時刻を運ぶ＝現物の完了 enum は全 variant が pid を返す形で、 variant ごとに運ぶ値が違う形へ改める) を足して唯一の wait 実装を通し (C3.4・第 2 の poll loop を持たない)、 wait の deadline SHALL 最も早い reset 時刻から計算した値とし (rules 行ではない・ADR-0021 §2.3 の SlotFree が rules 行の上限で縮退するのとは違い、 縮退を持たない)、 Timeout (C11.3 の Result) を受けた周は計測して選び直す (候補なしなら次の reset 時刻で待ち直す)。 待ちの上限 SHALL NOT rules 行で持たない (reset 時刻が上限・便を Failed にしない・C9「結果を保つ」)。 起こし直しの回数 SHALL NOT 上限を持たない (候補は当たっていない口座に限られ、 同じ口座を reset の前に続けて選ばない。 ADR-0019 §2.4 の起こし直しは rules 行で上限を持つが、 あれは衝突の解消の試行回数であり、 本 ADR の起こし直しは口座の窓に律速される再開で、 窓を跨いで続く)。 便の終端手段 SHALL pipe stop --run だけとし (窓を跨いで再開し続ける便を畳むのは席の判断)、 器は自動では終端しない。 待ちの間も便は live であり (ADR-0019 §2.1 の排他の母集団)、 pipe stop --run で終端にできる。

§2.4 開発 session は上限の手前で退避の合図を受け、 止まった後に別口座で同じ target に立て直す

計画役や管理役の席の口座の残りが、 席用の閾値に達したら、 管理 tick は席が手を止めるのを待たずに「退避してください」の合図を差し込みます (context の上限のときと同じ合図)。 席が退避して止まったら、 器が §2.2 の session 用の規則で別の口座を選び、 同じ窓 (target) で席を立て直し、 復元の command を差し込みます。 立て直しに使う起動行は、 席を登録したときに渡した雛形 (口座の置き場だけが穴) で、 器の repo には置きません。

管理 tick SHALL 登録済みの席 (ADR-0022 §2.1) ごとに、 実測行の鮮度が tick の周期より古い周は FR33 の計測を先に撃ち (定期計測の形は本 ADR が §2.5 で持つ)、 席の登録 row が持つ口座の逼迫度 (§2.2 の定義・席が使う model の窓を含む) を最新の実測行から読み、 R-C9-1 の値以上である間は idle を待たずに退避の合図を注入する (FR38・FR29 と同じ合図・軸は口座の使用率。 FR26 の cap guard のような Edit の deny は足さない)。 この判定は状態を選ぶだけの判定 (tick の inject / noop) であり、 ADR-0014 §2.1 の定義により guard ではなく、 極性一覧に SHALL NOT 載せない。 実測行が無い・計測が測れなかった周 SHALL 注入せず理由を記録する (縮退・止めない)。 席が退避して止まった周 (hook の打刻が Stop の後に session の終了を示す・ADR-0015 §2.1)、 器 SHALL §2.2 の session 用の規則で口座を選び、 席の登録 row が持つ起動の雛形 (穴は口座の credential dir 1 つ・登録時に渡す・fleet の store に在り tracked file に置かない・CON2) の穴を選んだ label の dir で埋めて同じ target の shell へ注入し、 続けて復元の command (FR28・ADR-0018 §2.1) を注入する。 器 SHALL 席の登録 row の口座 label を選んだ label に更新する (§2.2 の便用の除外の入力)。 候補なしの周 SHALL 立て直さず typed な理由を記帳し、 次の tick で選び直す (席を 0 口座で起こさない・止めない・記録する)。 立て直し SHALL 既存の登録 row を持つ席に限る (新しい席の作成・window の作成・登録の自動化は §2.6 の射程外)。 起動の雛形 SHALL NOT env を読まない・host 名や絶対 path を器が解釈しない (器は穴を埋めて注入するだけ)。

§2.5 ADR-0012 §2.4 / ADR-0016 §2.1 / §2.5 / ADR-0017 §2.4 / §2.5 を部分 supersede する

先の記録は「口座を選び直す仕組みはこの版では作らない」「実測の記録は止める判断にも選ぶ判断にも使わない」「口座を自動で選ぶのは v3」「便は席の口座を継承する」と決めていました。 この記録はそれぞれを、 「仕組みはこの記録」「選ぶ判断に使う (止める判断には使わない)」「v2 の MVP」「便の口座は選定の関数が決める」と読み替えます。 「使用率の閾値で便を止めない」と「上限の合図の読み方」は変えません。

ADR-0017 §2.4 の「器 SHALL NOT 本版で実測行を便の停止 (ADR-0012 §2.3・C9.2) にも口座の選定 (rules 行 R-C9-1 は enabled = false のまま・SRS scope out) にも用いない」は、 本 ADR により「器 SHALL NOT 実測行を便の停止に用いない (不変)。 器 SHALL 実測行を口座の選定に用い、 R-C9-1 は typed な値で enabled = true (§2.2)」と読む (SHALL be read as)。 同 §2.4 の「実測行の読み手は席 (planner / 管理席) と doctor であり、 判断は席が行う」は「読み手に選定の関数が加わり、 選定の判断は器が行う」と読む。 ADR-0017 §2.5 の「口座の自動選定と R-C9-1 の有効化 (v3・A2 の裁定を要する)」は「v2 の MVP・裁定は本 ADR の decided-by (R-C9-1 は憲法の閾値〔C4 / C13〕ではなく A2 の対象外・値の発効は C5 の裁定 id)」と読む。 同 §2.5 の射程外「計測を tick から定期実行する形 (seat-autonomy の領分・別途)」は「管理 tick が §2.4 の判定の前に、 鮮度が切れた周だけ計測を撃つ」と読む (SHALL be read as・定期計測はこの 1 形に限る)。 ADR-0012 §2.4 の「口座を選び直す仕組みは、 この版では作りません」は「仕組みは本 ADR §2.2 / §2.3」と読み、 同 §2.4 の「これらは口座の選定 (本版の射程外) の材料である」は「選定の材料は実測行 (ADR-0017 §2.4 の再配置のまま) であり、 上限 record の field は §2.1 の段の event が持つ当たった窓 (記録用途) にだけ使う」と読む。 ADR-0016 §2.1 の「口座 SHALL 席ごとに持ち、 run は親 (席) の口座を継承する (--account-dir を渡さない形)」は「席は 1 口座を持つ (登録 row・ADR-0022 §2.1)。 run の口座は §2.2 の便用の規則が選び、 --account-dir で渡す」と読む。 ADR-0016 §2.5 の「口座の自動選定 (SRS scope out)」は「本 ADR の決定 (SRS v0.7 で scope in)」と読む。 ADR-0012 §2.1〜§2.3 (判定入力・字面照合の撤去・閾値で止めない) と ADR-0017 §2.1〜§2.3 (実測行・計測の手段・label) は不変である。

§2.6 射程外

この記録が決めるのは「上限で止まった便の段」「口座を選ぶ関数と 2 つの規則」「別口座での途中再開」「席の退避と立て直し」だけです。 席を新しく作ること、 口座の置き場を探すこと、 鍵の更新や再 login、 閾値の値、 モデル別の窓を結ぶ細部は別に決めるか、 user の手番です。

次は本 ADR の決定ではない (MUST NOT be read as such): 席の起動そのもの (新しい席・window の作成・登録の自動化・口座の初回選択・台帳 s2-07l.38 の延長・SRS scope out)、 state dir 配下の走査による口座の発見 (ADR-0017 §2.3 のまま禁止)、 token の refresh と再 login (user の手番)、 SQLite 化 (v3・A3)、 モデル別 7 日窓を model に結ぶ細部 (display name の一致・設計 doc・ADR-0017 §2.5 のまま)、 R-C9-1 の値と session 用の閾値の値 (契約・裁定 id)、 便の同時本数の上限 (admission control・ADR-0021 §2.7 のまま)、 lens の口座 (便の口座と同じ・別に選ばない)、 上限停止の段の便の一覧画面 (v3)、 席の発話の監視。

§3. SRS との関係 (正本は SRS)

この記録が仕える要件は、 上限停止の検知 (FR35)、 口座選定 (FR36)、 別口座での途中再開 (FR37)、 開発 session の上限前の退避 (FR38) と、 その受入基準 (AC12 / AC13) です。 要件は同じ便の要件書 v0.7 に入り、 ここには文面を置きません。

本 ADR が仕える要件は SRS v0.7 (本 ADR と同じ便で改訂) が正本である: FR35 (上限停止の検知・§2.1)・FR36 (口座選定・§2.2)・FR37 (別口座での途中再開・§2.3)・FR38 (開発 session の上限前の退避・§2.4)・AC12 / AC13。 不変の要件: FR33 (計測・§2.2 は読み手を足すだけ)・FR14 (別 process からの再開・§2.3 はその 1 形)・FR22 (人由来の event は approval 以外 0 件・§2.3 / §2.4 の event は machine)・FR28 / FR29 (復元と退避の合図・§2.4 は合図を増やさず契機を足す)・FR32 (質問の再開・§2.3 は回答節を添える)。 SRS の scope は本便で「上限で止まった便の別口座での再開」を in に足し「複数口座の自動選定 (v3)」を out から外す。 要件の文面はここには写さない。 SRS v0.7 の FR38 / AC13 は本便で「口座の使用率が session 用の閾値以上」の向きに揃える (§2.2 / §2.4 の逼迫度と同じ軸・「残り」の向きでは読まない)。 段の名・event の detail の全項目・R-C9-1 の値の型・完了 variant・起動の雛形の形は §2 と現物が持ち SRS は持たない。

§4. Consequences

良い面は、 上限に当たっても便の作業が捨てられないこと、 口座を窓の終わりまで使い切れること、 席が上限で止まって他の仕事を詰まらせなくなること、 口座を選ぶ理由が 1 本の関数に閉じて人の手も前の版の道具も要らなくなること、 前の版の道具が見せなかったモデル別の窓が選定に効くことです。 悪い面は、 段と完了の種類が 1 つずつ増えること、 席の登録に口座と起動の雛形が要ること、 選定のたびに計測が 1 回走ること、 測れていない口座が選ばれないこと、 退避の合図が席の作業を途中で止めることです。

Positive: 上限停止の便の worktree・commit・回答が保たれ、 別口座で Landed まで続く (C9・N1・AC12)。 口座は当たるまで使われる (C9.2) が席の口座は便に食われない (§2.2 の除外)。 席は閾値の手前で退避し、 別口座で復元される (AC13)。 選定が 1 純関数・入力 2 種 (宣言値 + 実測値) に閉じ、 前の版の道具への依存が消える (C8 の向き)。 モデル別 7 日窓が逼迫度に入る (記録時点の事故型)。 R-C9-1 が散文の行から typed な行になり、 C1 / C14.2 の相互参照が実体を持つ。

Negative (受け入れるコスト): Stage の variant 1 つ・Completion の variant 1 つ (運ぶ値が pid でない初の variant)・rules 行 R-C9-1 の値の型変更 (契約・裁定 id)・管理 tick からの計測 (鮮度が切れた周だけ) が増える。 極性一覧は増えない (§2.4 の判定は guard ではない)。 席の登録 row (ADR-0022 §2.1) に口座 label と起動の雛形の 2 field が要り、 登録時に人が雛形を渡す (1 席 1 回)。 選定のたびに FR33 の計測 (host の HTTP client の子 process・口座数ぶん) が 1 回走る。 測れない口座 (credential 不在・墓標・HTTP 失敗) は選ばれない (保守側・その口座は席の手番で直す)。 逼迫度の比較はモデル別窓の display name 一致に依る (ADR-0017 §2.5 の限界のまま)。 退避の合図が busy の席に入るので作業が中断される (意図した不便・context の cap と同じ)。 候補なしの便は reset 時刻まで待つ (最長で窓 1 つぶん)。 R-C9-1 の値は初期は宣言値で、 退避の実測が溜まるまで保守的に出る (C10)。

§5. Alternatives Considered

6 つの案を退けました。 人が口座を選ぶ案は無人運転に反します。 席の口座を便が継承する案は席の口座を便が食い潰します。 使用率の閾値で便を止める案は憲法に反します。 上限で便を失敗にして新しい便で起こす案は作業を捨てます。 上限の合図に載る数字で選ぶ案は出所が違います。 席を止まるまで走らせて立て直す案は他の仕事を詰まらせ、 退避なしの停止は作業記憶を失います。

(A) 人が口座を選ぶ (記録時点の運用)。 却下: FR22 (人由来の event 0) と C9 (人手なしの再開) に反し、 planner が律速になる。 user 裁定で不採用 (自律制御を MVP に)。

(B) 席の口座を便が継承する (ADR-0016 §2.1 のまま)。 却下: 便が席の口座を食い潰し、 席が上限で止まる (記録時点の事故型)。 便と席で逆向きの規則 (使い切る / 余裕を残す) が要り、 継承では表せない。 §2.5 (iv) で部分 supersede。

(C) 使用率の閾値で便を止める。 却下: C9.2 と ADR-0012 §2.3 に反する。 便は当たるまで走り、 当たったら別口座で続く (§2.1 / §2.3)。

(D) 上限で便を Failed にし、 新しい便で起こし直す。 却下: worktree の commit・質問と回答・base が捨てられ、 C9「結果を保つ」と N1 に反する。 FR14 (別 process からの再開) が既に同じ worktree を前提にしている。

(E) 上限 record の utilization / resetsAt で選ぶ。 却下: 出所が違う 2 つの entity (ADR-0017 §2.4) で、 record は便の途中でしか届かず、 席の口座や便が使っていない口座の値を持たない。 選定は実測行 (1 コマンドで全口座) を入力にする。

(F) 席は上限で止まるまで走らせ、 止まったら別口座で立て直す。 却下: 席が止まる間に他の仕事 (契約・裁定・中継) が詰まる (user 裁定の趣旨)。 退避なしの停止は作業記憶 (ADR-0018) を失う。 手前で退避し (§2.4)、 便だけを当たるまで使う (§2.2)。

§6. Trace

出所は、 user の裁定、 モデル別の窓だけに当たった実測、 器の現物 (上限の rc・実測行・段と event)、 そして先行決定 (上限の検出・配送構造・口座残量の計測・作業記憶・gate の費用) です。

  • user の問いと裁定 (2026-09-12・会話面・planner 席): 口座残量の観測口の後に「口座の自律制御を MVP に入れるか」→ 裁定の要旨は decided-by。 逐語は台帳 s2-07l.142 の notes (tracked file には写さない・CON2)。 同日の同じ裁定で「テストは必須」(AC12 / AC13 の T / I)。
  • 実測 (2026-09-12): 7 日窓に余裕が在ってもモデル別の 7 日窓だけに当たって planner 席が止まった。 前の版の道具はモデル別の窓を表示できない。 v2 の計測 (台帳 s2-07l.138) はモデル名付きで記録する。
  • 器の現物 (2026-09-12): runner の rc 75 → Failed detail = rate-limit (pipe/spawn.rs の settle・止める status の集合は headless/runner.rs で空)・fleet の Stage 9 variant・Completion 2 variant・R-C9-1 (kind AccountSelection・散文の値・enabled = false)・headless の --account-dir・管理 tick の cap guard (FR26 / FR29)。
