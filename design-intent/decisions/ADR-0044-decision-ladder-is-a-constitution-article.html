CTX4

憲法の向き

N2 / C1.2 は散文にしか無い規則を規則と認めない (ponytail を skill として注入する形は取れない)。 C14 は規律を文書 (原則と裁定) と data (manifest = 強制する規則) の 2 面で持ち、 C14.2 は値を持つ規則の 2 面の drift を CI が拒む。 C2 は順序を列挙の宣言順で持ち散文の順序を持たない。 C4 / C13 は段の一部を既に deny gate で持つ。 C12.4 は検出線を deny へ昇格するには裁定 id が要ると定める。 A2 / N4.2 は条の追加を「新しい ADR + delta marker + 裁定 id」の手続きに限る。 憲法の順位は「場当たりの修正の禁止 → 増殖の防止 → compile 速度」で、 増殖の防止が 2 番目に在る。

03 検討した選択肢 / 5 つの形

それぞれの利点と欠点を並べる

候補を 5 つ並べます。決定はしごを憲法の条にして機械の面は既存のものを指す案、ponytail を skill や散文として注入する案、はしごの段を型で宣言させて gate が形を検査する案、条に対応する規則の行を 1 本足す案、そして何もしない案です。

OPT1決定はしごを憲法の条 C17 にし、 機械の面は既に在る lens の 5 観点と便の規模の record を指す (rules 行も機構も足さない)採用

Always の条 C17 を A2 / N4.2 の手続きで加える。 強制する面は台帳 s2-07l.188 / .189 で land 済の閉じた型 (findings の 5 観点・便の規模の 4 field) で、 新しい rules 行・走査・record・機構は足さない。 「先に消すものを名指す」は lens と提案の審査の散文の判断に残す。

「上から順に問い、最初に成立した段で止まる」「足すなら先に消すものを名指す」を憲法の条にします。機械が数える面は、審査役がすでに数えている過剰設計の 5 観点と、便の大きさの記録です。新しい規則の行も仕組みも足しません。この ADR 自身が、はしごの「既に在るか」の段で止まっています。

+ 利点

  • 条文 1 つで器の設計と提案の両方に効き、 code の変更は 0 (機械の面は land 済)
  • 散文の規則にならない (N2): 強制する面は閉じた型と件数と母集団で、 欠けた周は INCONCLUSIVE (FR9)
  • 判断は機械に肩代わりさせず (DR3)、 増殖の防止の順位を条文として持つ

− 欠点

  • 「先に消すものを名指す」は機械では拒めない = lens の delete の件数と審査の散文の判断だけが見る
  • 条に値が無いので manifest の行を持たない (C2 / C16 と同じ形)。 後で deny の門にしたければ裁定 id 付きの昇格が別途要る (C12.4)
OPT2ponytail を skill / prompt の散文として注入する不採用

ponytail の配布形そのまま。 散文にしか無い規則は規則ではなく (N2 / C1.2)、 prompt 本文が規範文になる穴 (台帳 s2-07l.176) を広げる (研究 §3 (a))。

ponytail をそのまま「読み物」として agent に渡す案です。いちばん手軽ですが、この器は「文章にしか無い規則は規則ではない」と決めているので、守られたかどうかを誰も測れず、prompt の本文が規則になってしまう穴を広げます。

+ 利点

  • 導入が最も軽い・ponytail の文面と強度をそのまま使える

− 欠点

  • N2 / C1.2 に反する (散文の規範文)・遵守を測る面が無い・prompt 本文の穴 (s2-07l.176) を広げる
OPT3はしごの段を runner が typed に宣言し、 gate が段の含意を検査する (研究 §4 (3))不採用 (保留)

段を閉じた enum (Skip / Reuse / Stdlib / Native / Dependency / OneLine / Minimal) にし、 runner が止まった段と上の段を退けた理由を record で宣言、 gate が形 (段の宣言・含意と diff の整合) を検査する。 契約の field と record の schema を決めるので SRS の FR と ADR が要る。

実装役に「どの段で止まったか」を型で宣言させ、gate がその形を検査する案です。効果は最も高いと読みますが、契約の形と記録の形を決める重い変更で、要件書の改訂も要ります。今は「足す前に消す」段階なので保留し、条文と lens の件数で足りないと分かったときに起こします。

+ 利点

  • runner が必ず一度「要るか・在るか」を通る構造になり、 過剰設計が record に残る (効果は 3 案で最も高いと読む)

− 欠点

  • schema と契約の field を決める (ADR を書く条件 3)・SRS の FR 1 本・契約 2〜3 便 = 今の「削る側」の向き (CTX3) と DR2 に反する・Stdlib / Native は照合できる形が無い (研究 §5)
OPT4C17 に対応する rules 行 1 本 (例: R-C17-1 / review.overdesign・値 = 過剰設計 5 観点の名) を manifest に足す不採用

C14.2 の 2 面のために行を 1 本足す案。 だが 5 観点の名は既に閉じた enum の宣言 (findings.rs) に在り、 行はその写しになる (1 つの列を 2 か所で持つ = drift の源)。 enabled の knob は誰も求めていない。 値 (閾値) の無い条は manifest に行を持たないのが現行の形 (C2 / C3 / C6 / C10 / C11 / C14 / C15 / C16 に行は無く、 R- 行を持つのは C4 / C7 / C8 / C9 / C12 / C13)。

条文に対応する規則の行を 1 本足す案です。「文書と機械の 2 面をそろえる」ためのようですが、5 観点の名前はすでに器の型に在り、行はその写しになって 2 か所がずれる元になります。値を持たない条は行を持たない、というのが今の憲法の形です。この案自体が、はしごの「既に在るか」で止まります。

+ 利点

  • C17 の機械の面が manifest から辿れる・後の deny への昇格が行の enabled の反転で済む

− 欠点

  • 閉じた enum の宣言を manifest に写す = 同じ列を 2 か所で持つ (C1 の「値は 1 か所」の趣旨に反する)・enabled の knob は yagni・値の無い条は行を持たない現行の形と揃わない
OPT5何もしない (機械の面は land 済なので条文は要らない)不採用

lens の 5 観点と便の規模の record は既に在る。 だが CTX1 の力学 (11 日で ADR 43 本・検出線 1 本を囲む機構 5 つ・同日に足して同日に消す門) は、 その 2 つが land した後も続いた。 「足す前に消す」を折れない線として持たなければ、 提案の段で止まる根拠が無い。

機械が数える面はもう在るのだから条文は要らない、という案です。しかし、その面が入った後も器は足す方向に積み上がり続けました。数える面が在っても、「足す前に消す」を守るべき線として持たなければ、提案の段で止まる根拠がありません。

+ 利点

  • 変更が 0・憲法の改訂手続きが要らない

− 欠点

  • CTX1 の力学がそのまま続く・lens の 5 観点は「数える」だけで、 提案を止める線がどこにも無い
04 採用した判断 / どの形を選ぶか

選んだ形と、 それが守る要件 (cross-doc 照会)

選んだ案と、それが要件書のどの要件を支えるかを示します。決定はしごを憲法の条 C17（Always）として加え、機械の面は審査役の過剰設計 5 観点と便の規模の記録を指します。規則の行・走査・記録・仕組みは足しません。審査役の判定が 3 値の外や観点欠けで判定不能になること（FR9）、審査役の予算（NFR1）、便の大きさの目標（NFR2）に対応します。

採用 — OPT1

憲法 SHALL Always に条 C17 を加える。 条文 (日本語): 「変更を提案・実装するとき、 scribe2 は決定はしごを宣言順に通り (要るか → 既に在るか → 標準 library か入っている依存で足りるか → 1 行で書けるか → 最小実装)、 最初に成立した段で止まる。 走査・record・rules 行・機構を足す提案は、 先に何を消すかを名指す。」 条文 (EARS・生成区間の形): 「C17: WHEN a change is proposed or implemented, scribe2 SHALL pass the decision ladder in declaration order (needed at all, already exists, standard library or an existing dependency suffices, one line, minimal implementation) and SHALL stop at the first rung that holds, and SHALL name what is removed before adding a scanner, record, rules row or mechanism.」 機械の面 SHALL 既に在るものを指す: lens の findings の閉じた category のうち過剰設計の 5 観点 (delete / stdlib / native / yagni / shrink・宣言順・0 件も書く・欠けた周と母集団 0 の周は INCONCLUSIVE・台帳 s2-07l.188・設計 pipeline.md §17) と、 便の規模の record (size / files / lines / pub_symbols・閾値なし・台帳 s2-07l.189)。 本 ADR SHALL NOT rules 行・走査・record・機構を足す (条に値が無く manifest の行を持たない形は C2 / C16 と同じ)。 「先に何を消すかを名指す」 SHALL lens (delete の件数) と提案の審査 (planner / user の対話面) の散文の判断で見るものとし、 機械 SHALL NOT それを拒む。 deny の門への昇格 SHALL 裁定 id を伴う別の裁定 (C12.4 / C5) とする。 発効 SHALL /folio-architect が constitution.html に C17 を delta marker 付きで挿し §2 の一覧表と件数を改めた版 (N4.2) とし、 本 ADR SHALL それまで proposed のまま何も拘束しない。

憲法の「いつも守る」段に C17 を足します。中身は「変更を提案するときも作るときも、要るか → 既に在るか → 標準 library か入っている依存で足りるか → 1 行で書けるか → 最小実装、の順に問い、最初に成立した段で止まる。走査・記録・規則の行・仕組みを足す提案は、先に何を消すかを名指す」です。機械が数える面は、審査役がすでに数えている過剰設計の 5 観点と、便の大きさの記録で、新しい行も仕組みも足しません。「何を消すか」の判断は審査役と人に残り、機械では拒みません。条文が効き始めるのは、/folio-architect で憲法の本文に印付きで挿してからです。 はしごの段の大半（依存・大きさ・再利用・宣言順）は憲法の既存の線に既に対応していて、無かったのは「要るか」「既に在るか」を先に問う順序そのものと、「足すなら先に消す」の線です。順序と線は値を持たないので、機械の面は閾値ではなく、審査役が数える 5 観点と便の大きさの記録で足ります。この 2 つは研究の写し方 (1)(2) として既に land しているので、条文以外に足すものがありません。行を 1 本足す案は、5 観点の名を型と manifest の 2 か所で持つことになり、はしごの「既に在るか」で止まります。判断（この抽象は要るか・何を消すか）は機械では決められないので、散文の判断に残すと正直に書き、拒む門にしたいときは裁定 id を伴う別の裁定にします。
