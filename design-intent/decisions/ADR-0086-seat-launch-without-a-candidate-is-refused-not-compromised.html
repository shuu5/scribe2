設計判断記録 (ADR) scribe2 — 口座の候補が無い席の起動

群の外の置き場で候補の無い席の起動は、 妥協の口座で起こさずに理由の語で断る — ADR-0041 の妥協の起動を supersede し (妥協の通知は ADR-0045 が既に削除)、 実装済みの断りを決定にする

ADR-0041 は、 閾値未満の口座が無い周も一番ましな口座で席を立てる妥協の起動を決め、 ADR-0049 は群の移動の妥協だけを退けてこの部分を据え置いた。 けれども code は妥協の起動を一度も持たず、 席の起動は理由の語で断ってきた。 SRS v0.28 は FR69 をこの断りに書き直し、 持ち主は 2026-09-28T09:04Z に妥協の口座で起こさず断る推奨を採った。 本 ADR は妥協の起動を置き換え (妥協の通知は ADR-0045 §2 (2) が管理 tick の軸ごと既に消した)、 断りの語と、 断った周に何も書かない範囲を決定にする。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session、 「口座」は AI を動かす契約の枠、 「閾値」は席に使ってよい余裕の線です。 群 (project のかたまり) に属さない置き場で、 口座を名指さずに席を起こすと、 器は閾値より余裕があり、 他の置き場の席が使っていない口座を選びます。 以前の決定 ADR-0041 は、 そういう口座が 1 つも無いときも一番ましな口座で席を立てる「妥協の起動」を決めていましたが、 器の code はこれを一度も持たず、 起こさずに理由の語で断ってきました。 要件書 v0.28 もこの断りに書き直し、 持ち主も 2026-09-28T09:04Z の裁定で、 妥協の口座で起こさずに断る推奨を採りました。 本 ADR は妥協の起動を置き換え (既に立っている席への「妥協の通知」は、 前の決定 ADR-0045 が定期の見回りごと既に消しています)、 断りの語 (no-account と 4 語の 1 つ) と、 断った周は席の記録も key も何も書かないことを決定にします。 口座を名指した起動と群の置き場の起動は、 この断りに当たりません (要件 FR69 と FR59 を支え、 断りの語は FR36 の口座選定の理由の語に拠ります)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (ADR-0041 が妥協の起動を決め、 ADR-0049 はそれを据え置いた)・現物 (code に妥協は無く、 席の起動は理由の語で断る)・要件の側 (要件書 v0.28 が FR69 を断りに書き直し、 同じ版で口座選定の句も code に揃える)・器が自分で起こし直す経路は選定を通らないこと・憲法と既存の決定の向き、 の 5 つで示します。

CTX1

経緯 — ADR-0041 が妥協の起動余裕が無くても席を立てることを決め、 ADR-0049 は群の移動の妥協だけを退けて席の起動席を立てる器の口の妥協を据え置いた

ADR-0020 §2.4 と ADR-0026 §2.3 は、 選定が候補なしを返す周は席を起こさず typed な理由で断る、 と決めていた。 ADR-0041 は 裁定 id user 2026-09-17T06:10Z の要旨 (3) (閾値未満の候補が無い周も席は必ず立て、 妥協で立った席は作業を止めて user の裁定を待つ) を受けて、 この断りを部分 supersede し、 妥協の起動を決めた。 閾値未満の候補が無い周は、 上限に当たっていない口座の中で逼迫度が最小の口座 (over-threshold)、 それも無ければ他の役割の口座との同居 (shared-with-role) で席を立て、 妥協の理由を役割の実効の記録使う口座の記録と起動の記録の行に載せ、 席の指示文の穴 1 つに出し、 既に立っている席には管理 tick が妥協の通知妥協を席に告げる行を 1 回注入する、 という形である。 当時の実測は、 同じ役割の席が選定で互いの口座を除き合い、 planner の席が立たず対話面user と話す窓口が消えたことだった。 ADR-0049 は役割の実効の記録を群の今の口座群がいま使う口座へ単位ごと置き換え、 群の移動の妥協を作らないと決めたが、 席の起動の妥協は決め直さずに据え置いた。 ADR-0045 は ADR-0041 を不変としたが、 §2 (2) で管理 tick の軸を消したので、 その上に載っていた妥協の通知は載る先ごと消えた (ADR-0049 が明記するのは管理 tick の軸の削除までで、 通知の消滅はそこから導いた結論である)。 SRS v0.27 の FR69 と AC40 は、 この据え置いた形を要件にしていた。

CTX2

現物 — 妥協の起動は code に 1 行も無く、 席の起動は候補なしを理由の語で断る

席の起動が口座を決める関数は 1 つで、 置き場が群に属する周は群の今の口座 (選定を撃たない)、 口座の引数が在る周は宣言に在る label をそのまま使い、 どちらでもない周だけ session 用の選定を撃つ。 その選定の除外は、 同じ state dir の event log に在る登録 row席の記録の 1 行 のうち、 自席 (同じ役割と置き場) でなく退役していない row の口座である (役割は orchestrator の 1 つなので、 他の置き場の席の口座になる)。 選定が候補なしを返すと、 起動は登録 row を書く前・窓を作る前・trust の印と起動の記録を書く前に止まり、 key を 1 つも送らず、 stderr に reason=no-account と detail=<語> を載せた 1 行を出して rc 1 を返す。 語は選定の候補なしの理由口座が外れた訳の閉じた型の 4 つである。 選定は口座ごとに理由を 1 つ付け (除外 → 測れない → 当たっている → 閾値以上の順に見る)、 外れた口座の理由のうち型の宣言順 (over-threshold → all-limited → unmeasured → excluded) で前の 1 つに畳む。 口座が 0 の周は unmeasured になる。 この断りと理由の語は、 ADR-0026 §2.3 の実装 (2026-09-14・ADR-0041 の 3 日前) から続いている。 ADR-0041 の妥協の 2 段・記録の妥協の理由・席の指示文の穴・妥協の通知は、 どれも code に無い (ADR-0049 CTX3 は役割の実効の記録が code に無いことを実測している)。 新しい repo を載せる init の席の段は、 子の起動の断りの語をそのまま写して止まる (failed:seat:no-account)。

CTX3

要件の側 — SRS v0.28 は FR69 と AC40 を実装済みの断りに揃えた

SRS v0.28 は FR69 の見出しを「口座の候補が無い席の起動の断り」とし、 群に属さない置き場で口座の引数が無い周に、 session 用の選定が閾値未満の候補を 1 つも返さないとき、 器は席を起こさず、 登録 row を書かず key を 1 つも送らず、 no-account と 4 語の 1 つ (複数が当たる周はこの順で前の 1 語) を 1 行で告げて断る、 と書き直した。 妥協の起動は持たず、 群の移動も妥協しない。 AC40 は、 4 形の断りと語 4/4・2 つが当たる周の前の語 1/1 (全部が上限の口座と実測が無い口座だけの fixture で all-limited)・登録 row 0・送った key 0・候補の在る周の起動 1/1 を測る。 この書き直しは ADR-0041 のうち ADR-0049 が据え置いた部分を覆すので、 決定の側にも置き換えの線が要る。 同じ SRS の版は、 FR36 の本文と AC13 を code に揃えた。 session 用の選定は自席の鍵 (役割と anchor) の外の登録 row の口座を除き、 自席の鍵の row の口座は除かない (excluded の語はこの除外の集合から来る)。 便用は便の repo を anchor に持つ席の登録 row の口座と各群の今の口座を除く。 用語集の実効の口座その役割の席が使う口座と実効の記録は、 役割の宣言と役割の実効の記録を語っていた定義を、 ADR-0049 がそれを群の今の口座へ置き換えたことを根拠に「器は持たず、 群の今の口座に置き換わった」と直した。 本 ADR の決定は妥協の起動を断りへ替えることに限り、 それらの揃えは SRS の版と ADR-0049 の側に在る。 持ち主は 2026-09-28T09:04Z に、 妥協の口座で起こさずに断る推奨を採った (裁定 id user 2026-09-28T09:04Z)。

CTX4

器が自分で起こし直す経路は選定を通らない

群の移動 (FR38) は群の今の口座を名指して席の起動を呼び、 移り先の候補が無い周は移らず user へ通知する (ADR-0049・ADR-0066)。 管理 tick の起こし (FR27) は、 置き場が群に属せば群の今の口座、 属さなければ登録 row の口座を名指して席の起動を呼ぶ。 どちらも選定を撃たないので、 候補なしの断りに当たらない。 選定を撃つのは、 人か init が口座を名指さずに群の外の置き場で席を起こす周だけである。 管理 tick の起こし直しは row の口座を閾値の門なしで名指す (FR27 の口座の門は合図の送信にだけ掛かる) ので、 閾値以上の row の口座で器が席を起こし直す経路は残るが、 本 ADR の射程の外で、 変えない。 席を同じ口座に揃える要求は、 群の宣言で表す形になった (ADR-0049)。 役割は orchestrator の 1 つになった (ADR-0045)。 それでも群の外の置き場で候補が尽きる形は残り、 その周がこの断りに当たる。

CTX5

憲法と既存の決定の向き

C2 は、 選定と除外をそれぞれ 1 つの型の上の 1 関数にし、 適用の順を型の宣言順だけから取り、 新しい理由は変種 1 つで表す、 と定める (4 語の畳み方はこれに従う)。 C9.2 は、 口座を R-C9-1 の選定規則に従って窓の終わりまで使い切る、 と定め、 session 用の閾値はこの規則の行である。 A1 は「使う」に当たる操作の前に user の承認を求め、 ADR-0049 CTX6 は口座を消費する session を器が起こすことを「使う」と読んだ。 C9 は止まった席を人手なしで再開すると定めるが、 再開の経路 (CTX4) は選定を通らない。 C17 は決定はしごの「既に在る」の段で止まることを、 C17.2 は記録や仕組みを足す前に消すものを名指すことを求める。 N2 から、 決定記録だけに在って歯も code も無い約束は規則として働かない。 入力の前提の断りは guard ではなく、 極性一覧の母集団を増やさない (ADR-0026 §2.3)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 席の起動の結果が決まった形になり、 断った周は何も書かず外れた訳が 1 語で出ること。 選定の経路では、 余裕の無い口座を席に使う判断を器が黙って取らないこと (登録した席の起こし直しは射程の外です)。 決定と要件と実装を揃えること。 足すものを最小にすること。 群の移動・管理 tick の起こし・群の置き場の席の起動と、 群の宣言の意味を変えないこと。

DR1席の起動の結果が「起きた・断った・失敗」のどれかに決まり、 断った周は何も書かず何も送らず、 外れた訳が閉じた語 1 つで出る CTX2・CTX5
DR2選定の経路では、 閾値以上か上限に当たった口座を席に使う判断を器が黙って取らない (使うのは選定規則の内側か、 人が口座を名指した周だけ) CTX1・CTX5
DR3決定・要件・実装を 1 つの形に揃え、 決定記録だけに在って code に無い約束を現行に残さない CTX1・CTX2・CTX3
DR4足すものを最小にする — 記録の欄・席の指示文の穴・tick の合図・待ちの仕組みを足さない (C17 / C17.2) CTX2・CTX5
DR5群の移動・管理 tick の起こし・群の置き場の席の起動と、 群の宣言の意味を変えない CTX4
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 起こさずに理由の語で断る案 (選んだ案)、 ADR-0041 のまま妥協の口座で席を立てる案、 閾値だけを外して選び直す薄い妥協の案、 候補が現れるまで起動の中で待つ案、 群の口座へ倒す案です。

OPT1候補の無い起動は起こさず、 no-account と候補なしの理由の語 1 つで断る (実装済みの形を決定にする)採用

群に属さない置き場で口座の引数が無い周に、 session 用の選定が候補なしを返したら、 席を起こさず、 登録 row・key・窓・trust の印・起動の記録のどれも書かずに、 no-account と 4 語の 1 つを 1 行で告げ rc 1 で断る。 語は選定の理由の型の宣言順で畳む。 人は口座を名指して起こし直すか、 口座を足すか、 窓の reset を待つ。 決め手は裁定 09:04Z (持ち主は断る推奨を採った) と現物と分析 (実装も要件 v0.28 も既にこの形で、 器の code に足すものが無い・足すのは AC40 を測る歯だけ)。

候補の無い起動は起こさず、 理由の語で断る案です。 群に属さない置き場で口座を名指さずに席を起こし、 使える口座 (閾値未満で、 他の置き場の席が使っていない口座) が 1 つも見つからなければ、 器は席を起こしません。 席の記録 (登録 row)・窓・trust の印・起動の記録のどれも書かず、 key も 1 つも送らず、 no-account と、 口座が外れた訳の 4 語 (over-threshold・all-limited・unmeasured・excluded) の 1 つを 1 行で告げます。 いくつも当たるときはこの順で前の 1 語です。 人は口座を名指して起こし直すか、 口座を足すか、 窓の reset を待ちます。 器の code と要件書 v0.28 は既にこの形で、 器の code に足すものはありません (足すのは AC40 を測る歯だけです)。 代わりに、 候補が尽きた置き場では人が動くまで席が立たず対話面も無いこと、 init の導入が席の段で止まりうること、 どの口座がどの訳で外れたかの内訳は行に出ないこと、 AC40 の 4 形のうち 3 形・2 つの訳が当たるときの語・閾値の形の起動を測る歯がまだ無いことを引き受けます。 持ち主も 2026-09-28T09:04Z の裁定でこの案を採りました。

+ 利点

  • 断った周は登録 row も key も書かないので、 同じ command をそのまま撃ち直せ、 登録 row を読む点検も汚れない (DR1)
  • 選定の経路では、 閾値以上や上限の口座を席に使う判断が器に残らない。 使うなら人が口座を名指し、 名指しは選定を通らない (DR2)
  • 決定・要件・実装が同じ形になり、 code に無い約束 (妥協の 2 段・妥協の理由・指示文の妥協の穴) が決定記録の現行から外れる (DR3)
  • 器の仕組みに足すものが 0 で (足すのは歯だけ)、 記録の欄・席の指示文の穴・tick の合図・待ちの仕組みのどれも増えない (DR4)
  • 群の移動の「候補が無い周は移らず通知し妥協しない」と同じ向きで、 群の宣言にも群の置き場の席にも触れない (DR5)

− 欠点

  • 群の外の置き場で候補が尽きた周は席が立たず、 人が口座を名指すか reset を待つまで、 その置き場には対話面が無い (ADR-0041 が妥協で避けた形を引き受ける)
  • init の 1 発で新しい repo を載せる周も、 口座の実測が無ければ席の段で止まり、 人の 1 手 (計測か口座の名指し) が要る
  • 断りの 1 行は 4 語の 1 つに畳むので、 どの口座がどの理由で外れたかの内訳は起動の行に出ない (内訳は選定の型が持つ)
  • AC40 の 4 形のうち 3 形 (over-threshold・all-limited・excluded) と、 2 つが当たる周の前の語と、 閾値の形で候補の在る周の起動は、 席の起動を通す歯がまだ無い
OPT2妥協の起動 (ADR-0041 のまま) — 一番ましな口座で席を立て、 理由を記録と指示文に出して user の裁定を待つ不採用

閾値未満の候補が無い周も、 上限に当たっていない口座の中で逼迫度が最小の口座、 それも無ければ他の席の口座との同居も入れて (ADR-0041 の「他の役割の口座」を、 役割が 1 つになった今は他の置き場の席の口座と読む) 逼迫度が最小の口座で席を立てる。 妥協の理由を記録と起動の記録の行と席の指示文に出し、 席は作業を止めて対話面で user の裁定を待つ。 既に立っている席には妥協の通知を 1 回注入する。 上限に当たっていない測れた口座が 1 つも無い周だけ断る。 決め手は分析 (code に無い仕組みを 3 つ〔消えた妥協の通知も作り直すなら 4 つ〕新しく作り、 閾値の外で器が口座を使う判断を取り、 群の移動と向きが逆) と裁定 09:04Z (持ち主は断る推奨を採り、 この妥協を覆した)。

ADR-0041 のまま、 余裕のある口座が無いときも一番ましな口座で席を立てる案です。 上限に当たっていない中で最も余裕のある口座、 それも無ければ他の席の口座との同居 (ADR-0041 の「他の役割の口座」を、 役割が 1 つになった今の形に読み替えたもの) で席を立て、 妥協した理由を記録と指示文に出し、 席は作業を止めて user の裁定を待ちます。 席が立つので対話面が残り、 user がその場で決められ、 妥協の事実も断りの 1 行より多く伝わり、 口座をどこまで使うかは user の予算の判断なので器が黙って使わない側に倒さない点で勝ります。 けれども、 妥協の 2 段・記録の理由の欄・指示文の穴の 3 つを新しく作ることになり (どれも今は code に無く、 このままにするなら消えた妥協の通知も作り直すことになります)、 閾値の外で口座を使う判断を器が取り、 上限に近い口座の席はすぐ止まりうり、 理由を載せる記録は ADR-0049 が置き換え済みで、 席が作業を止めて待つので人の 1 手が要る点は断りと同じで、 違いは手を打つ場 (対話面か command か) だけです。 持ち主も 2026-09-28T09:04Z の裁定で断る推奨を採ったので退けました。

+ 利点

  • 席が立つので対話面が残り、 user がその場で進め方を裁定できる (ADR-0041 の DR3・裁定 id user 2026-09-17T06:10Z の要旨 (3))
  • 妥協の事実と理由が記録と指示文に残り、 断りの 1 行より多くを伝える
  • どの口座をどこまで使うかは user の予算の判断で、 器が黙って「使わない」側に倒さない (ADR-0041 が断りの形を退けた理由)

− 欠点

  • 妥協の 2 段・記録の妥協の理由・席の指示文の穴の 3 つを新しく作ることになり、 どれも今は code に無い。 ADR-0041 のままにするなら、 消えた妥協の通知も戻った管理 tick に作り直すことになる。 足す前に消すものを名指す必要がある (DR4)
  • 閾値以上の口座を席に使う判断を器が取る。 閾値は R-C9-1 の選定規則の行で、 その外で口座を使う判断は人の名指しで表せる (DR2)
  • 上限に近い口座で立った席はすぐ止まりうり、 同居の段では他の席の口座を使う。 群の移動が退けた「止まる席が増えるだけ」と同じ型である (ADR-0049 OPT5) (DR5)
  • 妥協の理由を載せる役割の実効の記録は ADR-0049 が群の今の口座へ置き換えたので、 載せる先から決め直しが要る (DR3)
  • 席は立っても作業を止めて待つので、 人の 1 手が要る点は断りと同じで、 違いは手を打つ場 (対話面か command か) だけである (DR1)
OPT3薄い妥協 — 閾値だけを外して選び直し、 妥協の語を起動の行に出すだけにする不採用

候補なしの周に、 閾値に窓の全量を渡して選定を撃ち直し (上限に当たっていない中で逼迫度が最小)、 選べたらその口座で席を起こし、 起動の行に妥協の語を 1 つ足す。 記録の欄・指示文の穴・妥協の通知は足さない。 決め手は分析 (席が妥協を知らずに走り、 閾値が席の起動にだけ柔らかい線になる)。

薄い妥協の案です。 候補が無いときは閾値だけを外して選び直し、 選べた口座で席を起こし、 起動の行に妥協の語を 1 つ足すだけにします。 席が立ち、 足すのが 1 語だけで、 選定の関数も変えずに済む点で勝ります。 けれども、 席は妥協で立ったことを知らないまま上限に近い口座で作業を始めてすぐ止まりうり、 閾値の外で口座を使う判断を器が取ることは ADR-0041 の案と同じで、 閾値が群の移動では固い線・席の起動では柔らかい線になり、 選定を 2 回撃つ経路も増えるので退けました。

+ 利点

  • 席が立って対話面が残り、 足すのは起動の行の 1 語だけで、 記録も指示文も触らない
  • 選定の関数は閾値を入力で受けるので、 関数を変えずに書ける

− 欠点

  • 席は妥協で立ったことを指示文で知らないまま、 上限に近い口座で作業を始め、 すぐ止まりうる (DR1)
  • 閾値以上の口座を席に使う判断を器が取ることは OPT2 と同じで、 閾値が群の移動では固い線・席の起動では柔らかい線になる (DR2・DR5)
  • 選定を 2 回撃つ経路が起動の口に増え、 候補なしの周の結果が 2 通りに分かれる (DR4)
OPT4席の起動の中で候補が現れるまで待ち、 選び直してから起こす不採用

候補なしの周に断らず、 最も早い reset の時刻か計測の鮮度の窓まで起動の中で待ち、 選定を撃ち直して候補が出たら起こす。 便の再開が候補なしの周に reset まで待つ形 (FR37) を席の起動へ写す。 決め手は分析 (起動の口が長く塞がり、 待ちの仕組みを足し、 時間では解けない理由が残る)。

起動の中で、 候補が現れるまで待ってから起こす案です。 便の再開が候補の無いときに reset まで待つ形を席の起動へ写します。 人の手を待たずに候補が出た時点で席が立ち、 余裕の無い口座を使わず、 選定は口座が開き直る最も早い時刻を既に持つ点で勝ります。 けれども、 起動の口 (人が撃つ command・init の 1 段) が reset まで数時間塞がりうり、 待ちの仕組みを新しく足すことになり、 測れない口座と除外された口座は待つだけでは候補にならず、 待つ間の席の記録は、 書けば断った周に書かない約束に触れ、 書かなければ点検から見えないという板挟みも残るので退けました。

+ 利点

  • 人の手を待たずに、 候補が出た時点で席が立つ。 便の再開と同じ待ち方で、 器の中の候補なしの扱いが揃う
  • 閾値以上の口座を使わず、 R-C9-1 の選定規則の内側に留まる
  • 選定の型は当たっている口座が開き直る最も早い時刻を既に持つ

− 欠点

  • 起動の口 (人の手番・init の 1 段) が reset まで数時間塞がりうり、 呼び手は結果を待てない (DR1)
  • 待ちの仕組み (再計測・打ち切り・唯一の待ちの実装に足す完了の値) を起動の口に足すことになる (DR4)
  • 測れない口座と除外された口座は時間が経つだけでは候補にならず (計測か登録 row の解消が要る)、 待っても解けない形が残る (DR1)
  • 待つ間に登録 row を書かなければ点検から見えず、 書けば断った周に row を書かない約束 (FR69・AC40 の登録 row 0) に触れる (DR1)
OPT5群の外の置き場は、 候補なしの周に群の今の口座へ倒す不採用

群に属さない置き場で候補なしの周に、 宣言された群の今の口座 (群が複数なら宣言順で前の群) で席を起こす。 決め手は分析 (群の宣言と常設の承認の射程を黙って広げ、 群の移動に取り残される席を作る)。

群に属さない置き場で候補が無いとき、 宣言された群のいま使う口座で席を起こす案です。 その口座は群の移動が余裕のある状態に保ち、 新しい記録も要らず、 群を宣言した machine では対話面が残る点で勝ります。 けれども、 群の宣言は「この置き場の列の席をこの口座に置く」という user の宣言で、 口座を使う常設の承認でもあり、 列に無い置き場の席を載せると宣言と承認の範囲を黙って広げます。 群が移るときは群の置き場の席だけが起こし直されるので、 群の外の席は古い口座に取り残されます。 群が複数か 0 のときの倒し先も新しく決めることになり、 群の置き場で群の口座と違う口座を名指すと断る形とも食い違うので退けました。

+ 利点

  • 群の今の口座は群の移動が閾値未満に保つので、 余裕の在る口座で席が立ちやすい
  • 新しい記録も欄も要らず、 群の今の口座を読むだけで済む
  • 群を宣言した host では、 群の外の置き場でも対話面が残る

− 欠点

  • 群の宣言は「この置き場の列の席をこの口座に置く」という user の宣言で、 A1 の「使う」の常設の承認でもある。 列に無い置き場の席をそこへ置くと、 宣言と承認の射程を黙って広げる (DR2・DR5)
  • 群の逼迫は群の席が居る口座で測り、 群の移動は群の置き場の席だけを起こし直すので、 群の外の席は移動の周に古い口座へ取り残される (DR5)
  • 群が複数か 0 の host で倒す先の決め方を新しく決めることになり、 口座を決める経路が 1 本増える (C2) (DR4)
  • 群の置き場で群の今の口座と違う口座を名指すと断る形 (group-account) と、 群の外の席が黙って群の口座に載る形が並び、 群の口座の使い方が非対称になる (DR5)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 群に属さない置き場で口座を名指さない起動が、 使える口座 (閾値未満で、 他の置き場の席が使っていない口座) を 1 つも見つけられなければ、 器は席を起こさず、 何も書かず、 no-account と 4 語の 1 つで断ります。 妥協の起動は持たず、 既に消えた妥協の通知も戻しません。

採用 — OPT1

席の起動 (FR59) で、 置き場が群に属さず口座の引数も無い周に、 session 用の口座選定使う口座を選ぶ関数 (FR36) が閾値未満の候補を 1 つも返さないとき、 器 SHALL 席を起こさない。 器 SHALL その周に登録 row を書かず、 窓を作らず、 trust の印と起動の記録を書かず、 key を 1 つも送らず、 理由の語 no-account と候補なしの理由の語 1 つを載せた 1 行を stderr に出して rc 1 で断る。 候補なしの理由の語 SHALL 選定の候補なしの理由の閉じた型の 4 つ (over-threshold・all-limited・unmeasured・excluded) に限り、 選定が口座ごとに付けた理由のうち型の宣言順で前の 1 つとする (口座が 0 の周は unmeasured)。 語を足すときは型に変種を 1 つ足す (C2)。 器 SHALL NOT この周に、 閾値以上か上限に当たった口座・他の席の登録 row の口座・群の今の口座のどれでも席を起こさない (妥協の起動を持たない)。 器 SHALL NOT 妥協の理由の欄・席の指示文の妥協の穴・妥協の通知を持たない。 口座の引数を渡した起動と、 置き場が群に属する起動は選定を通らず、 この断りに当たらない (宣言に無い口座の断りと、 群の今の口座と違う口座の断りは不変)。 群の移動 (FR38) と管理 tick の起こしは口座を名指して席の起動を呼ぶ形のまま変えず、 群の移動は候補が無い周に移らず user へ通知する (ADR-0049)。 選定の関数と型・session 用の閾値の rules 行・登録 row の形・起動行の導出・init の席の段が子の断りの語を写す形は変えない。 この断りは入力の前提の断りで guard ではなく、 極性一覧を変えない。

群に属さない置き場で、 口座を名指さずに席を起こし、 使える口座 (閾値未満で、 他の置き場の席が使っていない口座) が 1 つも見つからないとき、 器は席を起こしません。 その周は、 席の記録 (登録 row)・窓・trust の印・起動の記録のどれも書かず、 key を 1 つも送らず、 no-account と、 口座が外れた訳の 4 語 (over-threshold・all-limited・unmeasured・excluded) の 1 つを 1 行で告げ、 rc 1 で断ります。 4 語は選定が口座ごとに付けた訳のうち、 この順で前の 1 つで、 口座が 0 のときは unmeasured です。 語を足すときは型に 1 つ足します。 余裕の無い口座・上限の口座・他の席の口座・群の口座のどれでも、 この周の席は起こしません。 妥協の理由の欄・指示文の妥協の穴・妥協の通知も持ちません。 口座を名指した起動と群の置き場の起動は選定を通らないので、 この断りに当たりません (宣言に無い口座を名指した断りと、 群の今の口座と違う口座を名指した断りは今のままです)。 群の移動と管理 tick の起こしは口座を名指す形のまま変えず、 群の移動は候補が無ければ移らずに user へ知らせます。 選定の関数・閾値の rules 行・席の記録の形・起動行の組み立て・init が子の断りの語を写す形は変えません。 この断りは入力の前提の断りで、 guard (逸脱を止める門) ではなく、 guard の一覧 (極性一覧) も変えません。 ADR-0041 が決めた妥協の起動は code に一度も入らず、 席の起動は ADR-0026 §2.3 の形のまま理由の語で断ってきました。 要件書 v0.28 は FR69 をこの断りに書き直したので、 決定の側でも ADR-0041 の残った部分を置き換えないと、 決定記録だけに在って code にも歯にも無い約束が現行に残ります (憲法 N2)。 断りを採ったのは、 選定の経路 (口座を名指さずに新しい席を起こす周) で、 余裕の無い口座を席に使う判断を器が黙って取らず、 他の席が持つ口座に同居もしないためです (選定の除外は規則の一部で、 その外で使うなら人が名指します)。 session 用の閾値は R-C9-1 の選定規則の行で (C9.2)、 その外で口座を使うなら、 人が口座を名指す起動がすでにその 1 手になります (名指しは選定を通りません)。 ADR-0041 が妥協を要した「席が立たず対話面が消える」形は、 群の置き場の席が選定を撃たずに群の口座で立つ形 (ADR-0049) と、 器が自分で起こし直す経路が口座を名指す形で狭まり (この経路は登録 row の口座を閾値の門なしで名指すので、 閾値以上の row の口座で席が起き直ることはあり、 本 ADR の射程の外で変えません)、 群の外の置き場で候補が尽きる周だけが残ります。 その周は断りの 1 行が外れた訳を告げ、 人の 1 手で進みます。 妥協の起動も席を立てた後は作業を止めて待つので人の 1 手が要る点は同じで (違いは手を打つ場が対話面か command かです)、 そのために記録の欄・指示文の穴を足し、 消えた妥協の通知まで作り直すのは、 決定はしごの「既に在る」で止まる線 (C17) に合いません。 群の移動も候補が無ければ移らずに知らせるので (ADR-0049)、 器の中の候補なしの扱いが同じ向きに揃います。 待って選び直す案は起動の口を長く塞ぎ、 群の口座へ倒す案は群の宣言と承認の範囲を広げます。 4 語の畳み方は選定の型の宣言順に従い (C2)、 新しい語は型に 1 つ足して表します。 この決定は、 持ち主が裁定 (裁定 id user 2026-09-28T09:04Z) で断る推奨を採ったもので、 ADR-0041 が受けた裁定 (裁定 id user 2026-09-17T06:10Z の要旨 (3)) をこの部分で覆します。 要件書と実装はすでに同じ形です。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR69claimFR69 (口座の候補が無い席の起動の断り) の決定の側。 候補の無い起動を起こさず、 no-account と 4 語の 1 つ (複数が当たる周はこの順で前の 1 語) で断り、 妥協の起動を持たないと決める (裁定 09:04Z)。 AC40 の 4 形の断りと語・2 つが当たる周の前の語・登録 row 0・key 0・候補の在る周の起動はこの決定を測る。
FR59claimFR59 (席の起動) が typed に断り key を送らない周の 1 つ (FR69 が断る周) の中身を決め、 口座の引数と群の今の口座の経路は選定を通らないことを保つ。
FR36rationale断りの語は FR36 の session 用の選定が返す候補なしの理由の閉じた型で、 excluded は FR36 の session 用の除外集合 (自席の鍵の外の登録 row の口座) に当たる。 選定の規則・除外・順序は変えない。 語の畳み方の根拠は選定の型の宣言順 (C2) に在る。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 4 つと、 代わりに引き受けること 6 つです。 良くなるのは、 決定と要件と実装が揃うこと、 断った周をそのまま撃ち直せること、 候補なしの周に余裕の無い口座を使う判断が人の手に残ること、 器の code の変更が無いことです。 引き受けるのは、 候補が尽きた置き場で席が立たず対話面も無いこと、 AC40 を測る歯を足す必要があること、 excluded の語が要件書の口座選定の除外の集合に結び付くこと、 設計 doc と語彙の書き直しが要ること、 以前の user の裁定 (候補が無くても席は立てる・全口座が上限のときだけは断る) を新しい裁定で覆し、 席が立たず対話面も無い形を引き受けること、 init の導入が席の段で止まりうることです。

✓ 良い結果

  • ●候補なしの周の起動は何も書かず何も送らないので、 同じ command をそのまま撃ち直せ、 登録 row を読む点検も汚れない
