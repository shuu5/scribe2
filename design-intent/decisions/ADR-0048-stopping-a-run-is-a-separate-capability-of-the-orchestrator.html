設計判断記録 (ADR) scribe2 — 便を止める権能

便を止める権能は起動の権能から分かれ、 orchestrator の席が持つ: pipe stop を launch から外して新しい権能 stop に結び、 rules 行 role.orchestrator に stop を足す (席が撃てるのは --run で便 1 本を名指す形だけ・--all は launch のままでどの席からも撃てない・起動 / 再開 / 受付 / 退役は launch のまま dispatcher の口・止めた便は Stopped で列外に入り契約の字か release の印で列に戻る・SRS FR30 / FR41 の字は変えない)

便の起動・着地・merge は席でなく器の dispatcher が行う (ADR-0045 §2 (1))。 その結果、 権能の表は pipe stop を pipe run / resume / intake / retire と同じ起動の権能 (launch) に結んだまま残り、 その launch は席の rules 行に無い＝便を止められる席が 1 つも無い。 判定に届かないまま driver の抜けた便が live のまま居座り、 write-set の重なる契約を塞ぎ続けた周 (実測 2026-09-20) は、 席から外す口が無く user が手で撃つほか無かった。 止める操作は安全側 (便 1 本を終端 Stopped に倒すだけ・worktree も branch も残る) で、 課金と並列度を動かす起動とは向きが違う。 本 ADR は権能の閉じた列に stop を 1 つ足して pipe stop をそれに結び、 席の行に stop を並べる。 席が撃てるのは便 1 本を名指す形だけで、 全部を止める形は今までどおりどの席からも撃てない。

この判断が約束すること (1 文サマリ)

「作業を始める」と「始まった作業を 1 つだけ終わらせる」を、別々の許可として分けます。いまは同じ 1 つの許可にまとまっていて、その許可は人と話す席に与えていないので、止まらなくなった作業を席から止める手段がありません。そこで「止める」だけの許可を新しく作り、人と話す席に渡します。渡すのは「この作業を止める」と名前で 1 本指定する形だけで、「走っているものを全部止める」形は今までどおり誰にも渡しません。一括で止めると走行中のものを全部失うので、取り返しの大きさが違うからです。止めた作業は終わりの状態になり、作業場所も枝もそのまま残ります。契約の中身を直すか「戻す」印を打てば、また順番待ちの列に戻ります。

01 背景 / なぜこの判断が要るか

いま何が問題か (止める口が起動の権能に括られ、 その権能を持つ席が無い)

なぜこの判断が要るのかを、現物と実測と裁定から説明します。器は「作業を始める・再開する・受け付ける・片付ける・止める」を 1 つの許可にまとめていて、その許可は人と話す席には与えていません。与えていないのは「始める」を席に戻さないためですが、同じ束に「止める」が入っているせいで、止まらなくなった作業を席から止める手段がどこにもありません。実際に、判定に届かないまま止まった作業が居座り、後ろの作業を塞ぎ続けた回があります。

CTX1

現物 — 権能は閉じた列で、 guard の表が pipe stop を起動の権能に結んでいる

権能 (Capability) は core が持つ閉じた列で、 文書は写さない (ADR-0013 §2.1)。 いまの variant は 11 個 — 回答の記帳・承認の記帳・go の記帳・便の起動 (launch)・go 後の merge・契約の編集・path 種別ごとの編集 4 つ・対象 repo の外の編集である。 Bash 面の guard はこの列と器の口を結ぶ表 8 行を持ち (ADR-0022 §2.3・設計 seat-roles.md §4)、 そのうち 5 行 — pipe intake / pipe run / pipe resume / pipe stop / pipe retire — が同じ launch に結ばれている (pipe answer は回答、 pipe approve は承認、 pipe land は merge)。 つまり「止める」は器の中で「始める」と 1 語を共有している。

CTX2

現物 — 席の行に launch が無い＝便を止められる席が 1 つも無い

席の権能は rules 行 role.orchestrator (裁定 id 付き・値は権能の名の列) が持つ (ADR-0022 §2.2)。 いまの値は 8 語で、 回答・承認・go・契約の編集・design-intent の編集・設計 doc の編集・歯の編集・対象 repo の外の編集である。 launch は並んでいない — ADR-0045 §2 (1) が「便の起動・着地・merge は器の dispatcher が行う」と決め、 launch と merge を席の行から外したためである。 席は 1 種類しかないので、 launch に結ばれた口はどの席からも撃てない。 pipe stop がその束に入っている以上、 便を止められる席は 1 つも無い。

CTX3

実測 (2026-09-20) — 判定に届かない便が live のまま居座り、 後ろの契約を塞いだ

全体の歯が 1 本赤い便の gate が、 終端の FAIL でなく判定できず (INCONCLUSIVE) に倒れた。 判定できずは終端ではないので便は live のまま残り、 driver は抜け、 同じ木を測り直しても赤いままで、 自分の bead と write-set の重なる契約を塞ぎ続けた (設計 gate-cost.md §28 の実測・verified)。 席は止められず、 user が手で撃つほか無かった。 この 1 件の根は判定の順で解けた (赤い行が在る周は検出線が測れなくても FAIL に着く・同 §28)。 だが「runner が応答しない便」「人が見て止めたい便」には口が無いままである。 設計 dispatcher.md §11 と §13 はこれを後続として名指し、 「pipe stop は起動の権能で、 ADR-0045 §2 (1) の後はどの席の行にも無い。 『止める』だけを席の権能に足すかは rules 行の変更＝user の裁定が先」と書いている。

CTX4

現物 — 止める操作は安全側で、 起動とは向きが違う

pipe stop --run <id> が書くのは終端の段 Stopped 1 つで、 worktree も branch も消さない (畳む口は pipe retire で、 それ自体が可逆な move である・憲法 N1.2)。 席を止め切れなかった周は終端の記帳を書かず rc 1 で断り (止めていない席を黙って落とすと「全部止めた」に化ける)、 既に終端の便には event を増やさず断り、 段の判定を読めない周は rc 2 で断る (読めないを「終端でない」に読み替えない＝fail-closed)。 一方 pipe run / resume / intake は便を起こす＝口座の消費と並列度を増やす側で、 retire は入れ物を畳む側である。 止めるは、 どれとも向きが違う。

CTX5

現物 — pipe stop は 2 つの口を持ち、 guard は flag を読んでいない

口は 2 つで意味が別である: --run <id> は便 1 本を排他の母集団から外す管理の操作、 --all は生きている席を全部止める掃除の操作で、 対象なしは rc 0 の冪等である (--run も --all も無い呼び出しは「--all が要る」と断る)。 これに対し Bash 面の guard は、 command 行を空白で割り、 器の binary を名指す token の直後の 2 語だけを表と照合する。 --run や --all のような flag はいま 1 つも読んでいない。 したがって「名指しの停止だけを通す」形を作るには、 照合を 2 語から 1 段広げる実装が要る (本 ADR の発効の条件の 1 つ)。

CTX6

裁定と憲法の向き

user 裁定 2026-09-20 (対話面・逐語は台帳 s2-07l.495 の notes) は、 便を止める権能を起動の権能から分け、 orchestrator の席に与えると決めた。 権能の名と行の値の形、 席が撃てる口の絞り方は本 ADR が決める。 C1 は規律を manifest と型に置き、 器の外の散文を規則の置き場にしない。 C5 は rules 行の追加・変更に user の裁定 id を要る。 C11 は失敗を境界ごとの enum で表し、 開くか閉じるかの極性を型に持たせる。 C16 は逸脱を編集・実行の時点で止める。 C17 (決定はしご・ADR-0044) は「要るか → 既に在るか → 標準 library か入っている依存で足りるか → 1 行で書けるか → 最小実装」を宣言順に通り、 最初に成立した段で止まる。 C17.2 は走査・record・rules 行・仕掛けを足す提案に、 先に消すものを名指すことを求める。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (向き・役割分担・誤射の大きさ・型と行・非増殖)

判断を評価する 5 本のものさしです。許可は操作の向き（増やすのか、終わらせるのか）で分けること。席は実装も起動もしないという役割分担を崩さないこと。撃ち間違えたときの被害が違う操作を同じ許可にまとめないこと。許可は型と規則の行で持ち、散文で持たないこと。そして、足すものは最小に留め、新しい記録も段も口も増やさないことです。

DR1権能は操作の向きで分ける。 起こす (口座を消費し並列度を増やす) と、 走っている 1 本を終わらせる (何も増やさず入れ物も残す) は別の向きで、 同じ 1 語に束ねない CTX1 / CTX4・憲法 N1.2
DR2ADR-0045 §2 (1) の役割分担を崩さない。 起動・再開・受付・退役・着地・merge は器の dispatcher の口のままで、 席へ戻すのは「止める」だけ SRS FR30 / FR41・CTX2
DR3誤射の被害の大きさが違う操作を同じ権能に入れない。 便 1 本の名指しの停止と、 走行中の全部を落とす一括停止は、 取り返しの規模が違う CTX5・憲法 N1
DR4権能は閉じた列と rules 行が持ち、 散文が持たない。 行の変更には user の裁定 id が付き、 執行・注入・生成文書は同じ 1 行を読む 憲法 C1 / C5・ADR-0013 §2.1 / ADR-0022 §2.2
DR5足すのは語 2 つまで。 新しい口・event kind・段・記録・走査を足さず、 既に在る口と表と行の中で済ませる 憲法 C17 の段 4・C17.2 / ADR-0044
03 検討した選択肢 / 5 つの形

それぞれの利点と欠点を並べる

候補を 5 つ並べます。「止める」だけの許可を新しく作って席に渡す案、席に「始める」の許可ごと渡す案、止める手段を user の手だけに残す案、器が時間を見て勝手に止める案、そして「全部止める」も席に許す案です。

OPT1権能 stop を 1 つ足して pipe stop を結び、 席の行に stop を並べる・席が撃てるのは --run の形だけ採用

権能の閉じた列に stop を 1 つ足し、 guard の表の pipe stop の行を launch から stop へ付け替える。 pipe run / resume / intake / retire は launch のままで、 席の行に launch は無い＝これらは今までどおり dispatcher の口である。 rules 行 role.orchestrator の値に stop を足す (裁定 id 付き)。 席が撃てるのは便 1 本を名指す形 (--run <id>) だけで、 --all を持つ呼び出しと名指しの無い呼び出しは stop の権能では通らず launch を要る＝どの席からも撃てない (guard は名指しが読めない周を launch の側へ倒す＝fail-closed)。 止めた便は終端 Stopped で列外に入り、 契約の字を直すか release の印で列に戻る。

「止める」だけの許可を新しく 1 つ作り、人と話す席に渡します。「始める」「再開する」「受け付ける」「片付ける」は今までどおり器の側の口で、席には渡しません。席が撃てるのは「この 1 本を止める」と名前で指定した形だけで、名前が読み取れない呼び出しは止める許可では通りません。止めた作業は終わりの状態になり、作業場所も枝も残ります。

+ 利点

  • 居座る便を席が自分で外せる (CTX3 の型が解ける)・列が人の手を借りずに回復する
  • 起動・再開・受付・退役・着地・merge は dispatcher の口のままで、 ADR-0045 §2 (1) の役割分担が崩れない (DR2)
  • 名指しの停止だけを渡し、 一括停止は渡さない＝誤射の被害の上限が今と変わらない (DR3)
  • 足すのは権能の列の 1 語と rules 行の値の 1 語だけで、 新しい口も event kind も段も記録も増えない (DR5)

− 欠点

  • guard が読む語が 1 段広がる (いまは器の binary の直後の 2 語だけ・CTX5)。 照合の面が 1 つ増え、 その面の歯も要る
  • 止めた便の worktree は残り、 畳む口 (retire) は launch のままなので席から撃てない＝終端の便の入れ物の片付けは別の設計に残る
OPT2席に launch を与える (行に 1 語足すだけ)不採用

権能は今のまま 11 個で、 rules 行 role.orchestrator の値に launch を足す案。 変更は行の 1 語だけで、 器の実装も guard の照合も 1 行も変わらない。 だが launch には pipe run / resume / intake / retire が同じ束で入っているので、 「止める」を渡すつもりで起動と再開と受付と退役まで席に戻る。 ADR-0045 §2 (1) が dispatcher へ移したのはまさにその 4 つで、 口座の消費と並列度が席の手に戻り、 「席は実装を自分で行わない」の隣にある「便は器が起こす」の線が消える。 解きたい問題 (居座る便を外す) に対して、 渡す権能が広すぎる。

席に「始める」の許可をそのまま渡す案です。行に 1 語足すだけで済みますが、その 1 語には「始める・再開する・受け付ける・片付ける」が全部入っています。止めたいだけなのに、作業を起こす力まで席に戻ってしまい、費用と同時実行数の決定権も戻ります。

+ 利点

  • rules 行の 1 語で済み、 器の実装も guard の照合も 1 行も変わらない (決定はしごの段 4)

− 欠点

  • 起動・再開・受付・退役まで席に戻り、 ADR-0045 §2 (1) の役割分担が崩れる (DR2)・口座の消費と並列度が席の手に戻る (DR1)
OPT3止める口を user の手だけに残す (現状維持)不採用

権能も行も 1 語も変えず、 居座る便は user が手で pipe stop --run を撃って外す案。 変更 0 で、 誤射の面も一切開かない。 だが器の向きは「席が無人でも列が進む」側にあり (便の起動・着地・merge は dispatcher が契機ごとに自動で回す)、 その間に居座る便だけが人の手を待つ。 塞がれた契約は write-set の交差で止まったまま列に残り、 待ち時間は列の長さに比例して伸びる。 CTX3 の周はこの形で止まり、 判定順の直しでその 1 件は解けたが、 runner が応答しない便・人が見て止めたい便は同じ場所で待ち続ける。 「人が居るときしか回復できない列」は、 自走を目的にした器の中では欠陥である。

何も変えず、止めるのは user が手で行う案です。変更も危険もありませんが、器は人が見ていない間も作業を進める作りなので、止まらなくなった作業だけが人を待つことになります。その間、後ろの作業も一緒に止まります。

+ 利点

  • 変更 0・権能も行も増えず、 席が誤って便を止める経路が 1 本も開かない

− 欠点

  • 席が無人で進む間、 居座る便を誰も外せない (CTX3)・塞がれた契約が人の手を待つ＝自走の器に人の手の段が残る (DR2 の目的に反する)
OPT4器が時間を見て自動で止める不採用

席にも user にも渡さず、 器が「一定の時間より長く段が動かない便」を自分で終端へ倒す案。 人の手も席の権能も要らない。 だが閾値が要る——何分・何時間で殺すかは値で、 値は rules 行に載り、 rules 行には user の裁定 id が要る (C5)。 つまり「裁定を要らなくする案」が、 裁定を要る値を 1 つ増やす。 しかも便の段は本来長い——gate は変異検査を回し、 runner は人の回答を待って止まることもある (待ちの段は関門が開くまで動かない)。 時間で殺す形は、 正常に長い便を誤って殺し、 その誤りは「測っていない値が効いている」形で静かに起きる。 決定はしごの段 1 (要るか) で、 解きたいのは時間でなく人か席の判断だと分かる。

器が時間を見て勝手に止める案です。人も席も要らなくなりますが、「何分で止めるか」という値が新しく必要になり、その値には user の承認が要ります。そのうえ、検査待ちや回答待ちで正しく長くかかっている作業まで誤って殺します。

+ 利点

  • 席にも user にも権能を渡さずに居座る便が消える・人が見ていない時間帯でも列が回復する

− 欠点

  • 閾値の rules 行が 1 本増え、 裁定の要る値が増える (DR5 / C5)・長い gate と待ちの段の便を誤って殺す・誤りが静かに起きる
OPT5権能 stop を足したうえで --all も席に許す不採用

OPT1 と同じく stop を足すが、 口を絞らず pipe stop の呼び出しを丸ごと席に許す案。 guard の照合は今のまま (器の binary の直後の 2 語) で済み、 実装は表の 1 行の付け替えと行の 1 語だけになる。 だが --all は生きている席を全部止める掃除の口で (CTX5)、 撃ち間違えた 1 回で走行中の便を全部失う。 名指しの停止の誤射は便 1 本ぶんで、 release の印で列に戻せる。 取り返しの規模が 2 桁違う操作を、 実装が 1 段楽になるという理由で同じ権能に入れることになる。 C17 のはしごは「1 行で書けるか」を段の 4 番目に置くが、 段の 1 番目は「要るか」——席に要るのは名指しの停止であって、 一括停止ではない。

止める許可を作ったうえで、「全部止める」形も席に許す案です。作りは楽になりますが、撃ち間違えた 1 回で走行中の作業を全部失います。1 本だけ止める誤りは戻せますが、全部止める誤りは戻せません。席に要るのは 1 本を止める力で、全部を止める力ではありません。

+ 利点

  • guard の照合が今のまま (2 語) で済み、 flag を読む面もその歯も要らない

− 欠点

  • 一括停止の誤射で走行中の便を全部失う (DR3)・名指しの誤射は release で戻せるが一括の誤射は戻せない・席に要るのは名指しの停止だけ (C17 の段 1)
04 採用した判断 / どの形を選ぶか

選んだ形と、 それが守る要件 (cross-doc 照会)

選んだ案と、それが要件書のどの要件を支えるかを示します。「止める」だけの許可を 1 つ作って人と話す席に渡し、渡す形は「この 1 本を止める」に限り、「全部止める」は今までどおり誰にも渡しません。始める・再開する・受け付ける・片付ける・着地させる・merge する口は器の側のままです。許可の一覧は規則の行が持つこと（FR41）、止める点を実行の時点に置くこと（FR45）、便を起こすのは席でなく器であること（FR30）、止まった便が列の契機になること（FR68）に対応します。

採用 — OPT1

権能の閉じた列 SHALL 新しい variant stop (行と記録に使う字面は stop) を 1 つ持ち、 Bash 面の guard の表 SHALL pipe stop をその stop に結ぶ (launch から外す)。 pipe intake / pipe run / pipe resume / pipe retire SHALL launch のままとし、 pipe land SHALL merge のままとする＝これらは席の行に無く、 器の dispatcher の口である (ADR-0045 §2 (1) は不変)。 rules 行 role.orchestrator の値 SHALL stop を含む (裁定 id は user 2026-09-20・憲法 C5)。 席が stop の権能で撃てるのは便 1 本を名指す形 (--run <id>) だけで、 --all を持つ呼び出しと名指しの無い呼び出し SHALL stop では通らず launch を要る＝どの席からも撃てず user の手だけが撃つ。 guard SHALL 名指しを読めない呼び出しを launch の側へ倒す (fail-closed・憲法 C11)。 pipe stop の口の挙動 SHALL 1 つも変わらない: 書くのは終端の段 Stopped 1 つで、 worktree も branch も残し (畳む口は retire・憲法 N1.2)、 止め切れなかった周は終端を書かずに断り、 既に終端の便には event を増やさず、 段の判定を読めない周は断る。 止めた便 SHALL 終端として列外に入り、 契約の字が変わるか release の印が打たれた周に列へ戻る (設計 dispatcher.md §12 の判定は不変)。 SRS FR30 / FR41 の字 (便の起動・着地・merge は席でなく器の dispatcher が行う) SHALL 不変である——止めるは起動でも着地でも merge でもない。 本 ADR SHALL NOT 新しい口・event kind・段・記録・rules 行を足す (足すのは権能の列の 1 語と既存の行の値の 1 語だけ・憲法 C17.2)。 発効 SHALL 権能 stop と rules 行の値と guard の照合が land した版とし、 本 ADR SHALL それまで proposed のまま何も拘束しない。

「止める」だけの許可を新しく 1 つ作り、器の停止コマンドをその許可に結び直します。始める・再開する・受け付ける・片付ける・着地させる・merge する口は、今までどおり器の側にあり、席には渡しません。人と話す席の規則の行に「止める」を 1 語足します（user の承認 id 付き）。席が撃てるのは「この 1 本を止める」と名前で指定した形だけで、「全部止める」形と名前の無い呼び出しは、止める許可では通らず、今までどおり誰も撃てません。名前が読み取れない呼び出しは、安全側（通さない側）に倒します。止めるコマンドそのものの動きは 1 つも変えません。終わりの状態を 1 つ書くだけで、作業場所も枝も残り、止め切れなかった回は終わりにせず断ります。止めた作業は順番待ちの列から外れ、契約の中身が変わるか「戻す」印が打たれた回に列へ戻ります。要件書の「便を起こす・着地させる・merge するのは席でなく器」という文は変えません。止めるのは、そのどれでもないからです。 いまの器では「止める」が「始める」と同じ 1 語に束ねられていて、その 1 語は席に渡していません（CTX1・CTX2）。渡していないのは正しい判断で、始める力を席に戻すと費用と同時実行数の決定権まで戻ります。しかし同じ束に入っているせいで、止まらなくなった作業を席から外す手段が 1 つも無くなりました。実際に、判定に届かないまま止まった作業が居座り、後ろの契約を塞ぎ続けた回があります（CTX3）。だから束をほどきます——止める操作は何も起こさず、終わりの状態を 1 つ書くだけで、作業場所も枝も残るので、始める操作とは向きが逆です（CTX4）。ほどいたうえで、渡すのは「1 本を名前で止める」形だけにします。「全部止める」は、撃ち間違えた 1 回で走行中の作業を全部失う操作で、1 本の誤りが「戻す」印で回復できるのとは取り返しの規模が違うからです。名前が読み取れない呼び出しを通さない側へ倒すのは、読み取れなさを「たぶん 1 本だろう」と解釈すると、一括停止がその隙間から通るからです。止めるコマンド自体の動きを 1 つも変えないのは、この判断が変えるのは「誰が撃てるか」であって「撃ったら何が起きるか」ではないからです。足すのが語 2 つで済むのは、口も段も記録も既に在るからで、増やす必要が無いものは増やしません。

この判断が正当化する要件 (cross-doc 照会 → SRS-SCRIBE2-MVP)

FR41claim役割ごとの権能を rules 行 role.orchestrator が裁定 id 付きで持つ形は不変で、 本 ADR はその値に stop を 1 語足す。 「便の起動・着地・merge は行に無く dispatcher だけが行う」の字も不変である (止めるはその 3 つのどれでもない)。
FR45claim権能で守られた操作を実行の時点で止め、 断るときに欠けた権能と rules 行の id を告げる形は不変。 本 ADR は照合の対象に「名指しの有無」を加えるだけで、 読めない周は通さない側へ倒れるので要件の中身は弱まらない。
FR30claim配送構造 (席 1 役割 + 器の dispatcher) と「便の起動・着地・merge は席でなく dispatcher」は不変で、 席が持つのは契約と priority と介入の印と回答——そこに「居座る便を 1 本外す」が加わる。 起動の権能は席へ戻らない。
FR68claim便が終端の段 (Landed / Failed / Stopped) に達した直後が列の契機である形は不変。 席が 1 本を Stopped に倒せるようになると、 その契機がその場で立ち、 交差が解けた契約が人の手を待たずに起きる。

照会先: SRS-SCRIBE2-MVP — SRS: 設計 → 契約 → 実装 → 検証 → land を、 人の手を借りずに 1 本通す器（MVP）

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、代わりに引き受けることです。止まらなくなった作業を席が自分で外せるようになり、始める力は器の側に残り、「全部止める」の誤射は今までどおり起こらず、足すものは語 2 つで済みます。代わりに、止める命令の形まで見分ける段が 1 つ増えること、止めた作業の作業場所は残ったままになること、断り文が「1 本ずつなら撃てる」とは教えてくれないこと、そして許可の名が 1 つ増えて席の説明文も 1 語伸びることを引き受けます。

✓ 良い結果

  • ●居座る便を席が 1 本ずつ外せる (CTX3 の型が解ける)・止めた直後が列の契機なので、 交差が解けた契約が人の手を待たずに起きる
  • ●起動・再開・受付・退役・着地・merge は器の dispatcher の口のままで、 口座の消費と並列度の決定権は席へ戻らない (ADR-0045 §2 (1) が保たれる)
  • ●一括停止は今までどおりどの席からも撃てない＝誤射で失いうる便の数の上限が 1 本のまま変わらない (しかもその 1 本は release で列に戻せる)
  • ●足すのは権能の列の 1 語と rules 行の値の 1 語だけ。 新しい口・event kind・段・記録・rules 行は 1 つも増えず、 pipe stop の挙動も 1 つも変わらない

⚖ トレードオフ・代償

  • ●guard が読む語が広がる。 いまは器の binary の直後の 2 語だけを表と照合しているので、 名指しの有無を見る段と、 その面の歯が要る (照合の面が 1 つ増える)
  • ●席が止めた便の worktree は残る。 畳む口 (retire) は launch のままで席から撃てず、 終端の便の入れ物の掃除は別の設計 (消す操作＝A1 の裁定が要る) に残る
  • ●席が --all を撃った周の deny 文は「この操作は席の権能でない」としか言わず、 「--run なら撃てる」とは告げない (代替ルートを添える口は断りの理由の enum の側に在る)
  • ●権能の名が 1 つ増えるので、 席の指示文が運ぶ権能の列と、 生成文書の rules 表と、 その drift の検査の期待値が 1 語ずつ伸びる
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この ADR が版の系譜のどこに在るかと、判断が最後に行き着く原則です。席の役割を決めた記録の一部だけを差し替えます——「止める」を「始める」の束から外し、席の行に 1 語足す部分です。始める・再開する・受け付ける・片付ける・着地させる・merge するのは器の側という線は、そのまま残します。行き着く原則は「始める力と、始まったものを 1 本だけ終わらせる力は別である」です。

改訂状態current (proposed)

置き換える ADRADR-0045 §2 (1) を部分 supersede

置き換えられたなし (現行)

ADR-0045 §2 (1) のうち 2 点を部分 supersede する: (i) 「Launch / Merge は器の dispatcher だけが行う操作として orchestrator の行から外す」の Launch の中身から pipe stop を抜き、 新しい権能 stop に結び直す。 (ii) 同 §2 (1) が並べる rules 行 role.orchestrator の値の列に stop を足す。 同じ §2 (1) の残り — 席は orchestrator の 1 つ・席は実装を自分で行わない・src の編集は行に無く歯の段だけが開く・便の起動と着地と merge は器の dispatcher が行う (pipe run / resume / intake / retire は launch・pipe land は merge)・Capability::Relay の削除・R-C7-1 の値 — は不変である。 ADR-0022 §2.2 (権能は役割ごとの rules 行が裁定 id 付きで持ち、 執行・注入・生成文書が同じ行を読む) と §2.3 (執行は PreToolUse の guard・identity は pane だけ・subcommand は役割を検査しない) は不変で、 本 ADR は行の値と列の 1 語を足すだけ。 ADR-0013 §2.1 (列挙は機械が持ち文書は写さない) も不変＝本 ADR は権能の名の列を文書に写さず、 足す 1 語だけを名指す。 ADR-0034 の列の入力・順序・介入の印 (first / hold / release) は不変で、 止めた便が列外に入り印で戻る形もそのままである。 ADR-0044 の C17 は OPT4 と OPT5 を落とす根拠として効く。 憲法の条文は 1 条も改訂しない。

照会終端 — PRIN-STOPPING-IS-NOT-STARTING (本 ADR)

始める力と、 始まったものを 1 本だけ終わらせる力は別の権能である。 器は口を誤射の被害の大きさで分け、 名指しの停止だけを席に渡し、 一括の停止は渡さない——名指しを読めない呼び出しは、 渡していない側へ倒す。

本 ADR の判断はこの原則に行き着く (これ以上は遡らない照会終端)。 憲法 N1 (元に戻せない削除をしない・退役は可逆な move) と C11 (極性は型が持つ) を、 「権能をどの粒度で切るか」の形で持ったものである。 実装が 1 段楽になることは、 取り返しの規模が違う 2 つの操作を同じ権能に入れる理由にならない。

07 用語集 / この文書で使う専門語

本文に出てくる専門語のやさしい説明

本文に出てくる専門語を、やさしい言葉で説明します。

権能capability
役割ごとに許された操作の閉じた一覧。 列挙は器の中の型が持ち、 文書は写さない。 どの役割がどの権能を持つかは役割ごとの rules 行 (値は権能の名の列・user の裁定 id 付き) が持ち、 同じ 1 行を執行 (guard)・席の指示文・生成文書が読む。
起動の権能launch
便を起こす側の操作をまとめた権能 (受付・起動・再開・退役)。 ADR-0045 §2 (1) の後は席の rules 行に無く、 器の dispatcher の口である＝どの席からも撃てない。 本 ADR はこの束から停止だけを抜く。
停止の権能stop
走っている便 1 本を終端へ倒す操作の権能 (本 ADR が足す)。 席の rules 行に並び、 撃てるのは便を名指す形だけである。 生きている席を全部止める形は起動の権能のままで、 どの席からも撃てない。
終端の段terminal stage
便がそれ以上進まない段 (着地・失敗・停止と、 判定が FAIL の段)。 終端でない便だけが排他の母集団に数えられ、 同時走行の最大値にも数えられる。 終端に達した直後は列の契機の 1 つで、 器が次の便を起こす。
列外out of the queue
終端に着いた便の契約が起動の列から外れている状態。 契約の字が変わるか、 release の印が打たれた周に列へ戻る。 印 1 回で戻るのは 1 回だけで、 同じ字でまた終端に着けば再び列外になる。
fail-closedfail closed
解けない・読めない周に「通す」ではなく「止める」側へ倒す極性。 ここでは、 便の名指しを読めない停止の呼び出しを起動の権能の側 (＝席では撃てない側) へ倒す。 極性は型が持ち、 全 guard の一覧は器が生成する。
