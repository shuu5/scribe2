設計判断記録 (ADR) scribe2 — 席の封じ込め

席の起動を封じ込めの箱で包む — 席 (人と話す claude とその subagent) の起動行の頭に便と同じ systemd の scope (memory の上限は rules 行 1 本・32 GiB・CPU の重みは付けない) を置き、 行が 0 / 読めない周と道具が無い host は素の行に縮退し、 溢れて殺されるのは箱の中の 1 process だけで claude が死んだ周は管理 tick が起こし直す (ADR-0026 の「cgroup の防壁は席には持ち込まない」の読みを部分 supersede・要件は FR59 / NFR6 の範囲)

ADR-0021 は便 (runner / lens / 検証行) を memory の上限つきの箱に入れ、 ADR-0026 は席の起動を器に足すときに「前の版の launcher の cgroup の防壁は席には持ち込まない」と決めた。 2026-09-25 に席の subagent が撃った sed 1 本が RSS 81 GB まで膨らみ、 user の slice 全体が詰まって ssh の login まで止まった。 持ち主は 2026-09-26 に、 席の起動を systemd の scope で包み上限を 32 GiB とすると裁定した。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session (その席が起こす下請けの agent = subagent と、 それらが撃つ Bash を含む)、 「便」は器が起こす作業の process (実装役・審査役・検証の行)、 「箱」は memory の上限つきの囲い (systemd の scope) です。 これまで便は箱の中で走り、 溢れても便 1 本が落ちるだけで済みましたが、 席には箱が無く、 2026-09-25 に席の subagent が撃った sed 1 本が RSS 81 GB まで膨らんで machine 全体が詰まり、 ssh の login まで止まりました。 この記録は、 席を起こす 1 行の頭にも便と同じ箱 (上限は規則の表の行 1 本・32 GiB・CPU の重みは付けない) を置くと決めます。 道具が無い machine や行が 0 / 読めない周は今までどおりの素の行で起こし、 理由を結果の 1 行に出します。 溢れて殺されるのは箱の中の process だけで、 席の claude 自身が死んだ周は見回り (管理 tick) が起こし直します。 持ち主は 2026-09-26 に上限を 32 GiB と裁定しました。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (便は箱の中・席は箱の外)・事象 (席の subagent の 1 本が machine を止めた)・器の今の部品・これまでの決まり・この判断の範囲の 5 つから説明します。 前の決定 (ADR-0021) は便を箱に入れ、 別の決定 (ADR-0026) は席を器で起こすときに「前の版の launcher の cgroup の防壁は席には持ち込まない」と決めました。 席は shell の子で器の子ではないからです。 2026-09-25 の事故で、 席の側にも箱が要ると分かりました。

CTX1

経緯 — 便は箱の中、 席は箱の外 (ADR-0021・ADR-0026)

ADR-0021 は便 (runner / lens / 検証行) を systemd の transient scope (memory の上限つきの箱) の内側で走らせ、 溢れたときに殺されるのは箱の中の process だけにした。 上限は rules 行 2 本 (gate.job_memory_mb と host.reserve_memory_mb) から導く 2 種で、 scope を作れない host は縮退箱なしで起こすことして素の起動に戻る。 ADR-0026 は席の起動 (seat launch) を器に足すとき、 前の版の launcher が持っていた cgroup の防壁は席には持ち込まないと決めた。 席は shell の子で器の子ではなく、 NFR6 (封じ込めの外で走る器の子 process 0 本) の対象でもないからである。 席 (人と話す claude と、 席が Agent tool で起こす subagent席が起こす下請けの agent と、 それらの Bash) は user の sliceその user の process 全部の囲い に直に入る。

CTX2

事象 — 席の subagent の 1 本が host 全体を止めた

2026-09-25 12:10 JST 頃、 別 host が ssh と console の両方で login できなくなった。 原因は user の slice (MemoryHigh 100 GiB / MemoryMax 110 GiB) で 1 process が RSS 81 GB と swap 5.7 GB を使い、 slice 全体が throttle された (PSI memory full 98%・load 73)。 犯人は別 project の席の subagent が撃った sed 1 本で、 word-diff の長い行 (29〜12,663 字) に量指定子つきの後方参照を当てた破滅的 backtrack だった。 12:52 JST に TERM で消して復旧した。 同種の正規表現を配る skill や prompt は無く (grep 0 件)、 ad-hoc の 1 本だった。 便なら箱の中で 1 本が落ちて済んだが、 席には箱が無い。

CTX3

現物 — 起動行の導出・封じ込めの語列・systemd-run --scope の振る舞い

main c4d6d20 で、 席の起動行は seat/cycle/launch.rs の derive_launch (pure) が env 3 語 → claude → plugin dir の列 → host の面の引数の順で組み、 launch が役割の既定 (--model / --effort)・cd の前置・会話の引き継ぎの語を足して pane へ注入する。 登録 row には導出した行 (穴を埋める前) が載る。 起動の呼び手は 4 つ (seat launch・管理 tick の起こし直し・群の段の起こし直し・follow の起こし直し) で関数は 1 本。 便の封じ込め (pipe/confine.rs) は語列 scope_args (--user --scope --quiet --collect --unit=<name> -p MemoryMax=<mb>M -p CPUWeight=<w> -p OOMPolicy=continue) と unit 名の 1 関数 (<NAME>-<場所>-<段>-<n>-<pid>-<seq>) と probe箱を試しに 1 つ作ること (scope を 1 つ試しに作る) と閉じた理由 (no-systemd-run / no-scope / no-rules …) を持つ。 systemd-run --scope は -- の後ろの command を exec して自分は残らない (実測 — 子の親は起動した shell)。 pane の前面は claude のままで、 管理 tick席を周期で見る仕組み の「窓が shell か」の読みは変わらない。 env の前置は exec した子へ継承される。 e2e の道具箱は偽 systemd-run を PATH の先頭に積み、 実 scope を作らない。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C2 (経路は 1 本) から、 席の箱席を入れる memory の囲いの語列は便の封じ込めと同じ 1 関数 (CPU の重みの有無の引数 1 つで 2 形) とし、 unit 名も同じ 1 関数で組む。 C10 (宣言値・実測値・導出値を分ける) から、 上限は rules 行の宣言値 (user 裁定 id つき)、 道具の有無は PATH の実測値、 起動の 1 行seat launch が出す結果の 1 行の scope= はその導出値で、 行を読めない周と道具が無い周は理由の語で縮退する (止めない)。 C17 (足すときに何を外すかを名指す) から、 足すのは rules 行 1 本・起動行の頭の語列・Launch の欄 1 つ・起動の 1 行の項目 1 つで、 外すのは無い (§4 の「持ち込まない」の判断を取り消す)。 決定はしごの各段を通した — 要るか (host の login 不能・持ち主の裁定)・既に在るか (便の箱は在るが席には無い)・既存の仕組みで足りるか (足りる — 便の scope の語列と unit 名の関数をそのまま使う)・1 行で書けるか (起動行の頭に語列 1 つ)・最小か (rules 行 1 本)。 N2 (散文にしか無い規則は規則として扱わない) から、 正規表現の字面を見張る形は退ける。 ADR-0021 の便の封じ込め、 ADR-0026 の口座の管理と起動の口、 ADR-0058 の管理 tick、 ADR-0067 の起こし直し (会話 id を運ぶ) は本 ADR の前提で変えない。

CTX5

射程 — 動かすのは起動行の頭と rules 行 1 本・起動の 1 行の項目 1 つ

動かすのは (1) 席の起動行の頭 (systemd の scope の語列・上限は rules 行 seat.memory_max_mb・値 0 と読めない周と道具の無い host は素の行)、 (2) 起動の 1 行の末尾の scope= (unit 名か縮退の語)、 (3) Launch の欄 1 つ (行の読み・4 つの呼び手が自分の manifest から埋める) の 3 つ。 動かさないのは、 席の起動の口と口座の選定・登録 row の形 (雛形には頭を載せない)・trust の書き・便の封じ込め (Wrap / probe / release)・管理 tick の判定の列・host の面・役割なしの手動の入口 (account shell)。 要件は FR59 (席の起動) と NFR6 (host の資源) の範囲に収まり、 SRS の改訂を伴わない。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 1 本の暴走が machine を道連れにしないこと (席とその subagent の Bash が溢れても殺されるのは席の箱の中だけ)。 上限は宣言値 1 つであること (規則の表の行 1 本で、 席ごと・役割ごとに分けない)。 止めずに縮退すること (道具が無い machine と行が 0 / 読めない周は素の行で起こし、 理由を結果の 1 行に出す)。 経路は 1 本であること (箱の語列と unit の名は便の封じ込めと同じ関数で、 席を起こす 4 つの呼び手は同じ 1 本を通る)。

DR11 本の暴走が host を道連れにしない — 席とその subagent の Bash が溢れても、 殺されるのは席の箱の中の process だけ (持ち主の裁定) CTX2・CTX5
DR2上限は宣言値 1 つ — rules 行 1 本 (user 裁定 id つき) で、 席ごと・役割ごとに分けない (C10) CTX4
DR3止めない、 縮退する — 道具が無い host と行が 0 / 読めない周は素の行で起こし、 理由を起動の 1 行に出す (ADR-0021 と同じ極性) CTX1・CTX3・CTX4
DR4経路は 1 本 — 箱の語列と unit 名は便の封じ込めと同じ関数で、 起動の 4 つの呼び手は同じ 1 本を通る (C2・C17) CTX3・CTX4
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 席を起こす 1 行の頭に便と同じ箱を置く案 (選んだ案)、 席の Bash を hook で 1 command ずつ箱に包む案、 正規表現の字面を規則で見張る案、 machine の user 全体の囲いの上限を下げる運用で受ける案、 起動の前に箱を試しに作って作れない machine は縮退する案です。 選ばなかった 4 つは、 hook の限界・散文の規則は規則でない・ssh も同じ囲いに居る・試しの箱が test の machine を詰まらせる、 という理由で退けました。

OPT1席の起動行の頭に便と同じ scope を置く (上限は rules 行 1 本・CPU の重みは付けない・probe は撃たない)採用

rules 行 seat.memory_max_mb (MiB・既定 32768・裁定 id つき) を足す。 起動行の導出席を起こす 1 行を組む関数 (pure) は頭の語列を Option で受け、 launch が決める — 値 0 / 読めない周は無し (語 no-rules)、 systemd-run が PATH の dir に実行可能な file として無い周は無し (語 no-systemd-run)、 在れば systemd-run --user --scope --quiet --collect --unit=<name> -p MemoryMax=<mb>M -p OOMPolicy=continue -- を env 3 語の直後・claude の前に置く。 語列は便の scope_args と同じ関数 (CPU の重みの有無の引数 1 つ)、 unit 名は便と同じ unit_name (<NAME>-<target>-seat-0-<pid>-<seq>)。 probe (scope を試しに作る) は撃たない。 登録 row の雛形には頭を載せない。 起動の 1 行の末尾に scope=<unit 名|off|no-rules|no-systemd-run>。 溢れた周は箱の中の 1 process が殺され、 claude が死んだ周は管理 tick が起こし直す。 決め手は現物 (持ち主の裁定)。

席を起こす 1 行の頭に、 便と同じ systemd の scope (memory の上限つきの箱) を置く案です。 上限は規則の表の行 1 本 (既定 32 GiB)、 CPU の重みは席には付けません。 行が 0 / 読めない周と systemd-run が無い machine は頭を付けずに素の行で起こし、 結果の 1 行に理由を出します。 起動の前に箱を試しに作ることはしません。 溢れて殺されるのは箱の中の process だけで、 claude 自身が死んだ周は見回りが起こし直します。 他の席と ssh が生き、 上限が宣言値 1 つで、 語列と名が便と同じ関数である点で勝ります。 代わりに、 起こす 1 行が長くなって既存の歯の期待が動き、 session manager の無い machine では起こす行が失敗し、 上限に届いた周は claude 自身が殺されて turn が失われることがあります。 持ち主の裁定で選びました。

+ 利点

  • 席の subagent の Bash が溢れても殺されるのは席の箱の中で、 他の席と ssh は生きる (DR1)
  • 上限は rules 行 1 本の宣言値で、 裁定 id が残る (DR2)
  • 道具の無い host と行が 0 / 読めない周は素の行で起こし、 理由が起動の 1 行に出る (DR3)
  • 語列と unit 名が便の封じ込めと同じ関数で、 4 つの呼び手が同じ 1 本を通る (DR4)

− 欠点

  • 席の起動行が長くなり、 起動行を pin する既存の歯 (31 本) の期待が動く
  • probe を撃たないので、 systemd-run は在るが user の session manager が無い host では起動行が pane で失敗する (管理 tick の unit と同じ前提・その host では行を 0 にする裁定で戻せる)
  • 箱の上限に届いた周は claude 自身が殺されることがあり、 会話は管理 tick の起こし直し (--resume) で戻るが、 その周の turn は失われる
OPT2席の Bash を hook で 1 command ずつ scope に包む不採用

PreToolUse の見張り (host-guard) が撃つ command を systemd-run の scope で包む。 決め手は分析 (hook の限界)。

席の Bash を、 hook (command を撃つ前の見張り) で 1 command ずつ箱に包む案です。 落ちるのが 1 command だけで claude 自身は殺されない点で勝ります。 けれども、 hook は command を書き換えられず、 subagent の Bash は hook を通らない周が在ります。 上限も command ごとで、 席の合計 (並走する Bash と claude 自身) を抑えられません。 退けました。

+ 利点

  • 落ちるのは 1 command だけで、 claude 自身は殺されない

− 欠点

  • PreToolUse は command を書き換えられず、 subagent の Bash は hook を通らない周が在る (DR1)
  • 上限が command ごとで、 席の合計 (並走する Bash と claude 自身) を抑えられない (DR2)
OPT3正規表現の字面を見張る (規則で塞ぐ)不採用

破滅的 backtrack の形 (量指定子つきの後方参照など) を prompt や hook の規則で禁じる。 決め手は分析 (N2)。

破滅的な正規表現の形を prompt や hook の規則で禁じる案です。 今回の事故の直接の原因に当たる点で勝ります。 けれども、 散文にしか無い規則は規則として扱えず、 GNU sed には複雑度の上限が無いので塞ぐ先がありません。 次の暴走は正規表現とは限りません。 退けました。

+ 利点

  • 今回の事故の直接の原因に当たる

− 欠点

  • 散文にしか無い規則は規則として扱えず (N2)、 GNU sed には複雑度の上限が無いので塞ぐ先が無い (DR1)
  • 次の暴走は正規表現とは限らない (DR1)
OPT4user の slice の MemoryHigh を下げる (host の運用)不採用

systemd の user slice の上限を下げ、 暴走が host の他の部分に及ばないようにする。 決め手は分析 (器の外・同じ slice)。

machine の user 全体の囲い (slice) の上限を下げて、 暴走が machine の他の部分に及ばないようにする運用の案です。 器に足すものが無い点で勝ります。 けれども、 ssh の login も同じ囲いに居るので、 囲いの上限では login 不能を防げません。 machine の運用であって、 器の宣言値にも記録にもなりません。 退けました。

+ 利点

  • 器に足すものが無い

− 欠点

  • ssh の login も同じ slice に居るので、 slice の上限では login 不能を防げない (DR1)
  • host の運用で、 器の宣言値にも記録にもならない (DR2・DR3)
OPT5起動で probe を撃ち、 scope を作れない host は縮退する (便の封じ込めと同じ)不採用

便の封じ込めと同じく、 起動の前に scope を 1 つ試しに作り、 作れない host は素の行に縮退する。 決め手は分析 (歯が実 scope を作る)。

便の封じ込めと同じく、 起動の前に箱を 1 つ試しに作って、 作れない machine は素の行に縮退する案です。 session manager の無い machine でも起こす行が失敗しない点で勝ります。 けれども、 席の起動の歯 (test) は偽の systemd-run の道具箱を積まないので、 試しの箱が本物の scope を作って test を走らせた machine の systemd を詰まらせます (以前の事故と同じ形)。 席の起動は user の session manager が在る machine が前提 (見回りの unit と同じ) なので、 試しの箱が守る周がありません。 退けました。

+ 利点

  • session manager の無い host でも起動行が失敗しない

− 欠点

  • 席の起動の歯は偽 systemd-run の道具箱を積まないので、 probe が実 scope を作り user の systemd を詰まらせる (台帳 .504 の事故と同型) (DR4)
  • 席の起動は user の session manager が在る host が前提 (管理 tick の unit と同じ) で、 probe が守る周が無い (DR3)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 器は規則の表に席の箱の行 (seat.memory_max_mb・既定 32768 MiB・裁定 id つき) を持ちます。 席を起こす 1 行の頭 (env の 3 語の直後・claude の前) に systemd の scope の語列を置き、 語列は便の箱と同じ関数 (CPU の重みは席には付けない)、 箱の名も便と同じ関数で組みます。 行が 0 / 読めない周と systemd-run が PATH に無い周は頭を付けず、 起動の前に箱を試しに作ることはしません。 登録の記録の雛形には頭を載せません。 結果の 1 行の末尾に箱の名か縮退の理由が付きます。 支えるのは FR59 (席の起動) の根拠と、 NFR6 (machine の資源)・FR27 (見回り) への主張です。

採用 — OPT1
