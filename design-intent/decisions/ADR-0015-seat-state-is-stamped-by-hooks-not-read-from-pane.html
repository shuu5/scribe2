ADR-0015 — 席の busy / idle は hook の打刻で typed に持ち、 pane の字面を判定入力から外す。 target は生成 hooks.json の shell 行が渡す pane id から解く

本 ADR は IETF RFC 2119 および RFC 8174 / BCP 14 に定義される MUST / SHALL / SHOULD / MAY のキーワード解釈規約に従う。 ADR は決定時点の記録であり、 改訂は新しい ADR による supersede で行う。

§1. Context

管理役は、 席が手を止めているときにだけ 1 行を差し入れ、 手を止めているときにだけ画面を作り直します。 いまの「手を止めているか」の判定は、 画面に出る回転する印や決まり文句を読む方法で、 道具の版が変わって印が消えたときに、 動いている席へ画面の作り直しを送ってしまいました。 憲法は「席の状態は型で持ち、 画面の見た目や自由な文章を判定材料にしない」と定めています。 その通りに作り直す方法を決めます。

憲法 C3.3 は「席の状態を typed enum で持ち、 端末描画や自由文を判定入力にしない」と定める。 記録時点の器は席の idle を pane の字面 (prompt 行の右が空 ∧ 探索域に spinner の形が無い・設計 seat-autonomy.md §3 裁定 (e)) で判定している。 2026-09-11 に Claude Code 2.1.268 で走行中の印 esc to interrupt が statusline から消え、 走行中の席を idle と読んで /clear を送った (s2-07l.94)。 字面の絞り込み (.94 (A)・.96) で露出は減ったが、 本文が印の形を持つ席を永久に busy と読む残余が残り (lens-94 HIGH-3)、 C3.3 との緊張は解けていない。

hook は席の中で器の binary を起こし、 stdin JSON で session_id / transcript_path / cwd を渡す。 一方 tick と cycle は tmux の target (session:window) で席を名指す。 席の状態を hook の打刻で持つには、 hook の中で自席の target を知る経路が要る。 憲法 C2.2 は「env を直接読まない・新しい env seam を作らない」と定め、 記録時点で env に触れるのは生成 hooks.json の shell 行 "${<NAME_UPPER>_BIN:-<NAME>}" だけである。

§2. Decision

§2.1 席の状態は hook の打刻から得る typed 値であり、 pane の字面は判定入力にしない

席の側が「いま始めた」「いま終わった」「いま起きた」と判子を押し、 管理役はその判子だけを見て手を止めているかを決めます。 画面の見た目は「差し入れが届いたか」を確かめる補助にだけ使い、 手を止めているかの判定には使いません。

器 SHALL 席の状態を閉じた enum SeatState (Busy / Idle) で持つ。 値の出所 SHALL Claude Code の hook event の打刻とする: UserPromptSubmit → Busy、 Stop → Idle、 SessionStart → Idle。 打刻 SHALL <state_dir>/seat/<target>/state.jsonl へ 1 行 JSON を append し (ADR-0004 §2.1 の追記だけの形・event で出所を名乗る = C10)、 tick と cycle SHALL 最終行を一次にする。 tick と cycle SHALL NOT pane の字面を idle の判定入力にしない (C3.3)。 pane の字面 MAY 注入の送達確認 (prompt 行の特定・目印の消費) にだけ使う。 本決定は seat-autonomy.md §3 の裁定 (e) を supersede する。

§2.2 target は生成 hooks.json の shell 行が渡す pane id から解く (core は env を読まない)

判子を押す側は、 自分がどの窓にいるかを知る必要があります。 それは、 器が自動生成する hook の設定行が tmux の窓の番号を引数として渡すことで解決します。 器の本体は環境変数を読みません。 読むのは生成された設定行だけで、 場所も生成器も今まで通り 1 つです。

生成される hooks/hooks.json の command 行 SHALL --pane "$TMUX_PANE" を渡し、 core SHALL その pane id から tmux display-message -p -t <pane> で target を解く。 core SHALL NOT env を読まない (C2.2)。 C2.2「新しい env seam を作らない」の解釈: env に触れる場所は生成 hooks.json の shell 行の 1 面に留まり (既存の ${<NAME_UPPER>_BIN} と同じ生成器 cargo xtask gen-manifest)、 core は typed な引数 (--pane) で受ける。 本 ADR はこれを「seam の場所を増やさない」充足形として記録する (MUST NOT be read as a new seam in core)。 --pane が空 (tmux の外) の周 SHALL 打刻せず黙る (打刻 hook は guard ではない・ADR-0014 §2.1 の定義)。

§2.3 打刻が無い・読めない・古い周は注入しない

判子が無い席、 判子が読めない席、 「始めた」の判子が古いまま止まっている席には、 差し入れも作り直しも送りません。 どれも「手を止めている」の証拠ではないからです。 理由はそれぞれ別の言葉で記録に残します。

tick と cycle SHALL 次の周に注入も作り直しもしない (fail-closed): 最終行が Busy／state.jsonl が無い (state-missing)／読めない (state-unreadable)／Busy の ts が rules 行 seat.tick_stale_s より古い (state-stale・hook が死んだ疑い)。 理由 SHALL typed な語 (既存の noop 語彙の内側) で判定行に出す。 器 SHALL NOT missing を idle に、 stale を busy に読み替えない。 打刻 hook 自身 SHALL 席を止めない (stdout 0 byte・rc 0・失敗しても黙る) = 極性一覧に載せない。

§2.4 射程外

この記録が決めるのは「状態の出所」「窓の解き方」「判子が無いときの倒れ方」だけです。 作り直しが本当に起きたかの証拠、 差し入れが読まれたかの証拠、 context の測り方は別に決めます。

次は本 ADR の決定ではない (MUST NOT be read as such): 作り直しの証拠 (SessionStart の打刻 ts と /clear 送達 ts の突合) と送達の証拠 (UserPromptSubmit の打刻 ts と注入 ts の突合) の契約 (設計 seat-state.md §6)、 context の計測 (meter・cap guard)、 cycle の lock、 stale の閾値の実値 (rules 行 seat.tick_stale_s を共用・変えるなら C5)、 doctor による sid と heartbeat の突合。

§3. Consequences

良い面は、 道具の版で印が変わっても判定が壊れなくなること、 そして「手を止めているか」の根拠が席自身の判子という型のある事実になることです。 悪い面は、 判子の仕組みが載っていない席 (古い版の席や hook が無い席) には何も届かなくなること。 それと、 hook が死んで判子が止まると、 その席は放置されます。 放置は記録に残るので人が気づけます。

Positive: C3.3 の充足形が実在する (typed enum + 出所付きの打刻)。 版依存の字面集合 (spinner の frame・statusline の文言) と探索域の記述を器と設計 doc から消せる。 idle の誤判定が「走行中の席へ /clear」(destructive) 側に倒れる経路が構造で消える。

Negative (受け入れるコスト): hook が載らない席 (v1 の席・plugin 未 install) は state-missing で永久に注入されない (併走期間は tick の対象を v2 の席に限る)。 hook が死んだ席は state-stale で放置される (fail-closed の代償・記録から人が拾う)。 hooks.json の entry が 2 つ増え、 hook の呼出回数が turn ごとに 2 回増える (打刻は append 1 行・hook 予算の内側)。

§4. Alternatives Considered

4 つの案を退けました。 印の読み方を改良し続ける案は、 次の版でまた壊れます。 席が打った命令文や差し入れの本文から窓を読む案は、 自由な文章を判定材料にすることになります。 OS の内部情報から席を特定する案は、 OS に依存して保証もありません。 記録 file の更新時刻で推測する案は、 時間に頼る場当たりの判定です。

(A) 字面の絞り込みを続ける (.94 (A)・.96)。 却下: 印は版で変わり (実測 2026-09-11)、 本文が印の形を持つ席の残余も消えない。 C3.3 との緊張が恒久化する。

(B) tool_input.command や prompt 本文から --target を読んで hook 側で target を得る。 却下: 自由文を判定入力にする形そのものである (C3.3)。 heartbeat の command 行に依存し、 別の書き方をした周に黙って外れる。

(C) /proc/<pid>/fd から transcript を辿り sid を得て、 tick が pane の pid から逆引きする。 却下: OS 依存で、 transcript の fd が開いている保証が無い (append して閉じる周は見えない)。

(D) transcript の mtime で busy を推定する。 却下: 時間依存の ad-hoc 判定であり、 憲法の順位 1 位 (ad-hoc 禁止) に反する。 lens-94 が同型の 0.5 秒二重 capture 案を退けたのと同じ理由。

§5. Trace

出所は、 実際に起きた事故の記録と、 hook がどんな情報を受け取れるかを実物で確かめたこと、 そして設定行がすでに環境変数を 1 つ展開している事実です。

  • 事故の記録 (2026-09-11・s2-07l.94): Claude Code 2.1.268 で esc to interrupt が statusline から消え、 tick が走行中の席を idle と読み /clear を送った。 暫定処置は字面の絞り込み (.94 (A)・.96) で、 分岐 (B) = 本 ADR は planner 裁定で別便とされた。
  • hook の入力の実測 (同日・crates/<NAME>/src/hook/mod.rs): stdin JSON から読む key は cwd / transcript_path / session_id 系で、 tmux の target は無い。 記録時点の hooks.json の event は SessionStart / PreToolUse / PermissionRequest の 3 つ (生成器 cargo xtask gen-manifest・render_hooks)。
  • env seam の現物 (同日): 生成 hooks.json の command 行は "${<NAME_UPPER>_BIN:-<NAME>}" を shell で展開しており、 core は env を読まない (C2.2 の既存の充足形)。 §2.2 はこれと同じ場所へ --pane "$TMUX_PANE" を足す。
  • Claude Code の hook event に UserPromptSubmit / Stop / SessionStart が在ることの実測 (同日・host の settings の lint 出力に列挙)。
  • 残余の記録 (.96 notes・.97 lens MEDIUM-2): 作り直しと送達の証拠は字面では閉じず、 本 ADR の打刻を根治とする申し送りが 2 件在る (§2.4・設計 §6)。
