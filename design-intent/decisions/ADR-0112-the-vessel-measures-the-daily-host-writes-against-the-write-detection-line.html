設計判断記録 (ADR) scribe2 — 書き込みの検出線

書き込みの検出線 — 器は host の面が宣言した block 装置の 1 日の書き込みを管理 tick の周で測って host の根に記し、 書き込みの検出線 (7 日平均・1 日・持ち主の段の連続日数) と比べて doctor の行と席の 1 行で示し、 作業は止めない

host の NVMe の書き込みは起動からの累計の実測で 1 日約 4.9 TB に達し、 今の速さのままなら記憶装置の寿命は約 230 日と推される。 器にはこの量を測って知らせる口が無く、 持ち主と席は手で読んで割り算している。 本 ADR は持ち主の値の裁定 (裁定 id user 2026-10-03T02:42Z) に沿い、 器が管理 tick の周に相乗りして装置ごとの 1 日の書き込みを host の根に記し、 7 日平均・1 日・続いた日数の線と比べて doctor の行と席の 1 行で示すと決める。 測れない日と欠けた日は 0 と書かず、 作業は止めない。 SRS では FR113 (書き込みの検出線) と AC90 がこの約束を持つ。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が動かす開発の AI の session、 「管理 tick」は器が席を 15 秒ごとに見回る定期の周です。 host の NVMe の記憶装置は、 起動からの累計の実測で 1 日約 4.9 TB を書いており、 今の速さのままなら寿命は約 230 日と推されます。 けれども器にはこの量を測る仕組みが無く、 持ち主と席は手で読んで割り算しています。 この記録は持ち主の値の裁定に沿い、 器が管理 tick の周のついでに装置ごとの 1 日の書き込みを測って host 共有の置き場に記し、 7 日の平均 (1 日 1.5 TB)・1 日 (3 TB)・続いた日数 (3 日) の線と比べて、 器の状態を照らす口 (doctor) の 1 行と席への 1 行で示すと決めます。 測れなかった日と一部が欠けた日は 0 と書かず、 別の語で残します。 線を越えても作業は止めません。 要件書 (SRS) では、 書き込みの検出線の要件 (FR113) と受け入れの基準 (AC90) がこの約束を持ちます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 5 つで示します。 host の記憶装置の書き込みの実測と寿命の見込み、 持ち主の値の裁定、 器に在るものと無いもの、 要件書に合う要件が無いこと、 憲法の向きとこの記録が動かす範囲です。

CTX1

実測 — host の NVMe の書き込みは 1 日約 4.9 TB で、 今の速さなら寿命は約 230 日と推す

host には NVMe の drive が 2 台在り、 書き込みの多い 1 台は起動からの累計 (kernel が装置ごとに出す書いた区の数) で約 8.2 日に約 39.7 TB、 1 日の平均で約 4.9 TB だった (2026-10-03 の実測)。 もう 1 台は約 0.2 TB だった。 drive の定格の書き込み量 (TBW) の見込みと照らすと、 今の速さのままなら残りの寿命は約 230 日と推す (推定で、 実測ではない)。 ADR-0111 は変異検査 (検出線) を着地ごとから 1 日 1 回に間引いたが、 書き込みのうちどれだけがどの仕事から来るかは分けて示しておらず、 間引いた効きを日ごとに測る物差しも器に無い。

CTX2

裁定 — 7 日の平均で 1 日 1.5 TB 以下・1 日 3 TB を越えた日も知らせる・持ち主へは 3 日続けて越えた時だけ・作業は止めない

持ち主は 2026-10-03T02:42Z に host の書き込みの値を裁定した (裁定 id持ち主の決定を指す印 user 2026-10-03T02:42Z・裁定日 2026-10-03)。 要旨は 4 点 — 7 日の平均で 1 日 1.5 TB 以下を線にする・1 日に 3 TB を越えた日も知らせる・持ち主へ知らせるのは 3 日続けて越えた時だけ・越えても作業は止めない。 逐語は本 repo の外の台帳にだけ在り、 本 file には写さない。 器の仕組みを置くこと・測り方・示す口・3 日続けての数え方・装置が複数ある host の扱いは、 持ち主の常設の裁定 (決めてほしいことは推奨で進める) の下で orchestrator が推奨を採った。

CTX3

現物 — 器に書き込みを測る口は無く、 使い回せる周・置き場・口は在る

器には block 装置記憶装置の書き込みを読む code が無く、 持ち主と席は装置の stat file を手で読んで割り算している。 使い回せるものは在る。 管理 tick席を見回る定期の周 は席ごとに rules 行裁定つきの規則の行 seat.tick_interval_s (15 秒) の周で撃たれ、 判定の後に返りを捨てる区画を持つ (ADR-0108 の全部の書き直しも同じ区画)。 host の根host 共有の置き場は state dir の親の下で置き場を跨いで 1 つで、 管理 tick が群の判定を host の lock の内で撃つ前例を持つ (ADR-0066)。 fleet の store の lock は pid と起動時刻で死んだ lock を回収する。 host の面host 固有の宣言は tick の宣言の表 [[tick]] と端末の表 [[device]] (ADR-0076) を持ち、 rules 行は置けない。 doctor器の状態を照らす口 は module ごとに 1 行を足す形で、 消費側の板器の外の表示の画面 (器の外の表示面) は doctor と tick status の行を key の名で読む前例を持つ。 席の hook は UserPromptSubmit の追加文脈AI への添え書きに群の逼迫の 1 行を出す前例を持つ。 入力欄への差し込みは SRS FR44 が閉じた列で、 器が持ち主へ直に届ける口は無く、 器が台帳に issue を起こすのは初期化の 1 か所だけである。

CTX4

SRS — 既存の要件は host の装置の書き込みを測らない

SRS の FR27 (管理 tick) の仕事の列に書き込みの標本は無く、 NFR6 (host の資源) は封じ込めの外の子 process と検証の行の並列度の約束で、 書き込みの量は測らない。 FR44 (差し込みの閉じた列) は動かさない。 器が host の装置の書き込みを測って示す要件は、 新しい FR113 (書き込みの検出線書き込み量を比べる線) と AC90 が持つ。

CTX5

憲法の向きと本 ADR の射程

C1 は規則の値を manifest の rules 行に持つことを求めるので、 線の値 2 つだけでなく窓の 7 日と持ち主の段持ち主に知らせる段の 3 日も rules 行にする。 C5 は rules 行を裁定 id なしに足すことを断る。 C3 は host ごとの dir に状態の真実を置かないことを求める。 本 ADR の記録は装置の累計 (真実は kernel の数) から取った出所つきの実測で、 host・口座・席・lease・退役の状態を持たず、 消えても判定は測っていない側に倒れるだけなので、 host の根に置く (群の今の口座を同じ根に実効の記録として置いた ADR-0049 の前例)。 C10 は宣言値と出所つきの実測を型で分けるので、 測れない日と再起動で欠けた日を 0 や完全な値と書かない。 C10.2 と N3 は host 固有の値を manifest にだけ置き code が分岐しないことを求めるので、 装置は host の面の値にし、 code は装置の名から path を組まない。 C15 は台帳を task と裁定だけに使う。 C17.2 は足す前に消すものを名指すことを求め、 本 ADR が消すのは手で撃つ使い捨ての読みである。 本 ADR は ADR を書く条件のうち 1 (C3 と C10 の読み)・3 (記録の on-disk の形と host の面の表と rules 行)・4 (却下案を残す価値のある分岐) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 書き込みが線を越えた日と続いた日数を手の読みに頼らずに知ること。 越えても作業を止めないこと。 測っていないものを測ったと数えないこと。 新しい依存・定期の仕組み・常駐の process・入口・差し込みの種類・台帳の書き口を増やさないこと。 線の値と装置を決まった置き場に置き、 code が host ごとの値で分かれないことです。

DR1兆しを早く見せる — 書き込みが線を越えた日と続いた日数を、 持ち主と席が手の読みに頼らずに知る CTX1・CTX2
DR2作業を止めない — 越えても管理 tick・gate・着地の rc と字を変えない (裁定の 4 点目) CTX2
DR3測っていないものを測ったと数えない — 測れない日と欠けた日を 0 や完全な値と書かない (C10) CTX5
DR4増やさない — 新しい依存・timer・常駐の process・verb・差し込みの種類・台帳の書き口を足さず、 在る周と面を使い回す (C17・A3・FR44) CTX3・CTX4
DR5値の置き場を守る — 線の値は裁定つきの rules 行に、 装置は host の面に置き、 code は host の値で分岐しない (C1・C5・C10.2・N3) CTX5
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 7 つ並べます。 管理 tick のついでに測って host 共有の置き場に記し、 doctor の行と席への 1 行で示す案 (選んだ案) と、 選ばなかった 6 つです。 選ばなかった案は、 drive 自身が数える書き込みの量 (SMART) を外部の道具で読む案・再起動を kernel の起動ごとの id (boot_id) で見分ける案・測るだけの専用の定期の仕組み (timer) を足す案・記録を器の出来事の記録 (event log) へ書く案・越えたことを席の入力欄へ差し込む案・越えた日に器が台帳へ memo を起こす案です。

OPT1管理 tick に相乗りして装置の累計から 1 日の書き込みを host の根に記し、 書き込みの検出線と比べて doctor の行と席の追加文脈の 1 行で示す採用

host の面の新しい表が名指す block 装置の stat file を、 管理 tick の判定の後の区画で読み、 host の根の記録を fleet の store の lock の内で 1 回だけ進める。 線は rules 行 4 本で、 判定の 1 本の関数を doctor と席の hook が呼ぶ。 決め手は在る周・置き場・面・口を使い回せることと、 測れない日を語で分けられること (CTX3・CTX5)。

host ごとの宣言の file に書いた記憶装置ごとに、 kernel が出す書いた量の累計を管理 tick の周のついでに読み、 1 日 (UTC) の書き込みを host 共有の置き場に記します。 規則の行 4 本の線と比べ、 doctor の行と、 越えた回だけ席への 1 行で示します。 手の読みが要らなくなり、 黙った席も次の合図の turn で読め、 作業と既存の出力を変えず、 測れない日と欠けた日を別の語で残して下限の値だけで越えた日も越えと数え、 新しい依存や仕組みを足さず、 値と装置を決まった置き場に置く点で勝ります。 代わりに、 管理 tick の無い host や tick が止まった間は測れないこと、 持ち主へ直に届ける口が無く持ち主向けの札は器の外の表示の画面を待つこと、 ごく短い起動の後の再起動は見分けられずその分を少なく数えること、 host 共有の置き場に版の違いをまたぐ形の file が 2 つ増えることを引き受けます。

+ 利点

  • 装置ごとの 1 日の書き込みと続いた越えの日数が doctor の 1 行に出て、 手の読みが要らなくなる (DR1)
  • 越えた周は席の追加文脈に 1 行が出て、 黙った席も次の合図の turn で読める (DR1)
  • 管理 tick・gate・着地・doctor の rc と既存の行の字を変えない (DR2)
  • 測れない日と欠けた日を unmeasured測れなかった日 と partial欠けを含む下限の値 で残し、 下限の和だけで越えた日は越えと数える (DR3)
  • 新しい依存・timer・常駐の process・verb・差し込みの種類・台帳の書き口を足さない (DR4)
  • 線の値は rules 行 4 本に、 装置は host の面に在り、 code は host の値で分岐しない (DR5)

− 欠点

  • 管理 tick の無い host と tick が止まっている間は測れず、 その日は partial か unmeasured になる (DR1)
  • 器から持ち主へ直に届ける口は無く、 持ち主向けの札は消費側の板が owner=yes を読んで出すまで出ない (DR1)
  • 再起動の後の最初の読みが前の boot の最後の読み以上だと減りで見分けられず、 その分だけ少なく数える (DR3)
  • host の根に装置ごとの file が 2 つ増え、 跨版の形 (schema=1) を持つ
OPT2drive の SMART の書いた量を読む不採用

NVMe の drive が自分で数える書いた量と摩耗の割合を、 外部の道具 (smartctl や nvme-cli) で読む。 決め手は依存と権限 (CTX3・CTX5)。

NVMe の drive が自分で数えている書いた量と摩耗の割合 (SMART) を、 外部の道具で読む案です。 drive 自身の累計なので再起動を跨いでも欠けず、 寿命の割合も同じ読みで取れる点で勝ります。 けれども、 管理者の権限 (root) と外部の道具が要り、 依存する OSS を足すこと (持ち主の承認が要る A3) に当たります。 道具と drive の種類ごとに出力の形も違い、 読み手の形が増えます。

+ 利点

  • drive 自身の累計なので再起動を跨いでも欠けない (DR3)
  • 寿命の割合も同じ読みで取れる (DR1)

− 欠点

  • root の権限と外部の道具が要り、 依存 OSS の追加 (A3) に当たる (DR4)
  • 道具と drive の種類ごとに出力の形が違い、 読み手の形が増える (DR4)
OPT3再起動を boot_id で見分ける不採用

標本ごとに kernel の boot_id を記し、 変わった周を再起動と見分ける。 決め手は読む path の数と得られる精度 (CTX3)。

読みの 1 回ごとに kernel の起動ごとの id (boot_id) を記し、 変わった回を再起動と見分ける案です。 起動してすぐ再起動して累計の減りが見えない場合も見分けられる点で勝ります。 けれども、 読む場所と記録の欄がもう 1 つずつ増えるのに、 得られるのは 1 回の読みぶんの精度だけです。 止まる前の最後の読みの後に書いた分はどちらの案でも欠けるので、 再起動の日はどちらでも下限の値になります。

+ 利点

  • 前の boot がごく短く累計の減りが出ない再起動も見分けられる (DR3)

− 欠点

  • 読む path がもう 1 つ増え、 記録の欄も増える (DR4)
  • 得は 1 標本ぶんの精度だけで、 停止の前の最後の標本の後の書き込みはどちらでも欠け、 再起動の日はどちらでも partial になる (DR3)
OPT4書き込みを測る専用の timer unit を足す不採用

管理 tick と別に、 書き込みを測るだけの systemd の timer unit を host に足す。 決め手は unit の種類と口の数 (CTX3)。

管理 tick と別に、 書き込みを測るだけの systemd の定期の仕組み (timer) を host に足す案です。 席の無い host でも測れ、 測る間隔を管理 tick と別に決められる点で勝ります。 けれども、 仕組みの種類が増え、 書く口・外す手・doctor の照らし合わせも増えます (憲法 C17 は、 足す前に既に在るもので足りるかを問うことを求めます)。 席ごとに 1 組と決めた管理 tick の仕組み (ADR-0030) とも別の形を持ちます。

+ 利点

  • 席の無い host でも測れる (DR1)
  • 測る周期を管理 tick と別に決められる

− 欠点

  • unit の種類が増え、 書く口・撤去・doctor の照合も増える (C17) (DR4)
  • 席ごとに 1 組の tick の unit (ADR-0030) と別の形を持つ (DR4)
OPT5標本と閉じた日を event log へ書く不採用

標本と閉じた日を、 置き場の event log に event として追記する。 決め手は置き場の数と量 (CTX3)。

測った値と閉じた日を、 器の出来事の記録 (event log) に追記する案です。 今の追記の形と読み手を使え、 記録が憲法 C3 の言う 1 つの置き場に近い点で勝ります。 けれども、 出来事の記録は器の作業記録の置き場ごとに在るので、 host に 1 つの記憶装置の記録が置き場の数に割れます。 15 秒の周なら 1 日に約 5,760 行が足され、 記録が肥えて読む口が遅くなります。

+ 利点

  • 既存の追記の形と読み手を使える
  • 記録が C3 の言う 1 つの置き場に近い (DR3)

− 欠点

  • event log は state dir ごとに在り、 host に 1 つの装置の記録が置き場の数に割れる (DR3)
  • 15 秒の周なら 1 日約 5,760 行が足され、 event log が肥えて読む口が遅くなる (DR4)
OPT6越えたことを席の入力欄へ差し込んで知らせる不採用

越えた周に、 席の入力欄へ 1 行を差し込んで知らせる。 決め手は SRS FR44 の閉じた列 (CTX3・CTX4)。

越えた回に、 席の入力欄へ 1 行を差し込んで知らせる案です。 黙った席でも turn を起こして届き、 人の目に見える形で出る点で勝ります。 けれども、 入力欄への差し込みは要件書の FR44 が種類を閉じた列で、 新しい種類を足すには要件書の改訂と ADR が要ります。 越えが続く間は差し込みが繰り返され、 席の作業の turn を使います。

+ 利点

  • 黙った席でも turn を起こして届く (DR1)
  • 対話面の席に人の目に見える形で出る (DR1)

− 欠点

  • 入力欄への差し込みは FR44 が閉じた列で、 新しい種類を足すには SRS の改訂と ADR が要る (DR4)
  • 越えが続く間は差し込みが繰り返され、 席の作業の turn を使う (DR2)
OPT7越えた日に器が台帳へ memo を起こす不採用

持ち主の段に届いた日に、 器が台帳に memo を 1 件起こす。 決め手は C15 と台帳の書き口 (CTX3・CTX5)。

持ち主へ知らせる段に届いた日に、 器が台帳 (beads) に memo を 1 件起こす案です。 持ち主と席が台帳で追え、 席が見落としても残る点で勝ります。 けれども、 台帳は task と裁定だけを持つと憲法 C15 が決めており、 測った記録は器の記録が持つものです。 器が台帳に issue を起こすのは初期化の 1 か所だけなので、 新しい書き口も要ります。

+ 利点

  • 持ち主と席が台帳で追え、 席が見落としても残る (DR1)

− 欠点

  • 台帳は task と裁定だけを持ち (C15)、 実測の記録は器の記録が持つ (DR3)
  • 器が台帳に issue を起こすのは初期化の 1 か所だけで、 新しい書き口が要る (DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 host ごとの宣言の file に、 測る記憶装置の名と、 kernel が書いた量を出す file の場所を 1 行ずつ書きます。 器は管理 tick の周のついでにその file を読み、 host 共有の置き場の記録を、 鍵を握って 1 回だけ進めます。 線は規則の行 4 本 (平均の線・1 日の線・窓の 7 日・持ち主へ知らせる 3 日) で、 越えたかの判定は 1 本の関数が持ち、 doctor の行と席への 1 行がそれを呼びます。 照会する要件は 4 つで、 書き込みの検出線の要件 (FR113) と管理 tick の要件 (FR27) はこの記録が支える側、 差し込みの閉じた列 (FR44) と hook の予算 (NFR5) は今の約束をそのまま保つ側です。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 6 つと、 代わりに引き受けること 7 つです。 良くなるのは、 手の読みが doctor の 1 行に置き換わること、 越えた回に席へ 1 行が出て持ち主の段の印も載ること、 作業と既存の出力が変わらないこと、 測れない日と欠けた日を測った値と混ぜないこと、 値と装置が決まった置き場に在って新しい仕組みが増えないこと、 書き込みを減らす手の効きを同じ物差しで見られることです。 引き受けるのは、 持ち主へ直に届ける口が無いこと、 管理 tick の無い host では測れないこと、 日の境目の前後が少し隣の日へ寄ること、 再起動の日が欠けて下限の値になること、 host 共有の置き場に file が 2 つ増えること、 越えが続く間は席の turn ごとに 1 行が載ること、 線を越えても器は書き込みを減らさないことです。

✓ 良い結果

  • ●装置ごとの 1 日の書き込み・窓の平均・続いた越えの日数が doctor の 1 行に出て、 持ち主と席が stat file を手で読んで割り算する使い捨ての読みを置き換える (C17.2 の消すもの)
  • ●越えた周は席の追加文脈に装置ごとの 1 行が出て、 黙った席も次の合図の turn で読める。 持ち主の段に届いた行は owner=yes を持ち、 消費側の板が key で読んで持ち主向けの札を出せる
  • ●作業は止まらない。 管理 tick・gate・着地・doctor の rc と既存の行の字は変わらず、 表の無い host では doctor の外形も 1 byte も変わらない
  • ●測れない日と欠けた日は unmeasured と partial (下限) で残り、 測った値と混ざらない (C10)。 下限の和だけで線を越えた日は越えとして立つので、 欠けが越えを隠さない
  • ●線の値は裁定つきの rules 行 4 本に在り (C1・C5)、 装置は host の面の値で、 code は host の値で分岐しない (C10.2・N3)。 新しい依存・timer・常駐の process・verb・差し込みの種類・台帳の書き口は増えない
  • ●ADR-0111 (変異検査を 1 日 1 回に間引いた判断) のような書き込みを減らす手の効きを、 同じ物差しで日ごとに見られる

⚖ トレードオフ・代償

  • ●器から持ち主へ直に届ける口は無い。 持ち主は doctor の行か席の行か消費側の板の札を見るまで知らず、 板が key を読む形に合わせるまで持ち主向けの札は出ない
  • ●管理 tick の無い host と tick が止まっている間は測れず、 その日は partial か unmeasured になる (専用の timer を足さない代償)
  • ●日の境目は UTC の日付が変わった最初の標本で、 境目の前後の書き込みは最大で周期の 2 倍ぶん隣の日へ寄る
  • ●再起動の日は停止の前の最後の標本の後の書き込みが欠けて partial (下限) になる。 再起動の後の最初の読みが前の boot の最後の読み以上だと減りで見分けられず、 前の読みの分だけ少なく数える (前の boot がごく短いときだけ・boot_id を読まない代償)
  • ●host の根に装置ごとの on-disk の file が 2 つ増え、 schema=1 の跨版の形を持つ。 装置を替えた周は stat-mismatch の間は数が動かず、 人が装置の dir を退避する (N1.2)
  • ●越えが続く間は、 席の turn ごとに装置ごとの 1 行 (約 40 token) が追加文脈に載る
  • ●器は線を越えても書き込みを減らさない。 減らす手 (変異検査の回数・一時の木の置き場など) は別の判断で、 本 ADR は効きを測る物差しだけを足す
