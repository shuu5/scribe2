設計判断記録 (ADR) scribe2 — 群の移り先の鍵と予約

群の移り先は残量の鍵で並べ、 群ごとの予約を宣言順に導出し、 群の名は Tier と数字に固定する — 移り先は「7 日窓と役割の model の 7 日窓の残量の小さい方が大きい順 → 7 日窓の reset が早い順 → 宣言順」で並べた候補から、 群を宣言順に見て「どの群の今の口座でもなく先の群の予約でもない先頭」を各群の予約とし、 予約は記録せず周ごとに lock の内側で導出し、 便の起動は排他しない (ADR-0049 の「候補の順 = 宣言順」と ADR-0055 / ADR-0068 の移り先の「候補の先頭」を部分 supersede・要件 FR38 と AC41 の改訂を伴う)

ADR-0049 は群の移り先を「宣言の候補の順で、 門を通る最初の口座」と決め、 ADR-0068 は門を「他の群の今の口座でない ∧ 閾値未満」の 2 条件にした。 2026-09-26 に持ち主は、 移り先が宣言順で黙って決まるのは要望 (Fable と 7 日窓の残量と reset までの時間を見て群ごとに最適な口座を選ぶ) と違うと指摘し、 残量の鍵で並べる形を裁定した (00:43Z)。 差し戻し (Fable の窓が高く 7 日窓が低い口座が選ばれないか) には、 門がモデル別 7 日窓も閾値で断り、 鍵が 2 つの窓の残量の小さい方を取ることで答えた。 群が増えても移り先が被らないよう、 群ごとの予約を宣言順に導出し (記録しない)、 予約は他の群の移動と予約を排他するが便の起動は排他しない。 群の名は Tier<数字> に固定し、 宣言順は数字の昇順に限る (00:48Z)。 要件 FR38 と AC41 (v0.25) の改訂を伴う。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「便」は契約 1 本を実装から着地まで運ぶ 1 回の走り、 「口座」は席や便が使う Claude Code の login 単位、 「群」は同じ口座を共有する project のかたまりです。 群の口座の残りが線を越えたとき、 群は別の口座へ移ります。 これまで移り先は「宣言に並べた候補の順で、 条件を満たす最初の口座」でした (ADR-0049)。 2026-09-26 に持ち主は、 それは要望 (Fable の窓と 7 日の窓の残りと、 reset までの時間を見て、 群ごとに最適な口座を選ぶ) と違うと指摘し、 残りの量で並べる形を裁定しました。 並べ方は、 7 日の窓とその席の model の 7 日の窓の残りの少ない方が多い順 → 7 日の窓の reset が早い順 → 宣言の順、 です。 差し戻し (Fable の窓が高くて 7 日の窓が低い口座が選ばれないか) には、 候補に入る条件が model の窓も線で断り、 並べ方が 2 つの窓の残りの少ない方を取ることで答えました。 群が幾つ増えても移り先が被らないよう、 群ごとの「次に移る口座 (予約)」を宣言の順に先の群から決め、 予約は file に残さず毎周計算し直します。 予約は他の群の移動と予約を避けますが、 便の起動は避けません。 群の名前は Tier1・Tier2 のように Tier<数字> に固定します。 要件書の FR38 と AC41 (版 0.25) の改訂を伴い、 同じ PR で land します。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (宣言の順)・別 project からの報告と裁定 1 (残りで並べる)・差し戻し (Fable の窓)・裁定 2 (予約と Tier の名)・器の今の部品・これまでの決まり・この判断の範囲の 7 つから説明します。 前の決定 (ADR-0049) は、 群の宣言に候補の口座を並べ、 「並べた順が候補の順」とし、 移り先を「候補の順で条件を満たす最初の口座」と決めました。 後の決定 (ADR-0055・ADR-0068) はその形を受け継ぎ、 条件を「他の群がいま使う口座でなく、 3 つの窓とも線の下」の 2 つにしました。 一方で、 便に口座を渡す選び方 (ADR-0042) は「7 日の窓の reset が早い順」で動的に並べる仕組みを持っていました。 つまり動的に並べる部品は器に在り、 群の移り先だけが宣言の順でした。 2026-09-26 に別 project (tsuzuri) の設計席が持ち主の指示で器の仕様を確かめ、 移り先が宣言の順で黙って決まるのは持ち主の要望と違うと報告しました。 持ち主は「orchestrator は Fable が既定なのに、 Fable の窓が 100% や 95% 以上の口座が優先的に選ばれないか。 Fable が高くて 7 日の窓が高くない状況は起きる」と差し戻しました。 実測で答えは 2 段でした。 候補に入る条件は 3 つの窓の全部を線で断り、 実データの model 別の行は Fable だけなので、 Fable が 95 以上の口座は候補に入りません。 並べ方の 1 つ目は 2 つの窓の残りの少ない方なので、 Fable 90 / 7 日 10 の口座は残り 10 として、 Fable 40 / 7 日 60 の口座 (残り 40) の後ろに沈みます。 残る穴は「席の model の行を持たない口座」で、 その口座は最後に並べます。 次に持ち主は、 群は幾らでも増え、 各群に口座を 1 つ占有させる想定 (新しい便と他の群の移動は弾き、 動いている便は残す) なので、 同じ並べ方を全群に当てると次の移り先が全群で被る、 群の中で次の移り先を占有する「予約」が要る、 予約は他の群の移動と予約を避けるが便の起動は避けない、 優先は群の並び順 (Tier1 → Tier2)、 名前は Tier<数字> に固定したい、 と裁定しました。 器の部品を見ると、 移動は見回りも 1 周も machine 全体の lock の内側で行い、 移った群はその場で記録を書き、 後の群はそれを読んで避けるので、 2 つの群が同じ周に同じ口座へ飛ぶ事故は既に起きません。 足りないのは優先で、 先に線を越えた群が最良の口座を取っていました。 決まりの側では、 宣言値と実測値と導出値を分ける・足すときに外す物を名指す・道は 1 本、 が効きます。 動かすのは、 並べ方・予約の導出・名前の形の 3 か所だけで、 候補に入る条件・lock・記録・承認の記録・退避・起こし直し・便に口座を渡す選び方・種の決め方は動かしません。

CTX1

経緯 — 移り先は宣言の候補の順 (ADR-0049 / ADR-0055 / ADR-0068)

ADR-0049 は群 (同じ口座を共有する project のかたまり) の宣言に候補の口座の列を持たせ、 「宣言順が候補の順」とし、 移り先を「候補の順で門候補に入るための条件を通る最初の口座」、 記録の無い周の今の口座 (種) を「候補の先頭」と決めた。 ADR-0055 は第 3 段の移り先を同じ形で受け継ぎ、 ADR-0068 は門を「他の群の今の口座かたまりがいま使う口座でない ∧ 3 窓とも閾値未満」の 2 条件にして稼働中の便の口座を候補に戻した。 種はその後の設計 (account-lifecycle.md §28・s2-07l.641) で「宣言順で前の群の種でない最初の候補」になり、 両群が同じ候補の列を宣言しても初期状態で同じ口座に乗らない。 一方、 便用の口座選定便に口座を渡す選び方 (ADR-0042) は「7 日窓の reset が早い順 → 走行中の便数 → label」の動的な並べ鍵候補を並べる比較の値の組を持つ。 動的に並べる機構は器に在り、 群の移り先だけが宣言順だった。

CTX2

relay と裁定 1 — 移り先は残量窓の使用率の残りの鍵で並べる

2026-09-26 に tsuzuri (別 project) の設計席が、 持ち主の指示で器の群の仕様を確かめ、 移り先が宣言順で黙って決まるのは持ち主の要望 (Fable と 7 日窓の残量と reset までの時間を考慮して群ごとに最適な口座を選ぶ) と違うと報告した (00:20Z・要旨)。 席は候補を集合とし順は同点の tie-break にだけ使う形と、 鍵 (7 日窓とモデル別 7 日窓の残量の小さい方が大きい順 → 7 日窓の reset が早い順 → 宣言順) を提案し、 持ち主は差し戻しの後にその形を裁定した (00:43Z・要旨)。 5 時間窓は門にだけ使い鍵に入れない (5 時間窓は数時間で開き直るので並べ順の材料にすると順が揺れる。 ADR-0042 も 5 時間窓を便用の並べ順に入れていない)。

CTX3

差し戻し — Fable の窓が高く 7 日窓が低い口座

持ち主は「orchestrator は Fable が既定なのに、 Fable の窓が 100% や 95% 以上の口座が優先的に選ばれる可能性が残らないか。 Fable が高くて 7 日窓が高くない状況は起きる」と差し戻した (00:36Z・要旨)。 実測で 2 段の答えを得た。 (1) 門は 3 窓 (5 時間・7 日・モデル別 7 日) の全部を閾値 (85 / 95 / 95) で断り、 実データのモデル別の行は Fable だけ (計測 6,882 行の全部) なので、 Fable が 95 以上の口座は候補に入らない。 (2) 鍵の第 1 項は 7 日窓と役割の model席の役割が既定で使う model の 7 日窓の残量 (100 − 使用率) の小さい方なので、 Fable 90 / 7 日窓 10 の口座は残量 10 として Fable 40 / 7 日窓 60 の口座 (残量 40) の後ろに沈む。 残る穴は「役割の model の行を持たない口座は鍵に model が入らず 7 日窓だけで上位に来る」ことで、 その口座は最後に並べる (便用の鍵が 7 日窓の reset を持たない口座を最後にするのと同じ形)。 役割の model は rules 行 seat.model.<役割> (orchestrator は fable) から取る。

CTX4

裁定 2 — 群が増えても移り先が被らない予約と、 Tier の名かたまりの名の形

持ち主は、 群は今 Tier1 と Tier2 だが幾らでも増え、 各群に口座を 1 つ割り当てて占有させる想定 (新規の便と他の群の移動は弾き、 稼働中の便は残す) なので、 同じ鍵を全群に当てると次の移り先が全群で被る、 群の中で次の移り先を占有する「予約」が要る、 予約は他の群の移動と予約を排他するが便の起動は排他しない、 予約の優先は群の並び順 (Tier1 → Tier2)、 群の名は Tier<数字> に固定して数字の小さい方を優先したい、 と裁定した (00:48Z・要旨)。 実測では、 移動は tick の判定も 1 周の群の段も host の lock 1 本の内側で行い、 移った群はその場で記録を書き、 後の群は他の群の今の口座を記録から読んで飛ばすので、 2 群が同じ周に同じ口座へ飛ぶ事故は既に起きない。 足りないのは優先で、 先に逼迫した群が最良の口座を取っていた。 予約を file に記録する形は退け、 lock の内側1 つの手だけが動く区間で周ごとに導出する (記録と実測のずれ・消し忘れで永久に塞がる、 という新しい事故の置き場を作らない)。 予約が便の起動を排他しないのは、 移った後に新しい便がその口座で起きないことを便用の口座選定が既に満たし (ADR-0068)、 予約の段階で便を弾くと口座が遊ぶためである (持ち主の裁定の要旨)。 移り先の判定の周は鮮度計測が新しいと言える窓の内側の実測を読み直す (計測を起こすのは判定の周だけ・鮮度の外の候補を 1 回測る・FR27 / FR38) ので、 予約は周ごとの導出で足りる。

CTX5

現物 — 移り先の判定・便用の鍵・種・lock

main aa4bfe1 で、 群の移り先は hook/group.rs の target_of が group.accounts() を宣言順に走査し、 今の口座・他の群の今の口座・退役中を飛ばし、 鮮度の外なら 1 回測り、 pressed が無い最初の label を返す (残量や reset で並べない)。 便用の並べ鍵は fleet/select.rs の run_key (7 日窓の reset の無い口座を最後・reset 昇順・走行中の便数・label) で、 session 用は逼迫度が最小。 種は rules/manifest.rs の seed_groups が宣言順に前の群の種を避けて埋め、 check_duplicate_groups が名と置き場の重複を断る。 1 周の群の段 (pipe/dispatch/group.rs の round) は lock の内側で群を宣言順に回し、 先に移った群の移り先を currents で更新して後の群が飛ばす。 tick (seat/tick.rs の judged) は同じ lock を取り others を記録から集める。 計測の記録 (fleet/usage.rs) は 5 時間窓・7 日窓・モデル別 7 日窓 (model の名つき) の行を持ち、 group.rs の pressed が 3 窓を閾値で判じる。 doctor の群の行は group= accounts= anchors= seat-accounts= current= の 5 項目。

CTX6

憲法と既存の決定の向き (本 ADR の解釈)

C10 (宣言値・実測値・導出値を分ける) から、 予約は導出値であり記録しない。 移り先の鍵は実測値 (計測の記録の行) だけから決め、 宣言値 (候補の列) は同点の順にだけ効く。 C17 (足すときに何を外すかを名指す) から、 足すのは並べ鍵の関数 1 本と doctor の項目 1 つで、 外すのは「候補の先頭 = 宣言順の最初」の読み。 file も型も足さない。 C2 (経路は 1 本) から、 鍵は用途別の関数に閉じ (便用の run_key の隣に群用の鍵を置く)、 移り先の判定と doctor の next= が同じ 1 本を呼ぶ。 C5 (裁定は値に印を持つ) から、 閾値の行 3 本と役割の model の行は今の裁定のまま (本 ADR は値を変えない)。 ADR-0042 (便用は reset が早い順) は用途が違うので不変。 ADR-0049 の群・宣言・記録・承認 event・候補が無ければ移らない、 ADR-0055 の契機と lock と 3 段、 ADR-0066 の判定の置き場、 ADR-0068 の門の 2 条件と便用の除外 (群の今の口座だけ) は本 ADR の前提。

CTX7

射程 — 動かすのは並べ方・予約・名の 3 か所と、 種の出所の追認

動かすのは (1) 移り先の候補の並べ方 (宣言順 → 残量の鍵・宣言順は tie-break)、 (2) 群ごとの予約の導出 (宣言順で先の群から・記録しない・doctor に next= を足す)、 (3) 群の名の形 (自由 → Tier<数字>・宣言順は数字の昇順) の 3 つ。 動かさないのは、 門の条件 (今の口座でない・他の群の今の口座でない・退役中でない・鮮度の内側の実測で 3 窓とも閾値未満)、 鮮度の外の候補を 1 回測る規則、 移動の契機・lock・記録・承認 event・退避・起こし直し、 便用の口座選定の除外 (群については今の口座だけ) と便用の並べ鍵、 閾値と model の rules 行の値、 event の種類。 種の規則は設計 §28 の形 (宣言順で前の群の種でない最初の候補) を本 ADR が追認し、 ADR-0049 の「候補の先頭」を置き換える (4 か所目)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 4 本のものさしです。 移り先は残りの量で選ぶこと (席が長く働ける口座を、 7 日の窓と席の model の 7 日の窓の残りの少ない方で測る。 Fable が高い口座は沈む)。 群の優先は宣言の順で、 予約は他の群の移動と予約を避け、 便の起動は避けないこと (群が増えても同じ決め方で、 数字の小さい Tier が良い口座を取る)。 予約は記録しないこと (lock の内側で毎周計算し直し、 記録と実測のずれや消し忘れの事故を作らない)。 口も型も増やさないこと (並べる関数 1 本と doctor の項目 1 つを足し、 条件・lock・記録・便の除外は変えない) です。

DR1移り先は残量で選ぶ — 席が長く働ける口座を、 7 日窓と役割の model の 7 日窓の残量の小さい方で測る (Fable が高い口座は沈む・持ち主の要望と差し戻し・C10) CTX2・CTX3・CTX6

DR3予約は記録しない — lock の内側で周ごとに導出し、 記録と実測のずれと消し忘れの事故を作らない (C10・N1 の可逆性) CTX4・CTX5・CTX6

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 残りの量で並べ・予約を宣言の順に導き・名前を Tier<数字> に固定する案 (選んだ案)、 今のまま (宣言の順で最初) の案、 便に口座を渡す並べ方 (reset が早い順) をそのまま群にも使う案、 予約を file に記録する案、 5 時間の窓も並べ方に入れて残りを reset までの時間で割った速さで並べる案です。 却下した 4 案にも利点を並べ、 退けた決め手が現物か分析かを各案に書きます。 今のままの案は要件も決定も動かさない点で、 便の並べ方を使う案は関数が 1 本で済む点で、 file に記録する案は予約が周をまたいで安定し画面が file を読むだけで済む点で、 速さで並べる案は reset までの時間を直接使える点で、 選んだ案に勝ります。

OPT1残量の鍵で並べ、 予約を宣言順に導出し、 名を Tier<数字> に固定する採用

門を通る候補を「7 日窓と役割の model の 7 日窓の残量の小さい方が大きい順 → 7 日窓の reset が早い順 → 宣言順」で並べ (役割の model の行が無い口座は最後)、 群を宣言順に見て「どの群の今の口座でもなく先の群の予約かたまりが次に移る口座でもない先頭」をその群の予約とし、 移る群は自分の予約へ移る。 予約は記録せず lock の内側で周ごとに導出し、 便用の口座選定は予約された口座を外さない。 群の名は Tier<数字> (数字は重複不可) に限り、 宣言順が数字の昇順でない面は読みで断る。 doctor の群の行に next= を足す。 決め手は現物 (裁定 2 つと差し戻しの実測)。

候補に入る条件を通る口座を「7 日の窓と席の model の 7 日の窓の残りの少ない方が多い順 → 7 日の窓の reset が早い順 → 宣言の順」で並べ (席の model の行が無い口座は最後)、 群を宣言の順に見て「どの群もいま使っておらず先の群の予約でもない先頭」をその群の予約とし、 移る群は自分の予約へ移る案です。 予約は記録せずlock の内側で毎周計算し直し、 便に口座を渡す選び方は予約された口座を外しません。 群の名前は Tier<数字> に限り、 宣言の順が数字の小さい順でない設定は読みで断ります。 doctor の群の行に next= を足します。 Fable の窓が高い口座は条件で断られるか並べ方で沈み、 群が幾つ増えても数字の小さい Tier が良い口座を取り、 予約の file が無いので記録と実測のずれや消し忘れが起きず、 足すのは関数 1 本と doctor の項目 1 つだけです。 代わりに、 後の群は先の群の予約を避けて二番手へ移ること、 名前の形が固定されること、 要件書の改訂を伴い前の決定の読みが置き換わることを引き受けます。 決め手は現物 (裁定 2 つと差し戻しの実測) です。

+ 利点

  • Fable の窓が高い口座は門で断られるか鍵で沈み、 席が長く働ける口座へ移る (DR1)
  • 群が幾つ増えても数字の小さい Tier が良い口座を取り、 2 群が同じ周に同じ口座へ飛ばない (DR2)
  • 予約の file が無いので、 記録と実測のずれ・消し忘れ・移動の途中で残る札、 という事故が起きない (DR3)
  • 足すのは鍵の関数 1 本と doctor の項目 1 つ・門と lock と記録と便用の除外は不変 (DR4)

− 欠点

  • 先の群の予約が後の群の候補から外れるので、 後の群は先の群が逼迫していなくても二番手の口座へ移る (持ち主の裁定どおり・先の群のために良い口座を空けておく)
  • 群の名の形が固定され、 既存の名 (Tier1 / Tier2) は合うが、 別の名を使う host は面の読みで断られる
  • 要件 FR38 と AC41 の改訂を伴い、 ADR-0049 / ADR-0055 / ADR-0068 の移り先の「候補の先頭」の読みが本 ADR に置き換わる
OPT2今のまま (宣言順で門を通る最初)不採用

ADR-0049 の「候補の順 = 宣言順」を保つ。 決め手は現物 (持ち主の要望と違うと裁定した)。

宣言の順で条件を満たす最初の口座、 という今の形を保つ案です。 要件も決定も動かさない点で勝ります。 けれども、 残りも reset も見ないので Fable が 90% の口座が 7 日の窓の低さだけで先頭に来て、 先に線を越えた群が最良の口座を取り Tier の優先が効きません。 決め手は現物で、 持ち主が要望と違うと裁定しました。

+ 利点

  • 要件も ADR も動かさない

− 欠点

  • 残量も reset も見ないので、 Fable が 90% の口座が 7 日窓の低さだけで先頭に来る (DR1)
  • 先に逼迫した群が最良の口座を取り、 Tier の優先が効かない (DR2)
OPT3便用の鍵 (7 日窓の reset が早い順) をそのまま群にも使う不採用

ADR-0042 の run_key を群の移り先にも当て、 鍵を 1 本にする。 決め手は分析 (用途が違う)。

便に口座を渡す並べ方 (7 日の窓の reset が早い順) をそのまま群の移り先にも使い、 関数を 1 本にする案です。 関数が 1 本で済む点で勝ります。 けれども、 便の並べ方は「reset までに使わなければ消える枠を使い潰す」ための順で、 席は何日も同じ口座に居るので残りを見ないと直ぐ線を越えます。 model 別の窓も見ないので Fable が高い口座を避けられません。 決め手は分析です。

+ 利点

  • 鍵の関数が 1 本で済む

− 欠点

  • 便用は「reset までに使わなければ消える枠を使い潰す」ための順で、 席は何日も同じ口座に居るので残量を見ないと直ぐ逼迫する (DR1)
  • モデル別の窓を見ないので Fable が高い口座を避けられない (DR1)
OPT4予約を file に記録する不採用

群ごとに <群>.reserved の file を置き、 移る群はそれを読む。 決め手は分析 (記録の事故の置き場)。

群ごとに予約の file を置き、 移る群はそれを読む案です。 予約が周をまたいで安定し、 画面が file を読むだけで済む点で勝ります。 けれども、 実測が変わっても予約が古いまま残って線を越えた口座へ移ることがあり (導いた値を記録する形)、 消し忘れ・移動の途中に残る札・読めないときの扱い、 という新しい口が増えます。 移り先の判定の周は新しい計測を読み直すので (測るのは判定の周だけ)、 毎周の計算で足ります。 決め手は分析です。

+ 利点

  • 予約が周をまたいで安定し、 GUI が file を読むだけで済む

− 欠点

  • 実測が変わっても予約が古いまま残り、 逼迫した口座へ移る (C10 の導出値を記録する形) (DR3)
  • 消し忘れ・移動の途中の札・読めない周の扱い、 という新しい fail-closed の口が増える (DR3・DR4)
  • 移り先の判定の周は鮮度の内側の実測を読み直す (計測は判定の周だけ・FR27 / FR38) ので、 周ごとの導出で足りる (DR3)
OPT55 時間窓も鍵に入れ、 残量を reset までの時間で割った速さで並べる不採用

3 窓の残量を reset までの残り時間で割り、 消費できる速さの大きい順に並べる。 決め手は分析 (式の妥当性を測る材料が無い)。

5 時間の窓も並べ方に入れ、 3 つの窓の残りを reset までの残り時間で割った「使える速さ」の大きい順に並べる案です。 reset までの時間を直接使える点で勝ります。 けれども、 5 時間の窓は数時間で戻るので並べ順が毎周揺れ (便の並べ方も 5 時間の窓を並べ順に入れていません)、 式の妥当性を測る材料が無く、 裁定した並べ方より複雑です。 決め手は分析です。

+ 利点

  • reset までの時間を鍵の中で直接使える

− 欠点

  • 5 時間窓は数時間で開き直るので並べ順が周ごとに揺れる (ADR-0042 も 5 時間窓を便用の並べ順に入れていない) (DR1)
  • 式の妥当性を測る材料が無く、 裁定した鍵 (残量 → reset → 宣言順) より複雑で C17 の最小に反する (DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 群の移り先は、 候補に入る条件 (いま使う口座でない・他の群がいま使う口座でない・退役中でない・新しい計測があり 3 つの窓とも線の下・計測が古い候補は 1 回測る) を通る口座を、 7 日の窓と席の model の 7 日の窓の残りの少ない方が多い順 → 7 日の窓の reset が早い順 → 宣言の順、 で並べたものから選びます。 席の model の行を持たない口座は最後です。 5 時間の窓は条件にだけ使い、 並べ方には入れません。 宣言に並べた候補は集合として読み、 順は同点のときにだけ効きます。 群の予約は、 群を宣言の順に見て「どの群もいま使っておらず、 先の群の予約でもない、 並べた候補の先頭」で、 移る群は自分の予約へ移ります。 予約は記録せず、 machine 全体の lockの内側で毎周計算し直し、 他の群の移動と予約を避けますが、 便の起動は避けません (便に口座を渡す選び方が外すのは群のいま使う口座だけのままで、 予約された口座を便は使ってよく、 動いている便は移動を妨げません)。 群の名前は Tier<数字> (数字は重複しない) に限り、 宣言の順が数字の小さい順でない設定は読みの時点で断ります。 優先は宣言の順のままです。 doctor の群の行に next= (今の並べ方で導いた予約) を足し、 移り先の判定と doctor は同じ 1 本の関数を呼びます。 候補が無い群は今どおり移らず断ります。 記録が無いときの種は、 宣言の順で前のかたまりの種でない最初の候補です (設計 doc の形をこの記録が追認し、 前の決定の「候補の先頭」を置き換えます)。 移動の契機・lock・記録・承認の記録・退避・起こし直し・便の並べ方・線の値・記録の種類は変えません。 前の決定のうち、 ADR-0049 の「並べた順が候補の順・移り先は候補の順で最初」と「種は候補の先頭」と、 ADR-0055 / ADR-0068 の移り先の「候補の先頭」の読みを置き換え、 他は保ちます。 要件書では、 FR38 (群の移動) の移り先を残りの量で並べ予約を導き名前を固定する根拠になり、 FR36 (便に口座を渡す選び方) は変えず予約された口座を便が使ってよいこと、 FR33 (残量の計測) の行が並べ方の材料であること、 FR27 (見回り) が判定を撃つ契機は変わらないことを主張します。

採用 — OPT1

群の移り先 SHALL 門 (今の口座でない ∧ 他の群の今の口座でない ∧ 退役中でない ∧ 鮮度の内側の実測を持ち 5 時間窓・7 日窓・モデル別 7 日窓とも閾値未満・鮮度の外の候補は 1 回測る) を通る候補を、 (a) 7 日窓と群の席の役割の model (rules 行 seat.model.<役割>) の 7 日窓の残量 (100 − 使用率) の小さい方が大きい順 → (b) 7 日窓の reset が早い順 → (c) 宣言順、 の辞書順で並べたものから選び、 役割の model の行を持たない口座 SHALL 最後に並ぶ。 5 時間窓 SHALL 門にだけ使い鍵に入れない。 宣言の候補の列 SHALL 集合として読み、 順 SHALL (c) にだけ効く。 群の予約 SHALL 群を宣言順に見て「どの群の今の口座でもなく、 先の群の予約でもない、 並べた候補の先頭」とし、 移る群 SHALL 自分の予約へ移る。 予約 SHALL 記録せず、 host の lock の内側で周ごとに導出し、 他の群の移動と予約を排他するが便の起動 SHALL 排他しない (便用の口座選定の除外は群の今の口座だけのまま・予約された口座を便は使ってよい・稼働中の便は移動を妨げない)。 群の名 SHALL Tier<数字> (数字は重複しない) に限り、 宣言順が数字の昇順でない host の面 SHALL 読みで断る (fail-closed)。 優先 SHALL 宣言順のまま。 doctor の群の行 SHALL next=<label|none> (今の鍵で導出した予約) を持ち、 移り先の判定と doctor SHALL 同じ 1 本の鍵の関数を呼ぶ。 候補が無い群 SHALL 今どおり移らず断る。 記録の無い周の種 SHALL 宣言順で前の群の種でない最初の候補 (設計 account-lifecycle.md §28 の形を本 ADR が追認し、 ADR-0049 の「候補の先頭が種」を置き換える)。 移動の契機・lock・記録・承認 event・退避・起こし直し・便用の並べ鍵・閾値と model の rules 行の値・event の種類 SHALL 変えない。 本 ADR SHALL ADR-0049 の「候補の順 = 宣言順・移り先は候補の順で門を通る最初・記録の無い周は候補の先頭が種」と、 ADR-0055 / ADR-0068 の移り先の「閾値未満の候補の先頭」の読みを置き換え、 他は保つ。 要件 FR38 と AC41 (SRS v0.25) の改訂を伴い、 同じ PR で land する。

群の移り先は、 候補に入る条件 (いま使う口座でない・他の群がいま使う口座でない・退役中でない・新しい計測があり 5 時間・7 日・model 別 7 日の 3 つの窓とも線の下・計測が古い候補は 1 回測る) を通る口座を、 7 日の窓とその群の席の役割の model (規則の表の行が決める。 orchestrator は fable) の 7 日の窓の残り (100 − 使用率) の少ない方が多い順 → 7 日の窓の reset が早い順 → 宣言の順、 で並べたものから選びます。 席の model の行を持たない口座は最後に並びます。 5 時間の窓は条件にだけ使い、 並べ方には入れません。 宣言に並べた候補は集合として読み、 順は同点のときにだけ効きます。 群の予約は、 群を宣言の順に見て「どの群もいま使っておらず、 先の群の予約でもない、 並べた候補の先頭」で、 移る群は自分の予約へ移ります。 予約は記録せず、 machine 全体の lockの内側で毎周計算し直し、 他の群の移動と予約を避けますが、 便の起動は避けません (便に口座を渡す選び方が外すのは群のいま使う口座だけのままで、 予約された口座を便は使ってよく、 動いている便は移動を妨げません)。 群の名前は Tier<数字> (数字は重複しない) に限り、 宣言の順が数字の小さい順でない設定は読みの時点で断ります。 優先は宣言の順のままです。 doctor の群の行に next= (今の並べ方で導いた予約。 無ければ none) を足し、 移り先の判定と doctor は同じ 1 本の関数を呼びます。 候補が無い群は今どおり移らず断ります。 移動の契機・lock・記録・承認の記録・退避・起こし直し・種の決め方・便の並べ方・線と model の規則の値・記録の種類は変えません。 前の決定のうち、 ADR-0049 の「並べた順が候補の順・移り先は候補の順で最初」と、 ADR-0055 / ADR-0068 の移り先の「候補の先頭」の読みを置き換え、 他は保ちます。 要件書の FR38 と AC41 (版 0.25) の改訂を伴い、 同じ PR で land します。 持ち主の裁定は、 移り先を残りの量で並べること、 群ごとに予約して宣言の順に優先すること、 予約は他の群の移動と予約を避けるが便の起動は避けないこと、 名前を Tier<数字> に固定すること、 の受諾でした。 残りの量で並べるのは、 席が何日も同じ口座に居るので、 いま残りが多い口座ほど長く働けるからで、 2 つの窓の少ない方を取るのは、 持ち主の差し戻し (Fable が高くて 7 日の窓が低い口座) をそのまま塞ぐためです。 候補に入る条件が model の窓も線で断るので、 線を越えた Fable の口座は並べる前に消えます。 席の model の行を持たない口座を最後にするのは、 その口座の Fable の残りが読めず、 7 日の窓だけで上位に来る穴を塞ぐためです (便の並べ方が reset の無い口座を最後にするのと同じ形)。 便の並べ方を流用する案を退けたのは、 便は「消える枠を使い潰す」順で、 席の目的 (長く働く) と逆だからです。 予約を宣言の順に導くのは、 群が幾つ増えても同じ決め方で数字の小さい Tier が良い口座を取るためで、 記録しないのは、 導いた値を記録すると実測とずれて線を越えた口座へ移ったり消し忘れで塞がったりする事故の置き場になるからです (宣言値・実測値・導出値を分ける決まり)。 移り先の判定の周は新しい計測を読み直す (測るのは判定の周だけ) ので、 lock の内側で毎周計算し直せば足ります。 予約が便の起動を避けないのは、 便に口座を渡す選び方が群のいま使う口座を外す既存の規則 (ADR-0068) で「移った後に新しい便がその口座で起きない」が既に満たされ、 予約の段階で便を弾くと口座が遊ぶからです (持ち主の裁定の要旨)。 5 時間の窓を並べ方に入れず速さの式も使わないのは、 5 時間の窓は数時間で戻って順が揺れ、 式の妥当性を測る材料が無いからです (足すときは最小に)。 名前を固定するのは、 数字の小さい群が優先という約束を名前で読めるようにし、 宣言の順と名前がずれる設定を読みで断るためです。 足すのは並べる関数 1 本と doctor の項目 1 つで、 条件・lock・記録・便の除外は変えないので、 足すときに外す物を名指す決まりと道は 1 本の決まりに沿います。 後の群が二番手へ移ること・名前の形の固定・要件書と前の決定の読みの置き換えは、 代償として引き受けます。
