設計判断記録 (ADR) scribe2 — 公開の除外の表

公開の除外の表は host の面に字句のまま置く — 無害と裁定した字句の除外を publish の種類の rules 行の digest の列から host の面の表へ移し、 行ごとに裁定 id を持たせ、 裁定 id の欄を欠く行を持つ面は読みで断る (ADR-0078 の除外の一覧の置き場と形を部分 supersede)

公開の見張りは、 隣の private repo の名の成分に当たる字面を止めるが、 無害と裁定した字句の中の当たりは数えない。 ADR-0078 はその字句の一覧を、 PUBLIC な repo に載る rules 行が sha256 の digest の列で持つ設計とした。 短い字句の digest は候補の字句で当て直せるので、 要素を足せば一覧に在る字句と、 そこから隣の repo の名の成分が読める。 今の rules 行の除外の要素は 0 で digest を計算する実装も無く、 本 ADR は除外を 1 つ足す前に、 一覧を tracked でない host の面へ字句のまま移し、 行ごとに裁定 id を持たせる先回りの判断である。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「見張り (host-guard)」は危ない操作を実行の直前に止める器の口、 「隣の private repo」は同じ machine の宣言に並ぶ非公開の repo、 「host の面」は置き場 (state dir) ごとに 1 つ置く、 git で追跡しない宣言の file です。 見張りは、 公開の repo へ出る文字に隣の private repo の名の一部が混じると止めますが、 持ち主が無害と裁定した語の中の当たりは数えません。 ADR-0078 はその語の一覧を、 公開の repo に載る規則の行が、 語を sha256 に掛けた指紋 (digest) の列で持つと決めていました。 短い語の指紋は、 候補の語を同じく指紋にして突き合わせれば当て直せるので、 語を足せば、 一覧に在る語と、 そこから隣の repo の名の一部が読めてしまいます。 ただし、 この repo の規則の行にはまだ除外の語が 1 つも無く、 指紋を計算する実装もありません。 この記録は、 起きた漏れへの対処でなく、 除外を 1 つ足す前に置き場を変える先回りの判断です。 一覧を host の面の「公開の除外の表」へ語のまま移し、 各行に裁定の番号 (裁定 id) を持たせ、 番号の欄が無いか空の行を持つ面は読むときに断ると決めます。 置き換えるのは ADR-0078 のうち、 除外の一覧の置き場と形だけです。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 経緯 (除外の一覧は ADR-0078 が規則の行に指紋の列で置いた)・危険 (指紋の列は候補の語で当て直せる)・機序 (除外が無いと無害な公開が毎回止まる)・憲法と既存の決定の向き・この判断の範囲の 5 つから説明します。 この repo の規則の行には、 まだ除外の語は 1 つもなく、 指紋を計算する実装もありません。

CTX1

経緯 — 除外の一覧は ADR-0078 が publish の種類の rules 行に digest字句から作る指紋 の列で置いた

ADR-0078 は host-guard に 6 つ目の種類 publish を足し、 rules 行 host_guard.publish の値を、 識別子の形の記号の閉じた列と、 無害と裁定した字句の除外の一覧 (字句の sha256 の digest の列で、 字句そのものは書かない) とした。 走査の段は、 repo の名の成分の当たりのうち、 除外の一覧に digest が在る字句の中の当たりだけを数えない。 除外の一覧は持ち主の裁定 2026-09-27T23:55Z (repo の名は区切った成分ごとに照合し、 無害と裁定した字句だけを除く) から来る。 今の器の rules 行の読み手は形の記号と除外の digest の 2 つの札を受け、 この repo の rules 行の値は形の記号 4 つだけで、 除外の要素はまだ 1 つも無い。 digest を計算する実装もまだ無い。 器を導入した別の repo (消費側) の rules 行が除外の要素を持てば、 本 ADR の後は読みで断られる。 digest を計算する実装が無いので、 そこで効いていた除外は無い。

CTX2

危険 — digest の列は候補の字句で当て直せる (辞書攻撃)

rules 行は tracked な manifest に在り、 PUBLIC な repo に載る。 除外に足す字句は、 隣の private repo群に並ぶ非公開の repo の名の成分を含むが無害な短い語 (一般の英単語や、 公開の文書に現れる語) で、 その候補の集合は小さい。 誰でも公開の字句を sha256 に掛けて digest の列と突き合わせれば、 一覧に在る字句が分かる。 字句が除外に在ることは、 その字句が隣の repo の名の成分を含むことを意味するので、 隣の repo の名の成分が読める。 digest は字句を隠さず、 公開の面から隣を指す手がかりになる。

CTX3

機序 — 除外が無いと無害な公開が毎回止まる

走査は repo の名を区切った成分の並びで照合し、 一般語の名も除かない (持ち主の裁定 2026-09-27T22:21Z)。 隣の private repo の名が一般語と同じ成分を持つと、 その語を含む無害な字面 (生成した文書など) の push と本文が毎回断られる。 除外の表は、 この偽陽性を持ち主が裁定した字句に限って外す口で、 ほかの経路は字面を言い換えて出し直すことだけである。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

C1 は規則の値 (閾値・enabled・裁定 id など) を repo の中の manifest 1 file に置く。 C10.2 は host 固有の値を manifest にだけ置き、 ADR-0026 はこの manifest を tracked の面と host の面host ごとの宣言の置き場 (state dir の 1 file・rules 行を置けない) の 2 面と読んだ。 本 ADR は、 識別子の形の列と enabled を rules 行の値 (C1)、 判定の順を器の決定 (ADR-0078・FR80) とし、 除外の字句を host 固有の宣言値と読む。 どの隣の repo が在るかは host 固有の事実 (隣は host の面の群の表の行の anchor から数える) なので、 その名の成分に当たる字句の除外も host 固有の値である。 ただし ADR-0078 が host の面を読んでよいとした根拠 (群の anchor は判定を緩める鍵でなく隣を数える host の事実の入力である) は、 除外の表には引き継げない。 除外の表は当たりを数えなくする、 判定を緩める鍵そのものである (群の表の anchor を消しても判定は緩むので、 host の面を書ける者が判定を緩められること自体は今も在り、 除外の表はその経路を 1 つ足す)。 C5 は rules 行を足すか変える変更に裁定 id裁定を指す番号 を求めて CI が断るが、 host の面は tracked でないので CI の門は届かない。 表の行ごとに裁定 id の欄を持たせ、 欄が無いか空の行を持つ面を読みで断っても、 保てるのは値が裁定 id の欄を持つところまでで、 id が台帳の裁定に解けるかは測らない。 欄に中身のある偽の id を持つ行は効き、 host の面を書ける者は除外を足せる。 CON2 と A1 (出す) から、 隣の名の成分を公開の面へ出す形 (字句そのものも、 当て直せる digest も) を採らない。 持ち主の裁定は 2 本 — 2026-09-29T05:46Z (除外の一覧を host の面へ字句のまま移す)・2026-09-29T04:37Z (公開情報の扱いは推奨で進める)。 逐語は台帳にだけ在る。

CTX5

射程 — 動かすのは除外の置き場と形と、 それに伴う読みと照合と起票の規則だけ

動かすのは (1) 除外の一覧の置き場を rules 行から host の面の公開の除外の表数えない字句の表へ移し、 形を digest から字句へ替え、 表の名と key の閉じた列を決めること、 (2) rules 行の値の要素を形の記号だけにすること、 (3) host の面の読み手が裁定 id の欄が無いか空の行を持つ面を断ること、 (4) 除外の字句の照合の単位を閉じること (digest の形では語の丸ごとの一致しか取れなかったが、 字句の形では部分の一致や大文字と小文字の扱いが分かれうるので、 repo の名と同じ区切りの成分の並びで閉じる)、 (5) 表の行を求める台帳の問いを答えが操作で済む問い (effect が operation) で立て、 その裁定を未反映の裁定文書が引いていない裁定 (FR84) に数えないこと (答えは host の面へ行を書く操作で済み、 字句は tracked な file に書かないので、 追跡された file へ写すものが無い)。 前提として、 除外の字句は台帳の問いと裁定の行 (逐語の欄) にも残り、 台帳の同期先は公開の面でないものとする。 動かさないのは、 host-guard の 6 つの種類・判定の順 (rules 行 → 全履歴を出す command → 解き → 可視性 → 走査)・識別子の閉じた 4 形と repo の名の照合の単位 (区切った成分・大文字と小文字を区別しない・一般語も除かない)・GitHub への問いの範囲と A1 の解釈・読む上限と締め切り (NFR5)・着地の前の呼び出し (FR11・FR50)・配線の hook 行・host の面の読み手 1 本と断り方・host の面に rules 行を置けない規則。 要件の側は SRS v0.30 の FR80 の除外の句と FR57 の host の面の項目が持つ。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 公開の面から隣の repo の名の一部を読めないこと。 除外の 1 行ずつに裁定の番号の欄を持たせ、 欄の欠けた除外を黙って効かせないこと。 machine ごとの値は machine ごとの宣言に置くこと。 足すものを最小にすること (既に在る読み手を使い、 依存を足さない)。 無害な公開を止め続けないこと。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 host の面の表に語のまま置く案 (選んだ案) と、 選ばなかった 4 つです。 選ばなかったのは、 今のまま指紋の列を規則の行に置く案、 語のまま規則の行に置く案、 除外を持たない案、 machine だけが持つ秘密の値 (salt) を混ぜた指紋を規則の行に置く案で、 当て直せる・そのまま公開になる・無害な公開が毎回止まる・規則の行が machine ごとの値になる、 がそれぞれの決め手です。

OPT1host の面の公開の除外の表に字句のまま置く採用

無害と裁定した字句を host の面の公開の除外の表に字句のまま置き、 各行に裁定 id を持たせる。 host の面の読み手は裁定 id の欄が無いか空の行を持つ面を断る。 表は tracked な file に書かず、 行を求める台帳の問いは答えが操作で済む問いで立て、 その裁定を未反映の裁定に数えない。 rules 行は識別子の形の記号だけを持つ。 決め手は持ち主の裁定 (2026-09-29T05:46Z)。

除外の語を host の面の「公開の除外の表」に語のまま置き、 各行に裁定の番号を持たせる案です。 番号の欄が無いか空の行を持つ面は、 読むときに断ります。 表は git で追跡しない file にだけ在り、 公開の repo には語も指紋も載らないので、 公開の面から隣の repo の名の一部を読めません。 隣の repo が在るという machine の事実と、 その名に当たる語の除外が、 同じ面に並びます。 既に在る読み手を使い、 照合は語の比べ合わせなので、 指紋を計算する実装も要りません。 代わりに、 除外の変更は PR の差分と CI の門に現れず、 置き場ごとの面に同じ行を置きます。 番号が台帳で解けるかは読むときに測らないので、 中身のある偽の番号の行も効きます。 host の面の file が漏れれば、 除外の語はそのまま読めます。 持ち主の裁定で選びました。

+ 利点

  • 字句も当て直せる形も PUBLIC な repo に載らず、 公開の面から隣の名の成分を読めない (DR1)
  • 行ごとの裁定 id の欄の有無と空を読みで確かめ、 欄を欠く除外を黙って効かせない (DR2)
  • 隣が在るという host の事実と、 その名に当たる字句の除外が同じ host の面に並ぶ (DR3)
  • 既存の host の面の読み手 1 本と断り方を使い、 照合は字句の比較で digest を計算する実装が要らない (DR4)
  • 裁定した字句の中の当たりは数えず、 無害な公開を止め続けない (DR5)

− 欠点

  • 表が tracked でないので、 除外の変更は PR の差分と CI の門 (C5) に現れず、 記録は台帳の裁定が持つ
  • host の面は置き場 (state dir) ごとの 1 file なので、 置き場が複数の host では各面に同じ行が要る
  • 読みが確かめるのは裁定 id の欄の有無と空だけで、 id が台帳の裁定に解けるかは測らず、 中身のある偽の id の行も効く
  • host の面 (state dir の file) が漏れれば、 除外の字句はそのまま読める (salt の案なら要る当て直しの手間も無い)
OPT2ADR-0078 のまま digest の列を rules 行に置く不採用

除外の一覧を今のまま publish の種類の rules 行に sha256 の digest の列で持つ。 決め手は分析 (候補の字句で当て直せる)。

今のまま、 除外の一覧を規則の行に指紋の列で持つ案です。 除外の変更が PR の差分と CI の門を通り、 全ての machine に同じ一覧が効き、 今の読み手をそのまま使える点で勝ります。 けれども、 短い語の指紋は、 公開の語を同じく指紋にして突き合わせれば当て直せ、 一覧に在る語と隣の repo の名の一部が読めます。 隣の在り方は machine ごとに違うのに除外は repo の追跡する行 1 つに固まり、 指紋を計算する実装も器に書くことになります。 退けました。

+ 利点

  • 除外の変更が PR の差分と CI の門 (C5) を通り、 全 host に同じ一覧が効く
  • 今の rules 行の読み手の札をそのまま使える

− 欠点

  • 短い字句の digest は、 公開の字句を hash して突き合わせれば当て直せ、 一覧に在る字句と隣の名の成分が読める (DR1)
  • 隣の在り方は host ごとに違うのに、 除外は repo の tracked な行 1 つに固まる (DR3)
  • digest を計算する実装を器に書く (DR4)
OPT3字句のまま rules 行に置く不採用

除外の字句を digest にせず、 字句のまま publish の種類の rules 行に置く。 決め手は分析 (名の成分をそのまま公開する)。

除外の語を指紋にせず、 語のまま規則の行に置く案です。 除外の変更が PR の差分と CI の門を通り、 照合が語の比べ合わせで済む点で勝ります。 けれども、 隣の repo の名の一部を含む語を公開の repo の追跡する file に書くことになり、 それ自体が公開です。 machine ごとの値を追跡する行に置くことにもなります。 退けました。

+ 利点

  • 除外の変更が PR の差分と CI の門 (C5) を通る
  • 照合は字句の比較で、 digest を計算する実装が要らない (DR4)

− 欠点

  • 隣の名の成分を含む字句を PUBLIC な repo の tracked な file に書くことになり、 それ自体が公開になる (DR1)
  • host 固有の値を tracked な行に置く (DR3)
OPT4除外の表を持たない不採用

除外を一切持たず、 当たった字面は言い換えて出し直すだけにする。 決め手は分析 (偽陽性が毎回起きる)。

除外を一切持たず、 当たった文字は言い換えて出し直すだけにする案です。 足す表も読み手も要らず、 除外の誤りで当たりを見逃すことも無い点で勝ります。 けれども、 隣の repo の名が一般的な単語と同じ部分を持つと、 その語を含む無害な push と本文が毎回止まります。 無害と裁定した語だけを除くという持ち主の裁定 (2026-09-27T23:55Z) を受ける口も無くなります。 退けました。

+ 利点

  • 足す表も読み手も要らない (DR4)
  • 除外の誤りで当たりを見逃すことが無い

− 欠点

  • 一般語と同じ成分を持つ名の隣が在る host では、 その語を含む無害な push と本文が毎回断られる (DR5)
  • 無害と裁定した字句だけを除くという持ち主の裁定 (2026-09-27T23:55Z) を受ける口が無くなる
OPT5host だけが持つ salt を掛けた digest を rules 行に置く不採用

除外の一覧を rules 行に残し、 host の面に置いた salt (字句に混ぜる秘密の値) を掛けた digest で持つ。 決め手は分析 (tracked な行が host 固有の値になる)。

除外の一覧を規則の行に残し、 host の面に置いた秘密の値 (salt) を語に混ぜてから指紋にする案です。 除外の変更が PR の差分と CI の門を通り、 salt を知らなければ公開の語から当て直せない点で勝ります。 けれども、 指紋が salt ごとに違うので、 追跡する規則の行の指紋の列が machine ごとの値になり、 salt の違う machine では効きません。 salt と指紋の 2 か所を揃える手間と、 指紋を計算する実装も要ります。 salt が漏れれば、 短い語の集合は再び当て直せます (漏れへの強さは、 選んだ案と同じく host の面に依ります)。 退けました。

+ 利点

  • 除外の変更が PR の差分と CI の門 (C5) を通る
  • salt を知らなければ、 公開の字句を hash しても当て直せない (DR1)

− 欠点

  • digest が salt ごとに違うので、 tracked な rules 行の digest の列が host 固有の値になり、 salt の違う host では効かない (DR3)
  • host の面の salt と rules 行の digest の 2 か所を揃え、 digest を計算する実装も要る (DR4)
  • salt が漏れれば、 短い字句の集合は再び当て直せる (DR1・漏れへの強さは OPT1 と同じく host の面に依る)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 除外の語は host の面の公開の除外の表 (表の名は publish-exclusion、 欄は語と裁定の番号の 2 つだけ) に語のまま置き、 番号の欄が無いか空の行を持つ面は読むときに断ります。 断られた面は丸ごと読めない面になり、 その面を読む口が止まります。 語の中の当たりは、 名と同じ区切りで切った並びが大文字と小文字を区別せずに一致する区間で見ます。 表の行を求める問いは答えが操作で済む問いとして立て、 文書へ写す裁定として数えません。 規則の行は識別子の形の一覧だけを持ちます。 見張りの区分・判定の順・名の照合の単位は変えません。 支えるのは FR80 (公開の字面の走査) の除外の句と、 FR57 (host の面) の項目への主張です。

採用 — OPT1

器 SHALL 無害と裁定した字句の除外を、 publish の種類の rules 行でなく host の面の公開の除外の表に置く。 表は host の面の表 [[publish-exclusion]] とし、 key の閉じた列 SHALL phrase (字句) と ruling (裁定 id) の 2 つだけとする (ほかの key は schema の外の項目として断る)。 表の各行 SHALL 字句を字句のまま (digest にせず) 持ち、 裁定 id を持つ。 host の面の読み手 (FR57・ADR-0026 の 1 本) SHALL 裁定 id の欄が無いか空の行を 1 行でも持つ面を、 行番号つきで typed に読みで断る。 拒む行を 1 つでも持つ host の面は在るが読めない host の面で、 host の面を読む口 (計測・選定・管理 tick・doctor・席の起動・公開の字面の走査) SHALL typed に止まり、 公開の字面の走査は公開の segment を断る (既存の断りと同じ極性で、 面が無い host は 0 宣言のまま続く)。 読みが確かめるのは欄の有無と空だけで、 id が台帳の裁定に解けるかは測らない。 表の字句 SHALL NOT tracked な file に書かない。 publish の種類の rules 行の値 SHALL 識別子の形の記号の閉じた列だけとし、 除外の要素を持たない (在れば読みで断る)。 走査 SHALL repo の名の成分の当たりのうち、 公開の除外の表に在る字句の中の当たりだけを数えない。 字句の中とは、 出ていく字面を repo の名と同じ区切り (ASCII の英数字と _ の外の字) で切った成分の並びのうち、 表の字句を同じ区切りで切った成分の並びと大文字と小文字を区別せずに一致する区間をいう。 器 SHALL NOT 除外のために digest を計算しない。 表の行は持ち主の裁定の答えを host の面へ書く操作で足し、 置き場 (state dir) ごとの面が自分の表を持つ。 表の行を求める台帳の問い SHALL effect を operation (答えが操作で済む問い) で立て、 その裁定は未反映の裁定 (FR84) に数えない。 document で立てた問いは FR84 が未反映と数え、 その裁定を引く契約を待たせる側に倒れる (安全な側・これを強制する門は置かない)。 除外の字句は台帳の問いと裁定の行にも残り、 本決定は台帳の同期先が公開の面でないことを前提とする。 host-guard の 6 つの種類・判定の順・識別子の閉じた 4 形と repo の名の照合の単位・GitHub への問いの範囲と A1 の解釈・読む上限と締め切り・着地の前の呼び出し・配線の hook 行 SHALL NOT 変えない。 host の面が rules 行を持てない規則 (ADR-0026) は変えない (表は rules 行でない)。 要件は SRS v0.30 の FR80 の除外の句と FR57 の host の面の項目が持つ。

器は、 持ち主が無害と裁定した語の除外を、 規則の行でなく host の面の「公開の除外の表」に置きます。 表の名は publish-exclusion で、 欄は語 (phrase) と裁定の番号 (ruling) の 2 つだけです。 表の各行は語を語のまま (指紋にせず) 持ち、 裁定 id を持ちます。 host の面の読み手は、 裁定 id の欄が無いか空の行を 1 行でも持つ面を、 行の番号をつけて読むときに断ります。 断られた面は丸ごと読めない面になり、 計測・口座の選定・管理 tick・doctor・席の起動・公開の字面の走査が止まります (公開の走査は公開の操作を断ります。 面が無い machine は宣言 0 のまま続きます)。 読むときに確かめるのは欄の有無と空だけで、 番号が台帳で解けるかは測りません。 表の語は git で追跡する file に書きません。 規則の行は識別子の形の一覧だけを持ち、 除外の要素を持ちません (在れば読むときに断ります)。 見張りは、 隣の repo の名の当たりのうち、 表に在る語の中の当たりだけを数えません。 語の中とは、 出ていく文字を名と同じ区切りで切った並びのうち、 表の語を同じく切った並びと大文字と小文字を区別せずに一致する区間です。 そのために指紋は計算しません。 表の行は、 持ち主の裁定の答えを host の面へ書く操作で足し、 置き場ごとの面が自分の表を持ちます。 表の行を求める台帳の問いは答えが操作で済む問いとして立て、 その裁定を文書へ写していない裁定 (未反映の裁定) に数えません。 文書へ写す問いとして立てると、 その裁定を引く契約が待たされる側に倒れます (これを強制する門は置きません)。 除外の語は台帳の問いと裁定の行にも残り、 台帳の同期先が公開の面でないことを前提にします。 見張りの区分・判定の順・識別子の 4 つの形と名の照合の単位・GitHub への問い合わせの範囲とそれを外へ出してよい範囲とする解釈・読む上限と締め切り・着地の前の呼び出し・見張りの呼び出しの設定は変えません。 host の面に規則の行を置けない決まりも変えません (表は規則の行ではありません)。 持ち主の裁定は、 除外の一覧を host の面へ語のまま移すこと (2026-09-29T05:46Z) と、 公開の情報の扱いは推奨で進めること (2026-09-29T04:37Z) でした。 規則の行は公開の repo に載るので、 指紋にしても、 候補の語を指紋にして突き合わせれば一覧の語が分かり、 隣の repo の名の一部が読めます。 語のまま規則の行に置けばそのまま公開になり、 machine だけの秘密の値を混ぜると規則の行が machine ごとの値になります。 除外を持たなければ、 一般的な単語と同じ部分を持つ名の隣が在る machine で、 無害な公開が毎回止まります。 そこで除外を公開の面から外し、 git で追跡しない host の面に置きます。 どの隣の repo が在るかは machine ごとの事実なので、 その名に当たる語の除外も machine ごとの値で、 machine ごとの値を host の面に置く決まり (ADR-0026) に合います。 host の面が規則の行を持てない決まりは保ちます (表は規則の行でなく、 識別子の形の一覧は規則の行に、 判定の順は器の決まり (ADR-0078) に残ります)。 ただし、 群の表の anchor は判定を緩める鍵でないという ADR-0078 の根拠は、 当たりを数えなくする除外の表には当てはまりません。 規則の行の変更に裁定の番号を求める憲法 C5 の門 (CI) は追跡しない file に届かないので、 表の各行に裁定 id を持たせ、 欄の欠けた行を持つ面を読むときに断って、 値が裁定の番号の欄を持つところまでは保ちます。 番号が台帳で解けるかは測らないので、 中身のある偽の番号の行は効き、 host の面を書ける者は除外を足せます。 行の裁定の答えは host の面へ行を書く操作で済み、 語は追跡する文書に書かないので、 文書へ写すものがありません。 そのため行を求める問いは答えが操作で済む問いとして立て、 その裁定を未反映の裁定に数えません。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 3 つと、 代わりに引き受けること 6 つです。 良くなるのは、 公開の repo から除外の語も指紋も消えること、 裁定の番号の欄を欠く除外が黙って効かないこと、 器に指紋を計算する実装を足さずに済むことです。 引き受けるのは、 除外の変更が PR の差分と CI の門に現れず台帳の裁定だけが記録を持つこと、 置き場ごとの面に同じ行が要ること、 番号が台帳で解けるかは測らず中身のある偽の番号の行も効くこと、 1 行の欠けで面を読む口が丸ごと止まること、 問いを操作で済む問いとして立てることを強制する門が無いこと、 公開の面から語を読めないのは台帳の同期先が公開でないという前提に依ることです。

✓ 良い結果

  • ●PUBLIC な repo の tracked な file から除外の字句も digest も消え、 公開の字句を hash しても隣の repo の名の成分は読めない (字句が残る台帳の同期先は公開の面でないという前提の上で・CSQ-N6)
  • ●裁定 id の欄が無いか空の行を 1 行でも持つ面は読みで断られるので、 欄を欠く除外が黙って効くことは無い (id が台帳の裁定に解けるかは測らない・CSQ-N3)
  • ●照合は字句の比較になり、 器に digest (sha256) を計算する実装を足さずに済む

⚖ トレードオフ・代償

  • ●表が tracked でないので、 除外の変更は PR の差分と CI の門に現れず、 変更の記録は台帳の裁定 (裁定 id と裁定 event) だけが持つ
  • ●host の面は置き場 (state dir) ごとの 1 file なので、 置き場が複数の host では各面に同じ行を置く。 行を欠く面は除外が少ない側 (断る側) に倒れ、 公開の側には倒れない
  • ●読みが確かめるのは裁定 id の欄の有無と空だけで、 id が台帳の裁定に解けるかは測らない (FR83 が数えるのは追跡された file の字面だけ)。 欄に中身のある偽の id を持つ行は除外として効き、 host の面を書ける者は裁定なしに除外を足して当たりを外せる
  • ●除外の表の 1 行で裁定 id の欄が欠けるだけで、 host の面全体が在るが読めない host の面になり、 計測・口座の選定・管理 tick・doctor・席の起動・公開の字面の走査が typed に止まる (FR57 の極性)。 安全な側に倒れるが、 止まる範囲は除外の外に及ぶ
  • ●問いの effect は起票する者が選び、 除外の表の行を求める問いを operation で立てることを強制する門は無い。 document で立てれば FR84 が未反映の裁定と数え、 その裁定を引く契約を待たせる (安全な側に倒れる)
  • ●除外の字句は台帳の問いと裁定の行 (逐語の欄) にも残る。 公開の面から字句を読めないのは、 台帳の同期先が公開の面でないという前提の上でだけ成り立つ
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

この記録が版の系譜のどこに在るかと、 判断が最後に行き着く原則です。 この記録は ADR-0078 の一部を置き換えます。 置き換えるのは、 除外の一覧の置き場 (規則の行から host の面の表へ) と形 (指紋から語のままへ) だけで、 語の中の当たりの見方もここで閉じます。 見張りの区分・判定の順・識別子の 4 つの形・GitHub への問い合わせの範囲はそのまま保ちます。 host の面を machine ごとの値の置き場とした ADR-0026 は置き換えず、 面が受ける表を 1 つ足すだけです。 行き着く原則は「隠す字は、 公開の面に字のままでも、 当て直せる指紋でも置かない」です。
