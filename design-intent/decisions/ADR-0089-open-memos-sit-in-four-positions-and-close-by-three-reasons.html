設計判断記録 (ADR) scribe2 — memo の局面と閉じ方

開いた memo は宣言順の 4 つの局面のどれかにいて、 bead は種類ごとの閉じた理由の形でだけ閉じる — 昇格は memo を契約へ書き直す形と memo を残して契約を分け昇格の行を足す形の 2 つ、 全部の昇格が全部着地した memo だけを器が「昇格済み」で閉じ、 memo の見送りだけは user の裁定を要る (ADR-0051 と ADR-0085 の memo の昇格・close・数え・知らせ直しの止めの決定を部分 supersede)

memo (契約の前の覚え書き) を契約へ上げる形は 1 つしか決まっておらず、 候補の一部だけを上げた memo も、 辿れる契約が閉じると残りの候補ごと閉じる条件だった。 閉じた理由の字は自由で、 席が要望を黙って閉じても機械は見分けられない。 本 ADR は、 開いた memo の居場所を 4 つの局面に、 昇格を 2 つの形に、 bead を閉じる理由を種類ごとの閉じた形に閉じ、 器が閉じてよい memo と、 user の裁定なしには閉じられない memo を分ける。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は器が立てる対話の AI の session、 「台帳」は仕事と裁定を記録する beads、 「memo」は契約にする前の覚え書きの bead、 「契約」は 1 本ずつ作って取り込む仕事の約束です。 これまで memo を契約へ上げる形は「memo をそのまま契約に書き直す」1 つしか決まっておらず、 1 つの memo から契約を幾つかに分けたときに memo をいつ閉じるかの印がありませんでした。 決まっていた閉じる条件は「memo から辿れる契約が全部閉じたら閉じる」で、 候補の一部だけを契約にした memo も残りの候補ごと閉じ、 契約が着地せずに閉じても memo が閉じます。 閉じた理由の字も自由なので、 席が要望を黙って閉じても機械は見分けられません。 本 ADR は、 開いた memo の居場所を宣言した順の 4 つの局面 (昇格の途中・問いの返事待ち・処置の待ち・引き金待ち) に決め、 どこにも当たらない memo を misfit (形の崩れ) として見せます。 昇格は、 memo を契約に書き直す形と、 memo を残して契約を分け、 memo の notes に「昇格: 全部」か「昇格: 一部」と契約の番号を書く形の 2 つにします。 最後の昇格の行が「全部」で、 書いた契約の番号と memo から辿れる契約が一致し、 その全部が着地で閉じ、 子の問いが開いておらず、 審査役の判定が始末の無いまま残っていない memo だけを器が「昇格済み」で閉じます。 bead を閉じる理由は種類ごとに決まった形 (頭は 9 つ) に限り、 memo の閉じ方のうち見送りだけは、 その memo の子の問いへの user の裁定の番号を要ります (契約の重複・後継・取り下げは席が片付けます)。 形の外の理由で閉じる書き込みは台帳の書き込みの門が台帳を読まずに止め、 種類との食い違いや解けない番号は後から misfit として数えます (要件 FR91 と FR93 を中心に FR50・FR81・FR87・FR51・FR90、 根拠に FR83・FR94・NFR5)。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 6 つで示します。 経緯 (memo を契約へ上げる形が 1 つしか無く、 閉じる条件が「辿れる契約が全部閉じた」だった)・事象 (一部だけ上げた memo が残りごと閉じ、 閉じた理由の頭の語は 100 通りを越えて機械で読めない)・裁定 (user が memo の整頓の定義を推奨の案で決めた)・現物 (台帳の書き込みの門は閉じる書き込みの判定で台帳を読まず、 取り込みの最後の手順が台帳へ書くのは閉じる書き込みだけ)・憲法と既存の決定の向き・射程です。

CTX1

経緯 — ADR-0051 と ADR-0085 は昇格を 1 つの形だけで持ち、 memo契約の前の覚え書き を閉じる条件を「辿れる契約が全部 closed」に置いた

ADR-0051 は台帳の bead を label intake:memo と受入条件の設計 pointer の 2 つの印の 4 象限で閉じ、 memo から契約への遷移を 3 書き (受入条件に pointer 行を書く・label を外す・discovered-from契約から覚え書きへの辺 の辺を張る) として席の手番に置いた。 同じ ADR は memo の close を land の終端に置き、 その memo から discovered-from で辿れる契約が全部 closed になった周に閉じ (理由の字は着地の sha を持つ・設計 ledger-form.md §3 の 10)、 辿れない周と読めない周は閉じずに台帳の lint の項目 (同 §3 の 4 の (viii)) が名指す、 と決めた。 ADR-0085 は昇格条件の節を閉じた 5 形の引き金契約へ上げる条件の行の行にし、 処置覚え書きへの始末を 4 種 (昇格・close・引き金の行の書き直し・keep の記帳) に閉じ、 昇格を「受入条件に設計 pointer を持つ契約へ書き直す」と定め、 discovered-from で辿れる契約を持つ memo を昇格済みとして引き金の判定から外した。 ADR-0085 は、 審査の lens の close の判定で器が memo を閉じる案を、 器の close は land の終端の 1 か所 (計算で決まる close) に限られ、 閉じるか残すかは人 (席) の裁定である、 として退け、 memo の処置を席の手番に置いた (DR4)。 どちらの記録も、 1 つの memo から契約を複数に分ける形と、 close の理由の字の形を決めていない。

CTX2

事象 — 一部だけ上げた memo は残りの候補ごと閉じ、 閉じた理由の字は機械で読めない

memo は候補の節に複数の候補を持ちうり、 その一部だけが契約になることがある。 今の条件は、 memo に候補が残っていても、 辿れる契約が全部 closed になった周に memo を閉じる。 条件は契約の閉じ方を問わないので、 着地せずに閉じた契約だけでも memo は閉じる。 land の終端の memo の close はまだ code に無く (終端が閉じるのは便の契約だけ)、 台帳の lint が、 辿れる契約が全部 closed の open な memo を数えるだけである。 本 repo の台帳 (2026-09-28・bead 802 本) の実測: label intake:memo の bead は 129 本で open は 23 本、 memo でない bead から discovered-from で辿れる memo は 10 本 (辺 32 本・open な memo では 3 本) である。 閉じた bead 775 本の close_reason の最初の語は 102 通り、 閉じた memo 106 本では 53 通りで、 着地の形着地で閉じた印 (landed と着地 commit id で始まる字) は 251 本だけである。 閉じた memo が上がったのか・まとめられたのか・見送られたのかを機械は読めず、 席が要望を黙って閉じても見分けがつかない。 open な memo の notes は中央値 764 byte だが、 最大の 1 本 (s2-07l.669) は 41,133 byte の作業の記録になっている。

CTX3

裁定 — 案件の一生の方向と、 memo の整頓の定義 (問い 4)

user は 裁定 user 2026-09-28T12:46Z で、 案件 (memo か台帳の問いから始まり、 その子の問い・昇格した契約・便・着地までを束ねた単位) の一生を、 器・裁定面・user の間で 1 対 1 に揃え、 LLM の死角を残さず、 memo の整頓もこの粒度で定義する方向を決めた。 問い 4 (memo の整頓の定義と今の開いた memo の処置) は 裁定 user 2026-09-28T13:14Z で推奨の案を採った。 その推奨は、 開いた memo は名のある状態 (引き金待ち・問いの返事待ち・昇格の途中) のどれかにいて、 閉じた memo は名のある閉じ方 (昇格済み・まとめた・見送り〔裁定を要る〕) のどれかを持ち、 作業の記録を memo に置かない、 という形である。 草稿の審査が、 引き金が満ちた memo と処置の無い審査の判定を持つ memo の居場所が無いこと (ADR-0085 の処置の待ち) と、 着地の外の閉じでも閉じる条件の甘さを見つけ、 orchestrator が下の常設の指示の下で 4 つ目の局面一生のいまの位置 memo-actionable を足した。 SRS の審査は、 close の理由の文法閉じ方の決まった形が着地しない契約と decision の型の bead を覆わず、 席が閉じられない bead ができることを見つけ、 orchestrator は契約の閉じの形を重複・後継・取り下げ (理由の字つき・裁定 id を求めない) に広げると決めた (契約は席の作業の単位で、 片付けのたびに user の裁定を求めると自律を損ない、 要望を黙って落とさない保証は memo の側が持つ〔その場で昇格した契約の取り下げを除く・CSQ-N3〕)。 残りの分岐 (昇格の 2 形と昇格の行上げた契約を書く行の読み方・自動の close の契機と条件・門の入力・decision と epic の形・見送りの裁定を memo の子の台帳の問いの裁定に限ること) は 裁定 user 2026-09-28T00:54Z の常設の指示の下で推奨の形に決めた。 逐語は台帳にだけ在る (記録は memo s2-07l.739)。

CTX4

現物 — 起票の門台帳の書き込みを止める門は close の判定で台帳を読まず、 land の終端の台帳の書きは close だけで、 局面の出力が死角を数える

起票の門 (ADR-0056・FR81) は、 close の書きの判定では、 器の plugin を積む席の道具の呼び出しの bd / bdw の command の字面と本文の file だけを読み、 台帳を読まない (ADR-0085 の memo の書きの門と同じ線・hook の予算は NFR5 の 2.0 秒と重い I/O を持たない線)。 門が台帳を読むのは親の付け先の形の判定 (設計 ledger-form.md §12・掛かる書きの周に 1 回だけ) だけで、 その読みは低い負荷では 1 秒ほどで予算の内側だが、 負荷の間は予算を越え、 正しい書きを断り続けた (memo s2-07l.738.3)。 close の command の字面からは、 名指した bead が memo か契約かも、 理由の裁定 id が解けるかも分からない。 land の終端が台帳へ書くのは便の close で、 理由は着地の形 (landed と着地 commit id で始まる字) で CI の結果を持つ (ADR-0045 §2 の dispatcher の着地・FR50)。 これとは別に、 器の口 bind と裁定面の答えの口が、 台帳の問いの notes に裁定の行を書き、 問いを「裁定 <裁定 id>」で close する (FR82・ADR-0083)。 SRS 版 0.29 の台帳 adapter は、 器の台帳の書きを close と裁定の行 (FR50・FR82・FR93) の口に限り、 着地の形の close は land の終端だけが書く (FR81 (d))。 dispatch の周は周ごとに台帳を 1 回読み、 open な memo の全部の引き金を判じる (FR87)。 SRS 版 0.29 は、 部品 (局面の出力が局面と手番を導く閉じた 9 種の単位) ごとの局面を器が 1 つの判定で導き、 どの局面にも当たらない部品を misfitどこにも当たらない印 と理由の語で出し、 close した部品を出力に載せる窓 (rules 行 lifecycle.closed_window_h) を表示にだけ掛ける局面の出力を持ち (FR90・同じ束の ADR-0088)、 便の終端の周の通知・doctor の行・管理 tick の alarm などの読み手は自前の判定を持たずにその結果を使う (FR94)。 memo の子に台帳の問いを起こすと親の label intake:memo を継ぐので、 継がない指定を持たない create は起票の門が断る (FR81 (a)・同じ束の ADR-0087)。

CTX5

憲法と既存の決定の向き — 1 関数と宣言順・台帳は task と裁定だけ・編集の時点の止め

C2 は選別と経路を 1 つの列挙の上の 1 関数にし、 適用の順を列挙の宣言順だけから取り、 順の散文を持たない。 C15 は台帳を task と裁定の記帳に限り、 規律を置かない (知見は ADR と research へ)。 C16 は仕様からの外れを編集の時点で止め、 後の検証で代えない。 C1 は規則の値を manifest の 1 file に置き、 C5 は rules 行の変更に user の裁定 id を求める。 C17.2 は記録・rules 行・仕組みを足す前に、 消すものを名指させる。 N2 は散文にしか無い規則を規則と認めない。 ADR-0053 は計算できる判断を code に、 意味の判断を lens に、 裁定を人に置く。 要望を落とすかは user の判断で、 席の判断で memo を閉じる形は、 要望の取りこぼしを席が作れる形である。 見送りの裁定 id を memo の子の台帳の問いの裁定に限れば、 その裁定がどの memo を落とす裁定かを台帳の親子の辺で確かめられる。 契約は設計から起こした席の作業の単位で、 その片付け (重複・後継・取り下げ) は席の手番に置ける。 本 ADR は C16 の読みを決める: 起票の門は hook の予算 (NFR5) の内側で字面から判じられる外れを編集の時点で止め、 台帳の中身を要る判定 (bead の種類・id の解け・notes の大きさ) は局面の出力と台帳の lint が後から件数と id で数える。

CTX6

射程 — 動かすのは局面・昇格の形・自動の close・close の理由の文法・notes の上限の 5 つ

要件は SRS 版 0.29 の FR91 (memo の局面と処置・常時)・FR93 (memo の自動の close) と、 改訂した FR50 (close の理由の頭と land の終端の台帳の書きの範囲)・FR81 (起票の門の 4 つの断りの (d))・FR87 (処置の中身と処置の待ちの数え)・FR51 (処置の待ちと notes の上限)・FR90 (局面の出力の misfit)・FR94 (局面の出力の読み手) が持ち、 AC61 が測る。 動かすのは、 開いた memo の局面の判定、 昇格の形、 memo の自動の close の条件と契機、 bead の close_reason の文法と門、 memo の notes の上限の lint の 5 つである。 動かさないのは、 memo の 4 節と 4 象限、 引き金の 5 形と審査の lens (本数・間隔・判定の 3 値)、 器が審査の判定で memo を閉じないこと、 land の終端の台帳の書きが close だけであること (FR50)、 bind と裁定面の答えの口の書き (FR82)、 起動の列 (memo は便を起こさない)、 処置の 4 種の数である。 局面の出力の置き場・手番・年齢・書き直しの契機は同じ束の ADR-0088 が、 発話を memo へ結ぶ仕分けは ADR-0087 が持つ。 局面の値 memo-actionable は、 前の器が消した棚卸しの印 [MEMO-DUE] (ADR-0085) と字を分けた別の語である。 昇格の行と close の理由の字面の正本は本 ADR が持ち、 SRS は形の名だけを持つ (FR91・FR50 の着地の形・FR82 の裁定の形)。 設計 ledger-form.md の改稿が文法を写す。 ADR を書く条件のうち 1 (C16 と C15 の読み)・3 (notes の行の形・close_reason の形・rules 行は版を跨ぐ形)・4 (却下案を残す価値のある分岐) に当たり、 ADR-0051 と ADR-0085 の決定の一部を置き換える。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。 4 つの局面と 2 つの昇格の形と種類ごとの閉じた理由の形を決める案 (選んだ案)、 今の条件のまま辿れる契約が全部閉じたら閉じる案、 memo を閉じずに開いたまま置く案、 memo の見送りを席の判断で書ける案、 門が台帳を読んで確かめる案、 契約の取り下げにも裁定の番号を求める案です。

OPT1開いた memo を 4 つの局面に置き、 昇格を 2 形にし、 全部の昇格が全部着地した memo だけを器が閉じ、 bead を閉じる理由を種類ごとの閉じた形に限る採用

開いた memo は memo-promoting・memo-asking・memo-actionable・memo-waiting の宣言順のどれかにいて、 読める引き金の行を持たず memo-promoting にも memo-asking にも当たらない memo と、 当たらない memo は局面 misfit で出る。 昇格は memo を契約へ書き直す形 (1 memo → 1 契約) と、 memo を残して契約を分け notes に昇格の行 (全部か一部と契約 id の列) を足し discovered-from を張る形の 2 つ。 land の終端が契約を close した周と dispatch の周は、 自動の close の条件 (最後の昇格の行が全部で、 その行の契約 id の列と discovered-from で辿れる契約の列が一致して 1 本以上在り、 その全部が着地の形で閉じ、 子の開いた台帳の問いと処置の無い昇格か close の審査の判定を持たない) を満たす memo (閉じるまでは memo-promoting) を「昇格済み <契約 id の列>」で閉じ、 それ以外の閉じ残りは memo-actionable で席の手番にする。 close_reason は種類ごとの閉じた形の和 (頭は 9 つ・種類との組は 10 形) に限り (契約・台帳の問い・memo・epic・decision の型の全部に形があり、 裁定 id を要るのは memo の見送り〔memo の子の台帳の問いの裁定〕と、 裁定そのものを記す問いと decision だけ)、 起票の門は台帳を読まずに和の外と席の着地の形の close を断り、 種類と形の食い違いと解けない id は局面の出力が misfit で数える。 memo の notes の大きさは rules 行の上限を越えると台帳の lint が名指す。 決め手は裁定 13:14Z (開いた状態 3 つ・閉じ方 3 つ・見送りは裁定) と、 常設の指示 00:54Z の下の orchestrator の決定 (4 つ目の局面・昇格の 2 形・自動の close・契約と epic と decision の閉じの形・見送りの裁定を memo の子の問いの裁定に限る) と、 分析 (要望を落とす出口が、 数えの外の 3 つ〔その場で昇格した契約の取り下げ・「まとめた」の移しの妥当さ・「全部」か「一部」かの宣言と書き直す昇格が候補の全部を覆うか〕を除き user の裁定だけに残り、 契約の片付けは席に残り、 門は close の判定で台帳を読まない)。

選んだ案です。 開いた memo は、 優先の順に、 昇格の途中 (memo から辿れる契約が開いているか、 器が閉じる条件を満たして閉じるのを待つ)・問いの返事待ち (memo の子の台帳の問いが開いている)・処置の待ち (引き金が満ちて「残す」の記帳が無い・審査役の「上げる」か「閉じる」の判定に始末が無い・昇格の行を持ち辿れる契約に開いたものが無いのに器が閉じる条件を満たさない)・引き金待ち (読める引き金が在って満ちないか、 満ちた引き金に「残す」の記帳が付いた) のどれかにいます。 読める引き金が 1 つも無く昇格の途中でも問いの返事待ちでもない memo と、 どれにも当たらない memo は misfit です。 昇格は、 memo をそのまま契約に書き直す形と、 memo を残して契約を分け notes に「昇格: 全部」か「昇格: 一部」と契約の番号を書く形の 2 つです。 最後の昇格の行が「全部」で、 行に書いた契約の番号と memo から辿れる契約が一致して 1 本以上在り、 その全部が着地で閉じ、 子の台帳の問いが開いておらず、 審査役の「上げる」か「閉じる」の判定が始末の無いまま残っていない memo だけを、 器が、 land の終端 (取り込みの最後の手順) が契約を閉じたときか便を起こす仕組みの回に「昇格済み」と閉じます。 bead を閉じる理由は種類ごとの決まった形 (頭は 9 つ) に限り、 memo の見送りには、 その memo の子の問いへの user の裁定の番号が要ります。 契約の重複・後継・取り下げは席が理由を添えて片付けます。 形の外は門が台帳を読まずに止め、 種類との食い違いや解けない番号は後から misfit で数えます。 memo の notes が上限の大きさを越えたら点検が名指します。 落とす出口が (その場で昇格した契約の取り下げと、 「全部」か「一部」かを席が正しく書いたかを除き) user の裁定だけに残り、 「一部」と書いた昇格が残りを巻き込まず、 門が閉じる判定で台帳を読まない点で勝ります。 代わりに、 席が書く行が増え、 字の形で止められない崩れは後から数えるだけになり、 契約の取り下げの妥当さは機械で確かめず、 その場で昇格した契約の取り下げは数えの外に残り、 「まとめた」の候補が本当に移ったかも、 「全部」か「一部」かを席が正しく書いたか (memo を書き直した契約が候補を全部覆うかも) も確かめず (席が「全部」と書けば、 器は残りの候補ごと memo を閉じます)、 今ある memo の移し替えと版を跨ぐ約束が増えます。

+ 利点

  • 閉じた bead の理由から閉じ方が機械で読め、 memo の見送りは user の裁定 id に結び、 着地の外で閉じた契約を辿る memo は memo-actionable に残るので、 席が要望を黙って落とす形が門と misfit の 2 か所で見える (その場で昇格した契約の取り下げ・「まとめた」の移しの妥当さ・「全部」か「一部」かの宣言と書き直す昇格が候補の全部を覆うかは数えの外・DR1)
  • 開いた memo は 4 つの局面か misfit のどちらかに必ず出て、 判定は 1 つの関数と列挙の宣言順で決まる (DR2)
  • 昇格の行に「一部」と書いた memo は残りの候補ごと閉じず、 分けた契約が全部閉じた後に memo-actionable として席へ戻る (DR3)
  • 門は close を字面だけで断り台帳を読まず、 器の台帳の書きに足すのは memo の自動の close (close の 1 種) だけ (DR4)
  • どの種類の bead にも閉じる形があり、 契約の重複・後継・取り下げは席がその場で片付けられる。 memo を契約へ書き直す昇格は今の 3 書きのまま通る。 足すのは notes の 1 行の形と理由の文法と rules 行 1 本 (DR5)
  • 作業の記録を積んだ memo を台帳の lint が名指す (DR6)

− 欠点

  • 分ける昇格では席が昇格の行と discovered-from の 2 つを書き、 両者が食い違う memo は自動の close をされず、 後から memo-actionable で見えるだけ
  • 門は字面しか見ないので、 種類と形の食い違い・解けない id・notes の大きさは編集の時点で止まらず、 局面の出力と台帳の lint が後から数える (C16 の編集の時点の止めは和の形まで)
  • 契約の取り下げは理由の字を添えれば席が閉じられるので、 取り下げの妥当さは機械で確かめず、 保証はその契約を辿る memo の memo-actionable と、 行の着地との突き合わせ (局面の出力の設計) に頼り、 その場で昇格した (memo を書き直した) 契約の取り下げは辿る memo が残らず数えの外に残る。 「まとめた」で候補が本当にまとめ先の memo へ移ったかも機械は確かめない。 「全部」か「一部」かの宣言と、 memo を契約へ書き直す昇格が候補の全部を覆うかも機械は確かめず (memo の候補の節は自由な文)、 席が「全部」と書けば器は残りの候補ごと memo を閉じ、 書き直しでは残りの候補が契約の着地と共に消える
  • 既存の open な memo 23 本と、 memo でない bead から辿れる 10 本の memo は、 昇格の行・辺・読める引き金を足すまで memo-actionable か misfit に出る
  • 跨版の面 (昇格の行の字面・close_reason の頭の 9 形・rules 行 1 本・misfit の理由の語) が増える
OPT2宣言なしに、 辿れる契約が全部閉じたら器が memo を閉じる (ADR-0051 の条件のまま)不採用

memo から discovered-from で辿れる契約が全部 closed になった周に、 land の終端が memo を閉じる。 昇格の行も close の理由の文法も持たない。 決め手は分析 (一部だけ上げた memo が残りの候補ごと閉じ、 契約の閉じ方を問わない)。

今の決まりのまま、 memo から辿れる契約が全部閉じたら、 land の終端 (取り込みの最後の手順) で器が memo を閉じる案です。 席は辺を 1 つ張るだけで済み、 上がり切った memo が開いたまま残らず、 新しい形も足さない点で勝ります。 けれども、 候補の一部だけを上げた memo も、 上げた契約が閉じると残りの候補ごと閉じます。 契約の閉じ方も問わないので、 着地せずに閉じた契約だけでも memo が閉じ、 要望が黙って落ちます。 閉じた理由の字は自由なままで、 閉じ方を機械で読めません。 だから退けました。

+ 利点

  • 席の書きが辺の 1 つで済み、 notes に行を足さない
  • 器が閉じるので、 上がり切った memo が開いたまま残らない
  • 既に決まっている条件で、 新しい形を足さない (C17.2)

− 欠点

  • 一部の候補だけを上げた memo も、 上げた契約が閉じると残りの候補ごと閉じる (DR3)
  • 契約の閉じ方を問わないので、 着地せずに閉じた契約だけでも memo が閉じ、 要望が黙って落ちる (DR1)
  • 閉じた理由の字は自由なままで、 閉じた memo の閉じ方を機械で読めない (DR1・DR2)
OPT3memo を閉じず、 昇格しても開いたまま置く不採用

memo を閉じる条件を持たず、 昇格した memo も開いたまま置き、 一覧で昇格済みと見せる。 決め手は分析 (開いた memo の母集団が膨らみ、 処置の要る memo が埋もれる)。

memo を閉じる条件を持たず、 契約へ上げた memo も開いたまま置き、 一覧で「上げ済み」と見せる案です。 残りの候補が閉じて落ちることが無く、 自動で閉じる仕組みも理由の決まりも要らず、 経緯が 1 つの bead に残る点で勝ります。 けれども、 開いた memo が上がり切った分で膨らみ、 始末の要る memo が埋もれます。 「開いている」が「まだ何かが要る」を意味しなくなり、 局面を 1 つ足すか、 読み手が自分で判じ直すことになります。 席の判断で閉じる形 (見送りなど) をどう扱うかも残ります。 だから退けました。

+ 利点

  • 残りの候補が閉じて落ちることが無い (DR3)
  • 器の自動の close も close の理由の文法も要らない
  • 経緯が 1 つの bead に開いたまま残る

− 欠点

  • 開いた memo の母集団が上がり切った memo で膨らみ、 処置の要る memo が埋もれる (DR2)
  • 「開いている」が「まだ何かが要る」を意味しなくなり、 局面が 1 つ増えるか、 読み手が自前で判じる (DR2)
  • 席の判断で閉じる形 (見送りなど) を別に決める手は変わらず残る (DR1)
OPT4memo の見送りを席の判断で書ける (close の理由の文法は持つが、 見送りに裁定を要らない)不採用

close の理由の文法は持つが、 memo の見送りを、 席が理由の字を添えて書ける。 決め手は分析 (要望の取りこぼしを席が作れる) と裁定 13:14Z (見送りは裁定を要る推奨を採った)。

閉じる理由の決まった形は持つが、 memo の見送りを、 席が理由の字を添えて自分の判断で書ける案です。 席が要らないものをその場で閉じられ、 user に問う手間が増えず、 理由の字が残る点で勝ります。 けれども、 要望を落とすかを席が決めるので、 user の知らないうちに要望が消えます。 理由の字は自由なので、 見送りが妥当だったかを機械は確かめられず、 user が知るのは閉じた後で、 見送りの前には止められません。 user が打った字 (発話) が要望として残らないという入口の取りこぼしと同じ型を、 memo の出口に残します。 user も見送りに裁定を要る推奨を採ったので、 退けました。

+ 利点

  • 席が要らない memo をその場で閉じられ、 user に問う手番が増えない
  • 見送りの理由の字が残るので、 後から読み返せる
  • 台帳の問いを起こさずに閉じられ、 手順が短い

− 欠点

  • 要望を落とすかを席が決め、 user の知らないうちに要望が消える (DR1)
  • 理由の字は自由な字で、 見送りの妥当さを機械は確かめられず、 user が知るのは閉じた後で、 見送りの前には止められない (DR1)
  • 発話が要望として残らないという入口の取りこぼしと同じ型を、 memo の出口に残す (DR1)
OPT5起票の門が台帳を読んで、 閉じる bead の種類と理由の形と id の解けを確かめる不採用

起票の門が close の書きのたびに台帳を読み、 名指した bead の種類に合う形か、 見送りの裁定 id が解けるか、 昇格済みの契約が全部着地したかを確かめて断る。 決め手は分析 (負荷の間は hook の予算を越え、 §12 の台帳の読みが timeout で正しい書きを断り続けた実例が在る)。

台帳の書き込みの門が、 閉じる書き込みのたびに台帳を読み、 閉じる bead の種類に合う形か、 見送りの裁定の番号が本当に在るか、 上げた契約が全部着地したかを確かめて止める案です。 崩れた閉じを書く時点で止められ、 後から数える手が要らず、 正しい形を名指して断れる点で勝ります。 けれども、 閉じるたびに台帳を読むので、 負荷の間は道具を 1 回使うごとの門の時間の予算 (2 秒以内・重い読み書きを持たない) を越え、 正しい閉じる書き込みを止めます (門が親の付け先を確かめる読みで起きた実例があります)。 負荷の低いときも、 閉じるたびに 1 秒ほどの読みが足されます。 台帳を読む判定が親の付け先の判定の外へ広がり、 読めないときは止める向きを閉じる書き込みにも持ち込みます。 だから退けました。

+ 利点

  • 種類と形の食い違いと解けない id を編集の時点で止められる (C16)
  • 後から misfit で数える手が要らず、 崩れた閉じが台帳に入らない
  • 門の断りに正しい形を名指せる

− 欠点

  • close の書きごとに台帳を読み、 負荷の間は hook の予算 (NFR5 の 2.0 秒と重い I/O を持たない線) を越えて正しい close を断る (設計 ledger-form.md §12 の親の付け先の判定の実例・memo s2-07l.738.3・DR4)
  • 低い負荷の周でも、 close ごとに 1 秒ほどの読みが足される (§12 の実測 0.83〜1.13 秒・DR4)
  • 台帳を読む判定が §12 の親の付け先の判定の外へ広がり、 timeout の極性 (読めない周は断る) を close にも持ち込む (DR4・DR5)
OPT6契約の取り下げにも裁定 id を求める (契約の閉じの形を着地と「取り下げ <裁定 id>」の 2 つにする)不採用

着地しない契約の閉じは全部「取り下げ <裁定 id>」とし、 重複や後継の片付けにも user の裁定を求める。 決め手は orchestrator の決定と分析 (席の作業の単位の片付けに毎回 user の手が要り自律を損ない、 要望を落とさない保証は、 その場で昇格した契約の取り下げを除き memo の側で足りる)。

着地しない契約の閉じを全部「取り下げ <裁定の番号>」にし、 重複や後継の片付けにも user の裁定を求める案です。 契約を着地させずに閉じる判断が全部 user の目を通り、 形が少なく、 要望と契約の出口に同じ線が引け、 選んだ案が数えの外に残す穴 (その場で昇格した契約の取り下げ) も塞げる点で勝ります。 けれども、 契約は席の作業の単位で、 重複して起こした契約や後継へ移した契約の片付けにも毎回 user の手が要り、 自律を損ないます。 要望を黙って落とさない保証は、 着地の外で閉じた契約を辿る memo が処置の待ちに残って始末を求められることで memo の側にほぼ在ります (その場で昇格した契約は辿る memo が無いので覆いません)。 裁定を待つ間は重複した契約が開いたまま残り、 便を起こす列から外す手を打たない限り、 同じ仕事の便が 2 本起きえます。 だから退けました。

+ 利点

  • 契約を着地させずに閉じる判断が全部 user の裁定に結び、 取り下げの妥当さを user が必ず見る (DR1)
  • 契約の閉じの形が 2 つで少なく、 id の解けを FR83 の解け方 1 つで判じられる
  • 要望と契約の両方の出口に同じ線 (落とすのは裁定だけ) が引かれ、 説明が揃う
  • その場で昇格した (memo を書き直した) 契約の取り下げ (OPT1 が数えの外に残す穴・CSQ-N3) も裁定に結び、 辿る memo の無い契約でも要望が黙って落ちない (DR1)

− 欠点

  • 重複して起こした契約や後継へ移した契約の片付けにも毎回 user の裁定が要り、 席の作業の単位の片付けで自律を損なう (DR5)
  • 要望を落とさない保証は、 着地の外で閉じた契約を辿る memo が memo-actionable に残って処置を求められることで memo の側にほぼ在り、 契約の全部に重ねる要が薄い (ただし memo の側の保証はその場で昇格した契約を覆わない・CSQ-N3・DR1)
  • 裁定を待つ間、 重複した契約が開いたまま起動の列に残り、 defer で列から外さない限り、 同じ仕事の便が 2 本起きうる (DR5)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが支える要件です。 開いた memo は 4 つの局面のどれかにいて、 優先の順は宣言した順だけで決まります。 昇格は 2 つの形で、 全部を上げた memo の契約が行の番号と一致して全部着地で閉じ、 子の問いが開いておらず、 審査役の判定が始末の無いまま残っていないときだけ器が閉じます。 bead を閉じる理由は、 契約・台帳の問い・memo・epic・decision の型のどれにも決まった形があり、 形の外は門が止め、 崩れは misfit で数えます。

採用 — OPT1
