設計判断記録 (ADR) scribe2 — trust の印を器が起動の前に置く

口座 × anchor の trust の印は席の起動が置く — seat launch の 1 本が prepare の後・置き換えと boot の分岐の前に、 選んだ口座の設定 dir の .claude.json に、 その anchor の trust の印を true で置いてから起動行を注入する。 依存は足さず既存の入れ子 JSON の読み手に書き手を足し、 言葉は閉じた列 written / created / accepted / unreadable / unwritable、 起動は止めない (ADR-0026 §2.2 / §2.5 の trust の受け入れと代筆の射程外を trust の印 1 key に限って部分 supersede・credential の fence は不変)

席が別の口座へ移るとき、 その口座がその repo (anchor) を一度も「信じる」と答えていないと、 Claude Code は起動直後に trust の dialog (既定は No, exit) を出して席が立たない。 群の自動の移動 (ADR-0049 §2・ADR-0055) と init が起こす席 (ADR-0063) はここで人の手を待つ (2026-09-25 の本番の移動でも持ち主が手で承認した)。 本 ADR は、 席の起動の 1 本 (seat launch) が登録 row を書いた後・自分の process の置き換えと起動行の注入の分岐の前に、 選んだ口座の設定 dir の .claude.json の該当の印 (projects の下の <anchor> の hasTrustDialogAccepted) を true に置くと決める。 依存は足さず (NFR3)、 既存の入れ子 JSON の読み手に「path に真偽を置く 1 関数」と「一時 file → 読み直し → rename の書き戻し」を足す。 結果は閉じた言葉 (written / created / accepted / unreadable / unwritable) で起動の 1 行の末尾に添え、 印を置けない周も起動は止めない。 書く相手は「今起こす口座 × 今の anchor」の 1 組に閉じ、 .credentials.json と settings.json は触らない。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「席」は人と AI が話す 1 つの session、 「口座」は席が使う Claude Code の login 単位、 「anchor」は対象 repo の本体の場所、 「信じた印」(trust の印) は口座ごとの設定 file (.claude.json) に置かれる「この folder を信じる」と答えた記録です。 Claude Code は、 その口座で一度も信じると答えていない folder で起動すると、 起動直後に「信じるか」の問い (trust dialog・既定は No, exit) を出し、 答えるまで席は立ちません。 席が別の口座へ移るとき (群の移動) や、 新しい repo を載せて初めて席を起こすとき (init) は、 ここで人の手を待ちます。 2026-09-25 の本番の移動でも、 持ち主が手で承認するまで席は立ちませんでした。 この記録は、 席を立てる口 (seat launch) が、 席の登録を書いた後・起動行を差し込む (か自分の process を置き換える) 前に、 選んだ口座の設定 file の該当の印を「信じる」に置いてから起動行を送ると決めます。 新しい部品 (依存) は足さず、 器がすでに持つ入れ子 JSON の読み手に「印を置く」と「書き戻す」の 2 つの関数を足します。 書くのはその 1 key だけで、 他の key と並びと値は保ち、 一時 file に書いて読み直してから置き換えます。 結果は 5 つの言葉 (置いた・作って置いた・すでに信じていた・読めなかった・書けなかった) のどれかで起動の記録と起動の 1 行の末尾に残し、 印を置けなくても席は立てます。 書く相手は「今起こす口座 × 今の anchor」の 1 組だけで、 credential と settings の file は触りません。 前の決定 (ADR-0026) の「login そのものと trust の受け入れは user が行い、 器は credential に触りません」のうち trust の受け入れを、 この 1 key に限って置き換えます (credential には触らないままです)。 要件書では、 席の起動 (FR59) の内側にこの 1 手を足し、 群の移動 (FR38) が人の手を待たない根拠になり、 依存 0 本 (NFR3) を保ちます。 この記録は、 受け入れられるまで何も拘束しない発効前 (proposed) の記録です。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 2 度の決定と、 実際に起きたことと、 器の今の部品と、 これまでの決まりから説明します。 群の移動の実地試験で、 移り先の口座がその repo を一度も信じると答えていないと、 起動直後の問い (trust dialog) で席が立たない穴が見つかりました。 1 回目の決定 (2026-09-24 13:38 UTC) は JSON を扱う部品を足して器が印を書く案を受け入れましたが、 器にはすでに入れ子 JSON の読み手が在り、 部品を足す案は「依存 0 本」の要件を書き換える必要があったので、 前提が誤りでした。 2 回目の決定 (同じ日の 22:56 UTC) は、 部品を足さず、 その読み手に書き手を足す形を受け入れ、 前の決定を取り下げました。 その後の 2026-09-25 の本番の移動では、 移り先の席が問いで止まり、 持ち主が手で承認するまで立ちませんでした。 器の部品は、 JSON を木として読んで戻す読み手と、 点検 (doctor) がその木から印を読む口までは在りますが、 木の path に真偽を置く関数と、 置いた木を同じ file へ書き戻す関数の 2 つが在りません。 席を立てる口は、 口座を選び、 起動行を組み、 登録を書いた後、 呼び手の窓が席の窓と同じなら自分の process を起動行に置き換え、 違えば窓へ差し込みます。 呼ぶ場所は 3 つ (人が打つ形・群の移動・見回りの移動) で、 席の立て直しの経路は前の決定 (ADR-0045) で消えているので、 席の起こし直しは全部この口を通ります。 決まりの側では、 依存 0 本・足す前に外す物を名指す・描画を判定に使わない・環境変数を読まない、 が効き、 前の決定は「器は credential の file に書かず、 trust は user が答える」としていました。 書く相手は席を起こすその 1 組に閉じ、 credential と settings と点検は触りません。

CTX1

経緯 — 2 度の裁定と、 取り下げた前提

群の移動口座の乗り換えの実地試験 (memo s2-07l.604) で、 移り先の口座がその anchorrepo の本体の場所 を一度も trust していないと起動の trust dialogfolder を信じる問い (既定は No, exit) で席が立たない穴 (a) が見つかった。 2026-09-24T13:38Z の裁定は「serde_json を依存に足して器が印を書く」推奨を受諾したが、 器には既に入れ子 JSON の読み手 (doctor点検の 1 コマンド の trust= の行が使う) が在り、 依存を足す案は SRS NFR3 (実行時の直接依存 0 本) の改稿を要するので、 推奨の前提が誤りだった。 2026-09-24T22:56Z の裁定は「依存を足さず、 既存の読み手に書き手を足す形で器が塞ぐ」推奨を受諾し、 前の裁定を取り下げた。 要旨だけを写し、 逐語は非公開の作業記録簿 (台帳 s2-07l.609) に在る。

CTX2

実測 — 2026-09-25 の本番の移動で、 持ち主が手で trust を承認した

2026-09-25 の群の自動の移動 (台帳 s2-07l.617) では、 tick が移り先の口座で席を起こしたが、 その口座はその anchor を trust しておらず、 起動の dialog で止まった (tick の記録は launched=launch-unconfirmed)。 席が立ったのは持ち主が手で承認した後である。 群の移動 (ADR-0049 §2・ADR-0055) は「新しい口座で新しい席を起こし、 復帰は機械の注入に任せる」と決めたが、 この 1 手だけが人の手に残っている。 init (ADR-0063) が起こす初回の席も同じ穴を持つ。

CTX3

現物 — 読み手は在るが、 置く関数と書き戻す関数が無い

base 80270bd で、 入れ子 JSON の読み手 (parse / Tree / render) は RFC 8259 の 6 形を読み、 数は 10 進の字面のまま持ち、 重複 key を拒み、 木を JSON に戻せる。 doctor の trust= の行 (accepted / missing / unreadable) は、 この読み手で口座の設定 dir口座ごとの設定の置き場 の .claude.json の projects の下の <anchor> の hasTrustDialogAccepted を読む (読むだけ)。 無いのは、 木の path に真偽を置く 1 関数と、 置いた木を同じ file へ書き戻す 1 関数の 2 つ。 席の起動席を立てる口の 1 本 (launch) は model → 役割の既定 → 口座の選定 → 起動行の導出 → prepare が登録 row を書く、 まで進んだ後で 2 つに分かれる。 呼び手の pane が target と同じ周 (置き換え・約束 7) は boot を通らず、 自分の process を起動行へ exec で置き換えて返らない (stdout の 1 行も Launched も無く、 記録は record_launch が exec の前に inject.jsonl へ 1 行書く)。 それ以外の周は boot が注入し、 結果は Launched (Done / None / Refused / Failed)。 呼び手は 3 つ (seat の長い形と短い形・群の移動の周に席を起こす経路・tick の移動の周)。 席の立て直しの経路は ADR-0045 §2 (2) で消えており (relaunch.rs が持つのは boot と初回の選定だけ)、 席の起こし直しは全部この 1 本を通る。 口座の設定 dir は state dir の accounts の下の label の dir (実 dir か symlink) で、 ADR-0017 §2.3 の経路で解く。

CTX4

射程 — 書くのは起動の 1 本だけ、 credential と settings と doctor は触らない

書くのは席の起動の 1 本だけで、 init と account add は書かない (書く相手を「今起こす口座 × 今の anchor」の 1 組に閉じる)。 doctor の trust= の行は読むだけのまま (書いた後の周は accepted と読める＝それが確認)。 .credentials.json と settings.json は書かない (ADR-0017 の fence のまま)。 pane の字面で dialog に答える形は持たない (C3.3)。 Tree の形と parse の判定・prepare と登録 row・Launched の他の variant は変えない。 README の「新しい repo を器に載せる」の trust の 1 文は後続の docs で書く。

CTX5

憲法と既存の決定の向き (本 ADR の解釈)

NFR3 は実行時の直接依存 0 本 (std だけで build) を求め、 C17.2 は仕組みを足す前に何を外すかを名指させる。 C3.3 は端末の描画や自由文を判定入力にしない。 C2.2 は env を読まず、 口座の設定 dir は state dir から解く (ADR-0017 §2.3・ADR-0026 §2.1)。 A1 は消す・出す・使うの 3 クラスを user に聞く。 本 ADR の読みでは、 .claude.json の 1 key の設置は 3 クラスに当たらない (消さず・repo の外に出さず・新しい資源を使わない)。 口座を使うこと自体は群の宣言の常設の承認 1 回で以後は都度聞かない (ADR-0049 §2)。 N1 は人の手で置いた物を壊さない。 ADR-0017 §2.3 は器が credential を読まず・書かず・代筆しないと決め (§2.5 は再 login を user の手番とするが、 .claude.json と trust には触れていない)、 ADR-0026 §2.2 は「login そのものと trust の受け入れは user が行い、 器は credential に触りません」と決め、 ADR-0026 §2.5 は login と trust の代筆を射程外 (account-autonomy.md §10 で却下済み) とした。 設計 §10 の当時の却下の理由は、 Claude Code の私有形式への書込 (ADR-0017 §2.5 と同じ fence と類推・credential と同じ dir) と、 trust は user が folder を信じる宣言＝器が代筆すると信じていない folder を信じたことになる、 の 2 つ。 ADR-0063 は trust を器が埋めるかを別の裁定と後続の ADR に送った。 ADR-0045 §2 (2) は席の立て直しを消し、 orchestrator の再起動は user が seat launch を撃つと決めた。 ADR-0049 §2 と ADR-0055 は群の移動を「新しい口座で新しい席を起こす」と決め、 ADR-0063 は init の 7 手を 3 語に閉じた。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 群の移動と init が起こす席が人の手を待たないこと。 部品 (依存) を足さず、 すでに在る読み手に書き手を足すだけにすること。 Claude Code の file の他の key と並びと値を保ち、 書くのは 1 key だけにし、 credential と settings は触らないこと。 書く相手を「今起こす口座 × 今の anchor」の 1 組に閉じ、 信じていない folder を信じた印を撒かないこと。 起動を止めず、 結果は決まった言葉で残し、 画面の描画は読まないことです。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 7 つ並べます。 席を立てる口が登録の後・差し込みの前に既存の読み手に足した書き手で印を置く案 (選んだ案)、 JSON の部品を足して書く案、 設定 file を丸ごと書き直す案、 画面の問いを読んで key を送る案、 repo を載せる init の段で全部の口座に先に印を置く案、 印が無ければ起動を断る案、 設定 file の中身を host の宣言 file に写す案です。 却下した 6 案にも利点を並べ、 退けた決め手が現物か分析かを各案に書きます。 部品を足す案は書き手の code が最小になる点で、 丸ごと書く案は書き手が単純になる点で、 画面を読む案は file に触らない点で、 init で先に置く案は起動の口を変えない点で、 起動を断る案は Claude Code の file を書かない点で、 宣言に写す案は器が読むのを自分の面だけにできる点で、 選んだ案に勝ります。

OPT1席の起動の 1 本が prepare の後・置き換えと boot の分岐の前に、 既存の読み手に足した書き手で印を置く採用

launch が登録 row を書いた後・置き換えと注入の分岐の前に 1 回だけ (置き換えの周も注入の周も同じ 1 回を通る)、 選んだ口座の設定 dir の .claude.json の projects の下の <anchor> の hasTrustDialogAccepted を true に置く。 書き方は同じ読み手で読み → 木の path に真偽を置く → 一時 file に書き → 読み直して確かめ → rename。 言葉は written / created / accepted / unreadable / unwritable の閉じた列で起動の記録に残し、 どの言葉でも起動行は送る。 決め手は分析 (裁定の推奨を、 依存を足さず 1 key だけを 1 組にだけ書く形で満たす)。

席を立てる口が、 席の登録を書いた後・置き換えか差し込みかの分かれ目の前に 1 回だけ、 選んだ口座の設定 file (.claude.json) の該当の印を「信じる」(true) に置く案です。 器がすでに持つ入れ子 JSON の読み手に、 「木の path に真偽を置く」と「書き戻す」の 2 つの関数を足して使います。 書き方は、 読んで、 置いて、 同じ dir の一時 file に書いて、 読み直して確かめて、 置き換える、 の順です。 結果は 5 つの言葉 (置いた・作って置いた・すでに信じていた・読めなかった・書けなかった) のどれかで起動の記録に残し、 どの言葉でも起動行は送ります。 群の移動と init が起こす席で人の手が消え、 部品を足さず、 他の key と並びと値は保ち、 書くのは今起こす 1 組だけで、 起動は止めず画面も読みません。 代わりに、 Claude Code の私有の file に器が 1 key を書くこと (前の決定の線をこの 1 key に限って置き換える)、 席の起動が file の読み書きを 1 回持って起動の記録と起動の 1 行に項目が 1 つずつ増えること、 印の形は Claude Code 側の約束で変われば問いがまた出ること、 器は「信じる」にしか置かず戻すのは人の手であること、 書式が読み手の形に揃うこと、 同じ file を使う Claude Code と鍵を共有しないこと (印が消えた周は点検が名指して次の起動が置き直す) を引き受けます。 決め手は分析で、 user の決定の推奨を、 部品を足さず 1 key だけを 1 組にだけ書く形で満たす案でした。

+ 利点

  • 群の移動と init が起こす席で、 持ち主が dialog を承認する 1 手が消える (DR1)
  • crate を足さず、 読み手 (parse / Tree / render) に「置く」と「書き戻す」の 2 関数を足すだけ。 NFR3 は不変 (DR2)
  • key・並び・値・数の字面を保ち (書式は render の形)、 一時 file → 読み直し → rename で部分書きを作らない。 既に true の周は書かない (DR3)
  • 書くのは今起こす口座 × 今の anchor の 1 組だけで、 init と account add は書かない (DR4)
  • 言葉は閉じた列で起動の記録と起動の 1 行の末尾に載り、 印を置けない周も席は立つ。 描画は読まない (DR5)

− 欠点

  • Claude Code の私有形式の file に器が 1 key を書く (ADR-0026 §2.2 / §2.5 の trust の受け入れと代筆の射程外を、 この 1 key に限って supersede する・credential の fence は不変)
  • 席の起動が file の読みと書き (一時 file・rename) を 1 回持ち、 起動の記録の what の末尾と起動の 1 行の末尾に trust=<語> が 1 項目増える
  • 書式は読み手の render の形に揃う (key・並び・値は保つが、 元の file の空白や escape の書き方が render の形と違う周はそこが変わる)

04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 席を立てる口 (seat launch) は、 席の登録を書いた後・置き換えか差し込みかの分かれ目の前に 1 回だけ、 選んだ口座の設定 file (.claude.json) の該当の印 (projects の下のその anchor の hasTrustDialogAccepted) を「信じる」(true) に置きます。 書き方は、 同じ読み手で読み、 木の path に真偽を置き (途中の入れ物が無ければ作り、 隣の key と並びと値と数の書き方は変えず、 書式は読み手の形で、 末尾の改行は元に在れば保ち)、 同じ dir の一時 file に書き、 読み直して印が入っていることを確かめ、 置き換えます。 file が無ければ最小の file を作り、 すでに信じていれば 1 byte も書きません。 結果は 5 つの言葉 (置いた・作って置いた・すでに信じていた・読めなかった・書けなかった) のどれかで、 どの言葉でも起動行は送り、 言葉は起動の記録に残し (置き換えの周も差し込みの周も)、 差し込みの周はさらに結果の値と起動の 1 行の末尾に添えます。 群の移動はこの言葉を判定に使わず、 見回りの移動は記録に写すだけです。 同じ設定 file を使う Claude Code とは鍵 (lock) を共有せず、 印が消えた周は点検が名指して次の起動が置き直します。 依存は足さず、 書くのは今起こす 1 組だけで、 init と口座の登録 (account add) は書かず、 点検は読むだけ、 credential と settings は触らず、 画面の問いには答えません。 要件書では、 席の起動 (FR59) の内側にこの 1 手を足して判定と断りは変えず、 群の移動 (FR38) が人の手を待たない根拠になり、 依存 0 本 (NFR3) は変えません。

FR38rationaleFR38 は群の移動を「移り先を 1 回だけ決め、 群の今の口座の記録を書き、 古い席へ退避の合図を送って新しい口座で席を起こし直す」形で求める。 移り先の口座が anchor を trust していない周は、 起こした席が dialog で止まり、 移動が人の手を待つ (CTX2)。 本 ADR は起動の 1 本の内側で印を置くので、 移動の周に席を起こす経路を変えずに、 この 1 手が消える。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなること 4 つと、 代わりに引き受けること 6 つです。 良くなるのは、 群の移動と init が起こす席で持ち主が問いを承認する 1 手が消えること、 部品を足さず読み手に 2 つの関数を足すだけで依存 0 本が変わらないこと、 書くのは 1 key だけで他の key と並びと値は保ち途中で壊れた file を作らないこと、 結果が決まった言葉で起動の記録と起動の 1 行と見回りの記録に残り、 印を置けなくても席が立ち、 確認は点検の既存の行で足りることです。 引き受けるのは、 Claude Code の私有の file に器が 1 key を書くこと (前の決定の線をこの 1 key に限って置き換える)、 席の起動が file の読み書きを 1 回持ち、 起動の記録と起動の 1 行と見回りの記録に項目が 1 つずつ増えること、 印の key 名や置き場は Claude Code 側の約束で、 変われば問いがまた出ること、 器は「信じる」にしか置かず、 戻すのは人の手であること、 書式が読み手の形に揃うので Claude Code の書式と違えば空白や escape の書き方が変わること、 同じ file を使う Claude Code と鍵を共有せず印が消える周がありうること (点検が名指して次の起動が置き直す) です。

✓ 良い結果

  • ●群の移動と init が起こす席で、 持ち主が起動の trust dialog を承認する 1 手が消える。 移動の復帰は機械の注入だけで進む (ADR-0049 §2・ADR-0055 の形が閉じる)
  • ●crate を足さず、 既存の読み手に「置く」と「書き戻す」の 2 関数を足すだけ。 NFR3 (実行時の直接依存 0 本) は不変で、 同じ file を 2 つの読み手で読む形を作らない
  • ●書くのは 1 key だけで、 key・並び・値・数の字面を保ち (書式は render の 2 空白の形で、 Claude Code の書式と同じである限り byte で同じ)、 一時 file → 読み直し → rename で部分書きを作らない。 既に true の周は 1 byte も書かない。 credential と settings は触らない
  • ●結果は閉じた言葉 (written / created / accepted / unreadable / unwritable) で起動の記録の行と起動の 1 行の末尾と tick の記録の行に残り、 印を置けない周も席は立つ。 doctor の trust= の行が書いた後の周を accepted と読むので、 確認は既存の口で足りる

⚖ トレードオフ・代償

  • ●Claude Code の私有形式の file (.claude.json) に器が 1 key を書く。 ADR-0026 §2.2 / §2.5 の trust の受け入れと代筆の射程外を、 この 1 key に限って supersede する (.credentials.json と settings.json は ADR-0017 §2.3 の fence のまま)
  • ●席の起動が file の読み・一時 file の書き・rename を 1 回持ち、 起動の記録の what の末尾と起動の 1 行の末尾に trust=<語> が 1 項目ずつ増える (外形 snapshot が動く)。 tick の記録の行にも 1 項目増える
  • ●印の key 名と置き場は Claude Code の側の約束で、 変われば器は unreadable か written のまま dialog が出る。 その周は doctor の trust= と起動の行の語で分かるが、 器は直せない
  • ●器は印を true にしか置かず、 false に戻す口は持たない (撤回は人の手)。 trust は user が folder を信じる宣言だが、 器が起こす席については器が代わりに置く (書く相手は今起こす 1 組に閉じる)
  • ●書き戻しの書式は読み手の render の形 (2 空白の入れ子・末尾の改行は元に在れば保つ) に揃う。 key・並び・値・数の字面は保つが、 元の file の空白や escape の書き方が render と違う周はそこが変わる。 歯の fixture は実物の .claude.json の書式で作る
  • ●同じ設定 dir を使って走る Claude Code と lock を共有しない。 読み → 一時 file → rename の間に Claude Code が同じ file を書いた周はどちらかが負け、 印が消えた周は doctor の trust=missing が名指して次の起動が置き直す (器の書きは読んだ木 + 印 1 つで、 他の key を消す方向には負けない)
