設計判断記録 (ADR) scribe2 — 便用の並べ鍵

便用の並べ鍵は 7 日窓の reset の早い順 (7 日窓の reset を持たない口座は最後・5 時間窓とモデル別窓は鍵にしない・席用の順序は不変・ADR-0027 §2.2 の 1 つ目の鍵を supersede)

便に渡す口座の並べ鍵の 1 つ目を、 「数える窓の reset のうち最も早いもの」から「7 日窓の reset」に替える。 7 日窓の枠は reset までに使わなければ消えるので、 消える順に使う。 2 つ目以降の鍵 (走行中の便数 → label)・候補の判定・席用の順序は変えない。

この判断が約束すること (1 文サマリ)

便に渡す口座は、7 日窓の reset がいちばん近い口座から順に選びます。7 日窓の残りは reset が来ると消えるので、先に消える口座から使い切るためです。5 時間窓の reset は順序に使いません。席を起こすときの選び方 (余裕が最大の口座) は変わりません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、現物と user の裁定から説明します。いまの便用の順序は「どの窓でもよいので reset がいちばん近い口座」で、実際にはほとんどの周で 5 時間窓の reset の順に並びます。消えると惜しいのは 7 日窓の残りなので、user は 7 日窓の reset が近い口座から使い潰すと裁定しました。

CTX1

現物 — 1 つ目の鍵は数える窓の reset の最小で、 実質は 5 時間窓の reset の順

ADR-0027 §2.2 の便用の並べ鍵便に渡す口座を並べる比較の値の組の 1 つ目は、 口座の数える窓 (5 時間窓・7 日窓・便が使う model のモデル別 7 日窓) の最新の実測行が持つ reset 時刻のうち最も早いもの。 選定の純関数 (crates/scribe2/src/fleet/select.rs) は口座の読みの 1 欄にその最小を持ち、 候補の reset の欄へ写して並べ鍵の関数が読む。 5 時間窓が reset を持つ口座では、 7 日窓の reset が 5 時間窓の reset より手前に迫った周を除いて 5 時間窓の reset が最小になるので、 並びは実質 5 時間窓の reset の順になる。

CTX2

消えると惜しいのは 7 日窓の枠

窓の枠は reset までに使わなければ消える。 5 時間窓は 1 日に何度も開き直るので、 ある 5 時間窓の残りを逃しても次の窓がすぐ来る。 7 日窓口座単位の 7 日の使用枠は開き直りが週に 1 回で、 reset の時点で残っていた枠はその週のぶんが丸ごと消える。 5 時間窓の reset の順で並べると、 7 日窓の reset が近い口座に便が回らないまま reset を迎え、 口座全体で使える量が減りうる。 ADR-0027 の狙い (reset で消える残りから使う・憲法 C9.2) に照らすと、 鍵にする窓が狙いと合っていない。

CTX3

user の裁定 — 便用は 7 日窓の reset が近い口座から順に使い潰す

裁定 id = user 2026-09-17T06:10Z (論点 A・逐語は台帳 s2-07l.436) と同日 06:2xZ (逐語は台帳 s2-07l.439)。 逐語は台帳が原本で本 file には写さない (CON2)。 要旨: 便用は 7 日窓の reset が近い口座から順に使い潰す (7 日窓の枠は reset までに使わなければ消える = 消える順に使うのが口座全体の消費を最大にする)。 席用 (逼迫度の最小 = 余裕が最大) とは順序を明示的に分ける。

CTX4

現物の型 — 窓の種類は閉じた enum で、 7 日窓は型で名指せる

口座残量の窓の種類は fleet の閉じた enum (crates/scribe2/src/fleet/mod.rs の WindowKind・5 時間窓 / 7 日窓 / モデル別の 7 日窓の 3 値) で、 実測行は窓の種類と任意の reset 時刻を持つ (ADR-0017・ADR-0024)。 選定の純関数は既にこの enum でモデル別窓を弁別している。 7 日窓の実測行だけを拾うのに新しい型も新しい入力も要らず、 口座の読みが reset を導く 1 か所を「全部の窓の最小」から「7 日窓の行の reset」に替えれば足りる。

CTX5

席用と便用は選ぶ順序が別

選定の純関数は用途で順序が分かれる (ADR-0041 CTX5): session 用は逼迫度数える窓のうち最大の使用率が最小 (= 余裕が最大) の口座、 便用は並べ鍵の昇順の先頭。 当たっている口座 (窓の全量) と測れない口座と除外の口座はどちらの用途でも候補にならない。 本 ADR が替えるのは便用の並べ鍵の 1 つ目だけで、 用途の分岐・候補の判定・session 用の順序には触れない。

03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 4 つ並べます。7 日窓の reset の早い順に並べる案、いまの「どの窓でも最も早い reset」のままにする案、5 時間窓と 7 日窓を重み付きで合成する案、残量の多い順に並べる案です。

OPT1便用の 1 つ目の鍵を 7 日窓の reset の早い順にする (7 日窓の reset を持たない口座は最後)採用

口座単位の 7 日窓の古くない最新の実測行が持つ reset 時刻の昇順で並べ、 その reset を持たない口座は最後に回す。 2 つ目以降の鍵 (走行中の便数 → label) は ADR-0027 のまま。 5 時間窓とモデル別 7 日窓は鍵に使わず、 当たっている口座を候補から外す判定にだけ効く。

7 日窓の reset がいちばん近い口座から便に渡します。7 日窓の残りは reset で消えるので、先に消える口座を先に使い切る形です。5 時間窓が上限に当たった口座は今までどおり候補から外れるだけで、順序には関わりません。

+ 利点

  • 消えると惜しい 7 日窓の枠を、 消える順に使える (口座全体の消費が増える)
  • 鍵が 1 窓 1 値で、 なぜその口座かを 1 文で説明できる
  • 窓の種類は既存の閉じた enum で弁別でき、 型・入力・rules 行を足さない
  • 席用の順序・候補の判定・待つ reset の導き方に触れない

− 欠点

  • 5 時間窓の残りが reset で消えるぶんは順序で拾わなくなる
  • 7 日窓の reset が同じ口座どうしは便数 → label の鍵に落ちる
  • 7 日窓の reset が近い口座に便が寄り、 その口座の 5 時間窓が上限に当たる回が増えうる (別口座での途中再開が受ける)
  • 並びを pin している既存の歯の期待値を書き換える
OPT2現状のまま (数える窓の reset のうち最も早いもの)不採用

ADR-0027 §2.2 の鍵 (1) を変えない。

いまの形です。変更は要りませんが、実際にはほとんどいつも 5 時間窓の reset の順に並ぶので、7 日窓の reset が近い口座の残りが使われないまま消えることがあります。

+ 利点

  • 器の変更が無く、 既存の歯もそのまま
  • 5 時間窓の残りを reset の前に拾いやすい

− 欠点

  • 並びが実質 5 時間窓の reset の順になり、 7 日窓の枠が消える順と合わない (user の裁定と食い違う)
  • 5 時間窓は開き直りが多く、 その残りを優先しても口座全体の消費はほとんど増えない
OPT35 時間窓と 7 日窓の reset を重み付きで合成した値で並べる不採用

2 つの窓の reset までの近さに重みを掛けて 1 つの得点にし、 得点の順で並べる。

両方の窓を少しずつ考慮する案です。どちらの残りも拾えそうに見えますが、重みという新しい値を誰かが決めて持ち続ける必要があり、「なぜこの口座が選ばれたか」を一言で説明できなくなります。

+ 利点

  • 5 時間窓の残りも順序に少し反映できる

− 欠点

  • 重みという値の線が増える (rules 行と裁定が要る・憲法 C1 / C5)
  • 得点は時刻でも使用率でもない合成値で、 選ばれた理由を説明できず、 歯で pin する期待値も重みに依存する
OPT4残量の多い順に並べる不採用

7 日窓の使用率が低い (残りが多い) 口座から便に渡す。

たくさん残っている口座から使う案です。上限に当たりにくくはなりますが、reset が遠い口座の残りは急いで使わなくても消えません。先に消える枠を先に使う、という目的に合いません。

+ 利点

  • 便が上限に当たりにくい口座へ回る

− 欠点

  • reset が近い口座の残りが後回しになり、 消える枠を先に使う目的に合わない
  • 席用の順序 (余裕が最大) と同じ向きになり、 席が使う口座と便が使う口座が同じ口座に集まる
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、それが要件書のどの要件を支えるかを示します。便用の並べ鍵の 1 つ目を 7 日窓の reset の早い順に替え、それ以外の鍵と候補の判定と席用の順序はそのままにします。

採用 — OPT1

便用の規則 SHALL 候補を次の 3 つの鍵で辞書順に並べ、 先頭を選ぶ: (1) その口座の 7 日窓 (口座単位の 7 日窓・モデル別の 7 日窓ではない) の古くない最新の実測行が持つ reset 時刻 (昇順)、 (2) その口座で走行中の便の数 (昇順・ADR-0027 §2.3)、 (3) label の辞書順。 (1) の reset 時刻を持たない口座 (7 日窓が消費の無い窓で reset 未定・ADR-0024 §2.1、 または 7 日窓の実測行が reset を過ぎて古く数えられない周) SHALL 候補からは外さず、 reset 時刻を持つ口座の後ろに並べる。 5 時間窓とモデル別 7 日窓の reset 時刻 SHALL NOT 便用の並べ鍵に使う: それらの窓は逼迫度と「当たっている」の判定にだけ効き、 当たっている口座は従来どおり候補から外れる。 窓の種類 SHALL 既存の閉じた enum (WindowKind) で弁別し、 新しい型・新しい入力・新しい rules 行を足さない。 候補の判定 (除外・測れない・当たっている)、 候補なしの周に運ぶ最も早い reset (当たっている窓の開き直る時刻から導く・待ちに渡す値)、 session 用の規則 (prefer → 逼迫度の最小 → label・R-C9-1)、 純関数の形 (入力と出力) は変えない。 便用と session 用の順序は用途の分岐で分かれたままとし、 session 用は 7 日窓の reset を読まない。 本 ADR は ADR-0027 §2.2 の鍵 (1)「口座の窓の reset 時刻のうち最も早い時刻」だけを supersede する。

便に渡す口座は、7 日窓の reset が近い順に並べて先頭を選びます。reset が同じなら走行中の便が少ない口座、それも同じなら名前順です。7 日窓をまだ使っていない口座は、消えるものが無いので最後に回します (候補からは外しません)。5 時間窓やモデル別の窓は順序に使わず、上限に当たった口座を候補から外す判定にだけ使います。席を起こすときの選び方は今までどおり余裕が最大の口座です。 7 日窓の残りは reset が来ると消え、次に開き直るのは 1 週間後です。5 時間窓は 1 日に何度も開き直るので、その残りを優先しても口座全体で使える量はほとんど増えません。だから消える順に使うなら、見るべき窓は 7 日窓です。重みで合成する案は新しい値を持ち込み説明もできなくなるので採らず、残量の多い順は目的に合わないので採りません。窓の種類は既に型で区別できるので、変えるのは選定の中で reset を読む 1 か所だけです。

05 結果 / 良い面とトレードオフ

この判断で何が良くなり、 何を引き受けるか

この判断で良くなることと、代わりに引き受けることです。7 日窓の枠を消える順に使え、鍵が 1 つの値で説明でき、型も入力も増えず、席用の選び方は変わりません。一方で 5 時間窓の残りは順序で拾わなくなり、reset が同じ口座どうしは便数と名前順で決まり、便が寄った口座は 5 時間窓の上限に当たりやすくなり、既存の歯の期待値を書き換えます。

✓ 良い結果

  • ●7 日窓の枠を reset で消える順に使い、 口座全体で使える量が増える
  • ●並べ鍵の 1 つ目が 1 窓 1 値になり、 選ばれた理由を 1 文で説明できる
  • ●既存の閉じた enum で窓を弁別するので、 型・入力の形・rules 行・event の形が増えない (変わるのは選定の純関数の中の reset の読み 1 か所)
  • ●席用の順序と候補の判定は変わらず、 席用と便用の順序が別であることが鍵の窓でもはっきりする

⚖ トレードオフ・代償

  • ●5 時間窓の残りが reset で消えるぶんは順序で拾わなくなる (5 時間窓は開き直りが多く、 失う量は小さい側)
  • ●7 日窓の reset が同じ口座どうしは走行中の便数 → label で決まる
  • ●7 日窓の reset が近い口座に便が寄り、 その口座の 5 時間窓が上限に当たる回が増えうる (上限停止と別口座での途中再開が受ける・SRS FR35 / FR37)
  • ●並びを pin している既存の歯 (選定の in-file の歯と性質の歯・CLI の e2e の歯) の期待値と fixture を書き換える
06 改訂関係と原則 / この判断の位置づけ

版の系譜と、 行き着く原則 (照会終端)

本 ADR は現行。 ADR-0027 を部分 supersede する: §2.2 の鍵 (1)「口座の窓 (5 時間窓・7 日窓・用途が使う model のモデル別 7 日窓) の最新の実測行が持つ reset 時刻のうち最も早い時刻」を「7 日窓の実測行が持つ reset 時刻」に置き換える。 同じ §2.2 の鍵 (2) (走行中の便数)・鍵 (3) (label)・「逼迫度は便用の順序に使わない」・「同じ周に 2 便を続けて選ぶと同じ口座が選ばれうる」、 §2.1 (候補は口座の状態だけで決め便数で絞らない)、 §2.3 (便数の出所)、 §2.4 (不変のもの) は現行のまま。 ADR-0041 の決定と CTX5 が便用の順序を指す句「reset の早い順に使い切る (ADR-0027)」は、 本 ADR の後は「7 日窓の reset の早い順」と読む (ADR-0041 の決定そのものは変えない)。 ADR-0020 §2.2 の純関数の形、 ADR-0024 §2.2 の reset 無しの実測行の読み (古くない実測として数える・待つ reset の導出に入れない)、 R-C9-1 は現行のまま。 SRS FR36 の句は窓を名指していないので改訂を要しない。

照会終端 — PRIN-SPEND-WHAT-EXPIRES-FIRST

reset で消える枠は、 消える順に使う。 順序の鍵は現物の型で名指せる 1 つの値にし、 合成した値では並べない。

07 用語集 / この文書で使う専門語

本文に出てくる専門語のやさしい説明

本文に出てくる専門語を、やさしい言葉で説明します。

便用の並べ鍵run ordering key
便に渡す口座を並べる比較の値の組。 7 日窓の reset 時刻 (早い順・持たない口座は最後)、 走行中の便数 (少ない順)、 label (辞書順) の 3 つで、 辞書順に比べて先頭を選ぶ。
7 日窓seven-day window
口座単位の 7 日の使用枠。 reset が来ると使用率が 0 に戻り、 それまでに使わなかった枠は消える。 モデル別の 7 日窓 (特定の model だけを数える枠) とは別の窓。
5 時間窓five-hour window
