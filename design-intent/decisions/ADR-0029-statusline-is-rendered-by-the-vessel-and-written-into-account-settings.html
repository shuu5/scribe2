§1. Context

管理 tick は、 席の画面に出ている 1 行 (statusline) を読んで「context がどれだけ埋まっているか」を知ります。 ところがその 1 行を描く script は器の外 (前の版の repo) にあり、 それを各口座の設定に配る手順もまた別の repo が持っています。 器の計測の入力の形を、 器でない 2 つの repo が決めている状態です。 user ごと・machine ごとに表示を変えられると、 計測は黙って「測れない」に落ちます。

記録時点 (2026-09-15) の現物 (main 1206210): 管理 tick の context 計測 (seat/meter.rs used_from_pane_pct) は transcript が名指されない周に pane の statusline を読み、 候補行の形は parse_statusline が定める (<pct>% <used>[kM]?/<window>[kM]・後ろは行末か空白・v1 の statusline と同じ規則)。 候補が無い周は pane-no-statusline で context=unmeasured となり、 退避も /clear も起きない (FR25 の「0% に化けない」極性)。 描画側は前の版の scripts/statusline-command.py (~/.claude/statusline-command.py の symlink 先) で、 各口座の settings.json の statusLine.command (7 口座すべて同じ python の行) は ubuntu-note-system の配備 script が書く。 器の口座の口 (account/mod.rs SETTINGS_BODY) は agent view を切る 1 項目しか書かない。 導入先の project scope の .claude/settings.json にも statusLine が在り、 Claude Code の設定の優先順位では口座の設定より前に来る。

憲法の向き: C2.2 は器の名 (NAME) から派生する識別子を 1 定数に集め、 env を読まない。 C3.3 は描画を判定の入力にしない (本 ADR は描画の形を器が持つことで、 描画を読む計測の入力を器の中に閉じる・判定の入力は typed のまま)。 C10 は測れない値を成功に倒さない。 N3 は host 固有の値で分岐しない。 C12.5 / C12.7 は外形を snapshot し、 場合を property で量産する。

§2. Decision

§2.1 描画は器の subcommand 1 つで、 stdin の payload だけから 1 行を組む

画面の 1 行は器自身が描きます。 Claude Code が渡してくる JSON を標準入力から読み、 それだけから 1 行を組んで返します。 file も環境変数も読まず、 他の command も起こしません。 値が取れないときはその部分を描かず、 「0%」のような嘘の値は出しません。

器 SHALL subcommand <NAME> seat statusline を 1 つ持ち、 stdin の Claude Code の statusline payload (JSON) を読み、 stdout へ 1 行を書く。 描画 SHALL pure な関数 1 本 (payload → 行) で、 file・env・子 process・network を読まない (C2.2・NFR5 の「重い I/O を持たない」と同じ極性)。 payload に無い・形が違う値の segment SHALL 描かない (空文字も 0% も - も出さない・C10)。 payload が JSON でない周 SHALL 空行を書いて rc 0 で終わる (statusline の失敗で claude を止めない・空行は計測の「候補なし」に落ちる = 偽の値を作らない)。 色 (ANSI escape) SHALL 付けない (1 形・snapshot・計測は tmux の capture-pane の素の本文を読む)。 JSON の読みは器が持つ std だけの reader (ADR-0017 §2.2 の Tree) を使い、 依存を足さない (C13)。

§2.2 行の形は計測の読み手の逆像で、 往復を property で pin する

描く形と読む形は同じ 1 つの規則です。 器が描いた行を器の計測が読むと、 描いたときの値がそのまま戻ります。 この往復を、 たくさんの値で自動生成した検査が守ります。 行の先頭は「使用率% 使用量/窓」で、 その後ろにモデル名と口座の窓の使用率が続きます。

行 SHALL 先頭の segment を context (<pct>% <used>[kM]/<window>[kM]・pct は整数 (切り捨て)・used / window は k (×1000) か M (×1000000) で丸めた整数・payload の context_window.used_percentage / current_usage の和 / context_window_size から組む) とし、 続く segment を model (display_name・末尾の「(… context)」を落とした語)・effort ([<effort>])・口座の窓 (5h:<pct>% / 7d:<pct>%・rate_limits の used_percentage) の順に空白 2 つで繋ぐ。 segment の順序 SHALL 閉じた enum の宣言順 (C2)。 描き手 SHALL 読み手 parse_statusline の逆像で、 「描いた行を読むと (pct, used の丸め, window の丸め) が戻る」往復を property test で pin する (C12.7)。 行の外形 SHALL snapshot で pin する (C12.5)。 読み手 (parse_statusline) SHALL NOT 変えない (前の版の行もそのまま読める・移行の間に両方が混在してよい)。

§2.3 口座の口が settings の statusLine を器の行に書き、 doctor が口座ごと・導入先ごとに名指す

口座を器で作ると、 その口座の設定に「画面の 1 行はこの器の command で描く」と書き込まれます。 前の版の script も、 別 repo の配備手順も要りません。 すでに在る口座については doctor が「器の行か・別の物か・無いか」を口座ごとに 1 語で示し、 器の口で書き換えられます。 導入先の project の設定が口座の設定を上書きしていないかも doctor が名指します。

口座の口 account add (ADR-0026 §2.2) SHALL settings.json に statusLine を 1 項目書く: {"type": "command", "command": "<NAME> seat statusline"}。 command の語 SHALL NAME 定数から導き (C2.2)、 binary の path は書かない (PATH が解く・ADR-0011 と同じ)。 refreshInterval SHALL 書かない (Claude Code の既定に従う・器の rules 行にしない = 数値を持たない)。 器 SHALL 既存の口座 dir の設定を書き換える口を 1 つ持ち (account statusline <label>)、 その書きは statusLine の key 1 つの置換で他の key を保ち、 読めない設定 (JSON でない・object でない) は断って上書きしない (C11)。 doctor の口座行と account ls (同じ 1 関数) SHALL 語 statusline=<vessel|other|absent|unreadable> を持つ (vessel = command が器の行と一致・other = 在るが違う・absent = key が無い・unreadable = file が無い / 読めない / 形が違う・absent に潰さない)。 doctor の導入先の行 (ADR-0028 §2.3) SHALL 同じ語で導入先の project scope の .claude/settings.json の statusLine を名指す (vessel 以外は口座の設定を上書きしている印)。 判定はしない (C10.2)。

§2.4 器が管理する口座では表示の形を器が固定する (machine が違っても同じ)

器が作った口座では、 画面の 1 行の形は器が決めた 1 つだけです。 user が machine ごと・口座ごとに別の描き方を設定することは想定しません (設定されていれば doctor がそれを名指します)。 これは user の裁定で、 計測の入力を 1 つに保つための固定です。

器が起こす席 (seat launch / 立て直し / 役割なしの起動) の口座 dir では、 statusline の形 SHALL §2.2 の 1 形とし、 器 SHALL NOT 口座ごと・host ごとの表示の変種を manifest にも code にも持たない (N3・C1.2 の「規範文は生成」と同じ向きで、 表示の規則は code の enum に 1 つ)。 statusline=other の口座・導入先は doctor が名指すだけで、 器は黙って上書きしない (書き換えは §2.3 の口を撃つ手番)。 前の版の script SHALL 残してよい (器が指す先が変わるだけ・退役は前の版の repo の手番)。

§2.5 射程外

この記録が決めるのは、 描く口・行の形・設定への書き込み・doctor の語・形の固定の 5 つだけです。 画面の 1 行に載る口座の残量を器の記録へ写すこと、 git の branch や PR の状態を描くこと、 導入先の project の設定を器が書き換えること、 前の版の script を消すことは決めません。

次は本 ADR の決定ではない (MUST NOT be read as such): payload の rate_limits を口座残量の実測 (AllowanceMeasured・ADR-0017 §2.1) として event log へ写す形 (計測の出所が 2 つになる・ADR-0017 §2.2 の curl の経路との整合は別の ADR)・git の branch / dirty / PR の segment (子 process と file の読みを要する・NFR5 の極性に反する)・導入先の project scope の .claude/settings.json を器が書く形 (他の repo の tracked file・ADR-0028 §5 (C) と同型)・前の版の script と配備 script の撤去 (前の版の repo と ubuntu-note-system の手番・consumer 通知で伝える)・refreshInterval を rules 行に持つ形 (§5 (D))。

§3. SRS との関係 (正本は SRS)

この記録が仕える要件は要件書 (SRS v0.11) に在ります。 要件の文面はここには置かず、 当該行を指すだけにします。 「context 使用量を出所付きで返し、 取れない周は取れないと言う」「context の閾値で退避の合図を注入する」を、 計測の入力の字面を器の中に閉じることで安定させます。 計測の入力を器が自足する旨の要件 1 本は、 要件書の改訂 (user の手番) で足します。

本 ADR の §2.1〜§2.2 が仕える要件は SRS v0.11 が正本である: FR25 context 使用量の計測 (出所付きで 1 件・取れない周は rc ≠ 0・0% に化けない) と FR29 退避の合図 (context 使用量が rules 行の上限以上の周に注入) と FR38 (口座の窓の閾値・同じ tick の判定)。 §2.3 は FR59 (席の起動・口座 dir の前提) と FR61 導入先の同期 (doctor の導入先の行) に語を足す。 §2.1 の「重い I/O を持たない」は NFR5 と同じ極性。 計測の入力の自足 (statusline の字面の正本が器の中に 1 つ在ること) を名指す FR は記録時点の SRS に無く、 要件書の改訂 (/folio-architect・user の手番) で 1 本足す。 それまで契約は FR25 / FR29 を指す。 要件書は本 ADR では 1 字も変えない。

§4. Consequences

良い面は、 計測の入力の形を器の中の 1 つの規則が決め、 描き手と読み手の往復が自動検査で守られること、 口座を作れば画面の 1 行が自動で揃い、 別 repo の配備手順が要らないこと、 machine が違っても同じ形で測れることです。 悪い面は、 前の版の 1 行に在った git や PR の情報が器の行には無いこと、 既存の口座と導入先の project の設定を 1 回ずつ書き換える手番が要ることです。

Positive: 計測の入力の字面が code の 1 か所 (描き手 = 読み手の逆像・C2)。 往復の property と外形の snapshot (C12.5 / C12.7)。 口座の口 1 つで設定が揃う (ADR-0026 §2.2 の延長・散文の配備手順が消える・N2)。 host 固有の値も分岐も無い (N3・C10.2)。 依存を足さない (C13)。 rules 行を足さない (C5 非該当)。

Negative (受け入れるコスト): 器の行は前の版の行より情報が少ない (git・PR・時間の残り・色を持たない・§2.5)。 既存の 7 口座の設定と導入先の project scope の設定は doctor が other で名指し、 書き換えは §2.3 の口と導入先の手番 (1 回)。 Claude Code の settings の優先順位 (project > user) は器の外の挙動で、 project scope の上書きは名指すだけで止められない。 statusline の payload の形は Claude Code の版で変わりうる (読めない周は空行・計測は pane-no-statusline に落ちて嘘を作らない)。

§5. Alternatives Considered

5 つの案を退けました。 「前の版の script と別 repo の配備のまま」は計測の入力を器の外が決める今の状態です。 「計測を画面でなく記録 file から読む」は hook の無い席で入力が無くなります。 「導入先の project の設定に書く」は repo ごとに複製が散ります。 「更新間隔を器の規則にする」は器の規則でない数を manifest に持ち込みます。 「前の版の script を器の repo に写す」は Rust でない歯と script を器に持ち込みます。

(A) 現状維持 (前の版の statusline-command.py + ubuntu-note-system の配備が statusLine を書く)。 却下: 計測の入力の形を器の外の 2 repo が決める (読み手だけ器に在る)。 user ごと・machine ごとの変種が計測を unmeasured に落とす。 §2.1〜§2.3 で器の中に閉じる。

(B) 計測を pane でなく transcript だけから読む (seat meter --transcript の経路を tick の既定にする)。 却下: tick は transcript の path を hook の打刻からしか知らず、 hook の無い席 (cwd が repo 外で立った席・前の版の wrapper で立った席) では入力が無い。 pane の経路は hook に依らない唯一の経路で、 その入力の形を器が持つのが本 ADR。 transcript の経路は残す (出所は入力で決まる 1 本道・seat-autonomy §3)。

(C) 導入先の project scope の .claude/settings.json に statusLine を書く。 却下: 導入先ごとに複製が散り、 他の repo の tracked file を器が書く (ADR-0028 §5 (C) と同型)。 口座 dir は器の管理下 (state dir 配下) で 1 か所。 project scope は doctor が名指すだけ (§2.3)。

(D) refreshInterval を rules 行に持つ (前の版の 10 秒を写す)。 却下: 器の規則でない数 (Claude Code の描画の間隔) を manifest に持ち込む (C1 の manifest は器の規則の値のため・C5 の裁定 id も要る)。 Claude Code の既定 (会話の更新ごと) で計測には足りる (context は会話の更新でしか動かない)。

(E) 前の版の python script を器の repo に写して配る。 却下: Rust でない実行物と歯を器に持ち込む (C12・C11 の lint の外)。 git / PR の segment は子 process と file の読みを要し NFR5 の極性に反する。 描画は pure な関数 1 本で足りる (§2.1)。
