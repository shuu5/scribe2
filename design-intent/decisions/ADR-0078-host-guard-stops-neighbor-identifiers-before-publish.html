設計判断記録 (ADR) scribe2 — 公開の走査

公開の直前に隣の private repo の識別子を止める — host-guard に 6 つ目の種類 publish を足し、 出ていく字面を同じ host の隣の private repo の閉じた 4 形の識別子で走査し、 可視性と remote の先端 は GitHub と git 自身に問う (ADR-0056 の閉じた 5 種類を部分 supersede)

公開の repo へ出る commit と本文に、 同じ host の private repo の内部の識別子が混じっても、 今は散文の手順と手の grep しか止めるものが無く、 CI は出た後に回る。 本 ADR は、 host-guard に公開の種類を足して撃つ前に走査する形と、 走査のための GitHub への問い合わせを外へ出してよい範囲とする解釈を決める。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「見張り (host-guard)」は危ない操作を実行の直前に止める器の口、 「隣の private repo」は同じ machine の宣言に並ぶ非公開の repo です。 公開の repo へ出る commit や本文に、 隣の private repo の名や id が混じることがあります。 今それを止めるのは手順の文章と手の検索だけで、 公開の repo の検査 (CI) は出た後にしか回りません。 この記録は、 見張りの区分を 5 つに閉じた ADR-0056 の一部を置き換えて 6 つ目の区分「公開」を足し、 外へ出す命令を撃つ前に、 出ていく文字を隣の private repo の 4 つの形の識別子で調べて止める形を決めます。 調べるために GitHub へ repo の名と相手の最新の問いを送ることを、 外へ出してよい範囲とする解釈も決めます。 要件書の FR80 (公開の字面の走査) を置き、 FR11 (main への着地)・FR50 (着地の終端)・NFR5 (見張りの時間) を改めます。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを、 危険 (公開の repo へ出る追加行が隣の repo の識別子を持ちうる)・今の守り (手順の文章と手の検索だけ)・機序 (出る経路は git と gh を通り、 公開か非公開かは GitHub だけが知る)・憲法と既存の決定の向き・この判断の範囲の 5 つから説明します。 動かすのは見張りの区分 1 つと、 器の着地の手順からの呼び出しと、 要件の改訂だけで、 既存の 5 つの区分と見張りの呼び出しの設定は変えません。

CTX1

危険 — 公開の repo へ出る追加行が隣の private repo群に並ぶ非公開の repo の識別子を持ちうる

同じ host に private repo と公開の repo が並び、 同じ session が両方の事実に触れるので、 公開の repo へ出る追加行が private repo の内部の事実 (repo の名など) を持ちうる。 push は取り消せない。 出た後の除去は本 ADR の外。

CTX2

今の守り — 散文の手順と手の grep だけ

公開の前に相手の可視性を測り差分を grep する手順と、 草稿の依頼文に毎回書く「隣の repo の事実を書かない」の 1 行は、 どちらも器の外の散文。 器の門 (契約表の検査・path の門・CI) はどれも隣の repo の識別子を測らず、 CI は push の後に回る。

CTX3

機序 — 出る経路は Bash の git と gh を通り、 可視性は GitHub だけが知る

公開の repo へ出る経路は、 手の push・gh の本文 (PR・issue・release・gist・api)・器の着地の push (FR50) で、 どれも Bash の git と gh を通る。 host-guard戻せない操作を止める見張り (ADR-0056) は口座の設定を読む全 session の Bash の直前に呼ばれ、 置き場は --state-dir で、 host の面 (host.toml) が同じ host の repo の anchors を持つ。 repo が公開か非公開かは GitHub だけが知っていて、 手元の宣言は切り替えの後に古びる。

CTX4

憲法と既存の決定の向き (本 ADR の解釈)

N2 (散文にしか無い規則を規則として扱わない) から、 手の grep の手順は器の門に変える。 A1 (出す) は外への送信に持ち主の承認を求める。 走査のために GitHub へ送るのは 公開先の repo出す先の repo と群の anchor (実体が在り公開先の repo と別のもの) の owner/name と remote の先端 の問いで、 相手は既にそれを持つので新しい情報を出さない。 持ち主の裁定は 3 本 — 2026-09-27T17:39Z (器の仕組みで止める)・2026-09-27T22:21Z (GitHub への問いを A1 の許せる範囲とする・一般語の repo の名も除かない・着地の push も走査する)・2026-09-27T23:55Z (repo の名は区切った成分で照合し、 無害と裁定した字句の除外の一覧だけを除く)。 ADR-0056 は host-guard の種類を閉じた 5 つにし、 名前・event・flag・出力の形を跨版で足すだけとした。 vessel-hook の設計が anchor-guard を host-guard の 6 つ目にしなかった理由は「repo の置き場と印を解く材料を持たない」で、 公開の種類は repo の器の置き場を要らず --state-dir の host の面と git と gh だけで閉じるので、 その理由は当たらない。 C17.2 から、 手の走査の手順のうち識別子の 4 形隣を指す 4 つの形を見る部分は門が着地したら消す (依頼文の 1 行は、 門が測らない散文の事実の手当てとして残す)。

CTX5

射程 — 動かすのは種類 1 つと着地の手順からの呼び出しと要件の改訂だけ

動かすのは (1) host-guard の種類の閉じた enum の末尾に publish を足し、 rules 行 host_guard.publish を置くこと、 (2) 器の着地の手順が main に載せる前と push の前に同じ判定を呼ぶこと、 (3) 要件 FR80 と AC50 を置き、 FR11 (main に載せる前の同じ走査)・FR50 (着地の push の前の同じ走査)・NFR5 (公開の segment外へ出す命令 の周の締め切り 6 秒) と AC23 を改めること。 同じ要件の改訂で FR50 に列の先端の CI による close も足すが、 それは本 ADR の決定ではない (持ち主の裁定 2026-09-27T22:21Z)。 動かさないのは、 既存の 5 種類の判定・配線の hook 行 (matcher と timeout 10 秒)・出力の形・binary の不在の fail-open。 散文の事実 (件数・規則の名・関数の名)・Claude の外の push・sh -c の中の push・git と gh の alias・runner の session は測らない (限界)。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 出る前に止めること (公開の push は取り消せない)。 規則を文章に置かず、 どの session でも同じ判定にすること。 確かめられない値は止める側へ倒すこと。 足すものを最小にすること (既に在る見張りの口と呼び出しを使い、 依存を足さない)。 公開でない命令のときの見張りの時間を増やさないこと。

DR1出る前に止める — 公開の push は取り消せない CTX1・CTX2
DR2規則を散文に置かない — どの session でも同じ判定 (N2) CTX2・CTX4
DR3偽の通過を作らない — 読めない値は止める側へ倒す (NFR4) CTX3
DR4足すものを最小にする — 既に在る host-guard の口と配線を使い、 依存を足さない (C17・NFR3) CTX3・CTX4
DR5公開でない周の hook の予算を増やさない (NFR5) CTX3
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 5 つ並べます。 見張りの 6 つ目の区分にする案 (選んだ案)、 公開の repo の検査 (CI) で調べる案、 clone ごとに git の push 前の hook を置く案、 machine の宣言に公開か非公開かを書く案、 公開か非公開かを周期で測って置いておく案です。 選ばなかった 4 つは、 出た後に回る・gh の本文を通らず clone ごとに置く必要がある・宣言が古びる・測った値が古びる、 がそれぞれの決め手です。

OPT1host-guard の 6 つ目の種類 publish採用

公開の segment (git の push・gh の本文を出す動詞) だけを同定し、 出ていく字面外へ出る文字を同じ host の隣の private repo の閉じた 4 形の識別子で走査し、 当たれば実行の前に断る。 行き先と remote の先端と公開先の repo は git と gh 自身に解かせ、 可視性は GitHub に問う。 読めない可視性は公開先の repo なら public・隣なら private と読む。 repo の全履歴を走査なしに出す command は GitHub に問わずに断る。 決め手は持ち主の裁定 (2026-09-27T17:39Z・2026-09-27T22:21Z・2026-09-27T23:55Z)。

見張りに 6 つ目の区分「公開」を足す案です。 見張りは外へ出す命令 (git の push と、 PR や issue などの本文を出す gh の命令・repo を作る・編集する命令) だけを見分け、 それ以外の命令では git も gh も撃ちません。 行き先と相手の最新と出ていく commit は git 自身に、 gh の相手は gh 自身に解かせ、 公開か非公開かは GitHub に問います。 確かめられないときは、 相手なら公開、 群の repo なら非公開と読んで止める側へ倒します。 出ていく文字に隣の private repo の 4 つの形の識別子が 1 つでもあれば止め、 repo を公開に切り替える・公開の repo を作る命令は問い合わせずに止めます。 撃つ前に止まり、 口座の設定を読む session に同じ判定が掛かり、 依存を足さない点で勝ります。 代わりに、 公開の命令では最大 6 秒待ち、 一般的な単語の名でも止まり、 文章の中の事実・別名 (alias)・sh -c の中・Claude の外・実装役 (runner) の session の push は調べません。 隣の repo が無い machine でも repo を公開に切り替える命令や解けない形は止まり、 GitHub へ名と相手の最新の問いを送り、 着地の push の前に当たると着地が止まります。 決め手は持ち主の裁定です。

+ 利点

  • 撃つ前に止まり、 出た後に気づく形にならない (DR1)
  • 口座の設定を読むどの session の Bash にも同じ判定が掛かる (DR2)
  • 読めない可視性・字面・締め切り越えは止める側へ倒す (DR3)
  • 既に在る口・配線・rules 行の形を使い、 依存を足さない (DR4)
  • 公開の segment でない周は git と gh を 0 回撃つ (DR5)

− 欠点

  • 公開の周は GitHub へ問い合わせ、 最大で締め切りの 6 秒まで待つ (NFR5 の改訂が要る)
  • 一般語の repo の名も止めるので、 偽陽性の周は言い換えて出し直すか、 無害な字句を裁定で除外の一覧に足す手間が出る
  • 散文の事実・alias・sh -c の中・Claude の外・runner の session の push は測らない
  • 隣を持たない host でも、 全履歴を出す command と解けない形は断られ、 持ち主が手で行うか書き直す
  • 公開の周ごとに GitHub へ名と remote の先端の問いを送り、 着地の push の前に当たると着地が止まる
OPT2CI の門で走査する不採用

push の後に CI が出た commit を走査する。 決め手は分析 (出た後に回る)。

公開の repo の検査 (CI) が、 出た commit を後から調べる案です。 見張りの時間を使わず、 どの経路で出た commit も同じ場で見られる点で勝ります。 けれども、 公開の repo では検査が回るときには既に出ていて、 止められません。

+ 利点

  • hook の予算を使わない (DR5)
  • どの経路で出た commit も同じ場で見る (DR2)

− 欠点

  • 公開の repo では CI が回る時には既に出ていて、 止められない (DR1)
OPT3git の pre-push hook を clone ごとに置く不採用

各 clone の git hook が push の前に走査する。 決め手は分析 (gh の本文を通らず、 clone ごとに置く必要がある)。

clone ごとに、 git の push の前に動く hook を置いて調べる案です。 Claude の外の terminal の push も止められ、 clone の中の git push なら別名 (alias)・sh -c の中・実装役 (runner) の session・器の着地の push にも掛かる点で勝ります。 けれども、 clone ごとに置く必要があり、 他の project の hook と衝突し、 --no-verify で外れ、 gh の本文 (PR・issue・release) を通りません。

+ 利点

  • Claude の外の terminal の git push も止める (DR1)
  • clone の中の git push なら alias・sh -c の中・runner の session・器の着地の push にも掛かる (DR2)

− 欠点

  • clone ごとの配置で、 他 project の hook と衝突し、 --no-verify で外れる (DR2)
  • gh の本文 (PR・issue・release) を通らない (DR1)
OPT4host の面に公開 / 非公開を宣言する不採用

host.toml に repo ごとの可視性を書き、 hook はそれを読む。 決め手は分析 (宣言が古びる)。

machine の宣言 (host.toml) に repo ごとの公開か非公開かを書き、 見張りはそれを読む案です。 GitHub へ問わないので外へ出す範囲の解釈が要らず、 速い点で勝ります。 けれども、 公開に切り替えた後に宣言が古び、 非公開と書いたまま公開にした repo へは調べずに通ってしまいます。

+ 利点

  • GitHub へ問わないので、 A1 の解釈が要らない
  • 公開の周も GitHub へ問わず待ちが短い

− 欠点

  • 可視性を切り替えた後に宣言が古び、 private と書いたまま public にした repo へは走査なしに通る (DR3)
OPT5可視性を周期で測って置き場に置く不採用

管理 tick か doctor が可視性を測って置き場に書き、 hook はそれを読むだけにする。 決め手は分析 (測った値が古びる)。

定期の見回りや健康診断が公開か非公開かを測って置いておき、 見張りはそれを読むだけにする案です。 見張りが問い合わせずに速く、 宣言より古びにくい点で勝ります。 けれども、 測ったときと push のあいだに公開へ切り替えると古い値で通り、 測る側と読む側の 2 本に分かれて足すものが増えます。

+ 利点

  • 公開の周も GitHub へ問わず待ちが短い
  • 宣言でなく実測なので、 OPT4 より古びにくい

− 欠点

  • 測った周と push の間に可視性を切り替えると、 古い値で通る (DR3)
  • 測る側と読む側の 2 本に分かれ、 足すものが増える (DR4)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 判定の順は、 規則の行 (無ければ止め、 off なら調べない) → repo の全履歴を公開する命令 (問い合わせずに止める) → 命令の解読 (解けなければ止める) → 公開か非公開かの確認 (相手が非公開なら、 または隣が 0 なら通す) → 出ていく文字の検査です。 行き先・相手の最新・出ていく commit は git 自身に、 gh の相手は gh 自身に解かせます。 出ていく文字に、 隣の private repo の識別子 (repo の名・隣にあって相手の最新から辿れない commit などの id (7 桁以上に縮めた形も含む)・/ を含み隣にあって相手の最新に無い file の path・台帳の id) が 1 つでもあれば止め、 言い換えて出し直す道を示します。 支える要件は FR80 (公開の字面の走査) で、 FR11 (main に載せる前にも同じ走査)・FR50 (着地の push にも同じ走査)・NFR5 (公開の命令のときだけ 6 秒で締め切る) の改訂も主張します。

採用 — OPT1

器 SHALL host-guard の種類の閉じた enum の末尾に 6 つ目の種類 publish を足し、 rules 行 host_guard.publish (値は識別子の形の記号の閉じた列と、 無害と裁定した字句の除外の一覧〔字句の sha256 の digest の列で、 字句そのものは書かない〕) を置く。 publish の種類は Bash の公開の segment (git の push と、 gh の公開の動詞〔本文を出す動詞と repo の作成・編集〕) だけを同定し、 それ以外の segment では git と gh を撃たない。 判定の順は次のとおり。 (1) rules 行が無い周は fail-closed で断り (経路は裁定を添えて行を置く)、 enabled が false の周は publish の種類を撃たずに通す。 (2) repo の全履歴を走査なしに出す command (器の閉じた形の一覧〔可視性を public へ変える gh repo edit と gh api の書き・public の repo を作る gh repo create〕) は、 公開先の可視性と隣の数に依らず GitHub に問わずに断り、 経路は持ち主が行う。 (3) 行き先 (pushurl と insteadOf を当てた後の、 git が実際に押す URL)・remote の先端・出ていく commit は git 自身に (同じ語の列の dry-run と ls-remote で)、 gh の公開先の repo は gh 自身に解かせ、 解けない周 (同定できない形・変数の ref・--mirror・標準入力の本文・可視性の欄を解けない repo の編集の gh api・読めない字面) は隣が 0 の host でも断る。 (4) 公開先の repo と群の anchor (実体が在り公開先と別のもの) の owner/name を、 git が実際に押す URL か gh が解いた repo の、 host が gh の既定の host である URL の path の末尾 2 成分として同じ規則で導き (導けない repo の可視性は読めない可視性)、 可視性を GitHub に 1 本の問いで問い、 読めない可視性は公開先なら public・anchor なら private と読む。 群に公開先の外の anchor が無い host は問わない。 隣の private repo は、 その anchor のうち public と実測できないもの。 公開先が private と実測できた周と、 隣が 0 の周は通す。 (5) 出ていく字面 (commit の message・author と committer の名・patch の追加行と path・押す annotated tag の本文・押す ref の名・gh の本文の flag の値と本文の file) を隣の識別子の閉じた 4 形 (repo の名は字面と名をともに ASCII の英数字と _ の外の字で区切った成分の並びで大文字と小文字を区別せずに照合し、 一般語の名も除かず、 除外の一覧に digest
