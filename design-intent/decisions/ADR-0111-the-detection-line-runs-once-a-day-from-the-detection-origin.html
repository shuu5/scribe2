設計判断記録 (ADR) scribe2 — 日次の検出

日次の検出 — land の終端は着地後の検出の口を rules 行 detection.daily_min_s の下限 (1 日) を空けて起こし、 口は検出の起点 (前に測った main の sha) から着地した sha までの差分をまとめて撃ち、 下限の内の便は deferred を記す (ADR-0060 の着地ごとに起こす句・base を親とする句・どの便も自分の record を持つ読みを部分 supersede)

ADR-0060 は変異検査 (検出線) を gate の外へ出し、 便が着地するたびに器が切り離して 1 回撃つと決めた。 2026-09-25〜10-03 の実測では host の記憶装置への書き込みが 1 日約 4.9 TB で、 検出線は 7 日で 167 本・変異 8,065 個を撃ち、 便ごとに着地した版を一時 dir でゼロから組み立てていた。 本 ADR は持ち主の裁定 (裁定 id s2-07l.736.34:20261003T0149Z-1) に沿い、 着地の後に口を起こす 1 か所はそのままに、 起こす回数を rules 行の下限で 1 日 1 回に間引き、 起こした回は前に測った main の位置 (検出の起点) から今の着地までの差分をまとめて測ると決める。 間引いた便と測れなかった差分は「測った」と別の語で残り、 次の日次の検出に含まれる。 gate と着地の判定は変えない。

この判断が約束すること (1 文サマリ)

この記録で「器」は scribe2 の本体、 「便」は契約 1 本を実装して main へ入れる 1 回の走り、 「検出線 (変異検査)」は code をわざと書き換えて歯 (test) が気づくかを数え、 落ちても止めない検査です。 今は便が main に着地するたびに、 器が着地した版を一時の場所でゼロから組み立てて変異検査を撃っており、 7 日で 167 本・書き換え 8,065 個になりました。 同じ 7 日の host の記憶装置への書き込みは 1 日約 4.9 TB です。 この記録は持ち主の裁定に沿い、 着地の後に変異検査を起こす仕組みはそのままに、 起こすのを 1 日 1 回に間引くと決めます。 起こした回は、 前に測った main の位置 (検出の起点) から今の着地までの差分をまとめて測るので、 間引いた回の差分も取りこぼしません。 間引いた回と測れなかった回は「測った」と別の語で残します。 着地の前の検査 (gate) と着地の判定は変えません。

01 背景 / なぜこの判断が要るか

いま何が問題か (確定方式を決める力学)

なぜこの判断が要るのかを 5 つで示します。 持ち主の裁定、 host の書き込みと変異検査の本数・数・秒の実測、 着地のたびに変異検査を起こす今の仕組み、 GitHub の週 1 回の変異検査が落ち続けていること、 憲法の向きとこの記録が動かす範囲です。

CTX1

裁定 — 検出線止めずに記録する線を着地ごとから 1 日 1 回にまとめてよい

持ち主は 2026-10-03T01:49Z に、 台帳の問い s2-07l.736.34 へ、 検出線 (vessel 宣言の detection-verify の行 = xtask mutants-diff の変異検査) を着地ごとから 1 日 1 回にまとめてよいと答えた (裁定 id持ち主の決定を指す印 s2-07l.736.34:20261003T0149Z-1)。 逐語は台帳にだけ在り、 本 file には写さない。 裁定は頻度を決め、 まとめ方 (どこから起こし、 何を base にし、 どの歯を当てるか) は設計に委ねた。

CTX2

実測 — host の書き込みは 1 日約 4.9 TB、 検出線は 7 日で 167 本・変異 8,065 個で、 便ごとに冷えた buildゼロからの組み立て を払う

2026-09-25〜10-03 の実測で、 host の NVMe の書き込みは 1 日約 4.9 TB だった (device の累計と user.slice の io.stat が一致)。 同じ 7 日に着地後の検出着地の後の変異検査は 167 本撃たれ、 変異は計 8,065 個で、 便 1 本の検出は変異 10〜108 個・81〜586 秒だった (run dir の検出の周の秒の file)。 便ごとに、 着地した commit の一時 dir の worktree で baseline を 1 回組み、 cargo-mutants が job ごとに写した木 4 本でも組むので、 target を共有しない冷えた build を着地のたびに払う (ADR-0060 の CSQ-N7 が未測のまま引き受けた費用)。 書き込みのうち検出線が占める分は、 本 ADR の時点で分けて示していない。

CTX3

現物 — land の finish が着地のたびに口を起こし、 base は着地した commit の親で、 どの便も自分の記録を持つ

ADR-0060 と設計 gate-cost §44 の形で、 land の finish は Landed の event を書いた後、 凍結した宣言に検出線の行が在る便だけ、 口 pipe land --detection-only を子 process として切り離して起こし、 detection:spawned (起こせない周は detection:unspawned) を記す。 口は着地した commit を一時 dir の worktree に出し、 {base} を親、 {teeth} を便の契約の写しの filter 語とし、 的と純移動中身を変えない移動の付け足しを足して、 受付札・封じ込めの箱・器の健康の遮断器を通して撃つ。 面の外の周は撃たずに skip を残し、 撃った周も撃たなかった周も便自身の run dir の verify-main.jsonl に landed 付きの record を 1 本以上書き、 写しの置き場検査の出力の置き場に判定行の写しか理由の file を置く。 pipe show --run は写しから行を出す。

CTX4

GitHub の週次の変異検査は落ち続け、 変異の記録は実質 local の検出線だけ

GitHub の週次の workflow mutants.yml は 2026-09-14 が failure・09-21 が cancelled・09-28 が failure で、 workspace 全体の変異検査は job の上限 6 時間に収まらない実績を持つ。 今、 変異の生存歯が見逃した書き換えの記録を持つのは実質 local の検出線だけである。 rules 行裁定つきの規則の行 R-C12-1 (変異の生存の線) の値は週次記録で、 極性は deny でない。

CTX5

憲法の向きと本 ADR の射程

C12.4 は変異の生存を検出線 (R-C12-1) として記録することを求めるが、 撃つ時点を定めていない。 まとめて撃つ周も起点から着地までの差分の全部を測るので、 着地した変更を測りから外さない。 C10 は宣言値・実測値・導出値を型で分けるので、 撃たずに後回しにした便 (deferred) と測れなかった差分を、 測った (measured) と別の語で残す。 C5 は rules 行を裁定 id なしに足すことを断るので、 下限は裁定 id つきの rules 行 1 本に置く。 本 ADR は ADR を書く条件のうち 1 (C12.4 と C10 の読み)・3 (検出の起点前に測った位置の記録の on-disk の形と record の任意 field)・4 (却下案を残す価値のある分岐) に当たる。

02 判断を縛る力 / 評価の軸

選択肢を測るものさし (安全・速さ)

この判断を評価する 5 本のものさしです。 host の資源 (書き込みと組み立て) を減らすこと。 着地した変更を測りから落とさず、 測っていないものを測ったと数えないこと。 gate と着地の判定と既存の囲いを変えないこと。 新しい口・常駐の process・timer を増やさないこと。 結果を外の公開の面へ出さないことです。

DR1host の資源 — 着地のたびの冷えた build と、 同じ行への重複した変異を減らす (NFR6) CTX1・CTX2
DR2記録の欠けを作らない — 着地した変更は必ずどこかの測りに含まれ、 測っていないものを測ったと数えない (C12.4・C10) CTX4・CTX5
DR3判定を動かさない — gate の判定・着地の rc・受付札と箱と遮断器を変えない (ADR-0060 の残り) CTX3
DR4増やさない — 新しい口・常駐の process・timer・置き場を足さず、 今の起こし方を使い回す (C2) CTX3
DR5外へ出さない — 変異の結果を host の外の公開の面に出さない (A1 の「出す」) CTX4
03 検討した選択肢 / 3 つの確定方式

それぞれの利点と欠点を並べる

候補を 6 つ並べます。 着地の後の起こし方はそのままに回数を 1 日 1 回に間引き、 前に測った位置から差分をまとめて測る案 (選んだ案) と、 選ばなかった 5 つです。 選ばなかった案は、 席ごとの定期の見張り (管理 tick) から撃つ案・GitHub の定期の CI へ移す案・変異検査専用の timer を足す案・着地ごとのまま一時の場所を memory に置く案・変異検査をやめる案です。

OPT1着地の終端の起こし方はそのまま、 起こす回数を rules 行の下限で 1 日 1 回に間引き、 検出の起点から差分をまとめて撃つ採用

land の finish が口を起こす 1 か所を変えず、 起点の file の fired から rules 行 detection.daily_min_s の秒が過ぎた周だけ起こし、 内の周は deferred を記す。 起こした口は起点の measured から着地した sha までを base..着地として撃ち、 歯の名はその間に着地した便の和を取る。 決め手は既存の起こし方・受付札・箱を使い回せることと、 起点が動かない限り差分を取りこぼさないこと (CTX3・CTX5)。

着地の後に器が変異検査を起こす 1 か所はそのまま使い、 起こすのを規則の行の下限で 1 日 1 回に間引きます。 下限の内に着地した便は起こさず「後回し」と記し、 起こした回は前に測った main の位置から今の着地までの差分をまとめて、 その間に着地した便の歯の名を合わせて測ります。 着地のたびのゼロからの組み立てが 1 日 1 回になり、 同じ日に何本もの便が触れた同じ行の書き換えを 1 回だけ撃ち、 起こし方・並列の枠・囲い・gate を変えず、 測っていない差分は位置が動かないので次の回に含まれ、 結果は host の中に残る点で勝ります。 代わりに、 結果が便ごとの見逃しを名指さないこと、 分かるまで最大 24 時間と次の着地までの遅れがあり着地の無い日は撃たないこと、 2 本以上の便をまとめた回は撃つ場所の付け足しが効かないこと、 書き換え 1 つごとの組み直しは差分の量だけ残ること、 器の作業記録の置き場に file が 1 つ増えて版の違いをまたぐ形を持つことを引き受けます。

+ 利点

  • 着地のたびの冷えた build が 1 日 1 本になる (7 日で 167 本の実測から) (DR1)
  • 同じ日に何本もの便が触れた同じ行の変異を 1 回だけ撃ち、 重複した変異が消える (DR1)
  • 起こし方・受付札・箱・遮断器・gate を変えず、 新しい口・process・timer・置き場の種類を足さない (DR3・DR4)
  • 測っていない差分は起点が動かないので次の日次の検出1 日 1 回の変異検査に含まれ、 deferred と測れなかった周は measured と別の語で残る (DR2)
  • 結果は host の中の record と写しに残り、 外へ出さない (DR5)

− 欠点

  • 判定行が便ごとの変異の生存を名指さない (含めた便の id の列までしか辿れない) (DR2)
  • 測るまで最大 24 時間と次の着地までの遅れがあり、 着地の無い日は撃たない
  • 2 本以上の便をまとめた周は、 的の付け足し (契約が名指した生存行に変異を当てる) と純移動の付け足し (移しただけの行を変異から外す) が効かない
  • 変異 1 つごとの組み直しは差分の量に比例して残り、 書き込みの減りは冷えた build の分が主になる (DR1)
  • state dir に on-disk の file (検出の起点) が 1 つ増え、 跨版の形を持つ
OPT2管理 tick から撃つ不採用

席ごとの管理 tick (systemd の user の timer の周) が、 下限を過ぎた周に検出線の行を撃つ。 決め手は timer の env と、 便に結ばない撃ちが要る口と置き場 (CTX3)。

席ごとの定期の見張り (管理 tick) の回に、 下限を過ぎていれば変異検査を撃つ案です。 着地の無い日も 1 日 1 回撃てて遅れが着地に依らず、 定期の契機が既に在る点で勝ります。 けれども、 見張りを動かす systemd の timer の環境には cargo の場所が無く、 そのままでは変異検査を撃てません。 便に結ばない撃ちなので、 新しい口と記録の置き場も要ります。

+ 利点

  • 着地の無い日も 1 日 1 回撃て、 遅れの上限が着地に依らない
  • 周期の契機 (管理 tick) が既に在る

− 欠点

  • systemd の timer の PATH に cargo が無く、 そのままでは検出線の行を撃てない (DR4)
  • 便に結ばない撃ちなので、 新しい口と record の置き場が要る (DR4)
OPT3GitHub の scheduled CI へ移す不採用

変異検査を GitHub の定期の workflow に移し、 host では撃たない。 決め手は歯の名の出所・公開の面・job の時間の上限 (CTX4)。

変異検査を GitHub の定期の CI へ移し、 host では撃たない案です。 host の書き込みと CPU の負荷が 0 になり、 着地に依らず定期に撃てる点で勝ります。 けれども、 契約が名指す歯の名は CI から読めず、 測る歯を絞れません。 結果が公開の job の要約に出て外へ出すものが増え、 workspace 全体の変異検査は job の上限 6 時間に収まらない実績で、 今の週 1 回の CI も落ち続けています。

+ 利点

  • host の書き込みと CPU の負荷が 0 になる
  • 着地に依らず定期に撃てる

− 欠点

  • 契約の歯の名 (契約の写しの filter 語) が CI から読めず、 {teeth} を埋められない (DR2)
  • 結果が PUBLIC の job summary に出て、 外へ出すものが増える (DR5)
  • workspace 全体の変異検査は job の 6 時間に収まらない実績で、 週次の mutants.yml も落ち続けている (DR2)
OPT4検出線専用の timer unit を足す不採用

管理 tick と別に、 1 日 1 回だけ検出線を撃つ systemd の timer unit を置き場ごとに足す。 決め手は unit の数と口の数 (CTX3)。

管理 tick と別に、 1 日 1 回だけ変異検査を撃つ専用の systemd の timer を置き場ごとに足す案です。 着地に依らず 1 日 1 回撃て、 見張りの回と独立に止めたり動かしたりできる点で勝ります。 けれども、 置き場ごとに 2 本目の timer が要り (timer は席ごとに 1 組と決めた ADR-0030 に反し、 前の設計でも同じ理由で退けた形です)、 便に結ばない撃ちなので管理 tick の案と同じく新しい口と記録の置き場も要ります。

+ 利点

  • 着地に依らず 1 日 1 回撃てる
  • 管理 tick の周と独立に止めたり動かしたりできる

− 欠点

  • 置き場ごとに 2 本目の unit が要る (ADR-0030 は席ごとに 1 組で、 設計 case-lifecycle §19 が書き直し専用の unit を同じ理由で退けた) (DR4)
  • 便に結ばない撃ちなので、 OPT2 と同じく新しい口と record の置き場が要る (DR4)
OPT5着地ごとのまま、 一時の木を RAM に置く不採用

器の頻度は変えず、 一時の worktree と cargo-mutants の写しの置き場を memory の上の file system に置いて記憶装置への書き込みを避ける。 決め手は裁定への答えと、 器の側で閉じられるか (CTX1)。

器の回数は変えず、 着地ごとの一時の木と変異検査の写しの置き場を memory の上に置いて、 記憶装置への書き込みを避ける案です。 器の変更が無く、 便ごとの測りと撃つ場所の付け足しがそのまま残り、 記憶装置への書き込みが減る点で勝ります。 けれども、 「1 日 1 回にまとめてよい」という頻度の裁定に答えず、 ゼロからの組み立ての CPU と時間は着地ごとに残ります。 host の設定なので、 器の宣言と歯で閉じられません。

+ 利点

  • 器の変更が無く、 便ごとの測りと的と純移動の付け足しがそのまま残る
  • 記憶装置への書き込みが減る

− 欠点

  • 頻度の裁定 (1 日 1 回にまとめてよい) に答えず、 冷えた build の CPU と秒は着地ごとに残る (DR1)
  • host の設定で、 器の宣言と歯で閉じられない (DR4)
OPT6検出線を廃止する不採用

detection-verify の行を外し、 変異検査を撃たない。 決め手は C12.4 (CTX5)。

変異検査の行を外し、 撃たない案です。 変異検査の書き込みと CPU の負荷が 0 になり、 着地の後の口と記録の形が器から消える点で勝ります。 けれども、 憲法 C12.4 (歯が見逃した書き換えを止めない線として記録する) に反し、 週 1 回の CI も落ち続けているので、 変異の記録が無くなります。

+ 利点

  • 検出線の書き込みと CPU の負荷が 0 になる
  • 着地後の検出の口・record・写しの形が器から消える

− 欠点

  • C12.4 (変異の生存を検出線として記録する) に反する (DR2)
  • 週次の CI も落ち続けており、 変異の記録が無くなる (DR2)
04 採用した判断 / どの方式を選ぶか

選んだ方式と、 それが守る要件 (cross-doc 照会)

選んだ案と、 それが要件書のどの要件を支えるかを示します。 着地の後に器が変異検査を起こす 1 か所はそのままで、 前に起こした時刻から規則の行の下限 (86,400 秒 = 24 時間) が過ぎた回だけ起こし、 下限の内の回は起こさずに「後回し (deferred)」と記します。 起こした回は、 検出の起点に記した前に測った main の位置から今の着地までの差分を、 その間に着地した便の歯の名を合わせて測ります。 測れた回と変異検査の対象に触れない回は起点を今の着地へ進め、 測れなかった回は進めないので、 その差分は次の回に含まれます。 支える要件は 3 つで、 どれも今の約束をそのまま保つ側です。

採用 — OPT1
