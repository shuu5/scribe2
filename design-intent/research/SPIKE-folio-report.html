(iv) 採否の推奨（結論を先に）

推奨 = 採用（条件付き）。 design-intent/ を v2 リポの spec 層にする。

folio-architect は 1 session で憲法（21 条・EARS 50 規範文・dual-audience）・ADR-0001（却下案つき）・vocabulary（64 語）を出せ、機械 gate（folio validate）は violation 0 で、link 整合・EARS 形式・dual-audience 構造・可読性 floor を機械が守る。plain markdown 1 本（CONSTITUTION.md）の代替案は不採用: 3 段と機構併記は書けても、id 整合・双方向 link・EARS pattern・章要旨の機械検査を失い、N2「散文だけの規則を残さない」を doc 層で支える手段が無くなる。

採用の条件（3 つ。いずれも folio 側または運用側の knob）:

  1. Phase F の軸数を絞れること。今回の token 超過の主因は review agent 5 本の並列（1 本 130k〜180k）。review_model は config で変えられるが、軸数は SKILL に固定されている。常用するなら「軸を選ぶ knob」を folio に要求するか、憲法級の編集だけ 5 軸・通常編集は ears + fidelity の 2 軸、と運用で絞る。
  2. vocabulary gate の fail-open を folio 側で修正すること（後述 (ii)-1）。修正までは forbidden 語の目視 grep を併用する。
  3. consumer 語彙の glossary / tooltip が無いことを受容するか、folio 側に derive を要求すること（後述 (ii)-2）。

(ii) folio が定義できなかった項目

  1. vocabulary gate が非決定的に fail-open（folio 側 bug）。bin/folio の printf '%s' "$prose" | grep -qF "$syn" が pipefail 下で SIGPIPE（rc 141）になり violation を捨てる。scratch で forbidden 語 3 件を注入して 3 回走らせ、2 回は先頭寄りの 2 件を見逃し、1 回だけ 3 件検出（timing 依存）。[OK] vocabulary を P-5 の裏取りに使えない。fix 案 = grep -qF "$syn" <<< "$prose" 等の非 pipe 形。
  2. consumer 語彙だけでは glossary.html が生成されず tooltip も付かない。folio build / fix / validate の glossary 系は domain: folio-closed の語しか扱わないのに、chrome の cluster-nav は vocabulary.yaml があれば無条件に ../glossary.html を出す。結果、README 3 本に link-rot の WARN が恒常化する（非 block）。domain を偽らずそのまま残した。rules §9.5「flip しない consumer では vocabulary.yaml から derive する」の記述と emitter 実装が食い違う。
  3. 数値の正本。憲法は「数値は条文に置かず rules 行へ」と定めるが、folio に rules 行に当たる概念は無い。憲法 §3 の <table>（行 id 付き・裁定列 = 論点番号）を manifest 実装までの写しとして置き、条文からは行 id の link で参照する形で代替した。
  4. 順位（論点 1）の id。条ではない tie-break に id を与える枠組みが folio に無く、§1 に id 無しの EARS block として置いた。
  5. 実装言語の規範。「実装言語 = Rust」は憲法に条が無く ADR-0001 §2.1 の MUST だけが持つ（条文化は版 N+1・N4）。SSoT review の指摘どおり §5 Trace に正本の所在を明記して固定した。
  6. §4 と v0.3 の矛盾（tokio 固定 vs C13「core は async を持たない」）は ADR §2.2 で「拘束条件は v0.3」と裁定を記録して解決した。SPEC §4 側の文言修正は未実施。
  7. toolchain 選定の WHY（nextest / proptest / insta / cargo-mutants / hyperfine / thiserror / cargo deny の採否理由）は WHY 側に無く、review は ADR-0002 の起票を提案した。新 ADR は user 承認必須のため未着手。
  8. §7（plugin 共存）と overview.html は起動指示の範囲外のため未作成。契約 (c) の tier / marker 不在はこの範囲差に由来する。
  9. CLI 周辺の小事: canonical path の symlink が実行口座に無い（repo を canonical path へ symlink すると解決見込み・未実施）。folio init --help が --help を dir 名と誤認する。
