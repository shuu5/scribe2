§1. 問い（何を調べたか）

Jev は「文章を返す」のではなく「型のある判定と、較正された確率を返す」ことを売りにする API です。scribe2 の pipeline で今 LLM（lens）か字面の規則で決めている判定のうち 3 つに当てて、正解との一致・確率が当てになるか・同じ入力での揺れ・速さと単価を測りました。

問いは 3 つで、いずれも scribe2 の現物から採った素材（契約の acceptance・lens の evidence・便の結末）に、この spike が正解を付けたもの。(q1) 契約の acceptance が「pointer だけ」か「本文を持つ」か（2 値）。(q2) lens の指摘 1 件が「契約適合 / 歯の非空虚性 / 憲法 / その他」のどれかと、その重さ（0 形式の逸脱 / 1 検査の穴 / 2 挙動の欠陥）。(q3) 便の結末を「着地 / 差し戻し / 人へ上げる」の 3 値で決める（state に lens の verdict の語は入れない）。比較の基準線は、q1 は設計 contract-source.md の lint (iii) の正規表現 1 本、q3 は lens の判定語（PASS → 着地・FAIL → 差し戻し）の規則 1 行。

§2. 調査対象の実体（Jev・記録時点）

Jev は 1 回の request に複数の問いを載せられ、問いの型は 3 つ（0〜1 の数 / 選択肢と確率分布 / 段階の加重値）です。確率とは別に confidence という統計量を返し、式は非公開です。入力 100 万 token あたり $0.042 で出力は無料、docs は英語が主で CJK は同等の精度ではないと明記しています。

§3. 実測（正解との一致・確率の較正・揺れ・速さと単価）

正解つき 87 件（q1 30・q2 27・q3 30）を、日本語の問いと英語の問いの両方で 3 回ずつ撃ちました（261 回・約 $0.014）。q1 は 30/30 で正規表現と同点、q2 は 22/27、q3 は 26/30 で lens の判定語の規則（28/30）を下回りました。確率 0.9 以上の判定は 422 件すべて的中し、誤りは全部 0.9 未満に集まります。同じ入力での揺れは確率 0.5 付近だけで、失敗は 444 回で 0、1 回の中央値は 527ms です。

§3.1 追補（2026-09-19）: 「CI が赤いとき flaky か回帰か」を shadow で測った

dispatcher の判断のうち「CI が赤いとき、flaky か回帰か」を、本番相当の材料（この repo の CI の失敗 52 件・失敗した job の log の末尾 255 行）で、Jev に判断を記録するだけの形で流しました。Jev は 52 件中 46 件を「回帰」と答え、flaky 9 件のうち拾えたのは 4 件、確率 0.9 以上の帯でも 11 件中 4 件を外しました（再走で緑になった flaky 3 件を 0.94〜0.99 で回帰と誤答）。前日の「0.9 以上は外れ 0」はこの問いでは成り立ちません。この判断は Jev に任せず、再走の A/B（code が決める）のままにします。

項目実測（2026-09-19・版 jev-1.13.0 に pin・応答の model 欄で確認）

読み方: (a) log の末尾だけでは「変更に起因するか」が見えない。flaky と回帰を分ける材料は log の外（同じ sha の再走・変更の内容）にあり、それは docs (d) の「code で計算できること」の側である。(b) 正解は機械の規則で付けたので、「直した」の中に回帰でない例（main が赤い期間に切った docs 便が次の push で緑になった等）が混ざる。ただし 0.9 以上の誤答 4 件のうち 3 件は再走で緑になった flaky の側なので、正解の粗さでは説明できない。(c) 前日の較正（0.9 以上で外れ 0）は問いに依存する＝閾値は問いごとに自分のデータで測る（公式 docs「自分のデータで確信度と正答率をプロットせよ」と一致）。(d) 問いの文は 1 版で調整していない（criteria に境界例を書き足す余地は未測定）。

§4. scribe2 との突合（どこに挿せるか・今は挿さない理由）

記録時点の推奨は「保留」です。3 問のどれも、Jev を足す理由が実測から出ませんでした。q1 は正規表現で足り、q3 は既存の規則が上回り、q2 は比べる基準線となる記録が scribe2 に無いからです。挿せる場所があるとすれば「lens の指摘 1 件ごとの重さの仕分け」と「dispatcher が人へ上げるかの判断」で、どちらも今は無い記録か無い口です。

挿し口の候補記録時点の scribe2Jev が足すもの今は挿さない理由
受付の分類（契約の形）設計 contract-source.md の lint (iii)（正規表現）。台帳 517 件の acceptance は pointer + 本文 140 / 散文のみ 227 / 空 150 で pointer だけの契約は 0 件（spike の計数）無し（同点）docs (d)「code で計算できることを model に聞くな」と決定はしごの段 2（既に在る）で止まる
lens の指摘の種別と重さlens の出力は verdict + evidence 1 行 + 観点の件数だけで、指摘 1 件ごとの文と重さの record は無い（q2 の重さは spike の定義）指摘ごとの重さの確率（0.9 以上なら外れ 0）仕分けの対象となる record が無い。lens が finding 単位の record を持つ設計（C17.2: 足す前に消すものを名指す）が先
dispatcher の 3 値（着地 / 差し戻し / 人へ上げる）lens の verdict の語からの規則 1 行（ADR-0045 の dispatcher は未着地）「契約の側を直すべき便」を確率つきで人へ上げる（境界例 2 件のうち 1 件は 3/3・もう 1 件は揺れる）規則 1 行が 28/30 で上回る。dispatcher の escalate の判断に確率が要ると分かってから（C10: まず測る）
CI が赤いときの flaky / 回帰の仕分け（dispatcher・ADR-0045）再走で緑なら flaky（planner の手で A/B）。同じ sha の再走は code で撃てる無し（§3.1: 0.9 以上で 7/11・flaky 4/9）実測で不採用。分ける材料（再走・変更の内容）は log の外にあり、code で決まる（docs (d)）
憲法の面——採るなら外部依存の追加（A3・C13）と課金（A1「使う」）の承認 event、版 ID の pin（rules 行・裁定 id）、外へ出す state の scrub（host 名・口座名・path・user の逐語）が要る。lens の evidence を state に入れるなら docs (c) の注入の弱さが効く

§5. 再検討の条件と未解決の問い

Jev を再検討するのは、lens が指摘 1 件ごとの記録を持つようになって重さの仕分けが必要になった時か、dispatcher の「人へ上げる」判断に確率が要ると分かった時です。その時は、版 ID の pin・閾値（問いごとに自分のデータで測る）・外へ出す素材の scrub・日本語の state のままでよいかを決めてから使います。当てない問いが 2 つ決まりました: CI の flaky / 回帰の仕分け（§3.1・code で決まる）と、runner の QUESTION の宛先（state が自由文そのもので、行動が不可逆側）。

  • 再検討の引き金: (1) lens の findings が閉じた型の record（1 件 1 行・種別つき）になり、重さの仕分けが人の手番を作るとき。(2) dispatcher（ADR-0045）の escalate の判断で、規則 1 行が取りこぼす「契約の側を直すべき便」が実測で積み上がるとき。(3) 停滞した便を人へ上げるかの判断で、段数と経過は code が数えて数値で渡し、Jev には「人の介入を要するか」の noul 1 本だけを聞く形が要るとき。
  • 挿す形の作法（公式 pattern Confidence-Gated Routing / Intent Routing / Speculative Fan-Out / Composite Scoring と第三者の実装〔CI の仕分け・段階式 review・tool 呼び出しの門〕の調査 2026-09-19・report は tracked ではない）: state には機械が持つ事実を名前付き field で入れ、LLM の自由文を裸で入れない（入れるなら 1 field に閉じ、「判定者への指示を含むか」の noul を併せて聞く）。choice の選択肢は境界の閉じた enum に一致させ、床を割ったときの既定は「人へ上げる」。Jev の答えは書き込みを起こさない。まず shadow（判断を記録するだけ）で確信度と実際の結果を対で貯め、床を測ってから切り替える。
  • 閾値: 実測の境は問いごとに違う（q1〜q3 は 0.9 以上で外れ 0・flaky / 回帰の問いは 0.9 以上で 4/11 外れ）。deny の門に使うなら閾値は rules 行（裁定 id・C5）で、検出線として置くなら C12.4 の型。
  • 版: alias は予告なく動くので rules 行に版 ID を pin する（記録時点 jev-1.13.0）。版が動いたら samples 87 件で再測定（費用 約 $0.014 / 周）。
  • 未測定: 並列の負荷・長い state（数万 token）・429 の挙動・請求額の照合・state を英訳した場合との差・criteria に境界例を書き足した場合の上がり幅・2 人目の正解付け。
  • 散文の面: docs (c) のとおり state 内の文が判定を動かしうる。lens の evidence（LLM の出力）を state に入れる設計は、注入に無防備な口を pipeline に足すことになる＝挿すなら state は機械が作った field に限る。
