01 ゴール / 絶対に避けたい 3 つの事故

「これが起きたら失敗」を先に決める

まず「これが起きたら失敗」を 3 つ先に決めます。人を待たせる・壊れたまま進む・記憶に頼る、の 3 つです。避けたい結果を共有してから要件を読むと、各要件が何を守るためのものか分かりやすくなります。

GOAL 1

人を待たせない

人の手番は 3 クラス人に聞く操作の承認と台帳の問い台帳に立てる問いへの裁定だけ。 それ以外の段で pipeline が人の入力を待って止まらない。

GOAL 2

壊れたまま進まない

検証が落ちた便・PASS を名乗れない便は記帳して止まり、 黙って landmain への着地 しない。

GOAL 3

記憶に頼らない

現在地は永続面（event log追記だけの記録）から読め、 process が死んでも中断点から再開できる。

FR3恒常常時各段は fleet便と席の状態の全体 の event log を replay して現在地を読み、 段の終わりに event を 1 件追記する（process の記憶に状態を持たない）各段は自分の記憶ではなく、追記だけの記録（event log）を最初から読み直して現在地を知り、終わるときに記録を 1 行足します。process の中に状態を抱えません。記憶に頼らない、というニーズ（N-3）から来ています。process の中に状態を持つと、その process が死んだ瞬間に現在地が消えるからです。必須 T
FR4きっかけ便が Intake 段にあり spawn が要求されたときbase を記録し、 worktree を切り、 write-set の allowlist を書いて runner を headless で起動する便が「受け付け済み」の段にあって起動を頼まれたら、出発点（base）を記録し、作業用の worktree を切り、触ってよい file の列を書き出してから、実装役（runner）を画面なしで起動します。人の手が入らなくても安全に進む、というニーズ（N-1）から来ています。出発点と触ってよい範囲を先に記録しておけば、実装役を無人で走らせても後から検証できます。必須 T
FR5恒常常時runner と lens は claude -p（headless・stdin に契約 / diff・stdout に構造化 1 行・permission を毎回明示・口座は環境変数で切替）の 1 形で呼ぶ実装役（runner）も審査役（lens）も、同じ 1 つの形で呼びます。画面なしの claude -p に、契約や diff を入力で渡し、答えは構造化した 1 行で受け取り、許可の設定は毎回明示し、口座は環境変数で切り替えます。自律安全のニーズ（N-1）から来ています。画面のある席を建てると宛先解決や見張りの仕組みが要りますが、画面なしの 1 形なら process の起動と終了だけで完結します。必須 T
FR6きっかけrunner が終了したときrc 0 かつ base からの commit変更の 1 区切りの記録 が 1 件以上なら Implemented、 それ以外は Failed と記帳する実装役が終わったとき、正常終了（rc 0）で、出発点から commit が 1 件以上あれば「実装済み」、そうでなければ「失敗」と記録します。記憶に頼らない、というニーズ（N-3）から来ています。「終わった」と言葉で申告させず、rc と commit の数という機械の事実で判定します。必須 T
FR7恒常常時変更した .rs ごとに、 test 差分だけを base に当てて新規・変更 test が 1 本以上 RED になり、 かつ HEAD では GREEN であることを機械で確かめ、 docs-only文書だけの変更 でない変更に test 差分が無ければ拒む変更した Rust の file ごとに、test の差分だけを出発点（base）に当てて「先に落ちる」こと、そして変更後（HEAD）では通ることを機械で確かめます。文書だけの変更（docs-only）を除き、test の差分が無い変更は受け付けません。契約は小さく、検証は base で落ちる test で表す、というニーズ（N-4）から来ています。先に落ちない test は何も守っていないので、入口で機械が確かめます。必須 T
FR8きっかけgate機械検証と審査の段 が要求されたとき契約の verify 各行を worktree で実走して行ごとの rc を記録し、 1 本でも rc が 0 でなければ FAIL とする審査（gate）を頼まれたら、契約に書いた検証コマンドを 1 行ずつ作業用 worktree で実際に走らせ、行ごとの結果を記録します。1 本でも失敗すれば FAIL です。自律安全のニーズ（N-1）から来ています。検証コマンドを実際に走らせた結果だけを信じ、実装役の自己申告を根拠にしません。必須 T

08 制約・規制 / 守らねばならない外枠

設計の前に決まっている制約と、 法令

設計の前から決まっている制約を並べます。憲法が上位にあること、repo が PUBLIC であること、test は Rust だけ、前の器の作法を持ち込まない、不可逆操作の口を持たない、headless の制約、の 6 点です。

CON1憲法憲法（Always 17 / Ask-first 4 / Never 4）を本書の上位に置き、 矛盾する要件を書かない 法令 憲法 v0.5.0
CON2公開本 repo は PUBLIC。 絶対 path・host 名・口座名・user 逐語を tracked file に書かない 法令 憲法 A1（出す）
CON3歯test は Rust の 1 framework だけで、 bash / bats の歯を書かない 法令 憲法 C12
CON4作法前の器（v1）の役割席・gate 席・QA 席・契約押印・tier ラベルを持ち込まない 法令 ADR-0003
CON5口binary は不可逆操作（force push・削除・公開・課金）の口を持たない 法令 憲法 A1 / N1

09 用語集 / この文書で使う専門語

本文に出てくる専門語のやさしい説明

本文に出てくる専門語（契約・runner・lens・gate・land・fleet・event log・hook・worktree など 97 語）を、やさしい言い換えと定義で並べます。本文中の専門語には同じ言い換えを併記しています。

契約contract
何を作り・何ができたら終わりかを表す 1 単位。 正本は設計 doc の契約表 1 行で、 器が便の契約 file を生成する。 台帳（beads）の 1 issue に対応する。
runnerrunner
契約 1 本を worktree で実装する headless の Claude process。 席ではなく使い捨て。
lenslens
diff を読んで PASS / FAIL / INCONCLUSIVE を返す headless の Claude process。
dispatcherdispatcher
便を自動で起こし、 gate を通った便を land して merge する器の口（契機と条件は FR68・終端は FR50・ADR-0034・ADR-0045）。 席ではない。
起動の列dispatch queue
dispatcher が台帳から導く、 起動を待つ契約の並び（入る条件・順序・待ちの理由は FR68 が定める）。 land の順序（FR50）とは別の実体。
受付contract intake
契約 file を便にする前に器が撃つ検査の段。 必須 field・verify の形・allowlist・write-set の余地・host の memory の枠・同時走行の最大値（FR68）を通った契約だけが便になる（交差の排他は FR39）。 vessel 宣言が ruling-check を true で持つ repo では裁定 id の実在（FR83）も確かめる。 変異検査の並列の枠（NFR6）とは別。
prioritycontract priority
台帳の bead が持つ契約の優先度（P0〜P4）。 起動の列の順序の 2 番目の鍵（FR68）。 要件の priority 欄（必須 / 推奨）とは別。
Reviewedreviewed stage
便の段の 1 つ。 契約の審査（FR49）の verdict を持ち、 PASS でない便は runner を起こさず FAIL で終端する。
介入orchestrator intervention
first（最優先へ）・hold（止める）・release（戻す）の 3 つの typed な印。 user の直命の対として記録され、 台帳の priority は書き換えず、 起動の列の記録として残る（FR68）。
gategate
契約の verify を実走し lens 1 本の verdict を採る段。 PASS でなければ land しない。
landland
worktree の成果を squash 1 commit で main に載せ、 main で歯を再実走すること。
fleetfleet
正定義は複数 host にまたがる席・口座・lease・退役の全体（憲法 C3）。 MVP では便と席の現在地の全体を指し、 実体は event log 1 file。
event logevent log
1 行 1 出来事を追記する file。 現在地はこれを replay して導く。

規則の値（閾値・有効 / 無効・裁定 id）を持つ tracked な TOML 1 file。 憲法 C1 の「値は manifest」の実体。
verdictverdict
gate が返す 3 値（PASS / FAIL / INCONCLUSIVE）。 構造化 field が一次 truth。

消す / 出す / 使う の 3 分類。 これに当たる操作だけ人の承認を要する。
write-setwrite-set
契約が宣言する、 編集してよい file の集合。 外への編集は編集の時点で止める。

repo root の固定名 file。 中身が name と version を言い、 どの器が仕えるかを決める。

変更の test 差分だけを base に当てて新規・変更 test が RED になり、 HEAD では GREEN であることを機械で確かめる検査（憲法 C12.2）。 docs-only の変更は対象外（C12.3）。
headlessheadless
対話画面を持たず、 入力を受けて 1 回で答えを返す Claude の実行形（claude -p）。
toy repotoy repo
到達点を測るために一時 dir に作る、 外部依存の無い小さな git repo。
設計 docdesign doc
要望を SRS の要件に結び、 契約が複数出る元になる tracked markdown。
要件カタログrequirements catalog
要件 doc の v2 行を scrub して写した一覧（requirements-catalog.html）。 FR との対応は同 page の §移行表 が持つ。
承認 eventapproval event
approval.requested / approval.received の 2 種。 逐語を伴い fleet に残る。
hookhook
Claude Code が tool を呼ぶ直前・直後に自動で走る短い処理。 器は編集を止める側（in-loop guard）と名乗りを出す側に使う。

変更前と後の違いだけを取り出したもの。 lens はこれを読んで審査する。
worktreeworktree
同じ repo の別の branch を別 dir に取り出した作業場所。 runner は 1 便ごとに 1 つ切る。

verdict の 3 値の 1 つ。 合格でも不合格でもなく「判断できない」で止まり、 land されない。

PR を出すたびに自動で走る検査（test・lint・xtask）。 緑でなければ merge しない。

repo root に置く .vessel のこと。 中身が name と version を言い、 hook はこれを見て仕えるかを決める。

git に残す変更の 1 単位。 runner の完了判定は base からの commit が 1 件以上あるかで測る。

変更が文書だけの PR。 flip check の test 差分の要件から除外される（憲法 C12.3）。

口座残量account allowance

追随follow

manifest の口座（退役中を除く・FR58）と実測の残量だけから口座を決定的に選ぶこと（FR36）。 便用と session 用の 2 規則を持つ。

claude が口座の上限を専用の record で伝える合図。 便の停止判定はこの record だけを入力にする（FR35・ADR-0012）。
anchoranchor
対象 repo の main checkout。 席と便の鍵の一部で、 1 つの anchor に orchestrator 1 席（FR40）。
席の指示文role brief
役割ごとの雛形と権能の rules 行から器が生成し、 session の文脈が初期化されるたびに注入する文（FR42）。 手書きの規範文は持たない。

設計 doc の path と契約 id の対。 intake の入力（FR53）で、 台帳の bead の受入条件が持つ 1 行でもある（FR2）。

器が台帳を読む口（読み取り専用）と close を書く口。 台帳へ触る module はこれ 1 つ（FR50 / FR51）。

command のうち撃ってはいけない語の並び。 値は manifest の rules 行だけが持ち（並びの例は行を見る）、 器が実行の前に止め、 intake が verify 行に同じ判定を掛ける（FR56）。

不可逆な操作を実行の直前に止める器の subcommand（見張りの種類の閉じた一覧は ADR-0078〔ADR-0056 の 5 つの末尾に publish の種類を足した 6 つ〕。 SRS が要件を持つのは禁じる語列・見張り自身の設定・rm・台帳の破壊と素 write・公開の字面の走査の 5 つ＝FR56 / FR72 / FR74 / FR76 / FR80・git の履歴破壊と tmux server の破壊の 2 種は FR56 の禁じる語列）。 口座の settings.json の hook 行（配線は FR75・健康診断は FR73）から呼ばれ、 口座の設定を読む全 session に marker の有無に依らず効く。 器が起こす session（runner・lens・usage の更新）には届かない。

口座の設定 dir の settings.json を読んで起きる session の全体（対話の席・口座の設定 dir を指定した起動・器を積まない session）。 host-guard の配線（FR75）が効く範囲と一致し、 器が起こす session（runner・lens・usage の更新）は含まず、 口座の設定 dir を指定しない起動は配線先に入れない（既定の設定 dir が口座の実体を指す host では届くが、 それは配線の約束ではない・FR56 / FR72 / FR74 / FR76 / FR80・ADR-0056）。

Bash の command を segment に分けたうち、 git の push と gh の公開の動詞（本文を出す動詞〔pr・issue・release・gist・label と api の書き〕と repo の作成・編集）の部分（FR80）。 host-guard の publish の種類はここだけを読む。 3 クラスの「出す」とは別で、 自 repo への push と PR の作成も含む。

候補の木candidate tree
main の先端に、 gate を通った便の並びの先頭から数本を順に rebase して作る 1 つの worktree。 gate はこの木に撃ち、 緑なら並べた順に着地する（FR50 の push の先端は最後に着地した commit）。
host の面host manifest
manifest の host の面。 state dir の 1 file が host 固有の宣言値を持ち、 tracked の manifest と同じ読み手で読まれる。 rules 行は置けない（FR57・ADR-0026）。
口座の登録account registration
器の subcommand が口座の設定 dir・席の前提の設定・host の面の宣言を揃え、 login 用の起動 command を user へ渡すこと（FR58）。 login は user の手番で、 器は credential に触れない。 退役と復帰も同じ subcommand が担う。
席の起動seat launch
役割を必須に受け、 口座を決め、 起動行を導出し、 席の登録を先に書いて target の窓の shell へ差し込むこと（FR59）。 器の subcommand 以外の起動経路を使わない。
同時走行の最大値live run cap
host で同時に走らせる便（終端でない段の便）の最大本数。 値は rules 行 pipe.max_live だけが持ち（user 裁定 id 付き）、 受付が終端でない便を数えて最大値以上の周は typed に断り、 その契約は起動の列に留まる（FR68）。 走っている便は止めない。
host の根host root
state dir の親の下に在る host 用の dir。 同じ host の全 project が共有し、 host 単位の受付の札と、 群の置き場（群の今の口座の記録・移動を頼む記録・群の段の lock と履歴・ADR-0049）がここに在る。 host の面（project ごとの state dir の 1 file）とは別。
実効の口座effective role account
役割の席が使うと器が役割ごとに解く口座（ADR-0041）。 器は持たず、 群の今の口座に置き換わった（ADR-0049）。 席の口座は群の今の口座か口座の引数か session 用の口座選定（FR36）で決まる（FR59）。
実効の記録effective role record
器が host の根に役割ごとに高々 1 件書く、 役割の実効の口座の記録（ADR-0041）。 器は持たず、 群の今の口座の記録（ADR-0049）に置き換わった。
妥協の起動compromise launch
閾値未満の口座の候補が無い周に、 閾値以上でも上限に当たっていない口座、 それも無ければ他の席の口座との同居で席を起こすこと（ADR-0041 の 2 段）。 器は持たず、 席の起動は理由の語で断る（FR69・ADR-0086）。 群の移動も妥協しない（FR38・ADR-0049）。
群の今の口座group effective account
project の群の席が実際に使う口座。 器が host の根に群ごとに高々 1 件の記録で持ち（ADR-0049）、 記録が無い周は種（宣言順で前の群の種でない最初の候補・ADR-0069）になる。 書き換えは群の移動（FR38）だけが行う。
群の逼迫group pressure
群の今の口座か群の席が居る口座の使用率が、 5 時間窓・7 日窓・モデル別窓のいずれかで閾値の rules 行の値以上である状態（ADR-0055）。 便の終端の周と席自身の hook が測り、 時計では測らない。
heartbeatheartbeat
