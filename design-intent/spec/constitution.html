本 constitution は IETF RFC 2119 および RFC 8174 / BCP 14 に定義される MUST / SHALL / SHALL NOT のキーワード解釈規約に従う。 規範文 (EARS) は機械層 (data-audience="machine") が正で、 人間向け要旨はその正確な要約である。

§1. Purpose — この憲法が何を決め、 どう読むか

scribe2 が版をまたいで守る「折れない線」を、 守り方の強さで Always / Ask-first / Never の 3 段に分けて置きます。 各条は「人が読む要旨」「機械が読む規範文 (正本)」「機械が検査できる形 (型 / lint / CI)」「出所 (どの裁定から来たか)」の 4 つを必ず併せ持ち、 数値は条文に書かず manifest の rules 行に置き、 その初期値を §3 に写します。 線どうしがぶつかったら、 場当たり修正の禁止 → 膨張防止 → compile 速度 の順位で決めます。

本 constitution は scribe v2「次の器」の design-intent の最上位文書であり、 条文の canonical WHAT かつ edit-SSoT である (folio ADR-0051 §3: flip しない doc は HTML が唯一の層)。 21 条の各条は (a) human 要旨、 (b) EARS 規範文 (canonical)、 (c) 機構 = 条を成立させる型 / lint / CI の形、 (d) 出所 = 裁定論点 id、 の 4 要素を持つ。 (c) を欠く条を置かない (散文だけの規則を残さない = N2)。 1 つの条は複数の規範文を持ちうる: 最初の規範文は条 id (例 C12)、 以降は条 id に連番を付す (例 C12.2)。 EARS pattern は各規範文の論理構造で決まり、 段 (Always / Ask-first / Never) とは独立である。 card の badge は最初の規範文の pattern を表し、 2 つ目以降の規範文の pattern は machine 層の各 block が持つ。 原本が執行主体を特定しない条は主語を scribe2 (system of interest) とし、 CI 等の執行機構は機構 dd に (導出) と明示する。 原本が CI を名指す条は scribe2 CI を主語にする。 数値 (閾値・件数・秒数) は条文に置かず rules 行 (manifest 内の値 1 行・裁定 id 付き) に置き、 本文書ではその初期値を §3 に写す。 改訂は A2 (利益の grill 検証を前置した user 裁定) のみで、 条文の改訂は同じ版の中では行わない (N4)。

順位: WHEN two lines of this constitution conflict in a decision, scribe2 SHALL resolve the conflict in this order: prohibition of ad-hoc fixes first, prevention of growth second, compile speed third.

出所: 論点 1。 順位は条ではなく全条に先立つ決め方であり、 条 id の連番を持たない (§2 の一覧表にも含めない)。

§2.1 Always — いつも守る (C1〜C13)

例外なく常に守る 13 条です。 規則・経路・状態を「1 つ」に閉じ、 大きさと消費と依存に予算を置き、 失敗と値の出所を型で扱い、 歯は Rust の test だけにします。

C1 Ubiquitous 規則はデータ

規則の「種類」は閉じた型で、 「値」は repo 内の manifest 1 file に置きます。 人が読む説明は型と manifest から生成し、 手書きの規範文は 0 行です。 機械が実行時に読む規則はこの manifest 1 file だけです。

normative (machine)

C1: scribe2 SHALL represent every rule kind as a variant of one closed type with a mandatory exhaustive check implementation, SHALL keep every rule value (threshold, enabled flag, ruling id, ruling time, verbatim text) in exactly one manifest file inside the repository, SHALL keep only runtime state in the database, and SHALL read rules at run time only from that manifest.

C1.2: scribe2 SHALL derive human-readable rule documentation from the rule type and the manifest, and SHALL contain zero hand-written normative lines in that generated rule documentation.

機構 (型 / lint / CI)
enum RuleKind + trait Rule { fn check(&self, ctx) -> Verdict } を網羅 match で実装必須 (未実装 = compile error)。 値は manifest 1 file (TOML・schema_version・未知 key 拒否・起動時 1 回読み)。 DB は実行時状態だけを持つ。 人間向け doc は enum の doc コメント + manifest からの build.rs 生成物。 CI は生成 doc 中の手書き規範文の行数を数え、 0 行でなければ落とす。
出所
論点 5
C2 Ubiquitous 経路は 1 本・語彙は 1 つ・名前は 1 定数

選定・除外・routing はそれぞれ 1 関数・1 enum で、 適用順は enum の並び順だけが決めます。 理由を足すときは enum に 1 値足すだけです。 設定は manifest 1 struct から読み、 env を直接読まず、 新しい env の口も作りません。 名前はすべて 1 つの定数から導きます。

normative (machine)

C2: scribe2 SHALL implement selection, exclusion and routing each as exactly one function over exactly one enumeration, SHALL take the application order solely from the declaration order of the stage enumeration, SHALL NOT carry a prose note on ordering, and SHALL express a new reason only as one new variant.

C2.2: scribe2 SHALL read configuration only from the manifest structure, SHALL NOT read environment variables directly, SHALL NOT introduce a new environment seam, and SHALL derive the plugin name, crate name, skill namespace, state directory, environment prefix and terminal-multiplexer server name from one NAME constant.

機構 (型 / lint / CI)
選定 / 除外 / routing = 各 1 関数 + 1 enum。 除外と適用順は宣言的で enum Stage の列挙順が唯一の適用順 (「適用点は X の後」の散文注記を持たない)。 設定 = manifest 1 struct・env 直読禁止・env seam を新設しない。 plugin 名 / crate / skill 名前空間 / state dir / env 接頭辞 / tmux server 名は NAME 1 定数から導出。

論点 8・SPEC §7
C3 Ubiquitous fleet の状態は 1 つ

host / 口座 / 席 / lease / 退役は 1 つの DB file (host 列付き) に置き、 host ごとの dir や TSV や cache に真実を置きません。 doctor 1 コマンドが全 host の版・口座・退役を照合します。 状態は型で運び、 端末の見た目や自由文を判定に使いません。 完了条件は 1 つの enum だけで表し、 待つ処理も 1 実装だけで、 その場限りの判定条件を書ける口は作りません。

normative (machine)

C3: scribe2 SHALL keep the state of hosts, accounts, seats, leases and retirements in exactly one database file carrying a host column, and SHALL NOT place truth in per-host directories, TSV files or caches.

C3.2: scribe2 SHALL provide one doctor command that reconciles version, accounts and retirements across all hosts.

C3.3: scribe2 SHALL carry seat state as a typed enumeration, and SHALL NOT use terminal rendering or free text as judgment input.

C3.4: scribe2 SHALL express completion conditions only as values of one completion enumeration, and SHALL provide exactly one wait implementation that accepts only those values, and SHALL NOT expose a wait entry point that takes an arbitrary predicate.

機構 (型 / lint / CI)
SQLite 1 file (host 列)。 doctor 1 コマンドが全 host の版・口座・退役を照合。 状態は enum SeatState で運ぶ。 完了条件は enum Completion の値でのみ表現でき、 待機 API は 1 実装 (引数型が Completion に閉じており、 その場で述語を書ける口を作らない)。
出所
論点 8
C4 Ubiquitous 大きさに上限

core・module・test の大きさと関数の粒度に上限を置き、 CI が実測します。 粒度の lint は #[allow] で黙らせられません。 上限の変更は A2 (利益の grill 検証を前置した user 裁定) でだけ行います。 判断に迷うときは「歯を足す」より「compiler に検査させる」を先に選びます。

normative (machine)

C4: scribe2 SHALL enforce upper bounds on core size (R-C4-1), module size (R-C4-2), the test-to-source line ratio (R-C4-3) and function granularity (R-C4-4) as CI-measured deny gates, SHALL NOT silence a granularity lint with an allow attribute, and SHALL change any such bound only through A2.

機構 (型 / lint / CI)
閾値 = §3 R-C4-1 (core 総行数) / R-C4-2 (1 module 行数) / R-C4-3 (test:src 行数比) / R-C4-4 (関数粒度 lint = 関数行数・複雑度・引数数)。 関数粒度 lint は deny で #[allow] による黙殺禁止。 CI が実測する。 判断規則 (A2 の審査観点): 「歯を足す」より「compiler に検査させる」を先に選ぶ。
出所
論点 2
C5 Unwanted 規則変更 = manifest diff + 裁定 id

rules 行の追加や変更は、 user の裁定 id が付いていなければ merge できません。 CI が「裁定 id の無い rules 行の diff」を落とします。

normative (machine)

C5: IF a change adds or modifies a rules row without an accompanying user ruling id, THEN scribe2 CI SHALL reject the change.

機構 (型 / lint / CI)
rules 行の diff を CI が検査し、 裁定 id (ts) の無い diff を落とす。 裁定 id と裁定時刻は rules 行の値の一部 (C1)。 帰結として AI が場当たりで規則を生やすことはできない。
出所
論点 5
C6 Ubiquitous 消費は害

Budget は Precheck の実測を使ってしか作れず、 起動口は Budget を受け取る 1 関数だけなので、 見積なしの起動は型の上で不可能です。 1 run の token 上限と検出線は rules 行に置き、 上限を超えたら人手を介さず止めます。 計測は 1 つの追記専用 store に残します。

normative (machine)

C6: scribe2 SHALL make a Budget constructible only by consuming a Precheck measurement, and SHALL expose exactly one spawn entry point, which requires a Budget.

C6.2: IF a run exceeds the per-run token ceiling (R-C6-1), THEN scribe2 SHALL stop the run without manual intervention.

C6.3: scribe2 SHALL record consumption in exactly one append-only store.

機構 (型 / lint / CI)
Budget は Precheck の実測を消費してしか作れず、 fn spawn(budget: Budget) が唯一の起動口 (帰結: 見積なしの起動は型で不能)。 計測は append-only store 1 つ。 上限と検出線の値は §3 R-C6-1。 C10 (値の出所を型で弁別) の応用。
出所
論点 11
C7 Ubiquitous planner が唯一の対話面

user の承認は planner を通った relay 印だけを機械が受け取ります。 他の経路で来た「承認」は承認として扱いません。

normative (machine)

C7: scribe2 SHALL accept a user approval only as a relay stamp issued through the planner.

機構 (型 / lint / CI)
承認 = planner 発行の relay 印のみを機械が受理する。 A1 / A2 / A3 / A4 の承認はすべてこの経路を通る。
出所
SPEC §2 (裁定 id なし)
C8 Ubiquitous 版 N+1 は版 N の下で作られる

器が自分自身を開発できるのは「成熟した版」だけです。 成熟の宣言は §3 の成熟条件がすべて成り立つことを機械が測り、 裁定 id を付けて行います。 自己開発が解禁されていない間は、 自分の repo への dispatch を拒みます。 立ち上げは 4 つの状態 (段 0 / 段 1 / 段 1-test / 段 2) を持ち、 機械が塞ぐのは最後の段 2 だけです。

normative (machine)

C8: scribe2 SHALL permit self-development only for a version declared mature.

C8.2: WHILE self-development is not enabled with a ruling id, scribe2 SHALL deny a dispatch onto its own repository anchor.

C8.3: scribe2 SHALL expose the maturity conditions as measured values through the doctor command.

C8.4: scribe2 SHALL attach a ruling id to every maturity declaration, and SHALL base every maturity declaration on all maturity conditions defined in R-C8-1 holding at once.

機構 (型 / lint / CI)
enum SelfDev { Disabled, Enabled { ruling_id } }。 dispatch は自 repo anchor を Enabled 以外で deny。 doctor selfdev が成熟条件を Measured<T> で出す。 bootstrap は 4 つの状態を持つ: 段 0 = v1 が v1 を自己開発 ／ 段 1 = v2 repo に v1 plugin の planner / admin を置いて v2 を開発 ／ 段 1-test = v2 repo 外の test project に v2 plugin を置いて試運転 ／ 段 2 = 成熟 + go の後に v2 repo 内の席を v2 plugin へ替えて自己開発。 deny が塞ぐのは段 2 だけ。 成熟条件の値は §3 R-C8-1。
出所
論点 9・SPEC §12
C9 Event-Driven 口座の連続性

不変量は 2 本だけです: 「席の停止は人手を介さず検知し、 作業は resume され、 成果は失われない」 「口座は枠の終わりまで使い切る」。 数値と選定規則は rules 行に置きます。

normative (machine)

C9: WHEN a seat stops, scribe2 SHALL detect the stop without manual intervention, SHALL resume the seat's work, and SHALL preserve its results.

C9.2: scribe2 SHALL consume each account until the end of its allowance window, following the selection rules of R-C9-1.

機構 (型 / lint / CI)
enum SeatState (T8)・enum Completion の 1 実装 (T7)・fn migrate(seat, budget) -> Outcome 1 本。 管理席の再起動は「記憶退避済み」を型の前提条件に持つ。 数値と選定規則 (新規投入の線・移住 lane の扱い・消費計画・管理席 watchdog の検知条件と再起動先) は §3 R-C9-1 の rules 行に持たせる。
出所
論点 8・U5
C10 Ubiquitous 値の出所と効力は型で弁別する

人が書いた宣言値・出所付きの実測値・導出値・効力を持つ値を、 別々の型で運びます。 宣言値は実測を経てはじめて効力を持ち、 配線されていない設定は CI が落とします。 host 固有の値は manifest 以外に置けず、 report は生成物だけで、 手書きの「verified」は書けません。

normative (machine)

C10: scribe2 SHALL distinguish declared values, measured values with provenance, derived values and effective values by type, and SHALL promote a declared value to effective only through a measurement.

C10.2: scribe2 SHALL keep host-specific values only in the manifest, SHALL produce reports and listings only as generated artifacts, and SHALL NOT accept a hand-written verified status.

C10.3: scribe2 CI SHALL reject unwired configuration.

機構 (型 / lint / CI)
Declared<T> (人が書いた宣言値) ／ Measured<T>{value, source: Provenance} (実測・出所付き) ／ Derived<T> (導出値・Independent を名乗れない型) ／ Effective<T> (Declared から実測を経てのみ格上げ)。 未 wire の設定は CI が落とす。 host 固有値は manifest 1 file 以外に置けない。
出所
論点 11・T11 / T13 / T15
C11 Ubiquitous 失敗と極性は型で

panic 系や unwrap 系、 標準出力への直書きなどを lint で deny し、 unsafe は forbid します。 例外は理由を書いた #[expect] のときだけ認めます。 失敗は境界ごとの enum で表し、 開く (FailOpen) か閉じる (FailClosed) かの極性を型に持たせ、 全 guard の極性一覧を build 時に生成します。 timeout は Result にして呼び出し側に分岐を強制し、 core では型の無い error を使いません。

normative (machine)

C11: scribe2 SHALL deny by workspace lint the use of unwrap, expect, panic, todo, unimplemented, unreachable, process exit, slice indexing, debug macros and direct stdout / stderr printing, SHALL deny unused must-use values, SHALL forbid unsafe code, and SHALL allow a lint exception only through an expect attribute carrying a written reason, apart from the test-scope exceptions declared in the lint configuration.

C11.2: scribe2 SHALL model failures as one enumeration per boundary carrying a FailOpen / FailClosed polarity type, and SHALL generate the polarity list of all guards at build time.

C11.3: scribe2 SHALL model a timeout as a Result that forces the caller to branch, and SHALL NOT use an untyped error type in core.

機構 (型 / lint / CI)
[workspace.lints] で unwrap_used / expect_used / panic / todo / unimplemented / unreachable / exit / indexing_slicing / dbg_macro / print_stdout / print_stderr を deny・unused_must_use deny・unsafe_code = forbid (test の例外は clippy.toml の allow-*-in-tests)。 失敗は境界ごとの enum (thiserror・許可リスト内) で極性 FailOpen / FailClosed を型に持ち、 全 guard の極性一覧を build 時に生成 (T12)。 timeout は Result<Verdict, Timeout>。 core での anyhow 禁止。 例外は #[expect(lint, reason = "…")] のみ。
出所
論点 6
C12 Ubiquitous 歯は Rust だけ・TDD

test は Rust の 1 framework だけで、 bash / bats は全廃します。 すべての変更は先に落ちる test から始まり、 CI の flip check がそれを機械で確かめます (test 差分の無い PR は docs-only を除いて拒みます)。 変異検査は検出線、 外形は snapshot、 case 量産は property test で担い、 KNOWN-RED 台帳は持たず main は常に GREEN です。

normative (machine)

C12: scribe2 SHALL use exactly one test framework (Rust native tests), and SHALL NOT keep shell-based tests.

C12.2: scribe2 CI SHALL verify by a flip check that every change starts from a failing test: the test diff of the PR applied alone to base fails at least one new or changed test, and HEAD passes.

C12.3: IF a PR carries no test diff and is not classified docs-only, THEN scribe2 CI SHALL reject the PR.

C12.4: scribe2 SHALL record mutation survival as a detection line (R-C12-1), SHALL NOT hand-write mutation controls, and SHALL promote that detection line to a deny gate only through a user ruling carrying a ruling id (C5).

C12.5: scribe2 SHALL snapshot external form (CLI output, generated documentation, polarity list), and SHALL reject unreferenced snapshots.

C12.6: scribe2 SHALL NOT keep a known-red ledger, and SHALL keep the main branch green at all times.

C12.7: scribe2 SHALL mass-produce test cases by property testing.

機構 (型 / lint / CI)
#[test] + nextest の 1 framework・bash / bats 全廃。 flip check = CI が PR の test 差分だけを base に当てて RED (新規・変更 test が 1 本以上落ちる) ∧ HEAD で GREEN。 test 差分の無い PR は reject (docs-only は分類で除外)。 非空虚性は cargo-mutants の検出線 (§3 R-C12-1)・変異対照を手書きしない。 外形 (CLI 出力・生成 doc・極性一覧) は insta snapshot + --unreferenced reject。 KNOWN-RED 台帳を持たない (RED は同じ PR で直すか test を消す)。 case 量産は proptest。
出所
論点 7
C13 Ubiquitous compile と依存に予算

依存は許可リストと予算で管理し、 追加は予算の範囲で user 確認つき・compile 時間の実測差を添えます。 derive は境界 crate に閉じ、 full feature は使わず、 重複版・脆弱性・license は cargo deny が CI で見ます。 core は async を持ちません。 compile 時間のうち決定論的に決まる形は CI が deny し、 秒数は検出線として記録して悪化時に自動起票します。

normative (machine)

C13: scribe2 SHALL manage dependencies by an allow-list with a budget (R-C13-1), and SHALL add dependencies only within the per-PR budget of R-C13-1, with user approval (A3) and a recorded incremental compile-time delta.

C13.2: scribe2 SHALL confine derive macros to boundary crates, SHALL NOT enable full feature sets, and SHALL audit dependencies (duplicate versions, vulnerabilities, licenses) in CI.

C13.3: scribe2 SHALL NOT use async in core.

C13.4: scribe2 CI SHALL deny only the deterministic shape constraints of compile time (R-C13-2).

C13.5: scribe2 SHALL treat compile-time seconds as detection lines recorded at the interval defined in R-C13-3, SHALL file an issue automatically on regression beyond that line, and SHALL NOT block a PR on those lines.

機構 (型 / lint / CI)
依存 = 許可リスト + 予算 (§3 R-C13-1)。 derive は境界 crate に閉じる・full feature 禁止・cargo deny (重複版 / 脆弱性 / license) を CI に。 core は async を持たない (std::thread + channel・tokio 却下)。 compile は CI deny が決定論の形だけ (§3 R-C13-2: profile の debug 設定・統合 test file 数・runner nextest・proc-macro 展開後比率・critical path 上の crate 分割)。 秒数は検出線 (§3 R-C13-3: hyperfine 記録・悪化で原因 crate を名指しした issue を自動起票・PR は止めない)。 閾値は C4 と同じ扱い (A2)。
出所
論点 3・4

§2.2 Ask-first — 変える前に user に確認 (A1〜A4)

勝手に変えず、 必ず user に確認してから行う 4 条です。 確認の経路は C7 の planner 経由の relay 印だけです。

A1 Event-Driven 3 クラスの操作

「消す / 出す / 使う」の 3 クラスに当たる操作は、 実行前に user の承認 (relay 印) を取ります。

normative (machine)

A1: WHEN an operation of one of the three classes (delete, send out, consume) is about to be performed, scribe2 SHALL obtain the user's approval as a relay stamp through the planner before performing it.

機構 (型 / lint / CI)
承認は relay 印 (C7) のみ。 3 クラスの定義は vocabulary (消す / 出す / 使う)。
出所
SPEC §2 (裁定 id なし)
A2 Event-Driven 憲法条文の改訂と C4 / C13 の閾値変更

条文を変えるときも、 C4 / C13 の閾値を変えるときも、 先に「その変更で何が良くなるか」を grill で検証し、 そのうえで user が裁定します。 裁定には裁定 id が付きます。 この手続きの正本は本条です。

normative (machine)

A2: WHEN an amendment to a constitution article or a change to a threshold governed by C4 or C13 is proposed, scribe2 SHALL first perform a grill verification of the claimed benefit, and SHALL obtain a user ruling (carrying a ruling id) before applying the change.

機構 (型 / lint / CI)
閾値変更 = rules 行の diff + 裁定 id (C5 が CI で強制)。 条文の改訂は同じ版の中では行わない (N4) ため版 N+1 で行う。 手続きの流れは §4 (正本は本条・C5・N4)。

A3: WHEN an OSS dependency is to be added or removed, scribe2 SHALL obtain the user's approval as a relay stamp through the planner first, and SHALL follow the C13 procedure (C13, R-C13-1).

normative (machine)

論点 9

§2.3 Never — 絶対にやらない (N1〜N4)

例外を認めない 4 条です。 いずれも「やろうとしたら機械が拒む」形で守ります。

N1 Unwanted rm による削除

元に戻せない削除はしません。 消す必要が出たら、 退役として可逆な move で行います。

normative (machine)

N1: IF an operation would irrecoverably delete any object managed by scribe2, THEN scribe2 SHALL reject the operation.

N1.2: scribe2 SHALL perform any retirement only as a reversible move.

機構 (型 / lint / CI)
退役 = 可逆 move の 1 経路 (C2)。 (導出) 削除経路を実装しない。
出所
SPEC §2 (裁定 id なし)
N2 Unwanted 規則を散文・memory・chat にだけ置く

文章・記憶・会話の中にしか無い「規則」は規則として扱いません。 そういう変更は CI が落とします。

normative (machine)

N2: IF a change would introduce a rule that exists only in prose, memory or chat, THEN scribe2 SHALL NOT treat it as a rule, and scribe2 CI SHALL reject the change (C1.2: hand-written normative lines are zero).

機構 (型 / lint / CI)
C1.2 の CI (生成 doc 中の手書き規範文の行数 = 0) と C5 (裁定 id 無しの rules 行 diff を落とす)。
出所
SPEC §2 (裁定 id なし)・論点 5
N3 Unwanted host 固有の分岐を code に焼く

「この host なら」の分岐を code に書きません。 host ごとの値は manifest に置きます (C10)。

normative (machine)

N3: IF code would branch on a host-specific value, THEN scribe2 SHALL reject the change.

機構 (型 / lint / CI)
host 固有値は manifest 1 file 以外に置けない (C10.2)。 (導出) 検査は C10.2 の未 wire 設定 CI 検査を host 固有値へ拡張する形で行う。

SPEC §2 (裁定 id なし)・論点 11
N4 Unwanted 同じ版の中で憲法改訂・schema 非互換・C4 超えをしない

今の版の中で憲法を書き換えたり、 schema を壊したり、 C4 の上限を超えたりする変更は拒みます。 そうした変更は版 N+1 として別 repo で行います。

normative (machine)

N4: IF a change inside the current version would amend the constitution, break schema compatibility or exceed a C4 bound, THEN scribe2 SHALL reject the change in the current version.

機構 (型 / lint / CI)

§4. 改訂の手続き — どう変えると何が起きるか

変えたいときはまず利益を grill で検証し、 user が裁定します (A2)。 閾値なら manifest の diff に裁定 id を付けて merge し (C5)、 条文なら同じ版では変えず版 N+1 で改訂します (N4)。 C4 / C13 以外の rules 行は A2 を通さず、 裁定 id 付きの diff (C5) だけで変えます。 したがって、 この file 自体を同じ版の中で書き換えるのは §3 の写しの更新と誤記の修正だけです。

本章は新しい規則を持たない。 手続きの正本は A2 (grill 検証 → user 裁定)・C5 (rules 行の diff + 裁定 id)・N4 (条文は版 N+1) である。 本 constitution の version は SPEC の版に追随する。 A2 / C5 / N4 の帰結として、 同一版内の本 file の変更は §3 の写しの更新と誤記の修正に帰着する。 改訂の trace は folio の delta marker (ins.delta / del.delta) で本文に残す。
